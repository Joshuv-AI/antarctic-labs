Final Project Report, “Data Structure Alchemy”​
(Reporting period 2019 - 2024)

1 Project Vision & Objectives
In an increasingly more data-driven world, the project set out to uncover the first principles of
data-structure design, chart the immense design space they form, and build automation that
can synthesize an optimal structure, or even a whole storage engine, for any given
workload, hardware platform, and cost target.
Data structures are at the center of every computational related system and are directly
responsible for its performance.
Two core technical thrusts were defined:
 ●​ Mapping design spaces for key data-centric abstractions (filters, hash functions,
 storage-engine layouts, neural-network topologies, blockchain protocols, image layouts,
 etc.).
 ●​ Developing search & synthesis algorithms, initially analytical cost models, later
 neural-guided bi-level optimisers, that navigate sextillions of candidate designs in
 seconds and materialise the best one as ready‐to-run code.
This report distills the key insights, accomplishments, and impact.

2 Scientific & Societal Importance
Data structures underpin every data-driven application, from databases, AI, and compilers to
operating systems, bio-informatics and astronomy pipelines. Even a 1 % inefficiency ripples
into multi-million-dollar cloud bills and large carbon footprints. Automating their design
therefore promises:
 ●​ Order-of-magnitude performance gains without months of expert labour.
 ●​ Dramatic energy & cost reductions at hyperscale.
 ●​ Democratisation of advanced data handling for disciplines lacking deep CS expertise.

3 Major Achievements
Data Structure Alchemy tackles data-structure design by first isolating the irreducible
“knobs” that govern every classical or learned structure, fan-out, node layout, buffering
regime, hashing family, model components, etc., and arranging them into an explicit
combinatorial design map. With this cartography in hand, the framework trains cost models
that predict each candidate’s latency, space, and energy, then runs a two-tier optimiser
(gradient-guided/Bayesian inner search plus outer budget-aware pruning) that can navigate
sextillions of possibilities to find the design sitting on the Pareto frontier for a user’s specific
workload, hardware, and cost target. Finally, a code generator materialises the chosen point as
compilable templates (e.g., in Rust), producing a bespoke data structure, or an entire storage

engine, in minutes. By chaining design-space cartography → learned cost modelling →
automated search → code synthesis, the methodology converts what was months of expert
trial-and-error into a repeatable, first-principles “compiler” for data structures.
Over the course of the last five the project applied this core methodology in a series of diverse
data-driven areas to reimagine the fundamentals of storage in each area. The table below
summarizes some of the core results.

4 Illustrative Breakthroughs
4.1 Image Calculator (SIGMOD’23 & CIDR’24)
Self-Designing Storage for Image AI. The Image Calculator paper observes that most
image-AI pipelines still consume JPEGs, a format tuned for human perception rather than the
needs of neural networks. It reframes image storage as an optimisation problem: for a given
model, dataset and accuracy target, choose the transform, quantisation, tiling and metadata
layout that minimise both inference time and bytes. To do so, we construct a vast design space
of candidate formats from first principles and search it with composite cost models that jointly
predict storage footprint, decoding latency and model-accuracy impact. The resulting
“calculator” automatically synthesises a bespoke format that is tailored to the given task and
neural network at hand.
Across diverse datasets, tasks and hardware, Image Calculator’s self-designed formats cut
end-to-end inference latency by up to 14.2× and dataset size by 8.2× relative to JPEG and
modern variants, all while maintaining (or occasionally improving) accuracy. These gains
translate into lower cloud costs and energy use, demonstrating that co-designing storage with
compute is a powerful lever for scaling vision workloads.

4.2 Limousine (SIGMOD’24)
Self-designing Big Data Systems. Limousine reframes the storage-engine problem as
automated architecture search: given a workload, cloud budget and performance target, it
explores a unified design space where learned models (e.g., PGM, RadixSpline) and classical
layouts (B-trees, LSMs, hash tables) can be blended into “clearned” hybrids. A
distribution-aware I/O model scores each candidate, while a bi-level optimiser traces the Pareto
frontier of cost-vs-throughput and then autogenerates Rust code for the chosen design. This
turns what used to be manual knob-twiddling into an end-to-end pipeline that can synthesise
one of 10^48 possible engines and compile it in minutes.
Technically, Limousine identifies the shared first principles behind learned and classical indexes,
introduces algorithms to fix the write inefficiencies of learned components, and builds a
continuum of storage-engine designs spanning AWS, GCP and Azure hardware. Across YCSB
workloads with 10–100 M keys it outperforms RocksDB, WiredTiger, FASTER and COSINE by
up to three orders of magnitude in latency while keeping cost flat, and it adapts gracefully as
data scales or budgets shift. These results demonstrate that automatically crafted, hybrid
engines can dominate fixed designs across the full spectrum of read-write mixes and cloud price
points.

5 Impact
From hyperscale cloud back‑ends to edge devices, the advances described above reverberate
across industry, academia, and everyday technology alike. The ability to conjure a bespoke data
structure in minutes, rather than months of expert tuning, unlocks new economic efficiencies,
accelerates scientific discovery, and lowers the environmental cost of data at scale.
By elevating data‑structure design to a search problem rather than an artisanal craft, the
project lays the groundwork for a future where every application, scientific, industrial, or societal,
can obtain custom‑fit storage and compute with trivial effort. Immediate benefits include:
 ●​ Advancing the discipline. The project provides a unifying lens that explains why classic
 structures behave as they do and how to invent hybrids that outperform them, laying
 groundwork for a future “compiler for data structures”.
 ●​ Energy & cost savings. By collapsing compute-heavy hashing and I/O-heavy storage
 layers, the techniques demonstrated here can halve to order-of-magnitude the server
 footprint for large-scale analytics and AI.
 ●​ Societal reach. Faster, cheaper data processing accelerates progress in biology,
 astronomy, and any field drowning in data; the textbook is already used in graduate
 courses worldwide.

6 Concluding Remarks
Over five years, Data Structure Alchemy progressed from foundational theory to deployable
systems that learn, generate and compile optimal data structures automatically. The
resulting algorithms, artifacts and educational materials position the community to treat
data-structure choice as a solved optimization problem rather than artisanal craft, unlocking
pervasive performance gains and fostering the next wave of data-driven discovery.
