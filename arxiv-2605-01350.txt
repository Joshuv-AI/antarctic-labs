LLM Output Detectability and Task Performance Can be Jointly Optimized
Koshiro Saito, Ryuto Koike, Masahiro Kaneko, Naoaki Okazaki, [0.5em] Institute of Science Tokyo MBZUAI

Abstract
Detecting machine-generated text is essential for transparency and accountability when deploying large language models (LLMs). Among detection approaches, watermarking is a statistically reliable method by design—it embeds detectable signals into LLM outputs by biasing their token distributions. However, it has been reported that watermarked LLMs often perform worse on downstream tasks. We propose PUPPET , a framework that fine-tunes an LLM via reinforcement learning to generate text that is both more detectable and better performing on downstream tasks. We use two reward functions: a detector that outputs a machine-class likelihood and an evaluator that measures a task-specific metric. Experiments on long-form QA, summarization, and essay writing show that LLMs trained with PUPPET achieve high detectability competitive with watermarking methods while outperforming them on downstream tasks. The analysis shows that this optimization can be performed efficiently with only a few thousand samples in 1–2 GPU hours. Moreover, these gains are consistent across out-of-domain tasks, different LLM families, and model sizes, and are even robust to paraphrasing attacks.

Introduction

LLMs now generate so fluent text that humans are almost unable to distinguish it from human-written text
(
45
;
5
;
18
)
.
This raises urgent concerns about misuse, including academic fraud, spam, and automated disinformation campaigns
(
4
;
11
)
.
Therefore, detecting machine-generated text is essential for transparency and accountability.

From a LLM provider’s perspective, it is ideal for LLMs to be both highly detectable and strong on downstream tasks: high detectability supports accountability and misuse tracking, while strong task performance prevents users from exploring less detectable alternatives.

Watermarking

(
19
)
is the de facto standard approach toward this goal—by biasing token distributions at generation time, it enables statistically reliable detection via a hypothesis test with a provably controlled false-positive rate.
However, since this approach optimizes only detectability, the resulting output distribution deviates from what is optimal for downstream tasks, leading to task performance degradation
(
2
;
10
;
42
;
9
)
.
Directly optimizing the LLM for both detectability and task performance simultaneously would address this limitation.

In this paper, we propose
PUPPET

, a framework for training an LLM via Direct Preference Optimization (DPO;
35
) to produce texts that are both more detectable and better performing on downstream tasks.
We use two reward functions: a detector that outputs a machine-generated class likelihood, and an evaluator that measures task performance.
The detector encourages outputs that exhibit features indicative of machine-generated text, while the evaluator encourages the model to produce outputs that improve task performance.
By constructing preference data from a combined score of these rewards and applying DPO, we aim to obtain a model that simultaneously improves both objectives.

Experiments on Llama-3-8B-Instruct
(
12
)
across long-form QA, summarization, and essay generation show that PUPPET achieves comparable or superior detectability while consistently higher task performance, compared to five state-of-the-art watermarking methods: KGW
(
19
)
, SynthID
(
6
)
, Unigram
(
46
)
, EXPGumbel
(
1
)
, K-SemStamp
(
16
)
.
For instance, on long-form QA, PUPPET improves both detectability and task performance by +3.8 and +2.6 points on average over those methods.

Importantly, these gains generalize across out-of-domain tasks and different base LLMs and detectors, and remain robust even to paraphrasing attacks
(
20
)
—a major challenge for watermarking methods.
In addition, PUPPET is practically efficient, requiring only a few thousand samples and 1–2 GPU hours. Finally, our exploratory analysis suggests that the learned detection-relevant features may also support model attribution, i.e., identifying whether a given LLM has been trained with PUPPET.

Proposed Method: PUPPET

Figure
1
illustrates an overview of PUPPET.
We build a preference dataset and apply DPO to the model
\pi
, jointly optimizing both detectability and task performance.
We adopt DPO for its training stability compared with policy-gradient alternatives such as PPO
(
37
)
.
We describe the details of the construction of the preference data in this section.

First, we sample
k
responses
t_{j}\ (j\in\{1,\dots,k\})
from the base model
\pi
for each input query
q
drawn from a query dataset
Q
(this dataset is task-specific):

\{t_{1},\dots,t_{k}\}\sim\pi(\cdot\mid q).

To select “chosen” and “rejected” responses from the candidates, we design two scores to assess the detectability and task performance of a generated text
t_{j}
.
The first is the
detector score
: the probability of the machine-generated class computed by a detector,

S^{\text{Det}}_{j}=p(\text{Machine}\mid t_{j}).

The second is the
evaluator score
: a task-specific evaluation score assigned by an evaluator,

S^{\text{Eval}}_{j}=\mathrm{metric}(t_{j}),

where
\mathrm{metric}(\cdot)
is a task-specific evaluation metric such as ROUGE-L
(
24
)
or LLM-as-a-Judge
(
47
)
.

The two scores are then combined into a final score for
t_{j}
,

S_{j}=\alpha\cdot z\!\left(S^{\text{Det}}_{j}\right)+(1-\alpha)\cdot z\!\left(S^{\text{Eval}}_{j}\right),

where
z(\cdot)
denotes z-score normalization within the
k
samples to prevent either score from dominating due to differences in scale or variance, and
\alpha\in[0,1]
is a hyperparameter controlling the relative emphasis
between detectability and task performance.
Setting
\alpha>0.5
prioritizes detectability; and
\alpha<0.5
prioritizes task performance.

Finally, we build a dataset for DPO,
\{\bigl(q,\ t_{j^{+}},\ t_{j^{-}}\bigr)\mid q\in Q\}
by selecting a chosen response
t_{j^{+}}
and rejected response
t_{j^{-}}
for each query
q\in Q
,

j^{+}=\argmax_{j\in\{1,\dots,k\}}S_{j},\quad j^{-}=\argmin_{j\in\{1,\dots,k\}}S_{j}.

Analysis

We conduct five analyses to further characterize PUPPET:
(1)
generalizability
—whether PUPPET transfers to out-of-domain tasks,
(2)
robustness
—whether PUPPET holds up across the different choices of base LLM, detector, and paraphrasing attacks,
(3)
efficiency
—whether PUPPET can be applied with modest data resources,
(4)
reward ablation
—whether both reward components are necessary for jointly optimizing both objectives,
and (5)
model attribution
—whether PUPPET enables distinguishing its outputs from those of other models.

Related Work

Research on machine text detection can be broadly categorized into two directions:
(1) detectors: utilizing discriminative features of machine-generated text, and
(2) watermarking: embedding detectable features into text during generation.

Detectors

A standard approach involves training supervised classifiers on labeled datasets of human-written and machine-generated text.
RoBERTa
(
27
)
is widely used as the base model
(
38
;
44
;
41
;
23
)
, and the RoBERTa-based OpenAI Detector
(
38
)
is widely used as a benchmark in prior work
(
31
;
21
)
.

A complementary, training-free paradigm exploits statistical properties of the generation process.
DetectGPT
(
30
)
exploits the observation that machine-generated text lies near local maxima of a model’s log-probability surface, so perturbations lower its log-probability, whereas human-written text does not exhibit this behavior.
Fast-DetectGPT
(
3
)
achieves comparable accuracy at substantially lower cost by replacing perturbation-based estimation with conditional probability curvature sampling.
Binoculars
(
14
)
achieves strong zero-shot detection by computing the ratio of cross-perplexity and perplexity between two related models.

Watermarking

Watermarking methods embed detectable signals into LLM-generated text and can be grouped into logit-based and sampling-based approaches.

Logit-based methods
bias the token output distribution at generation time.
KGW
(
19
)
partitions the vocabulary into green and red lists conditioned on the preceding token, and increases the logits of green-list tokens by a fixed
\delta
.
Unigram
(
46
)
simplifies this by using a fixed, context-independent green list, thereby making it more robust to token-substitution attacks.
Both methods introduce systematic distortions into the output distribution, which has been shown to degrade task performance
(
2
;
10
;
42
;
9
)
.

Sampling-based methods
, in contrast, intervene at the token selection stage without directly modifying logits.
EXPGumbel
(
1
)
resamples tokens via a seeded Gumbel distribution, and SynthID
(
6
)
selects tokens through a tournament procedure over multiple random scores.
K-SemStamp
(
16
)
is a clustering-based extension of SemStamp
(
15
)
,
which steers sentence-level generation toward watermarked regions in semantic embedding space.
These methods are generally less disruptive to the output distribution than logit-based approaches, but task performance degradation can still be observed
(
42
)
.

7
Conclusion

We presented PUPPET, the DPO-based framework that trains an LLM to produce text that is both highly detectable and performant on downstream tasks.
By jointly optimizing detectability and task performance, PUPPET matches watermarking methods in detection while surpassing them on downstream tasks—a combination that prior methods, which optimize only one objective at a time, cannot achieve.
These gains generalize to out-of-domain tasks and prove robust to the choice of base LLM, detector, and paraphrasing attacks, all within moderate data and computational resources.
Our exploratory analysis further suggests that PUPPET opens the door to model attribution.

Two directions remain for future work: deeper mechanistic explanations of the acquired detect-relevant features, and systematic hyperparameter tuning—including the relative weighting of the two rewards—which may yield further gains.
We hope this work encourages research into jointly optimizing LLMs across multiple accountability objectives, thereby contributing to more transparent deployment of language models.

Ethics Statements

Detection approaches, including PUPPET and watermarking, are still in the research stage.
Therefore, it is essential to use these techniques with utmost caution under high-stakes settings where false positives (incorrectly identifying human-written text as machine-generated text) may cause significant harm.

Reproducibility Statements

We release the PUPPET implementation on GitHub.
The repository contains the experimental code and configuration files used in this paper, enabling researchers to reproduce our results.
It also provides a refactored implementation to facilitate applying PUPPET to researchers’ own models, data, and tasks.

A.3.2
LLM-as-a-Judge Evaluation

For IELTS, task performance is measured using an LLM-as-a-Judge score on a
[0,9]
IELTS band scale.
We use GPT-OSS-20B
(
32
)
as the judge model with temperature
0.0
and
max_tokens

=4096
.
The scoring prompt is adapted from
43
.

Probability-weighted scoring.

Rather than parsing the generated integer directly, we compute the final score as a probability-weighted expected value over the ten score labels
\{0,1,\ldots,9\}
, following
26
:

\hat{s}\;=\;\sum_{v=0}^{9}\;v\cdot P(v),\qquad P(v)\;=\;\frac{\exp(\ell_{v})}{\displaystyle\sum_{v^{\prime}=0}^{9}\exp(\ell_{v^{\prime}})},

(1)

where
\ell_{v}
is the log-probability of score token
v
as assigned by the judge model.
This yields a continuous score in
[0,9]
and, crucially, produces sufficient variance across the
k=5
preference candidates—a necessary condition for effective DPO training.

Handling the reasoning model.

Because GPT-OSS-20B is a reasoning model, it generates a thinking trajectory before producing the final score token.
To compute token-level log-probabilities conditioned on that reasoning, we proceed in two steps:
(1) we first generate the full thinking trajectory by sampling with a stop sequence that marks the end of the thinking phase;
(2) we then prepend the thinking trajectory and the prefix
“
Score:
” to each candidate score token and extract the corresponding prompt log-probability via vLLM.
This ensures that
\ell_{v}
reflects the model’s judgment after reasoning rather than being estimated unconditionally.
Step (1) may fail to complete the thinking trajectory within the token limit (
max_new_tokens
).
We set the maximum number of retries to 20 and exclude samples whose thinking trajectory fails to terminate.
7
7

7

LLM-as-a-Judge failures were negligible: 3 out of 25,000 judgments (5,000 samples
\times
5 responses) for Llama-3 and
1 out of 25,000 for Qwen3. The corresponding samples were excluded from preference pair construction.

A.5

The span visualization in Figure

shap
library
8
8

8

https://github.com/maciejskorski/shap

Detector-salient spans (red).

We compute SHAP values for the OpenAI Detector with respect to class 0 (Machine).
Only the positive component of each token’s SHAP value is retained (

To normalize scores comparably across conditions, we compute a shared upper bound
