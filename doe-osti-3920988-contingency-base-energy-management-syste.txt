 Abstract
 Contingency bases, also known as expeditionary bases and forward operating bases, are used
 by the Army at temporary sites to allow military forces to perform expeditionary warfare,
 humanitarian efforts, and disaster relief. Because of their remote locations, contingency bases
 are often powered by generators, which require a considerable amount of fuel. The high cost of
 delivering fuel to these sites, along with the risk to personnel delivering that fuel, makes energy
 efficiency a high priority.

 The Contingency Base Energy Management System (CB-EMS) is a software application that
 enables the camp manager to monitor camp energy operations and identify issues that can
 cause excessive energy consumption. It also gives camp managers real-time visibility of the
 fluid levels for all camp fuel and water tanks, as well as the consumption to estimate how long
 the current reserves will last. Instrumentation throughout the camp provides information to the
 system. These include the structure temperature, energy usage, and generic metering to
 monitor other parameters. Generators are monitored for performance to maintain system
 efficiency. Solar photovoltaic arrays are monitored by CB-EMS to allow efficient operation of
 those resources.

 CB-EMS is built using Ignition by Inductive Automation as the Supervisory Control and Data
 Acquisition (SCADA) platform. Ignition runs using Java within their Vision Client Launcher. CB-
 EMS uses instrumentation throughout the camp to create an energy “dashboard” to enable the
 camp manager to view the camp and identify areas where the camp is outside operational
 guidelines.

 This user manual is intended to enable camp managers to work with the system. A separate
 manual for the CB-EMS administrator details how the camp dashboard is configured for a new
 site and how to apply changes to an existing site, and a third manual is provided to document
 how to set up a new system head end.

 1.0 Introduction
 The Contingency Base Energy Management System (CB-EMS) is a government-owned expert
 system designed to integrate site operations and energy management at contingency bases.
 Contingency bases, or base camps, are non-enduring locations outside the United States that
 support and sustain operations during contingencies or other operations and are categorized by
 mission life-cycle requirements as initial, temporary, or semipermanent. CB-EMS enables base
 camp managers to operate and manage their camps in the most effective and efficient manner.

 CB-EMS provides detailed information on camp operations that allows the camp manager to
 identify issues related to important functions such as power, fuel consumption, water
 consumption, and equipment maintenance. The main “dashboard” screen provides a quick
 visual representation of the camp and highlights areas that are outside operational parameters.
 Once an issue is identified, CB-EMS provides the camp manager with detailed information that
 enables them to identify the problem and act accordingly. CB-EMS also monitors fuel and water
 supplies, offers the camp manager an indication of how much of these resources the camp is
 consuming, and predicts the amount of time left before the available fuel and water are
 consumed.

 When deployed, CB-EMS provides detailed information for the camp manager to run the base
 efficiently. In addition to reducing energy use (and thus energy consumption) at the camp, it also
 provides the following benefits:
 • Fuel and water consumption information improves camp readiness
 • Efficient operation of generators extends equipment life
 • Maintenance staff workload is reduced
 • Maintenance parts and labor costs are reduced

 CB-EMS is designed to be user configurable to allow the CB-EMS administrator to add new
 resources during operations and remove them as the camp changes. This plug-and-play
 capability allows the software to be customized on the fly as the camp changes. Separate
 manuals for the CB-EMS administrator and user provide instructions for changing the camp
 dashboard as equipment is added or removed from the camp.

Introduction 1

 2.0 Architecture
 CB-EMS uses Ignition by Inductive Automation to provide the graphics to display data, organize
 the connections to the equipment providing signals, and manage the database to store data.
 Ignition is compatible with several commercially available databases. Microsoft (MS) SQL
 Server was selected for CB-EMS because of its ease of use and the security available within
 the software. Most CB-EMS head end systems will use MS SQL Server Express, which can be
 installed free of charge. In some cases, the full MS SQL Server will need to be installed, and
 that process is nearly identical to the process for MS SQL Server Express covered here.
 MySQL was also implemented for and only used at one test site. This installation manual will
 not cover the installation of that option.

 The information contained in this manual related to installing Ignition and Installing MS SQL
 Server can also be found in the documentation for Ignition. It is provided here for convenience.

Architecture 2

 3.0 Installation Media
 As mentioned above, installing CB-EMS requires installing both MS SQL Server and Ignition,
 which are available from Microsoft and Inductive Automation, respectively. Once those two
 applications are installed, the CB-EMS database must be installed on the system; then, both
 software packages must be configured to communicate with each other. Finally, the CB-EMS
 project must be restored to the Ignition gateway for the software to operate.

 The files listed below are provided to install CB-EMS on a new head end unit. Newer versions of
 the software can be installed, and the process should be very similar.
 • Ignition-8.3.8-windows-64-installer.exe. The most recent installation media for Ignition as of
 this writing and is required for CB-EMS to operate.
 • SQLEXPR_x64_ENU.exe. The SQL Express installer for version 17.0. Newer versions can
 be installed, but version 17.0 was the last to provide an easy offline installer.
 • SSMS-Setup-ENU.exe. The installer for SQL Server Management Studio (SSMS) version
 21.0. This is the last version available with a simple offline installer as of this writing. Newer
 versions should work fine, and the installation process should be similar.
 • Sqljdbc_9.4.0.0_enu.zip. This contains the Java Database Connectivity (JDBC) files
 required for Ignition to use Windows Security for access to the database.
 • CB-EMS_30.gwbk. The gateway backup file that contains the CB-EMS software. It’s used
 during the installation to install the CB-EMS project on Ignition.
 • CBEMS_dB.bak. Backup file of a blank CB-EMS database. It is used to restore the
 database on a new CB-EMS install.
 • SSHQuery.zip. This contains the program that connects to the radios via SSH to gather
 connection strength information.
 • dotnet-runtime-8.0.26-win-x64.exe. Installer for Microsoft .NET runtime 8.0. This utility is
 required for the SSHQuery software to run.

 10.0 Radio Signal Check Software
 The radio signal check feature was added using a separate program to perform the SSH
 connection to the radio to obtain signal status information. That software is installed by copying
 the program to a specific directory on the server and also installing MS .NET version 8.0.

 10.1 MS .NET Installation
 Installing MS .NET 8.0 can be done by simply executing dotnet-runtime-8.0.26-win-x64.exe
 provided with the installation software and pressing Install (Figure 61).

 Figure 61. MS .NET installation.

 10.2 SSHQuery Install
 The SSHQuery program is executed from CB-EMS periodically to check the radio signal status.
 The results of the query are read by CB-EMS and stored in the database for analysis. To install
 the program, extract the files located in the SSHQuery.zip file into the C:\ directory. This can be
 done from Windows by right-clicking on the file and choosing Extract (Figure 62).
