Abstract
. Multi-stage programming with quotations has long provided a powerful way to generate and manipulate code. By treating code as data, programmers can write multi-stage programs in which earlier stages produce specialized code from inputs available at generation time. Modern typed multi-stage languages ( e.g. , MetaML, MetaOCaml, Template Haskell, and Scala 3) adopt quotation/splicing constructs while enforcing the well-typedness of generated code. Introduction

Semantics-Breaking Staging Annotations

Despite the expressive power and popularity of MetaML-style syntactic MSP, multi-stage programs
are notoriously difficult to reason about

Unlike the name “annotations” might suggest, staging annotations are not just

Staging annotations are syntactic in nature, but they can rearrange the
evaluation order of programs, which can lead to inconsistent behaviors between

Why it Matters?

To summarize, these examples show that, because syntactic staging annotations
permit evaluation to be rearranged, they can arbitrarily discard, reorder, or
duplicate effects.
Although such a flexibility can be useful for program manipulation in some cases,
we lose the ability to relate the staged program with the unstaged program,
thus weakening semantic predictability and making staged
programs much harder to reason about.

This is particularly hindering performance-driven uses of staging,
such as Futamura projections
(
24
)
and domain-specific
compilers
(
58
;
61
;
63
;
64
)
,
where the
goal is precisely to obtain faster code without changing the
observable behavior of the original unstaged program
.
In such settings, if annotations do not preserve semantics,
the unstaged program cannot be treated as a reference
specification from which one derives a faster but semantically equivalent staged
version merely by inserting staging annotations,
therefore the generated program cannot be used as drop-in replacement for the original
unstaged program.

The key property connecting a staged program and its unstaged
counterpart is known as
erasure soundness

(
30
;
29
;
71
)
or semantics preservation of staging.
Although it was recognized as an important property
(
30
;
29
)
,
MetaML-style CBV staging unfortunately does not enjoy this property in general.
In fact, staging in CBN calculi is better behaved, since the semantics of
quotation remains aligned with the underlying CBN semantics

(
29
;
30
;
56
)
.
However, adding staging annotations to a CBV language breaks the host language’s
equational theory
(
29
;
30
)
.
As a result, the standard reasoning principles for CBV programs can no longer be
assumed to apply to staged programs.

“When Do We Know That Erasing Annotations Preserves Semantics?”

Nevertheless, erasing staging annotations does preserve semantics for certain
classes of staged programs. This raises a natural question from

29
;
30
: “
when do we
know that erasing annotations preserves semantics
”?
They partially answered this question by developing applicative bisimulation techniques
for proving the equivalence of
specific
staged programs and their
unstaged counterparts. However, these techniques require substantial manual
proof effort and remain program-specific: they do not yield a general
erasure-soundness guarantee for the language as a whole.
This leaves a fundamental open question: can we still obtain stronger semantic
guarantees other than well-typedness of generated code for a call-by-value
staging language?

To shed light on this question, let us turn to practical staging languages and
frameworks. They often adopt
let-insertion

(
23
)
as a remedy, which has long been used in
partial evaluation for effectful programs
(
34
;
18
;
41
;
19
;
21
)
.
The idea is to introduce let-binding at the right places to force the evaluation
and intended effects of a code fragment to happen, and then refer to the
let-bound variable in the rest of the code.
In this way, let-insertion preserves both effects
and
their relative
evaluation order (see
Section

2
for illustrative examples).
MetaOCaml
(
39
)
supports

ad-hoc
let-insertion through the primitive
genlet
, which allows the
programmer to explicitly indicate let-insertion.
By contrast, LMS in Scala
(
47
;
48
;
50
)
provides

automatic
let-insertion uniformly for code fragments, relieving
programmers from having to mark such insertion sites manually.

One may then ask whether an
automatic let-insertion
staging semantics
makes staged programs easier to reason about. More specifically, does it
guarantee semantics preservation of staging?
After all, let-insertion is widely used in practical staging systems precisely
because it is believed to help preserve the intended semantics.
Answering it, however, requires a formal account relating three artifacts: the
staged program, the code it generates, and its unstaged counterpart. Despite
substantial research in MSP on typing, hygiene, and intensional analysis,
this relational property has received far less attention.
As a result, whether let-insertion in MSP provides stronger reasoning principles
or semantic preservation remains folklore.

This Work

To gain a rigorous understanding of the semantic guarantees provided by
let-insertion, this paper develops novel typed staging calculi featuring

automatic let-insertion
and investigates their metatheory.
We summarize the main results below;
Section

2.2
provides an
overview for key ideas in our calculi, while the remainder of the paper
develops the formal theory.

Following
29
;
30
, we begin
with a pure setting without side effects, while still allowing divergence. In
this setting, we introduce
\lambda_{\mid\mathsf{2}|}
, a call-by-value, statically typed, two-stage

\lambda
-calculus with general recursion and automatic let-insertion (
Section

3
).
Its reduction semantics follows
3
’s
untyped
\lambda_{\uparrow\downarrow}
-calculus, which already captures let-insertion
operationally (
Section

3.2
).
We develop a novel type-and-effect system for automatic let-insertion
(
Section

3.3
), where
the key idea is to treat code generation as a control effect in the first stage
and to distinguish complete code values from intermediate code fragments.

We then develop the metatheory of
\lambda_{\mid\mathsf{2}|}
. Our type-and-effect system is crucial
for establishing syntactic type soundness via progress and preservation
(
Section

3.4
).
We formally define the erasure operation and show the erasure preserves syntactic
typing (
Section

4
), which is a prerequisite for semantics preservation.
We further prove the semantics-preservation theorem for staging and erasure (
Section

5
).
The central technical tool is a binary Kripke logical relation for the two-stage
calculus: we show that if a well-typed two-stage program
t_{1}

evaluates to code
t_{2}
, then
t_{2}
is contextually equivalent to the erased
term
|t_{1}|

|\cdot|

Thus, in
\lambda_{\mid\mathsf{2}|}

This directly answers the question posed by
29
;
30

erasing annotations in
\lambda_{\mid\mathsf{2}|}
always
preserves semantics
.

Beyond its theoretical significance, our result allows the unstaged
program to serve as a faithful reference specification for the generated program under
the standard CBV semantics. Therefore, programmers can introduce staging
annotations for performance without worrying that they will silently alter the
program’s meaning.
This guarantee is also essential leading to stage-polymorphic programming

(
3
;
27
;
44
)
, where programmers can abstract over stages
and write stage-generic code that behaves uniformly regardless of staging
annotations.

Next, we introduce ML-style mutable references in order to study the interaction between
let-insertion and store effects (
Section

6
). Here the picture is mixed. On the negative
side, unrestricted mutable references break erasure soundness: because staging
may evaluate under second-stage binders or conditional branches, first-stage
store effects can arise that are not preserved by erasure (
Section

6.1
).
On the positive side, we show that erasure soundness can still be recovered for
a broad class of staged programs by restricting mutable references to the second
stage.
We formalize this result in
\lambda^{\mathsf{ref}}_{|\mathsf{2}|}
(

6.2

\lambda_{\mid\mathsf{2}|}

both syntactic type soundness and erasure soundness for it (
Section

6.3
).
This result remains significant in its own right, since manipulating effectful
generated code is one of the central use cases for staging.

At the same time, our study proposes
a challenging open question: how to support more expressive first-stage store effects while
retaining erasure soundness. We discuss the obstacles and possible directions (
Section

7
),
and hope this work will serve as a foundation for future progress on
semantics-preserving staging.

Finally, all calculi and their metatheory results are mechanized (
Section

8
) in
Lean 4
(
20
)
.

Contributions and Organization

The main contributions of this paper are threefold:

•

To the best of our knowledge, no prior work has developed a typed,
semantics-preserving staging calculus with a mechanized erasure soundness proof.
We close this gap and answer the open question raised by

29
;
30
by developing
the first typed CBV multi-stage calculi (one with divergence and one with mutable references),
with mechanized erasure soundness proofs.

•

We develop a novel type-and-effect system for automatic let-insertion.
The key idea is to treat code generation as a control effect, while
distinguishing complete code values from intermediate code fragments.

reusable foundation for future work.

2.2.
Key Ideas and Main Results

In the example above, the let-inserted staged
power
clearly generates code
semantically equivalent to the reference implementation, namely the unstaged
power

function.
However, formally establishing this property is far from trivial, especially in the
presence of the subtle interactions between staging annotations and effects.
While such equivalence can sometimes be shown for individual examples, the
real challenge is to understand, in general, when a staged program generates
code that preserves the semantics of its unstaged counterpart.

Our approach is to develop staging calculi with automatic let-insertion and
to study erasure soundness as a relational property in the metatheory, captured
by binary logical relations.
Our results connect staged and unstaged programs via

erasure
, and connect generated code with unstaged programs via
contextual equivalence.

Figure

Below, we present the key ideas behind our calculi
and give an overview of our results.

Syntax and Dynamic Semantics

The
\lambda_{\mid\mathsf{2}|}
- and
\lambda^{\mathsf{ref}}_{|\mathsf{2}|}
-calculi share the same foundation of syntax and semantics, with
the latter extending the former with ML-style mutable references.
Unlike MetaML-style staging languages using quotations/splices as
surface syntax, our calculi follow the two-level syntax
(
43
)
,
in which each syntactic construct (such as application) has a distinct second-stage counterpart.
This design is also known as combinator-based staging

(
31
;
35
)

Type-and-Effect System

Although automatic let-insertion has been formalized in prior work
(
3
)
,
a type system that guarantees type soundness is new in this work.
Keeping erasure soundness in mind, the challenge is that code fragments cannot be
treated as ordinary pure values: they cannot be duplicated, reordered, or discarded arbitrarily.
A simply typed system cannot rule out programs that violate these constraints.
This issue is particularly acute for effectful second-stage code, whose
let-insertion points must precisely preserve effects and evaluation
order.
For example, consider the following program, which attempts to construct second-stage

To rule out such programs, we develop lightweight type-and-effect systems for

named by code variables; they are therefore pure (

Intermediate code fragments, by contrast, have not yet been reified into
second-stage bindings and thus cannot be treated as unrestricted values.
Instead, the type system tracks their pending reification explicitly through an
effect flag that records let-insertion effects.

Metatheory

By combining a first-stage effect system with a type-level distinction between
complete code values and intermediate code fragments, we obtain a simple and
robust foundation for proving syntactic type soundness,
i.e.
, progress and
preservation, which further ensures that the generated program
is also well-typed.

Our main technical contribution is the semantics-preservation theorem relating
staging annotations to their inverse operation, erasure.
To show that, instead of reasoning about the staged program itself,
we can just reason about the result of such a staged program, namely
the generated code, and its equivalence with the erased program.

Informally, the theorem (
Section

5
) states that if a well-typed
two-stage program

To prove this result, we develop a binary (step-indexed) Kripke logical relation
that captures contextual equivalence across let-inserting reduction steps.
To the best of our knowledge, this is the first use of binary logical relations
to reason about staging semantics and relate generated code to its erased
counterpart.

Extending with Store Effects

The base calculus
\lambda_{\mid\mathsf{2}|}
already admits divergence, and we show that
let-insertion preserves semantics with respect to staging annotations and their
erasure even in its presence.
In this sense,
\lambda_{\mid\mathsf{2}|}
supports strong call-by-value reasoning principles for
multi-stage programming.
At the same time, contrary to the common intuition that let-insertion ensures
semantics preserving in the presence of arbitrary effects, we show that
let-insertion alone is not enough once mutable references are introduced.

To study this interaction, we extend

In

Designing a type-and-effect system expressive enough to reject the former while
admitting the latter is a challenging open problem and beyond the scope of this paper.
Instead, this paper lays the foundation for that direction by proving that
semantics preservation by let-insertion still holds when store effects are
restricted to the second stage.
This is still a useful result, as it allows programmers to soundly
manipulate effectful code, which is common in practice.
By adapting both the reduction semantics and the logical relation to this
setting, we prove the semantics-preservation theorem for

We prove that

Progress

Our type system is crucial for progress: many terms can get stuck in the

As in typical staging calculi,

We prove a stronger statement which implies the standard progress theorem to strengthen the

\Gamma\vdash t:\tau\mid\epsilon
.

We are required to show that either

t
is a value
v

t^{\prime}
such that

t\to t^{\prime}
.
By induction on the typing derivation. Most cases follow from the inductive hypothesis.
∎

Theorem 3.4 (Progress).

If

5.3.
Semantics Preservation of Staging

Overview

We now state the central theorem of

To prove this result, we first establish a stronger invariant: semantics are

Here we rely on the soundness of the logical relation
(

From this single-step result, multi-step preservation follows.
Combined with transitivity of contextual equivalence,

).

Semantics Preservation of Single-Step Reduction

7.
Open Questions and Future Work

We have presented
\lambda_{\mid\mathsf{2}|}
and
\lambda^{\mathsf{ref}}_{|\mathsf{2}|}
, along with their type soundness and semantic
preservation results.
A central open question is whether one can design an expressive multi-stage
language with flexible store effects while still preserving semantics.
As discussed in
Section

6.1
, the main obstacle is that
\lambda_{c}
-terms
and 2nd-stage conditionals cease to be evaluation contexts after erasure,
so two-stage evaluation may produce store effects absent from the stage-erased
program.

Still, it is not entirely hopeless.
Whereas
\lambda^{\mathsf{ref}}_{|\mathsf{2}|}
enforces a strong
syntactic purity
in the first stage,
a more flexible alternative is to enforce
semantic purity

(
51
;
4
)
,
allowing store effects that are guaranteed not to interfere with staging.
For example, lifting a
\lambda
-term with encapsulated local store effects is
benign with respect to contextual equivalence.
This suggests a promising direction by adopting recent Rust-style
resource-tracking type systems

(
10
;
62
;
42
;
5
;
69
)
:
ensure that the store reachable during first-stage evaluation is disjoint from
the store used by
\lambda_{c}
-terms.
Under such separation, non-interfering effects could remain semantically
invariant even under reordering, duplication, or omission.
Related ideas already appear in the literature of partial evaluation,
e.g.
,

21
infer binding-times based on
regions, which are disjoint sets of stores leading to non-interfering effects.

For conditionals, one could similarly require the locations reachable from the two
branches to be disjoint, so that the order would not matter.
Another possible approach, at the cost of code duplication, is polyvariant
specialization: branches together with their
shared continuations are specialized under different stores
or more fine-grained stack-like structure of stores
(
21
)
.

More than a decade ago,
29
observed that
“imperative MSP is not yet ready” for a study of erasure soundness.
In light of recent advances in resource-tracking type systems, we believe it is
now within reach to design a flexible, semantics-preserving imperative MSP.
The design space of semantics-preserving imperative
MSP has not been fully explored, and we hope the present work can serve as a
stepping stone toward that goal.

Extensions

\lambda^{\mathsf{ref}}_{|\mathsf{2}|}
models second-stage first-order mutable store for simplicity,
however, it is straightforward to extend it to support second-stage higher-order store.
Such an extension for the logical relation would require adapting the world model
following the literature
(
1
;
2
)
.

This paper focuses on the two-stage setting, which already suffices for many
practical applications and lays the foundation for extending to more stages.
It is possible to build a binary logical relation
to reason about
N
-stage programs (
N>2
), where
our logical relation can be used to reason about the final stage and the generated code.
It is interesting future work to develop semantic typing
(
60
)
or logical relations
for code types.

\lambda_{\mid\mathsf{2}|}
’s context decomposition
P[E[\mathsf{reflect}~t]]
uniquely decides the position to
insert let-bindings.
Although semantically correct, it is not the only possible way to perform code
motion. It is also not always necessary to let-insert pure computations.
A finer-grained effect system tracking dependency
(
11
)

could be used to inform more flexible let-insertion strategies.

Locally Nameless with de Bruijn Levels

Variables are represented in the locally nameless style

(
14
)
: free variables use de Bruijn levels and
bound variables use de Bruijn indices.
Using de Bruijn indices for bound variables simplifies the generation of fresh
variables in let-insertion and avoids
\alpha
-equivalence.
Unlike some other locally nameless approaches, we use de Bruijn levels rather
than explicit names for free variables, which simplifies the introduction of new
free variables during typing.

Level-Indexed Reduction and Contexts

Because reification contexts introduce second-stage bindings and can be plugged
into terms in which second-stage variables occur free, our reduction relation is
indexed by the current de Bruijn level.
Evaluation contexts also track the current de Bruijn level, and their levels
inform the reduction relation.
For example,
\lambda_{\mathsf{c}}x.\,\square
increases the current level by one
when entering its body.
At the top level, the well-formed levels of reduction and evaluation contexts are 0.

Deterministic Memory Allocation

Without loss of generality, we simplify the design of our store in the
formalization by modeling it as a stack rather than a heap. Our locations start
at 0 and increment continuously with each allocation. This simplification still
ensures that the properties we aim to discuss remain sufficiently strong.

Related Work

Staged Programming

MetaML-style staging languages
(
57
;
56
;
37
;
65
)

support syntactic annotations,
brackets
,
escape
and

run
, which could alter the evaluation order of programs.
Unlike MetaML, LMS
(
47
;
50
)
relies on operator overloading from the host
language, and uses an internal
graph IR to track dependencies and to schedule generated code.

3
introduced the untyped multi-stage

\lambda_{\uparrow\downarrow}
-calculus with automatic let-insertion
to model the semantics of LMS-style staging.
Building on
\lambda_{\uparrow\downarrow}
’s foundation, we restricted it
to a two-stage setting, developed a sound type system, extended it to support
side effects, and proved the semantics preservation.
Although it is folklore that LMS-style staging preserves semantics,
this work examines the precise conditions when it does and does not.

Let-Insertion in Staging and Specialization

Let-insertion
(
21
;
18
;
32
;
41
;
26
)
has a long history used in partial evaluation
for sound specialization of effectful programs.

21
developed partial evaluation with let-insertion for higher-order languages
with mutable states; a region type system is used to infer binding times.
In more recent staging systems,
BER MetaOCaml supports the
genlet
primitive
to explicitly indicate let-insertion
(
39
)
,
relying on delimited control operators
(
36
;
16
)
.
Similarly,
33
;
34

combined delimited control with code generation and let-insertion.
LMS
(
47
;
50
)

systematically performs let-insertion via its graph IR
(
11
)
,
requiring no explicit indication from programmers.
Squid
(
45
;
46
)

also uses an A-normal form
(
23
)
IR for object code.
In our calculi, we do not explicitly use delimited control operators, but
the underlying phenomenon of let-insertion is indeed a control effect and captured
by the type-and-effect system.
Similar to our type-and-effect system, MetaOCaml’s let-insertion
also distinguishes general code fragments and object-code variables
returned by
genletv
, yet it has not been formally examined with
mechanization as we showed in this paper.

In principle, MetaML-style staging can simulate behavior similar to
our calculi by inserting
genlet
ubiquitously.
However, rather than permitting unconstrained staging behavior as in MetaML,
we argue that semantics-preserving staging semantics is a more
disciplined and predictable default.
Programmers can always opt out explicitly when necessary, much like
unsafe
in Rust.
This design makes potentially semantics-breaking behavior visible and
intentional, instead of leaving it implicit.
In practice, staging libraries such as LMS take this approach as well,
relying on the host-language Scala’s by-name arguments to support code duplication.

Reasoning Multi-Stage Programs and Partial Evaluation

In the literature on partial evaluation,

22
showed that TDPE is sound and complete for a call-by-name, pure
\lambda
-calculus.

32
proved the correctness of partial evaluation
Lambdamix, which features general recursion.

41
proved the soundness of
on-the-fly let-insertion, but did not address the issue
of performing effects at specialization time (as we discussed in
Section

6.1
).

30
;
29
used applicative
bisimulation to reason about
\lambda^{U}
-calculus; they showed that semantic
preservation under CBV cannot be achieved even
without
imperative features
such as mutable states.
We use step-indexed Kripke logical relations, which can be combined with
bisimulation techniques
(
28
)
.

40
developed
a two-level type theory (2LTT) and
staging-by-evaluation with dependent types to model staged computation,
where staging is given by the evaluation of 2LTT syntax in a semantic domain.

40
also proved the conservativity
of 2LTT.

71
was the first to propose the
erasure soundness

property, and regarded it as a criterion of “semantic correctness” for code
generation, complementing the “syntactic correctness” guarantee of well-typed
generated code. He proved erasure soundness for a CBN two-level
language without mutable state, and identified duplication of effects as the key
reason why a naive CBV two-level language fails to preserve semantics.
Although let-insertion was proposed as a potential solution,
a formal treatment or proofs were not provided in his work.

Independently and concurrently with this work,
66

mechanized an LMS-like calculus and proved a similar semantics-preservation
theorem in Agda. Although the top-level theorems are similar, there are several
key differences: First, we use a small-step reduction semantics, whereas

66
follows the big-step stateful semantics of

50
. Second, our calculi model both divergence and
store effects, whereas the calculus of
66
requires
strong normalization and does not include store effects. Finally, the proof
techniques differ: we use Kripke-style binary logical relations that do not
directly model code types, whereas
66
directly
incorporates the equivalence between a two-stage term and its generated code
into the value-type relation for code types.
A more detailed comparison between the two works is left to future work.

10.
Conclusion

In this paper, we answer the question posed by
29
:
when do staging annotations preserve the semantics of the underlying
single-stage program?
To this end, we design the
\lambda_{\mid\mathsf{2}|}
- and
\lambda^{\mathsf{ref}}_{|\mathsf{2}|}
-calculi that
support automatic let-insertion and include a lightweight
type-and-effect system for tracking code-generation effects.
Our main results establish syntactic type soundness via progress and
preservation, and semantics preservation via step-indexed Kripke logical relations.
We believe that the design of these calculi, together with their mechanized
semantics-preservation proofs, fills a long-standing gap in reasoning about
multi-stage programs using modern logical-relation techniques.
We hope this work serves as a solid foundation for future developments in
expressive, reliable, and semantics-preserving multi-stage languages.
