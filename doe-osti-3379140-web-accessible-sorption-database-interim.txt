1 INTRODUCTION
This progress report (Level 4 Milestone Number M4SF-26LL010204053) summarizes research
conducted at Lawrence Livermore National Laboratory (LLNL) within the Crystalline Host Rock
Properties & Processes - LLNL Number SF-26LL01020405. This research is focused on the
development of a web-accessible database of sorption data for minerals and rocks (bentonite
backfill and crystalline host rock) that are likely to be present in a US hosted repository, including
elevated temperature data that are expected in a DPC DGR scenario.
The Livermore Surface Complexation Ion Exchange (L-SCIE) sorption database has been in
development for a number of years in support of the US nuclear waste repository program. It is
composed of a series of linked tables and, in 2025, was transformed from a Microsoft Access©
database to an open source MariaDB© SQL relational database. The details regarding the structure
and content of the database have been described in the past (Zavarin et al., 2022) and the general
structure remained unchanged when converting to the MariaDB format. Nevertheless, it is important
to note some key properties that represent the basis for the collection of data in L-SCIE:
• The data in L-SCIE are focused primarily on synthetic and mined mineral phases with a strong
emphasis on simple binary sorption data. However, recent additions have included bulk rocks
relevant to the nuclear waste program (granite, shale, etc.)
• The database is composed of original data extracted from journal manuscripts, “grey literature”
reports, or other digital databases available in the community.
• Data are stored in their original form (no unit conversions performed) and directly linked to the
manuscript and the associated tables and figures from which the data were extracted.
• The data are not screened through any type of data quality process.
• All data processing/transformation is performed external to the database via R and Python codes
and associated workflows.
• Links to geochemical modelling codes and optimization algorithms used to develop models
based on L-SCIE data are integrated with but external to the database.
• All L-SCIE database products are freely available, follow the FAIR principles (Wilkinson et al.,
2016), and adhere to the Open Science philosophy (https://github.com/mzavarin/L-SCIE).
This fiscal year, the L-SCIE database reached a milestone and now contains over 100,000 sorption
data. Recent major additions to this database, beyond the manual extraction of data from the
literature, were the inclusion of approximately 2,500 clay sorption data that were provided through a
collaboration with the research group at the Paul Scherrer Institute (Marinich et al., 2023), 61,000
data (out of 70,000 total) that were extracted from the online sorption database supported by the
Japanese Atomic Energy Agency (JAEA, 2025), 10,000 data that were provided through our
collaboration with the SOREDA/RES3T team at the Helmholtz-Zentrum Dresden-Rossendorf (Brendler
et al., 2003; Bok, 2025) and 5,000 data that were digitized at MIT (H. Wainwright) and Clemson
University (B.A. Powell). It should be noted that the JAEA data are stored separately from the core L-
SCIE database but reformatted and transformed to be compatible with L-SCIE.
While the sorption data extracted from literature figures and tables are stored in L-SCIE using the
original units and nomenclature (e.g. ppm, % sorbed, atoms/nm2), a code, written in R, is used to
perform all the necessary unit conversions to yield a standardized data file in which sorption data
and associated metadata (i.e. solution conditions, mineral characteristics, etc.) are all uniformly
formatted. In addition, parameter uncertainties are reported (if available) or estimated based on
estimates of experimental uncertainty and/or uncertainty associated with data digitization from

August 19, 2026                                                                                          3

figures. The “unified” datafile then becomes the source of all downstream modeling efforts
described below.
As part of the L-SCIE development effort, a number of publications are in preparation. Han et al.
(submitted) describes the development of machine learning algorithms trained on the L-SCIE
database to determine Kd values, associated parameter uncertainties, and prioritize experimental
data collection activities given specific solution conditions. Han et al. (in prep) tests an automated
mechanistic surface complexation modeling tool for expedited surface complexation database
development. Eguiguren et al. (Accepted) presents a new automated modeling workflow that
incorporates the CrunchFlow modeling code and ion exchange parameters into a fitting routine
linked to the L-SCIE database.

2 WEB-BASED INTERFACE TO EXTRACT SORPTION DATA FOR USE IN
 PERFORMANCE ASSESSMENT
Our primary goal this fiscal year was to develop a simple and web-based interface that would allow
users to interrogate the database and yield relevant sorption parameters for direct use in
Performance Assessment modeling. Based on guidance from the program, an open web-based
platform was not pursued. Instead, we developed a standalone code with a simple user-friendly
web-like interface that allows users to interact with the L-SCIE database. The interface does not
require users to have any python or database background to perform the data extractions. The
python code is provided here as an Appendix.

This Python code is a data preparation and distribution-fitting workflow for the L-SCIE sorption
database. It begins by loading a merged CSV file containing sorption measurements, then cleans up
the Sorbate and Mineral fields so that naming is more consistent for downstream grouping and file
creation. In particular, it removes spaces, replaces slashes with periods, and applies a few specific
nomenclature corrections so that equivalent or commonly conflated materials are treated
consistently.

Next, the code computes log(Kd, mL/g) for every record using the sorbed concentration, aqueous
concentration, and mineral loading. It also calculates ionic strength for each row by mapping
electrolyte names to charges from a separate lookup table and combining the charge and
concentration contributions of up to 13 electrolyte species. This creates a standardized chemistry
descriptor for each observation, which is then used later as one of the filtering criteria.

The script also flags whether CO2 is present in the sample conditions. It does this by searching the
electrolyte and gas columns for carbonate-related terms like C(+4) and CO2(g), then storing the result
in a boolean CO2? column. At the same time, it applies additional cleanup rules, such as replacing
smectite with montmorillonite, converting silica and SiO2 to quartz, and correcting misclassified
rocks, minerals, and sorbates.

After the data are standardized, the notebook removes entries that are not relevant for the intended
Kd analysis, including potentiometric titration data and any records with missing log(Kd) values. It
then exports the cleaned data into separate CSV files for each unique sorbate-mineral pair. This first
export step creates a large set of individual datasets, each corresponding to one radionuclide,
oxidation state, and mineral combination. The user can readily identify the source of all data using
the reference ID column that is included in the data export.

The second half of the notebook is an interactive modeling step. A small Tkinter window (Figure 1)
asks the user to enter ranges for pH and ionic strength and to choose whether CO2-bearing systems

August 19, 2026                                                                                          4

should be included, excluded, or ignored. The dataset is then filtered according to those criteria, and
only sorbate-mineral pairs with at least five observations are retained for downstream model fitting.
For each subgroup, the code writes out a filtered CSV, computes summary statistics, and fits either a
triangular or uniform distribution to the log(Kd) values after removing outliers by the 1.5 InterQuartile
Range (IQR) rule.

Model selection (triangular vs. uniform) is based on both sample size and goodness-of-fit. The code
uses a Kolmogorov-Smirnov test to judge whether the triangular fit is acceptable, and if the p-value is
too low or the cleaned sample size is too small, it falls back to a uniform model. For each group, it
saves a plot showing the histogram of observed values together with the fitted probability density
function, and it records the fitted limits, mode when applicable, p-value, and sample counts in a
summary table that is exported as model_statistics.csv. The result is a reusable pipeline for cleaning
sorption data, conditioning it on geochemical constraints, and generating simplified probabilistic
models for each mineral-radionuclide pair. An example graphical output for radionuclide sorption to
granite in the pH range of 7 to 9, ionic strength ranging from 0.01 to 0.1, and in the presence of CO2
is plotted in Figure 2. The values, source information, and model statistics are all available via
exported CSV files for further analysis.

3 APPLICATION OF L-SCIE DATA EXTRACTION TOOL FOR PERFORMANCE
 ASSESSMENT MODELING OF A SHALE REPOSITORY
As part of a broader FY26 effort to develop a repository concept for shale rock and a test case for our
approach, we applied our new data extraction tool to directly link radionuclide retardation in
Performance Assessment using the L-SCIE database. For the repository concept in shale rock and to
extract appropriate Kd data from L-SCIE, a model groundwater chemistry must be identified. We
used water chemistries that were developed at Sandia National Laboratories to represent three
mineralogically distinct geologic units that may be present in a shale deposit: chalky marl,
sandstone, and primary shale (Table 1).
Radionuclide sorption (log(Kd, mL/g)) values were estimated from data contained in LLNL’s L-SCIE
sorption database. For the purposes of this data extraction, we selected radionuclides that have
been identified as important potential contributors to the performance of a nuclear waste repository
(Am, Ac, Cl, C, Cs, I, Np, Pu, Ra, Se, Sn, Tc, Th, U) and particular focus was on oxidation states
relevant to reducing conditions (though some data for oxidizing condition are also provided).
Some general L-SCIE data filtering and processing was performed as part of the data extraction
workflow:
 • Ionic strength was calculated based on the background electrolyte composition associated
 with each sorption datapoint.
 • The presence and absence of CO2 was determined from metadata that indicated
 experiments performed under atmospheric conditions or the addition of bicarbonate into
 solutions as part of the experiment.
 • Smectite and montmorillonite were treated as equivalent mineral phases
The range of solution conditions used to extract data from the database were the following (based on
data compilation from C.F. Jove-Coló n, Table 1):
    •   pH: Niobara chalky marl: 6.24-7.92; Dakota sandstone: 6.84-8.50; Pierre shale: 6.94-8.90
        (+-2SD range)
 • Ionic strength: Niobara chalky marl: 0.070-1.757; Dakota sandstone: 0.003-0.075; Pierre
        shale: 0.012-0.298 (+- factor of 5 from average)
 • CO2: experiments performed in the presence of CO2
 • Radionuclide-mineral datasets with fewer than 5 total data were rejected from consideration
Four broad categories of rock types were selected and associated Kds were extracted for each
radionuclide based on the following workflow:
 • Shale: Shale data were used. Alternatively, either clay data or argillite data were selected. If
 neither was available, the data for bentonite were used. Mudstone was only used for Se(-2).
 (with Pierre shale water chemistry)
 • Bentonite backfill: bentonite data were selected from the database. If bentonite data were
 not available, montmorillonite data were used. If montmorillonite data were not available,
 clay data were used. (Pierre shale water chemistry)
 • Limestone: calcite data were selected from the database. Alternatively, marl or dolomite data
 were used. (Niobara chalky mark water chemistry)
 • Sandy aquifer: quartz data were selected from the database. Alternatively, sand, sandstone,
 or sand+quartz were used. (Dakota sandstone water chemistry)

If sufficient data were not available based on this strict geochemical constraint, a second attempt to
extract relevant data allowed for a broader pH range of 6.0 to 9.0. If sufficient data were still not
available, then the ionic strength criterion was removed and the presence/absence of CO2 was also
removed. These are noted in the tables below.
For each radionuclide-rock type above, the following workflow was used to populate the Kd data
report in the following tables:
 • Outlier data were identified and rejected based on the 1.5×IQR criterion. However, we found
 that very few data were rejected.
 • For the remaining data, a triangular fit to the data was reported if and only if:
 o The number of data were 20 or more
 o The resulting p-value was >=0.05
 • If the above criteria were not met, a uniform distribution is reported
 • If data for some radionuclides were not available, chemical analogs were employed as
 needed (e.g. Am(3+) ~ Ac(3+)) to complete the data tables.

4 FY27 PROPOSED EFFORTS
LLNL recommendations for work packages for FY27 leverage work completed in FY26 to expedite
parameter extraction and statistical evaluation using the L-SCIE database platform. In FY27, data will
be extracted and evaluated in support of the generic granite repository Performance Assessment
model development led by Sandia National Laboratories. In addition, our development of a user-
friendly data extraction and modeling platform in FY26 has led to the identification of significant
sorption data gaps that we propose to correct via a literature mining effort. In particular, the
incorporation of sorption data for weakly sorbing radionuclides will be a priority (iodine, selenium,
14C). These elements are not well represented in our database and a focused effort to mine data for

these elements is needed. This data mining effort will be integrated into the L-SCIE platform for use
in Performance Assessment modeling and general testing of sorption behavior of rock types. One
additional model improvement that will be pursued is the linking of mineral-specific sorption data to
bulk rock sorption data. If successful, this would significantly enhance the application of L-SCIE data
to a broader range of rocks whose mineralogy can be reasonably well defined or estimated.
