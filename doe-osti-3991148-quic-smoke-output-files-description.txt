2 Overview
2.1 Brief description
QUIC-SMOKE produces various output files in both ASCII (.dat) and binary (.bin) formats. The output format is controlled by the ‘format_flag’
parameter:
 • format_flag = 1: ASCII output only
 • format_flag = 2: Binary output only
 • format_flag = 3: Both ASCII and binary output
The current scripts to process and plot the output files use the binary files so Flag 2 is recommended/required unless you desire to process your
outputs with custom scripts

2.2 File naming conventions
Output files follow these patterns:
 • Base files: (e.g., QP_confield.bin)
 • Snapshot files: qp_filename_XXXXX.ext (e.g., qp_confield_00050.bin) - individual timesteps, where XXXXX = time in seconds (zero-
 padded)
 • Size-dependent: Files with `SP` suffix (e.g., QP_confieldSP.bin) include particle size bin dimensions

2.3 Concentration field snapshots (3D)
Stores cumulative 3D concentration fields from QUIC-SMOKE particle dispersion simulations. This file contains the complete time series of
concentration snapshots for gases (CO) or total PM when size bins are not used.
 Always
 File name File type Write statement

 QP_confield*.bin Binary Header (written once at start):

 - Real*4 (nbx): x-coordinates of cell centers in meters
 - Real*4 (nby): y-coordinates of cell centers in meters
 - Real*4 (nbz): z-coordinates of cell centers in meters

 Time Step Data (repeated for each output time):

 - Real*4 (nbx×nby×nbz): 3D concentration field in mass/volume (kg/m³)

 Data Organization
 YES
 - Fortran column-major order (the x-index runs through all its values first, then y
 increments, and finally z increments)

 Units:
 -g/m³ (grams per cubic meter)

 - Concentrations are accumulated over the output interval and then reset to zero after
 each write
 - Each record represents a time-averaged snapshot rather than an instantaneous field
 - The time step data section repeats for every output interval throughout the simulation

2.4 Concentration field snapshots of each particle bin (3D)
Stores 3D concentration fields separated by particle size bins. This file is used when size-dependent calculations are enabled (PM2.5, PM10,
etc.).

 Always
 File name File type Write statement

 QP_confieldsp*.bin Binary Time Step Data (repeated for each output time):

 - Real*4 (nbx×nby×nbz×n_part_conc_bins): 4D concentration field in g/m³

 Time Step Data (repeated for each output time):

 - Real*4 (nbx×nby×nbz): 3D concentration field in mass/volume (kg/m³)

 The concentration values are written in this nested loop order:
 1. All spatial cells (i,j,k) for particle bin 1
 2. All spatial cells (i,j,k) for particle bin 2
 3. All spatial cells (i,j,k) for particle bin 3 YES
 4. ...
 5. All spatial cells (i,j,k) for particle bin n_part_conc_bins

 Within each particle size bin, spatial cells follow Fortran column-major order.

 Units:
 -g·s/m³ (grams per cubic meter)

 - Concentrations are accumulated over the output interval and then reset to zero after
 each write

2.5 Cumulative concentration field snapshots (3D)
Stores cumulative dosage (time-integrated concentration) fields. Dosage is important for assessing exposure over time.

 Always
 File name File type Write statement

 QP_dosfield*.bin Binary Header (written once at first output):

 - Real*4 (nbx): x-coordinates of cell centers in meters
 - Real*4 (nby): y-coordinates of cell centers in meters
 - Real*4 (nbz): z-coordinates of cell centers in meters

 Time Step Data (repeated for each output time):

 - Real*4 (nbx×nby×nbz): 3D concentration field in mass/volume (kg/m³)

 YES
 Data Organization:
 - Fortran column-major order (x, y, z)

 Units:
 g·s/m³ (gram-seconds per cubic meter)

 - Dosage accumulates over time (not reset like concentration)
 - Represents total exposure at each location
 - The standard QUIC-SMOKE postprocessing scripts (`drawsmoke.py`) do NOT
 automatically generate plots for dosage data.

2.6 Cumulative concentration field snapshots (3D) for each particle bin
Stores size-binned dosage fields for particles in different size categories.
 File name File type Write statement Always printed out
 QP_dosfieldsp*.bin Binary Time Step Data (repeated for each output time):

 - Real*4 (nbx×nby×nbzxn_part_conc_bins): 4D dosage field in
 mass/volume (kg/m³)

 Data Organization:
 Loop order (fastest to slowest):
 1. x-index (i = 1 to nbx)
 2. y-index (j = 1 to nby) No, only when
 3. z-index (k = 1 to nbz) sizeDependentCalcsFlag = 1
 4. particle size bin (ipb = 1 to n_part_conc_bins)

 Units:
 g·s/m³ (gram-seconds per cubic meter)

 - Dosage accumulates over time (not reset like concentration)
 - Represents total exposure at each location
 - The standard QUIC-SMOKE postprocessing scripts (`drawsmoke.py`) do
 NOT automatically generate plots for dosage data.

2.7 Particle data
Stores individual particle positions, velocities, masses, and other properties. This Lagrangian particle data can be used for detailed plume analysis
and visualization.
 Always
 File name File type Write statement

 QP_partfield.bin Binary For each output time:

 - Int32 (1): Number of active particles

 For each particle:

 - Real*4 (1): x-position in meters
 - Real*4 (1): y-position in meters
 - Real*4 (1): z-position in meters
 - Real*4 (1): xnear - nearest surface x-coordinate
 - Real*4 (1): ynear - nearest surface y-coordinate No
 - Real*4 (1): znear - nearest surface z-coordinate
 - Real*4 (1): mass - particle mass times weight (g)
 - Real*4 (1): dpm - particle diameter (μm)
 - Real*4 (1): source_num - source number identifier

 Units:
 - Position: meters
 - Mass: grams
 - Diameter: micrometers (μm)

2.8 Total deposition
Stores particle deposition on surfaces (ground, building faces, vegetation). Deposition is accumulated over the simulation and represents the
total mass deposited.

 Always
 File name File type Write Statement

 QP_depct.bin Binary For each deposition surface point:

 - Real*4 (1): x-coordinate in meters
 - Real*4 (1): y-coordinate in meters
 - Real*4 (1): z-coordinate in meters
 - Real*4 (1): face identifier (1-6: building faces; 6: ground/terrain)
 - Real*4 (1): deposition amount in g/m²

 Face Identifiers:
                                   - 1: -X face (west)
 - 2: +X face (east) No
 - 3: -Y face (south)
 - 4: +Y face (north)
 - 5: -Z face (floor/bottom)
 - 6: +Z face (roof/top) or ground surface

 Units: g/m² (grams per square meter)

 - Deposition is tracked on all exposed surfaces including terrain, buildings, and vegetation
 - Values accumulate over time

2.10 Particle removal by precipitation
Wet deposition (removal by precipitation) on the ground surface.

 Always
 File name File type Write statement

 QP_wetdep.bin Binary For each deposition surface point:

 - Real*4 (1): x-coordinate in meters
 - Real*4 (1): y-coordinate in meters
 - Real*4 (1): z-coordinate in meters
 - Real*4 (n_part_conc_bins): deposition amounts for each size bin in g/m²

 Units: g/m²

 - Wet deposition occurs when precipitation is enabled No
 - Represents mass removed from the atmosphere by rainfall

2.11 Particle removal by precipitation per particle bin size
Size-binned wet deposition (removal by precipitation) data showing how different particle sizes are removed from the atmosphere by rainfall.
Size-binned data allows analysis of differential removal rates across the particle sizes.

 Always
 File name File type Write statement

 QP_wetdepsp*.bin Binary For each ground cell:

 - Real*4 (1): x-coordinate in meters
 - Real*4 (1): y-coordinate in meters
 - Real*4 (1): z-coordinate (ground height) in meters
 - Real*4 (n_part_conc_bins): wet deposition amounts for each size bin in g/m²

 Units: g/m²

 - Wet deposition occurs when precipitation is enabled No
 - Represents mass removed from the atmosphere by rainfall for each particle size
 - Larger particles typically have higher wet deposition rates due to more efficient
 scavenging

2.12 Observation points
Time series of concentration and dosage at user-specified observation points. These points allow detailed monitoring at specific locations of
interest.

 File Always
 File name Write statement
 type printed out
 QP_observations.bin Binary For each observation sensor and output time:

 - Real*4 (1): x-coordinate in meters
 - Real*4 (1): y-coordinate in meters
 - Real*4 (1): z-coordinate in meters
 - Real*4 (1): concentration in g/m^3
                                   - Real*4 (1): dosage in g·s/m^3

 If size-dependent calculations are enabled:
 - Real*4 (n_part_conc_bins): concentration for each size bin in g/m^3
 - Real*4 (n_part_conc_bins): dosage for each size bin in g·s/m^3
 - Int32 (1): header No

 Units:
 - Concentration: g/m^3
                                   - Dosage: g·s/m^3

 - Observation sensor definitions are read from QP_observations.inp.
 - This file stores sampled model results, not the original sensor definitions.
 - Data is written once per observation averaging period.
 - For moving sensors, x, y, and z are interpolated sensor coordinates at the output time.
 - Useful for comparing with sensor measurements.
