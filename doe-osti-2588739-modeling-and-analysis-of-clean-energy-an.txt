Executive Summary of CRADA Work:

The goal of this project is to provide Southern Company Services, Inc. ("Participant") with
custom scripts that can be used to create an average PV energy production profile, calculate
lifetime energy value, calculate capacity value, and calculate the resultant financial metrics
considering those value streams. Secondly, a fuel-cell model will be added to the public version
of System Advisor Model (SAM). This standalone technology will incorporate PV and battery
storage, allowing the participant to model the interaction of these three technologies. By adding
this capability to a public version of SAM, a broad audience will be able to consider the system
performance and financial benefits of installing a fuel cell as a baseline generator with PV.
Thirdly, automated dispatch algorithms will be developed and added to SAM. These algorithms
will enable Southern Company to dispatch a DC-connected front-of­the-meter battery system
while considering price signals and PV clipping behavior. By adding these capabilities to a public
version of SAM, users will be able to consider more complex and realistic ways of dispatching a
battery system.

1 Introduction
This project was comprised of three main tasks:

Task 1: SAM Scripting for production profiles (and energy and capacity valuation)

Task 2: Fuel Cells with PV + battery (Adding Fuel Cells with PV + battery storage to SAM)

Task 3: DC-connected battery control algorithms

The first goal of this project was to provide custom (non-public) scripts that can be used to create an
average PV energy production profile, calculate lifetime energy value, calculate capacity value, and
calculate the resultant financial metrics considering those value streams.

The second goal of this project was to add a fuel-cell model into SAM (public). This standalone
technology incorporates PV and battery storage, allowing a user to model the interaction of these
three technologies. Users will be able to model charging a battery with a fuel cell in addition to the
existing capability of charging a battery with PV generation.

The third goal of this project was to develop algorithms for operating a PV plus DC-coupled storage
system, with the goal of maximizing revenue under a PPA agreement.

The completion of these three tasks will be described in this report.

The Financial Parametrics Macro in the System Advisor Model (SAM) is used to calculate and

 • Levelized Cost of Electricity (LCOE) ($/MWh)
 • Present Value of Benefits (PVB) ($)
 • Self Build Net Present Value (NPV) ($) *
    •   PPA NPV (Fixed) ($) **
 • PPA NPV (Escalating) ($) **
    •   PPA NPV (Annual) ($) **

* levelized sum of cap costs plus transmission and distribution cost vs disc. value

** including transmission and distribution cost

2.2.2 Setting and Building Up the Parametrics Table Spreadsheet
A parametric simulation involves assigning more than one value to one or more input variables
to explore the dependence of a result on the inputs. The Parametrics button is under Simulate.
A parametric simulation requires input and output variables in a table format. For this macro, the
sample parametric table spreadsheet provides the required inputs for two plants.

 Figure 1: Parametrics table input
In SAM, in the Parametrics Tool, click Import and select the spreadsheet. Each column header
will be matched to the SAM variable, and each plant characterization will be specified as a row.
The column headers are the names of SAM variables and should only be modified using the
Parametrics tool by using the Import and Export functions. Numbers have semicolons behind
them if the variable type is an array. Even if an array consists of a single entry, removing the
semicolon will result in a type error during import.

4 Task 3: DC-connected battery control algorithms
The primary goals of developing algorithms to operate PV plus DC-coupled storage plants were
to capture energy from the PV array, which would otherwise be clipped due to inverter limits,
add the ability to specify a weather forecast, and create a pseudo-optimal dispatch algorithm to
operate the battery to maximize revenue. It was found that with relatively little modification, the
algorithms can also apply to PV plus AC-coupled storage plants, and so a user can specify either
type of plant.

4.1 Description
The PV plus DC-coupled storage system being modeled assumes that the battery and PV systems
use the same inverter and that the PV system can charge the battery without going through the
inverter.

 Figure 17: DC-coupled PV plus storage system
Within this system, it is assumed that the system owner is compensated for electricity sold to the
grid through a power-purchase agreement (PPA). This PPA can have time-of-delivery factors
that make peak periods more valuable than off-peak periods. It is also assumed that the battery
can charge from the grid through a bidirectional inverter. Electricity purchased from the utility to
charge the battery is assumed to be under a behind-the-meter tariff that is different from the PPA
agreement.

 19

 • System Design – Inputs for the PV system
 • Battery Storage – Inputs for the battery system

 This section will describe the relevant inputs for these pages and how the model works.

4.2.1 System Design Inputs
The primary input to be aware of on this page is the DC to AC ratio and AC sizing:

 Figure 18: PV system design

4.2.2 Battery Storage Inputs
New capabilities added for battery storage are grouped under the Storage Dispatch Controller:

 Figure 19: Battery storage inputs

 20

Choose the automated dispatch model that most closely represents how you would like the
battery to be charged and discharged, or choose the manual dispatch option to specify the timings
manually.

 • Automated dispatch - look ahead- For each day, SAM looks ahead however many
 hours are specified in the dispatch options under “frequency to update dispatch.” SAM
 uses a perfect prediction of the PV production to estimate when the system will clip. For
 DC-connected batteries, the algorithm will reserve some capacity for predicted clipping
 events, charge the battery when PPA prices are low (if the battery can charge from the
 system), charge when electricity rates are low (if the battery can charge from the grid),
 and discharge when the PPA price is high.
 • Automated dispatch - look behind- Similar to the look ahead option, except SAM looks
 behind 24 hours at the PV production to predict future clipping events for DC-connected
 batteries.
 • Automated dispatch – input forecast - Similar to the lookahead option, except the user
 can input their own weather forecast for SAM to predict the PV performance for the next
 N hours.
 • Input battery dispatch- Input a time series of desired battery power charging and
 discharging. Discharge power is specified as greater than zero; charge power is specified
 as a negative number. The dispatch controller will attempt to operate the battery with this
 signal, within the context of state-of-charge and power constraints.
 • Manual dispatch - No automation. Specify the timing of battery charges and discharges
 using up to six dispatch periods and a set of weekday and weekend hourly profiles by
 month.
Battery charge options

For non-manual dispatch options, the user selects whether the battery can charge from the grid
and/or from the system (PV or generic system) and/or from otherwise clipped system power.

Automated dispatch options

The automated dispatch models, may also require a forecast weather file if using the input
forecast option.

 • Frequency to update dispatch - How often the dispatch should be updated in hours
 • Look ahead-period- For the look-ahead option, how many hours to look ahead.
 • Battery cycle cost choice - Choose whether to have SAM predict the cost to cycle the
 battery, based on specified capital costs and ongoing degradation, or to input an estimate
 for battery cycle costs on a $/cycle-kWh basis.

4.2.3 Time of Delivery Factors
Time-of-delivery factors for the PPA govern how the PPA price changes depending on the time-
of-day or season. Example time-of-delivery factors are available, or the user can fully customize
a schedule.

 Figure 20: Time of delivery factors

4.2.4 Electricity Rates
For the controller to make decisions about when and how to charge or discharge the battery,
information about the buy-rate of electricity is required. This information is specified on the
electricity rates page. The user must enable the electricity rate on the electricity rates page and
then populate energy charges for the rate. Only the “Buy all / sell all” option for metering is
available in this scenario.

4.3 Model
The model which calculates how to charge and discharge the battery works according to these
principles:

 • Always charge from PV if clipping occurs.
 • Charge from PV if it is more valuable to sell the PV power later.
 • But reserve capacity for future clipped power.
 • Charge from the grid if the energy price is less than a future PPA price, accounting for
 charge and discharge efficiencies.
 • Discharge if in a high PPA price period, and the system has adequate inverter and battery
 capacity.
 • Don’t operate the battery if the benefit to do so is less than the cost to cycle.

5 Summary
Three tasks were completed under a Cooperative Research and Development Agreement. Under
the first task, private scripts were created to enable Southern Company to perform energy and
capacity valuation analysis in SAM. Under the second task, a new public fuel cell model was
created that enables modeling of fuel cells coupled with PV plus storage systems. In this work,
generic models were added to SAM that could approximate a generic generator and evaluate
combined heat and power applications. Under the third task, new dispatch algorithms for front-
of-the-meter PV plus storage systems were developed to operate the battery system in a pseudo-
optimal fashion with the goal of maximizing revenue while considering PV system
overproduction.
