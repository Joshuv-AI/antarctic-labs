 Abstract
 Each step in the scientific process generates contextual information about the data that is
 important to consider when performing data integration, developing models of biological
 process, or training AI models. We will develop a flexible, template-driven tool that will log
 biological samples, capture metadata about those samples, and track the type(s) of analysis
 being performed by researchers providing samples for analysis by mass spectrometry.

 1.0 Introduction
 Metadata are contextual data describing the characteristics of other data, providing critical
 details about a data point or dataset. However, metadata are often inconsistent across
 individuals, laboratories, and organizations due to variations in data collection practices (e.g.,
 who, where, and how) and confusion regarding data standards. This variability results in data
 silos, lack of data sharing and integration, and a paucity of AI-ready data for biological
 investigations. When metadata are structured and compliant with data standards, the data can
 be integrated appropriately and reused for different downstream analyses. Thus, metadata are
 critical for accurate data analysis and interpretation of biological data.

 We are developing a software tool designed to streamline the management and validation of
 biological sample metadata, for samples destined for analysis by mass spectrometry. This
 software tool leverages open-source tools and standards and provides several features
 designed to lower the barrier to collection of complete and accurate sample metadata.

 2.0 Results
 To leverage the prior work developing metadata tools for the EMSL User Facility, we branched
 their Science Central code and started work to remove unneeded elements and modify or add
 elements uniquely required for the Biological Sciences Division. The portal code is managed in
 a GitLab repository (https://gitlab.emsl.pnl.gov/scientia/bsd-sample-submission), and rendered
 on a development server (http://prismdb1.emsl.pnl.gov:5000/). Metadata are stored in a
 PostgreSQL database running in a docker image on the development server.

 In this first development phase, we have set up a metadata portal that uses PNNL's single sign-
 on credentials for secure and efficient access for authorized users. Once authenticated, the
 portal guides the user through a set of web pages to collect relevant information (Figure 1). On
 the initial page, the project, principal investigator and work package number are entered in fields
 that support incremental search to filter through projects in PNNL’s project management system
 and autocomplete the entries. On the following page, the user selects the type of samples being
 submitted (e.g., soil, human, water) and the types of mass spectrometry analyses being
 requested using radio buttons and check boxes; the list of analyses are consistent with the
 Mass Spectrometry Service Center request options. The user is also asked to provide
 information needed by the sample preparation staff by selecting radio buttons to indicate
 relevant information on the physical state of the sample (e.g., solid, liquid, lyophilized, storage
 temperature). The final page presents an interface that emulates a spreadsheet for entering
 sample metadata appropriate to the sample type previously identified (e.g., soil). The metadata
 required in this form is guided by schemas designed for each type of sample.

 We have developed a LinkML-based schema [1] to encode the sample metadata fields in JSON
 format. The schema encodes the metadata standards set by the Genome Standards
 Consortium, in the Minimum Information about any (X) Sequence (MIxS) [2] [3] and the ENVO
 ontology [4] to contextualize environmental samples. We are investigating a number of

Results 2

 ontologies to add to our schema that would be suitable for contextualizing human samples, for
 example Uberon [5] to classify organ and tissue source. To ensure adherence to the standards,
 the metadata entry leverages the capabilities of the handsontable [6] javascript library to
 validate input metadata against the encoded schema elements.

 Upon submission through the entry form and validation against the standards encoded in the
 schema, the metadata are encoded in JSON format and stored in a PostgreSQL database. The
 sample metadata can then be automatically shared with the laboratory LIMS system to create
 the sample entries necessary to initiate the mass spectrometry analysis workflows.
