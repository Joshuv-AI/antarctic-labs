Useful Memories Become Faulty When Continuously Updated by LLMs
Dylan Zhang, Yanshan Lin, Zhengkun Wu, Yihang Sun, Bingxuan Li, Dianqi Li, Hao Peng

Abstract
Learning from past experience benefits from two complementary forms of memory: episodic traces—raw trajectories of what happened—and consolidated abstractions distilled across many episodes into reusable, schema-like lessons. Recent agentic-memory systems pursue the consolidated form: an LLM rewrites past trajectories into a textual memory bank that it continuously updates with new interactions, promising self-improving agents without parameter updates. Yet we find that such consolidated memories produced by today’s LLMs are often faulty even when derived from useful experiences. As consolidation proceeds, memory utility first rises, then degrades, and can fall below the no-memory baseline. More surprisingly, even when consolidating from ground-truth solutions, GPT-5.4 fails on 54% of a set of ARC-AGI problems it had previously solved without memory. We trace the regression to the consolidation step rather than the underlying experience: the same trajectories yield qualitatively different memories under different update schedules, and an episodic-only control that simply retains those trajectories remains competitive with the consolidators we test. In a controlled ARC-AGI Stream environment that exposes Retain , Delete , and Consolidate actions, agents preserve raw episodes by default and double the accuracy of their forced-consolidation counterparts; disabling consolidation entirely (episodic management only) matches this auto regime. Practically, robust agent memory should treat raw episodes as first-class evidence and gate consolidation explicitly rather than firing it after every interaction. Looking forward, reliable agentic memory will require LLMs that can consolidate without overwriting the evidence they depend on.

Introduction

Memory consolidation is the cognitive process by which individual experiences are stabilized, reorganized, and integrated into long-term memory over time. Rather than preserving every episode as a raw record, consolidation helps extract recurring patterns, discard incidental details, and connect new information with existing knowledge. A central hallmark of intelligence is the ability to turn repeated experience into reusable knowledge. Humans do not treat every new situation as entirely unfamiliar; instead, they gradually summarize common structure from past episodes and organize it into abstractions through memory consolidation
(

;

Recent agentic-memory systems pursue a similar idea for LLM agents. After solving a problem, an agent can distill its trajectory into a textual abstraction of the skill it has learned, store this abstraction in persistent memory, and refine it as more related problems are encountered

In this work, we systematically examine what happens when agents repeatedly compress past trajectories into memory and reuse that memory over long horizons. To make the experiences themselves informative by construction, we study settings in which the input trajectories are demonstrably useful: either drawn from problems the agent has already solved without memory, or supplied with ground-truth solutions. Even under these favorable conditions, we find that
current LLMs are not reliable memory consolidators
. Each consolidation step is a lossy rewrite of the memory store: useful details are dropped, spurious rules are introduced, and once-helpful abstractions drift away from the underlying task structure. Across ALFWorld, ScienceWorld, WebShop
(
38
)
, AppWorld
(
32
)
, and a controlled testbed we introduce to make consolidation failures more visible, agents that incrementally abstract their accumulating trajectories into a textual memory bank can briefly improve or plateau before degrading—in some cases falling below the same agents without memory at all (Fig.
1(a)
). The clearest case isolates the consolidation step from any input-side excuse: GPT-5.4 first solves a set of ARC-AGI problems at
100\%
accuracy with no memory; after consolidating from ground-truth solutions to those very problems, it then fails on
46\%
of them (Fig.
2
). The failure can therefore be attributed to
faulty memory
rather than to noisy trajectories.

Consolidation is fragile in a second sense: the same set of trajectories can yield qualitatively different memories depending on the order and grouping of updates. Consolidating the whole trajectory pool in one pass (
Static-All
) versus streaming it batch-by-batch (
Stream
) produces different end states (Fig.
3
); updates on one task overwrite memory of another (Figs.
8(b)
and
8(c)
); and a stream of repeated near-duplicates causes the memory to overfit to seen instances and generalize poorly within the same task (Fig.
11
). Meanwhile, an episodic-only control that consumes the same trajectories without abstracting them—appending raw rollouts to context as in-context demonstrations—is already competitive with the lesson-style consolidators we test (Table
2
). Because the trajectory pool is held fixed across these comparisons, the variance across schedules and the episodic-only control together point to the consolidation step itself, not the underlying experience, as the source of the failure.

We further identify three mechanisms behind faulty memory (§
6
). First, agents misgroup experiences before abstracting them, pooling episodes that do not share underlying structure. Second, even when grouping is correct, abstraction can strip the applicability conditions of a lesson, so that overgeneralized entries interfere with neighboring tasks. Third, when the input stream is narrow, abstraction overfits to seen instances. Together, these failure modes weaken the boundary between what should be generalized, what should remain task-specific, and what should be preserved as raw episodic evidence
(
30
;
1
;
2
)
.

These findings suggest a limitation in current LLM agents: while they can often benefit from individual past episodes, they do not reliably turn those episodes into stable and reusable abstractions over long horizons. Many recent agentic-memory systems—CLIN
(
16
)
, Agent Workflow Memory
(
36
)
, Dynamic Cheatsheet
(
31
)
, and ACE
(
40
)
—adopt update-after-every-interaction designs that treat each consolidation step as at worst neutral; our results contradict this assumption. For today’s models, retaining episodes is the more robust default: when ARC-AGI Stream agents are given retain, delete, and consolidate actions, they preserve episodes by default and outperform their forced-consolidation counterparts. Yet episodic accumulation cannot be the long-term answer: as deployment continues, raw histories grow unboundedly and resist compositional reuse—compression and transfer ultimately require abstraction. We see faulty memory as a central open problem in agentic memory, and our results motivate architectures that keep the episodic and abstraction-forming roles distinct rather than collapsing both into a single rewrite loop.

A popular paradigm is that LLMs abstract useful procedural information from experience into text. This work mainly concerns that category.

Schema formation and metacognitive control.

Cognitive theories of memory describe two complementary processes: a fast episodic system that stores individual experiences, and a slow process that extracts compact
schemas
—abstractions over many episodes that integrate with prior knowledge to support future generalization
(
17
;
28
;
6
;
21
)
. Schema formation is beneficial when new evidence fits existing structure
(
33
)
, but harmful when it is non-selective or poorly controlled: nonselective consolidation causes interference and loss of specificity
(
17
;
30
)
. Whether consolidation helps therefore depends on
metacognitive control
—deciding which experiences belong together, how abstractly to rewrite them, and when to preserve distinctions rather than collapse them.
Human metacognition is itself imperfect
(
7
;
23
;
10
)
, and whether LLMs reliably monitor their self-generated abstractions is an open question—in adjacent settings, chain-of-thought explanations have been shown to diverge from the underlying computation
(
34
)
. Agent-memory systems implement an explicit analogue, abstracting “lessons” that are reused on later tasks while putting the same model in charge of both generating the memory and monitoring its own abstraction; the failure modes we observe (§
6
) are consistent with this control loop being unreliable in practice.

Memory construction conditions.

Three regimes differ only in how trajectories are presented to the memory manager:
Static-All
abstracts memory from the entire pool in one-shot;
Static-Group
does so for each task type (for ALFWorld and ScienceWorld) and concatenate: this simulates offline memory construction and is used for control;
Stream

For Stream we change batch size and within-batch task composition (homogeneous vs. heterogeneous) and consider both unbounded and size-capped memory banks. At evaluation we provide all memory entries in context and average two repeats per question unless noted otherwise.

We introduce

4
Useful Memories Become Faulty When Continuously Updated by LLMs

4.1
Stream Updates Reveal The Cumulative Effect Of Imperfect Abstraction

Abstracted memory utility is non-monotonic in updates.

Starting from an empty memory store,
abstracted-memory utility rises early and then falls below the no-memory baseline as updates accumulate.
Figure
1(a)
shows this curve on ScienceWorld with batches of 4 trajectories: the score peaks near step 20 and declines through step 100 for every memory size and sometimes below no-memory baseline. The same shape recurs on WebShop, where AWM goes from
0.64
at
8
examples to
0.20
at
128
while no-memory sits at
0.20
(Fig.
1(b)
)—scaling the memory eventually erases its own benefit.

A strong memory is not a fixed point.

A high-quality starting memory does not stabilize under continued consolidation either. We first consolidate ALFWorld trajectories with GPT-5.4—the strongest model we test—following the
Static-Group
setting from §
3
, then continue updating that store in batches with GPT-5-nano on the same trajectory pool.
Evaluated under three solvers (Qwen3.5-{27B, 9B, 4B}) to avoid idiosyncraticy, utility declines across all three solvers and can drop drastically between consecutive evaluation steps (Fig.
4
).

The agent regresses on tasks it has already solved.

The cleanest, most striking instance is in-distribution regression on a 19-problem slice of the ARC-AGI Stream that GPT-5.4 solves at
100\%
accuracy without memory. Streaming those same problems through the consolidation loop, with ground-truth solutions available at every step, brings GPT-5.4 down to
54\%
on the very problems it had previously solved (Fig.
2
).

The consolidation procedure itself shapes the rate of decline.

The decline is not driven by content alone; how trajectories are presented to the consolidator changes the resulting memory in content-independent ways.
1.
Grouping by task family helps.
Holding update strategy fixed, consolidating each task family separately (
Static-Group
) outperforms consolidating across families jointly (
Static-All
- marked as Ungrp.); pooling heterogeneous tasks into a single abstraction step invites confusion between unrelated procedures (Fig.
3
).
2.
One-shot consolidation beats streaming.
Holding the trajectory pool fixed,
Stream
ed incremental updates underperform a single whole-pool pass (Fig.
3
).
This suggests that early abstractions can anchor later rewrites and mistakes are reused as context for future consolidation, so small errors in segmentation or abstraction compound into progressively distorted memories. However, in continual learning loops, memory gets repeatedly updated as agents collect more experiences, instead of seeing the entire pool of past interactions, precisely falling to the lossy update regime.

3.
Heterogeneous batches accelerate the decline within streaming.
Even when updates must be streamed, batches that mix tasks produce worse memory than batches drawn from one task at a time (Fig.
4
): the model merges incompatible lessons inside a single update.

Implications for memory design.

Each abstraction pass is a lossy rewrite that compounds over updates. The pattern makes two predictions for how memory should be organized, which §
5
tests directly. (i) The raw trajectory logs that the consolidator distills from should remain a competitive baseline, since they retain what each rewrite discards. (ii) Allowing an agent to keep raw episodes alongside (or instead of) abstracting them should outperform a regime that forces every trajectory through consolidation.

4.2
An episodic-only store should be a diagnostic baseline

In WebShop, ALFWorld and AppWorld, an
episodic-only
memory—append-only trajectory rollouts in context, with no cross-trajectory abstraction —is competitive with lesson-style consolidator we test (Table
2
; WebShop in Table
3
in Appendix). The trajectory baseline stores the same experience that ACE, AWM, and Dynamic Cheatsheet are asked to compress, and all memory entries are placed in context at evaluation.

In most cases, abstracted memory cannot significantly outperform direct in-context learning from trajectory logs (or subsets of them). It means the evidence available before abstraction already contains task-relevant signal that the solver can exploit directly: observations, actions, intermediate failures, and environmental feedback remain tied to the concrete situation in which they occurred. Schema-like behavior can emerge
from in-context learning on preserved instances comparative to a separately stored abstraction
(
9
;
3
;
19
;
15
)
. Therefore, we suggest that a memory method whose value depends on distillation should be tested against the unabstracted rollouts it distills.

5
Mitigating Faulty Abstraction

The findings in §
4
imply experiences contain information the LLMs can consume for better task performance, but the challenge is that those information fades with repeated LLM updates instead of being refined.

Therefore, the memory architecture should be allowed to preserve episodes instead of forcing every new experience through consolidation. In this section, we present a controlled study to test whether granting models autonomy of retention versus abstraction, and allowing parallel stores of abstract and episodic memory would be a mitigation to the effect.

ARC-AGI Stream lets us instantiate the two-process design explicitly. The agent maintains both an
Episodic
buffer and an
Abstract
store, and at each step may
Retain
,
Delete
, or
Consolidate
(
Auto
; cf. §
3
). We compare this to
Force
, where consolidation is required at every round and no episodic entry persists between rounds. Three observations follow.

First, the episodic store carries most of the gain.
Removing episodic evidence and using only abstract lessons collapses accuracy back to the no-memory baseline (Fig.
9(a)
), indicating that the useful information was retained in raw episodes rather than distilled entries.

Second,
Episodic Management Only
—retention and deletion of raw episodes with abstraction disabled—matches or exceeds the full Auto mode (Fig.
9(a)
). In this regime, the agent’s gains do not require an abstract store at all.

Third, forced abstraction underperforms retained-episode policies. Across
400
training steps, Auto—which keeps episodes by default and uses abstraction sparingly—generally outperforms Force on both backbones we test (Fig.
5
). Whatever Force gains from compression, it can lose more by overwriting evidence.

Figure 6
:
Buffer composition over time on the ARC-AGI Stream

The agent’s own management decisions point in the same direction. Given the option, it saturates the episodic buffer quickly at both budget levels while keeping the abstract store sparse (Fig.
7(b)
). The Auto-mode result therefore reflects an episodic-first policy that the agent chooses when the architecture permits it.

Principle.

Episodic and schema-forming roles should not be collapsed into a single rewrite loop. Complementary Learning Systems make this prescription explicitly: a fast episodic store and a slow schema-forming store are kept architecturally distinct so that fast learning does not overwrite the slow one, and consolidation is gated by schema fit rather than triggered on every event
(
17
;
11
;
33
;
30
)
. The Force regime collapses this separation into a mandatory rewrite loop, recreating the interference conditions the dual-system design was meant to prevent
(
18
;
8
)
. An episodic store should therefore retain the evidence; abstraction, when it happens, should be opt-in and gated by the agent rather than forced on every trajectory.

In our experiments, both policies that gate abstraction (Auto) and policies that disable it entirely (Episodic Management Only) match or exceed forced abstraction (Force), pointing to
mandatory rewriting at every step
—rather than abstraction itself—as the decisive failure mode in this regime
(
23
;
10
)
.

6
Failure Modes

We introspect three abstraction failures both quantitatively and qualitatively: misgrouping before abstraction, interference from overgeneralized lessons, and overfit to narrow streams of examples. We present full case study results in
Appendix

D
.

6.1
Correct Segmentation Takes Time, Forced Abstraction Breaks It

Correct segmentation—identifying which experiences belong together before abstraction—is a precondition: an agent cannot abstract a lesson from a set of episodes it has failed to group correctly
(
39
)
.

The capacity for correct segmentation is in fact
present
. Given autonomy over its memory, the model eventually converges to a clean episodic store covering each of the 6 problem types(Fig.
6
).
Yet the process takes time: only after 71 steps (568 examples) does the model admit all six problem types into the buffer.
In the Force regime, where the model must consolidate at every step (8 fresh examples), it makes mistakes frequently. Figure
7(a)
reports the
misclassification count
— the number of memory-management actions that combine episodes from two or more distinct problem classes — and shows that, under forced consolidation, the model routinely merges across class boundaries. The bottleneck is not recognizing class structure but preserving it through
cross-episode abstraction: the forced act of abstraction overrides the segmentation the model is otherwise capable of.

6.3
Overfit

A complementary failure mode emerges when the input distribution narrows rather than widens. In our ARC-AGI experiments, we repeatedly feed the model tasks drawn from a single strategy family across consolidation cycles. As the iteration count grows, the memory overfits to the specific instances it has seen: performance remains stable on exact repetitions of those problems but collapses on simple variations within the same strategy family (Fig.
11
; see
Appendix

D
for case studies).

The abstraction loop, given a narrow stream, abstracts toward the surface regularities of the observed instances rather than the underlying problem-solving strategy.

Memory turns overspecified and hurt performance outside of the compressed questions.

Persistent memory is meant to let LLM agents move beyond static competence: experience is stored, compressed into reusable lessons, and carried forward. We identify an issue that may undermine this promise — across agent benchmarks and ARC-AGI Stream, continuously updated textual memory can become less useful as experience accumulates; in the cleanest case, an agent becomes worse on the very problems its memory was built from.

The failure lies in the consolidation loop itself. Current LLMs do not reliably decide which episodes belong together, which distinctions should survive compression, or when an experience should remain episodic. They misgroup trajectories, overgeneralize lessons, and overfit to narrow streams. Because each update rewrites the products of earlier updates, small abstraction errors compound into faulty memory.

These findings suggest that raw episodes should be treated as first-class evidence, not disposable material to be compressed away. Abstraction should be selective, delayed, and grounded in recoverable trajectories. Until agents can control when and how to consolidate experience, continuously updated textual memory should be treated not as a reliable engine of self-improvement, but as a fragile mechanism that can make more experience produce worse memory.

8
Limitations

Our study has several scope conditions. First, we evaluate text-based agentic
benchmarks (ALFWorld, ScienceWorld, WebShop, AppWorld, Mind2Web) and a
controlled ARC-AGI Stream environment; whether the same erosion dynamics
appear in embodied, multi-modal, or tool-rich production settings remains
open. Second, we study natural-language abstraction as implemented by
contemporary LLMs (GPT-5.4 family and Qwen3.5 family); parametric memory
(weight updates, distillation into the model) and structured non-textual
memory representations are out of scope. Third, the consolidator and the
solver are themselves LLMs, so faulty abstraction reflects current model
capability and could shift with stronger consolidators or with consolidator-
specific fine-tuning. Fourth, due to API-cost constraints we report
point estimates from a small number of repeats per question rather than
formal error bars; we mitigate this by checking that conclusions hold across
multiple models, benchmarks, and memory frameworks, but per-figure variance
should be interpreted with this in mind.

9
Broader Impacts

Our findings are diagnostic: they identify a failure mode in a widely adopted
paradigm for agent memory and suggest more conservative default designs that
preserve raw evidence and gate abstraction. The positive impact is to reduce
silent regressions in deployed long-horizon agents and to direct research
toward more reliable abstraction mechanisms. Negative impacts are indirect:
better long-horizon agent memory could amplify the reach of autonomous
systems whose downstream uses (persuasion, automation of consequential
decisions) carry their own risks, and our diagnosis of failure modes does not
constitute a fix. We do not release new datasets or models that pose
specific misuse concerns, and the benchmarks we use are public.

Appendix A
Family and skill taxonomy [ARC-AGI]

This section defines the two terms “family” and “skill” and
lists the six families and seven skills used in the ARC-AGI experiments.

A.1
Definitions

Our task generator decomposes an ARC-style task along two
independent axes:

•

Family
: a rule that selects the subset of
connected non-background objects in the input grid that
participates in the task’s transformation.

•

Skill
: a fixed transformation applied to each
selected object.

The two axes are orthogonal: the same family can be paired with
different skills, and the same skill can be paired with different
families. Some families are adapted from concept groups in
ConceptARC; for example,
detect_inside_frame_relation

corresponds to the
InsideOutside
concept group.

A.2
Family catalog

The six families span five distinct selection criteria: two are based
on intrinsic per-object attributes (color, size extremum), one on a
global conditional cue (a marker cell that triggers a branch), one
on a cross-object relation (shape-frequency mode), one on a spatial
containment relation (objects strictly inside a frame), and one on a
cross-grid structural property (a sub-scene of a two-panel input).
The chosen skill is then applied uniformly to whichever objects the
family selects.

Appendix B
Prompts [ARC-AGI]

The experiments use three prompts: a solver prompt issued once per task, a consolidator decision prompt that selects an action on the recent history buffer after each passing step, and a consolidator extraction prompt that produces a replacement strategy memory from a selected subset of history. To make every field concrete we reproduce one full step from a real run in which the current solve passes; the history buffer carries two prior passing trajectories and strategy memory holds one entry distilled at an earlier step. Each prompt is shown together with the response it elicited. Where long content repeats across prompts (the eight extra IO examples for the current task; the 8 tool-buffer helper bodies; grids and solve code already shown above), we mark the elision in square brackets; everything else is byte-for-byte from the run logs.

Appendix C
Strategy memory evolution over time [ARC-AGI]

C.1
How a strategy is traced across compress steps

At each compress step we run the extraction prompt (
section

B.4
); the consolidator returns the rewritten strategy memory as a JSON list. Each list item declares its
kind
, one of three values:

•

retain
— keep an existing entry from the current memory; the field
from_existing
lists 1-based indices into that memory.

•

new
— distill a fresh entry from selected input tasks; the field
from_functions
lists 1-based indices into this step’s input tasks.

•

merge
— emit a new entry that combines existing entries (
from_existing
) with new input tasks (
from_functions
).

Both
kind
and the two index fields come directly from the consolidator’s JSON output. After parsing the response, we persist the resulting memory as a per-step JSON snapshot; each entry in the snapshot carries this step’s
kind
and its associated indices.

Because both
merge
and
new
produce a fresh entry rather than editing an existing one in place, tracking how a strategy evolves over multiple steps requires walking
from_existing
pointers backwards across snapshots. Starting from a target entry, we look at its
kind
: if
kind = new
, the chain has reached its root and the walk terminates; if
kind = merge
, the index
from_existing: [j]
points to a predecessor in the previous compress step’s memory; we look up the predecessor in the snapshot we persisted for that step and take it as the new target. We call a chain reconstructed by this procedure a
strategy lineage
.

Appendix E
Examples of useful / well-formed strategies [ARC-AGI]

Below are four memory entries that share one property: their
procedural body is concrete and directly operational — each step
names an action the solver can translate into a Python helper, and
the directions, boundaries, and object selections it depends on
are stated specifically rather than left implicit. Yellow
highlights mark the phrases that most directly drive this
property.

Strategy memory entry — compose-horizontal (operation left as a slot)

When to use:

The task has two separate input grids of the
same height, and the output width is exactly the sum of their widths,
indicating horizontal concatenation. The left half of the output is
just the first input, while the right half is the second input after
a uniform transformation applied only there
: either every
non-background cell is recolored to one fixed color, or each
connected component keeps its shape but receives a center marker at
its bounding-box midpoint.

Strategy:
(1) Verify that the output is formed by placing the
first input on the left and the second input on the right with no
vertical offset.
(2) Build the output by horizontally concatenating corresponding rows
of the two inputs.
(3) Determine what extra rule applies only to the right half by
comparing examples.
(4) If the right-half rule is uniform recoloring,
replace every
non-background cell from the second input by the designated output
color while preserving all positions and shapes.

This can be done cellwise or per connected component.
(5) If the right-half rule is center marking, extract each
non-background 4-connected component in the second input,

compute its bounding box, and find the bbox center using the
midpoint row and midpoint column.

Shift that center into the concatenated output’s right half and write
the marker color there, leaving the rest of the component unchanged.
(6) Keep the left half identical to the first input throughout.

Strategy memory entry — largest-object

When to use:

The grid contains several disconnected
objects on the same background, and the output changes only the
object or objects with the greatest area/cell count while leaving all
smaller objects untouched
. The transformation on the selected
objects may be marking a special point, recoloring the whole object,
or mirroring the object within its own bounding box.

Strategy:
(1) Extract all connected non-background objects.
(2) For each object,
compute its size as the number of occupied
cells.

(3) Find the maximum size across all objects; if several objects tie
for largest, select all of them.
(4) Copy the input grid to the output.
(5)
Apply the task-specific operation only to the selected largest
objects, preserving their positions
: for example, recolor every
cell of each selected object, mark the object’s center cell if the
examples show a single inserted marker, or horizontally mirror the
object’s occupied cells within its own bounding box.
(6) Leave every non-selected object and all background cells unchanged.

Strategy memory entry — inside-frame

When to use:

A grid contains one large hollow
rectangular frame and several separate objects both inside and
outside it. The output keeps only the objects strictly enclosed
by the frame
, removes the frame itself, removes every outside
object, and leaves the kept inner objects unchanged in their
original positions on a same-size grid.

Strategy:
(1) Find all connected non-background objects.
(2)
Identify the frame as the large hollow rectangle, typically
the largest object by size and with an empty interior.

(3) For every other object, compare its bounding box to the frame’s
bounding box;
keep only objects whose top, left, bottom, and
right bounds lie strictly inside the frame bounds, not touching the
frame border.

(4) Start from a copy of the input or from an empty same-size grid.
(5) Erase the frame cells.
(6) Erase every object not strictly inside the frame.
(7) Preserve each inside object exactly as is: same shape, same
color layout, same absolute position.
(8) Leave all remaining cells as background.

Strategy memory entry — key-marker (earlier extraction schema)

Use
the top-left cell as a preserved control marker
; for every
other object, choose between two transforms according to whether
that marker matches a designated color.

What is in the memory at the peak.

At stage 20 the 42 items each cover a distinct decision-relevant insight. We reproduce items 0–5 verbatim below; items 6–41 expand on this cover set with concrete recipes for heat/cool/clean tasks, look-at-light tasks, and multi-object planning.

Stage 20 memory (peak, 42 items) — items 0–5 verbatim

Item 0.
Most ALFWorld tasks reduce to a small set of reusable plans. For plain pick-and-place: find object, pick it up, go to destination, place it. For cool/heat/clean tasks: find object, pick it up, apply the required state change at the correct appliance/fixture, then move it to the goal receptacle. For look-at-obj-in-light tasks: get the target under or near the desklamp, turn on/use the desklamp, then examine or hold the target there. Recognizing the task type early lets you prioritize the right fixtures: fridge for cooling, microwave for heating, sinkbasin for cleaning, desklamp for light-examination.

Item 1.
When the object location is unknown, systematic search beats wandering. Common sources recur by room type: kitchen objects often appear on countertop, diningtable, in fridge, cabinet, drawer, sinkbasin, stoveburner, or microwave; living-room objects often appear on sofa, armchair, coffeetable, sidetable, desk, shelf, dresser, or tvstand; bathroom objects often appear on toilet, toiletpaperhanger, handtowelholder, bathtubbasin, countertop, cabinet, or drawer. Open closed containers when needed, and once you find one instance of the target type, revisit that source because the second instance is often in the same place.

Item 2.
If the goal location is a closed container like a drawer, cabinet, fridge, microwave, or safe, opening it early can simplify the rest of the task. This avoids carrying the object to the destination only to discover it is closed, and it is especially helpful in two-object tasks because the container remains ready for repeated placements. The same applies when the destination is also the object source: open once, retrieve object, do the state change, then return and place.

Item 3.
Cooling and cleaning are usually simpler than heating: once you hold the target object, go to the fridge or sinkbasin and apply ‘cool X with fridge’ or ‘clean X with sinkbasin’. You often do not need to insert the object into the appliance/container first. This means a strong default is: pick up target, go to the relevant fixture, apply the state change directly, then place at destination.

Item 4.
Many state-change tasks start with the target object already on or in the goal receptacle. In these cases, the object still must be picked up, changed to the required state, and then placed back. Examples include cooling an object already on a diningtable or in a coffeemachine, heating an object that ends up back in the fridge or diningtable, and cleaning an item that returns to the same surface. Do not stop just because the object is already at the destination.

Item 5.
The robust default for ‘pick two obj and place’ is: find one target, pick it up, carry it to the destination, place it, return for the second, and repeat. If both objects are visible and inventory permits, carrying both can help, but many successful trajectories simply shuttle one at a time. Once a source location is known to contain multiple copies, revisit it directly instead of re-searching the whole room.

Overgeneralization modes

(1)
Tautological directive.
An agent already pursuing a subgoal already prefers actions that advance it; the clause names no observable cue and so leaves the action distribution unchanged at retrieval.

(2)
Vacuous ranking criterion.
“Nearest feasible fixture or item” offers a preference but no operational definition of feasibility or distance, no rule for selecting among candidates that all look feasible, and no fallback when none is.

(3)
Meta-directive without operationalization.
“Interleave subgoals when beneficial” is a control-flow recommendation with no condition for “beneficial”; the item supplies no procedure that produces the benefit signal at action-selection time.

J.1
Abnormal memories

J.1.1
Representative cases

We first present three representative abnormal memory cases identified in the ScienceWorld environment, one from each abnormality category. These cases illustrate qualitatively different failure modes in memory consolidation:
over_generalization
, where a memory abstracts from prior experience too broadly and may bias the agent toward inappropriate actions;
over_specialization
, where a memory is tied to overly specific entities or procedures and therefore has limited transferability; and
useless_garbage
, where a memory is vague, malformed, or insufficiently actionable. For each case, we annotate the problematic components of the memory and explain why retrieving it may hurt downstream decision-making.

Representative
over_generalization
memory from ScienceWorld

Using a lighter, fire source, or oven MAY BE NECESSARY
(1)
to
change the state of a food or substance
(2)
in
state-change tasks
(3)
.

Why this memory is harmful

(1)
Overgeneralized tool prior.
The memory promotes a broad prior over heat sources, even though many state-change tasks may require cooling, freezing, melting, or task-specific apparatus rather than a lighter, fire source, or oven.

(2)
Underspecified target transformation.
“Change the state” collapses different physical transformations into one generic goal, ignoring whether the required transition is boiling, freezing, melting, or another state change.

(3)
Cross-task overreach.
The rule is stated for all state-change tasks, so retrieval may bias the agent toward heat-related actions even in contexts where heating is irrelevant or harmful.

Representative
over_specialization
memory from ScienceWorld

For conductivity-sorting tasks,
picking up and testing unknown substance B
(1)
in a circuit SHOULD BE NECCESSARY before
placing it in the correct box
(2)
.

Why this memory is harmful

(1)
Instance-specific binding.
The memory is tied to “unknown substance B” rather than the general class of unknown substances, so it may fail to transfer to otherwise identical tasks involving different item names.

(2)
Narrow task schema.
The final action is framed around a specific sorting protocol, making the memory useful only for a narrow subset of conductivity tasks rather than a robust reusable strategy.

Representative
useless_garbage
memory from ScienceWorld

Using the correct container or setup
(1)
MAY BE CONTRIBUTE to
boiling the target substance
(2)
.

Why this memory is harmful

(1)
Vague object reference.
“Correct container or setup” does not specify which observable object should be selected, moved, opened, filled, or heated, so it provides little actionable guidance.

(2)
Generic task hint.
The memory merely restates that some appropriate setup may help with boiling, but does not identify a concrete precondition, action sequence, or failure mode.
