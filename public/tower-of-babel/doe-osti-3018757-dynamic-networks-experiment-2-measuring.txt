ABSTRACT
The seismic event building pipeline consists of several processing stages (i.e., waveform data
quality control, signal detection, association, and then location) in which waveforms recorded by
a seismic sensor network are transformed into an event bulletin containing event sources (i.e.
latitude, longitude, depth, and time) and their associated waveform signal onset times. Optimizing
the event bulletin’s accuracy is a difficult problem as it requires selecting the best algorithm and
tuning for each processing stage to optimize the inter-stage interaction. In this study, we
experimentally assess association performance as it relates to input signal detection dataset
quality with the Probabilistic Event Detection, Association, and Location (PEDAL) and Gaussian
Mixture Method Association (GaMMA) association algorithms. Using the Dynamic Networks
Experiment 2 (DNE2) human-analyst event bulletin picks as a baseline signal detection dataset,
we generate 47 additional datasets by gradually reducing their accuracy and completeness by
randomly removing DNE2 picks, changing the initial phase labels from P to S and vice-versa, and
injecting noise detections to simulate real-world signal detection algorithms. We find that
GaMMA outperforms PEDAL when the signal detection P and S phase label accuracy is
approximately 65% or greater, thus establishing a performance target for deep learning phase P,S
pickers. Additionally, we discuss the patterns in which GaMMA and PEDAL split DNE2 event
associations and show GaMMA’s split events are dependent on dataset quality while PEDAL’s
patterns persist across several datasets suggesting they are due to algorithmic biases.

1. INTRODUCTION

The difficulty in adapting an association algorithm to monitoring regions that differ from the data
on which it was originally tested is a function of the complex combination of its implementation,
and the new signal environment properties such as the sensor network geometry, sensor
characteristics which affect the ratio between nuisance and good signal detections, seismic
waveform propagation, etc. Additionally, integrating an associator into an event building pipeline
introduces difficulties when the algorithms generating the associator input and consuming the
associator output are different from those in which the associator was designed and tested. As
such, assessing the ease in which any given association algorithm can be applied to new use cases
requires considerable manual tuning and engineering effort to achieve the best results.
In a recent Department of Energy quad-lab collaboration, the Dynamic Networks Experiment 2
(DNE2) [1], researchers were tasked with comparing an operationally representative baseline
seismic event building pipeline with a pipeline constructed from recently developed
next-generation research algorithms for near-regional monitoring. Thus, researchers faced several
challenges in adapting existing association algorithms into the DNE2 event building pipeline. For
example, the baseline associators considered for DNE2 deployment included the Global
Associator (GA) and the Probabilistic Event Detection, Association, and Location (PEDAL)
[2, 3] algorithms which were designed for global seismic monitoring using the International
Monitoring System (IMS). Global monitoring primarily relies on array station backazimuth and
slowness estimates to achieve good performance. Because the DNE2 sensor network only
consisted of 3-component seismometers adapting either of these algorithms would require
addressing the lack of accurate backazimuth and slowness estimates. Additionally, the DNE2
sensor network density ranged from high at the National Nevada Security Site (NNSS) to low
density around the periphery (see Subplot (a) in Figure 2-1). In contrast, the IMS consists of a
sparse sensor network. As PEDAL was previously utilized for the first Dynamic Networks
Experiment (DNE1), and was deemed simpler in implementation and tuning relative to GA, it
was selected as the operational baseline. Of the several next-generation associator algorithms the
Graph Earthquake Neural Interpretation Engine (GENIE) [4], a graph neural network and the
Gaussian Mixture Model Association (GaMMA) [5] algorithm, a probabilistic unsupervised
clustering method adapted to seismic event building [5] were considered for the DNE2. Again,
opting for simplicity in design and tuning, GaMMA was chosen as it did not require expertise in
training graph neural networks.
Researchers faced several challenges in comparing PEDAL to GaMMA due to differences in their
designs and how these differences were amplified (or not) by the DNE2 pipeline. In contrast to
PEDAL, GaMMA was designed for a regional three-component sensor network, and thus, was
naturally suited for the DNE2 dataset. However, as GaMMA cannot assign phases to associated
signals, the initial phase (iPhase) determined by station processing [2] is essential. Specifically,

 11

GaMMA was designed to leverage the P and S iPhases and probability of detection score
generated by the deep learning phase detection model, PhaseNet [6]. Thus, to maximize
GaMMA’s performance, an accurate PhaseNet model must be trained for the target signal
environment, which in the DNE2, was not available [1]. In contrast, PEDAL does not utilize the
iPhase during its association processing. Hence, the need to assess iPhase accuracy to compare
GaMMA to PEDAL, and whether this accuracy could be achieved in practice was left as an open
question from DNE2, motivating the current work.
In this report we address the complications of adapting association algorithms to new signal
environments by comparing PEDAL’s and GaMMA’s sensitivity to degrading input data
conditions. We employ the DNE2 human analyst signal picks to compute a best case baseline
performance for PEDAL and GaMMA results with respect to the DNE2 event bulletin using the
Event Commonality Score (ECS) [3, 7]. We then compare performance trajectories of these two
algorithms over several input datasets by degrading the DNE2 “ground truth” bulletin by
randomly removing picks to simulate missed signal detections, randomly injecting signal
detection times to simulate false signal detections, and randomly changing P iPhases to S iPhases,
and vice-versa. These performance trajectories experimentally establish the input dataset
conditions for which each algorithm is best suited. Finally, although our results are specific to
PEDAL and GaMMA, our methodology for generating degraded input datasets and comparing
the performance trajectories can be applied to any associator to assess their “transferability” to
new signal environments and event building pipeline use cases.

2. METHODS AND DATA

2.1. Ground-Truth Data and Input Datasets

The DNE2 dataset consists of six segmented time periods which collectively span June 21st, 2019
to July 31st, 2022 from the southern Nevada region using a mixed sensor network (Figure 2-1).
As part of the DNE2, an expert analyst manually built an event bulletin which served as a
benchmark for analyzing seismic, infrasound, and radionuclide event detection algorithms [1]. In
this study, we use the DNE2 seismic event bulletin as the ground-truth representation of the
region’s seismic activity which is comprised of local to near-regional distance events with 19606
Pg, 2016 Pn, 21910 Lg, and 1203 Sn associated phases. Because GaMMA requires associated
phases to be identified during station processing when signal onset times are detected from
waveforms (i.e. with PhaseNet), we set the iPhase for Pg and Pn to P, and Lg and Sn to S. (Note
that we also tested GaMMA with Pn, Pg, Sn, and Lg iPhases, but this resulted in worse
performance relative to using only P and S iPhases). In total, the ground-truth dataset which we
use to measure associator performance is comprised of 44812 human-analyst picks associated to
1857 events, each of which has at least five associated phases. Finally, of the 44812 ground-truth
picks 21624 are P iPhases and 23188 are S iPhases.
Using the DNE2 bulletin picks, we generate 47 degraded input signal detection datasets by
randomly removing human analyst picks, randomly injecting spurious detections, and changing P
iPhases to S iPhases (and vice-versa). By degrading the input data quality, we simulate real-world
signal environments in which associators must build events with incomplete and inaccurate
evidence. Table 1 lists the degradation values for each of these parameters along with the
parameter code we use to identify each dataset. In total, we run each associator on 48 input
datasets and measure the corresponding results with respect to the DNE2 human analyst bulletin.
As a final note, we apply the pick transformations in the following order: 1) pick dropout, 2) pick
phase accuracy, and 3) noise detection injection. In cases where one or more transformations are
not applied, the corresponding step in the above-listed sequence is skipped.

challenges. For example, PEDAL’s spatial and fitness functions incorporate back-azimuth and
slowness estimates derived by station processing algorithms such as the International Data
Centre’s Detection and Feature Extraction (DFX) software [8], however, in this study, these
estimates were not available, thus PEDAL’s results were based solely on signal detection time.
Additionally, we made several tuning updates to PEDAL for the DNE2 dataset. For the IMS,
PEDAL’s station phase prediction models incorporate several phases which are not applicable in
local to near regional monitoring (e.g. core phases). For the DNE2 dataset, we limited PEDAL’s
station phase prediction models to Pg, Pn, Lg, and Sn to coincide with our DNE2 ground-truth
signal environment. Ideally, an accurate travel time model would be used to predict these phases.
However, we opted to use AK135 to test PEDAL from the standpoint of having no prior
geophysical knowledge, other than the regional phases (note that we made the same choice for
GaMMA). To better match GaMMA’s event definition criteria (see section “The GaMMA

Algorithm”), we added an event definition criteria check at the end of PEDAL’s processing loop
to only keep events with five or more associations. Finally, as PEDAL’s initial event candidate
detection algorithm assumes every phase is a first-arriving P (i.e. a Pg or Pn phase in this study),
true S phase signal detections are always incorrectly backprojected which can cause PEDAL to
generate erroneous candidate events. Thus, we updated PEDAL to selectively ignore a

sets of results for PEDAL: 1) the label “PEDAL” designates the case in which all signal
detections are backprojected as first arriving P during the event candidate generation, and 2) the
label “PEDAL-P” designates the results where only P iPhases were backprojected as the first
arriving P during the event candidate generation.

2.3. The GaMMA Algorithm

GaMMA is a Python-based associator that models detected signals as originating from a
combination of K Gaussian distributions, i.e. source locations and times [5]. Because Gaussian
mixture models require the number of distributions to be specified a priori, the authors employed
a Bayesian version of the model which allows a user to configure many more source distributions
than required without overfitting the data through a variational learning process that suppresses
unnecessary sources [5]. GaMMA utilizes the expectation maximization algorithm to identify
sources by maximizing the likelihood of the observed signal detections given the source location
parameters. In the expectation step, each detection association probability to the K possible
earthquakes (i.e. Gaussian distributions) is computed, and in the maximization step, the
earthquake source parameters are updated. Each possible event location is then passed to the
filtering stage where a user-configured minimum number of associated phases and the associated
phase pick time residuals are checked. Events failing any of these checks are discarded.
GaMMA’s design utilizes the signal onset time, a detection probability (i.e. PhaseNet confidence
score), detection waveform amplitude, and iPhase (P or S). However, as our signal detection
datasets did not include amplitude and detection probability values, we configured GaMMA to
only use signal detection time and iPhase.
GaMMA’s runtime is proportional to the number of Gaussian distributions, i.e. the product of the
maximum number of potential earthquakes and number of signal detections. The number of
earthquakes has an upper bound configured by the user, but the number of signal detections varies
depending on the sensor network activity. Thus, when a large number of signal detections are
generated, GaMMA’s runtime will increase [5]. To reduce computational burden, the
density-based spatial clustering of applications with noise (DBSCAN) [9] algorithm is employed
to subdivide the input signal detections into separate processing windows. These signal detection
clusters are identified by comparing their onset time difference to the likely maximum allowable
time difference if they were generated by the same earthquake [5]. Each window can then be
processed independently of the others, allowing GaMMA to be run in parallel.
GaMMA’s tuning parameters were selected to achieve optimal performance on the ground-truth
picks and these same parameters were used for all data augmentation tests. The spatial and

 15

temporal configuration for possible event locations and origin times were kept consistent with
those used for PEDAL: 1) a spatial bounding box of -120 to -113.1 longitude and 34.3 to 42.0
latitude, and 2) a temporal bound of 6/21/2019 00:00:00 UTC to 7/31/2022 00:00:00 UTC. We
limited GaMMA to only build events on the surface, i.e. 0 km depth, because allowing the event
depths to range between 0 km and 20 km yielded worse results. GaMMA’s P and S phase
velocities were set to their respective AK135 global velocity average shallow crust values. Lastly,
we set the minimum number of associations needed to keep an event to be five, consistent with
the threshold value used for the PEDAL algorithm.
For DBSCAN we set our initial oversampling factor to 3.0. Additionally, we achieved our best
results by setting the maximum arrival time neighborhood (the DBSCAN eps parameter) to 48
seconds to better account for phases from the same source propagating across local and
near-regional source-receiver distances. It is important to note that the proper tuning of the
DBSCAN clustering parameters was the most vital tuning step to achieving optimal results with
the GaMMA algorithm on the DNE2 datasets.

3. RESULTS AND DISCUSSION

In this section, we measure the bulletins generated from the degraded data sets using ECS metrics
to compute overall precision and recall trajectories as a function of signal detection precision,
recall, and iPhase label accuracy. We choose two input datasets to highlight each associator’s
algorithmic efficacy (or lack thereof) in these signal environments using the ECS Valid and False
Split event locations. Figure 3-1 shows the number of true positive and false positive events
generated by PEDAL and GaMMA for each input dataset. Each subplot shows the performance
dependence with respect to iPhase accuracy. In each column the noise-to-true detection ratio
(NR) is constant. Finally, in each row, the true signal detection dropout (DO) is constant. To
specify subplots and/or specific iPhase label accuracy data points we use the notation [Dropout
Percentage, Noise Rate, iPhase accuracy]. For example, the upper-left subplot would be identified
as “[DO=0%, NR=0],” and the 100% iPhase accuracy data point within this subplot would be
identified as “[DO=0%, NR=0, P=100%].”
First, examining the [DO=0%, NR=0] subplot, as the iPhase accuracy decreased, both GaMMA
and PEDAL-P generated fewer true positive events and more false positive events. This behavior
held for all datasets, thus, for brevity, we only label the iPhase accuracy in the upper-left subplot.
Also note that although PEDAL was run on all datasets, its results in upper-left subplot appear as
a single data point. This behavior is due to PEDAL’s algorithm ignoring the iPhase label.
However, in subplots with D0 > 0% and (or) NR > 0, PEDAL’s results varied due to each arrival
dataset being randomly generated with different initial seed values, rather than depending on the
iPhase accuracy. Thus, within each subplot, these distributions are a measure of PEDAL’s
robustness with respect to false alarm rate and dropout percentage.
GaMMA generated the greatest true positive event count when the iPhase accuracy was greater
than 50%, and its largest decrease in recall consistently occurred with iPhase between 75% and
50%. With 50% iPhase label accuracy, GaMMA’s and PEDAL’s recall were roughly equal across
all datasets. Because the baseline dataset consisted of approximately an equal number of P and S
phases, PEDAL’s event detection algorithm, which assumes each input phase is a first-arriving P,
can be interpreted as “having an iPhase accuracy of 50%.” When the iPhase accuracy was 50%,
PEDAL also generated fewer false positive events than GaMMA at the [D0=50%], [D0=25%,
NR<=2], and [D0=0%, NR<=1] datasets.
PEDAL-P consistently generated fewer false positive events than PEDAL on all datasets, and
when iPhase accuracy was >= 75%, PEDAL-P also registered better recall than PEDAL.
However, GaMMA outperformed PEDAL-P’s recall performance for most test cases. For
example, at data points [DO<=25%, NR<=2, P>=75%] GaMMA registered better recall and
comparable or better precision relative to PEDAL-P. However, we note two opportunities for
improving the PEDAL-P results. First, the PEDAL-P results were generated with the same tuning
parameters as PEDAL, thus we believe better results could be achieved by re-tuning PEDAL-P’s

 19

event detection algorithm parameters such as event detection threshold, its secondary association
algorithm search threshold, and fitness function multipliers [3]. Second, unlike GaMMA,
PEDAL-P does not benefit from accurate S iPhase labels. Additional logic could be added to
PEDAL’s code to leverage secondary phases.
In summary: 1) If recall is prioritized, GaMMA is the best associator when the iPhase accuracy is
greater than 50%. 2) If precision is prioritized, PEDAL-P is the best associator if iPhase accuracy
is greater than 75%. 3) If the iPhase accuracy is 50%, the choice between GaMMA and PEDAL
should be made from additional information beyond precision or recall.
Finally, we note that GaMMA’s recall improved without increasing the number of false events
when noise was increased (compare data points P=100% and P=75% in subplot NR=0 to those of
subplot NR=1 in Figure 3-1). This apparent improvement in performance is observed both when
DO=25% and DO=50%. For the NR=2 and NR=3 tests, GaMMA also generates a greater number
of true positive events as compared to the NR=0 test case. Hence, contrary to intuition, as the
number of noise signal detections increased, GaMMA generated an increased number of true
positive events for the aforementioned datasets. There are several potential explanations for this
behavior. First, the ECS algorithm and tuning could be interacting with GaMMA’s results in
unexpected ways, causing this apparent performance increase. Second, because we are randomly
generating one input dataset for each dataset tuning point, it is possible this effect was due to a
small sample size, i.e. an outlier data set realization. Third, and most intriguing, is this
performance increase being a stochastic resonance effect, a well-known phenomenon observed in
nonlinear systems whereby increasing input noise yields improved processing results (Moss et al.
2004). While testing GaMMA, we noticed that DBSCAN generated additional signal detection
neighborhoods with respect to increasing the number of randomly injected noise signal
detections. Most of these newly created neighborhoods did not yield additional events. However,
of the additional events that were generated, several were labeled as a true positive, thus
increasing recall. Although far from definitive proof, the possibility that associators, which are
nonlinear systems, exhibit stochastic resonance warrants further investigation. If stochastic
resonance can be identified or engineered into associators, signal detection algorithms should be
tuned to downstream associator’s optimal stochastic resonance noise rate.

4. ALGORITHM DESIGN

When deciding which of the viable candidate events to associate arrival Ai , PEDAL simply selects
the event with the highest phase fitness score (arg maxe∈Events P(Ai , Phase|e)) [3]. In contrast,
GaMMA’s probability model prioritizes event solutions that jointly associate a station’s P and S
phases. GaMMA is also constrained to only associate a P iPhase as P and S iPhase as S, a
constraint not present in PEDAL. Thus, PEDAL is more likely to generate event solutions that
overfit individual signal detections either by spliting phase P and S phase pairs, or by associating
P phases to S and vice-versa. These two factors lead to PEDAL consistently splitting DNE2 R1
associations to the S3 regions in all datasets. Although our attempt at constraining PEDAL by
limiting its initial event candidate search to utilize only P phases reduced false positives, it did not
mitigate this split event behavior. Hence, PEDAL as designed, is under-constrained relative to
GaMMA for this signal environment. Figures A-1, A-2, A-3, and A-4 in Appendix A illustrate
PEDAL splitting an R1 DNE2 event’s associations between two false events, one in the S1 region
and one in the S3 region.
Nonetheless, there are additional opportunities for improving PEDAL’s performance without
re-engineering/redesigning the associator. First, in addition to signal detection time, PEDAL’s
event detection fitness function incorporates observed back azimuth and waveform slowness
measurements [3]. If station back azimuth estimates were available for this signal environment,
the DNE2 R1 event associations would be less likely to associate with grid locations in the S3
region. Second, PEDAL’s event detection fitness function also includes a probability of detection
(PDET) term conditioned on station and event location. These distributions scale each station’s
contribution to a given grid location during the backprojection event candidate search [3].
Estimating each station’s PDET distribution requires an accurate historical bulletin for the
monitoring area under consideration. For example, in [3], these PDET functions were estimated
from the Late Event Bulletin [8], a human analyst-reviewed bulletin. Hence, similar machine
learning methods, configuring these PDET distributions requires accurate “training data.” In this
study, we set the PDET functions equal to one for all station-grid location pairs, i.e. a uniform
sensor network prior. Adjusting the PDET functions could reduce the NNSS station influence on
splitting DNE2 R1 events to the S3 region.

5. CONCLUSION

In this sensitivity analysis we explored associator performance on 48 signal detection datasets
developed in part for the Dynamic Networks Experiment 2 [1]. We used the DNE2 human-analyst
event bulletin picks as our “perfect” input signal detection dataset to generate baseline results for
the GaMMA and PEDAL association algorithms. We generated 47 additional input datasets from
the baseline input by gradually removing picks, changing their iPhase labels, and injecting noise
detections. We discussed the resulting association performance trajectories generated from these
datasets to assess each associator’s robustness to imperfect data. We found that GaMMA’s
performance was most sensitive to the iPhase accuracy dropping from 75% to 50%, whereas
PEDAL was not affected due to its “iPhase agnostic” design. However, GaMMA’s superior
performance to that of PEDAL when the iPhase accuracy was greater than 75% led us to update
PEDAL to only back-project P phase detections during its event candidate grid search. Denoted
as PEDAL-P, the precision was better than that of PEDAL, but with iPhase accuracy <= 75%,
PEDAL’s recall was better than that of PEDAL-P. We did note that additional PEDAL-P tuning
could result in better performance relative to PEDAL. Nonetheless, our results demonstrated the
utility of constraining associator solutions using iPhases when P and S-phase accuracy was
greater than or equal to 75%.
Examining DNE2 pick dropout (DO), all algorithms performed as expected: as dropout increased
associator recall was reduced. With 50% DNE2 pick dropout, GaMMA generated more false
detections for each iPhase value and injected noise detection rate (NR). Meanwhile, the increased
NR resulted in all algorithms generating more false positives, as would be expected. GaMMA’s
increased recall at NR=1 relative to NR=0 did not follow the expected behavior that fewer noise
detections should result in “better” performance. We discussed several possible reasons why this
occurred: 1) our Event Commonality Score algorithm and tuning assessed GaMMA’s NR=0 and
NR=1 results in unexpected ways, 2) we have generated one data point for each iPhase accuracy
level in the NR=0 and NR=1 datasets, thus, this effect could be due to small sample size, or 3)
this behavior could be a stochastic resonance effect.
Finally, we discussed the false split event patterns observed in GaMMA and PEDAL. GaMMA’s
most notable split event behavior showed a bimodal dependence on the iPhase accuracy, in which
the Northwest DNE event associations were assigned to false split events in the NNSS region
when iPhase accuracy was less than 100%. When the iPhase was 100% accurate, the majority of
NNSS region false events were associated to DNE2 events from the same region. Both PEDAL
and PEDAL-P consistently associated signals from the Northwest DNE2 events to false events in
the Southwest along a radial arc centered on the NNSS stations. This behavior persisted across
several NR and DO values indicating it was not a data effect, but rather algorithmic in nature. We
noted that because PEDAL’s event candidate fitness function can incorporate station-to-event
back-azimuth, if reasonably accurate source direction estimates for the NNSS station signal

 27

detections were available, associating Northwest signals to the Southwest would be less likely to
occur. Additionally, as we set PEDAL’s station probability of detection (PDET) to one for all
station grid-location pairs, tuning NNSS station PDET functions could also result in better
performance for PEDAL.
