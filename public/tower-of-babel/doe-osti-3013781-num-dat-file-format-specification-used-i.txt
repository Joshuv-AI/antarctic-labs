1 Summary
The M-9 Shock and Detonation Physics group executes experiments on gun and explosive platforms
with large numbers of oscilloscopes used for data acquisition. The data acquisition from these
oscilloscopes was automated many years ago using a custom piece of software called RunDig. The
default save format from this software is a custom structure referred to as "NUM-DAT" format.
This file format includes a text ".DAT" file which is a header file used to interpret the binary
".NUM" file which contains the oscilloscope data. The data save format was originally developed
by John Vorthman and has been in use by M-9 personnel for over 20 years. This data format has
been used for archiving data from experiments performed by M-9 personnel at TA-40, TA-39, and
the TA-55 Impact Test Facility. Numerous custom analysis and visualization programs have also
been developed, and continue to be used, that utilize this data format. This document describes the
NUM-DAT format and provides code examples for reading the format and converting it to other
formats.

2 Introduction
The NUM-DAT format was developed many years ago by John Vorthman. The format was originally
implemented in FORTRAN, then implemented in software developed in Visual Basic, then imple-
mented in the LabVIEW "RunDig" program by Ramon Saavedra, and ultimately implemented in
MATLAB and Python. The data format is the default into which data is saved from the "RunDig"
program used by M-9 to save oscilloscope data from experiments. The file format is also the de-
fault which is read into various programs used by M-9 for analysis of shock physics experimental
data, especially for VISAR (Velocity Interferometer System for Any Reflector) and PDV (Photonic
Doppler Velocimetry) data profiles.
 The specification of the NUM-DAT format reported here was reverse engineered from the various
programs used by M-9 as any original documentation of the file format has not been archived. The
source material included RunDig, qplot, a NUM-DAT reader which was implemented in MATLAB
(included here as Appendix A), and a NUM-DAT writer implemented in LabVIEW. The specifica-
tion was verified by the authors here by verifying example data files were accurately written and
read.

3 NUM-DAT Specification
The .DAT file is an ASCII file which contains header information and metadata for interpreting the
.NUM file which is stored in a binary format. A screenshot of an example .DAT file is shown in
Figure 3-1 for reference. The .DAT file identifies the file name (DEV21.DAT), scope model that was
used to record the data (DPO72304DX), the date the file was recorded (7/10/2025 at 11:42am), a
comment line, the number of traces in the binary file (4), and the details of each individual trace.
The structure of each line and the variables that are written are identified in Figure 3-2.

 Figure 3-1: Example .DAT file.

 The .NUM file contains the saved data in binary as 16-bit signed integers. Little-endian byte
ordering was used to save all data the authors are aware of. Very old (>30 years) data that were
saved on legacy computer systems (e.g., mainframes, minicomputers) may have used big-endian
byte ordering. The signal values for each oscilloscope channel are stored sequentially, starting with
the first channel identified in the .DAT file. The first 16 bits of the .NUM file that would correspond
to the first signal value on the first channel, the next 16 bits are the second signal value on the first
channel, and so forth. The second channel first data point starts immediately after the first channel

last data point. The .DAT file information for the number of entries for each channel is critical to
segmenting the .NUM file. The size of the .NUM file is defined by:

 SCOPE_CHANNEL_COUNT ∗ RECORD_LENGTH ∗ 16 bit (1)

assuming that all of the record lengths are the same, which is typical.
 The .NUM file does not contain the x-axis (time axis) information directly, it is assumed that the
points are equally spaced as defined by the "XINCR" value in the .DAT file for each channel. The
"XZERO" value in the .DAT file then gives the offset value of the x-axis. The .NUM file contains
the vertical signal value at each point, which is multiplied by the "YMULT" value and offset by
the "YZERO" values in the .DAT file. Data records are reconstructed from the .NUM file by first
parsing it into a data array DATA(i,j), with channel count i and time index count j. The true data
is then recovered for time (X) and voltage (Y) data using:
for i=1:SCOPE_CHANNEL_COUNT
 for j=1:RECORD_LENGTH
 X(i,j)=X_ZERO(i)+X_INCREMENT(i)*j
 Y(i,j)=Y_ZERO(i)+Y_MULTIPLIER(i)*DATA(i,j)
 end
end

4 A note on other file formats
The NUM-DAT format is useful because all of the scope channnels are saved into a single .NUM file
which is efficiently compressed through the saving structure. Other file formats are also commonly
used by M-9 personnel and are noted here for reference.

 Table 4-1: Common file types

 Format Comment
 .num, .dat M-9 format described by this document
 .dig Nevada Test Site format - see discussion below and [1, 2]
 .csv comma separated variable (ASCII) format - large files, not typically used
 .wfm Tektronix Waveform file format saved directly by oscilloscopes [4]
 .mat MATLAB data file [3]

 A useful toolbox for data analysis and handling is the SMASHToolbox developed by Dolan et al.
[2] at Sandia National Laboratories. This toolbox is available through GitHub (http://github.com)
at https://github.com/sandialabs/SMASHtoolbox. This toolbox can read .dig and .wfm files
directly. It does not have any support for the NUM-DAT format.

5 Example Data
An example dataset was created on an oscilloscope and saved using several file formats to serve as
a reference across the formats. The data archive has been placed on github.com under the title of
"num-dat" at the location https://github.com/mjhargather1/num-dat.git.
 The example data were saved from a Tektronix MSO68B scope. The data was acquired with
16-bit voltage resolution. Channel 1 was a frequency-chirped sine wave. Channel 2 was a constant-
frequency sine wave. Channels 3-8 were disconnected, and only recorded digitizer noise. Figure 5-1
shows the data plotted.
 The data include the following:

 • CSV/Tek001_ALL.csv - Comma-Separated Value ASCII format saved directly by the scope.
 All scope channels in one file.

 • CSV/Tek001_ALL_NoHeader.csv - The same as CSV/Tek001_ALL.csv without the meta-
 data header.

 • DIG/dev33_ch1..8.dig - NTS binary data file format converted from LANL (M-9) binary
 format (NUM-DAT) by xlv17r in MATLAB. [1]

 • MAT/Tek000_ch1..8.mat - MATLAB binary data file format saved directly by the scope. One
 file per scope channel.

 • NUM/DEV33.DAT,NUM - LANL (M-9) binary data file format saved by RunDig 2.7. All
 scope channels in one file.

 • WFM/Tek001_ch1..8.wfm - Tektronix Waveform file format saved directly by the scope. One
 file per scope channel.

The data in all formats agrees to within round-off error.

% are extracted from the .NUM file, cast into a (npts x ntraces) matrix

import numpy as np
from pathlib import Path

def read_num(filename):
 """
 Read binary files generated by RunDig.

 Reads .DAT file for metadata (points, traces, scaling factors),
 generates time data, then extracts and scales y data from .NUM file.

 Parameters
    ----------
 filename : str or Path
 Path to the .DAT file

 Returns
 -------
 Y : ndarray
 Scaled y data (npts x ntraces)
 t : ndarray
 Time data (npts x 1)
 """

 # Input validation
 if not filename:
 raise ValueError("Input error: must specify DAT file to read.")

 filepath = Path(filename)
 if not filepath.exists():
 raise FileNotFoundError(f"File error: {filename} does not exist!")

 if not filepath.is_file():
 raise ValueError(f"File error: {filename} cannot be opened!")

 # Define matching .NUM file
 numfile = filepath.with_suffix('.NUM')

 # Parse .DAT file
 with open(filepath, 'r') as fid:
 next(fid) # Skip filename line
 next(fid) # Skip comment line
 ntraces = int(next(fid).strip()[0])

 # Pre-allocate arrays for scaling factors
 numpts = np.zeros(ntraces, dtype=int)
 xincr = np.zeros(ntraces)
 xzero = np.zeros(ntraces)
 ymult = np.zeros(ntraces)
 yzero = np.zeros(ntraces)

 # Read scaling factors for each trace
 for i in range(ntraces):
 next(fid) # Skip header line
            numpts[i] = int(next(fid).split(',')[0])
            xincr[i] = float(next(fid).split(',')[0])

 1

            xzero[i] = float(next(fid).split(',')[0])
            ymult[i] = float(next(fid).split(',')[0])
            yzero[i] = float(next(fid).split(',')[0])

 # Use first trace parameters for time generation
 npts = numpts[0]

 # Generate time data (vectorized)
   t = xzero[0] + xincr[0] * np.arange(1, npts + 1)

 # Read binary .NUM file and reshape
 with open(numfile, 'rb') as fid:
 A = np.fromfile(fid, dtype=np.int16)

 # Reshape: one column per channel
 B = A.reshape(npts, ntraces, order='F') # Fortran order for MATLAB compatibility

 # Scale Y data (vectorized operation)
 Y = yzero + ymult * B

 return Y, t
