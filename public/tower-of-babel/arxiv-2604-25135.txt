FAMA: F ailure- A ware M eta- A gentic Framework for Open-Source LLMs in Interactive Tool Use Environments
Amir Saeidi, Venkatesh Mishra, Souradeep Mukhopadhyay, Gaowen Liu, Ali Payani, Jayanth Srinivasa, Chitta Baral

Abstract
Large Language Models are being increasingly deployed as the decision-making core of autonomous agents capable of effecting change in external environments. Yet, in conversational benchmarks, which simulate real-world customer-centric issue resolution scenarios, these agents frequently fail due to the cascading effects of incorrect decision-making. These challenges are particularly pronounced for open-source LLMs with smaller parameter sizes, limited context windows, and constrained inference budgets, which contribute to increased error accumulation in agentic settings. To tackle these challenges, we present the Failure-Aware Meta-Agentic (FAMA) framework. FAMA operates in two stages: first, it analyzes failure trajectories from baseline agents to identify the most prevalent errors; second, it employs an orchestration mechanism that activates a minimal subset of specialized agents tailored to address these failures by injecting a targeted context for the tool-use agent before the decision-making step. Experiments across open-source LLMs demonstrate performance gains up to 27% across evaluation modes over standard baselines. These results highlight that targeted curation of context through specialized agents to address common failures is a valuable design principle for building reliable, multi-turn tool-use LLM agents that simulate real-world conversational scenarios.

In this work, we argue that reliable multi-turn tool use requires failure-aware agent composition. We introduce a two-stage framework, named the

FAMA operates in two stages. First, it analyzes failure trajectories produced by a baseline agent and categorizes errors into a small set of common failure types.
Rather than treating all errors equally, this analysis surfaces the dominant errors that most strongly impact performance.

In the second stage, the FAMA framework employs a lightweight routing mechanism consisting of an orchestrator and a mitigation agent (Figure

meta-agentic

4
Method

Although frontier models in agentic frameworks demonstrate strong performance on complex, dynamic tasks, their deployment is often prohibitively expensive. Additionally, integrating these models into private or proprietary products is often impractical due to cost and security constraints. Open-source models, by contrast, offer a viable alternative; their smaller size enables local deployment, making them more cost-effective and better suited for privacy-sensitive applications.

Recent works
(
38
;
52
;
24
)
show that open-source models, along with inference-time frameworks built around them, can achieve performance comparable to frontier models on mathematical and reasoning tasks; however, their use within agentic frameworks to solve a complex task remains challenging. Due to their smaller size and the nature of the data on which they are fine-tuned, these models exhibit distinct failure modes and limitations. Additionally, strict context constraints limit their applicability in complex multi-agent frameworks, where multiple agents must collaborate to solve a task, and rapidly fill up the context windows. These factors lead open-source models to exhibit weaker decision-making capabilities compared to frontier models.

To address these challenges, we propose the
Failure-Aware Meta-Agentic (FAMA)
framework, a general and dynamic framework designed to identify failure patterns in the behavior of open-source model agents and determine an effective set of agents that achieves improved performance under resource constraints. In the following sections, we present and analyze the FAMA framework in detail.

4.1
Failure-Aware Meta-Agentic Framework

We assume the availability of a predefined set of agents
\mathcal{A}
, where each individual agent is denoted by
a\in\mathcal{A}
, and subsets of agents are denoted by
\mathcal{A}^{\prime}\subseteq\mathcal{A}
. The full agent set
\mathcal{A}
is adapted from
43
, which proposes a collection of specialized agents for improving performance in tool-calling environments, and is further extended with additional modules tailored to the benchmarks evaluated in this work. Specifically,
\mathcal{A}
includes a Domain Constraints Extractor Agent (DCE), a Tool Suggestion Agent (TSA), a Tool Output Reformulator Agent (TOR), a Planner Agent, a Decision Verifier Agent, and a User Context Manager (Memory) module.

We further assume the availability of a predefined set of general error categories representing common agent failures, denoted by
\mathcal{E}
, where a realized error instance is denoted by
e\in\mathcal{E}
. Based on prior studies
43
;
54
;
31
and our own analysis, we categorize failures in tool-calling environments into four classes:
(1)
Domain Policy Violation,
(2)
Incorrect Retrieval from Complex Tool Outputs,
(3)
Contextual Misinterpretation and Hallucination, and
(4)
Incomplete Fulfillment or Early Stopping. Detailed definitions of these error categories are provided in Appendix
E
.

Given the agent set
\mathcal{A}
and the error category set
\mathcal{E}
, we define
|\mathcal{E}|
independent error analysis agents, each responsible for detecting the cause of failure associated with a specific error category
e
. These agents operate over a predefined list of failure causes derived from empirical analysis of baseline trajectories. Additional details on the causes of failure for each error category are provided in Appendix
E
. Each error analysis agent produces both a categorical decision and a supporting rationale in textual form.

The textual outputs and rationales produced by all error analysis agents are concatenated into a single input and, together with the full interaction trajectory between the user and the tool-calling agent for a given task
\tau
, are passed to the orchestrator agent for final failure attribution. This process explicitly accounts for cases in which an agent may initially make incorrect decisions but later recover after receiving feedback from the environment, ensuring that failure attribution reflects the overall trajectory rather than isolated errors.

In the final stage, conditioned on the error categories identified by the orchestrator agent and the functional definitions of agents in
\mathcal{A}
, a dedicated mitigation agent determines an efficient subset of agents
\mathcal{A}^{*}\subseteq\mathcal{A}
that can mitigate a specific error category
e
. Aggregating the mitigation agent’s recommendations across the selected error categories yields a final agent subset that represents the minimal configuration required to address the dominant failure modes.

We collect these recommendations across tasks and deploy multi-agent frameworks composed only of the selected agent subsets (See Algorithm
1
). The results reported in Tables
1
-
4
demonstrate that FAMA consistently achieves better performance across different settings compared to IRMA, ReAct, and FC on both
\tau
-bench,
\tau
-trait, and ACEBench across different models.

5.2
Experimental Results

Open-source agents can be trusted as user simulator agents.

In this experiment, we use the Qwen3-4B-Thinking model as the tool-calling agent. We select this model due to its relatively small size and its ability to achieve performance comparable to larger models. For the user simulator, we evaluate five state-of-the-art open-source models, namely LLaMA-3.1-70B-Instruct
(
22
)
, Qwen2.5-72B-Instruct, Qwen3-8B, Qwen3-14B, and Qwen3-32B
(
66
)
. All experiments are conducted on the Airline domain of
\tau
-bench, and the results are compared against a setting in which GPT-4o is used as the user agent. The results in Figure
3
indicate that, among open-source models, Qwen-2.5-72B-Instruct is the closest to a frontier model such as GPT-4o, as its pass@1 performance averaged over five runs surpasses that of GPT-4o.

Using all agents leads to inconsistent performance across models.

Consistent with prior work, we evaluate open-source models on
\tau
-bench in the IRMA setting. Table
1
shows that IRMA outperforms other baselines in a limited number of cases, indicating that while multi-agent frameworks can be beneficial, indiscriminately using all agents does not consistently improve performance across models and can, in some cases, degrade the base agent’s performance.

FAMA consistently outperforms baseline methods across different benchmarks.

Tables
1
–
4
show that the effectiveness of an agentic framework is highly sensitive to both agent selection and domain, and that naively including all agents can degrade performance. By selectively enabling agents based on dominant failure modes, FAMA avoids unnecessary context injection and focuses mitigation on the most impactful errors. As shown in Table
1
, FAMA outperforms ReAct, FC, and IRMA by 4.63%, 11.57%, and 5.27% in the Airline domain and by 5.30%, 8.96%, and 6.15% in the Retail domain, averaged over five runs.

FAMA is a generalizable method.

Generalizability is a key limitation of static multi-agent frameworks, which are typically tailored to frontier-model failures in specific domains and require extensive manual redesign to adapt to changes. In contrast, FAMA is a dynamic framework that overcomes this limitation. Experiments across multiple domains and benchmarks, including ACEBench and
\tau
-trait, show that FAMA consistently outperforms other methods by adapting to agent failure behavior (See Tables
3
and
4
). For detailed results on the
\tau
-trait and ACEBench benchmarks, refer to Appendix
D
and
C
.
The modular components in FAMA enable the easy addition of specialized agents to address specific error patterns.

To further contextualize our results, we also evaluate reasoning-enabled (“thinking”) variants of Qwen3 models. As shown in Figure
6
, while such variants can improve certain baseline methods, they incur higher token usage (see Table
2
) and frequently lead to context window overflows in multi-turn settings, where accumulated reasoning traces consume a significant portion of the available token budget. We quantify this effect by counting instances (refer to Table
8
) that exceed the maximum token limit across runs and treat them as failures, as mitigating them would require truncating critical context (e.g., domain constraints or prior tool outputs), potentially leading to incorrect decisions. In contrast, FAMA achieves stronger and more stable performance across k without relying on expensive internal reasoning steps.

5.3
Analysis and Ablation Study

To analyze error patterns, we run each task within a domain five times. The results in Figures
4
,
12
, and
14
show that all evaluated open-source models exhibit significant difficulty with domain constraint violations and contextual misinterpretations. This indicates that, even when solving a task, selecting actions that strictly adhere to domain-specific rules remains challenging. This issue becomes more pronounced as conversations grow longer, since domain constraints provided in the system prompt tend to be forgotten over time, highlighting memory-related limitations in open-source models. The results in Figure
5
show that the mitigation agent strongly recommends the Memory module and the DCE agent, confirming that memory is a critical bottleneck for open-source agents.

Motivated by these findings, we conduct an ablation study on memory size to identify effective configurations across domains. As shown in Appendix
F
, the optimal memory size is domain-dependent rather than model-dependent. Specifically, Figure
10
shows that the Retail domain, which involves longer and more complex user–agent interactions, benefits from a larger memory size, with
k=6
achieving the best performance, whereas the Airline domain attains optimal results with a smaller memory size of
k=2
. We also compare these settings against a no-memory baseline. Overall, the results demonstrate that an agentic framework with an appropriately sized memory not only outperforms IRMA, which uses all agents, but also surpasses other baseline methods. Additional ablation studies on agent combinations that differ from those recommended by the mitigation agent, as well as evaluations with various frontier models in the FAMA framework, have been provided in Appendix

. A comparison with an additional baseline, Self-Reflection (based on
42
), is provided in Appendix

We also experiment and analyze efficiency in terms of latency and token overhead (see Figure

Methods that introduce additional reasoning or helper agents incur higher runtime and token costs, which can worsen context-window size constraints in multi-turn settings. In particular, IRMA exhibits substantial overhead (50 and 58%), and task completion latency (149.8 and 111.6 seconds averaged) for Qwen3-32B on retail and airline tasks. the added cost of agentic scaffolding offsets its benefits by straining the available token budget and degrading overall reliability.

6
Conclusion

In this work, we present the Failure-Aware Meta-Agentic (FAMA) framework, a dynamic multi-agent approach designed to overcome the limitations of open-source language agents in interactive environments such as tool calling. FAMA operates in two stages: first, it analyzes agent failures to identify dominant error patterns; second, it selects a minimal, task-relevant subset of agents via an orchestrator framework to mitigate these errors. We evaluate FAMA across three interactive tool-calling benchmarks and four open-source LLMs. Results and analyses demonstrate the potential of FAMA as a generalizable, failure-aware orchestration framework for constructing optimized prior contexts as a key design principle for improving and building dependable, resource-efficient conversational agents.

Limitations

While the proposed Failure-Aware Meta-Agentic (FAMA) framework achieves consistent improvements across multiple benchmarks, several limitations remain.

First, FAMA operates over a predefined pool of specialized agents inherited from the underlying agentic framework (§4.1). This design reflects a common setting in existing user-facing, modular tool-use systems, where a fixed set of components is orchestrated rather than dynamically generated. As a result, FAMA’s effectiveness is bounded by the coverage of this agent pool: failure modes that are not well captured by existing agents may not be adequately mitigated. Importantly, this assumption does not imply rigidity. FAMA is designed to be extensible. New specialized agents targeting emerging failure patterns can be incorporated without modifying the orchestration mechanism. However, the current framework does not address the automatic discovery or synthesis of such agents, which remains an important direction for future work.

Furthermore, the benchmarks considered in this study primarily focus on structured conversational environments. While these settings provide a controlled testbed for analyzing failure-aware orchestration, they do not capture the full spectrum of interactive agent deployments. Extending FAMA to more diverse settings, including embodied, multimodal, or open-ended environments with less well-defined failure taxonomies, is an important avenue for future investigation.

\tau

\tau
-trait, we evaluate the task success performance using the pass^k metric
(
67
)
. It is defined as the probability that all of the k independently sampled outputs successfully complete the task, averaged across all tasks. Specifically, if a task is run for
n
independent trials and
c

r=1
), then pass^k can be computed using the following formula:

\text{pass\textasciicircum k}=\mathbb{E}_{\text{task}}\left[\binom{c}{k}\middle/\binom{n}{k}\right]

ACEBench is a tool used for benchmarking centered on function-call correctness across broad everyday domains, built in two parallel languages (English and Chinese) with a final size of 2,000 annotated entries. From 50 agent-based tasks, we have mainly focused on 30 agent multi-turn tasks for our work, discarding the other 20 multi-step tasks.

For ACEBench, End-to-End Accuracy measures the degree of correspondence between

Appendix E
Error Categories and Causes of the Failures

In this section, we first describe the error categories and then elaborate on the underlying causes of failure associated with each category. The definition of each error category is provided below.

Domain Policy Violation:

This error refers to a failure mode in which a tool-using agent issues an action or tool invocation that contravenes the explicit operational rules, constraints, or policies of the simulated domain defined by the environment. These policies govern which actions are permissible under specific states and preconditions. A violation occurs when the agent ignores, misinterprets, or incorrectly applies these domain rules, such as invoking a return operation that is disallowed by the retail domain’s return policy in
\tau
-bench, resulting in an invalid state transition. Because the environment enforces domain policies strictly, such violations cause the task execution trajectory to terminate unsuccessfully, even if the agent’s intent aligns with the high-level task objective.

Incorrect Retrieval from Complex Tool Outputs:

refers to a failure mode in which a tool-using agent fails to correctly extract relevant information from prior tool responses stored in its context. This error typically arises when tool outputs are large, unstructured, or weakly structured (e.g., verbose logs, nested text fields, or mixed natural language and metadata), making it difficult for the agent to reliably identify the correct entities, values, or state variables required for subsequent actions. As a result, the agent conditions later tool calls or reasoning steps on incorrect or incomplete information, leading to invalid decisions or task failure despite the necessary information being present in the environment output.

Contextual Misinterpretation and Hallucination:

refers to a failure mode in which a tool-using agent incorrectly infers the user’s underlying intent due to nuanced, ambiguous, or adversarial natural language instructions. Instead of grounding its interpretation in the domain’s available operations and constraints, the agent over-literalizes phrasing, overlooks implied intent, or hallucinates an incorrect task formulation. This results in the selection and invocation of an inappropriate tool, such as executing a return operation when the user implicitly intends an exchange, despite the correct intent being inferable from contextual or domain knowledge.

Incomplete Fulfillment or Early Stopping:

refers to a failure mode in which a tool-using agent does not fully satisfy all components of the user’s task requirements before terminating or effectively abandoning the interaction. This error commonly arises in long-horizon, multi-turn trajectories where the agent must track multiple obligations across conversational turns while operating over large, unstructured tool outputs. As the interaction progresses, the agent may lose track of pending subgoals, become over-focused on intermediate tool calls, or prematurely conclude the task, resulting in unmet user requests despite partial progress.

To enable judgment agents to detect task failures, a detailed list of failure causes is required. Accordingly, we analyze the trajectories produced by baseline methods and provide a comprehensive list of failure causes for each error category, as described below.

Cause of Domain Policy Violation

1.
The assistant performs an action that the policy explicitly forbids

2.
The assistant skips a step that the policy explicitly requires

3.
The assistant proceeds without meeting conditions the policy requires

4.
The assistant makes commitments that contradict policy rules

5.
The assistant uses data/arguments not provided by user or tools (fabrication)

Cause of Wrong Retrieval from Complex Tool Outputs

1.
The agent states information that differs from what the tool output actually contains

2.
The agent miscounts items or provides wrong totals from tool outputs

3.
The agent selects wrong items when correct options exist in tool output

4.
The agent misses relevant data in tool output that would change the action

5.
The agent attributes data to the wrong entity when multiple exist in output

6.
The agent uses wrong values (IDs, prices, dates, etc.) from tool output

Cause of Incomplete Fulfillment or Early Stopping

The user may have multiple requirements, questions, or actions they need completed. This error occurs when the agent:

1.
Addresses only some parts of a multi-part request

2.
Stops after encountering a difficulty without trying alternatives

3.
Receives confirmation to proceed but never executes the action

4.
Terminates the conversation with unfinished tasks

1.
Understands the words but misses the actual intent

2.
Confuses which entity/item/order the user is referring to

3.
Misapplies criteria or constraints the user specified

Takes an action that doesn’t match what the user actually wanted
