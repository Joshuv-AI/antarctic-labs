Protocol for automated optimization of feature selection and clustering parameters in single-cell RNA-seq using scAutoTune
Authors: Shi Hai Sun, John S. Pezaris
Published: 2026

ABSTRACT
SummarySingle-cell RNA sequencing (RNA-seq) analysis requires dataset-specific tuning of feature selection and clustering parameters. Here, we present a protocol for automated optimization of feature selection and clustering parameters in single-cell RNA-seq using scAutoTune. We describe steps for installing scAutoTune, preparing Seurat objects from public single-cell RNA-seq datasets, and performing grid-based parameter sweeping with optional Harmony batch correction. We then detail procedures for computing silhouette-based performance metrics, visualizing generalized additive model (GAM)-smoothed landscapes, and applying optimal settings to generate uniform manifold approximation and projection (UMAP) embeddings and interpretable clusters.For complete details on the use and execution of this protocol, please refer to Sun et al.1

Before you begin

In this protocol, we describe the use of scAutoTune, an R-based pipeline for global optimization of feature selection and clustering parameters in single-cell RNA-seq analyses performed with Seurat.2 scAutoTune is built around a silhouette-based global parameter optimization workflow that was originally developed to resolve nuanced subpopulations within magnocellular, parvocellular, and koniocellular neurons in the macaque lateral geniculate nucleus (LGN).1 In that work, SCTransform normalization, Harmony-based batch integration, and a systematic grid search across highly variable gene (HVG) counts, principal components, and clustering resolutions were used to maximize cluster separation while preserving biological structure.

Here, we adapt this optimization strategy into a reusable protocol implemented in an R package, named scAutoTune. We focus on two reference datasets: (1) a cell-sorted peripheral blood mononuclear cell (PBMC) dataset (SRP073767) with ground-truth immune-cell labels, derived from Wang et al.3 and downsampled to 399 cells from Zheng et al.,4 and (2) a 334-cell koniocellular (K) neuron subset from the Allen Brain Map LGN dataset,5,6 where Harmony integration was used to account for multi-animal and multi-species batch structure (i.e., batch correction). The PBMC dataset serves as a validation benchmark, where optimized parameters recover known immune populations with high concordance to true labels, whereas the LGN K dataset illustrates how careful parameter tuning can reveal transcriptionally heterogeneous neuronal subpopulations that are otherwise obscured by default settings.

This protocol assumes basic fluency with R, Seurat, and an integrated development environment such as RStudio, as well as familiarity with command-line file navigation. Users may either reproduce the preprocessing pipeline described in the associated transcriptomics manuscript or start from their own processed Seurat objects. In all cases, scAutoTune operates on a Seurat object with relevant metadata (e.g., batch labels) already defined.

Conceptually, scAutoTune performs the following operations: estimates an optimum number of principal components (PCs) to use for dimensionality reduction, sweeps over user-defined ranges of HVG counts and clustering resolution at a fixed number of principal components, performs Seurat nearest-neighbor graph construction and Louvain clustering for each parameter combination, and computes average silhouette width on the resulting clusters. A generalized additive model (GAM) is then fitted to the grid of silhouette scores to generate a smooth performance landscape, from which the HVG-resolution pair that maximizes the predicted silhouette is extracted. The selected parameters are applied back to the Seurat object to regenerate the graph, clustering, and UMAP embedding, yielding an optimized object ready for downstream marker analysis and visualization.

The steps below outline what should be in place before running the main parameter sweep.

Innovation

Single-cell RNA-seq analysis currently lacks a standardized pipeline for parameter selection. In practice, most workflows rely on Seurat’s default settings followed by iterative, manual tuning of highly variable gene counts, number of principal components, and clustering resolution. Because these choices are strongly dataset-dependent, results can vary substantially between analysts and experiments, and it is often unclear whether a given clustering solution is close to optimal or simply “good enough.”

scAutoTune provides an automated, quantitative alternative to this ad hoc process. It performs a structured grid search across user-defined ranges of feature counts and clustering resolutions at a fixed number of principal components, evaluating each combination with silhouette-based performance metrics. A generalized additive model (GAM) is then fit to the resulting score surface, enabling the identification of robust high-performing parameters rather than a noisy optima.

The workflow integrates seamlessly with Seurat functions and operates directly on standard Seurat objects. It can be inserted as a modular optimization step before marker discovery, differential expression, and visualization, or embedded into larger single-cell analysis pipelines. By replacing default-heavy, trial-and-error tuning with a reproducible, data-driven optimization routine, scAutoTune reduces subjective decision-making, acknowledges the dataset-specific nature of analysis choices, and moves the field one step closer to a more standardized and transparent approach to single-cell clustering.

Expected outcomes

The protocol yields several complementary outputs. First, scAutoTune produces an estimated number of principal components (PCs) to use downstream. This can be manually verified or adjusted via the elbow plots that are produced (Figure 1A). Second, the parameter sweep produces a complete grid-search table in which each combination of highly variable gene count and clustering resolution is associated with silhouette and, optionally, modularity scores. These values are summarized in a GAM-smoothed heatmap (Figure 1B) that highlights a peak region in the parameter space, providing an intuitive view of how clustering performance changes across settings. Applying the optimal parameters back to the Seurat object generates revised UMAP embeddings that typically show coherent cluster structure (Figure 1C), which align well with the true label clustering (Figure 1D). The final product is an optimized Seurat object that is immediately usable for downstream tasks such as marker differential expression and visualization (Figures 1E and 1F). Because scAutoTune operates on Seurat objects, additional assays stored in the object from multimodal experiments (e.g., ADT or cell-surface protein), can be retained for downstream analysis. However, the workflow described here optimizes RNA-based feature selection and clustering parameters. Users performing joint RNA-protein or other multimodal analyses should verify that the RNA-optimized parameters are appropriate for their specific analysis goals. Limitations

This protocol has several limitations. Full parameter sweeps can be computationally intensive for large datasets, particularly those with more than 50,000 cells or extensive parameter grids. As a practical estimate, datasets with fewer than 5,000 cells often complete within minutes to a few hours, datasets with 10,000-50,000 cells may require several hours on a typical high-performance computer, and datasets larger than 50,000 cells may require overnight or multi-day runs depending on grid density, number of PCs, and whether batch correction is used. In such cases, users may need to reduce the number of parameter combinations, perform sweeps on a representative subset of cells, or use higher-performance computing resources. At present, scAutoTune operates exclusively on Seurat objects within the R ecosystem; although this covers a large fraction of current single-cell workflows, it does not yet support commonly used formats such as h5ad or Python-based pipelines, which we expect to incorporate in future versions to broaden compatibility across transcriptomics toolchains.

Silhouette scores favor well-separated, compact clusters and may underestimate structure in datasets where rare populations, lineage continua, or gradient-like transitions are biologically important. Additional metrics or qualitative inspection of embeddings may be necessary to capture such complexity. Harmony batch correction, while optional, can strongly influence performance metrics in multi-donor datasets; incorrect or unnecessary use of batch correction may obscure genuine biological variation rather than remove technical effects.

In addition, the current implementation always enforces a clustering solution with two or more clusters for each parameter combination, even in cases where the underlying population may be effectively homogeneous. This design can lead to overclustering, and it is ultimately the user’s responsibility to decide whether small or weakly separated clusters are biologically meaningful or should be merged or discarded.

Finally, the optimal parameters identified by scAutoTune are inherently dataset-specific. Parameter settings should not be transferred directly across experiments without reassessment, even when sample types are similar. Instead, scAutoTune should be rerun for each dataset or experimental condition to ensure that clustering reflects the underlying biological structure rather than artifacts of prior optimization.

Potential solution

•Check the number of PCs used for clustering and UMAP. Too few PCs (e.g., 3) can exaggerate minor variation and produce many tiny “islands” of clusters. Consider increasing the number of PCs and rerunning the analysis.•Narrow the resolution range to lower values and rerun the sweep (for example, 0.1–0.6 rather than 0.1–1.5), then reselect optimal parameters within this restricted window.•Reduce the maximum number of highly variable genes; very large HVG sets can promote fragmentation of clusters.•Inspect small clusters for marker expression and cell counts. If they lack distinct markers or contain very few cells, consider merging them with neighboring clusters or treating them as over-segmentation.•If Harmony or other batch correction is used, confirm that the batch variable is appropriate and that integration is not removing genuine biological differences while accentuating noise.

Problem 5

The silhouette heatmap or GAM-smoothed surface is noisy with no clear optimum (Step 20).

Potential solution

•Adjust the degrees of freedom used for GAM smoothing (k_val parameter in scAutoTune). Too little smoothing can leave the surface noisy, whereas too much can flatten structure.•Reduce or increase grid density by adjusting step sizes for HVG counts or resolution.•Exclude parameter combinations that produce degenerate clustering (for example, only one cluster or clusters with extremely few cells) before fitting the GAM. These outliers can distort the surface.•Inspect raw silhouette distributions (not just averages) for a few representative parameter combinations to understand whether noise arises from data ambiguity or from specific parameter regimes.•If the surface remains noisy, restrict the search to a narrower window around biologically reasonable settings (based on prior experience or initial exploratory runs) and re-run the sweep in that region.
