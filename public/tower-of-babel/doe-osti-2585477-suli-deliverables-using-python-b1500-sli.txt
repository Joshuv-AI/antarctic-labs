General Abstract: The project I was a member of was Electro-Chemical Random Access
Memory (ECRAM) at Sandia, Livermore. This project focuses on trying to create devices
which can be programmed in a non-volatile manner, meaning they retain or “remember”
their state. These devices also operate using analog signals which is in stark contrast to
industry which is largely dominated by digital logic. Rather than two states, a “0” and a “1”,
analog memory has a continuous range of states. The analog nature of the devices leads to
great difficulties in fabrication because the memory must be extremely consistent. For
example, when the same “write” signal is sent to the device it must consistently “read” the
same output. This requires a high level of precision and stability. However, the analog
nature of ECRAM is also its greatest advantage, and the reason for its research. By using
analog logic, once complicated digital logic becomes much simpler. The most common
example is matrix multiplication, required for Machine Learning and AI. Using analog
signals, this simply requires a grid of op-amps and ECRAM devices. The equivalent digital
circuit is significantly more complicated. This complexity leads to drastically more power
consumption. Thus, the reason for researching ECRAM is to reduce the power
consumption of modern computation circuits. My personal contribution to the project
consisted mostly of more practical work, rather than theoretical. I created python programs
to control a Keysight measurement unit which was capable of programming ECRAM
devices. Then I worked on creating a python GUI which would give the user control over
how they wanted to send “write” pulse to ECRAM. Lastly, I assisted with the collection of
data for ECRAM circuits and other ECRAM application such as Vector Matrix
Multiplications.

Abstract
A new electrical setup for testing ECRAM devices is described in this
presentation. This presentation details the background of ECRAM
devices, how the B1500 is used to program ECRAM devices, and the
python GUI that was created for controlling the B1500. ECRAM devices
are a form of non-volatile memory. The stored data is the resistance
between two of the terminals on the device. Using only the B1500, the
ECRAM devices can be programmed and the state read out. This creates
a simple, logical testing setup. The overall setup was successful, ECRAM
devices could easily be programmed and measured. However, there is
still room for improvement. Specifically, in the creation of an automated
“Program” feature and a “Data Collection” feature. These features will
require additional advances in the understanding of ECRAM devices but
will greatly automate and improve the current data collection and
application of ECRAM devices.

 Testing of ETCRAM Devices
 By: Patrick Crandall

 ABSTRACT

Electro-thermo-chemical random-access memory (ETCRAM) devices have made great advances
in the past few years. These devices can be programmed to a non-volatile, specific resistance
value. However, to efficiently manage data collection and device programming, software must be
written to control instruments. This report details a method of data collection and device
programming using the Keysight B1500 to produce “write” and “read” waveforms. To allow user
control, a python GUI using the tkinter library was written. This GUI allows the user to specify
write programs, save data, visualize data, and more. Using the GUI, ECRAM devices have been
effectively and easily programmed. Additionally, all relevant data can easily be saved and stored
using python. However, a major area for future development is the creation of “programming”
algorithms and functions. The GUI has been created with a “program” feature, but it fails to
successfully function for different devices. The development of this algorithm is crucial for real-
world applications of ECRAM but is difficult due to the non-linearity of ECRAM’s update
strength.

I. ETCRAM
 a. Background
 The ETCRAM device stack is shown in Figure 1. The change in resistance,
 effectively the programming of the device, is measured in the channel. To
 change the resistance of the channel, “write” voltages are applied to the heater.
 These voltages, through the application of heat and an electric field, allow for
 the movement of oxygen vacancies between the reservoir and the channel.
 The electrolyte helps to ensure device stability and state retention, effectively
 keeping the channel at a constant resistance in the absence of a write voltage.

 Figure 1. ETCRAM Device Stack

 b. Programming
 Figure 2 shows the typical probe placement for testing ETCRAM devices.
 Two probes are placed on both the heater and channel device pads. This
 creates a closed-circuit path to be formed. On both the channel and the heater,
 one probe will apply a voltage, and current, and the other probe will sink the
 current. Using the initial probe to measure voltage, the second probe can
 measure current which effectively gives the resistance between the probes.

 Figure 2. ETCRAM Probe Placement

 Figure 3 depicts the circuit described in the previous paragraph. For the
 heater, the write voltage and GND represent two probes while the channel
 read voltage and GND represent the other two probes. This figure clearly
 shows the electrical connections and circuits being created using the device.

 Figure 3. ETCRAM Programming Circuit

II. KEYSIGHT B1500 SEMICONDUCTOR DEVICE ANALYZER (SDA)
 a. Overview
 The Keysight B1500 is essentially a rack with different slots and channels for
 measurement tools. The most basic measurement tool, inside of the B1500, is
 a Source Measurement Unit (SMU) which is good at measuring resistances. A
 slightly more advanced tool is the Waveform/General Measurement Unit
 (WGFMU) which can source a voltage waveform and complete an accurate
 measurement or voltage or current waveforms. In this testing setup, two
 SMUs are placed on the channel, to measure resistance, while two WGFMUs
 are placed on the heater to apply a write waveform.

 b. Source Measurement Unit (SMU) Python
 1. Control File
 The main control file for the SMUs is called “patrick_b1500_core.py”.
 This file is a python class that, when initialized, will connect to the
 specified channels of the B1500. It is important to note, that the user
 will have to input the correct channel that corresponds to the SMUs.
 For example, if two SMUs are in slot 1, their channel number would
 be “101” and “102”. Them most used function is “TTIV_meas” which
 completed a fast IV measurement. Communication with the SMUs
 occurs using PyVisa.

 2. The test file for the b1500 is called “patrick_SMU_test.py”. This file,
 when run, will complete a specified number of SMU resistance
 measurements using the TTIV function. This test file will show the
 basic setup and use of the TTIV “measure” function.
 3. Lastly, the SMU manual is linked here: B1500 (SMU) Programming
 Guide. This manual shows the commands that can be sent to the SMU
 and has examples on how to setup the SMUs. The main caveat is the
 python code will use pyvisa write and read functions to send the
 commands to the SMUs.

 c. Waveform/General Measurement Unit (WGFMU) Python
 1. The main control file is “patrick_WGFMU_funcs.py”. This file is a class
 which contains the necessary functions for controlling the WGFMU. The
 general setup is very similar to the SMUs, but the control of the WGFMU
 and SMU (i.e. commands) are very different. The most important function
 is called “two_ch_run”. This function will output a voltage pulse, inputted
 to the function, to one of the WGFMUs and measure the received current
 on the second WGFMU. Another significant difference from the SMUs is
 that communication occurs using a C wrapper. Because of this, some
 variable types must be converted to C before being “sent” to the
 WGFMUs.
 2. The test file is called “patrick_WGFMU_test.py”. Similarly to the SMUs,
 this test file will show the basic setup and use of the WGFMUs. The file,
 when run, will complete a specified number of pulses and plot the
 measured voltage and current once at the end.
 3. Lastly, this is the link to the WGFMU manual: B1530A (WGFMU) Guide.

III. PROGRAMMING GUI
 Figure 5 shows the GUI’s home page, which displays when the
 “b1500_tkinter.py” file is run. This page has three graphs. The first graph
 (top) displays the voltage measured by the WGFMU, which should ideally be
 the user specified voltage waveform. This voltage is applied to the Gate
 (Heater) of the ECRAM device. Next, the middle graph shows the current
 received by the second WGFMU. The reason the sign is negative is because
 current is being received, sunk, into the WGFMU rather than outputted.
 Lastly, the final graph shows a history of the measured conductance values.
 For every outputted WGFMU waveform, the conductance value of the
 channel will be measured and plotted in the green graph. The graph shows

how the conductance value is non-volatile, programmable memory through
the different states reached and the stability of the states (flat sections).

 Figure 5. GUI Home Page

 Additionally, Figure 5 has a few buttons and selections the user can make.
For one, the user can select a specific run “mode”. The different run modes
are shown in Figure 6. When the “run” button is pressed, it will complete the
function specified by the run mode. Additionally, when different run modes
are selected, new user inputs appear. These user inputs are specific to the
selected run mode. For example, in Figure 6 the “Cycling” mode is selected.
To run this mode, a lower and upper conductance value must be inputted.

 Figure 6. GUI “Run” Modes

 Another important feature is the pop-up window that is created when the
 “Configure Write Waveform” button is pressed. This pop-up is shown in
 Figure 7, and it allows the user to specify their desired write pulse. The user
 can change the amplitude and timing characteristics of their pulse. When
 programming ECRAM, the update strength, change in conductance, is
 dependent upon the amplitude and duration of the pulse applied to the heater.
 Additionally, the user can specify the number of points to collect, or sample,
 for each pulse. When the “Graph Waveform” button is pressed, the graph will
 update its settings. This window will automatically store and save user inputs,
 regardless of whether the “Graph Waveform” button is pressed or not.

 Figure 7. GUI “Configure Write Waveform” Popup

IV. RESULTS
 a. Automatic Data Collection
 The automatic data collection is very much under development and is not
 ready for general users. For one, the automatic data collection is attempting to
 integrate the “Program” functionality of the GUI. However, the “Program”
 feature does not work well across different devices and conductance ranges.
 The idea behind using the “Program” function is to collect data at a specific
 conductance value (i.e. transmit a write pulse, save data, program back to
 original conductance and repeat).
