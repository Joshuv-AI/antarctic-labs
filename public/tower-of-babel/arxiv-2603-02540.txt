A Neuropsychologically Grounded Evaluation of LLM Cognitive Abilities
Faiz Ghifari Haznitrama, Faeyza Rishad Ardi, Alice Oh

Abstract
Large language models (LLMs) display a unified ”general factor” of capability across 10 benchmarks—a finding confirmed by our factor analysis of 156 models—yet they still struggle with simple, trivial tasks for humans. This is because current benchmarks focus on task completion, failing to probe the foundational cognitive abilities that highlight these behaviors. We address this by introducing the NeuroCognition benchmark, grounded in three adapted neuropsychological tests: Raven’s Progressive Matrices (abstract relational reasoning), Spatial Working Memory (maintenance and systematic search), and the Wisconsin Card Sorting Test (cognitive flexibility). Our evaluation reveals that while models perform strongly on text, their performance degrades for images and with increased complexity. Furthermore, we observe that complex reasoning is not universally beneficial, whereas simple, human-like strategies yield partial gains. We also find that NeuroCognition correlates positively with standard general-capability benchmarks, while still measuring distinct cognitive abilities beyond them. Overall, NeuroCognition emphasizes where current LLMs align with human-like intelligence and where they lack core adaptive cognition, showing the potential to serve as a verifiable, scalable source for improving LLMs.



1
Introduction

Large language models (LLMs) show increasingly powerful capabilities
(
1
)
, further enhanced by the emergence of reasoning abilities
(
64
)
. This is demonstrated by their beyond human-level capabilities in tasks such as olympiad-level problems
(
60
)
. However, even with these impressive capabilities, they still stumble on trivial or straightforward tasks
(
55
;
35
)
. This raises a curiosity about the underlying cognitive mechanism of LLMs and how it compares to human cognitive abilities.

Most current LLM benchmarks are task-specific, limiting their analysis and insights to the task performance itself. These benchmarks are not able to uncover the underlying cognitive abilities required to solve the task
(
38
;
2
)
because task performance is not a reliable measure of intelligence, but rather heavily influenced by prior knowledge and experience
(
14
)
.
One interesting test that is often overlooked is neuropsychological tests, which are a well-established method for measuring specific cognitive abilities in humans, originally designed to isolate specific cognitive functions using controlled stimuli and interpretable outcomes. Previous works have attempted to apply neuropsychological tests to LLMs
(
23
;
27
)
, but they are limited to a single task or modality, or they lack a deeper analysis of the model’s underlying cognitive abilities.

We present the NeuroCognition benchmark, built from three well-established neuropsychological tests: Raven’s Progressive Matrices
(
48
;
47
;
49
;
13
)
(RPM) targeting abstract relational reasoning (fluid intelligence), Spatial Working Memory
(

(SWM) targeting maintenance and systematic search across working memory, and the Wisconsin Card Sorting Test
(

(WCST) targeting cognitive flexibility and task switching. Each test is adapted into multiple text and image variants (including harder versions) to vary interaction length, modality, and complexity. We also include experiments using assistance inspired by simple strategies that humans use (e.g., taking notes), a process known as cognitive offloading
(
51
;
33
)
, to see if they reduce observed errors and improve overall performance.

Our main contributions are:

•

NeuroCognition, a benchmark repurposed from well-established neuropsychological tests, into a simple, multimodal, scalable, robust assessment, and easily reproducible suite with various setups.

•

Evaluation results show that state-of-the-art models perform strongly in baseline text settings, but struggle in image or when task complexity increases, and that explicit reasoning is not always beneficial.

•

Experiments with human-like strategies (pattern hints and notes) show mixed effects—limited on RAPM/SWM but more consistent on WCST—suggesting some deficits are fundamental.

•

Factor analysis and correlation results show that NeuroCognition measures specific cognitive abilities that differ from, yet correlate with, the general capabilities captured by standard benchmarks.

Overall, NeuroCognition is a benchmark that can identify gaps in LLMs’ cognitive abilities relative to humans, offering insights into how LLMs operate and informing the design and training of future LLMs. Our code

Related Works

The neuropsychological tests included in our work measure different aspects of human cognitive abilities. The RPM
(
48
;
47
;
49
;
13
)
measures abstract, relational reasoning capabilities
(
54
)
. RPM has been used to identify intellectually gifted individuals, and has been shown to be widely reliable across different geographical boundaries
(
41
)
. The SWM test
(
4
)
, on the other hand, measures the working memory, the ability to hold and mentally work with information, which may no longer be perceptually present
(
18
)
. This test has been used to detect at-risk individuals for psychosis
(
65
)
, and highlight the working memory deficits in individuals with autism
(
56
)
. Finally, WCST
(
11
;
25
)
measures cognitive flexibility, i.e., the ability to adapt to a change in perspective and reallocate resources to process relevant information
(
18
;
22
)
. Patients with schizophrenia are shown to perform worse on this test
(
19
)
, and are shown to be robust even in clinical settings
(
30
)
.

Recent advances in LLMs have led many works seeking to establish stronger correlations between LLMs and human intelligence. Many works focus on developing a cognitive benchmark aiming to measure fluid intelligence
(
14
;
21
;
69
;
43
)
, emphasizing abstractness and dynamic evaluation to avoid the data contamination issue
(
37
)
. Other works applied human cognitive tests to LLMs
(
17
)
and showcased cognitive behaviors in LLMs, such as similar working memory capacity between humans and GPT-4 in the n-back test
(
23
)
, and above human-level cognitive flexibility in the WCST
(
27
)
. Some works also revealed common factors of models’ performance across different benchmarks
(
12
;
28
)
, indicating the existence of a common underlying intelligence.

Aside from cognitive abilities, several studies have also quantified specific areas where LLMs struggle. In multi-turn evaluation, LLMs tend to perform worse than single-turn evaluations
(
32
)
, and still perform sub-optimally in multi-turn tasks
(
31
;
53
)
. LLMs also struggle in longer multi-step reasoning
(
44
)
and in complex multi-stage tasks
(
34
)
. LLMs also exhibit cross-modal hallucination
(
61
)
, and struggle in multi-image, multi-turn benchmarks
(
39
;
68
)
. LLMs also fail in simple pattern tasks using modified alphabets
(
35
)
, indicating the lack of general analogical reasoning in LLMs.

3
NeuroCognition Benchmark Tests

3.1
Raven’s Progressive Matrices

Task.
RPM presents a 3x3 matrix of construct patterns with the bottom-right cell missing. The participant needs to infer abstract relations across rows and columns, and fill the missing cell by either selecting one of the 8 available options or constructing it. In our benchmark, we use the Raven’s Advanced Progressive Matrices (RAPM)
(
13
)
form.

Setup.
For the image version, we use the RAVEN dataset
(
73
)
, implementation of RAPM with 7 different figure configurations licensed with GPL-3.0. We take 20 items per configuration, resulting in a total of 140 test data. We combine the 3x3 question matrix with the 8 available options into a single image input, as shown in Figure
1
, and present it to the model in multiple-choice (MC) format. For the text setting, we programmatically generate symbolic matrices using character and string attributes (see Appendix
A
for generation details). We provide two answer formats for text setting: multiple-choice (MC, same 8 options) and generative (Gen, free-form string). A stored rule representation enables automatic validation of Gen outputs (see Appendix
B
for validation details). We generate 200 test data for the text setting with random configurations.

Metrics.
We report accuracy for both MC and Gen. Average human performance for images is 0.814, reported by
73
, and not yet established for the text variant.

3.2
Spatial Working Memory

Task.
In the SWM test, participants are presented with an image with several boxes. A token is hidden in one of the boxes, and participants are asked to search for it by elimination, opening one box at a time. After the token is found, it is regenerated in another box that has not previously contained it in the current trial. This is repeated until all boxes have contained all tokens, with the goal of locating all tokens with minimal redundant checking and without revisiting boxes unnecessarily.

Setup.
We implement two difficulty levels.
Easy
: 8 boxes, 1 token active at a time, early stop after all 8 tokens found or a maximum of 64-guess cap.
Hard
: 12 boxes with 2 distinct tokens active concurrently (24 tokens found required, maximum 144 guesses), with each token directly reappearing after being found, and one box can contain both tokens at once. We experiment with three types of feedback setups: text-only, image-only (a grid with no additional textual information), and image+text variants. The image input uses a grid system for easier answer verification, as shown in Figure
1
. The text-only setup identifies the boxes by number and ask the model to choose a box number.

Metrics.
Since SWM is highly affected by luck, we define some metrics that focus on penalizing errors and unfinished tests. We classify three avoidable error types:

•

illegal
: opens a box that can no longer contain a token because it has already yielded all available tokens for the trial.

•

no-box
: refers to a box index/identifier that does not exist.

•

repeated
: re-opens a box that was previously opened and found empty, before any new token was regenerated (i.e., no state change that could justify revisiting).

These three error types sum to
n_{err}
. Let
n_{valid}
be the total valid guesses. A consistency term
S_{c}
:

S_{c}=1-\frac{n_{err}}{n_{valid}}

(1)

measures avoidance of structurally unjustified moves. Note that we omit
invalid
guesses (no parseable answer) to ensure fair evaluation of real guessing attempts. Let
T_{f}
be number of tokens found out of
T
required; the final score
S_{swm}
is

S_{swm}=\frac{T_{f}}{T}\times S_{c}

(2)

Human worst-case.
A cognitively normal human, given a complete history of their own moves (like conversation history in LLMs), will be able to achieve full completion by systematic elimination and yield
n_{err}=0
regardless of the setup and difficulty, therefore obtaining
S_{swm}=1
.

3.3
Wisconsin Card Sorting Test

Task.
In WCST, four option cards containing shapes are shown to participants. They are then asked to match the given card to one of the four option cards using one of three rules: shape, color, or number. Importantly, participants are not informed of the correct rule for matching the cards and must eliminate potential rules to find the correct one. After choosing the correct answer, a different card is shown while maintaining the same rule. The matching rule is considered complete after a fixed number of consecutive correct answers and is changed upon completion without expressly informing the participant. The test finishes after a fixed number of rules are completed or a maximum number of guesses is reached.

Setup.
We require 5 consecutive correct matches (
c=5
) to complete a rule instance. We define two difficulty levels.
Easy
: 3 candidate rules (color, shape, number), each repeated twice (6 total rule instances) or until the 64-guess cap.
Hard
: adds background color (4 candidate rules, 8 total rule instances) with a maximum of 96 guesses. We also construct controlled ambiguity variants for the hard setting: (i)
off
(no ambiguous cards), (ii)
first
(only the first card under a new rule is ambiguous), and (iii)
rest
(all subsequent cards after the first are ambiguous). Ambiguity occurs when multiple attributes match simultaneously, forcing the model to track disambiguating feedback over turns. The image-input setting provides images of the cards (Figure
1
), while the text-only setting lists descriptions of the option cards.

Metrics.
Each completed rule
i
uses
g_{i}
guesses from the start of that rule until
c
consecutive correct response. Therefore, we can define a score
S_{r_{i}}
for each completed rule
i
:

S_{r_{i}}=\frac{c}{g_{i}}.

(3)

where unfinished rules contribute zero. Lower
g_{i}
means faster hypothesis convergence, which repeated reliance on an incorrect hypothesis inflates
g_{i}
and lowers
S_{r_{i}}
. With
n_{c}
completed out of
N
target rule instances, we can calculate the final score
S_{wcst}
as:

S_{wcst}=\frac{1}{N}\sum_{i=1}^{n_{c}}S_{r_{i}}.

(4)

We additionally report two specific error rates aggregated over a single trial with total turns
L
. Let
y_{t}\in\{0,1\}
denote correctness at turn
t
(
y_{t}=1
if the model’s match is correct), and let
r_{t}\in\mathcal{R}
be the rule the model is currently following at turn
t
(e.g., color/shape/number/background).

Perseverative Response (PR).
PR measures how often the model re-selects a rule that has already been ruled out by negative feedback within the current rule block. We use PR rather than the standard WCST perseverative error (PE) because it captures a broader range of errors while still including PE.

Let
k(t)
index the current (ground-truth) rule block containing turn
t
, and let
\mathcal{R}_{\neg}^{t}\subseteq\mathcal{R}
be the set of rules eliminated by feedback from earlier turns in the same block. Then:

\mathrm{PR}=\frac{\sum_{t=1}^{L}\mathbf{1}\{\mathcal{R}_{\neg}^{t}\neq\emptyset\}\,\mathbf{1}\{r_{t}\in\mathcal{R}_{\neg}^{t}\}}{\sum_{t=1}^{L}\mathbf{1}\{\mathcal{R}_{\neg}^{t}\neq\emptyset\}}.

(5)

Failure-to-maintain-set (FMS).
We mark a rule as
conceptually acquired
after
m=3
consecutive correct responses
within a block
. For each block
k
, let
\tau_{k}
be the first turn index in that block at which this acquisition criterion is met (if it is never met, the block contributes no turns). Let
\mathcal{T}_{\mathrm{post}}
be the set of all turns after acquisition and before the next rule switch:

\mathcal{T}_{\mathrm{post}}=\bigcup_{k}\{t:k(t)=k,\ t>\tau_{k}\}.

(6)

FMS is the error rate on these post-acquisition turns:

\mathrm{FMS}=\frac{\sum_{t\in\mathcal{T}_{\mathrm{post}}}\mathbf{1}\{y_{t}=0\}}{|\mathcal{T}_{\mathrm{post}}|}.

(7)

Human worst-case.
For the easy setup, a cognitively normal human needs at most two exploratory wrong guesses to find the correct rule, then continues with 5 correct answers
\Rightarrow 5/7\approx 0.714
. For hard, the worst case happened with the
first
ambiguity setup, where at most there are two exploratory wrong guesses, one ambiguous early correct, one disambiguating wrong, and 5 consecutive correct answers
\Rightarrow 5/9\approx 0.556
.

4.1
Key Findings

Models are stronger in text, struggle in image.
Across all tests, models show a consistent advantage in text-only setups compared to image-based inputs. Even combined modalities (image+text) yield worse results than text alone, indicating difficulties in parsing and reasoning over visual stimuli and combining visual with textual information.

Performance drops with difficulty.
Increasing task difficulty, particularly in SWM, causes a significant drop in performance. In the SWM text easy setup almost all models complete the task perfectly, while in the hard setting only three models manage to do so. Even the two best models are unable to do it consistently through all setups. This is interesting because the core ability required is still the same. The harder setting only increases demands on maintaining and updating internal state, proven to still be a challenge.

Models possess good cognitive flexibility.
Compared to RAPM and SWM, models generally perform better on WCST, with more models passing the human worst-case baseline. This suggests current LLMs handle rule inference and task-switching behavior more robustly than abstract relational reasoning or complex working-memory maintenance, though image setup is still an issue for some models.

Answer format matters.
In RAPM text, models exhibit different preferences for multiple-choice versus generative answer formats on the same items.
This likely reflects differences in decision constraints and how models interpret the problem, which sometimes leads to overcomplication.

4.2
Failure Cases & Patterns

RAPM.
Our analysis of RAPM reasoning traces (Appendix
E
Table
10
,
11
) reveals three persistent deficits across modalities. First,
hallucination and mis-grounding
: models fabricate visual features or impose non-existent numerical patterns on text that contradict the data. Second,
semantic over-interpretation
: models overlook simple local rules (XOR, concatenation) in favor of complex, global hypotheses like ”symmetry grids.” Third, specifically in Text Gen, models exhibit
content-logic disconnect
, where they frequently derive correct attribute constraints but generate hallucinated strings that satisfy these metadata rules while violating the actual constructive logic. These failures suggest a disconnect between low-level feature verification and abstract reasoning.

7
Conclusion

In this work, we introduce the NeuroCognition benchmark, a suite of neuropsychological tests (RAPM, SWM, WCST) adapted for LLMs to probe specific cognitive processes using multimodal, process-aware metrics. Across tasks, state-of-the-art models show meaningful but incomplete alignment with human cognition. They perform better in text, but performance drops for images and harder settings that demand intensive grounding and state tracking. Overall, explicit reasoning is not uniformly beneficial, and human-like assistance shows mixed effects. The impact of pattern hints is limited, while note-taking helps more consistently in WCST but not in SWM. Complementing these results, our factor analysis suggests a dominant general-capability factor across standard benchmarks, highlighting redundancy in current evaluation. Correlations with external benchmarks further suggest that gains in NeuroCognition process scores translate into improvements in semantically related real-world tasks, while individual tests still measure distinct cognitive abilities. In summary, our results suggest that current LLMs do not possess the same kind of intelligence as humans, but still align with humans in some aspects, which can inform how we use and improve them.

8
Future Work

Since we apply neuropsychological tests designed for humans to LLMs, it is important for future work to validate whether the same cognitive abilities measured in humans are also captured in LLMs. This helps to further understand the relationship between human and LLM intelligence and improve the interpretability of the benchmark results. Another interesting direction is improving the LLM itself through neuropsychologically grounded training data. The data that we used in this benchmark captures basic cognitive processes that are foundational to human intelligence, and therefore can be used to improve the cognitive abilities of LLMs. Additionally, recent works investigate ways to compress context
(
36
;
20
)
, or utilize some sort of memory in their architecture
(
10
;
9
;
16
)
, and our benchmark could serve to evaluate such methods. Finally, this data can be easily generated synthetically with code, making it scalable to create a large amount of data for training purposes.

Limitations

Our evaluation has three main limitations. First, sample sizes are constrained by cost: running state-of-the-art models with effectively unlimited reasoning is expensive. For RAPM, we capped runs at n = 200 (text) and n = 140 (image), which may compromise the robustness of our results, especially in the original image modality. Second, our benchmark assumes that the same neuropsychological test used to assess a specific cognitive ability in humans can also be applied to LLMs to evaluate that same ability. In the neuropsychological field, this is not always the case, since a neuropsychological test is standardized on a specific population and must be validated based on psychometric properties (validity, reliability, and measurement invariance) when applied to a different population. Therefore, even when a model performs consistently as well as humans across all tasks in our benchmark, we can only claim that the model exhibits a similar level of intelligence and can simulate human-like cognitive abilities, but not that it thinks like humans or possesses the same underlying cognitive mechanism. Third, since the neuropsychological tests we used are widely used and well-established, we assume they are valid and reliable based on their psychometric properties (validity, reliability, and measurement invariance). However, this assumption may not hold in all cases, and further validation across prompts, contexts, and a wide range of LLMs is needed.

Rule Space and Attributes

The generation engine employs a compositional rule space defined by attributes that constrain string properties. For each matrix, two primary attributes are sampled—one for rows and one for columns. Additional consistency rules (leaks) are inferred if they naturally emerge from the intersection of constraints.

The implemented attributes and their parameters are:

1.

•

Values
:
letters

•

Logic

2.

•

•

Rules

Logic

3.

•

A.2
Generation Algorithm

The matrix generation process follows a constraint-satisfaction approach with backtracking, as detailed in Algorithm
1
. The core logic proceeds as follows:

1.

Attribute Sampling
: Randomly sample one attribute specification for rows and one for columns.

2.

Compatibility Check
: Validate that the row and column attributes are compatible. For example, a ”Sorted” row attribute conflicts with a ”Positional” column attribute because sorting rearranges characters, potentially violating fixed-position constraints. Infeasible combinations trigger a re-sampling.

3.

Constraint Propagation
: The row and column attributes are combined to define specific constraints for each of the
3\times 3
cells. ”Leak” detection is performed to identify additional properties that effectively become constant across rows or columns (e.g., if a row rule restricts characters to digits and a column rule restricts them to even numbers, a universal ”digits” constraint might apply).

4.

Grid Construction
: Cells are generated sequentially. For each cell, a string is constructed to satisfy the merged constraints. Random backtracking is used if a cell cannot be generated given the current constraints and history.

5.

Variation Enforcement
: To prevent trivial patterns, we enforce a minimum Hamming distance between strings in the same row or column. This ensures that the progression relies on abstract rules rather than simple repetition.

Upon successful generation, the defining constraints for the missing cell (including “leaked” rules) are stored for automatic rule validation.

C.3
Evaluation Protocol Details

•

Zero-shot:
All evaluations are zero-shot.

•

Temperature:
We used a temperature of 0 when possible to reduce sampling variability; when a model’s API does not allow overriding temperature, we used the model’s default.

•

Reasoning mode:
We used each model’s default reasoning configuration except for Claude Sonnet 4 and Grok 4 Fast, for which we adjusted reasoning as described in the main text (see Section

•

Maximum output tokens:
For RAPM, we allowed the model’s maximum permitted output tokens. For SWM and WCST, we limited per-turn outputs to 8192 tokens.

•

Thinking budget:
The system prompt described a thinking budget (not enforced as a hard token limit). For RAPM, we used an effective thinking budget of 30,000 tokens for models with a context limit of 32K and 60,000 tokens for models with a context limit of 65K+. For SWM and WCST, the per-turn thinking budget was 4,000 tokens.

•

Repetitions:
SWM and WCST setups were run three times each to assess variability (data are generated on the fly); RAPM was run once per model.

•

WCST (notes):
For WCST runs that used note-taking assistance, we set the note window to 6.

System Prompt for Image RAPM

You are taking the Raven’s Progressive Matrices (RAPM) test, a non-verbal intelligence test that measures abstract reasoning ability.

You will see a 3x3 matrix of images with the bottom-right image missing (shown as a question mark), followed by 8 answer choices numbered 1-8.

Your task is to:

1. Analyze rows and columns

2. Infer the governing logical rule(s)

3. Select the answer choice (1-8) that correctly completes the matrix.

/* PATTERN HINT */

The patterns can involve:

- Shape transformations (rotation, reflection, scaling)

- Position changes (movement, arrangement)

- Attribute changes (color, size, number of elements)

- Logical operations (addition, subtraction, intersection)

- Sequence progressions (systematic changes across rows/columns)

Additional common rule types:

- Constant-in-row: Same value across a row; varies down columns.

- Quantitative step: Fixed +/- increment between adjacent cells (size / count / position offset).

- Figure add/subtract: Combine (overlay or juxtapose) or remove elements from two cells to form the third.

- Distribution-of-three: Three distinct categorical values appear once each per row (order may permute).

- Distribution-of-two: Two values each appear once; third slot is empty / null.

Look horizontally and vertically; the missing piece must satisfy ALL relevant row and column rules.

Your final answer should be a number between 1-8 corresponding to the correct choice.

System Prompt for SWM

You will be performing the Spatial Working Memory task.

You will be given an image containing {N_BOXES} yellow boxes in a grid.

There are {N_TOKENS} types of tokens, hidden in any one of {N_BOXES} boxes.

Each token type is represented by a distinct color.

Your goal is to find the {N_TOKENS} types of tokens {N_BOXES} times each, by repeatedly selecting a box to open.

A box can contain multiple types of tokens, but only one token of each type.

If the box contains multiple tokens, a token with mixed colors corresponding to the tokens will be shown.

Once the token is found, another will be generated in another box.

The token will be generated in a box that has never contained a token of that type before in the trial.

The token may be generated in a box that has been opened and found empty before, as long as it never contained that type of token previously.

/* TEXT VERSION */

System Prompt for WCST

You are performing the Wisconsin Card Sorting Test (WCST).

You will be shown a given card with a symbol on it, and you will have to match it to one of four option cards according to an attribute that you have to figure out.

The cards will be described by the following attributes:

1. Number of symbols

2. Color of symbols

3. Shape of symbols

/* HARD VERSION */

4. Background color of the card

You will be told ”Correct!” if you are correct and ”Incorrect. Please try again.” if you are incorrect.

If you are incorrect, you either made a mistake or the rule has changed.

If you believe you have made a mistake, correct it and try again.

If you believe the rule has changed, you have to figure out the correct rule to match the cards.

If you are correct, you have to stick with the same attribute until you are incorrect.

There is always a true answer in the task, and you have to keep performing the task until the end of the test.

Your final answer should be a number between 1-4 corresponding to the index of the card you think is the correct match.
