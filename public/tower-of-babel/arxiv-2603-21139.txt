Ontology-driven personalized information retrieval for XML documents
Ounnaci Iddir, Ahmed-ouamer Rachid, Tai Dinh

Abstract
This paper addresses the challenge of improving information retrieval from semi-structured eXtensible Markup Language (XML) documents. Traditional information retrieval systems (IRS) often overlook user-specific needs and return identical results for the same query, despite differences in users’ knowledge, preferences, and objectives. We integrate external semantic resources, namely a domain ontology and user profiles, into the retrieval process. Documents, queries, and user profiles are represented as vectors of weighted concepts. The ontology applies a concept-weighting mechanism that emphasizes highly specific concepts, as lower-level nodes in the hierarchy provide more precise and targeted information. Relevance is assessed using semantic similarity measures that capture conceptual relationships beyond keyword matching, enabling personalized and fine-grained matching among user profiles, queries, and documents. Experimental results show that combining ontologies with user profiles improves retrieval effectiveness, achieving higher precision and recall than keyword-based approaches. Overall, the proposed framework enhances the relevance and adaptability of XML search results, supporting more user-centered retrieval.

Introduction

Information Retrieval (IR) is a fundamental field of computer science, aiming to identify and extract documents from large collections based on their relevance to a user’s information needs, typically expressed as textual queries
[
50
]
. An Information Retrieval System (IRS) generally encompasses three core tasks: representing document content, modeling the user’s query or information need, and comparing these representations to compute a relevance score. One of the enduring challenges in IR lies in accurately modeling relevance so as to deliver the most meaningful and useful results
[
1
]
.

The rapid digitization of content and advances in web technologies have led to exponential growth in available data. Over time, document formats have evolved from flat, unstructured text to semi-structured representations such as SGML and, more prominently, XML—a widely adopted standard for data representation. XML is particularly well suited for IR because it combines structural richness with descriptive content, enabling fine-grained and personalized access to information
[
62
]
. Despite notable progress in indexing and querying techniques, personalized search systems still face important limitations. Many approaches rely on user profile models that are either overly generic or insufficiently expressive, failing to capture the complexity of user preferences
[
47
]
. Moreover, the semantic integration between user preferences and document structure is often shallow, neglecting the hierarchical granularity of XML documents and the richness of conceptual relationships
[
60
]
. Most existing work also focuses primarily on the profiling phase without providing mechanisms for the continuous adaptation of profiles as user queries evolve
[
44
]
.

To address these gaps, we propose an approach that integrates semantic user profile modeling via a domain ontology with structural exploitation of XML documents. Personalization is achieved by constructing a user profile that reflects individual interests and incorporating it into the search process to improve result relevance. Our system represents user interests as weighted ontology-based vectors, enabling fine semantic interpretation of queries. Profiles are dynamically updated after each user interaction through a progressive reinforcement mechanism for the most relevant concepts.

The choice of XML as the core document representation is motivated by its structured nature and semantic richness, which are key features for fine-grained, personalized IR. Its hierarchical organization supports precise content modeling, while its compatibility with ontology languages such as OWL facilitates semantic integration
[
60
,
11
]
. XML also offers a flexible framework for representing both data and user preferences, making it a strong candidate for adaptive and intelligent search systems.

While other formats such as JSON, YAML, Markdown, or NoSQL data models are prevalent in modern development (particularly for lightweight structures and efficient data exchange), they have limitations in representing rich hierarchies and semantic annotations. JSON, for instance, is efficient for API-based data transfer but lacks native typing, complex schema validation, and smooth integration with Semantic Web standards such as RDF or OWL
[
8
]
. YAML and Markdown are even more minimalist, making them unsuitable for deep semantic structuring
[
38
]
. NoSQL databases, including document-based (MongoDB) and column-based (Cassandra) systems, excel in scalability but do not provide standardized frameworks for fine-grained semantics, semantic validation, or automated reasoning
[
41
]
.

XML thus remains a strategic choice, combining explicit structure, W3C standardization, compatibility with semantic technologies, and flexible processing through XPath/XQuery. These features make it an ideal medium for personalized IR in complex, information-rich environments. Recent studies highlight XML’s potential in personalized search, leveraging profile extraction, semantic transformation, and structured indexing techniques
[
25
]
. However, few offer a coherent integration of ontology, XML structure, and dynamic online profile adaptation. Our work addresses this gap by providing a unified framework that combines ontological representation, dynamic vectorization of user interests, and semantic exploitation of XML documents to improve the accuracy, personalization, and relevance of retrieved results.

The main contributions of this paper are summarized as follows:

-

We propose a personalized information retrieval framework for semi-structured XML documents that integrates a domain ontology with user profiles to improve result relevance.

-

We represent documents, queries, and user profiles as ontology-based weighted concept vectors, and introduce a concept-weighting mechanism that emphasizes more specific (lower-level) ontology concepts.

-

We design a personalized matching and ranking process based on semantic similarity, coupled with a dynamic user-profile updating mechanism that progressively reinforces concepts inferred from user interactions.

-

We validate the proposed approach through experiments on an XML document collection, showing improved retrieval effectiveness (precision, recall, and F1-score) compared to a non-weighted baseline, and we will make the source code and experimental data publicly available to support reproducibility.

Preliminaries

3.1
Domain ontology

Building on prior work in semantic indexing, we propose an approach to indexing XML documents based on a domain ontology. This ontology extends the one used in
[
29
]
and is inspired by the OBIREX (Ontology-Based Information Retrieval for XML documents) ontology developed in
[
2
]
. OBIREX was originally designed for e-learning in computer science and structures pedagogical knowledge through hierarchical and interrelated concepts, supporting semantic annotation of resources and improving the relevance of search results.

In our study, the adopted knowledge division provides a generic, modular, and reusable framework for organizing domain concepts around the following entities:

•

Domain
: a set of alternatives from which the user selects.

•

Path
: a learning or navigation path that specifies a vocabulary supporting domain understanding.

•

Field
: an area in which a study activity is carried out.

•

Element
: a teaching unit that can be combined with others to personalize search.

•

Script
: a set of knowledge checks characterized by prerequisite elements.

•

Concept
: a set of evaluated granules that may be linked to other concepts by various relationships.

•

Granule
: a knowledge unit within a script, presented alone or combined with other granules.

Ontology concept weighting

In our approach, we aim to improve the relevance of information retrieval (IR) by exploiting our domain ontology. When both a parent concept and one of its child concepts can describe an element, we select the child concept because it is more specific and therefore more informative.

To emphasize specific concepts (i.e., those located deeper in the ontology hierarchy), we assign weights to ontology concepts. We assume that the total weight of the ontology equals one (1), i.e., it is the sum of the weights of all its concepts. The weight is distributed across ontology levels so that concepts at depth
i
receive higher weights than those at depth
i-1
. Coefficients are assigned as follows:

•

Each parent concept receives a coefficient equal to its depth in the ontology.

•

If a concept has several parent concepts, its coefficient is the average of its parents’ coefficients (sum divided by the number of parents).

•

Coefficients are propagated toward leaf concepts, starting from the highest depth, and increased only when moving from depth
i
to a deeper depth
i+1
.

This assignment favors descendant concepts, especially leaf concepts. We denote the resulting coefficient by the function
\mathrm{Coef}(C_{k})
. Figure
4(a)
illustrates an example of coefficient assignment.

(a)

Domain ontology concepts depth coefficients.

(b)

Weight of ontology concepts after weighting.

Figure 4
:
Illustration of concept coefficient assignment and the resulting concept weights.

Next, we compute the
margin

(\Delta)
, which is used to determine the final weights of ontology concepts. The margin is defined as:

\Delta=\frac{1}{\left(\sum_{k=1}^{|N|}\left(\mathrm{Coef}(C_{k})-\mathrm{Coef}(C_{1})\right)\right)^{2}}

(1)

where:

•

1
is the total weight of the ontology,

•

\mathrm{Coef}(C_{k})
is the coefficient of concept
C_{k}
,

•

\mathrm{Coef}(C_{1})
is the coefficient of the root concept,

•

|N|
is the number of concept classes in the ontology.

For our domain ontology, we obtain:

\Delta=\frac{1}{\left((1-1)+(2-1)+(2.5-1)+(3-1)+(4-1)+(4.5-1)+(5-1)\right)^{2}}=\frac{1}{15^{2}}=0.0044.

We then compute the average coefficient of the ontology concept classes, denoted
\mathrm{Coef}_{AVG}
:

\mathrm{Coef}_{AVG}=\frac{\sum_{k=1}^{|N|}\mathrm{Coef}(C_{k})}{|N|}

(2)

where:

•

\sum_{k=1}^{|N|}\mathrm{Coef}(C_{k})
is the sum of the coefficients of all ontology concepts,

•

|N|
is the number of concept classes in the ontology.

For our ontology, we obtain:

\mathrm{Coef}_{AVG}=\frac{1+2+2.5+3+4+4.5+5}{7}=\frac{22}{7}=3.1428.

Independently of the coefficients, the average weight of a concept class is:

W_{AVG}=\frac{W_{\Omega}}{|N|},

where
W_{\Omega}
is the total weight of the ontology. In our case:

W_{AVG}=\frac{1}{7}=0.1428.

Figure 5
:
Representation of an XML document as a tree.

Finally, the real weight
W_{R}(C_{k})
of each concept is computed by combining the average weight, the margin, and the concept coefficient:

W_{R}(C_{k})=W_{AVG}+\Delta\times\left(\mathrm{Coef}(C_{k})-\mathrm{Coef}_{AVG}\right)

(3)

where:

•

W_{AVG}
is the average weight of an ontology concept class,

•

\Delta
is the margin,

•

\mathrm{Coef}(C_{k})
is the coefficient of concept
C_{k}
,

•

\mathrm{Coef}_{AVG}
is the average coefficient of the ontology concept classes.

These formulas ensure that the sum of all concept weights equals the ontology weight (1). The resulting weights for our ontology are shown in Figure
4(b)
.

The proposed approach

4.1
Indexing process

Our approach relies on the semantic vector model
[
59
,
7
]
and the domain ontology (Section
3.1
) to build personalized concept vectors for XML document nodes. Let
\Omega
be the domain ontology and
C_{\Omega}
the set of its concepts with cardinality
n
(
n=|C_{\Omega}|
). The conceptual space associated with
\Omega
is defined as
E_{\Omega}=C_{\Omega}=\{c_{1},\ldots,c_{j},\ldots,c_{n}\}
. In this space, each text node
N_{t}^{\,i}
is represented by a concept-weight vector:

\vec{N}_{t}^{\,i}=\left(w_{i1},\ldots,w_{ij},\ldots,w_{in}\right),

where
w_{ij}
is the weight of concept
c_{j}
in the text node
N_{t}^{\,i}
.

Term (concept) weighting estimates local importance within a node and global importance within the collection. Classical schemes include TF–IDF
[
53
]
and probabilistic models such as BM25
[
45
]
and its extensions (e.g., BM25F
[
46
]
, BM25F–S
[
10
]
). Following
[
51
]
, we adopt a TF-like factor and an element-based inverse frequency, and we incorporate the ontology-derived concept weight
W_{R}
(Section
3.1
). The weight of concept
c_{j}
in a text node
N_{t}^{\,i}
is computed as:

w_{ij}=cf_{ij}\times iecf_{j}\times W_{R_{j}}

(4)

where:

•

cf_{ij}
is the number of occurrences of concept
c_{j}
in text node
N_{t}^{\,i}
,

•

iecf_{j}=\log\frac{|N_{t}|}{|N_{t}^{c_{j}}|}
, with
|N_{t}|
the total number of text nodes in the collection and
|N_{t}^{c_{j}}|
the number of text nodes containing concept
c_{j}
,

•

W_{R_{j}}
is the real weight of concept
c_{j}
in the ontology
\Omega
.

4.1.1
Acquiring a user profile

User profiles can be defined along several dimensions. In this work, we focus on the
domain of interest
, which reflects the general characteristics of the information the user seeks. We model the user profile as a vector of centers of interest aligned with the ontology concepts. Thus, the number of centers of interest equals the number of ontology concepts
|C_{\Omega}|
, and the initial weights are set uniformly:

w_{CI}=\frac{1}{|C_{\Omega}|},

where
|C_{\Omega}|
is the number of concepts (centers of interest) in the ontology
\Omega
.

Users express their information needs through a sequence of requests, which are recorded and used to progressively update the profile. At any time, the profile is represented by the centers-of-interest vector:

\vec{V}_{CI}=(w_{CI_{1}},\ldots,w_{CI_{j}},\ldots,w_{CI_{n}}).

A user request at time
t
is represented by the query vector:

\vec{q}_{t}=(w_{t1},\ldots,w_{tj},\ldots,w_{tn}),

where
w_{CI_{j}}
denotes the weight of the
j^{\mathrm{th}}
center of interest in
\vec{V}_{CI}
, and
w_{tj}
denotes the weight of concept
c_{j}
in the query
\vec{q}_{t}
.

After each request, the weight of each center of interest is updated as:

w_{CI_{j}}(t+1)=\left(e^{w_{tj}}-1\right)+w_{CI_{j}}(t)

(5)

where
w_{CI_{j}}(t)
and
w_{CI_{j}}(t+1)
are the weights of the
j^{\mathrm{th}}
center of interest before and after processing the request at time
t
.

4.1.2
Building node indexes

Index construction is based on concept propagation, inspired by
[
27
,
29
]
. Because XML documents are tree-structured, an element-type node index aggregates the indexes of its descendant text nodes; in other words, concepts extracted from text nodes are propagated upward in the XML tree (Figure
6
).

Figure 6
:
Concept propagation from text nodes to element nodes for index construction.

To identify the document part that best matches a user request, we propagate concepts and weights from leaf text nodes to ancestor element nodes while incorporating the user interest vector
\vec{V}_{CI}
. The construction is guided by two intuitions: (i) the larger the distance between a text node and an ancestor element node, the smaller its contribution; and (ii) for an element node, concepts that appear across many descendant text nodes contribute more to its representation.

Let
N_{e}
be an element-type node and
Set_{N_{e}}=\{N_{t}^{1},\ldots,N_{t}^{k},\ldots,N_{t}^{m}\}
the set of its
m
descendant text nodes. We define:

•

Dist(N_{e},N_{t}^{k})
as the number of arcs between
N_{e}
and its descendant text node
N_{t}^{k}
,

•

|N_{t}^{e}|
as the number of descendant text nodes of
N_{e}
(i.e.,
|N_{t}^{e}|=m
),

•

|N_{t}^{c_{j}^{e}}|
as the number of descendant text nodes of
N_{e}
that contain concept
c_{j}
.

For concept
c_{j}
, the corresponding weight in the vector of
N_{e}
is:

w_{ej}=\left(\sum_{k=1}^{m}\frac{|N_{t}^{c_{j}^{e}}|}{|N_{t}^{e}|}\times\frac{1}{Dist(N_{e},N_{t}^{k})}\times w_{kj}\right)\times w_{CI_{j}},

(6)

where
w_{kj}
is the weight of concept
c_{j}
in the descendant text node
N_{t}^{k}
(Eq. (
4
)), and
w_{CI_{j}}
is the current weight of the
j^{\mathrm{th}}
center of interest in
\vec{V}_{CI}
.

4.2
Node–query matching

This step assigns relevance scores to XML document elements (text nodes and element nodes) by comparing the query representation with node representations. The goal is to return units of information that are both (i)
specific
(fine-grained) and (ii)
exhaustive
(cover the information requested). Therefore, score computation and concept weighting play a central role in evaluating the relevance of a node to a user request.

4.2.1
Text-type node

A text-type node is represented by a concept weight vector:

\overrightarrow{N_{t}^{\,j}}=(w_{1j},\ldots,w_{kj},\ldots,w_{nj})
,
where
w_{kj}
is the weight of concept
c_{k}
in node
N_{t}^{\,j}
.
Similarly, a query
q
is represented by a concept weight vector

\vec{q}=(w_{1},\ldots,w_{k},\ldots,w_{n})
.

The query concept vector is constructed according to the type of concepts sought. For example, if the user requests a
Domain
-type concept, the system considers the concepts associated with that domain by exploiting semantic relations in the ontology (e.g.,
made-of
,
trait
).

We measure the proximity between a node and a query using cosine similarity
[
48
]
. The relevance score of a text node
N_{t}^{\,j}
with respect to query
q
is:

score(q,N_{t}^{\,j})=\frac{\sum_{i=1}^{n}w_{ij}\,w_{i}}{\left[\sum_{i=1}^{n}w_{ij}^{2}\right]^{\frac{1}{2}}\left[\sum_{i=1}^{n}w_{i}^{2}\right]^{\frac{1}{2}}}.

4.2.2
Element-type node

Since textual information is contained in text nodes, the evaluation of an element node depends on its descendant text nodes: to what extent do the descendants contain (and concern) the information requested by the query?

Following Harrathi et al.
[
27
]
, we consider:

|N_{t}^{P}|
, the number of descendant text nodes with non-zero score, and

|N_{t}^{NP}|
, the number of descendant text nodes with zero score.

Figure 7
:
Example of start and end values assigned to nodes in an XML document.

Intuitively, if
|N_{t}^{P}|
is large and/or
|N_{t}^{NP}|
is small, the element node is more likely to contain useful information for the query. The relevance (pertinence) of an element node
N_{e}
is computed as:

\mathrm{Pertinence}(q,N_{e})=\frac{e^{\frac{|N_{t}^{P}|}{|N_{t}^{P}|-1}}}{e^{|N_{t}^{NP}|}}\,score(q,N_{e}).

(7)

where
score(q,N_{e})
is obtained using the same cosine similarity formula applied to the concept vector of
N_{e}
.

4.3
Query processing

Query processing allows users to search the document collection by submitting a query through a search interface. In our approach, both text nodes and queries are represented as ontology-based concept vectors, and results (document fragments) are ranked according to their similarity to the query. Efficient querying in semi-structured documents additionally requires exploiting structural relationships (e.g., ancestor–descendant and predecessor–successor).

We rely on the DOM model and on a refinement of Dietz’s tree numbering scheme
[
15
,
26
]
. Each XML node is assigned two identifiers:
start
and
end
, defined as:

•

start
: the order of appearance of the node in a sequential traversal of the XML document;

•

end
: the order of disappearance of the node in the same traversal.

Figure 8
:

As illustrated in Figure
7
, the node
title
(
N_{e}^{2}
) has
start=4
and
end=7
.
To support navigation and fast structural filtering, each node is represented by the tuple

\langle start,end,parent,type,name,value\rangle
, where:

•

start
: the order of appearance of the node in the traversal;

•

end
: the order of disappearance of the node in the traversal;

•

parent
: the identifier (start value) of the parent node;

•

type
: the node type (element, attribute, text);

•

name
: the tag/attribute name (null for text nodes);

•

value
: the attribute value or text content (null for element nodes).

Mapping nodes to the
(start,end)
plane provides the following properties for a node
n
(e.g.,
doc/sec1
):

•

all ancestors of
n
lie above-left of
n
;

•

all descendants lie below-right;

•

predecessors lie below-left;

•

successors lie above-right.

Using intervals, structural relationships between two nodes
u
and
v
are resolved as follows:

•

ancestor–descendant
:
u
is an ancestor of
v
iff the interval of
u
contains the interval of
v
;

•

predecessor–successor
:
u
precedes
v
iff the interval of
u
precedes the interval of
v
.

Figure
8
presents the result of applying this technique to the XML document represented in Figure
5
. To extract node descriptors, we parse XML documents using a parser. Two common parser families are:

•

event-oriented parsers: API
SAX
(Simple API for XML);

•

tree-oriented parsers: API
DOM
(Document Object Model).

We use SAX callbacks to compute descriptors, mainly:

•

startDocument
: invoked when a new document is encountered;

•

startElement
: invoked when an opening tag is encountered;

•

endElement
: invoked when a closing tag is encountered;

•

characters
: invoked when text is encountered.

A stack is used to store
start
values of nodes whose
end
value is not yet known:

•

on
startElement
: push the start value onto the stack;

•

on
endElement
: read the start value from the stack top, pop it, and obtain the parent from the new stack top.

These steps generate descriptors of the form
(element\_name,start,end,parent)
, which support navigation, subtree inclusion, and filtering during indexing and retrieval. Figure
9
shows the evolution of the stack as the XML document is traversed.

The algorithm can also compute additional attributes such as node height (stack depth minus one) and path (stack content). For implementation, we store descriptors in a relational database using the following tables:

•

Document
(
Idf_doc, doc_name
)

•

Element
(
idf_doc, begin, ele_name, end, parent
)

•

Attribute
(
idf_doc, begin, end, parent, att_name, value_att
)

•

Text
(
idf_doc, begin, value, end, parent
)

4.4
Implementation

The proposed approach is implemented as a web application. We chose the Java programming language and Servlets for their flexibility and portability. This work is situated in the Semantic Web context, which aims to enrich content with machine-interpretable meaning. Accordingly, we use OWL (Web Ontology Language) to represent the domain ontology and the Jena API for ontology creation, manipulation, and access. Figure
10
presents the overall architecture of our prototype.

Figure 10
:
General architecture of the developed prototype.

As shown in Figure
10
, after registration, the user provides personal information and an initial profile is created, where the centers of interest are assigned uniform default weights. The user then submits information needs in the form of queries; these queries are stored in the profile database and used to continuously enrich the profile by updating the centers of interest according to the user’s searches. For index storage, we use four relational tables to separately store XML document nodes by type (element, attribute, text, and document) together with their associated identifiers and names.

Experimental protocol and positioning

Our evaluation is designed to make the effect of personalization explicit at different granularities. We report results (i) for repeated requests issued by the same user profile (to isolate the impact of ontology weighting and profile integration), and (ii) for multiple users with different interests over successive instants
T_{1}
–
T_{8}
(to analyze stability and adaptation as interests evolve). In addition, we report global average metrics to provide a compact summary that is easier to compare with the literature.
Because datasets, ontologies, query sets, and relevance assessment procedures differ substantially across related studies, a direct numerical comparison is not always feasible. We therefore complement the reported scores with a clear methodological comparison, highlighting differences in experimental design (dataset construction, query generation, and evaluation granularity) to strengthen scientific soundness and reduce the risk of misinterpretation.

6
Conclusion

This paper presented a personalized XML information retrieval approach that combines a domain ontology with a dynamically updated user interest vector. By weighting ontology concepts and continuously adapting profile weights based on user queries, the system exploits explicit semantic structure while accommodating evolving preferences. Experimental results, including F1-scores across different user profiles, indicate that the approach improves retrieval effectiveness, particularly for specific concepts supported by the ontology hierarchy.

Future work will focus on validating the approach on larger and more heterogeneous XML collections and on extending it beyond the computer science domain. We also plan to investigate neural methods to refine user interest vectors from both explicit and implicit interaction signals, and to explore automatic ontology enrichment from XML corpora. Additional directions include modeling collective user profiles for collaborative personalization and integrating a proactive recommendation module to anticipate information needs.
