QQ: A Toolkit for Language Identifiers and Metadata
Wessel Poelman, Yiyi Chen, Miryam de Lhoneux

Abstract
The growing number of languages considered in multilingual NLP, including new datasets and tasks, poses challenges regarding properly and accurately reporting which languages are used and how. For example, datasets often use different language identifiers; some use BCP-47 (e.g. en_Latn ), others use ISO 639-1 ( en ), and more linguistically oriented datasets use Glottocodes ( stan1293 ). Mapping between identifiers is manageable for a few dozen languages, but becomes unscalable when dealing with thousands. We introduce QwanQwa, a light-weight Python toolkit for unified language metadata management. QQ integrates multiple language resources into a single interface, provides convenient normalization and mapping between language identifiers, and affords a graph-based structure that enables traversal across families, regions, writing systems, and other linguistic attributes. QQ serves both as (1) a simple “glue” library in multilingual NLP research to make working with many languages easier, and (2) as an intuitive way for exploring languages, such as finding related ones through shared scripts, regions or other metadata.

Introduction

As multilingual NLP scales across languages, so do the logistics of tracking language metadata.
Researchers must decide how to represent language varieties (e.g., language vs. dialect), resolve ambiguous or deprecated identifiers (e.g.,

Several resources provide rich language metadata, but they are often distributed in formats that are not optimized for Python-based NLP workflows.

2.1
Compiling the Database

Given the highly interconnected nature of language data (
Figure 1
), QQ is structured as a graph.
The primary entities (nodes) in this graph are
Languoid
,
Script
, and
Region
, which are linked through relational edges.
Through these relations, all entities are potentially transitively connected.

The term “languoid” was coined by
Good and Hendryx-Parker 2006
to refer to “a language, variety of a language, or group of languages.”
Since many identifiers (ISO codes, Glottocodes, etc.) can refer to all three, we chose to use
Languoid
as the main “language-like” entity in the graph.
Similarly, we use “region” to refer to continents, countries, provinces, macro-areas, etc.
Both “languoid” and “region” were chosen as neutral umbrella terms: specifying what level a languoid belongs to (language, dialect, family) is easily done through a property, rather than a new entity type.
The same applies to regions.
QQ should not have the responsibility of defining what region is considered a country or which language a dialect, for example.
Sources should be responsible for this, meaning our data model should be neutral.
Such classifications can carry political implications, which we avoid by using a neutral data model.

In selecting our sources, we focus on those most relevant to our target audience in
multilingual NLP
.
Based on interactions with users and personal experience, we narrowed this down to:

Each source registered in QQ is automatically checked for updates or changes when the database is rebuilt.
Sources have one or more
importers
.
When compiling the database, importers extract relevant values from sources, normalize, resolve, and merge them, and finally the graph is made.
QQ can resolve conflicting information through either manual resolution or by source priority.
For example, LinguaMeta classifies the ISO 3166-2 region code
AN
as “not historical”, whereas
pycountry
(correctly
3
3

3

https://en.wikipedia.org/wiki/ISO_3166-2:AN
) lists it as historical.
QQ reports conflicts encountered during database construction and which resolution strategy was used per conflict.
This allows for detecting potential data issues, which can be reported upstream.
A typical user can use the pre-compiled database that QQ ships with, but updating sources and rebuilding the database is possible, even with the PyPi version.

A full update of the sources and rebuild of the database are performed with a single command
qq rebuild
.
Extending the database is easily done by adding a source provider and an importer.
All other parts work independently of this.
QQ’s final database is
\sim
2 MB compressed and contains 27,256 Languoids, 227 Scripts, 5,361 Regions, and 97,288 edges between them.

We formulate the colexification graph as
{\mathcal{G}}=({\mathcal{V}},{\mathcal{E}})
, where each node
v\in{\mathcal{V}}
is a concept, each edge
(u,v)\in{\mathcal{E}}
indicates that the two concepts are colexified by a lemma in at least one language.
For each rating type

{\bm{x}}^{(d,\ell)}\in\mathbb{R}^{|{\mathcal{V}}|}
, where
{\bm{x}}_{i}
is the z-scored rating of concept

We frame colexification as a

This allows for research questions such as:

RQ1.
Do cross-lingual colexified concepts exhibit structural and non-random patterns in psycholinguistic ratings?

RQ2.
Are they universal, or do they vary across languages?

Graph-based Smoothness Analysis.

To answer
RQ.1
, we quantify the smoothness of each rating type over the colexification topology using the normalized Rayleigh quotient.
For a given language and rating vector
{\bm{x}}
, we compute
R={\bm{x}}^{\top}{\bm{L}}{\bm{x}}/{\bm{x}}^{\top}{\bm{x}}
, where
{\bm{L}}={\bm{I}}-{\bm{D}}^{1/2}{\bm{A}}{\bm{D}}^{1/2}
is the normalized graph Laplacian of the
{\mathcal{G}}
.

Lower
values of
R

9

9

The eigenvalues of
L
is bounded by
[0,2]
, therefore
R\in[0,2]

To determine whether the observed smoothness is above chance, we compare each observed

Rayleigh values are below 1 across languages and ratings, and most are highly significant under permutation testing (

This indicates that ratings vary smoothly over the cross-lingual semantic colexifications, rather than being randomly distributed.

Own-Language vs. Other-Language Colexified Concepts.

Building on the strong valence alignment, we further examine
whether colexifications are most semantically coherent within the language that produces them
, addressing
RQ2
.

Let
x_{i}^{(l)}
be the valence z-score of concept
i
in language
l
.
We define valence dissimilarity in language
l
for any pair of concepts
(i,j)
as
\Delta_{l}(i,j)=|x_{i}^{(l)}-x_{j}^{(l)}|
.
Let
{\mathcal{E}}
denote the set of all colexified concept pairs in the global colexification graph
{\mathcal{G}}
.
For each language
l
, we define the subset as

{\mathcal{E}}_{l}=\{(i,j)\in{\mathcal{E}}\mid\text{concepts }i,j\text{ are colexified in language }l\}
,
and its complement within colexified pairs

{\mathcal{E}}_{\neg l}={\mathcal{E}}\setminus{\mathcal{E}}_{l}
.
We compare the distributions of
\Delta_{l}(i,j)
over
{\mathcal{E}}_{l}
and
{\mathcal{E}}_{\neg l}
, testing the directional hypothesis:

\mathbb{E}[\Delta_{l}(i,j)\mid(i,j)\in\mathcal{E}_{l}]<\mathbb{E}[\Delta_{l}(i,j)\mid(i,j)\in\mathcal{E}_{\neg l}]
,
i.e., concept pairs colexified in language
l
should exhibit smaller valence differences within that same language than pairs colexified in other languages (see details in
Appendix A
).
We observe that valence dissimilarity is consistently lower for own-language colexifications, with an average of
0.083
.
This pattern holds across languages (
Figure 3

5
Conclusion

We present QQ: a Python library for language identifiers and metadata.
QQ imports, combines, and normalizes metadata sources relevant to multilingual NLP.
We provide convenient access through easy conversion between identifiers and graph-based traversal of common relations between languoids, scripts, and regions.
Through three case studies, we show how QQ can be a useful addition to multilingual NLP research workflows.

Limitations

Data.

There are two limitations regarding the data in QQ.
We are grateful for and indebted to the sources we incorporate, but there can always be issues with the data.
While developing and using QQ, we spotted small data issues, which we also reported upstream.

We analyze what the HF API returns regarding language metadata about datasets, we do not investigate if there are other or multiple “language id” columns in the contents of the datasets themselves.

Appendix A
Details Colexification Analysis

A.1
Colexification Graph Construction

First, we construct colexification graphs using the cross-lingual concepts in BabelNet following
Chen et al. 2023
;
Chen and Bjerva 2023a
. The concepts are then anchored to Concepticon identifiers, resulting in a colexification graph in which nodes are Concepticon concepts and edges record the languages and lemmas through which each pair colexifies.
Then, affective and other psycholinguistic norms are drawn from NoRaRe, across multiple dimensions, such as valence, dominance, arousal, age of acquisition, imageability, familiarity, frequency, concreteness, and emotionality, across 10 languages.

We extract the average ratings, denoted by
MEAN
, across all datasets from NoRaRe. For a fair comparison, we apply z-score normalization to each dataset to place them on a common scale.
The resources are then merged by restricting colexification edges to pairs in which both endpoints (nodes), i.e., concepts, have at least one rating, producing a colexification graph for each rating type.
Each edge stores the per-language z-scored ratings at the connected nodes and the absolute z-score difference for each language, enabling direct cross-lingual comparison of rating similarity within colexified concepts.

The z-score normalization is applied on raw ratings within the dataset
d
:

z_{c,d}=\frac{r_{c,d}-\bar{r}_{d}}{\sigma_{d}},

where
r_{c,d}
is the raw rating of concept
c
in dataset
d
and
\bar{r}_{d}
,
\sigma_{d}
is are the dataset mean and population standard deviation.
This places all datasets on a common scale (
\mu=0
,
\sigma=1
) regardless of the original rating range.

Since multiple datasets may provide ratings for the same concept in the same language (e.g., two English valence norms), we compute a mean z-score per concept per language by averaging
z_{c,d}
across all datasets that contribute a rating for concept
c
in language
\ell
:

\bar{z}{c,\ell}=\frac{1}{|D{c,\ell}|}\sum_{d\in D_{c,\ell}}z_{c,d},

where
D_{c,\ell}
is the set of datasets for concept
c
in language
\ell
.
Each contributing dataset is weighted equally, since the z-score is standardized across dataset sizes.

3

We test our hypotheses using a one-sided Mann-Whitney U test for each language
l
, with the alternative hypothesis that
\Delta_{l}
is smaller for
{\mathcal{E}}_{l}
than for
{\mathcal{E}}_{\neg l}
.
We additionally report Cohen’s
d

d_{l}=\frac{\mu_{\neg l}-\mu_{l}}{\sqrt{\frac{\sigma_{\neg l}^{2}+\sigma_{l}^{2}}{2}}},

where
\mu_{l}
and
\sigma_{l}
denote the mean and standard deviation of
\Delta_{l}
