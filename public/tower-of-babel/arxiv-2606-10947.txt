Enumerating tuples of spanning trees
Rahul CS, Michał Włodarczyk

Abstract




1
Introduction

Consider the problem of enumerating all spanning trees in undirected graphs. Let
G=(V,E)
be an undirected graph. The problem of enumerating all spanning trees has long history and numerous applications in networks and circuit analysis. We use the notation T-Enum to refer to this problem. The work detailed in
[
2
]
gives a simple and efficient solution for the problem where the delay between two successive enumerations is polynomial. Another classical problem of the kind is to compute a set
\mathcal{S}
of pairwise edge disjoint spanning trees. The number of trees in the set (tree pack)
\mathcal{S}
is part of problem definition. We use the notation TP
k
to represent this problem.

Motivated by the above two problems, we look at the problem of enumerating all tree packs in a graph with polynomial delay between two succesive enumerations. Let
k
be the number of spanning trees in a pack. The problem T-Enum corresponds to the case where
k=1
.

Tutte
[
4
]
and Nash-Williams
[
3
]
came up with the following nice characterization
[
1
, Theorem 1]
for the existence of such a pack.

Theorem 1
.

A graph contains
k
pairwise edge disjoint spanning trees if and only if for every partition
\mathcal{P}
of
V(G)
, the graph
G/
\mathcal{P}
has
k(|
\mathcal{P}
-1|)
edges.

This is such a clinical characterization which gives us the following corollary being recursively evolved from the original version.

Corollary 2
.

Let
\mathcal{P}
be a nontrivial partition of
V(G)
where
G[X]
contains
k
pairwise edge disjoint spanning trees for each
X
in
\mathcal{P}
. Then the graph
G
has
k
pairwise edge disjoint spanning trees if and only if for every partition
\mathcal{P}
’ of
\mathcal{P}
, the graph
G/
\mathcal{P}
’ has
k(|
\mathcal{P}
’
-1|)
edges.

We extend this characterization to come up with a polynomial time algorithm for the
tree-pack enumeration problem
, formally defined as follows.

Tree-Pack Enumeration
(TP
k
-Enum)

Input:
An undirected graph
G=(V,E)
and a parameter
k

Task:
Output each set
\mathcal{S}
of
k
pairwise edge disjoint spanning trees with polynomial delay between two successive enumerations

Note that our problem is not about enumerating all sets of edges that constitutes a tree pack of the above form, but to enumerate the packs itself.

3.1
A Reformulation of the Algorithm for TP
k

The algorithm
\mathcal{A}
is a tail recursive algorithm which ensures a steady progress in each recursion. The input to each recursion in the algorithm is a
k
-decomposition
\mathcal{T}
and the output being another
k
-decomposition
\mathcal{T}
’ which being fed as the input to the next recursion, unless the progress function hits its threshold. Once the algorithm terminates, it outputs either a tree pack(
k
) or a
k
-decomposition certifying the violation of the characterization in Theorem
1
.

A single recursion of
\mathcal{A}
takes a
k
-decomposition
\mathcal{T}
as input having
k
-1 of its coordinates being trees. The remaining coordinate is a non-tree, as otherwise we are done. There is an arbitrary strict ordering between the coordinates, with the last being the non-tree. Our algorithm follows the same structure with each recursion constitutes of two phases. The first phase is exactly the same as in
\mathcal{A}
. In the second phase,
\mathcal{A}
performs a single edge swap between the coordinates
G_{k}
and some
G_{j}
in
\mathcal{T}
, retaining the connectedness of
G_{j}
(
j\neq k
). We modify this part in such a way that we perform minor shortcutting operations on the computation path associated with
\mathcal{A}
.

In the first phase, the algorithm performs a sequence of partition refinement operations starting from the partition
\mathcal{P}_{0}=\{V(G)\}
. Each refinement constructs a new partition
\mathcal{P}_{i+1}
from
\mathcal{P}_{i}
as follows: For each
X
in
\mathcal{P}_{i}
and coordinate
G_{j}
in
\mathcal{T}
(iterate
j
from 1 to
k
as in the predefined ordering), check whether
G_{j}[X]
is connected. Pick the least
j
violating the condition. Now, we construct the partition
\mathcal{P}_{i+1}
from
\mathcal{P}_{i}
by adding the vertex set of each component in
G_{j}[X]
as a part to
\mathcal{P}_{i+1}
, for each
X
in
\mathcal{P}_{i}
. Thus,
\mathcal{P}_{i+1}
is a refinement of
\mathcal{P}_{i}
. At this point, we define an indexing function SI(
\mathcal{P}_{i}
) (the
split index
of the partition
\mathcal{P}_{i}
) as the index
j
of the coordinate in
\mathcal{T}
being responsible for the split. We address this coordinate as the splitter of
\mathcal{P}_{i}
, denoted as
S(\mathcal{P}_{i})
which is exactly same as
G_{\textnormal{SI(}\mathcal{P}_{i}\textnormal{)}}
. Further, the level
l(e)
of an edge is defined as the largest
i
such that some part in
\mathcal{P}_{i}
contains both ends of
e
.

This refinement procedure terminates at least when
\mathcal{P}_{i}
is
V(G)
. This final partition in the sequence is being addressed as
\mathcal{P}_{\infty}
, where
G_{j}[X]
is connected for each part
X
in
\mathcal{P}_{\infty}
and each
j
between 1 and
k
. The split index of
\mathcal{P}_{\infty}
is infinity(
>k
). Note that
\mathcal{P}_{1}
is induced by the components in
G_{k}
. The split index of

is always at least
k
. Our objective is to hit a recursion where

(the split index of
\mathcal{P}_{0}

).

Let

be a part in a partition
\mathcal{P}_{i}
in a sequence constructed above. Let

be a pair of vertices in

Let us consider the forward direction of the claim. Clearly, there exists at least one path

in

having exactly one of its ends in

To prove the reverse direction, observe that there does not exist a path

Given a partition

in the sequence and a

Observe that an edge

has its end vertices belong to distinct parts in

∎

Lemma 8

Let

be partition in the sequence and let

in

. Let

Proof of Correctness

We follow the same line of proof as in
[
1
]
. The way we modify the algorithm helps us to redefine the progress function associated with the algorithm in a much simpler way. We claim that in each recursion of our algorithm, there is a strict reduction in the number of components in
G_{k}
, which is enough to ensure a positive progress towards the solution.

Recall that by the end of first phase, each
X
in
\mathcal{P}_{\infty}
has the property that
G_{j}[X]
is connected for each
G_{j}
(
1\leq j\leq k
) in
\mathcal{T}
and hence a tree pack(
k
) for each
G[X]
. These tree packs together with the solution for
G/\mathcal{P}_{\infty}
constitutes the final solution. This is by virtue of Corollary
2
. It is easy to see that this construction is recursive in nature. This is an additional filter function that could be added to our algorithm and
\mathcal{A}
.

Next we discuss the correctness of the second phase which itself is a recursive subroutine. We make the following claim.

Lemma 9
.

Each call to the subroutine CONNECTOR(
rf
,
final
) maintains the invariant that the subgraph
G_{rf}/\mathcal{P}_{final}
has at least one multicycle in it.

Proof.

Consider the first call to the subroutine CONNECTOR from the first phase. Clearly,
G_{k}
contains an open cut as otherwise we are done. Assuming the instance satisfying the characterization, by counting argument, there exists a multicycle in
G_{k}/\mathcal{P}_{\infty}
as all the remaining coordinates are trees and contributes at most
|\mathcal{P}|-1
edges to
G_{k}/\mathcal{P}_{\infty}
. If not, we have a certificate vindicating that the instance fails the characterization, and we stop. Thus, the algorithm progresses to the second phase for yes instances.

For subsequent calls, we make an inductive argument. Let us assume that the invariant holds for a call to some intermediate recursion. We assume a recursive call follows, and prove the invariant for that. Let us consider the execution sequence associated with this recursion. We pick the multicycle
\mathcal{C}
in
G_{rf}/\mathcal{P}_{final}
. Clearly,
final\neq 0
and
\mathcal{C}
induces at least one edge in
G_{rf}/\mathcal{P}_{final}
. From Lemma
7
, the level of each edge
e
in
\mathcal{C}/\mathcal{P}_{final}
is strictly less than
final
. Let
e=(u,v)
be the edge with least level in
\mathcal{C}
and the algorithm sets
i=l(e)
. From Lemma
8
, there exists
P\in\mathcal{P}_{i}
such that
V(\mathcal{C})\subseteq P
.
The algorithm moves the edge
e
to
S(\mathcal{P}_{i})
. From the assumption that this is not the last recursion,
u
and
v
are connected by a path
P_{uv}
in
S(\mathcal{P}_{i})
(excluding
e
). From Lemma
6
, each
P_{u,v}
in
S(\mathcal{P}_{i})
spans beyond
\mathcal{P}
and has at least one edge in
S(\mathcal{P}_{i})/\mathcal{P}_{i}
. Thus, the addition of
e
to
S(\mathcal{P}_{i})
creates a multicycle in
S(\mathcal{P}_{i})/\mathcal{P}_{i}
.
∎

To conclude, observe that the subroutine CONNECTOR always pulls out the edge
e
from a cycle and this does not disturb connectedness of any of those coordinates in
\mathcal{T}
. Further, it terminates when the end vertices of the edge
e
belong to different components in
S(\mathcal{P}_{i})
. This happens when SI(
\mathcal{P}_{i}
)
=k
and
i
takes the value 0. Thus
final
always takes a positive value. Since, the cycle
\mathcal{C}
under consideration is in
G_{rf}/\mathcal{P}_{final}
and completely contained in a part in
\mathcal{P}_{i}
,
i<final
and there is strict decrease in the value of the second parameter over recursions. Thus, CONNECTOR always terminates and at this point, our algorithm makes a positive progress.

As there is a strict reduction in the number of components in
G_{k}
over each recursion of our algorithm, there are at most
\mathcal{O}(n)
recursions.

\neq k

Theorem 11
.

Assume there is an algorithm for
k
-
Partial Spanning Tree
with running time
T(n,m,k)
.
Then there is an enumerating algorithm that enlists all (pairwise non-isomorphic)
k
-tuples of pairwise disjoint spanning trees in
G
with at most
\mathcal{O}(mk\cdot T(n,m,k))
operations per one output.

Proof.

Let us fix an ordering on
E
.
We construct a decision tree with nodes representing partial solutions, i.e.
k
-tuples of pairwise disjoint forests in
G
.
The partial solutions at depth
\ell
can use only edges from
e_{1},\dots e_{\ell}
.
The root of the tree is given by tuple
\emptyset^{k}
and has depth 0.
The leaves for which all
F_{i}
contain
n-1
edges correspond to the
k
-tuples that should be returned.

The algorithm performs a DFS starting at the root and for each node at depth
\ell<m
it tries to augment some of
F_{i}
with edge
e_{\ell+1}
.
If the edges in
F_{i}
start forming a cycle then such a node is neglected.
The node also gets neglected if the instance of
k
-
Partial Spanning Tree
given by

E^{\prime}=\{e_{\ell+1},\dots,e_{m}\}
and
F_{1},\dots,F_{k}
has a negative answer.
After neglecting a node we omit its whole subtree since we know it does not contain any solutions to be returned.

Consider a node
w
at depth
\ell
given by a partial solution
F_{1},\dots,F_{k}
.
For each
i
such that
F_{i}\neq\emptyset
we construct a tree
F^{\prime}_{i}=F_{i}\cup\{e_{\ell+1}\}
.
With other trees unaffected we check if such a partial solution is extendable to some full solution and, if yes, we proceed recursively to the newly created node.
If the
k
-tuple in the node
w
contains empty forests we pick the smallest
i
such that
F_{i}
is empty.
We set
F^{\prime}_{i}=\{e_{\ell+1}\}
and we move to the new node.
After checking all possibilities of adding
e_{\ell+1}
in the node
w
,
we proceed to another node at level
\ell+1
with all trees unchanged.
This move corresponds to not using
e_{\ell+1}
at all.

We argue that all
k
-tuples of spanning trees will be finally generated,
one per each orbit of the tuple isomorphism.
Let
ind(T)
denote the smallest
\ell
such that
e_{\ell}\in T
.
For a set
\{T_{1},\dots,T_{k}\}
of spanning trees we fix an ordering such that
ind(T_{1})<ind(T_{2})<\dots<ind(T_{k})
.
We can see that by augmenting only the empty forest with the smallest index we will generate only this ordering.

To estimate the number of operations between outputting two results,
note that DFS only enters nodes with at least one proper solution in its subtree.
Therefore the path traveled between visiting two leaves consists of at most
2m
nodes.
At each node we consider at most
k+1
children and in every such step we need to launch the algorithm for
k
-
Partial Spanning Tree
.
By multiplying these quantities we obtain the postulated running time.
∎

Theorem 12
.

Let
G
be a DAG graph with fixed vertices
s,t
.
There is an enumerating algorithm that enlists all (pairwise non-isomorphic)
k
-tuples of pairwise edge-disjoint (or vertex-disjoint)
s,t
-paths with at most
\mathcal{O}(m^{2}n)
operations per one output.

Proof.

The idea of the proof is the same as in Theorem
11
.
Each node in the decision tree is associated with a partial solution
P_{1},\dots,P_{k}
, where
P_{i}
is a path starting at
s
.
We fix a topological ordering on
E
.

Consider a node
w
at level
\ell
with a partial solution
P_{1},\dots,P_{k}
.
We try to augment every path
P_{i}
ending at
u
where
e_{\ell+1}=(u,v)
.
For each such
i
we create
P^{\prime}_{i}
by adding
e_{\ell+1}
to
P_{i}
and move recursively to the newly created node.
Again, if there are some empty paths in the partial solution and
u=s
we augment only the one with the smallest index.
We also create a duplicate node in which
e_{\ell+1}
will not belong to any path.

In order to omit subtrees with no solutions we check for each node if its
partial solution is extendable.
By Menger’s Theorem this is equivalent to computing
s,t
-flow
in a graph with edges
\{e_{\ell+1},\dots,e_{m}\}
and
(s,s_{i})
for
s_{i}

being the end of the path
P_{i}
(note that in the edge-disjoint case these edges might be parallel).
If we consider the vertex-disjoint case, we firstly apply the known reduction from
Min
s,t
-Vertex Cut
to
Min
s,t
-Edge Cut

The argument that every solution modulo isomorphism will be generated is alike
in Theorem
11
.
Let
ind(P)
be the index of the first edge on path
P
(since the egdes
are ordered topologically this is also the edge with the smallest index).
For a set
\{P_{1},\dots,P_{k}\}
we fix an ordering such that
ind(P_{1})<ind(P_{2})<\dots<ind(P_{k})
and only this tuple will be found by the algorithm.

To estimate the number of operations between outputting two results,
consider the path of length at most
2m
between the corresponding leaves in the decision tree.
Although each node can have
k+1
children, observe that the answer returned by the max flow algorithm does not depend on the index of a path to which we add the new edge.
Therefore we need to run the
\mathcal{O}(nm)
-algorithm for max flow only twice per node, depending on whether we add an edge or not.
The claim follows.
∎
