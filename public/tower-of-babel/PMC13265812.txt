Optimized N-deque partition dual-deque merge string sorting algorithm
Authors: Sirilak Ketchaya, Apisit Rattanatranurak
Published: 2026

ABSTRACT
AbstractString sorting is a fundamental operation in various data-intensive applications, ranging from bioinformatics to database indexing. However, parallelizing string sorting remains challenging due to irregular memory access patterns, which often lead to inefficient cache utilization. This paper introduces the Parallel N-Deque Partition Dual-Deque Merge string sorting algorithm, which is evaluated against several state-of-the-art parallel sorting techniques. It utilizes a parallel block-based partitioning strategy to divide the data into smaller blocks for independent sorting. The algorithm harnesses the N-Deque data structure and OpenMP scheduling to optimize execution efficiency. The performance is evaluated on two distinct platforms: an Apple M2 (8-core) and an Intel Xeon Gold 6142 (16-core). Experimental results demonstrate that speedups of 5.25 and 11.92 can be obtained on the Apple M2 and Intel Xeon Gold 6142, respectively. Moreover, parallel efficiencies of 0.65 and 0.74 are achieved when sorting 20 and 50 million random strings, respectively. Factors such as input data size, block size, sorting cutoff, OpenMP scheduling types, and the number of deques significantly impact runtime performance by influencing cache misses and branch mispredictions.Keywords: Parallel algorithm, Sorting, String, OpenMPSubject terms: Engineering, Mathematics and computing, Physics

Introduction

Sorting is a crucial algorithm widely applied to solve problems in various fields such as biology, big data, engineering, and computer science. Several conventional sorting algorithms, such as QuickSort, MergeSort, and Radix Sort, have been extensively studied and parallelized to handle large-scale datasets. Quicksort is a widely recognized algorithm that employs the divide-and-conquer paradigm, relying on an efficient partitioning mechanism to sort data. This paradigm recursively partitions the dataset into smaller subproblems (divide) and sorts them once they reach a predefined cutoff (conquer). Typically, the process begins by partitioning the dataset into two disjoint subsets based on a selected pivot element. This step is performed recursively until the partitions reach a predefined cutoff, at which point the data within each partition is sorted using its sequential sorting algorithm.

This work introduces the Parallel N-Deque Partition Dual-Deque Merge string sorting algorithm. By adopting a block-based partitioning scheme, the algorithm effectively minimizes synchronization overhead while maximizing parallel throughput. In this paper, a novel algorithm named Parallel N-Deque Partition Dual-Deque Merge String Sorting Algorithm, which utilizes a block-based partitioning concept to enhance sorting efficiency. The sequential partitioning is replaced with the parallel N-Deque Partitioning algorithm. However, this partitioning approach necessitates a subsequent merging phase to reintegrate the dispersed data. To achieve this, the Dual-Deque Merge algorithm is employed, effectively consolidating the sub-partitions into a single, correctly ordered sequence. The OpenMP library1 is utilized in this algorithm to parallelize the partitoning, and sorting algoirthm, enhancing its efficiency and performance. The performance of the algorithm is evaluated using the following metrics: run time, speedup, and efficiency. Subsequently, we optimized this algorithm by utilizing an N-Deque in the partitioning step, which significantly enhances its performance. In the previous work, we employed a parallel Multi-deque data structure for partitioning the data, but its number of threads was not controllable. Furthermore, OpenMP scheduling is implemented to optimize the partitioning phase. This feature enables dynamic workload distribution across threads, allowing for more granular control over parallel block execution. By effectively balancing the task load, this approach significantly enhances performance compared to our previous work. Finally, string sorting in this algorithm is implemented, which compares string data efficiently.

The contributions of this paper are as follows: (1) The Parallel N-Deque Partition Dual-Deque Merge algorithm is proposed as a high-performance solution specifically designed for parallel string sorting. (2) Scheduling strategies are evaluated to optimize the partitioning phase and identify the most effective workload distribution for parallel execution. (3) The N-Deque data structure is incorporated into the partitioning process to demonstrate scalability and efficiency across various configurations. (4) A string sorting mechanism is integrated within the proposed algorithm.

Background and related work

In this section, the related works of the sequential and parallel sorting algorithms, OpenMP, and Dual-Deque Merge algorithm are presented.

Related works

Sorting is a fundamental algorithm that is widely implemented and available in the C++ Standard Template Library (STL). The std::sort function, provided through the header, is a highly optimized sorting utility used to arrange data in a specific order. Internally, std::sort utilizes the Introsort algorithm, which combines the efficiency of Quicksort and Heapsort during the divide phase. For smaller data in the conquer phase, it employs Insertion Sort to ensure optimal performance across a wide range of data sizes and patterns.

In this paper, Parallel BQSort2 and MWSort are executed on our system as benchmark algorithms. BQSort employs a block-based parallel partitioning strategy, similar to the approach proposed by Tsigas and Zhang3. The data is divided into multiple blocks, which are partitioned concurrently. The remaining elements within each block are relocated to the center of the subarray, where a sequential partitioning algorithm is subsequently applied to finalize the distribution. On the other hand, parallel Multi-Way Merge sort (MWSort) is based on the merge sort paradigm. It initially divides the input data into smaller, equally sized segments, which are subsequently merged in parallel using a specialized parallel merge algorithm known as the Multi-way Merge algorithm. This method utilizes a temporary array to store the merged data, requiring at least twice the original memory. Intel Threading Building Blocks (TBB)4 provides a highly optimized implementation of parallel sorting, specifically through the function (TBBSort). It primarily employs the divide and conquer paradigm, utilizing a parallelized version of Quicksort or Introsort in some version. TBBSort partitions the data into two subarrays using a pivot. This partitioning algorithm is recursively run until the subarray becomes sufficiently small and sorts them sequentially. The efficiency of TBBSort is largely attributed to the TBB Work-Stealing Scheduler, using a local double-ended queue (deque). When a thread becomes idle, it attempts to steal a task from the tail of another thread. This ensures that all available CPU cores remain productive and increase CPU utilization.

There are several studies that have explored the implementation of parallel sorting algorithms. In 1990, a parallel quicksort algorithm utilizing the Fetch-and-Add instruction was implemented on a Parallel Random-Access Machine (PRAM), achieving a speedup of 400 when sorting elements using 500 processors5. In 2008, Mishra et al.6 conducted an analysis and comparison of various sorting algorithms, including bubble sort, selection sort, insertion sort, merge sort, quicksort, and heap sort. Furthermore, the paper presented the time, space complexities, and stability of each algorithm. Ultimately, this paper demonstrated that the optimal sorting algorithm selection is contingent upon the data size, memory constraints, and the necessity of stability. This research serves as a valuable resource for comprehending the trade-offs inherent in different sorting strategies. Later, NG and Kakehi7 presented the LCP-MergeSort algorithm. The LCP concept is implemented to minimize character-wise comparisons and key accesses by leveraging the longest common prefixes (LCP) between the strings. Furthermore, there exists an implementation of parallel string radix sort8, which is a highly optimized implementation renowned for its exceptional cache efficiency and performance in string distribution. LCP-MergeSort enhances recursive merge sort by maintaining an average computational complexity of . In 2013, Tsigas and Zhang3 introduced PQuicksort, a block-based parallel sorting algorithm that partitions data concurrently and neutralizes the blocks. This method achieved a speedup of 11 on a 32-core processor. Bingmann et al.9 developed parallel K-way LCP-merge on NUMA architectures in 2017. Given their and K-way LCP-merge implementations, this constructs a fast parallel external memory string sorter for short strings. Its throughput is likely to exceed the available I/O bandwidth. Gebili et al. proposed the Parallel Multidimensional Lookahead Sorting algorithm, designed to run efficiently on General-Purpose Graphics Processing Units (GPUs)10. Subsequently, Cortis et al. introduced the Parallelised Modified Quickselect algorithm, which is conceptually similar to quicksort11. Marowka12 evaluated the performance of the parallel quicksort algorithm. Marowka’s work introduced a vector-based quicksort that integrates both process-based and thread-based execution models. In 2021, a parallel multi-deque sorting algorithm was proposed13, utilizing a block-based partitioning strategy. Each thread maintains its own deque to store the boundary indices of blocks. The algorithm performs partitioning by simultaneously traversing the array from both ends—left and right—toward the center. In 2022, the parallel sorting algorithm named In-place Parallel Super Scalar Samplesort (IPSo) was proposed14. The iHmas algorithm, which performs partitioning and sorting in parallel using MPI, was further optimized by Helal and Shaheen15 to enhance its performance. In addition, Mubarak et al.16 introduced preprocessing techniques that can be applied prior to sorting, significantly reducing time complexity. Later, the Dual Parallel Partition Sorting algorithm was introduced17, which partitions data using two threads during the initial stage. It incorporates the Multi-Swap algorithm for merging, achieving a speedup of up to 6.82 on a 4-core Intel i7-6770 processor. More recently, in 2023, a novel parallel sorting algorithm named Parallel MPDMSort was proposed18. It employs a block-based parallel partitioning approach, followed by the Dual-Deque Merge algorithm to efficiently merge the partitioned data. This method achieved a speedup of 13.81 on an Intel Xeon Gold 6142 processor. The performance of sorting algorithms has been significantly enhanced through various techniques and innovations. Gupta et al.19 proposed a GPU-based sorting algorithm leveraging a sorted matrix structure, achieving a fivefold speedup relative to the CUDA Thrust library20. Mankowitz et al.21 explored the use of deep reinforcement learning to improve sorting algorithm performance. Kobus et al.22 optimized segmented sorting on GPUs, achieving speedups ranging from 1.26 to 1.35 on four GPUs. Vásquez et al.23 proposed the Parallel Block-InsertionSort algorithm, also implemented using OpenMP. Each block is sorted independently, and a multiway merge algorithm from the libstdc++ parallel mode is used to combine the results. This approach yielded a speedup of up to 17 on a 32-core processor. Yang et al.24 developed thSort, a parallel bitonic sorting algorithm tailored for the FT-M7032 CPU-DSP heterogeneous processor, achieving a speedup of up to 2.15 compared to std::sort. Takase et al.25 presented the H-P Sort algorithm implemented on GPU, demonstrating a 3.45 speedup over its original version. Alhabboub et al.26 introduced a parallel large-scale quicksort algorithm using the OpenMP library, capable of sorting millions of elements in approximately 16,339 milliseconds. Dang’ana and Jacobsen27 presented FractalSort, a novel compressed radix-sorting architecture for FPGA that effectively addresses the exponential histogram growth and data skew issues inherent in high-precision sorting. By employing a tree-based recursive circuit with optimized merge, fractal swap, and fractal filter algorithms, the design guarantees bounded memory usage and eliminates the traditional need for data bucketing and pre-processing. Consequently, FractalSort achieves unprecedented bandwidth efficiency and sorting speeds, outperforming state-of-the-art CPU, GPU, and FPGA algorithms by up to 6, 3, and 2.5, respectively, across massive datasets ranging from 4GB to 2TB Recently, Ala’anzy et al.28 proposed GPU-based parallelization of merge sort, quicksort, bubble sort, radix top-k selection sort, and slow sort. The experiments demonstrate that radix sort implemented on GPUs achieves a speedup of approximately 50 on 10 million random data. Additionally, quicksort, merge sort, bubble sort, and slow sort exhibit speedups of 97, 103, 17, and 18.6, respectively.

OpenMP

OpenMP1 is an Application Programming Interface (API) designed to support multi-platform shared memory multiprocessing programming in C, C++, and Fortran. It provides a portable, scalable model that gives programmers a simple and flexible interface for developing parallel applications. OpenMP is crucial for parallelizing code in shared memory systems, which is essential for optimizing the performance of parallel sorting algorithms. Various OpenMP scheduling types, such as static and dynamic scheduling, can be employed to manage the distribution of tasks among threads efficiently. In this paper, we utilize OpenMP to parallelize the block-based partitioning and sorting processes using OpenMP for and OpenMP task directives. Moreover, we implement OpenMP scheduling to control the data which is partitioned in parallel.

Dual-Deque Merge algorithm

In this paper, Parallel N-Deque Partitioning algorithm which uses block-based concept is implemented to our sorting algorithm. After parallel partitioning is completed within each block, the partitioned data must be relocated to their correct positions. Note that, data elements less than the pivot are moved to its left, while those greater than the pivot are moved to its right. Therefore, a merging algorithm is integrated into the sorting algorithm to ensure correct data arrangement. The Dual-Deque Merge algorithm18 is employed to merge data based on the boundaries of a dual-deque. The concept of this algorithm is shown in Algorithm 1.

The left boundary of deqg and right boundary of deql are assigned to ii and jj, respectively (Lines 6-7, Algorithm 1). The data in arr[ii] and arr[jj] are exchanged until ii or jj is out of bound of that block. Then, ii is increased and jj is decreased (Lines 8-12, Algorithm 1). N-Deque partitioning algorithm

N-Deque data structure is implemented to push/store the boundaries and pop new boundaries of data for partitioning. The number of deques can be set when parallel partitioning is executed. This algorithm begins by exchanging the pivot (arr[p]) at its position (p) and data in the leftmost position (arr[L]) (Line 1, Algorithm 3). It is illustrated in Fig. 1 (Lines 1-7). Next, N-Deque data structures NDeq[T] are allocated to store the boundaries of blocks where T is the number of deques as shown in Fig. 1 (Lines 3-6) (Line 3, Algorithm 3). Then, two deques, deql and deqg in Fig. 1 (Lines 8-9), are created to store the boundaries of values less than or equal to the pivot an greater than the pivot, respectively, (Line 3, algorithm 3). Moreover, the N-Deque Partitioning algorithm with directive is executed to partition the blocks of data in parallel (Lines 4-5,Algorithm 3). In each block, the boundaries are popped from NDeq[t] in the critical section (Lines 7-8, Algorithm 3), where t is the thread number of the N-Deque. After that, the Lomuto’s partitioning algorithm is executed using the boundaries from the N-deque (Lines 10-16, Algorithm 3). Note that, CompareStr (Algorithm 4) is used to compare strings in this algorithm. When that block is partitioned, the boundaries of that block are pushed to the dual-deque deql and deqg in the critical section (Lines 20-21, Algorithm 3). Next, Dual-Deque Merge algorithm18 (Line 28, Algorithm 3) is the sequential algorithm which merges the data that is less than or equal to the pivot and larger than the pivot using a dual-deque data structure. It returns dltemp and dgtemp, which are the left and rightmost unpartitioned positions, respectively. Block size and sorting cutoff size

NPDMSTRSort is a parallel block-based sorting algorithm. It partitions the data in each block using an N-deque data structure. Therefore, we can declare different block sizes of the ParallelNPDMSTRPartition algorithm. Block size (BSz) is a very important parameter in the parallel partition part. This algorithm executes BlockInit() to initialize boundaries to the deques (Line 3, Algorithm 3). Only left and right boundaries, which are equal to Block size, are assigned and pushed to NDeq[T]. When the block size is larger, the number of data in parallel partitioning is larger than the lower block size.

Sorting cutoff size (C) is the parameter which is compared to the partition size (Line 1, Algorithm 2). If C is greater than that partition, sequential sorting algorithm is executed in parallel using (Lines 2-3, Algorithm 2). Otherwise, the N-Deque Partitioning algorithm is executed repeatedly. When C is larger, the sequential sorting algorithm will sort the large size of data. The choice of C is empirical and serves as a heuristic to balance the trade-off between parallel throughput and sequential execution efficiency. Block size and sorting cutoff size can affect the run time of the parallel sorting algorithm.

The optimal run time values of NPDMSTRSort on an Intel Xeon Gold 6142 machine for sorting random data of sizes 2, 5, 10, 20, and 50 million are 0.16, 0.26, 0.31, 0.54, and 1.19 seconds, respectively. Its run time when sorting random 50 million data is less than the MWSort, TBBSort, LCP-MergeSort, and std::sort. The best run time values for NPDMSTRSort on Intel Xeon Gold 6142 machine, for nearly sorted data of sizes 2, 5, 10, 20, and 50 million are 0.16, 0.18, 0.20, 0.32, and 0.81 seconds, respectively. Note that, our NPDMSTRSort’s run time values are only greater than BQSort.

The experimental results demonstrate a significant performance flip between two architectures. While AkibaRadixSort maintains an edge on the Apple M2, NPDMSTRSort consistently outperforms it on the Intel Xeon Gold 6142. This performance divergence highlights the critical role of memory subsystem design in the scalability of parallel sorting. On the Intel Xeon Gold 6142, the superiority of NPDMSTRSort and standard libraries like BQSort, and MWSort over AkibaRadixSort suggests a bottleneck related to the Memory Wall and the complexities of Non-Uniform Memory Access (NUMA).

Moreover, it can be noticed that the best run-time value corresponds to BSz values of 1/64 and 1/32. The block size parameter is the primary focus in the experiments. The run-time of NPDMSTRSort reveals slight variations across different block sizes.

In this algorithm, its cache misses and branch load misses grow linearly and are greater than the others are caused by the auxiliary array. Most of the branch load misses and cache misses values of NPDMSTRSort are less than MWSort. However, when sorting the largest data, cache misses of NPDMSTRSort are greater than MWSort. Conclusion

In this paper, we propose an optimized parallel N-Deque partition dual-deque merge string sorting algorithm. This algorithm integrates N-Deque partitioning, dual-deque merge, and sequential sorting techniques to enhance performance and efficiency. Speedup and efficiency are the metrics used to measure the performance of the parallel algorithm. The optimal speedup of NPDMSTRSort can reach up to 5.25 on an 8-core Apple M2 machine with a data size of 20 million. The parameters of NPDMSTRSort include B = 1/64, which is the smallest value of B. The sorting cutoff C is set to 1. The number of N-Deques is equal to the number of cores. OpenMP scheduling is configured as static scheduling with a chunk size of 1. Block size, cutoff size, number of deques, and OpenMP scheduling are the parameters that significantly affect the performance of the algorithm.

Despite the significant performance gains achieved by the proposed algorithm on multi-core processors, several open research challenges remain. A critical gap in the current literature is the adaptation of complex partition and merge techniques for heterogeneous computing environments, such as GPU-accelerated architectures or distributed computing clusters, which are essential for handling extreme-scale datasets.

For future work, we aim to further minimize the memory footprint by investigating a block-based two-way iterative scanning approach. Instead of maintaining auxiliary deques, this method would process data blocks from both the leftmost and rightmost boundaries, converging toward the center of the array. This would transition the algorithm toward a truly in-place partitioning mechanism, effectively reducing the auxiliary space complexity to near-constant overhead. Finally, we plan to evolve the current static cutoff into an adaptive hybrid selection framework on heterogeneous systems. This would enable the algorithm to dynamically select the most efficient sorting kernel based on specific data characteristics, such as the Longest Common Prefix (LCP) depth and alphabet distribution.
