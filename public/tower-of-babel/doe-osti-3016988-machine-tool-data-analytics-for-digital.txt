 ABSTRACT

The primary objective of this project is to improve machining process performance using in-process
machining data from the machine tool controller and external sensors. Advances in the Industrial Internet
of Things (IIoT) enable monitoring of machines using controller data. Examples of the data provided by a
controller include execution status of the controller, part count, block of code being executed, door status,
tool position, the spindle and axis load, etc. MTConnect and OPC-UA are the two common protocols for
capturing machine information. In this collaboration, methods for retrieving the machine controller data
from selected machine tool controls and making these data accessible in different subsystems (such as
digital twins and machine maintenance portals, etc.) will be developed and tested. In addition, analytics to
improve machining process performance (by increasing productivity and reducing downtime) will be
developed.

1. SUMMARY

Phase I of the project successfully established the foundations for data collection from multiple machines.
The success was demonstrated by application of the collected data to monitor machine productivity at the
part level by identifying partial and full runs of the cycle in a discrete part manufacturing scenario. In phase
II, external high-speed vibration sensor was introduced, and the analytics was further advanced from the
part-level to the toolpath level.

1.1 MULTIPLE SENSING MODALITY

A vibration sensor was identified, procured and installed to the stationary casing of the spindle illustrated
in Fig. 1(a). For safety a separate insulated electrical box was prepared to house the PLC which is
responsible for collecting and controlling the sensor acquisition start and stop. The insulated electrical box
is illustrated in Fig. 1(b).

Figure 1. Vibration sensor installed. (a) Sensor placement on spindle (b) Insulated electrical box housing the PLC with
logic for sensor data acquisition and coordination with controller PC.

Three data modalities in total became available for advanced data analytics. The three data modalities
include:
(1) Machine data served by standard industrial protocols like MTConnect and OPC-UA
(2) External vibration sensor
(3) Part program

The additional sensor installed is an independent sensing system and was therefore required to be integrated
with the machine data to provide synchronized. The synchronization was performed using a common clock
for timestamping the Machine data and vibration sensor data.
The analytics developed in phase I can summarize part-cycles as a complete or a partial run and the time
taken to complete the runs using only the machine data. In comparison, the analytics in phase II uses all
three data modalities to provide a detailed breakdown by G-code and toolpath. A comparison of the
advancement in analytics is illustrated in Fig. 2 using only Machine data and external vibration sensor.

Figure 2. Comparison of analytics details in phase I which used only machine data to advanced analytics in phase II which
uses machine data and vibration data. (a) Phase I analytics (b) Phase II analytics which shows breakdown of vibration data
distribution and time-to-complete breakdown by blocks in the G-code.

It was noted that when using only machine data augmented with external sensor data, certain machines,
which have slow sampling rate for the machine data in the sub-10 Hz range, up to 90% of the machine
information can be lost due to high-speed movements. This limit is noted by the illustration in Fig. 2(b)
where duration and vibration information is organized based on only the sampled G-code. This limitation
significantly reduces the resolution of information available.

1.2 METHOD AND APPLICATION FOR TOOLPATH LEVEL ANALYTICS

A method was developed to address the limited sampling rate of machine controller data by incorporating
contextual information from the part program. The method enables reconstruction of toolpath-resolved
process information even when controller data is sampled at sub-10 Hz, where a large fraction of executed
G-code blocks may not be directly observed.
The method was evaluated using experimental data collected from two CNC machines – a Makino a51nx
and a DMU 60 eVo – executing a common test geometry (Fig. 3(a)(i)) and corresponding toolpath (Fig.
3(a)(ii)). Raw machine controller data, external vibration data, and the part program were combined to
organize process information in the context of the programmed toolpath. As shown in Fig. 3(b)(i), the raw
machine data is sparse and non-uniform, providing limited visibility into toolpath execution.

a representative test geometry and (ii) the corresponding programmed toolpath executed on a Makino a51nx and a DMU

Application of the developed method produces an upsampled, toolpath-level representation that
substantially increases the effective resolution of the available data. Figures 3(b)(ii) and 3(b)(iii) illustrate
the ability to visualize duration and spindle load continuously along the toolpath, while Fig. 3(b)(iv)
demonstrates localization of feedrate override behavior on a different toolpath segment. Compared to the
raw controller data, the resulting representations provide a consistent and detailed view of machining
behavior along the programmed path.
These results demonstrate that the developed method advances analytics from part-level summaries to
localized toolpath-level insights, supporting improved process understanding and diagnostics in machining
operations.

1.3 REAL-TIME DATA MONITORING IN A MODERNIZED GUI

In Phase II of the project, the data collection developed using Scytec DataXchange were demonstrated
through a modernized, real-time graphical user interface (GUI) designed for shopfloor use. The GUI was
implemented to visualize live machine data streamed simultaneously from multiple CNC machines,
enabling intuitive monitoring of machine status and operational context in a single environment.
The demonstration included four CNC machines – DMU 60 eVo, Makino a51nx, HAAS TM-0P, and a
FANUC-controlled concrete base machine – represented within a virtual shopfloor layout illustrated in Fig.
4. Each machine was displayed with real-time color-coded operating status (running, idle, or stopped),
along with key execution information such as the active program and current G-code line (Fig. 4(a)). This
provided immediate situational awareness at the shopfloor level.

In addition to high-level monitoring, the GUI supported machine-level inspection through interactive
selection. Upon selecting a machine, users could access short-term historical trends of critical variables
such as spindle load and axis position, enabling rapid assessment of machine behavior during operation
(Fig. 4(b)). The system was deployed on a touchscreen interface, allowing shopfloor personnel to interact
directly with the visualization without specialized training (Fig. 4(c)).

2. CONCLUSIONS

Overall, this demonstration showed that real-time machine data served through Scytec DataXchange can
be effectively integrated into an intuitive, modern GUI to enhance operational visibility, support decision-
making on the shop floor, and provide a foundation for future integration of advanced analytics developed
in this project.
