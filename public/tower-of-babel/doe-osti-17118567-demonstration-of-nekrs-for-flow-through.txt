 Summary

The U.S. DOE’s NEAMS program is developing the next generation of tools to accelerate the
design and deployment of advanced nuclear power. Their thermal hydraulics capabilities include
SAM, Pronghorn, and NekRS for system scale modeling, mid length scale modeling, and lower
length scale computational fluid dynamics respectively. To fully realize the capabilities of these
tools, the program seeks to use the higher-fidelity tool NekRS to inform models implemented in the
lower-fidelity tools SAM and Pronghorn. The objective of this work is to develop and demonstrate
the process for using NekRS to generate a large quantity of high-fidelity data which can be used to
as such.

 For the purposes of demonstration, a case of flow through a contraction was selected due to
its combination of relative simplicity and relevance to current efforts in Pronghorn and the nuclear
industry in general. A set of python routines was developed to setup, run, and post process an
arbitrary number of NekRS simulations on a high performance computing cluster. These routines
were used to setup a series of 32 cases distributed logarithmically across the range of Reynolds
number from 10k to 200k. The k – τ Reynolds-average Navier-Stokes turbulence model in NekRS
was used for these simulations. As a result of these simulations, a correlation was developed for the
minor loss coefficient for the contraction, which can be implemented in Pronghorn or SAM. The
mean squared error for the correlation was 2.75(10−6 ). Future work will expand the python routines
to explore additional parameters, such as the geometry of the correlation, and will demonstrate the
capability for other applications relevant to advanced nuclear power.

1 Introduction

The U.S. Department of Energy’s Nuclear Energy Advanced Modeling and Simulation (NEAMS)
Program is developing the next generation of computational tools to accelerate the design and
deployment of advanced nuclear power. Their thermal hydraulics (TH) tools include the system
scale code SAM [1], the engineering scale code Pronghorn [2], and the lower length scale code NekRS
[3]. SAM is a modern system-level modeling and simulation tool for advanced non-light water
reactor safety analysis. Pronghorn is a multidimensional coarse-mesh, thermal hydraulics code for
advanced reactors, serving as the meso-scale analysis tool between lumped parameter system models
and fine-scale computational fluid dynamics (CFD). Both Pronghorn and SAM are based on the
Multiphysics Object-Oriented Simulation Environment (MOOSE) [4].

 NekRS is an open source GPU-accelerated high-fidelity CFD code originally developed as the
GPU version of Nek5000 by both the DOE’s Exascale Computing Project and NEAMS. NekRS and
its predecessor Nek5000 are based on the spectral element method, which combines the high-order
accuracy of spectral methods with the flexibility of the finite element method. NekRS has been
demonstrated to be highly scalable on the leadership-class computers Aurora and Frontier at the
Argonne Leadership Computing Facility and Oak Ridge Leader Ship Computing Facility, respectively.
It is a general fluid dynamics solver used in the nuclear field for both light water reactors (LWRs)
and non-LWRs. It is also used extensively outside the nuclear field. It includes direct numerical
simulation (DNS), large eddy simulation (LES), Reynolds-averaged Navier-Stokes (RANS), and
hybrid LES/RANS turbulence models.

 The objective of this work is to develop and demonstrate the process for using NekRS to
generate a relatively large quantity of high-fidelity data that can be used to inform lower-fidelity,
faster running models implemented in SAM or Pronghorn. In order to achieve this, a series of
python routines were developed to automate the configuration, running, and post processing of an
arbitrary number of cases on a high performance computing (HPC) cluster. These routines can be
easily adapted to control nearly any parameter in NekRS. Latin hypercube sampling was integrated
to automate the exploration of a parameter space. The produced data is then ideal for integration
in to the other NEAMS TH tools, either directly or via a machine learning interface. In the future,
more advanced post processing will be automated with the multiphysics tool Cardinal [5], which
couples NekRS with MOOSE.

 A relatively simple case of flow through a contraction was chosen for this demonstration. This
is aligned with current modeling priorities in Pronghorn and is ideal for a demonstration because
the individual problem size can be minimized. This allowed the demonstration to be executed
on modest-sized cluster consisting of 16 A100 Nvidia GPUs. This also allowed for a considerably
faster debugging process as the typical queue time of an HPC system was not a factor. While the
developed routines are capable of fully integrating with NekRS, they will require integration with
the job submission environment on any HPC system that is used. They are currently configured
to interact with a SLURM environment, but could be easily expanded and generalized. A RANS
turbulence model was used for most of this work to keep the computational cost down. The use of an
LES model was initially investigated, but would have required significantly more resources and time.
LES would be ideal for a larger effort in the future with deployment on leadership computing where
the scalability of NekRS can be truly leveraged. Additionally, the hybrid LES/RANS model could

be used as a compromise for large problems where fidelity is an absolute requirement. However, this
also demonstrates what can be accomplished without access to leadership computing resources.

2 Model

To demonstrate the use of NekRS to generate data for Pronghorn and SAM, a relatively simple
problem of flow through a contraction was simulated. This was chosen because it can be well
represented by a loss coefficient model which is readily implemented in either of the higher length-
scale codes, the CFD simulation requirements are relatively modest, and because flow contractions
are ubiquitous in nuclear systems. This allows for a large number of different cases to be simulated
quickly, effectively leading to a bespoke correlation for the problem.

 A diagram of a general flow contraction is shown in Fig. 2.1 with the inlet on the left and
the outlet on the right. The contraction is fully characterized by specifying the pipe diameter, the
contraction diameter, and the contraction length. For the current work, only a single instance of
the geometry was simulated, with dimensions provided in Tab. 2.1. Note that the geometry is
non-dimensionalized with the pipe diameter as the chosen length scale. The remaining dimensions
are chosen to achieve fully developed flow before the contraction and to allow the flow to return to
a fully developed condition after.

 The mesh used for the RANS simulations is shown in Fig. 2.2. Only a quarter of the domain was
meshed, as evident in Fig. 2.2(b). Because a RANS model does not resolve turbulent fluctuations,
symmetry boundaries can be used to simplify the domain and reduce the size of the problem to 1/4
of the full domain. However, because no wall-model is used, a thin element layer next to the wall is
necessary to resolve the near-wall behavior. This resulted in a modest total element count for this
mesh of 6136.

velocity and the RANS scalars are recycled from downstream and the inlet condition is updated at
every time step. Velocity is rescaled to ensure a consistent flow rate, while no scaling is applied

2.2 LES Model

A case using the LES model was included as a benchmark as RANS models can have difficulty with
the flow separation that is typical behind a flow contraction. Generally, even if a RANS model may
struggle with specific flow details, it can still give good results for integral quantities such as overall
pressure drop. The LES model in NekRS uses a high-pass filter approach [?]. The dimensionless
governing equations for mass and momentum, including the high-pass filter, are

 The mesh used for LES is shown in Fig. 2.3. Unlike a RANS model, LES resolves turbulent

significant increase in required resolution throughout the flow domain, the element count for the
LES mesh is 125k.

3 Results

Four initial cases were run at Reynolds numbers of 10k, 50k, 100k and 200k to get an understanding
of the behavior of the model. Normalized pressure profiles along the flow are presented in Fig. 3.1 for
the four initial cases. The expected behavior is observed. Pressure drops quickly in the contraction
due to the Bernoulli effect, but recovers more slowly. The momentum of the flow prevents the
effective flow area from expanding immediately, resulting locally higher velocity and keeping the
pressure low. This effect is exacerbated at higher Reynolds numbers where the flow takes considerably
longer to return to a fully developed condition.

3.2 Data Generation

Following the setup and investigation described above, the actual data generation required relatively
little time and effort. The python script that was written to automate the data generation uses a
template case directory with the required NekRS case files An additional 32 cases were generated
using the Latin hypercube random sampling algorithm in python. The generated samples were
distributed uniformly over a logarithmic space. The lower bound on the Reynolds number was
chosen to ensure the flow is well into the turbulent regime. The upper bound was chosen to cover a
wide range of conditions, while keeping the problem tractable. At these higher Reynolds numbers,
LES would be quite expensive computationally. We note that the single LES case required 20x
more computational time than the single RANS case, at the higher end of Re = 200k, this factor is
likely much higher.

 Loss coefficients which can be incorporated into 1D models in Pronghorn or SAM model were
calculated. This are shown as a function of Reynolds number in Fig. 3.4 and the tabulated values are
available in Tab. A.2 in Appendix A. From the plotted data, we can observe that the loss coefficient
appears parabolic on a semi-log plot. This implies a relationship of the form

4 Conclusions

A set of routines were developed for configuring, running, and post processing a large number of
similar cases. These have been demonstrated for generating data for flow in a contraction across a
range of Reynolds numbers. The generated data is well fit by a traditional correlation which can
be implemented directly into SAM or Pronghorn. The observed error between the curve fit and
the generated data is practically negligible. This implies that implementing this model into SAM
or Pronghorn would yield a pressure drop model of comparable accuracy to a full RANS model.
Finally, the data is available for integration in to a machine learning model, which may be necessary
if additional parameters are explored.

 Future work will focus on expanding the setup and post processing capabilities as well as further
demonstrations at higher fidelity. Integration with a meshing script will allow additional parameters
to be tested, including the contraction diameter and thickness. This will further support current
modeling efforts in Pronghorn. By integrating Cardinal, the data output will be more flexible.
Specifically, Cardinal can produce exodus files which can be read directly by any of the MOOSE
tools. This will allow for tighter integration of additional data, e.g. eddy viscosity, which can be
used to develop GNN or transformer based data-driven models in SAM. We will also leverage the
higher-fidelity turbulence models and leadership computing to investigate other scenarios relevant
to advanced nuclear reactors. This may include heat transfer in liquid metal cooled wire wrapped
bundles, molten salt flows through complex geometries, or multiphase flows.
