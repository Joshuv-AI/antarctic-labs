When Agents Go Quiet: Output Generation Capacity and Format-Cost Separation for LLM Document Synthesis
Justice Owusu Agyemang, Michael Agyare, Miriam Kobbinah, Nathaniel Agbugblah, Prosper Addo, [4pt] Sperix Labs VIA Cybersecurity Lab, KNUST GCTU, Ghana NCA, Ghana

Abstract
LLM-powered coding agents suffer from a poorly understood failure mode we term output stalling : the agent silently produces empty responses when attempting to generate large, format-heavy documents. We present a theoretical framework that explains and prevents this failure through three contributions. (1) We introduce Output Generation Capacity (OGC), a formal measure of an agent’s effective ability to produce output given its current context state—distinct from and empirically smaller than the raw context window. (2) We prove a Format-Cost Separation Theorem showing that deferred template rendering is always at least as token-efficient as direct generation for any format with overhead multiplier μ f > 1 \mu_{f}>1 , and derive tight bounds on the savings. (3) We formalize Adaptive Strategy Selection , a decision framework that maps the ratio of estimated output cost to available OGC into an optimal generation strategy (direct, chunked, or deferred). We validate the theory through controlled experiments across three models (Claude 3.5 Sonnet, GPT-4o, Llama 3.1 70B), four document types, and an ablation study isolating each component’s contribution. Deferred rendering reduces LLM generation tokens by 48–72% across all conditions and eliminates output stalling entirely. We instantiate the framework as Gen-Pilot , an open-source MCP server, demonstrating that the theory translates directly into a practical tool.

2
Motivating Incident

We briefly describe the real-world failure that motivated our
theoretical investigation.

An LLM coding agent (Claude 3.5 Sonnet, 200K context) evaluated nine
research papers, accumulating
{\sim}90{,}000
tokens of analysis.
When asked to generate a formatted Word document via python-docx,
the agent produced
five consecutive empty responses
,
burning
{\sim}50{,}000
tokens with zero output. Switching to
LaTeX with chunked generation succeeded immediately, producing
a 14-page PDF in one attempt using
{\sim}10{,}000
tokens.

Key observation:
The failure was not due to insufficient
context window (200K tokens available) but to the agent attempting
to generate
{\sim}10{,}000
output tokens in a single turn while

{\sim}90{,}000
tokens of context were already occupied. The

effective
generation capacity at 45% context occupancy
was insufficient for the output size, but no mechanism existed to
detect this before the attempt.
Note that newer models with larger context windows (e.g., 1M tokens)
shift the absolute occupancy at which stalling occurs, but do not
eliminate it—the OGC framework (Section
3
) shows that
degradation is a function of the
occupancy ratio

o/C
, not
the absolute context size.

This incident raises three questions that the remainder of this
paper addresses formally:
(1) How does effective generation capacity relate to context
occupancy?
(2) Can we reduce the token cost of formatted output without
reducing content?
(3) Given limited capacity, what generation strategy minimizes
failure risk?

3
Output Generation Capacity

We formalize the concept of
Output Generation Capacity

(OGC)—the maximum number of tokens an LLM can reliably generate
in a single turn given its current context state.

3.1
Formal Definition

Definition 1

(Context State)
.

A
context state

\sigma=(C,o)
consists of the model’s
context limit
C
(maximum tokens) and the current context
occupancy
o
(tokens consumed by conversation history, system
prompts, and tool results), where
0\leq o\leq C
.

Definition 2

(Raw Headroom)
.

The
raw headroom

H(\sigma)=C-o
is the maximum
number of tokens the model could theoretically generate.

Definition 3

(Output Generation Capacity)
.

The
Output Generation Capacity

\mathrm{OGC}(\sigma)
is the
maximum number of tokens the model can
reliably
generate
(with probability
\geq 1-\epsilon
for a reliability threshold

\epsilon
) in a single turn at context state
\sigma
.
Formally:

\mathrm{OGC}(\sigma)=\alpha\!\left(\frac{o}{C}\right)\cdot H(\sigma)

(1)

where
\alpha:[0,1]\to[0,1]
is a
capacity degradation
function
satisfying
\alpha(0)=1
,
\alpha(1)=0
, and

\alpha
is monotonically non-increasing.

The key insight is that
\mathrm{OGC}(\sigma)<H(\sigma)
in general:
effective generation capacity degrades faster than raw headroom
as context fills. This is because:
(a) the model must allocate attention across all context tokens,
reducing effective compute per output token
[
27
,
16
]
;
(b) internal generation limits (e.g.,
max_tokens
) may
be smaller than the context window; and
(c) the model’s internal planning for long outputs may fail when
it cannot “see” enough empty space ahead.

Format-Cost Separation

We now formalize the decomposition of generation cost into content
and format components, and prove that
format-cost separation
via deferred rendering
is provably more efficient than direct generation.

4.1
Token Cost Model

Definition 4

(Format Multiplier)
.

For a document with raw content
c
(plain text) and target format

f
, the
format multiplier

\mu_{f}\geq 1
is the ratio:

\mu_{f}=\frac{|c|_{f}}{|c|_{\text{raw}}}

(3)

where
|c|_{f}
denotes the token count of content
c
expressed in
format
f
, and
|c|_{\text{raw}}
is the token count of the raw
content.

Definition 5

(Generation Cost)
.

The
generation cost
of producing content
c
in format
f

s
is:

\displaystyle T_{\mathrm{direct}}(c,f)

\displaystyle=|c|_{\text{raw}}\cdot\mu_{f}

\displaystyle T_{\mathrm{defer}}(c,f)

\displaystyle=|c|_{\text{data}}+T_{\text{tpl}}

(5)

\displaystyle T_{\mathrm{chunk}}(c,f,k)

\displaystyle=\sum_{i=1}^{k}|c_{i}|_{\text{raw}}\cdot\mu_{f}+T_{\text{asm}}

where
|c|_{\text{data}}
is the token count of
c
as structured
data (typically JSON),
T_{\text{tpl}}
is the one-time cost of
template registration,
k
is the number of chunks,
c_{i}
is the

i

T_{\text{asm}}
is the assembly overhead.

4.2
The Format-Cost Separation Theorem

Theorem 1

(Format-Cost Separation Bound)
.

For any content
c
with
|c|_{\text{raw}}>0
and any format
f

with multiplier
\mu_{f}>1
:

T_{\mathrm{defer}}(c,f)\leq T_{\mathrm{direct}}(c,f)\;\;\text{iff}\\
|c|_{\text{data}}+T_{\text{tpl}}\leq|c|_{\text{raw}}\cdot\mu_{f}

(7)

Moreover, the
token savings ratio
is:

\rho=1-\frac{T_{\mathrm{defer}}}{T_{\mathrm{direct}}}=1-\frac{|c|_{\text{data}}+T_{\text{tpl}}}{|c|_{\text{raw}}\cdot\mu_{f}}

(8)

Proof.

By Definition
5
,
T_{\mathrm{defer}}\leq T_{\mathrm{direct}}
is equivalent to

|c|_{\text{data}}+T_{\text{tpl}}\leq|c|_{\text{raw}}\cdot\mu_{f}
.
Since structured data (JSON) contains only content without format
markup, we have
|c|_{\text{data}}\leq|c|_{\text{raw}}\cdot\mu_{\text{json}}

where
\mu_{\text{json}}\approx 1.15
. For
T_{\text{tpl}}

amortized over documents of non-trivial size (
{>}500
tokens),
the condition holds whenever
\mu_{f}>\mu_{\text{json}}+T_{\text{tpl}}/|c|_{\text{raw}}
.
For typical documents (
|c|_{\text{raw}}\geq 2000
,
T_{\text{tpl}}\leq 1500
),
this requires
\mu_{f}>1.15+0.75\approx 1.20
—satisfied by
HTML,
L
a
T
e
X
, and python-docx.
The savings ratio follows by algebraic substitution.
∎

Corollary 1

(Asymptotic Savings)
.

As document size grows (
|c|_{\text{raw}}\to\infty
), the template
cost is amortized and:

\rho\to 1-\frac{\mu_{\text{json}}}{\mu_{f}}

(9)

For python-docx (
\mu_{f}=1.40
):
\rho\to 17.9\%
.
For
L
a
T
e
X
(
\mu_{f}=1.30
):
\rho\to 11.5\%
.
In practice, savings are larger because deferred rendering allows
the LLM to produce
compressed
structured data (omitting
redundant phrasing the template re-introduces), yielding

|c|_{\text{data}}<|c|_{\text{raw}}
.

5
Adaptive Strategy Selection

Given the OGC model and the format-cost decomposition, we now
formalize the strategy selection problem.

5.1
Feasibility and Strategy Space

Definition 6

(Generation Feasibility)
.

A generation task
(c,f)
is
feasible
under strategy
s

at context state
\sigma
if the generation cost under
s
does
not exceed the OGC:

T_{s}(c,f)\leq\mathrm{OGC}_{\mathrm{eff}}(\sigma)

(10)

where
\mathrm{OGC}_{\mathrm{eff}}(\sigma)=\alpha(o/C)\cdot(C-o)
from
Definition
3
.

Definition 7

(Strategy Space)
.

The strategy space
\mathcal{S}=\{\text{direct},\text{chunk}_{k},\text{defer}\}
consists of:

•

direct
: generate the full formatted output in one turn

•

\text{chunk}_{k}
: split generation into
k
sequential turns

•

defer
: generate structured data + template separately

Theorem 2

(Strategy Dominance)
.

The strategies satisfy a
feasibility dominance
ordering:

\mathcal{F}_{\text{defer}}\supseteq\mathcal{F}_{\text{chunk}}\supseteq\mathcal{F}_{\text{direct}}

(11)

where
\mathcal{F}_{s}
is the set of
(c,f,\sigma)
triples for
which strategy
s
is feasible. That is, any task feasible under
direct generation is also feasible under chunked and deferred, but
not vice versa.

Proof.

For direct: feasible iff
|c|_{\text{raw}}\cdot\mu_{f}\leq\mathrm{OGC}_{\mathrm{eff}}(\sigma)
.

For chunk
k
: each chunk must satisfy

|c_{i}|_{\text{raw}}\cdot\mu_{f}\leq\mathrm{OGC}_{\mathrm{eff}}(\sigma_{i})
where

\sigma_{i}
is the context state at chunk
i
. Since

|c_{i}|\leq|c|/k
, chunking reduces the per-turn requirement,
making more tasks feasible.

For defer: the LLM generates only
|c|_{\text{data}}
tokens
(plus a one-time
T_{\text{tpl}}
), with template rendering
consuming zero LLM tokens. Since
|c|_{\text{data}}\leq|c|_{\text{raw}}\cdot\mu_{f}
(strict inequality for all

\mu_{f}>1
), defer is feasible whenever direct is, plus
additional tasks where
|c|_{\text{data}}\leq\mathrm{OGC}_{\mathrm{eff}}
but

|c|_{\text{raw}}\cdot\mu_{f}>\mathrm{OGC}_{\mathrm{eff}}
.
∎

5.2
Optimal Strategy Selection

Given the dominance ordering, the optimal strategy minimizes
cost while remaining feasible:

s^{*}=\arg\min_{s\in\mathcal{S}}T_{s}(c,f)\quad\text{s.t.}\quad T_{s}(c,f)\leq\mathrm{OGC}_{\mathrm{eff}}(\sigma)

(12)

In practice, we implement this as a decision cascade:

s^{*}=\begin{cases}\text{direct}&\text{if }T_{\mathrm{direct}}\leq\mathrm{OGC}_{\mathrm{eff}}\cdot\beta\\
\text{chunk}_{k}&\text{if }T_{\mathrm{direct}}/k\leq\mathrm{OGC}_{\mathrm{eff}}\cdot\beta\\
\text{defer}&\text{otherwise}\end{cases}

(13)

where
\beta\in(0,1)
is a
safety margin
(we use
\beta=0.67
,
requiring the estimated cost to be at most 67% of OGC to account
for estimation uncertainty). The cascade prefers simpler strategies
when feasible, falling back to more robust ones as capacity tightens.

6
Implementation

We instantiate the theoretical framework as
Gen-Pilot
, an
open-source MCP server
[
2
]
that exposes seven tools
organized into three layers corresponding to the three
theoretical contributions.

Layer 1 (Budget)
implements OGC estimation:

gp_estimate
computes
|c|_{f}=|c|_{\text{raw}}\cdot\mu_{f}

using the
cl100k_base
tokenizer
[
18
,
24
]
;

gp_budget
computes
\mathrm{OGC}_{\mathrm{eff}}(\sigma)
and returns the
strategy recommendation from Equation
13
.

Layer 2 (Planning)
implements adaptive strategy selection:

gp_plan
solves Equation
12
and returns an
ordered step sequence;

gp_replan
applies the dominance ordering
(Theorem
2
) to recover from failures by
descending the cascade.

Layer 3 (Rendering)
implements format-cost separation:

gp_register_template
stores Jinja2
[
22
]
templates;

gp_render
performs the
T_{\text{tpl}}=0
rendering step;

gp_list_templates
provides template discovery with
JSON Schema for each template’s expected data structure, enabling
agents to construct valid input without trial-and-error.

Recovery bounds.

The cascade in Equation
13
could in principle cycle
between chunked and deferred strategies indefinitely. The
implementation bounds recovery at three replans; beyond this,

gp_replan
returns an actionable error recommending context
compaction or scope reduction.

Security.

Templates are rendered inside Jinja2’s
SandboxedEnvironment
,
preventing server-side template injection. HTML templates enable
auto-escaping to prevent cross-site scripting when rendered output
is viewed in a browser. Template names are validated against path
traversal, directory separators, and null bytes.

The implementation integrates with
Resilient-Write

[
1
]

for atomic file writes. All state is persisted in

.gen_pilot/
(templates, plans, configuration) with
automatic garbage collection of stale plan files.
The package ships with four pre-built templates and a calibration
script for measuring
\mu_{f}
on new content types.
Format multipliers are configurable per-workspace via

.gen_pilot/config.json
, allowing calibrated overrides
to propagate consistently through budget estimation, planning, and
replanning.

is sufficient to prevent waste—by
detecting infeasibility
before
the attempt, it eliminates
the
{\sim}50{,}000
wasted tokens. However, it falls back to
chunked generation (60% success rate).

2.

Adding FCS
brings success to 100% and delivers
55% token savings, because deferred rendering operates well
within OGC even at high context occupancy.

3.

Adaptive selection
adds marginal benefit in this
high-pressure scenario (defer is always chosen), but matters at
lower occupancy where direct or chunked generation is cheaper
and equally reliable.

This demonstrates that OGC and FCS are the two
essential

contributions, while adaptive selection is an optimization that
matters across the full occupancy spectrum.

Discussion.
Three patterns emerge from Table
4
:

(1) Deferred rendering dominates across all conditions.

It achieves 100% success rate in every cell (60 out of 60 runs)
while reducing tokens by 48–72%. No other strategy achieves
universal success.

(2) Savings scale with format complexity.

Data reports (
\rho=72\%
) and API docs (
\rho=66\%
) benefit
most because their format-to-content ratio is highest (many tables,
structured fields, boilerplate headings). Meeting notes (
\rho=48\%
)
benefit least because Markdown has low format overhead (
\mu=1.05
),
so less is saved by separating format from content.

(3) The framework is model-agnostic.

Savings and success rates are remarkably consistent across Claude,
GPT-4o, and Llama 3.1. This validates that OGC and format-cost
separation are
properties of the generation task
, not of
any particular model.

8
Related Work

We situate our contributions at the intersection of tool-using
LLM agents, context management, structured generation, and
agent self-evaluation. To our knowledge, no prior work formalizes

generation-capacity planning
as a theoretical framework.

8.1
Tool-Using LLM Agents

Toolformer
[
23
]
demonstrated self-supervised
tool learning; ReAct
[
33
]
showed that interleaving
reasoning with actions improves task completion.
MRKL
[
15
]
proposed modular neuro-symbolic routing;
Gorilla
[
20
]
fine-tuned models for API call
accuracy; ToolLLM
[
21
]
scaled tool learning to
16,000+ APIs. These works address
which tool
to call
and
how
. Our framework addresses a complementary question:
given the agent’s capacity,
can
it generate the required
output, and if not,
what strategy
should it use?

8.2
Autonomous Agent Frameworks

LangChain
[
9
]
provides composable tool chains;
MetaGPT
[
11
]
assigns specialized roles in
multi-agent pipelines; SWE-agent
[
32
]
designs
agent-computer interfaces for software engineering;
AgentBench
[
17
]
benchmarks agents across
diverse environments. None include generation-capacity awareness.
When output exceeds effective OGC, these systems have no detection
or recovery mechanism. Our framework is composable—any
agent system can integrate OGC checking as a pre-generation step.

8.3
Context Window Management

Large context windows
[
3
]
mitigate but
do not eliminate context pressure.
Liu et al.
[
16
]
showed that models struggle with
information in the
middle
of long contexts, implying
effective capacity is smaller than nominal.
LongBench
[
6
]
benchmarks long-context tasks.
MemGPT
[
19
]
treats the LLM as an OS with
virtual memory; Xu et al.
[
31
]
combine retrieval
with long context. These manage
input
context. Our OGC
concept addresses
output
capacity—the ability to

generate
tokens given current context state, a distinct
and previously unformalized problem.

8.4
Structured and Constrained Generation

Outlines
[
29
]
uses finite-state machines
to guide token sampling; LMQL
[
7
]

provides a query language for constrained outputs;
SGLang
[
34
]
offers efficient structured
generation with parallelism. These constrain
individual
tokens
. Format-cost separation operates at the
document

level, selecting the generation strategy rather than constraining
the decoding process. The approaches are complementary:
constrained generation could enforce JSON schema compliance
within our deferred strategy.

8.5
LLM Failure Modes and Self-Evaluation

Hallucination—generating fluent but incorrect
content
[
13
,
12
]
—is
the most studied LLM failure mode. Output stalling is
fundamentally different: the model produces
no output
,
leaving no artifact for correction.
Kadavath et al.
[
14
]
showed models can
partially assess their knowledge boundaries;
Reflexion
[
25
]
enables verbal self-correction.
Our OGC framework extends self-evaluation from

knowledge
(“do I know this?”) to
capacity

(“can I express this?”)—a novel metacognitive dimension.

8.6
Tokenization and Cost Estimation

BPE tokenization
[
24
]
varies across model
families
[
8
,
26
]
, meaning format
multipliers are tokenizer-dependent. Code-optimized
models
[
10
]
may exhibit different
\mu_{f}
for
python-docx boilerplate. Our calibration methodology
(Section
4
) is designed to be re-run per deployment,
and the theoretical results (Theorem
1
,
Theorem
2
) hold for any
\mu_{f}>1
.

9
Limitations

OGC measurement.
The capacity degradation function

\alpha
(Figure
1
) is measured empirically and
may vary with prompt structure, system instructions, and
fine-tuning. A theoretical derivation of
\alpha
from attention
mechanics would strengthen the framework.

Context access.

Gen-Pilot
cannot directly read the
LLM’s token counter; all OGC estimates are approximate. Agent
platforms exposing
context_tokens_used()
would enable
exact OGC computation. As a consequence, the current
implementation approximates Equation
13
using
raw headroom ratios rather than the
\alpha
-degraded

\mathrm{OGC}_{\mathrm{eff}}
, since computing
\alpha
requires knowing the
true context occupancy.

Multiplier stability.
Format multipliers are measured
per-document-type and may shift with content characteristics
(e.g., code-heavy vs. prose-heavy text). Our calibration
script addresses this but requires manual re-measurement.

Template quality.
Deferred rendering is only as good
as the template. Complex layouts (multi-column, figures with
captions) require sophisticated templates that may themselves
be costly to generate. Pre-built template libraries and
JSON Schema–annotated variable declarations mitigate but do not
eliminate this concern.

Cascade termination.
The replan cascade
(Section
6
) is bounded at three iterations as a
practical safeguard. A formal analysis of convergence conditions
—when
no
strategy can succeed—would allow the bound to
be derived rather than chosen empirically.

Evaluation scale.
While we test three models and four
document types, the evaluation uses 5 runs per condition.
Larger-scale studies with more models, document types, and
occupancy levels would strengthen statistical claims.

10
Conclusion

We have presented a theoretical framework for understanding and
preventing output stalling in LLM coding agents, grounded in
three contributions:

1.

Output Generation Capacity (OGC)
—a formal
measure of effective generation capacity that degrades
non-linearly with context occupancy, explaining why agents
stall at context levels well below the nominal limit.

2.

Format-Cost Separation Theorem
—a provable
decomposition showing that deferred rendering eliminates format
tokens from LLM generation, with savings that grow with
format complexity (
\rho=48\text{--}72\%
empirically).

3.

Adaptive Strategy Selection
—a decision framework
with provable dominance ordering (
\text{defer}\succeq\text{chunk}\succeq\text{direct}
) that maps OGC to optimal
strategy.

Across three models, four document types, and 180 experimental
runs (60 per strategy), deferred rendering achieved

100% success rate
while reducing generation tokens by

48–72%
. The
ablation study shows that OGC and format-cost separation are each
independently essential, and that the framework is model-agnostic.

The broader implication is that LLM agents need

metacognitive tools
—not just tools that act on the world,
but tools that help agents reason about their own generation
capabilities. Output Generation Capacity formalizes a previously
implicit constraint; format-cost separation provides a principled
technique for working within that constraint. Together, they
transform output stalling from an invisible failure into a
preventable one.
