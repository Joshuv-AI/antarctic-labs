1.0 Introduction
1.1 Purpose
This document defines the software requirements for the sanitization of the IPC and or
the controller. The system is intended to manage part programs and associated data
(e.g. simulations, probing data) by capturing metadata, securely sanitizing files, logging
operations, backing up data to a defined path, deploying a user defined program to a
controller, and restoring part programs and associated data when required.

1.2 Scope
The Sanitization shall:

 • Capture all part programs and associated data.
 • Log file size, timestamps, file path and sanitization actions (before and after
 state).
 • Copy part programs to a user defined custom path.
 • The software shall keep three current backups
 • Securely sanitize (delete) part programs.
 • Deploy a user defined program to the controller after deletion.
 • Restore part programs and associated data from the custom path.

The software shall ensure traceability, logging, and verification of all operations.

1.3 Functional Requirements
The software shall scan the configured source directory for part programs associated
data.

The software shall capture the following part programs and associated data for each
file:

 • File name
 • Full file path
 • File size
 • Creation timestamp
 • Last modified timestamp
 • Location

The software shall store part programs and associated data in a structured log prior to
sanitization.

2.0 Logging and Audit Trail
2.1 Description
The software shall maintain a detailed audit log for all actions.

2.1.1 Functional Requirements
The software shall create a sanitization log for each execution session.
The log shall include:

 • Execution date and time
 • Initiating user
 • List of affected files
 • Pre-sanitization metadata
 • Post-sanitization status
 • Logs shall be stored in a persistent and retrievable format
 • Logs shall record success or failure for each file operation

3.0 Backup to Custom Path
3.1 Description
The software shall support copying part programs and associated data to a defined
storage path.
3.1.1 Functional Requirements
 • The software shall allow configuration of a custom backup path.
 • The software shall keep three backups, renaming each file folder and deleting
 the last.
 • The software shall validate accessibility of the custom path before copying files.
 • The software shall copy part programs and metadata to the custom path prior to
 deletion.
 • The software shall verify successful transfer of each file.
 • Copy operations shall be logged with:

 • Source path
 • Destination path
 • Timestamp
 • Status

4.0 Data Sanitization
4.1 Description
The system shall securely delete part programs and associated data after successful
backup.
4.1.1 Functional Requirements
 • The software shall securely delete selected part programs and associated data.
 • The software shall verify file removal after deletion.
 • The software shall log deletion confirmation or failure.
 • If backup fails, deletion shall not proceed (show message to user).

5.0 User Defined Program Deployment
5.1 Description
After successful sanitization, the software shall deploy a user defined program to the
controller.

5.1.1 Functional Requirements
 • The software shall transfer the user defined program to the controller after
 deletion of part programs and metadata.
 • The software shall verify successful transfer to the controller.
 • The software shall log deployment details including timestamp and status.

6.0 Restoration Capability
6.1 Description
The software shall support restoring part programs and associated data from the
custom path.

6.1.1 Functional Requirements
 • The software shall allow selection of part programs and associated data for
 restoration.
 • The software shall transfer selected files from the custom path to a specified
 target location.
 • The software shall verify file integrity after restoration.
 • The software shall log restoration actions and results.

7.0 Reliability Requirements
 • The software shall not delete files unless backup is verified.
 • The software shall provide error handling and recovery mechanisms.
 • The software shall maintain operation logs even in case of failure.

8.0 Performance Requirements
The software shall complete metadata capture and logging without significant
performance degradation.

9.0 Usability Requirements
The software shall provide a clear user interface for operation.

10.0 Verification and Acceptance Criteria
 • Successful capture of metadata for all files.
 • Verified backup prior to deletion.
 • Confirmed secure deletion.
 • Verified user defined program deployment.
 • Successful restoration from custom path.
 • Complete and auditable logs for all operations.
