ABSTRACT
Many modern CPUs that are available to the NNSA as mission computing resources support vector
instruction sets. Making good use of vector instructions, referred to as “vectorization”, is often
critical to getting the best performance from these CPUs. While other codes choose to rely on
compiler auto-vectorization, the SMASH shock physics code chooses to leverage APIs for explicit
vectorization. These APIs are similar to directly calling the CPU vendor’s vector intrinsics, with the
additional benefit of being vendor-agnostic. This document explains what the SIMD APIs are and
how to use them in developing SMASH.

1. SIMD CONCEPTS
Since the early days of Cray vector machines, computing hardware vendors have found it beneficial
to deliver hardware that provides vector instructions. These instructions direct the computing
hardware to apply the same operation to multiple data values at once. The computing hardware can
then be designed to execute those instructions using less time and with fewer transistors on the chip
than would otherwise be possible.

1.1.       Vector
In the context of SIMD programming, a vector is a set of multiple data values that are operated on
as a unit by the computing hardware. The number of data values in a vector is a fixed quantity,
usually a power of two. More fundamentally, computing hardware such as Intel CPUs support a
fixed vector size expressed in bits, such as Intel’s AVX-512 instruction set in which vectors are up to
512 bits in length. Physics codes typically use floating-point data values in which each value is 64
bits, so for AVX-512 that works out to 8 floating-point numbers in a vector. If instead the data
values are 32-bit integers, then one can operate on 16 such integers at a time using AVX-512
instructions. Many modern CPUs have dedicated vector registers, for example the Intel ZMM
registers which each hold 512 bits.

1.2. Lane
Once the CPU vector width in bits is known and a particular data type such as 64-bit floating point
numbers is chosen, then one can talk about the data values within a vector. In the AVX-512
example with 64-bit numbers, there are 8 vector “lanes”, each lane being a unique data value inside
the vector.

1.3. Mask
One key challenge in SIMD programming is that often we do not want all lanes to perform the same
operation. One common reason is that the number of data values input by the user is not a multiple
of the number of lanes available, so the last batch will process the remainder which is between 1 and
the maximum number of lanes. Another common reason is conditional logic, in which operations
should only be applied under certain conditions, and each lane may or may not satisfy the condition.
A mask, conceptually, is like a vector where each data value is a Boolean yes or no, indicating
whether or not an action should be taken by a given vector lane.
While some modern instruction sets represent a mask as an integer with one bit per lane, older
instruction sets implement a mask as a vector with the same number of bits as the floating-point
data and set all bits matching a certain data value to 1 or 0. For example, imagine a 128-bit vector
instruction set. This instruction set could operate on two 64-bit floating point values at once. If we
want an operation to only apply to the second value, the mask could be implemented as 128-bit
vector where the first 64 bits are 0 and the second 64 bits are 1.

1.4. Load and Store
Both SIMD and non-SIMD (“scalar”) CPU programming that processes large amounts of data
values involves copying data values from main memory to CPU registers and back. These operations
are called loading data from main memory to registers and storing register values back into main
memory. We use the term “vectorized load” to refer to loading multiple data values into a vector
register on the CPU, and similarly “vectorized store” for storing multiple data values from a vector

 7

register into main memory. Vectorized loads and stores benefit (in terms of speed) from being
contiguous and aligned. Contiguous means that the values in the vector register are loaded from
consecutive addresses in main memory, in other words the data values are contiguous in main
memory. Alignment means that the data values begin at an address which is a multiple of the vector
size. Informal experiments by the author indicate that vectorized loads and stores are the only way
to get close to the advertised memory bandwidth of an Intel CPU, “scalar” loads and stores by
comparison achieve only a fraction of memory bandwidth.

1.5. Gather and Scatter
Like the rationale for masks, the rationale for gather and scatter operations is that in some complex
algorithms, each SIMD lane would like to load a data value from a different address in memory and
the addresses are not contiguous or unique. A gather operation is a vector instruction which
performs the equivalent of many scalar loads, each at a different index or offset from some base
address. The gather operation takes a base address, a vector of integer offsets, and returns a vector
of data values which were loaded from those offsets. The scatter operation is the inverse of this,
taking a vector of data values and a vector of integer offsets and performing the equivalent of
several scalar stores.

1.6. Blend
Many non-vectorized algorithms make use of conditional statements, executing certain instructions
only if a certain condition is met. When attempting to vectorize those algorithms, one may find that
each SIMD lane may or may not meet the given condition. One of the only tools that vector
instruction sets provide us to deal with these scenarios is the blend operation. A blend operation is
given a mask and two vectors of data values. The result of a blend operation is a new vector of data
values, and for each lane the result value is either the value in that same lane in the first vector or the
second vector depending on whether the mask is on or off at that lane. Because of the limited tools
provided by vector instruction sets, first attempts to vectorize conditional code often result in
computing all possible code paths and then using blend operations to select the proper result value.
This can make vectorized code slower than scalar code depending on the variations in conditions
being satisfied or not at each lane.

2. API
The SMASH code heavily leverages the SIMD API provided in the INGEST library. The basic way
to bring this API into a piece of code is to load the header simd.hpp as follows:

#include <ingest/simd.hpp>

2.1. Vector of Floating Point Numbers
The SIMD API makes the assumption that most of the work being done is on 64-bit floating point
numbers. As such, it provides a type simd_double to represent a vector register filled with 64-bit
floating point values. On machines that support multiple vector widths, this will be the largest
supported vector width. C++ math operator overloads are provided for this type so that common
mathematical code looks the same as it would for the built-in type double. For example, the
following is valid code using our API:

simd_double solve_quadratic(
 simd_double a,
 simd_double b,
 simd_double c)
{
  return (-b + sqrt(b * b - 4.0 * a * c)) / (2.0 * a);
}

For the simple operation of setting all the lanes of the vector to the same floating-point value, there
is a function simd_dfill.

2.2. Counting and Accessing Lanes
The number of 64-bit floating point values that fit in the CPU’s largest supported vector width is
provided as a macro SIMD_WIDTH which expands to an integer literal. There is also a function to
get the single 64-bit floating point value in a given lane of the vector register. These two together are
especially useful when debugging SIMD code:

void print_vector(simd_double a)
{
  printf("There are %d lanes.\n", SIMD_WIDTH);
  for (int lane = 0; lane < SIMD_WIDTH; ++lane) {
 printf("Lane %d has value %g\n", lane, simd_dget(a, lane));
  }
}

Also useful when debugging is to detect whether a lane is on or off in a given mask, in order to only
print lanes which are actively participating in some computation:

void print_vector(simd_double a, simd_dmask mask)
{
  printf("There are %d lanes.\n", SIMD_WIDTH);
  for (int lane = 0; lane < SIMD_WIDTH; ++lane) {

2.3. Vectorizing a Loop
The usual application of these SIMD tools is to explicitly get the CPU to take advantage of
parallelism that we have in a software loop that we know has a very large number of data values.
There are several ways to translate loops into vector instructions, but the one shown here is the one
most often seen in the SMASH code and supporting libraries. All approaches to vectorizing loops
consist of two parts
 1. Process as many data values as possible in complete vectors
 2. Deal with the remainder of data values that do not fill one complete vector
Our approach combines these so that every vector “batch” of data values is processed using a mask
that indicates which lanes actually have corresponding data values to process. Since the data values
are contiguous in main memory, the active lanes will always be at the beginning of the vector. We
have a helper simd_first_n that creates a mask with the first N lanes active and the rest inactive.
For most iterations of this loop, the number of active lanes will be equal to SIMD_WIDTH (in
other words, all the lanes). The last iteration will have the number of lanes active be equal to the
remainder obtained from dividing the number of data values by the total number of lanes.
Below is an example of this loop vectorization for the common BLAS function “A X plus Y”:

void axpy(int n, double a, double const* x, double* y)
{
  for (int i = 0; i < n; i += 1) {
 double yval = y[i];
 double xval = x[i];
 yval = a * xval + yval;
    y[i] = yval;
  }
}

void axpy(int n, double a, double const* x, double* y)
{
  for (int i = 0; i < n; i += SIMD_WIDTH) {
 int active_lanes = n - i;
 if (SIMD_WIDTH < active_lanes) active_lanes = SIMD_WIDTH;
 simd_dmask mask = simd_first_n(active_lanes);
 simd_double yval = simd_dload(y + i, mask);
 simd_double xval = simd_dload(x + i, mask);
 yval = a * xval + yval;
 simd_dstore(yval, y + i, mask);
  }
}

2.4. Conditionals
As introduced in the section above on blend operations, there are limited tools available to vectorize
conditional code. In the INGEST SIMD API, the key function employed here is called
assign_where, which is inspired by the WHERE statement in the Fortran programming language.
It assigns to individual lanes of a vector of floating-point values based on whether a mask is on or
off in each lane.
Below is an example of how to use assign_where to vectorize code that has an if statement:

double compute_density(double mass, double volume)
{
  double density = mass / volume;
  if (volume == 0.0) density = 0.0;
  return density;
}

simd_double compute_density(simd_double mass, simd_double volume)
{
  simd_double density = mass / volume;
  assign_where(volume == 0.0, density, 0.0);
  return density;
}

Sometimes it is useful to manage masks as Boolean variables; their type is simd_dmask in the
current SIMD API. As mentioned in the section on blends, when vectorizing conditional code, one
may want to take extra effort to ensure that very expensive operations are not executed at all in the
special case that none of the SIMD lanes have to execute the operation. Here is an example of a
highly accurate method of computing sin(x)/x in all regimes, in which the vectorized version takes
care not to execute the expensive sin(x) function if none of the SIMD lanes need it. It uses the
function simd_any, which returns true if and only if the given mask is on for any lane:

double sin_x_over_x(double x)
{
  double y = fabs(x);
  if (y < 1.4901161193847656e-08) {
    return 1.0;
  } else if (y < 1.22070312500000000e-04) {
    return 1.0 - ((y * y) / (6.0));
  } else {
 return sin(y) / y;
  }
}

simd_double sin_x_over_x(simd_double x)
{
  simd_double y = fabs(x);
  simd_double result = simd_dfill(1.0);
  assign_where(y >= 1.4901161193847656e-08, result, 1.0 - ((y * y) / (6.0)));
  simd_dmask cond = (y >= 1.22070312500000000e-04);
  if (simd_any(cond)) {
 assign_where(cond, result, sin(y) / y);

 return result;

2.5. Iterative Solves
Another difficult scenario to vectorize is the scenario of trying to implement iterative numerical
methods, where the number of iterations depends on the data values being operated on. Most loops
can be expressed as an infinite loop with conditionals, so we build on the conditional tools in the
previous section. The basic approach is as follows: continue iterating while any of the lanes have not
converged, and use conditional assignment to only advance the lanes that have not converged. Here
is an example using the classic Newton’s method algorithm for inverting a differentiable function.
The tools in this example take the forward function and its first derivative as C function pointers:

#include <ingest/simd.hpp>

double newton_solve(
 double (*f)(double),
 double (*dfdx)(double),
 double x,
 double y,
 double tol)
{
  bool not_converged = true;
  while (not_converged) {
 double y2 = f(x);
 double dy2dx = dfdx(x);
 not_converged = fabs(y2 - y) > tol;
 if (not_converged) x = x - y2 / dy2dx;
  }
  return x;
}

simd_double newton_solve(
 simd_double (*f)(simd_double),
 simd_double (*dfdx)(simd_double),
 simd_double x,
 simd_double y,
 double tol)
{
  simd_dmask not_converged = simd_dtrue();
  while (simd_any(not_converged)) {
 simd_double y2 = f(x);
 simd_double dy2dx = dfdx(x);
 not_converged = fabs(y2 - y) > tol;
 assign_where(not_converged, x, x - y2 / dy2dx);
  }
  return x;
}
