 ABSTRACT

Space domain awareness (SDA) requires a reproducible way to reduce millions of orbital records to a tractable set
of object-time intervals for analyst review. We present a Two-Line Element (TLE)-driven screening pipeline that
converts cached Space-Track histories into propagated states, orbital features, detector scores, transition residuals,
calibration products, and traceable candidate-transition tables. The pipeline uses TLE-native Simplified General Per-
turbations 4 (SGP4) propagation and provides a Lawrence Livermore National Laboratory (LLNL) Space Situational
Awareness Python (SSAPy) execution path for scriptable, high-performance-computing workflows. The detector suite
combines long short-term memory (LSTM) reconstruction error, window-feature Isolation Forest scores, a determin-
istic consecutive-TLE residual rule, and a transition-residual Isolation Forest. The public-event calibration inventory
contains 31 source windows from five objects; overlap merging yields 30 non-overlapping evaluation intervals. The
sensitive transition tier matches 30 of 30 intervals (Wilson 95% confidence interval: 88.6–100%) and produces zero
hits in five passive geodetic control windows, defined here as windows centered on non-maneuvering geodetic satellites
used as negative controls for commanded propulsion. The frozen high-confidence residual tier matches 27 of 30 inter-
vals (90.0%; 74.4–96.5%) and flags 13/965 non-propulsive calibration-control object-windows (1.35%; 0.79–2.29%).
We then apply the frozen tier to 14 catalog windows spanning 28–32 days. The application processes 26,586,023
TLE rows in 405,729 object-windows with zero object-level failures and retains 177,114 candidate-transition rows
across 58,635 flagged object-windows. De-duplication across overlapping catalog windows leaves 176,962 unique
candidate-transition timestamps. These results establish an auditable catalog-triage workflow; they do not constitute
held-out maneuver validation or maneuver confirmation.

 1. INTRODUCTION

Space domain awareness (SDA) analysts must distinguish operationally relevant orbital changes from routine catalog
variation across archives that contain millions of records. Catalog growth, debris-generating events, conjunction risk,
and routine spacecraft operations all increase this screening burden. Kessler and Cour-Palais identified the collision-
cascade risk, subsequent studies quantified debris growth, and the current European Space Agency environment report
documents continued increases in cataloged objects, orbital mass, and cross-sectional area [1, 2, 3]. The practical
question is narrower than maneuver reconstruction: which object-time intervals contain changes large enough to
justify follow-on orbit determination, sensor tasking, or analyst review?
Optical surveys, machine-learning tracklet extraction, resident-space-object classification, and self-supervised or-
bit modeling address adjacent portions of the SDA problem [4, 5, 6, 7, 8]. Recent Advanced Maui Optical and
Space Surveillance Technologies (AMOS) studies also examine transformer and convolutional backbones, action-free
inverse-reinforcement-learning similarity metrics, uncertainty-aware rapid propagation, maneuver determination, and
post-maneuver uncorrelated-track correlation [9, 10, 11, 12, 13]. These methods do not remove the need for a repro-
ducible first-pass screen over broad TLE archives. Two-Line Elements (TLEs) remain compact and widely available
through Space-Track, but they are mean-element products designed for Simplified General Perturbations 4 (SGP4)
rather than definitive state estimates or burn reconstructions [14, 15, 16]. We therefore define an anomaly as an un-
usual catalog transition, not as proof of a commanded maneuver.
The contribution is an end-to-end screening and evidence pipeline rather than a new propagator, neural architecture,
or maneuver-estimation algorithm. It couples TLE ingestion, propagation, orbital-feature generation, unsupervised
diagnostics, consecutive-TLE residual scoring, public-event matching, catalog-scale accounting, and analyst-facing

reports. Every retained candidate carries the source TLEs, state frame, residual components, operating thresholds, and
run provenance needed to reconstruct its origin.
Lawrence Livermore National Laboratory’s (LLNL’s) Space Situational Awareness Python (SSAPy) provides
the orbit, propagation, time, coordinate-frame, and observation-model infrastructure needed to extend this
screen beyond the TLE-native problem [17, 18]. The present implementation constructs TLE orbits with
ssapy.orbit.Orbit.fromTLETuple, propagates them with ssapy.propagator.SGP4Propagator, and evaluates
states with ssapy.compute.rv. The companion SSAPy Toolkit supplies time-grid and visualization utilities. This
interface preserves a path from direct SGP4 screening to richer force models, sensor geometry, and uncertainty-aware
batch analysis on high-performance-computing (HPC) systems.
We make three quantified contributions. First, we implement an auditable TLE-to-candidate-event pipeline with in-
put and implementation hashes, software versions, coordinate frames, and artifact manifests. Second, we compare
sequence-model diagnostics with transition-residual detectors on 30 non-overlapping public-event evaluation inter-
vals and 965 non-propulsive calibration-control object-windows. Third, we apply the frozen high-confidence tier to
26,586,023 TLE rows in 405,729 catalog object-windows and measure candidate volume, cadence dependence, prior-
class separation, failure rate, and compute cost. The analysis uses public, unclassified TLE and event/schedule data
only; it does not include the classified-domain validation proposed in the submitted abstract. Section 2 defines the
pipeline, Sections 3–5 describe the data, propagation, and sequence diagnostics, Section 6 reports detector calibration,
Sections 7–9 present catalog, compute, and reporting results, and Sections 10–11 state the limitations and conclusions.

 2. PROBLEM FORMULATION AND PIPELINE ARCHITECTURE

For an object identified by its North American Aerospace Defense Command (NORAD) catalog number, the screen
tests whether an ordered TLE history contains unusual state transitions. Let T = {T1 , . . . , TN } denote the TLE se-
quence over a specified interval. The propagation operator P maps each TLE to one or more state samples,

                                                (ri, j , vi, j ) = P(Ti ,ti, j ),                                    (1)

where r and v are position and velocity and ti, j is a sample epoch. The feature map converts each state to a vector xk
of orbital quantities. For the sequence-model diagnostics, a sliding-window operator constructs

                                            Xm = [xm , xm+1 , . . . , xm+w−1 ],                                      (2)

where w is the configured sample count. The long short-term memory (LSTM) autoencoder and window-feature
Isolation Forest assign scores to each Xm . The catalog detector instead propagates Ti to the epoch of Ti+1 and compares
the predicted state with the state represented by Ti+1 . A threshold crossing identifies a maneuver-like TLE transition
for review. It does not solve for burn time, direction, duration, or magnitude.
The Python modules under amos pipeline implement the eight stages in Table 1. The Space-Track ingest path
records covered date ranges in a cache manifest, requests only uncovered ranges, divides catalog requests into one-
day chunks, and appends only previously unseen TLE pairs. Repeating a covered request therefore leaves the cache
unchanged unless its manifest is deliberately refreshed. Each pipeline run writes source-linked data products, plots,
model warnings, metrics, a manifest, and a human-readable summary. This structure makes each detection timestamp
traceable through the source TLE pair, propagated states, feature values, detector score, threshold, and event-matching
result.
Figure 1 summarizes the ingest stage. The display cases, calibration runs, and catalog application read the same cached
TLE products. Downstream tables retain the NORAD identifier, source TLE lines, and TLE epochs so that no detector
score becomes detached from its orbital input.

 4. PROPAGATION, FEATURES, AND DETECTOR DEFINITIONS

The display-case diagnostics propagate each TLE for one day at 12 h cadence with SGP4, while a sep-
arate 1 min ephemeris supports smooth trajectory rendering without changing detector cadence. The
catalog screen does not construct these dense arcs; it evaluates consecutive TLE updates directly.
The direct path parses each TLE with sgp4.api.Satrec.twoline2rv and evaluates the state with
Satrec.sgp4. The SSAPy path uses Orbit.fromTLETuple, SGP4Propagator, and ssapy.compute.rv;
ssapy toolkit.time functions.get times supplies the common sample grid [17, 18]. Direct SGP4 states are
labeled True Equator Mean Equinox (TEME), and SSAPy states are labeled Geocentric Celestial Reference Frame
(GCRF).
From each propagated state, the feature stage computes radius, speed, specific orbital energy, specific angular mo-
mentum, inclination, eccentricity, semi-major axis, orbital period, and first differences. The display-case pipeline
normalizes these channels per run and forms overlapping four-sample windows with a one-sample stride. A detector
window is therefore defined by sample count rather than fixed elapsed time. Because one-day propagation arcs from
successive TLEs overlap and the combined rows are sorted by epoch, the elapsed span of a four-sample window varies
with TLE cadence.
Public sources provide sparse event intervals rather than dense labels, and their timing precision differs by object
and event class. We use the LSTM reconstruction channel and window-feature Isolation Forest as sequence-model
diagnostics. The deterministic consecutive-TLE residual rule and transition-residual Isolation Forest form the catalog-
screening stream. Figure 2 illustrates the normalized feature matrix and four-sample windows used by the sequence-
model diagnostics; the transition-residual path is defined separately below.
The TensorFlow/Keras reconstruction model contains an encoder LSTM, a repeated latent representation, a decoder
LSTM, and a time-distributed dense output layer [19]. It trains on all normalized windows from a display case
because no externally labeled nominal training subset exists. High reconstruction error therefore means that a window
is poorly represented by the dominant within-case distribution; it is not an independently trained maneuver classifier.
Early stopping, learning-rate reduction, and gradient clipping stabilize training on the small display-case datasets.
Table 3 defines the detector scores and operating points used in the remainder of the paper. The two window-based
diagnostics score normalized feature windows. The transition stream scores adjacent TLE pairs and estimates each
residual channel’s center and scale within the same object-window using the median and 1.4826 times the median
absolute deviation (MAD), with a standard-deviation fallback. This object-relative normalization supports cross-
regime screening but makes the score distribution dependent on TLE count and cadence.

 6. RETROSPECTIVE CALIBRATION AND DETECTOR SELECTION

Table 6 reports detector behavior after the 31 source windows are merged into 30 non-overlapping evaluation in-
tervals. The LSTM and window-feature Isolation Forest diagnostics match 13/30 and 16/30 intervals. Their fixed
percentile and contamination settings also force 146 and 145 candidate timestamps, respectively, into the five passive-
control windows. The sensitive transition tier matches 30/30 intervals and 0/5 passive windows, but it flags 631/965
non-propulsive calibration controls (65.4%). The transition-residual Isolation Forest matches 29/30 intervals and 0/5
passive windows. The frozen high-confidence residual tier matches 27/30 intervals and flags 13/965 non-propulsive
controls (1.35%). Wilson intervals quantify binomial counting uncertainty only; they do not correct repeated measure-
ments from the same object or the optimism introduced by threshold selection on the same data.
The aggregate 27/30 result is not uniformly distributed across objects or event classes. Table 7 shows that ISS supplies
25/30 evaluation intervals and 24/27 high-confidence matches. By event label, the high-confidence tier matches 17/17
reboost intervals, 7/8 combined collision-avoidance/reboost intervals, 1/3 collision-avoidance-only intervals, and 2/2
station-keeping intervals. The non-ISS and collision-avoidance-only strata are too small to support population-level
recall claims. Machine-readable object and event-label stratifications accompany the paper.
Figure 8 summarizes the operating-point trade. We retain the sensitive transition tier as a discovery tier because it
matches all 30 evaluation intervals. We use the high-confidence residual tier for catalog statistics because it reduces the
non-propulsive calibration-control detection fraction from 631/965 to 13/965 while retaining 27/30 interval matches.
Both values are resubstitution statistics.

 9. REPORTING PRODUCTS

The reporting stage preserves the evidence needed to inspect or reproduce a candidate. Each run records the configura-
tion, source and truth-input hashes, implementation hashes, Git revision and dirty state, Python and package versions,
coordinate frame, propagation method, artifact paths, and artifact hashes. Candidate tables retain the source TLE pair
and residual components. Display-case runs also write an optional Earth-centered three-dimensional trajectory artifact
from the plot-only ephemeris; this visualization supports contextual review and does not enter any detector score.
The retained artifacts separate sensitive discovery output, high-confidence catalog output, passive-control checks, and
display-case diagnostics without requiring an additional summary graphic.

 10. DISCUSSION AND FUTURE WORK

10.1 Disposition of submitted-abstract objectives
The final implementation satisfies the submitted abstract’s unclassified software objectives. It provides incremen-
tal, idempotent Space-Track ingest for cache-covered date ranges; NORAD-based filtering; TLE-native SGP4 and
SSAPy SGP4 propagation paths; radius, speed, specific-energy, angular-momentum, inclination, eccentricity, semi-
major-axis, and period features; normalized sliding windows; LSTM reconstruction and Isolation Forest diagnostics;
transition-residual screening; comma-separated-value (CSV) reports with feature-level context; anomaly-score plots;
and optional three-dimensional trajectory artifacts. The report also supplies detector, threshold, window-size, cadence,
propagation-backend, control, catalog-scale, and compute comparisons.

 14

The evidence scope is narrower than the submitted validation plan. The study uses public, unclassified TLEs, pub-
lic event or schedule windows, and non-propulsive controls; it contains no classified-domain validation. The event
windows do not provide orbit-determination-derived maneuver epochs, directions, durations, or ∆v values. The vi-
sual products support qualitative inspection, but the study does not include a blinded or structured analyst-review
experiment. The results therefore replace the abstract’s preliminary operational-validation language with retrospective
public-event calibration and catalog-triage burden measurements.
The results support a bounded claim: consecutive-TLE residuals can reduce a 26.6-million-row archive to a traceable
candidate set while preserving a frozen operating point and explicit control accounting. Within the retrospective cali-
bration, the sensitive tier matches 30/30 evaluation intervals and 0/5 passive geodetic windows. The high-confidence
tier matches 27/30 intervals and flags 13/965 non-propulsive calibration-control object-windows. These values justify
a two-tier review workflow in the present dataset—sensitive discovery followed by lower-burden catalog triage—but
they do not estimate performance on unseen maneuvers.
Four limitations control interpretation. First, threshold selection and evaluation use the same calibration data. Second,
ISS contributes 25/30 evaluation intervals, while Fermi/GLAST, Suomi NPP, and Sentinel-1A contribute one interval
each. Third, source timing ranges from public burn times to broad event intervals and scheduled station-keeping
windows. Fourth, a passive or non-propulsive label constrains commanded-maneuver interpretation but does not
eliminate drag, attitude-related effects, catalog-estimation changes, or TLE fit artifacts. Wilson intervals describe
binomial counting uncertainty and do not remove these dependencies.
Catalog scale does not compensate for sparse truth. The prior-class ordering—29.83% flagged for expected ma-
neuvering, 18.64% for plausible maneuvering, 4.93% for unknown or not expected, and 0/62 passive controls—is
consistent with a useful triage signal. However, flag fraction also rises strongly with TLE count, from 0% at three
TLEs to 22.8% at 101–200 TLEs. Exposure, object class, orbit regime, and within-window normalization are there-
fore confounded. The 177,114 retained candidate-transition rows must also be distinguished from the 176,962 unique
candidate-transition timestamps created after cross-window de-duplication.
The propagation comparison isolates a separate reproducibility issue. Direct SGP4 and SSAPy agree to 0.002–0.006
m position RMS in common GCRF coordinates, yet the ISS LSTM match count changes under millimeter-level
perturbations because percentile ranking determines its anomaly labels. State agreement is therefore necessary but in-
sufficient for detector equivalence. Future reproducibility tests should compare candidate identities and event matches
in addition to row counts and state residuals.
The next evaluation should freeze code and thresholds before collecting new truth. A pre-registered set should separate
objects as well as event intervals and should report results by collision avoidance, reboost, north–south station keeping,
and east–west station keeping. Detector development should then address cadence-normalized residuals, clustering of
adjacent transition rows into event-level candidates, and regime-specific controls. Where tracking observations and
covariances are available, follow-on orbit determination should test whether a candidate is dynamically consistent
with a maneuver. An indexed TLE store and object-parallel SSAPy execution can support that evaluation at scale, but
additional compute cannot substitute for independent truth.

 11. CONCLUSION

We present an auditable TLE anomaly-screening pipeline that links each candidate to its source TLE pair, coordinate
frame, propagated states, residual components, detector thresholds, software environment, and artifact hashes. Four
display cases containing 502 TLEs, 1,506 propagated state rows, and 1,490 feature windows exercise the sequence-
model and reporting path. The transition calibration adds 31 public source windows that merge to 30 non-overlapping
evaluation intervals, five passive geodetic windows, and 965 non-propulsive control object-windows.
The sensitive transition tier matches 30/30 evaluation intervals and 0/5 passive geodetic windows. The frozen high-
confidence residual tier matches 27/30 intervals and flags 13/965 non-propulsive calibration controls (1.35%; Wil-
son 95% confidence interval: 0.79–2.29%). Applied without threshold changes, it screens 26,586,023 TLE rows in
405,729 object-windows with zero object-level failures. The output contains 177,114 candidate-transition rows across
58,635 flagged object-windows and 176,962 unique candidate-transition timestamps after de-duplication.
The measured screening cost is 60.09 summed CPU h, with medians of 0.509 s per object-window and 0.00771 s per
TLE row, excluding network transfer, truth matching, and rendering. The pipeline is therefore computationally prac-

 15

tical for catalog triage, but its scientific validity remains bounded by retrospective threshold selection, ISS-dominated
truth, and cadence-dependent scores. The next required result is prospective, pre-registered evaluation on new objects
and event classes. Until then, the 176,962 outputs remain maneuver-like TLE transitions for review, not maneuver
confirmations.
