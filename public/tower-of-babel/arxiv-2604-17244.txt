DORA Explorer: Improving the Exploration Ability of LLMs Without Training
Priya Gurjar, Md Farhan Ishmam, Kenneth Marino

Abstract
Despite the rapid progress, LLMs for sequential decision-making ( i.e. LLM agents) still struggle to produce diverse outputs. This leads to insufficient exploration, convergence to sub-optimal solutions, and becoming stuck in loops. Such limitations can be problematic in environments that require active exploration to gather information and make decisions. Sampling methods such as temperature scaling introduce token-level randomness but fail to produce enough diversity at the sequence level. We analyze LLM exploration in the classic Multi-Armed Bandit (MAB) setting and the Text Adventure Learning Environment Suite (TALES). We find that current decoding strategies and prompting methods like Chain-of-Thought and Tree-of-Thought are insufficient for robust exploration. To address this, we introduce DORA Explorer (Diversity-Oriented Ranking of Actions), a training-free framework for improving exploration in LLM agents. DORA generates diverse action candidates, scores them using token log-probabilities, and selects actions using a tunable exploration parameter. DORA achieves UCB-competitive performance on MAB and consistent gains across TALES, e.g. , improving Qwen2.5-7B’s performance from 29.2% to 45.5% in TextWorld. Our project is available at: https://dora-explore.github.io/ .



1
Introduction

The strong reasoning capabilities of auto-regressive LLMs have led to their widespread adoption as decision-making agents across diverse domains, including recommendation systems
(
34
)
, scientific discovery
(
21
)
, game-playing
(
3
)
, healthcare
(
7
)
, and robotics
(
14
)
. Despite the great zero-shot capabilities of LLM agents on these tasks
(
12
)
, the auto-regressive nature of most language models introduces a new problem:
exploration
.
Exploration is a fundamental issue in decision-making problems and classical reinforcement learning (RL). In a new environment, the agent often operates under partial information and must balance exploration to acquire knowledge with exploitation to maximize reward or goal completion.
Exploration enables agents to gather information about unknown states, avoid suboptimal local policies, and discover high-reward behaviors that are not immediately apparent.

Despite the importance, exploration is an area where LLM agents struggle
(
15
;
26
)
. In environments with text interfaces, LLM agents use their language output space to produce domain-specific actions in that environment. For example, in a text adventure game, an agent might output “move forward” which can then be interpreted by the environment to move the player character forward. While this translation allows for LLMs to work zero-shot
(
12
)
, the text-based nature of this action space means that to properly explore, LLM agents must sample diverse
sequences
of tokens which comprise the action. Unfortunately, as seen in narrative generation
(
20
)
, sampling diverse sequences
is extremely challenging and LLMs continue to generate high-likelihood and uncreative sequences. In the context of LLM agents, this often results in repetitive or high-confidence action patterns
(
15
)
.
Temperature sampling is a common strategy to increase diversity by introducing stochasticity in the distribution of the output tokens. However, a sequence of such tokens need not represent a novel text; indeed, recent empirical studies by
20
suggest that temperature (often cited as a ’creativity parameter’) has only a weak correlation with novelty in narrative generation. Furthermore,
23
found that increasing sampling temperature also reduces task accuracy compared to deterministic decoding.

In this work, we introduce DORA Explorer (Diversity-Oriented Ranking of Actions), a training-free inference time framework designed to improve exploration in LLM-based agents, visualized in Figure
1
.
While prior approaches have attempted to improve LLM agent exploration using pure sampling
(
6
)
, pure prompting
(
31
)
or through controlled exploration
(
28
)
, our approach uses aspects of all three approaches to explicitly control the exploration/exploitation tradeoff, generate a variety of diverse actions, and sample actions based on the level of exploration through an exploration parameter
\lambda
.
LLMs tend to favor a narrow set of familiar responses over other plausible alternatives
(
33
)
; however, when explicitly prompted to generate multiple candidates, they can help recover some of this latent diversity
(
33
)
. DORA leverages this property for different candidate action generation. For sampling these action candidates in proportion to the desired level of exploration
\lambda
,
we use a combination of sequence-level metrics, mean log prob
(
16
)
and variance of log probability
(
8
)
, which reflect the exploratory intent of the action better.

Importantly, DORA is modular and plug-and-play: it can be seamlessly integrated into existing LLM pipelines without additional training, environment-specific tuning, or architectural changes. We demonstrate its effectiveness across both Multi-Armed Bandit (MAB) settings and the Text Adventure Learning Environment Suite (TALES), where it consistently improves performance by enabling exploration. DORA achieves UCB-competitive performance on MAB and consistent gains across the TALES environments.

, generates candidate actions, scores each one, and samples based on the derived
\lambda

2
Related Work

We can broadly categorize four approaches to controlling and improving exploration in LLM agent problems: sampling-based methods, prompting-based methods, controlled sampling, and learning-based approaches. DORA Explorer draws on aspects of these first three categories, creating an LLM agent framework that can explicitly control the level of exploration and reliably sample diverse actions without additional training.

The first category of methods is

sampling-based decoding strategies
for LLMs.
Top-
k
sampling restricts generation to the
k
most probable tokens
(
6
)
, top-
p
(nucleus) sampling
(
10
)
selects the smallest set of tokens whose cumulative probability exceeds a threshold
p

(
10
)
, and min-
p
sampling truncates low-probability continuations relative to the model’s highest-probability token
(
18
)
. These methods are designed to improve fluency, coherence, diversity, and repetition control in open-ended generation.
22
shows that, in LLM-based problem solving on multiple-choice question answering (MCQA) tasks, different sampling strategies exhibit minimal performance difference in the temperature range
[0,1]
. For higher temperatures (
>1
), generation quality degrades significantly, leading to incoherent outputs and a steady drop in accuracy.
20
observe only a weak positive correlation between novelty and temperature, and a moderately negative correlation
between coherence and temperature.
Our approach separates the processes of generating candidates and sampling them to ensure that we have highly diverse but also correct actions, which can also be explicitly controlled through our exploration parameter
\lambda
.

The second type of approach is
prompting-based
, which includes both frameworks for explicitly increasing the diversity or randomness of LLM-generated outputs and general frameworks for agents in embodied settings to explore more effectively.
15
evaluate 32 prompt designs to study LLM exploration in a Multi-Armed Bandit setting. They find that no matter the prompts used, LLMs do not explore robustly, even for this fairly simple canonical exploration setting.
Most relevant to us is
33
, which introduces Verbalized Sampling (VS), a simple prompting technique for generating many diverse output sequences to allow for more diverse outputs (e.g., “Generate 5 jokes about coffee and their corresponding
probabilities”). One step of DORA uses a similar technique, but in the context of generating multiple possible actions before scoring and sampling (see §
4.1
).
Chain-of-Thought (CoT) prompting
30
encourages step-by-step reasoning, while Tree-of-Thought (ToT)
31
extends this to structured search over multiple reasoning paths. While these methods improve reasoning and planning, they do not explicitly address exploration under uncertainty and often rely on carefully designed prompts or additional control mechanisms. We compare these approaches to DORA in our experiments and find that they underperform DORA.

The third type of approach is
controlled exploration
as exemplified in
28
. In this paper, the authors identify a tradeoff between high-temperature sampling to produce diverse outputs and low-temperature sampling to ensure that outputs are not incorrect (e.g., not sampling incorrect mathematical expressions). They introduce a method that dynamically switches between greedy and high-temperature sampling using a learned risk classifier. Our method similarly controls generation between greedy and exploratory action sampling to ensure agents can both properly explore and reach the goal in an environment. However,
28
requires training a model-specific classifier and relies on the fact that they use verifiable tasks (in their case, mathematical reasoning). In contrast, DORA requires no additional training and is agnostic to the task and environment.

Other works have explored improving LLM exploration via algorithmic guidance and training.
19
study in-context exploration of LLMs in bandit settings and propose incorporating classical exploration algorithms (e.g., UCB) into LLM decision-making. While these methods demonstrate that structured exploration signals can significantly improve LLM performance, they rely on explicit access to algorithm-derived statistics or additional training, which may limit applicability.
Similarly, other training-based approaches, such as
27
, learn to explore better by explicitly training models to explore and adapt their behavior on new tasks. However, this too requires additional training.

3
Preliminaries

3.1
Problem Formulation

We model the multi-step decision-making task as an episodic Partially Observable Markov Decision Process (POMDP), defined by the 7-tuple
\langle\mathcal{S},\mathcal{A},\mathcal{O},\mathbb{T},\mathbb{T}_{0},\mathbb{O},R\rangle
. At step
t
, the agent receives the observation
o_{t}\in\mathcal{O}
, where
o_{t}\sim\mathbb{O}(\cdot\mid s_{t})
, for latent state
s_{t}\in\mathcal{S}
, selects an action
a_{t}\in\mathcal{A}
, and receives reward
r_{t}=R(s_{t},a_{t})
. The environment then transitions as
s_{t+1}\in\mathbb{T}(\cdot\mid s_{t},a_{t})
with
\mathbb{T}_{0}
as the initial state distribution. Since
s_{t}
is unobserved, the agent relies on the interaction history
h_{t}=\{(o_{i},a_{i},r_{i})\}_{i=1}^{n}
, acting under the history-conditioned autoregressive policy
\pi(a\mid h_{t},\tau;\theta)
with parameters
\theta
and temperature
\tau
. A large language model (LLM) serves as the policy to produce a textual action that is parsed into an executable action
a_{t}=\psi(y_{t})\in\mathcal{A}_{t}
. Unparsable or infeasible generations are marked invalid.

3.2
Exploration via Temperature Scaling

In the context of autoregressive agents, diversity and creativity in generated outputs are commonly controlled via temperature scaling, which re-scales the model’s raw output scores (logits) prior to the softmax operation
(
28
)
. This is often superficially related to the notion of exploration in reinforcement learning, where an agent visits a broader range of states. Exploration is usually
epistemic
in nature as the agent seeks out novel states where its knowledge is uncertain, with the goal of reducing the uncertainty and thereby improving the estimation of the policy. Given a context
c=(x_{1},\dots,x_{|c|})
, the model autoregressively generates a continuation
\mathbf{x}=(x_{|c|+1},\dots,x_{|c|+L})
of length
L
. The joint probability of the generated sequence conditioned on
c
can be formulated as:

P(\mathbf{x}\mid c,\tau)=\prod_{l=1}^{L}P(x_{|c|+l}\mid c,x_{|c|+1},\dots,x_{|c|+l-1},\tau)

(1)

where each conditional is given by the temperature-scaled softmax:

P_{\tau}{(x_{l}\mid c,x_{<l})}=P(x_{|c|+l}=v\mid c,x_{|c|+1:l-1},\tau)=\frac{\exp\!\left(z_{v}^{(|c|+l)}/\tau\right)}{\sum_{k=1}^{V}\exp\!\left(z_{k}^{(|c|+l)}/\tau\right)},\quad\forall v\in\{1,\dots,V\}

(2)

where
z_{i}^{j}
is the
i^{\text{th}}
logit at sequence position
j
, and
\tau
is the temperature hyperparameter that controls the sharpness of the softmax distribution. At low
\tau
, the model greedily selects its most probable continuations, and at high
\tau
, the distribution approaches uniform, with the model sampling less likely tokens. However, this diversity operates purely at the token level. In practice, temperature scaling is rarely used alone. Current LLMs typically pair it with a token filtering strategy, such as top-
p
(nucleus) sampling
(
11
)
, which retains only the smallest set of tokens whose cumulative probability exceeds a threshold
p
.

4

Stochastic sampling does not constitute epistemic exploration, as the model has no mechanism to reason about its own uncertainty. DORA Explorer shifts the focus from token-level sampling to sequence-level exploration, placing the control of exploration directly in the hands of the agent. DORA generates candidate actions (§
4.1
), scores them to compute probabilities (§
4.2
), and samples an action based on those probabilities (§
4.3
). The degree of exploration
\lambda
, can be controlled by the agent or by fixed scheduling (§
4.4
). An overview of our method is formalized in Algorithm
1
, and prompts are reported in §
C
.

4.1
Candidate Action Generation

The essence of DORA lies in letting the policy decide to be
greedy
or to
explore
. At each step
t
, the agent receives a context
c=[\mathcal{H};o_{t}]
of the interaction history with the current observation, then samples the greedy-exploration decision
d\sim\pi_{d}(c,\tau_{d})
. If the agent decides to explore, it samples
n_{\mathcal{C}}
candidate actions using list-level prompting via
\pi_{\mathcal{C}}(c,\tau_{\mathcal{C}},n_{\mathcal{C}})
. Standard prompting and sampling strategies tend to collapse to a higher probability action, and repeating such calls simply resamples the same mode. In contrast, when the agent is prompted to generate a list of
n_{\mathcal{C}}
actions jointly, it is forced to explore the breadth of the distribution, naturally producing diverse candidate actions
(
33
)
. Only valid candidate actions that have not been used previously in the current observation are retained. If the agent decides
not
to explore, the final action is sampled greedily,
a^{*}_{t}\sim\pi_{g}(c,\tau=0)
.

4.2
Action Sequence Scoring

Each candidate action
a\in\mathcal{C}
can be represented as a sequence of tokens,
a=\langle x_{1},\dots,x_{n}\rangle
. The score
{s}\in[0,1]
provides a confidence value by aggregating how
likely
and
consistent
each action sequence is based on its constituent tokens. The score is defined as
{s}=\text{Score}({a},\alpha)=\alpha\cdot\tilde{\mu}({a})-(1-\alpha)\cdot\tilde{\sigma}^{2}({a})

where
\alpha
is the scoring hyperparameter,
\tilde{\mu}(\cdot)
and
\tilde{\sigma}^{2}(\cdot)
are the min-max normalized mean and variance of the log-probabilities from Eq.
2
of each token in a candidate action, defined:

\displaystyle\tilde{\mu}({a})=\text{min-max}\underbrace{\left(\frac{1}{N}\sum_{i\in{a}}\log({P}_{\tau}(i))\right)}_{\mu(a)}~~\text{and}~~\tilde{\sigma}^{2}({a})=\text{min-max}\underbrace{\left(\frac{1}{N}\sum_{i\in a}(\log{P}_{\tau}(i)-\mu(a))^{2}\right)}_{\sigma^{2}(a)}

(3)

where
\text{min-max}({x}):=\left(\frac{x-x_{\min}}{x_{\max}-x_{\min}+\epsilon}\right)
and
\epsilon=1\cdot e^{-8}
is a small constant.

A higher mean log-probability naturally indicates that the model assigns greater likelihood to each token in the sequence
(
16
)
, while a lower variance shows better internal consistency across tokens
(
8
)
. Together, they favor sequences that are globally probable and locally coherent.

4.3
\lambda
-probabilities and Action Sampling

Based on the scores, we generate the
\lambda
-probabilities using

P_{\lambda}(a)=\text{Softmax}(\lambda\cdot s_{a})=\frac{\text{exp}(\lambda\cdot s_{a})}{\sum_{a^{\prime}\in\mathcal{C}}\text{exp}(\lambda\cdot s_{a^{\prime}})},

(4)

where the exploration parameter
\lambda
controls the sharpness of the distribution and acts as an inverse of the softmax temperature
\tau
,
i.e.
, lower
\lambda
leads to more exploration and higher
\lambda
leads to greedy sampling. The final action
a^{*}_{t}
is sampled via

a^{*}_{t}\sim\text{Categorical}(\mathbf{p}_{\lambda})
,
where the likelihood of each action
a
corresponds to
\lambda
-probabilities
P_{\lambda}(a)
from Eq.
4
.

4.4
How do we select
\lambda
?

\lambda
determines the degree of exploration. Classic reinforcement learning problems generally require higher initial exploration to build epistemic knowledge, followed by exploitation based on that knowledge. A
\lambda
-scheduler simulating exploration
\xrightarrow{}
exploitation shift should suffice in simpler tasks. We formulate a
\lambda
exponential scheduling function,

\lambda_{\text{exp}}(t)=\lambda_{\min}+(\lambda_{\max}-\lambda_{\min})\frac{e^{kt/T}-1}{e^{k}-1},

(5)

where
T
is the horizon, and
k
is the exponential growth
constant. However, the predefined exploration
\xrightarrow{}
exploitation shift may not always hold true. The exploration distribution of complex decision-making tasks is rarely predictable, making
\lambda
-scheduling impractical. In such cases, we draw an analogy to human behavior and allow the autoregressive agent to determine its degree of exploration by sampling
\lambda
from the policy
\lambda\sim\pi_{\lambda}(c,\tau_{\lambda})

conditioned on the context
c
and the exploration temperature hyperparameter
\tau_{\lambda}
.

5
Experiments

5.1
Multi-Armed Bandits (MAB)

Experimental Setup.

Multi-Armed Bandits (MAB) provide a classical testbed for studying the exploration-exploitation trade-off
(
17
;
25
)
. As a single-state Markov Decision Process, MAB serves as a minimal “unit test” for evaluating new exploration strategies in decision-making. Following
15
, we consider stochastic Bernoulli bandits with
K
arms, where each arm
a\in[K]
has an unknown mean reward
\mu_{a}\in[0,1]
. At each time step
t\in[T]
, the agent selects an arm
a_{t}
and observes a reward
r_{t}\sim\mathrm{Bernoulli}(\mu_{a_{t}})
. As the mean reward of each arm must be inferred from repeated pulls and feedback is only observed for the selected arm, the agent faces an exploration–exploitation trade-off: exploring to identify high-reward arms while exploiting known rewards to maximize cumulative reward. The objective is to maximize cumulative reward, or equivalently, minimize cumulative regret, which is defined as

R_{T}=T\mu^{\star}-\mathbb{E}\!\left[\sum_{t=1}^{T}\mu_{a_{t}}\right].

(6)

LLM agents interact through a text interface, with details provided in Appendix
A.1
.

Baselines.
We evaluate MAB using
Llama-3.1 8B
, results reported in
Table 1
, and
Qwen-2.5 7B
, results provided in
Appendix D
; both are instruction-tuned open-source models. We compare against standard (non-LLM) bandit baselines, including Upper Confidence Bound (UCB)
(
2
)
and Thompson Sampling (TS)
(
1
)
, which enjoy theoretical performance guarantees, as well as Greedy and
\epsilon
-greedy strategies. To contextualize LLM behavior, we additionally include sampling-based policies with fixed temperatures
(0,0.7,1.0,1.5)
, along with an adaptive
\tau
-policy that employs an exponentially decaying temperature schedule, mirroring the
\lambda
-schedule described in Eq.
5
.

To adapt DORA to MAB, we use a scheduled
\lambda
policy (cf. §
4.4
),
exponentially increasing
\lambda\in[0,40]
to transition from early exploration to later exploitation. We evaluate performance using mean average reward, cumulative regret, and the fraction of optimal arm selections. Additionally, we report
Suffix Failure Frequency
, the fraction of runs in which the agent fails to select the optimal arm at least once after
T/2
steps.

5.2
TALES

TALES
(
5
)
is a unified benchmark spanning five text-based environments—TextWorld, TextWorldExpress, AlfWorld, ScienceWorld, and Jericho—that vary in horizon length, parser strictness, feedback quality, and reward structure. Because TALES preserves each environment in its canonical form with minimal task-specific scaffolding, it provides a direct test of an agent’s ability to reason, plan, and explore from text alone in uncertainty. Each TALES task is a partially observable Markov decision process (POMDP; §
3.1
), where the agent receives a textual observation along with interaction history and outputs a textual action at each step. See Appendix
A.2
for additional details.

Environments.

TextWorld uses CookingWorld instances
(
4
)
, in which the agent follows recipes by locating and processing ingredients as task complexity increases. TextWorldExpress
(
13
)
is a faster re-implementation with a stricter parser and simpler deterministic tasks. AlfWorld
(
24
)
consists of text-based household tasks with sparse feedback, no intermediate rewards, and the constraint that the agent can hold only one object at a time. ScienceWorld
(
29
)
contains open-ended scientific tasks with multiple valid solution paths and occasional irreversible states. Jericho
(
9
)
includes long-horizon, human-authored interactive fiction and represents the most challenging setting in the suite.

Experimental Setup.
Given the dynamic exploration requirements of TALES tasks, we use a variant of DORA, called
DORA Auto-Explorer
, as described in Algorithm
1
. In this setting, the LLM dynamically decides whether to explore and, if yes, selects an exploration parameter
\lambda
at each step, enabling intermittent exploration behavior within an episode.

)

6
Conclusion

One of the most important aspects of embodied agents is exploration: the ability to take unlikely paths and gather information from the environment. However, LLM agents struggle with this due to the disconnect between sampling in token space versus actions.
To address this we introduce DORA Explorer, a general training-free LLM inference framework.
DORA goes beyond standard sampling and prompting strategies by exploring diverse action sequences in a structured manner. This enables the agent to reach more informative states, supporting rapid in-context adaptation. We show in our experiments across diverse environments that
DORA Explorer significantly outperforms sampling and prompting strategies and is able to generalize to different models and environments.

Reproducibility Statement

We provide sufficient details about our implementation, hyperparameters, and environment design in the main paper and the appendix to effectively
reproduce the results in this paper. We will release the complete codebase upon publication.

Appendix A
Environment Details

A.1
Multi-Armed Bandits

We study the hard instance from
15
, where a single optimal arm has mean
\mu^{\star}=0.5+\frac{\Delta}{2}
and all other arms have mean
\mu=0.5-\frac{\Delta}{2}
, yielding a gap
\Delta=\mu^{\star}-\mu
. In our experiments, we fix
K=5
,
\Delta=0.2
, and horizon
T=200
. We model the LLM as a decision-making agent that interacts with the bandit via natural language. At each step, the model is prompted with a description of the task (including the horizon
T
) and a concise summary of the interaction history. Actions correspond to selecting one of
K
arms via a neutral button-pressing interface. The model is required to output a single action in a constrained format (
<Answer>...</Answer>
), specifying one arm. Outputs that do not follow the required format or fail to identify a valid arm are treated as invalid actions. Invalid actions yield no reward and incur a regret penalty equal to the suboptimality gap (
0.2
in our setting). More details of the prompt design, including examples, are provided in Appendix
C.1
. Classical bandit baselines (UCB, TS, Greedy,
\epsilon
-greedy) are averaged over
N=1000
runs, while LLM-based methods are averaged over
N=20
runs.

A.2
TALES

Each TALES task is modeled as a partially observable Markov decision process (POMDP; §
3.1
), where the agent receives a textual observation along with interaction history and outputs a textual action at each step. Episodes terminate either upon task completion or after a fixed horizon of 100 steps.

We evaluate across all TALES environments, including TextWorld (10 tasks), TextWorldExpress (16 tasks), AlfWorld (12 tasks), and ScienceWorld (30 tasks). For Jericho, which contains 54 tasks, we report results on 52 tasks. There is a known issue with the Jericho environment
1
1

1

https://github.com/microsoft/jericho/issues/64
that causes segmentation faults at specific execution steps, rendering it unrunnable.

Appendix B
Algorithms and Hyperparameters

B.1
Multi-Armed Bandit Algorithms

Upper Confidence Bound(UCB):
We use UCB
(
2
)
as an upper bound algorithm for MAB. UCB uses a balance of the exploitation and exploration factors. Score for each arm, the exploitation factor is equal to its empirical mean reward augmented by an exploration bonus. Specifically, the score for arm
a
is defined as
\hat{\mu}_{a}+\sqrt{C/n_{a}}
, where
\hat{\mu}_{a}
denotes the running average reward and
n_{a}
is the number of times arm
a
has been selected. At each step, the agent selects the arm with the highest score. To ensure sufficient initial coverage, each arm is pulled once before applying the UCB rule. In our implementation, we fix
C=1
as a simple and effective heuristic as also used by
(
15
)

Thompson sampling (TS):
We employ Thompson Sampling with independent Beta-Bernoulli models for each arm. The mean reward of each arm
a
is treated as a latent parameter with a Beta prior,
\text{Beta}(\alpha_{0},\beta_{0})
, initialized uniformly with
\alpha_{0}=\beta_{0}=1
. At each step, a sample is drawn from the posterior distribution
\text{Beta}(\alpha_{a},\beta_{a})
for every arm, and the arm with the highest sampled value is selected. After observing a Bernoulli reward, the posterior is updated by incrementing
\alpha_{a}
for a success and
\beta_{a}
for a failure. This procedure naturally balances exploration and exploitation by sampling according to posterior uncertainty.

Greedy:
After sampling each arm once, the greedy algorithm always selects the arm with the highest empirical mean reward.

\epsilon
-greedy:
For
\epsilon
-greedy, at each step, the agent selects a random arm with probability
\epsilon
, and otherwise chooses the arm with the highest empirical mean reward. We initialize
\epsilon=0.1
and decay it multiplicatively by a factor of
0.99
after each update to gradually transition from exploration to exploitation.

C.2
TALES Prompts

Zero-Shot System Prompt

You are playing a text-based game. Your goal is to maximize the final score.

At each step, read the current observation and output a single concise action to interact with the environment (e.g., get lamp). Do not include explanations.

If you are uncertain or stuck, consider using the ”help” command to discover available actions.

Zero-Shot CoT Prompt

You are playing a text-based adventure game. Your goal is to finish it with the highest score.

Before acting, reason briefly covering:

1. What the current scene tells you (exits, objects, state).

2. What your immediate sub-goal is.

3. Which single command best advances that sub-goal.

After your reasoning, output exactly one line and nothing after it:

ACTION: <single short command, e.g. get lamp>

Rules:

- Put only the game command after ACTION: (a few words). No second sentences on that line.

- Do not write ACTION: anywhere except this final line.

- No backticks or quotes around the command.

When stuck, try using the ‘help‘ command to see what commands are available.

Tree-of-Thought (ToT) Prompt (
k=3
,
b=1
)

Tree of Thought Reasoning

Branch Generation (k=3)

Consider the current game state and generate EXACTLY 3 distinct candidate actions.

Each branch must differ meaningfully --- not just rephrasings of the same idea.

Format:

Branch A: <action>

Branch B: <action>

Branch C: <action>

Branch Evaluation

For each branch, reason through ONE step ahead: what is the likely outcome?

Score each on two dimensions (1--5 each):

- Progress: Does it advance toward the goal or unlock new options?

- Safety: Does it avoid irreversible mistakes or dead ends?

Format:

Branch A: Progress=? Safety=? Total=? | Reasoning: <one sentence>

Branch B: Progress=? Safety=? Total=? | Reasoning: <one sentence>

Branch C: Progress=? Safety=? Total=? | Reasoning: <one sentence>

Pruning (b=1)

Eliminate the two lower-scoring branches.

State which branch survives and why in one sentence.

Final Action

After pruning, output exactly ONE line in this format (this line must be last):

ACTION: <single short game command to type, e.g. open fridge>

Rules:

- Put only the command after ACTION: (no backticks, no quotes).

- Do not write ACTION: anywhere except this final line.

- When stuck, try using the ‘help‘ command to see what commands are available.

ReAct System Prompt

You are playing a text-based game and your goal is to finish it with the highest score.

At each step you receive an observation from the game. You must respond with a Thought and an Action, in that order.

Format your response exactly as:

Thought: brief reasoning about the situation and what to do

Action: single short game command, e.g. get lamp

Rules:

- Always output exactly one Thought line followed by exactly one Action line.

- The Action must be a bare game command (no backticks, no quotes).

- When stuck, try using the ”help” command to see what commands are available.

Prompt Explore System Prompt

You are playing a text-based game. Your goal is to maximize the final score.

Upon reading the current observation, output a single short phrase to interact with the game, e.g. get lamp, without backticks.

If you are stuck in an observation-action loop, or are uncertain about the next action, choose a more exploratory command and try different action phrases.

If you are stuck, consider using the ”help” command to see what actions are available.

C.3
Explore prompts

Mode Decision Prompt

Decide whether to act GREEDY or EXPLORE.

You go GREEDY if you know your goal and how to achieve it, and you are confident about your next action.
Choose EXPLORE only if you are stuck in an observation-action loop, or are uncertain about your next action.

Return ONLY strict JSON on a single line with one of these shapes:

{"mode":"GREEDY"}

{"mode":"EXPLORE"}

Rules:
- mode must be exactly ”GREEDY” or ”EXPLORE”.
- Do not include markdown, code fences, or explanation.

Candidate Generation Prompt

Based on the current game state, list
{n}
possible actions you could take.

Write one action per line as a short command phrase.

Do not number the lines. Do not include any explanation.

Lambda Decision Prompt

You chose to EXPLORE. Now select the exploration parameter
\lambda
.

\lambda\in[\lambda_{\min},\lambda_{\max}]
, where lower values correspond to higher exploration (flatter sampling), and higher values correspond to lower exploration (sharper sampling).

Return ONLY strict JSON on a single line with the following format:

{"lambda":<float>}

Rules:
-
\lambda
must lie within the allowed range
[\lambda_{\min},\lambda_{\max}]
.
- Example:
{"lambda":0.5}

- Do not include any additional text, markdown, or explanation.
