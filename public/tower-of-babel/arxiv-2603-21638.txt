No Dense Tensors Needed: Fully Sparse Object Detection on Event-Camera Voxel Grids
Mohamad Yazan Sadoun, Sarah Sharif, Yaser Mike Banad

Abstract
Event cameras produce asynchronous, high-dynamic-range streams well suited for detecting small, fast-moving drones, yet most event-based detectors convert the sparse event stream into dense tensors, discarding the representational efficiency of neuromorphic sensing. We propose SparseVoxelDet, to our knowledge the first fully sparse object detector for event cameras, in which backbone feature extraction, feature pyramid fusion, and the detection head all operate exclusively on occupied voxel positions through 3D sparse convolutions; no dense feature tensor is instantiated at any stage of the pipeline. On the FRED benchmark (629,832 annotated frames), SparseVoxelDet achieves 83.38% mAP@50 while processing only ∼ {\sim} 14,900 active voxels per frame (0.23% of the T × {\times} H × {\times} W grid), compared to 409,600 pixels for the dense YOLOv11 baseline (87.68% mAP@50). Relaxing the IoU threshold from 0.50 to 0.40 recovers mAP to 89.26%, indicating that the remaining accuracy gap is dominated by box regression precision rather than detection capability. The sparse representation yields 858 × \times GPU memory compression and 3,670 × \times storage reduction relative to the equivalent dense 3D voxel tensor, with data-structure size that scales with scene dynamics rather than sensor resolution. Error forensics across 119,459 test frames confirms that 71% of failures are localization near-misses rather than missed targets. These results demonstrate that native sparse processing is a viable paradigm for event-camera object detection, exploiting the structural sparsity of neuromorphic sensor data without requiring neuromorphic computing hardware, and providing a framework whose representation cost is governed by scene activity rather than pixel count, a property that becomes increasingly valuable as event cameras scale to higher resolutions.

Introduction

Detecting small unmanned aerial vehicles (drones) in real time is critical for airspace security, yet conventional RGB-based detectors struggle under low-light, high-dynamic-range, and cluttered-sky conditions
(
21
)
. Event cameras, neuromorphic sensors that asynchronously report per-pixel brightness changes with microsecond latency and
>
120 dB dynamic range
(
15
)
, are increasingly used for this task
(
7
)
. Recent benchmarks such as FRED
(
21
)
demonstrate that dense detectors applied to event-frame representations already achieve strong accuracy (87.68% mAP@50 with YOLOv11), validating the information content of the event stream for drone detection.

However, converting asynchronous events into dense frame-like tensors fundamentally discards the sensor’s most distinctive property:
extreme sparsity
. On the FRED benchmark, typical event frames occupy less than 1% of the input voxel grid, yet dense detectors must process all 409,600 pixel positions after resizing to 640
\times
640. This dense conversion imposes a computational cost disproportionate to the actual information content, undermining the efficiency promise of neuromorphic sensing (Figure
1
).

This mismatch creates a central opportunity for neuromorphic perception: if computation is tied to event activity rather than image resolution, event-camera systems can scale to higher resolutions and longer deployments without inheriting the full cost profile of dense vision pipelines.

In the LiDAR domain, sparse 3D convolution backbones such as SECOND
(
35
)
and detection frameworks including PointPillars
(
14
)
and CenterPoint
(
36
)
have progressively reduced the reliance on dense representations. Most recently, VoxelNeXt
(
1
)
demonstrated that point-cloud object detection can be performed entirely through sparse 3D convolutions without constructing any dense bird’s-eye-view maps. We observe that event-camera voxel grids share a similar sparse structure: both are 3D tensors (temporal bins
\times
height
\times
width for events; depth
\times
height
\times
width for LiDAR) with low occupancy rates. This structural analogy motivates our central hypothesis:
can an object detector process event data natively in the sparse domain, end-to-end, without any dense tensor conversion?

We present SparseVoxelDet, to our knowledge the first fully sparse object detector for event cameras. Existing event detectors either convert events to dense frames before applying conventional architectures
(
24
;
9
;
19
)
or employ sparse representations only partially, reverting to dense feature maps at intermediate stages
(
23
;
5
)
. SparseVoxelDet maintains sparse 3D tensor representations end-to-end, reframing event-camera detection as a native sparse-computation problem rather than a dense-image adaptation. The architecture chains three purely sparse stages: (1) a SparseSEResNet backbone that processes event voxel grids through 3D sparse convolutions with element-wise residual connections and squeeze-and-excitation attention, producing multi-scale features at strides 4, 8, and 16; (2) a Sparse Feature Pyramid Network that fuses these scales top-down through sparse lateral connections and sparse transpose convolutions, producing a unified feature map at stride 4; and (3) a SparseDetHead that applies an MLP to each active voxel position to predict classification, box regression (LTRB), and centerness, following the anchor-free FCOS formulation
(
34
)
. After temporal max-pooling to collapse the time dimension, non-maximum suppression yields final detections. No dense feature map is allocated at any point.

On the FRED canonical drone detection benchmark
(
21
)
, SparseVoxelDet achieves 83.38% mAP@50 with 6.2M parameters, narrowing the gap to the YOLOv11 baseline (87.68%) to 4.3 percentage points. To understand the nature of this gap, we conduct an error forensics analysis across all 119,459 test frames. The analysis reveals: (i) 71% of false negatives are localization near-misses (IoU
>0
but
<0.5
), indicating the model detects the drone but regresses imprecise boxes; (ii) confidence separation is strong (
\mu_{\text{TP}}=0.46
vs.
\mu_{\text{FP}}=0.11
); and (iii) recall reaches 95.4% at IoU
\geq 0.40
, confirming that the gap is predominantly a box-tightness penalty rather than a detection failure.

Related Work

2.1
Event-Based Object Detection

Event cameras
(
15
)
report pixel-level brightness changes asynchronously, producing streams with microsecond temporal resolution and high dynamic range
(
7
)
. Adapting object detectors to this modality has followed two main strategies.

Dense conversion methods. The predominant approach converts events into frame-like representations (event histograms
(
4
)
, time surfaces, or voxel grids
(
37
)
) and applies conventional dense detectors.
24
introduced the first large-scale event detector on the 1-megapixel Prophesee Gen1 dataset using histogram-based representations.
22
proposed learning event representations end-to-end for object detection rather than hand-crafting them. The FRED benchmark
(
21
)
reports results for YOLOv11
(
13
)
, RT-DETR
(
19
)
, and Faster R-CNN operating on event frames extracted at 30 FPS. RVT
(
9
)
applies recurrent vision transformers to event representations for automotive detection on Gen1, and
8
proposed end-to-end learning of event representations. These methods achieve strong accuracy but inherit the computational cost of dense convolutions, processing all spatial positions regardless of event occupancy.

Sparse event processing. SAST
(
23
)
introduced a scene-adaptive sparse transformer that selectively attends to event tokens rather than processing the full spatial grid. SAST applies sparsity at the
attention mechanism
level while retaining a dense backbone for initial feature extraction. Our approach differs fundamentally: SparseVoxelDet maintains full sparsity from the input representation through to the detection head, using sparse 3D convolutions that never instantiate a dense feature map at any stage. SAST’s selective attention and our sparse convolution pipeline address complementary aspects of efficiency; combining them (e.g., layering selective attention atop a sparse backbone) is an interesting direction for future work.

Spiking and hybrid methods. Spiking neural networks (SNNs) process events through biologically-inspired spike trains, preserving temporal sparsity during computation. EAS-SNN
(
38
)
introduces attention-based spiking neurons for event detection.
3
benchmarked SNN-based detectors on automotive event datasets, and SFOD
(
5
)
proposed spiking fusion for event detection. The SEW-ResNet architecture
(
6
)
proposes spike-element-wise residual connections that enable deeper spiking networks and forms the theoretical basis of our backbone. ER-DETR
(
20
)
fuses RGB and event modalities via cross-attention for drone detection. However, these architectures typically convert to dense intermediate representations during feature fusion or detection head stages. Our work extends the spiking residual idea by maintaining full sparsity throughout: we use the SEW residual pattern with sparse 3D convolutions rather than dense spiking neurons.

2.2
Sparse 3D Convolutions for Point-Based Detection

Sparse convolutions, pioneered by
10
and implemented efficiently in libraries such as spconv
(
32
)
, process only occupied voxel positions in 3D grids. This approach is well-established for LiDAR-based 3D object detection, where point clouds are voxelized before processing. Early point-based approaches such as PointNet
(
25
)
and PointNet++
(
26
)
processed raw point sets directly, but voxel-based methods have since become dominant for efficiency. SECOND
(
35
)
introduced sparse convolutions for LiDAR detection, PointPillars
(
14
)
organized point clouds into vertical columns for efficient processing, and CenterPoint
(
36
)
combined sparse backbones with center-based detection heads. In the 2D domain, Sparse R-CNN
(
33
)
demonstrated that a small set of learnable proposals can replace dense feature maps for detection, though it relies on a dense backbone.

VoxelNeXt
(
1
)
demonstrated that 3D object detection on LiDAR point clouds can be performed
fully sparsely
, predicting bounding boxes directly from sparse voxel features without any dense bird’s-eye-view conversion. This eliminates the computational overhead of processing empty space. The key insight that sparse-in, sparse-out architectures can match dense counterparts when occupancy is low directly motivates our work on event cameras, where we measure occupancy rates below 1% on FRED (Section
3.1
), making dense processing particularly wasteful.

Our SparseFPN adapts the top-down feature pyramid concept from FPN
(
16
)
to the sparse domain, using sparse transpose convolutions for upsampling and sparse addition for multi-scale fusion. Unlike dense FPN implementations, our Sparse FPN propagates features only to positions that have evidence from at least one scale.

2.3
Drone Detection

Detecting small unmanned aerial vehicles is a growing security concern that poses unique challenges: drones are small (often
<
20 pixels), move fast, and operate under variable lighting including dawn, dusk, and night conditions. RGB-based approaches
(
31
)
struggle under these conditions due to low contrast and motion blur.

The FRED dataset
(
21
)
provides synchronized RGB and event data for drone detection across 231 sequences with diverse scenarios including varying altitude, weather, and illumination. It establishes three benchmarks: detection, tracking, and trajectory forecasting. Event-frame representations significantly outperform RGB (
+
52 mAP@50 points for YOLOv11 on canonical splits), confirming that event cameras capture motion-salient features invisible to RGB under challenging conditions.

Our work contributes
sparse-native
results on FRED, bridging the gap between the event-based detection literature (which has not used sparse 3D convolutions) and the sparse convolution literature (which has focused exclusively on LiDAR).

Method: SparseVoxelDet

We present SparseVoxelDet, a fully sparse object detector for event cameras. The key design principle is that
every computation operates only on active positions
, fundamentally preventing dense feature map construction. We define an
active position
as any coordinate
(x,y,z)
in the 3D voxel grid where a feature value is non-zero. Unlike dense pipelines which allocate
O(H\times W)
memory and compute over all spatial positions regardless of occupancy, our system maintains a hash table of active coordinates and executes multiply-accumulate operations exclusively where they carry signal. Figure
2
illustrates the pipeline. We describe each stage below.

3.1
Event Voxelization

Given a stream of asynchronous events
\{(x_{i},y_{i},t_{i},p_{i})\}
within a time window, we construct a sparse voxel grid following the temporal binning strategy of
37
. The temporal axis is discretized into
T
uniform bins at a spatial resolution of
H\times W
pixels.

Per-voxel features. Each active voxel at position
(t,y,x)
stores a
C_{\text{in}}
-channel feature vector computed from the events falling into that bin. A minimal representation uses
C_{\text{in}}=2
channels consisting of positive and negative event counts
(c^{+},c^{-})
. A richer representation uses
C_{\text{in}}=6
channels that additionally capture recency and temporal variation per polarity:

\mathbf{f}=\bigl[\underbrace{\log(1{+}c^{+}),\;\log(1{+}c^{-})}_{\text{count}},\;\underbrace{r^{+},\;r^{-}}_{\text{recency}},\;\underbrace{\sigma^{+}_{t},\;\sigma^{-}_{t}}_{\text{temporal std}}\bigr],

(1)

where
\log(1{+}c^{\pm})
compresses high-activity counts;
r^{\pm}=\exp(-\lambda(t_{\max}-t_{\text{last}}^{\pm}))
are exponential recency features, with
t_{\max}
denoting the maximum event timestamp in the current time window and
\lambda=5/\Delta t_{\text{range}}
(chosen so that an event arriving at the start of the window decays to
e^{-5}\approx 0.007
, effectively distinguishing the most recent 20% of the window from stale activity), that distinguish recently active voxels (moving objects) from stale ones (noise); and
\sigma^{\pm}_{t}
are normalized temporal standard deviations of event timestamps, discriminating steady motion from transient flicker.

The resulting representation is a
SparseConvTensor
with spatial shape
[T,H,W]
and
C_{\text{in}}
channels. Even at the native sensor resolution of
1280\times 720
with
T=16
bins, the grid contains
{\sim}14.7\times 10^{6}
possible positions, of which
<
1% are typically occupied. This extreme sparsity is the fundamental motivation for maintaining sparse computation throughout. Section
4.2
details the specific configurations evaluated.

3.2
SparseSEResNet Backbone

The backbone is a sparse 3D convolutional residual network whose element-wise residual connections are inspired by SEW-ResNet
(
6
)
, adapted to operate entirely through sparse convolutions following the deep residual learning paradigm
(
11
)
. Unlike SEW-ResNet, our network does not use spiking neurons; the residual pattern is adopted purely for its gradient-friendly properties in deep sparse networks. It uses the
nano_deep
configuration: a base channel width of 32 with block depths
[2,2,2,1]
across four stages, and squeeze-and-excitation (SE) attention
(
12
)
on the final two stages.

Architecture. A sparse convolutional stem with stride
(1,2,2)
maps the
C_{\text{in}}
-channel input to 32 channels while downsampling spatially by
2\times
. Four stages of sparse residual blocks follow with per-stage strides
(1,2,2,2)
, producing cumulative spatial strides 2, 4, 8, and 16 from the original input (equivalently 1, 2, 4, 8 relative to the stem output). Feature channels double at each stage: 32, 64, 128, 256. Each residual block consists of two
SubMConv3d
(submanifold sparse convolution) layers with layer normalization and ReLU activation, connected by an element-wise residual addition that operates on the sparse feature tensors.

Residual connections. Following the element-wise addition pattern of
6
, residual connections add features in the sparse domain. When the input and output dimensions differ (at stride boundaries), a
1\times 1
sparse convolution with stride acts as the shortcut.

The backbone outputs multi-scale features at three levels:
\{C_{2},C_{3},C_{4}\}
with stride
\{4,8,16\}
and channels
\{64,128,256\}
. All operations are sparse: the number of active positions decreases at deeper stages as sparse strided convolutions subsample only occupied locations.

3.3
Sparse Feature Pyramid Network

We adapt the Feature Pyramid Network
(
16
)
to the sparse domain. The goal is to fuse multi-scale features into a single feature map at stride 4 (the finest backbone level) for high-resolution detection of small objects.

Lateral connections. Each backbone output
C_{k}
is projected to a common channel dimension (
d=128
) through a
1\times 1
sparse submanifold convolution followed by layer normalization:

P_{k}=\text{SparseLN}(\text{SubMConv3d}_{1\times 1}(C_{k})),\quad k\in\{2,3,4\}.

(2)

Top-down pathway. Features flow from coarse to fine through sparse transpose convolutions (
SparseConvTranspose3d
) with spatial stride
(1,2,2)
, which upsample the spatial dimensions by
2\times
while preserving the temporal dimension. Fused features at each level are obtained via sparse element-wise addition:

\displaystyle P_{3}^{\prime}

\displaystyle=P_{3}+\text{SparseUpsample}(P_{4}),

(3)

\displaystyle P_{2}^{\prime}

\displaystyle=P_{2}+\text{SparseUpsample}(P_{3}^{\prime}).

(4)

Output refinement. A
3\times 3
sparse submanifold convolution refines the fused stride-4 features, producing the final feature map
F\in\mathbb{R}^{M\times d}
where
M
is the number of active voxel positions. We fuse to a single stride-4 level rather than maintaining multi-scale outputs, as the FRED target class (drones) spans a relatively narrow size range (10–50 pixels at detection distance), favoring fine-grained spatial resolution over multi-stride coverage.

The sparse transpose convolution only generates output positions that overlap with the upsampling kernel centered on occupied input positions. The sparse addition operation produces outputs at the
union
of active positions from both operands. Together, these ensure that top-down context propagates only to spatially relevant locations.

3.4
Temporal Squeeze

The backbone and FPN produce 3D sparse features with indices
(b,t,y,x)
. Detection requires 2D spatial predictions. We collapse the temporal dimension by grouping all active voxels that share the same
(b,y,x)
position and applying max-pooling over their features:

f_{(b,y,x)}=\max_{t\in\mathcal{T}_{(b,y,x)}}F_{(b,t,y,x)},

(5)

where
\mathcal{T}_{(b,y,x)}
is the set of temporal bins with active features at spatial position
(y,x)
. This produces
M^{\prime}
unique 2D positions with
d
-dimensional features. We choose max-pooling over mean-pooling or learned attention because it preserves the strongest activation across time, appropriate for detecting transient moving objects whose event signature may be concentrated in a few temporal bins. This design also maintains the fully sparse paradigm, as the operation requires no dense allocation.

3.5
Detection Head

The detection head follows the anchor-free FCOS design
(
34
)
, predicting classification, box regression, and centerness at each active 2D position. Since the temporally-pooled features are a flat tensor of
M^{\prime}
position vectors (not a dense grid), the head is implemented as a shared MLP (equivalent to pointwise
1\times 1
convolutions), operating independently per position. This pointwise design is a deliberate choice: spatial context has already been aggregated by the backbone’s multi-layer 3D sparse convolutions and the FPN’s top-down fusion; the head’s role is to classify and localize from the resulting per-position feature vector.

Shared trunk. Two layers of Linear
\rightarrow
GroupNorm
\rightarrow
ReLU, both with hidden dimension
d=128
.

Prediction branches. Three linear heads applied in parallel:

•

Classification:
\hat{c}\in\mathbb{R}^{M^{\prime}\times 1}
, sigmoid-activated, initialized with prior probability
p_{0}=0.01
.

•

Box regression:
\hat{b}\in\mathbb{R}^{M^{\prime}\times 4}
, predicting left–top–right–bottom (LTRB) distances from the position center. The exponential of the raw predictions gives pixel distances.

•

Centerness:
\hat{z}\in\mathbb{R}^{M^{\prime}\times 1}
, sigmoid-activated quality estimate following
34
.

Box decoding. Each active position
(y,x)
at stride
s=4
corresponds to a region center at pixel coordinates
(x\cdot s+s/2,\;y\cdot s+s/2)
. The LTRB predictions define the bounding box as:

\text{box}=\left[c_{x}-l,\;c_{y}-t,\;c_{x}+r,\;c_{y}+b\right],

(6)

where
(c_{x},c_{y})
is the position center and
(l,t,r,b)=\exp(\hat{b})
.

3.6
Training Objective

The training loss combines three terms:

\mathcal{L}=\lambda_{\text{cls}}\mathcal{L}_{\text{cls}}+\lambda_{\text{reg}}\mathcal{L}_{\text{reg}}+\lambda_{\text{ctr}}\mathcal{L}_{\text{ctr}}.

(7)

Classification loss (
\mathcal{L}_{\text{cls}}
): Focal loss
(
17
)
applied to all active positions. A position is positive if it falls within a ground-truth bounding box.

Regression loss (
\mathcal{L}_{\text{reg}}
): GIoU loss
(
29
)
between decoded predicted boxes and ground-truth boxes, computed only for positive positions.

Centerness loss (
\mathcal{L}_{\text{ctr}}
): Binary cross-entropy between predicted centerness and the target centerness computed from LTRB distances, applied only to positive positions.

3.7

\text{score}=\sigma(\hat{c})\cdot\sigma(\hat{z})

Batched non-maximum suppression (NMS), a standard post-processing step that iteratively removes lower-scoring detections whose bounding boxes overlap a higher-scoring detection by more than a given IoU threshold, selects the final detections with IoU threshold 0.5, capped at 100 per frame. 3.8
Design Discussion

Why stride 4? At native
1280\times 720
input, stride 4 produces a
320\times 180
grid where a typical 10–50 pixel drone spans 2.5–12.5 cells, sufficient for precise regression. At the
640\times 640
ablation resolution, this becomes a
160\times 160
grid. In both cases, the sparse pipeline’s cost scales with active voxels, not total grid positions, so the higher-resolution grid does not proportionally increase computation.

Why MLP head? After temporal pooling, features are a flat matrix
[M^{\prime},d]
. The detection head’s receptive field is limited to single positions, making an MLP both simpler and faster than reconstructing a sparse 2D tensor for spatial convolutions.

Model size. The full model contains 6.2M parameters: 4.8M in the backbone, 1.4M in the FPN, and 34K in the detection head.

Experiments

4.1
Dataset: FRED Benchmark

We evaluate on the FRED (Florence RGB-Event Drone) dataset
(
21
)
, the largest event-camera benchmark for drone detection, providing synchronized RGB and event-camera recordings. The dataset comprises over 7 hours of data across 231 sequences captured with a Prophesee EVK4 (IMX636) event camera at a native resolution of 1280
\times
720, co-registered with an RGB sensor. Five commercial and custom drone models serve as targets: Betafpv Air75, DarwinFPV CineApe20, DJI Tello EDU, DJI Mini 2, and DJI Mini 3, spanning a wide range of sizes, speeds, and flight patterns.

Sequences cover diverse operational conditions: varying altitude (
{\sim}
5–80 m), illumination (daylight, dusk, night), weather (clear, overcast, rain), and background complexity (open sky, buildings, vegetation). We use the canonical 80/20 train/test split provided by the benchmark, balanced across scenarios.

A defining property of the FRED dataset is that event cameras maintain usable signal across the full range of lighting conditions, including complete darkness where RGB cameras produce unusable frames. Figure

4.5
Evaluation Protocol

We report the standard COCO-style mAP@50 and mAP@50:95 metrics computed over all test frames. At inference, the score threshold is 0.05 (a deliberately permissive value standard in COCO-style evaluation that retains all plausible detections for the precision–recall curve computation; the AP metric integrates over all confidence thresholds, so this floor has negligible impact on reported mAP), NMS IoU threshold is 0.5, and the maximum number of detections per frame is 100. The evaluation uses the EMA model weights.

4.6
Error Forensics Pipeline

Beyond aggregate metrics, we conduct a systematic analysis of all detection failures. We first run inference on all 119,459 test frames and record per-frame predictions with scores, matched ground-truth boxes, IoU values, and TP/FP/FN labels. We then analyze failures along seven dimensions: IoU distribution of near-misses, confidence rank of true positives, object size vs. error rate, event density vs. recall, per-sequence breakdown, false positive patterns, and temporal consistency. Finally, we render event-frame and RGB side-by-side visualizations for worst-performing sequences.

This pattern is structurally linked to how event cameras encode moving objects. Unlike conventional cameras that capture the complete spatial extent of targets as filled regions, event cameras fire only at pixels experiencing brightness changes, generating contour-like activations concentrated along motion boundaries. A drone translating against a static background produces events primarily along its leading and trailing edges, with few events in its interior where brightness remains constant. The resulting sparse voxels trace the object’s silhouette rather than filling its area. Since SparseVoxelDet regresses bounding boxes from these occupied positions alone, with no dense spatial context between active voxels, the network must infer object extent from incomplete boundary evidence. Dense detectors, by contrast, process every pixel, including the uniform object interior, providing a clear spatial template for box regression. This asymmetry explains why detection recall is high (the contour signal is sufficient to recognize the drone) while box precision suffers (the contour signal underspecifies the object’s full spatial extent). The effect intensifies for faster-moving targets: rapid motion produces elongated event trails along the trajectory, potentially biasing the regressed box to include the motion streak rather than the instantaneous object footprint.

5.3
Representation Efficiency

One important advantage of fully sparse processing is in
representation
: SparseVoxelDet operates directly on the sparse event stream without reconstructing dense frames, yielding order-of-magnitude reductions in data movement, storage, and memory footprint.

At
640\times 640
, the median frame contains only
{\sim}
14,900 active voxels out of
16\times 640\times 640\approx 6.6
million possible positions (0.23% occupancy). At native
1280\times 720
, occupancy drops to 0.11% (
{\sim}
16,200 voxels out of 14.7 million possible positions). Storing only the occupied coordinate-feature pairs requires
{\sim}
94 KB of GPU memory per frame, compared to
{\sim}
78.6 MB for the equivalent dense 3D tensor (
T{\times}H{\times}W
with float32 features), an 858
\times
compression. On disk, the sparse NPZ representation averages
{\sim}
22 KB per sample versus
{\sim}
78.6 MB dense, a 3,670
\times
storage reduction. These ratios quantify the data-structure efficiency of storing a 3D voxel grid sparsely versus densely. For practical context: the FRED baselines process 2D event-frame images (a single
H{\times}W
plane, typically
{\sim}
1.2 MB at
640^{2}
in float32), not the full 3D grid. Against this 2D baseline input the sparse advantage is still substantial (
{\sim}
13
\times
in memory,
{\sim}
55
\times
on disk) and, crucially, SparseVoxelDet retains the full
T{=}16
temporal axis that 2D conversion discards. The sparse representation’s memory footprint scales with scene activity (the number of brightness-change events) rather than sensor resolution, a property with direct implications for edge deployment on memory-constrained platforms. At dataset scale (629,832 frames), the full FRED training set occupies
{\sim}
8.7 GB in sparse format; the dense equivalent would require
{\sim}
40 TB.

Dense detector cost scales as
O(H\times W)
: YOLOv11 must process 409,600 pixels at
640^{2}
and 921,600 at
1280\times 720
(
2.25\times
more). In contrast, the sparse representation’s size is governed by scene dynamics, not sensor resolution. We measure a median of
{\sim}
14,900 active voxels at
640^{2}
and
{\sim}
16,200 at native
1280\times 720
, a mere 9% increase despite a
2.25\times
growth in pixel count. For future 4K event sensors (
3840\times 2160
), dense cost would grow
{\sim}
20
\times
; sparse cost remains bounded by the number of brightness-change events in the scene.

Dense detectors applied to event cameras convert the asynchronous event stream into image-like tensors. The FRED baselines use simple event accumulation (histogram binning), which is computationally light. However, applications requiring high-quality frame reconstruction (e.g., E2VID
(
27
)
, 15–30 GFLOPs; FireNet
(
30
)
, 1.5–3 GFLOPs) face substantially higher overhead. SparseVoxelDet bypasses any such conversion: voxelization is a scatter operation with
O(N_{\text{events}})
additions and zero multiply-accumulate cost.

No dense feature map is allocated at any stage. At deeper layers, strided sparse convolutions subsample only occupied positions, reaching
{\sim}
2,700 active 3D positions at stride 16 versus
{\sim}
24,000 in the dense equivalent. For edge deployment on memory-constrained platforms (e.g., Jetson Orin Nano with 8 GB shared RAM), this compression is critical: the sparse pipeline can process high-resolution event streams that would be infeasible for dense methods under the same memory budget.

The sparse backbone processes only occupied voxels and their immediate neighbors, achieving compute proportional to the number of active positions. However, the current Feature Pyramid Network uses sparse transposed convolutions for upsampling, which expand the set of active positions at each fusion stage. All computations remain on sparse tensors throughout—no stage reverts to dense processing—but this expansion partially attenuates the sparsity advantage; we discuss alternatives in Section
6

6
Limitations and Future Work

6.1
Limitations

Accuracy gap. SparseVoxelDet trails the dense YOLOv11 baseline by 4.3 mAP@50 points (83.38% vs. 87.68%), though at IoU
=0.40
the gap narrows substantially as the model reaches 89.26% mAP. Our error analysis identifies box regression precision as the primary bottleneck: 71% of failures are localization near-misses rather than missed detections. Multi-scale training, richer temporal features, and longer training schedules may further narrow this gap.

FPN position expansion. The sparse backbone and detection head process only occupied positions, but the Feature Pyramid Network’s transposed convolutions expand the active position set at each upsampling stage. All operations remain on sparse tensors (no dense
H{\times}W
grid is allocated), but the increased position count may erode the sparsity advantage in practice. Sparsity-preserving alternatives such as VoxelNeXt-style single-stride detection
(
1
)
, sparse inverse convolutions
(
2
)
, and nearest-neighbor upsampling can maintain sparsity throughout the network. Resolving this expansion is the most immediate avenue for reducing per-frame compute.

Single-class evaluation. The current model detects a single class (drone). Extension to multi-class detection requires validating that sparse processing maintains class discrimination across categories with different size and motion characteristics.

Ablation scope. The present study validates the fully sparse paradigm with a single architecture configuration. Systematic ablation of individual components—temporal fusion strategy, channel depth, and feature pyramid design—is an important direction for extending these results.

Runtime characterization. Sparse-to-dense comparisons of runtime are confounded by implementation maturity: dense detectors benefit from years of kernel-level optimization (TensorRT, cuDNN), while sparse convolution libraries (spconv) are less mature. Meaningful latency comparisons require controlling for implementation quality, which is beyond the scope of this work.

6.2
Future Directions

Learnable temporal fusion (e.g., sparse temporal attention or recurrent aggregation) could capture motion trajectories and improve detection of fast-moving drones. Multi-scale detection heads at strides 4, 8, and 16 with bidirectional feature pyramids could improve detection across varying target distances, and our preliminary multi-stride experiments (eliminating the FPN in favor of direct multi-stride prediction heads) suggest this is a viable direction for preserving sparsity while improving box regression, as it avoids the position-expanding transpose convolutions identified in Section
5.3
.

All results are reported on the FRED benchmark, the largest publicly available event-camera dataset for drone detection (629,832 annotated frames, 231 sequences, Prophesee EVK4 at
1280\times 720
), recorded under diverse real-world conditions from daylight to complete darkness. While the sparse processing principles are sensor-agnostic (the architecture requires only coordinate–feature pairs from any voxelization), cross-class and cross-dataset benchmarking on additional event-camera datasets is an important direction for future work, as it would validate the generality of the fully sparse paradigm beyond single-class drone detection.

6.3
Ethical Considerations

Drone detection has dual-use implications: it can protect critical infrastructure but could also enable surveillance. In infrastructure protection contexts, false negatives (undetected drones) carry disproportionate risk; our error forensics (Section
5.2
) reveals that 71% of current failures are spatially proximate to true targets (IoU
>0
), suggesting that recall-oriented post-processing could address the most safety-critical failure mode. We advocate for transparent evaluation protocols and deployment guardrails that account for the asymmetric consequences of false positives and false negatives.

6.4
Reproducibility

All architecture code, training configurations, evaluation scripts, and the error forensics pipeline are publicly available at
https://github.com/INQUIRELAB/SparseVoxelDet
. The FRED dataset is publicly available. Training on a single GPU and reporting multi-seed results makes the work accessible without large compute infrastructure and statistically grounded.

7
Conclusion

We presented SparseVoxelDet, a fully sparse object detector for event cameras that performs all computation, from backbone feature extraction through feature pyramid fusion to the detection head, exclusively on occupied voxel positions using 3D sparse convolutions. On the FRED drone detection benchmark, SparseVoxelDet achieves 83.38% mAP@50 while processing only
{\sim}
14,900 active voxels per frame at
640\times 640
, roughly 28
\times
fewer than the 409,600 pixels processed by the dense YOLOv11 baseline (87.68% mAP@50). The sparse representation achieves 858
\times
GPU memory compression and 3,670
\times
storage reduction relative to the equivalent dense 3D voxel tensor, with voxel counts that remain nearly constant across sensor resolutions, eliminating the
O(H\times W)
scaling of dense methods.

Our systematic error forensics reveals that the 4.3-point mAP@50 gap to the YOLOv11 baseline is dominated by localization near-misses (71% of failures), not missed detections. At a slightly relaxed IoU threshold of 0.40, SparseVoxelDet recovers to 89.26% mAP, confirming that the model detects drones in nearly every frame but produces bounding boxes that are slightly too loose for the strict IoU
\geq 0.50
criterion. The wider gap at mAP@50:95 (39.23% vs. 49.25%) further confirms that box regression precision is the primary bottleneck. The model achieves 91.9% recall at IoU
\geq 0.50
(rising to 95.4% at IoU
\geq 0.40
) with well-calibrated confidence scores. Multi-seed evaluation confirms training stability across random initializations (
\pm
0.16 pp at
640^{2}
,
\pm
0.14 pp at native resolution).

These findings suggest that the sparse structure of event-camera data, exploited extensively by the LiDAR community but still underused in event-camera detection, is not only conceptually elegant but practically important: representation cost can scale with scene dynamics rather than sensor resolution. As event cameras improve in resolution and move toward edge deployment, fully sparse architectures like SparseVoxelDet provide a concrete path toward neuromorphic-native detection systems that preserve temporal detail without paying dense-resolution cost at every stage. Our measurements show that active voxel counts increase by only 9% when sensor resolution grows
2.25\times
, a property unattainable by dense pipelines. The identification of box regression precision as the specific bottleneck, coupled with the strong detection recall (91.9%), provides a clear and focused target for future architectural improvement.

More broadly, event cameras and sparse 3D architectures are natural complements: the sensor emits sparse, asynchronous signals, and the model computes only where those signals exist. This alignment opens a high-upside direction for the field, from high-resolution aerial monitoring to always-on, power-constrained edge intelligence, where dense pipelines are often bottlenecked by memory movement rather than recognition capacity. By establishing a fully sparse baseline and isolating its dominant failure mode, this work sets up the next phase of progress as an optimization problem with a clear target: retain sparse efficiency while tightening localization precision.
