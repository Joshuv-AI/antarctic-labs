1.0 Introduction
 The Merged Aerosol Value-Added Product (VAP) simplifies scientists’ use of Atmospheric Radiation
 Measurement (ARM) User Facility aerosol data by performing several tedious, time-consuming tasks for
 the users. First, the VAP identifies the best data available when multiple datastreams exist for a single
 geophysical quantity so that ARM users do not have to research this for themselves. Second, the VAP
 consolidates multiple ARM aerosol datastreams into a single file for ARM data users so that they do not
 have to download, open, and read multiple files for their analysis. Next, the VAP transforms all
 measurements onto a common one-hour timestamp. The one-hour resolution matches the time resolution
 of the slowest instrument. Instruments with faster sampling rates than one measurement per hour are
 averaged over the time interval. Finally, the VAP reads the QA/QC variables and marks data with known
 issues as missing, so that users do not have to spend excessive time cleaning data. This includes
 incorporating Data Quality Reports (DQRs) that exist at the time when the VAP data is generated. DQRs
 are reports filed by instrument mentors or data users that indicate a problem with the output data of
 individual instruments.

 Scientists can use this VAP to streamline their aerosol data analyses. It represents a one-stop file for most
 aerosol-relevant quantities measured by ARM.

2.0 Algorithm and Methodology
 The algorithm for this VAP is relatively simple. It uses the ARM Data Integration (ADI) tool to average
 all the input datastreams to the desired time resolution. In this case, we average data to a one-hour time
 resolution, which is the time resolution for the slowest instrument, the cloud condensation nuclei counter
 (CCNC). The timestamp presented in the output files represents the midpoint of the time-averaging
 window. If more than 75% of an input datastream is bad or missing in a given one-hour time block, the
 data for that one-hour period are marked as missing for the entire one-hour time period. If between 50%
 and 75% of the input data are bad or missing, the data are averaged and reported, but marked as
 indeterminant by the VAP code.

 The VAP will run in two modes. One mode will run in near-real time and will be labeled as c0. These
 data will be available very quickly for users, but will not have final versions of some input data
 (e.g., aerosol chemical speciation monitor [ACSM] composition-dependent collection efficiency [CDCE];
 see section 2.0 for more details). In addition, the c0 version of the VAP will have missing values for input
 data that are evaluated at the end of a field campaign (e.g., aerosol optical depth [AOD] at some sites) or
 that are otherwise unavailable at the time of processing. It will also not include DQR checks. The second
 mode, labeled c1, will run approximately yearly or when all input data become available. This c1 version
 is expected to have final versions of the input data and will incorporate DQR checks as described below.

 QA/QC variables in the input data are evaluated and simplified into three options for reporting: good,
 indeterminate, and bad. In addition, we integrate information from any DQRs into the c1 VAP as follows.
 When the VAP processes c1 level data, it searches for any DQRs that are applicable to the input data and
 applies these DQRs prior to any averaging. Any input data that DQRs have flagged as “suspect” are
 included when calculating average values for a given time period, but output data are flagged as
 indeterminate. ARM data users can decide whether they would like to use these data, based on the

 QA/QC flags associated with that data variable. Any input data that DQRs have flagged as “incorrect” are

5.0 Summary
 The merged aerosol VAP provides ARM users with a product that performs several tedious and
 time-consuming steps for them, allowing them to streamline their data analysis. The VAP provides users
 with a single file that contains most aerosol data products averaged onto a common time stamp and
 quality controlled. Two versions of the VAP are produced:

 c0 – generated in near-real time for users, but will not contain some data that are only produced after a
 significant time delay or at campaign end. This version of the VAP also does not contain any DQR
 information.

 c1 – generated after the final version of all input data becomes available, typically after campaign end or
 approximately yearly for fixed sites. This version will incorporate any DQRs available at the time the
 VAP is processed.
