Connectivity Oracle Under Vertex Failures by Shortcutting Unbreakable Decomposition
Xizhe Li, Yaowei Long, David Pidugu, Thatchaphol Saranurak, Benyu Wang

Abstract
We give an improved connectivity oracle under vertex failures . After a set of k k vertices fails, our oracle performs an O ⁡ ( k 6 ) O(k^{6}) -time update independent of the graph size n n , and then answers pairwise connectivity queries in optimal O ⁡ ( k ) O(k) time. For constant k k , it uses near-linear space and can be built in near-linear preprocessing time. In contrast, all prior oracles with n n -independent update time [ 23 , 24 ] either require Ω ⁡ ( n 2 ) \Omega(n^{2}) space or incur 2 2 O ⁡ ( k ) 2^{2^{O(k)}} update and query time. Moreover, their preprocessing time is polynomially large in n n , far from near-linear. Our oracle builds on the unbreakable decomposition framework of [ 23 ] , but introduces three new ingredients: (i) shortcutting over the tree decomposition to reduce space from quadratic to near-linear, (ii) bootstrapping that leverages n n -dependent oracles internally to obtain near-linear preprocessing, and (iii) a new patch set mechanism that yields conditionally optimal O ⁡ ( k ) O(k) query time.

Overview

The unbreakable decomposition framework.

We start by introducing the framework inspired by
[
23
]
using unbreakable decomposition
[
16
]
. In a graph
G
, we say a set
B\subseteq V
is
(q,k)
-unbreakable if for any subset
S\subseteq V(G)
of at most
k
vertices, there can be at most one connected component
C
in
G\setminus S
such that
|C\cap B|>q
while
|B\setminus C|\leq q
. A
(q,k)
-
unbreakable decomposition
of a graph
G
is a tree decomposition
\mathcal{T}=(T,\textsf{bag})
where the bag associated with each tree node
x\in V(T)
is
(q,k)
-unbreakable in
G
. Additionally, we say that
\mathcal{T}
is
strongly

(q,k)
-unbreakable if every
\textsf{bag}(x)
is
(q,k)
-unbreakable in the subgraph of
G
induced by the union of all bags in the subtree of
T
rooted at
x
. Throughout the paper, we will use a strongly
(k,k)
-unbreakable decomposition of adhesion
k
given by
[
16
]
, thus in this paper we always assume
q=k
.

Given the set of at most
k
failed vertices
S
and for each
u\in S
, we first identify the topmost node
x\in T
where its bag contains
u
and call the node
x

important
. Let
X
be the set of all important nodes and let
Y
be the least common ancestor closure of
X
in
T
, adding the root if it is not already included. Note that
|X|\leq k
and
|Y|\leq O(k)
. For each
x\in X
, we aim to compute the
profile
of
x
, which is a graph on the adhesion of
x
where two vertices are adjacent if and only if they are connected in the subgraph of
G\setminus S
induced by the union of all bags in the subtree rooted at
x
. We build these profiles bottom-up, starting from the lowest nodes in
Y
and working all the way to the root. We use additional precomputed graphs called
torsos
to quickly jump between important nodes and skipping sections of the graph where no vertex failures occur. For any
x,y\in V(T)
where
x
is a strict ancestor of
y
, the graph
\textsf{torso}(x,y)
is on the adhesions of
x
and
y
. Two vertices in
\textsf{torso}(x,y)
are adjacent if and only if there exists a path between them in
G
whose interior lies entirely within the the induced subgraph on the union of all bags in the subtree rooted at
x
and stopping at
y
.

Computing torsos is a main bottleneck in the preprocessing time from
[
23
]
. To speed up this, we observe that torso queries can be computed via standard connectivity queries with vertex failures. Therefore, we build another oracle using
[
17
]
to boost the preprocessing time.

To evaluate the query
u,v
, we first consider
u
and repeat the same process for
v
. We first
augment

u
to the computed profile of its closest ancestor in
Y
while maintaining its connectivity invariants. Then we identify all important nodes along the path from
u
to the root, and working upward by augmenting
u
to each of their profiles until the root. After this is repeated for
v
, we can simply check the profile of the root to determine if
u
and
v
are connected in
G\setminus S
.

Shortcuts.

To avoid quadratic space used in storing all torsos
[
23
]
, we develop an approach using
shortcuts
. We observe that, suppose we have
x,y,z\in V(T)
where
x
is an ancestor of
y
and
y
is an ancestor of
z
in
T
, then
\textsf{torso}(x,z)
can be computed through
\textsf{torso}(x,y)
and
\textsf{torso}(y,z)
efficiently.

With this observation, we only need to store a subset of torsos in our oracle. We model this by a set of
shortcut edges
in
T
that when
x
is an ancestor of
z
,
x
can reach
z
through constant shortcut edges. Therefore, when
\textsf{torso}(x,z)
is needed, we just use the stored torsos on those shortcut edges to compute
\textsf{torso}(x,z)
. From
[
4
,
19
]
, we only need
n\alpha_{c}(n)
shortcut edges, and thus we only need to store
n\alpha_{c}(n)
(instead of
n^{2}
) torsos.

Patch sets.

Next, we introduce how our oracle can achieve
O(k)
optimal query time instead of
\text{poly}(k)
as in
[
23
]
with storing some additional information about
patch sets
. As standard local search in
[
23
]
still has
O(k^{2})
query time even in
(q,k)
-unbreakable graphs, it would be good to assume
G
is
(q,k)
-unbreakable below while still capturing the hardness and our ideas.

We define a collection
\mathcal{P}
of
patch sets
as follows. Start from an arbitrary vertex
v\in V
, we perform BFS in
V
from
v
until a set
P\subseteq V
with
(k+1)
vertices are visited. We add
P
to
\mathcal{P}
, delete
P
from
V
, and then repeat the procedure until there’s no connected component in
V
with at least
(k+1)
vertices. Finally, for each remaining component
P
, we add
P
into
\mathcal{P}
. We say
P\in\mathcal{P}
is
large
if
|P|=k+1
and
small
otherwise. A small patch set can only link to large patch sets.

We know that, for any failed vertex set
S
with size at most
k
, there exists at most one large component
C
in
G\setminus S
with
|C|>k
. We say a patch set
P\in\mathcal{P}
is
touched
if
P\cap S\neq\emptyset
, and
untouched
otherwise. For each vertex
v
that’s in an touched patch
P
, we do BFS from
v
in
G\setminus S
. By visiting at most
k+1
vertices in
O(k^{2})
time, we either find all vertices connected with
v
in
G\setminus S
, or certify
v\in C
. Since there are at most
k
affected components, the total update time will be
O(k\cdot k\cdot k^{2})=O(k^{4})
.

Then consider any vertex
u\in V
. If
u
is in an affected patch set
P
, we already know the component of
u
. If
u
is in an unaffected large patch
P
, we also know
u\in C
. Otherwise,
u
is in an unaffected small patch
P
. By enumerating at most
(k+1)
neighbors of
P
, if
P
is not a component itself, we will find some
u^{\prime}
that’s in a large patch set and connected with
P
. We can then compute the component of
u
by
u^{\prime}
. Therefore, given a query
u,v
, we can check if they are in the same connected component using
O(k)
time.

A

For a node

z\in\textsf{children}(x)
, we add a copy of the edge
(u,v)
for every pair of vertices
u,v\in\textsf{adh}(z)
in
\textsf{bgraph}(x)
. We call these edges
adhesion edges supported by
z
, and they would be labeled as such. Note that we allow multiple edges between some pair of
u,v\in\textsf{bag}(x)
supported by different children of
x
, which means that
\textsf{bgraph}(x)
is in fact a multigraph.

We claim that the total size of all bag graphs is linear to the total size of
G
.

Lemma 3.2
.

Let
\mathcal{T}=(T,\textsf{bag})
be a regular tree decomposition of
G
of adhesion
q
. Then we have the following.

1.

\sum_{x\in V(T)}|V(\textsf{bgraph}(x))|\leq O(qn)

2.

\sum_{x\in V(T)}|E(\textsf{bgraph}(x))|\leq O(m+q^{2}n)

Proof.

For the first bound, note that the vertex set of each
\textsf{bgraph}(x)
is
\textsf{bag}(x)
, and by definition we have
|\textsf{bag}(x)|=|\textsf{mrg}(x)|+|\textsf{adh}(x)|
for each bag. The margins of
\mathcal{T}
are all disjoint, so the total size of all margins would be exactly
n
. Note that since
\mathcal{T}
is regular, each margin is non-empty. Since each vertex is in the margin of exactly one node, we have that
|T|\leq n
as otherwise, there would exist at least one node
x
such that
\textsf{bag}(x)=\textsf{adh}(x)
. We also have
|\textsf{adh}(x)|\leq q
for all nodes
x
, then

\sum_{x\in V(T)}|V(\textsf{bgraph}(x))|=\sum_{x\in V(T)}|V(\textsf{mrg}(x))|+\sum_{x\in V(T)}|V(\textsf{adh}(x))|\leq n+n\cdot q=(q+1)n=O(qn)

For the second bound, in each
\textsf{bgraph}(x)
, first consider all edges whose two endpoints are both in
\textsf{mrg}(x)
, we call these edges
vital
. Note that each edge in
G
can be vital in at most one bag graph, so the total number of vital edges in all bag graphs is at most
m
. Each vertex in
\textsf{bgraph}(x)
has at most
q
edges incident to
\textsf{adh}(x)
as
|\textsf{adh}(x)|\leq q
. For each child
z
of
x
, the number of adhesion edges supported by
z
in
\textsf{bgraph}(x)
is at most
q^{2}
as
|\textsf{adh}(z)|\leq q
. Note that each node has at most one parent, thus

\sum_{x\in V(T)}|E(\textsf{bgraph}(x))|=m+\sum_{x\in V(T)}(q\cdot|V(\textsf{bgraph}(x))|+q^{2}\cdot|\textsf{children}(x)|)

=m+q\cdot\sum_{x\in V(T)}|V(\textsf{bgraph}(x))|+q^{2}\cdot\sum_{x\in V(T)}|\textsf{children}(x)|

\leq m+q(q+1)n+q^{2}|T|\leq m+q(q+1)n+q^{2}n=O(m+q^{2}n)

This concludes the proof.

Restricted bag graphs.

For a regular tree decomposition
\mathcal{T}=(T,\textsf{bag})
of
G
, a tree node
x
, and a subset
S\subseteq V(G)
, we define the
S
-restricted bag graph
of
x
, which is denoted by
\textsf{bgraph}_{S}(x)
and obtained in the following way. We start with
\textsf{bgraph}(x)
, and for each child
z
of
x
, we consider all adhesion edges supported by
z
. We remove a
z
-supported adhesion edge
(u,v)
from
\textsf{bgraph}(x)
if and only if there does not exist a
u
-
v
path in
G[\textsf{cone}(z)]\setminus S
. We obtain
\textsf{bgraph}_{S}(x)
after considering all adhesion edges. Note that
\textsf{bgraph}_{\emptyset}(x)=\textsf{bgraph}(x)
as
\mathcal{T}
is regular.

We now consider some vital properties of restricted bag graphs in unbreakable decompositions, captured in the following lemma.

Lemma 3.3
.

Let
\mathcal{T}=(T,\textsf{bag})
be a strongly
(q,k)
-unbreakable decomposition of
G
that is regular. Let
x\in V(T)
and
S\subseteq V(G)
where
|S|\leq k
, then the following properties must hold.

1.

For any
u,v\in\textsf{bag}(x)
, they are connected in
G[\textsf{cone}(x)]\setminus S
if and only if they are connected in
\textsf{bgraph}_{S}(x)
.

2.

Suppose
C\subseteq\textsf{bag}(x)
is a connected component in
\textsf{bgraph}_{S}(x)
where
|C|>q
. Let
C_{1},...,C_{\ell}
be the connected components in
\textsf{bgraph}_{S}(x)\setminus C
, then we have
\sum_{i=1}^{\ell}|C_{i}|\leq q
.

Proof.

Note that the property 1 directly follows from the construction of
\textsf{bgraph}_{S}(x)
. For property 2, let
C^{\prime}=\bigcup_{i=1}^{\ell}C_{i}
, and suppose that
|C^{\prime}|>q
. By property 1,
C
and
C^{\prime}
must be disconnected in
G[\textsf{cone}(x)]\setminus S
. Let
L
be the connected component in
G[\textsf{cone}(x)]\setminus S
such that
C\subseteq L
, and let
R=(\textsf{cone}(x)\setminus S)\setminus L
. Note that
C^{\prime}\subseteq R
. Then,
(L\cup S,R\cup S)
is a separation in
G[\textsf{cone}(x)]
of order at most
k
with separator
S
, where
|(L\cup S)\cap\textsf{bag}(x)|=|C|>q
and
|(R\cup S)\cap\textsf{bag}(x)|=|C^{\prime}|>q
, contradicting the unbreakability condition. Thus, we must have
|C^{\prime}|\leq q
. This finishes the proof.

Shortcutting of trees.

We now consider adding shortcuts to a tree. Formally, given a tree

, we want to add a small number of additional edges to

where

is an ancestor of

from

via
h
non-reversing edges where

is a constant. The non-reversing edges mean that every edge taken from

travels towards the root. This is called a

of the tree

with
hop-diameter

. From
[
4
,
19
]
we know that a good shortcutting can be computed efficiently on paths and trees. Explicitly, we can utilize the following theorem.

Theorem 3.5

(
[

,
4
]
)
.

Every tree of
n
nodes admits a shortcutting with hop-diameter

that uses
O(n\alpha_{h/2+1}(n))

O(n\alpha_{h/2+1}(n))
.

Although implicit in

,

]
, given any

, one can compute an

-hop path with shortcut edges in

constant time. Note that here

means inverse Ackermann function as in

]
. For example,

and
\alpha_{4}(n)=O(\log^{*}n)

4.1
Torsos and profiles

We now design data structures that allow quick evaluations of the connectivity between vertices in the adhesions of tree nodes that speed up update and query times.

First, we introduce the notion of torsos. For any
x,y\in V(T)
where
x
is a strict ancestor of
y
, we define the
torso graph between
x
and
y
, denoted by
\textsf{torso}(x,y)
, in the following way. The vertex set of
\textsf{torso}(x,y)
is
\textsf{adh}(x)\cup\textsf{adh}(y)
. Any two vertices
u,v\in V(\textsf{torso}(x,y))
are adjacent if and only if there exists a
u
-
v
path in
G[\textsf{cone}(x)\setminus\textsf{comp}(y)]
whose interior is disjoint from
V(\textsf{torso}(x,y))
. Note that any torso graph consists of at most
2k
vertices.

We often need torsos in the update and query phases. To do this quickly, we need a data structure that answers torso queries in constant time. We first show that we can compute all torsos quickly.

Claim 4.2
.

One can compute in
O(k^{3}n\log^{2}n+k^{6}n\log n)
time
\textsf{torso}(x,y)
for all
x,y\in V(T)
where
x
is a strict ancestor of
y
.

Proof.

We first build
\textsf{torso}(x,z)
for every pair
x,z\in V(T)
where
x
is the parent of
z
. Note that
V(\textsf{torso}(x,z))=\textsf{adh}(x)\cup\textsf{adh}(z)\subseteq\textsf{bag}(x)
. Consider the
\textsf{comp}(z)
-restricted bag graph of
x
, recall from
3.3
that two vertices in
\textsf{bag}(x)
are connected in
G[\textsf{cone}(x)\setminus\textsf{comp}(z)]
if and only if they are connected in
\textsf{bgraph}_{\textsf{comp}(z)}(x)
. Any pair of vertices in
\textsf{torso}(x,z)
are adjacent if and only if there is a path in
\textsf{cone}(x)\setminus\textsf{comp}(z)
that is internally vertex disjoint from
\textsf{adh}(x)\cup\textsf{adh}(z)
. Thus to determine the adjacency of vertices in
V(\textsf{torso}(x,z))
in
G[\textsf{cone}(x)\setminus\textsf{comp}(z)]
, we only need to determine if such path exists in
\textsf{bgraph}_{\textsf{comp}(z)}(x)
for each pair of vertices. We can obtain
\textsf{bgraph}_{\textsf{comp}(z)}(x)
explicitly by removing all
z
-supported adhesion edges in
\textsf{bgraph}_{\emptyset}(x)
since two vertices
u,v\in\textsf{adh}(z)
are connected in
G[\textsf{cone}(z)\setminus\textsf{comp}(z)]
if and only if they are adjacent in
G[\textsf{adh}(z)]
, and these adjacencies are represented by the normal edges in
\textsf{bgraph}_{\textsf{comp}(z)}(x)
.

These torsos are computed in the following way. For each
x\in V(T)
, consider a variant of
\textsf{bgraph}_{\emptyset}(x)
where for every adhesion edge
(u,v)
, we delete it and replace it with the edges
(u,w),(w,v)
where
w
is a new vertex. There are at most
k^{2}\cdot|\textsf{children}(x)|
adhesion edges in
\textsf{bgraph}_{\emptyset}(x)
since each child
z
of
x
has adhesion of size at most
k
thus supports at most
k^{2}
adhesion edges. Thus the number of vertices in this variant is at most
|V(\textsf{bgraph}_{\emptyset}(x))|+k^{2}\cdot|\textsf{children}(x)|
and it has at most
|E(\textsf{bgraph}_{\emptyset}(x))|+k^{2}\cdot|\textsf{children}(x)|
edges. We then use
3.4
to construct an vertex-failure connectivity oracle on this variant of
\textsf{bgraph}_{\emptyset}(x)
for each
x\in V(T)
and set
d=2k=O(k)
.

To build
\textsf{torso}(x,z)
we first consider each pair of vertices
u,v\in\textsf{adh}(z)
. Suppose
w
is the added vertex in the variant where
(u,w),(w,v)
replaced the
z
-supported adhesion edge
(u,v)
. To decide if any such pair
u,v
are adjacent in
\textsf{torso}(x,z)
, we update the oracle of
x
by giving the set
D=(\textsf{adh}(x)\cup\textsf{adh}(z)\cup\{w\})\setminus\{u,v\}
of failed vertices, and query if
u,v
are still connected after the update. We add the edge
(u,v)
to
\textsf{torso}(x,z)
if they are still connected. Note that this is correct because the query outputs connected if and only if there is a
u
-
v
path in
\textsf{bgraph}_{\textsf{comp}(z)}(x)
that is internally disjoint from
\textsf{adh}(x)\cup\textsf{adh}(z)
as we deleted all vertices in
\textsf{adh}(x)\cup\textsf{adh}(z)
and all
z
-supported adhesion edges by also deleting
w
. We do a similar process for the cases of
u\in\textsf{adh}(z),v\in\textsf{adh}(x)
and
u,v\in\textsf{adh}(x)
with the only difference being setting
D=(\textsf{adh}(x)\cup\textsf{adh}(z))\setminus\{u,v\}
instead as there is no such
w
in these cases. Then we have correctly computed
\textsf{torso}(x,z)
. Additionally, the updates are valid since
D\leq 2k
for all updates.

We now analyze the runtime of this procedure. Initializing the oracle for every variant of
\textsf{bgraph}_{\emptyset}(x)
by
3.4
in total takes time:

\sum_{x\in V(T)}2k\cdot(|E(\textsf{bgraph}_{\emptyset}(x))|+k^{2}\cdot|\textsf{children}(x)|)\cdot\log(|V(\textsf{bgraph}_{\emptyset}(x))|+k^{2}\cdot|\textsf{children}(x)|)

\leq 2k\cdot\sum_{x\in V(T)}(|E(\textsf{bgraph}_{\emptyset}(x))|+k^{2}\cdot|\textsf{children}(x)|)\cdot O(\log n)

=O(k\log n)\cdot(\sum_{x\in V(T)}|E(\textsf{bgraph}_{\emptyset}(x))|+k^{2}\cdot\sum_{x\in V(T)}|\textsf{children}(x)|)

\leq O(k\log n)\cdot((m+k^{2}n)+k^{2}n)=O(k^{3}n\log n)

Each update step takes at most
O(k^{4}\log n)
time and each query step takes
O(k)
time. There are
n
such
\textsf{torso}(x,z)
, and to build each we perform an update followed by a query for
k^{2}
times, so in total these steps take time
O(k^{6}n\log n)
. Thus we can construct all such
\textsf{torso}(x,z)
in
O(k^{6}n\log n)
time.

Now we build all
\textsf{torso}(x_{\ell},x_{1})
where
x_{\ell}
is a strict ancestor of
x_{1}
but
x_{\ell}\neq\textsf{parent}(x_{1})
. Let
x_{1},x_{2},...,x_{\ell}
be the
x_{1}
-
x_{\ell}
path in
T
. We construct the graph
H
on the vertex set
\bigcup_{i=1}^{\ell-1}V(\textsf{torso}(x_{i+1},x_{i}))
and the edge set
\bigcup_{i=1}^{\ell-1}E(\textsf{torso}(x_{i+1},x_{i}))
. Note that any
u,v\in V(\textsf{torso}(x_{\ell},x_{1}))
have a path in
G[\textsf{cone}(x_{\ell})\setminus\textsf{comp}(x_{1})]
that is interior disjoint from
\textsf{adh}(x_{1})\cup\textsf{adh}(x_{\ell})
if and only if such a path exists in
H
since each
\textsf{torso}(x_{i+1},x_{i})
maps the connectivity within
G[\textsf{cone}(x_{i+1})\setminus\textsf{comp}(x_{i})]
and any path that goes through
\textsf{torso}(x_{i},x_{i-1})
and
\textsf{torso}(x_{i+1},x_{i})
must pass some vertex in
\textsf{adh}(x_{i})
. This way we can construct
\textsf{torso}(x_{\ell},x_{1})
by performing BFS in
H
starting from each
v\in V(\textsf{torso}(x_{\ell},x_{1}))
, avoiding other vertices in
\textsf{adh}(x_{\ell})\cup\textsf{adh}(x_{1})
, to determine which other vertices

are reachable via a path that is internally disjoint from
\textsf{adh}(x_{\ell})\cup\textsf{adh}(x_{1})
, and add the edge
(u,v)
for all such reachable

.

Since each torso has at most
k^{2}
edges and
\ell\leq O(\log n)
by the depth of

, each BFS step takes
O(|E(H)|)\leq O(k^{2}\log n)
time. There are at most
n\log n
pairs of
x_{\ell},x_{1}
and to construct each
\textsf{torso}(x_{\ell},x_{1})
we need to perform
O(k)
BFS steps, so we can construct all these torsos in time
n\log n\cdot O(k)\cdot O(k^{2}\log n)=O(k^{3}n\log^{2}n)
. Combining with the previous procedure, we can build all torso graphs in
O(k^{3}n\log^{2}n+k^{6}n\log n)
time, completing the proof.

Now we design the following structure that outputs torsos in constant time when being queried.

Lemma 4.3
.

There is a data structure that uses
2^{O(k^{2})}+O(k^{2}n\alpha_{c}(n))
space, initializes in
O(k^{3}n\log^{2}n+k^{6}n\log n)
time, and answers the query in
O(1)
time: given
x,y\in V(T)
where
x
is a strict ancestor of
y
, outputs a pointer to the graph
\textsf{torso}(x,y)
.

Proof.

Each
\textsf{torso}(x,y)
has at most
2k=O(k)
vertices so storing it takes
O(k^{2})
space. Let
S_{t}
be the set of all possible graphs on
2k
vertices, then
|S_{t}|=2^{O(k^{2})}
, and we can store
S_{t}
using
O(k^{2})\cdot 2^{O(k^{2})}
space. We use
4.2
to compute all possible torsos. For each computed
\textsf{torso}(x,y)
we keep a pointer to
G_{t}\in S_{t}
where
G_{t}=\textsf{torso}(x,y)
for now.

Consider constructing a shortcutting of
T
using
O(n\alpha_{c}(n))
edges with hop-diameter
2(c+1)
by calling
3.5
. We aim to only store a pointer to
\textsf{torso}(x,y)
for any

where the edge
(x,y)
is in the shortcutting. This implies that we only need to store
O(n\alpha_{c}(n))
pointers of size
O(k^{2})
. To achieve constant time query, we build and store a two dimensional look-up table

indexed by pairs of torsos. For each computed
\textsf{torso}(x,y)=G_{t,1}
and
\textsf{torso}(y,z)=G_{t,2}
, we store the pointer to

in the entry
U(G_{t,1},G_{t,2})
where
G_{t}=\textsf{torso}(x,z)
. Then this table has at most
(2^{O(k^{2})})^{2}=2^{O(k^{2})}
entries. Given any torso query
x,y\in V(T)
where
x
is a strict ancestor of
y
, suppose
y,x_{1},x_{2},...,x_{h},x
is the
y
-
x
path in the shortcutting of

, so

. We can obtain
\textsf{torso}(x_{2},y)
by looking up

, and then we can obtain
\textsf{torso}(x_{3},y)
by looking up

. Thus we can get
\textsf{torso}(x,y)
by repeating this step
h
times along the path. Each look-up step takes constant time, so obtaining
\textsf{torso}(x,y)
takes
O(h)=O(1)
time.

Therefore, the structure uses
2^{O(k^{2})}+O(k^{2}n\alpha_{c}(n))
space to store all possible torsos, the table
U
, and the pointers. The initialization time is dominated by computing all torsos, which is
O(k^{3}n\log^{2}n+k^{6}n\log n)
, and torso queries can be answered in
O(1)
time, finishing the proof.

Next we introduce profiles, which maintain the connectivity of an adhesion within its subtree. For a node
x\in V(T)
, we define the
profile
of
x
, denoted by
\textsf{profile}(x)
, which is a graph on the vertex set
\textsf{adh}(x)
. Two vertices
u,v\in V(\textsf{profile}(x))
are adjacent if and only if they are connected in
G[\textsf{cone}(x)]\setminus S
where
S
is the set of failed vertices. Note that by this definition every connected component in each profile must be a clique as connectivity is transitive. As profiles are dependent on the set
S
of failed vertices, we do not build profiles directly in this section, but they will be constructed and used extensively in the update and query phases. In this section, we design the following data structure to compute profiles quickly from existing profiles and torsos.

Lemma 4.4
.

There is a data structure that uses
O(k^{2})\cdot 2^{O(k^{2})}
space, initializes in time
O(k^{2})\cdot 2^{O(k^{2})}
, and answers the query in
O(1)
time: given
\textsf{profile}(y)
and
\textsf{torso}(x,y)
, where
x
is a strict ancestor of
y
and
\textsf{comp}(x)\setminus\textsf{cone}(y)
is disjoint from
S
, output the following.

1.

The graph
\textsf{profile}(x)
.

2.

A coloring
\text{col}:\textsf{adh}(x)\cup\textsf{adh}(y)\rightarrow[O(k)]
where
\text{col}(u)=\text{col}(v)
if and only if
u,v\in\textsf{adh}(x)\cup\textsf{adh}(y)
are connected in
G[\textsf{cone}(x)]\setminus S
.

3.

A inverse coloring
\text{invcol}:[O(k)]\rightarrow\textsf{adh}(x)
such that
\text{invcol}(i)=v
where
v\in\textsf{adh}(x)
is an arbitrary vertex with
\text{col}(v)=i
.

Proof.

First note that
|V(\textsf{profile}(x))|\leq k
for any

, so
|E(\textsf{profile}(x))|\leq O(k^{2})
. There are
2^{k^{2}}
possible graphs on
k
vertices, we compute and store them explicitly in
k^{2}\cdot 2^{k^{2}}
time and space. Recall that each torso has at most
2k
vertices, so storing all possible torsos take
O(k^{2})\cdot 2^{O(k^{2})}
time and space.

Let
S_{t},S_{p}
be the set of all torsos and profiles. Next, we construct a 2-dimensional look-up table
U
, indexed by torsos and profiles. For each
G_{t}\in S_{t}
and
G_{p}\in S_{p}
we compute entry be
U(G_{t},G_{p})
in the following way. Construct graph
H
on the vertex set
V(G_{t})\cup V(G_{p})
and the edge set
E(G_{t})\cup E(G_{p})
. Then, perform BFS over
H
to identify its connected components. We construct the graph
H^{\prime}
on vertex set
V(H^{\prime})=V(G_{t})\setminus V(G_{p})
, and each pair of vertices
u,v
in this vertex set are adjacent if and only if they are in the same connected component in
H
. We assign an arbitrary coloring
\text{col}:V(G_{t})\rightarrow[O(|V(G_{t})|)]
such that only vertices in the same connected component in
H
have the same color. For each color
i
used, we assign
\text{invcol}(i)=v
where
v
is an arbitrary vertex
v\in V(H^{\prime})
such that
\text{col}(v)=i
(or
\text{invcol}(i)=\emptyset
if such
v
does not exist). Finally we set the entry
U(G_{t},G_{p})=(H^{\prime},\text{col},\text{invcol})
.

It is clear that computing one entry takes
O(k^{2})
time. Suppose that on a valid query
\textsf{torso}(x,y)
and
\textsf{profile}(y)
we have the entry
U(\textsf{torso}(x,y),\textsf{profile}(y))=(H^{\prime},\text{col},\text{invcol})
. By construction,
H^{\prime}
has vertex set exactly
\textsf{adh}(x)=V(\textsf{profile}(x))
, and two vertices
u,v\in\textsf{adh}(x)
are adjacent if and only if they are connected in

, thus

. The coloring

and inverse coloring

are also correct by the same argument.

U
has
|S_{t}|\cdot|S_{p}|=2^{O(k^{2})}\cdot 2^{k^{2}}=2^{O(k^{2})}
entries, each storing a graph of at most

time to compute along with a coloring and inverse coloring linear in its size. Thus, constructing the table

time and space. On query

4.2
Patch sets, processed bag graphs, and neighbor sets

To maintain and determine connectivity in update and query, the data structure relies heavily on bag graphs. More specifically, for every node

, we store a version of
\textsf{bgraph}_{\emptyset}(x)
that is preprocessed, along with the

of

, denoted by
\textsf{pset}(x)
. Each
\textsf{pset}(x)
contain
patches
, where a

P\subseteq\textsf{bag}(x)
is simply a subset of vertices. We add patches to
\textsf{pset}(x)
in the following way. Start by choosing an arbitrary vertex
v\in\textsf{bag}(x)
and perform BFS in
\textsf{bgraph}_{\emptyset}(x)
starting from
v
until
k+1
vertices, including
v
, are visited. Let
P_{1}
be a set that contains exactly these
k+1
visited vertices, remove
P_{1}
from
\textsf{bgraph}_{\emptyset}(x)
, include
P_{1}
in
\textsf{pset}(x)
, and repeat this process in
\textsf{bgraph}_{\emptyset}(x)\setminus P_{1}
. This is repeated until in
\textsf{bgraph}_{\emptyset}(x)\setminus(\bigcup_{P_{i}\in\textsf{pset}(x)}P_{i})
there is no connected component of size at least
k+1
. Finally, for any remaining connected component
C
, we include
C
as one patch in
\textsf{pset}(x)
.

We say a patch
P\in\textsf{pset}(x)
is

if
|P|=k+1
, and we say that it is
small
otherwise. Moreover, we call two patches
P_{i},P_{j}\in\textsf{pset}(x)

adjacent
to each other if and only if there exist some
u\in P_{i}
and
v\in P_{j}
such that
u
and
v
are adjacent in
\textsf{bgraph}_{\emptyset}(x)
. From the construction process, the following structural claim is clear.

Claim 4.5
.

For any
x\in V(T)
and its computed
\textsf{pset}(x)
, the following properties must hold.

1.

All patches in
\textsf{pset}(x)
are disjoint, and
\bigcup_{P_{i}\in\textsf{pset}(x)}P_{i}=\textsf{bag}(x)
.

2.

Any small patch
P\in\textsf{pset}(x)
can only be adjacent to big patches.

We then proceed with a simple processing of bag graphs. For each vertex
v\in\textsf{bag}(x)
, store in
\textsf{bgraph}_{\emptyset}(x)
a pointer along with
v
that points to
P_{v}
, where
P_{v}\in\textsf{pset}(x)
is the patch such that
v\in P_{v}
.

Along side this, we also store some neighbor sets of the patches. Let
N(P)
be the set of at most
k+1
vertices
v\in\textsf{bag}(x)
where
v\notin P
and there exists a normal edge
(u,v)
in
\textsf{bgraph}_{\emptyset}(x)
such that
u\in P
(if there are more than
k+1
such

, choosing an arbitrary subset of
k+1
of them suffices). We call

the set of

of
P
.

Moreover, for any patch
P\in\textsf{pset}(x)
, let

be the set of neighbors
v
such that there is an adhesion edge
(u,v)
in
\textsf{bgraph}_{\emptyset}(x)
where

and
v\notin P
. We call this the set of
adhesion neighbors
of

. Each set

stores at most
k^{3}+1
such vertices, and we implement it as a doubly-linked list such that deletion can be done in constant time. We store along with each vertex
v\in N_{\textsf{adh}}(P)
a counter indicating the number of adhesion edges
(u,v)
where
u\in P
.

Now, suppose
P_{1},...,P_{\ell}\in\textsf{pset}(x)
are all the small patches. We store with each

the set

and

. Furthermore, we claim that we can compute and store all patch sets, processed bag graphs, and neighbor sets of small patches in time and space linear to the size of

.

Lemma 4.6
.

One can in time
O(k^{3}n)
and space
O(k^{2}n)
compute and store the following.

1.

For every
x\in V(T)
, the patch set
\textsf{pset}(x)
and the processed
\textsf{bgraph}_{\emptyset}(x)
.

2.

For every
x
and each small patch
P\in\textsf{pset}(x)
, the neighbor sets
N(P)
and
N_{\textsf{adh}}(P)
.

Proof.

Recall from
3.2
that in
\mathcal{T}
the total size of all bags is at most
O(qn)=O(kn)
and the total size of all bag graphs is at most
O(m+k^{2}n)
. From
4.5
we know that for a
\textsf{pset}(x)
all patches are disjoint and cover
\textsf{bag}(x)
, thus
|\bigcup_{P\in\textsf{pset}(x)}P|=|\textsf{bag}(x)|
, so the total space to store all patch sets would be the same as the total size of all bags, which is
O(kn)
. We compute
\textsf{pset}(x)
by performing BFS procedures in
\textsf{bgraph}_{\emptyset}(x)
such that each edge is visited only once, so the total time required to computed all patch sets would be
\sum_{x\in V(T)}|E(\textsf{bgraph}_{\emptyset}(x))|=O(m+k^{2}n)
. Moreover, when processing each
\textsf{bgraph}_{\emptyset}(x)
, we only add one pointer for each vertex, so the space to store all processed bag graphs would still be
O(m+k^{2}n)=O(k^{2}n)
. This process can be done while we are computing patch sets.

In each
\textsf{pset}(x)
there can be at most
|\textsf{bag}(x)|
small patches. For each small patch

, at most
k+1
vertices can be in

. Hence storing all normal neighbor sets across all patch sets would require at most
O(k\cdot kn)=O(k^{2}n)
space. To compute

, we visit
2k+1
neighbors of each

if able, and for each neighbor
u
of
v

if it is not already included and
u\notin P
. We stop early when
|N(P)|=k+1
. This guarantees that if
P
has at most
k
neighbors, all of them would be in
N(P)
, and otherwise

would contain
k+1
arbitrary neighbors of
P
. This takes
O(k^{2})
time for each small patch
P
, so in total across all patch sets this takes
O(k^{2}\cdot kn)=O(k^{3}n)
time.

For each
x
, we next check each adhesion edge
(u,v)
in
\textsf{bgraph}_{\emptyset}(x)

P_{u},P_{v}
be the patches that contain
u,v
respectively. If

, we discard this edge and continue to the next one. Otherwise, we add
v
to
N_{\textsf{adh}}(P_{u})
and
u
to
N_{\textsf{adh}}(P_{v})
, incrementing the counters accordingly. We do not add an edge to a set if it already contains
k^{3}+1
vertices. There are at most
k^{2}\cdot|\textsf{children}(x)|
adhesion edges in
\textsf{bgraph}_{\emptyset}(x)
since each child of

supports at most
k^{2}
adhesion edges. Thus the total number of adhesion edges for in bag graphs is
\sum_{x\in V(T)}k^{2}\cdot|\textsf{children}(x)|=k^{2}n=O(k^{2}n)
, and we can compute all outgoing adhesion edge sets with
O(k^{2}n)
time and space.

Combining all of these, the total time required is
O(k^{3}n)
while the total space usage is
O(k^{2}n)
, which proves the lemma.

5
Update and query algorithms

In this section we prove the update and query time in

of failed vertices where

5.1
Update phase

Suppose we are given
S
, we first label all
v\in S
as ”failed” in
G
without deleting them or their incident edges. We then compute the set
X\subseteq V(T)
of all nodes
x\in T
that satisfy
\textsf{mrg}(x)\cap S\neq\emptyset
. This can be computed in
O(k)
time by including
x_{v}
in
X
for each
v\in S
by checking its pointer, where
x_{v}
is the unique node such that
v\in\textsf{mrg}(x_{v})
. Let
r
be the root of
T
, if

, we also include
r
in
X
. Note that
|X|\leq k+1
. Additionally, let
Y
be the lowest common ancestor closure of
X
, so
|Y|\leq 2|X|-1\leq 2k-1=O(k)
. We can compute

in
O(k^{2})
time by computing
\textsf{lca}(x,y)
using
4.1
and including it in

for every pair of nodes

.

We say that a node
x\in T(V)
is

if
x\in Y
. Furthermore, we call a node
x

if
\textsf{comp}(x)\cap S\neq\emptyset
, otherwise we call it

. We begin by providing a algorithm that allows us to determine connectivity between a subset of vertices of
\textsf{bag}(x)
within

quickly for any important node

.

Lemma 5.1
.

For a node
x\in V(T)
, given
\textsf{bgraph}_{S}(x)
and a subset of vertices
V(H)\subseteq\textsf{bag}(x)
, we can compute the graph
H
in time
O(k^{2}\cdot|V(H)|)
, where two vertices
u,v\in V(H)
are adjacent in
H
if and only if they are connected in
G[\textsf{cone}(x)]\setminus S
.

Proof.

From
3.3
we know that two vertices
u,v\in\textsf{bag}(x)
are connected in
G[\textsf{cone}(x)]\setminus S
if and only if they are connected in
\textsf{bgraph}_{S}(x)
, and that there exists a unique connected component
C\subseteq\textsf{bag}(x)
in
\textsf{bgraph}_{S}(x)
with
|C|>k
. Then we build the edge set of
H
as follows. We perform BFS in
\textsf{bgraph}_{S}(x)
starting from each
v\in V(H)
until
k+1
vertices are reached, avoiding failed vertices. We add an edge
(u,v)
in
H
for every
u
reached by

where

. If more than
k
vertices are reached,
v
must be in
C
, and we mark it as such. After this step has been repeated for all vertices in
V(H)
, we add edges between all pairs of
u,v\in V(H)
where both
u
and
v
have been marked that they are in
C
.

It is clear from the construction of

that any two vertices are adjacent in

if and only if they are connected in
\textsf{bgraph}_{S}(x)
and thus in
G[\textsf{cone}(x)]\setminus S
. Each
(k+1)
-step BFS takes
O(k^{2})
time, so processing all vertices in

takes
O(k^{2}\cdot|V(H)|)
time, completing the proof of this lemma.

Recall the definition of profiles, the next step is to compute
\textsf{profile}(x)
for all
x\in Y
.

5.1.1
Computing important profiles

We will compute these profiles in a bottom-up manner. We first focus on a general node
x\in V(T)
. Suppose
Z\subseteq\textsf{children}(x)
is the set of all affected children of
x
. The following claim describes how
\textsf{profile}(x)
is computed given the profiles of all nodes in

.

Claim 5.2
.

Let
x\in V(T)
be a node. Given the set
Z
and
\textsf{profile}(z)
for all
z\in Z
, one can compute
\textsf{bgraph}_{S}(x)
and
\textsf{profile}(x)
in time
O(k^{3})
.

Proof.

First note that
|Z|\leq|S|\leq k
as there are at most
k
vertices in
S
and the components of all affected children are pairwise disjoint. We will build
\textsf{bgraph}_{S}(x)
by removing edges from
\textsf{bgraph}_{\emptyset}(x)
. By the definition of
\textsf{bgraph}_{S}(x)
, only adhesion edges supported by the affected children need to be considered for deletion as
S
is disjoint from the components of children in
\textsf{children}(x)\setminus Z
. For every
z\in Z
, consider all adhesion edges supported by
z
. Recall that any such edge
(u,v)
is not deleted in
\textsf{bgraph}_{S}(x)
if and only if
u
and
v
are connected in
G[\textsf{cone}(z)]\setminus S
. Note that this is also exactly the definition of the edge set of
\textsf{profile}(z)
, which is provided. Thus for each such edge
(u,v)
, we delete it if and only if
(u,v)
is not in
\textsf{profile}(z)
, which can be checked in constant time. Since each
|\textsf{adh}(z)|\leq k
, there will be at most
|Z|\cdot k^{2}\leq k\cdot k^{2}=k^{3}
edges to consider, thus we can construct
\textsf{bgraph}_{S}(x)
in
O(k^{3})
time.

To build
\textsf{profile}(x)
, we need to decide for every pair

whether they are connected in

or not. We use
5.1
to compute
\textsf{profile}(x)
by giving as input the
\textsf{bgraph}_{S}(x)
that we just computed and

. Thus, we can obtain

in time

. Note that building both
\textsf{bgraph}_{S}(x)
and

take

Note that this lemma holds even when

has no affected children since in this case
\textsf{bgraph}_{S}(x)=\textsf{bgraph}_{\emptyset}(x)
.

Next, we need to compute the profiles of all affected children
Z
of
x
in order to compute
\textsf{profile}(x)
. The next lemma shows how
\textsf{profile}(z)
is computed for any non-important

from the important profiles in its subtree.

Claim 5.3
.

Let
z
be an affected child of
x
and suppose
z\notin Y
, given
\textsf{profile}(y)
for all
y\in Y
that are contained in the subtree

, one can compute
\textsf{profile}(z)
in time

.

Proof.

Let
y\in Y
be the topmost important node in the subtree of

rooted at

. It can be computed in
O(k)
time by considering every

and choosing the node with the smallest depth such that
\textsf{lca}(y,z)=z
. Note that
\textsf{comp}(z)\setminus\textsf{cone}(y)
is disjoint from
S
because otherwise there must be an important node

and
\textsf{lca}(y,y^{\prime})
will also be in

and have a smaller depth than

. Since we have
\textsf{profile}(y)
and can get
\textsf{torso}(z,y)
in constant time from

4.4
to compute
\textsf{profile}(z)
in constant time in this situation. This completes the proof.

With these tools, we can proceed with computing all important profiles.

Lemma 5.4
.

Given the set of important nodes
Y
, one can in time
O(k^{4})
compute
\textsf{profile}(x)
for all
x\in Y
.

Proof.

We begin by constructing the tree
T_{Y}
where
V(T_{Y})=Y
. For any two nodes
x,y\in Y
,
x
is the parent of
y
in
T_{Y}
if and only if it is a strict ancestor of
y
and the
x
-

path in
T
is disjoint from
Y
. Note that one can compute
T_{Y}
in
O(k^{2})
time using
lca
queries on
Y
. Then, for each leaf node
x
in
T_{Y}
, we can compute
\textsf{profile}(x)
using
5.2
by setting

as
x
must have no affected children.

Next, for any non-leaf node
x\in Y
, we compute the set

of its affected children in

by checking every

, and we include
\textsf{dir}(x,y)
in

if
\textsf{lca}(x,y)=x
. Note that this takes
O(k^{2})
time for all

. With this, we can build all important profiles bottom-up by repeating the following process until all of them are computed. First, use
5.3
to compute the profiles of all affected children

where the profile of every node in

to compute any

There are
O(k)

. Therefore, computing all important profiles takes

Note that in the process of computing all important profiles, for each

5.1.2
Computing adhesion connectivity graphs

Lemma 5.5

3.

We first consider computing

have the same color. For each used color

\text{invcol}(i)=v
by choosing an arbitrary

with

\text{invcol}(i)=\emptyset
if no such

exist.

It is clear that computing
\textsf{adhconn}(x)
with its coloring

and inverse coloring

takes

time for each

O(k)
important nodes, so computing these for all

takes
O(k\cdot k^{4})=O(k^{5})
time. This completes the proof.

5.1.3
Precomputing connectivity within bag graphs

To achieve fast query time, we precompute some vital connectivity information with regard to the patch set
\textsf{pset}(x)
of
\textsf{bgraph}_{S}(x)
, for every node
x
where
\textsf{profile}(x)
is computed. Note that
x
can either be an important node or an affected children of some important node. For any such

, we say a patch

is

if it either contains some vertex
v\in S
, or it contains both
u,v
for some adhesion edge
(u,v)
that is deleted during construction of
\textsf{bgraph}_{S}(x)
. Let

be the set of all touched patches in
\textsf{pset}(x)
.

Suppose

is the set of affected children of
x
. For every affected child

, the set of all
z
-supported adhesion edges form a clique in
\textsf{bgraph}_{\emptyset}(x)
on at most
k
vertices and
k^{2}
edges. Note that only at most

of these edges are vertex disjoint, so at most
O(k)
patches can be touched due to these

|A|\leq k+O(k\cdot k)=O(k^{2})
as
|S|\leq k
and there can be at most
|Z|\cdot O(k)\leq O(k^{2})
disjoint patches touched due to adhesion edge deletions.

Additionally, for each small patch

, we need to update the set

of adhesion neighbors for each small patch

due to the adhesion edge deletions in
\textsf{bgraph}_{S}(x)
. We need to compute

and update

for all small patches

before proceeding to the next step.

Claim 5.6
.

For a node
x\in V(T)
, given
\textsf{bgraph}_{S}(x)
, one can in time
O(k^{3})
compute the set
A
of affected patches and update the set

for each small patch

.

Proof.

We have
\textsf{bgraph}_{S}(x)
and
\textsf{profile}(z)
for all
z\in Z
where
Z
is the set of its affected children since
x\in Y
. We first check all vertices
v\in S
. For any

, we identify the patch
P_{v}
where
v\in P_{v}
by looking at its stored pointer and include it in

. Then we compute the set of deleted adhesion edges by comparing for each
z\in Z
the set of
z
-supported adhesion edges in
\textsf{bgraph}_{S}(x)
and
E(\textsf{profile}(z))
. For any deleted adhesion edge
(u,v)
, we check if they are in the same patch by comparing their pointers, and we include

if
u,v\in P
. It is clear that computing

take
O(k^{3})
time as there are at most
O(k^{3})
deleted adhesion edges.

We now update

for each small path
P
. For any deleted adhesion edge
(u,v)
in
\textsf{bgraph}_{S}(x)
, we consider the patches

and

are in. Let

be the patches containing

if the counter reaches zero. We do the same for

if it is small. We can compute this in
O(k^{3})
time as there can be at most

deleted adhesion edges in
\textsf{bgraph}_{S}(x)

Next, we precompute and store for each vertex in a touched patch whether it is in the unique connected component in
\textsf{bgraph}_{S}(x)
that has size more than

. If not, we label the vertex with the connected component it is in, formally stated in the following lemma.

Lemma 5.7
.

For a node
x\in V(T)
, given
\textsf{bgraph}_{S}(x)

v\in P
for each patch

whether it is in the single connected component

\textsf{bgraph}_{S}(x)
in the same time.

Proof.

Recall that each patch has size at most

, then the total number of vertices in touched patches is
|\bigcup_{P\in A}P|\leq|A|\cdot O(k)=O(k^{3})
. We first call

with
\textsf{bgraph}_{S}(x)
and

to obtain

that has been marked as in

Note that

by

since

as follows. For each vertex

be an arbitrary unused color in

if

starting from

5.1.4
Complete update process

Now we have finished every step in the update algorithm, let us summarize the complete update process below.

1.

Given the set of failed vertices
S
where
|S|\leq k
, compute the set of important nodes
Y
in
O(k^{2})
time.

2.

Compute
\textsf{profile}(x)
for all
x\in Y
using
5.4
. The profiles of all affected children of every
x\in Y
are also computed in this process.

3.

Compute
\textsf{adhconn}(x)
along with its coloring and inverse coloring for all
x\in Y
using
5.5
.

4.

Precompute bag graph connectivity information for every node
x
where
\textsf{profile}(x)
is computed by repeating
5.7
.

It is clear that the runtime of the update algorithm is dominated by step 4, where repeating
5.7
for all important nodes and their affected children takes
O(k^{5})\cdot O(|Y|)\leq O(k^{6})
time. This proves the update time guarantee in
1.2
.

5.2

Vertex-Cut Oracles

In this section, we discuss two problems closely related to the vertex-failure connectivity oracle problem: the
vertex-cut oracle
problem and its generalization, the
Steiner vertex-cut oracle
problem.

A
k
-vertex-cut oracle for an undirected graph

is a data structure that supports vertex-cut queries: given a set
F
of vertices with
|F|\leq k
, does
F
form a global vertex cut, or more generally, how many connected components does
G\setminus F
have? The more general Steiner
k
-vertex-cut oracles will further receive a set
A
of terminal vertices, and the corresponding Steiner-vertex-cut queries ask whether
A\setminus F
is disconnected in
G\setminus F
, or more generally, the number of connected components in
G\setminus F
intersecting
A
.

In what follows, we introduce simple reductions from these two problems to the vertex-failure connectivity oracle problem. These two reductions both work for the harder queries which ask for the number of connected components.

Theorem 8.1

(Refinement of
[
18
]
)
.

. Suppose there is a

-vertex-failure connectivity oracle of

, space

The reduction from vertex-cut oracles to vertex-failure connectivity oracles (

9
Discussions and Open Problems

The ideal bounds for a
k
-vertex-failure connectivity oracle are

O(\min\{m,nk\})\text{ space},\qquad O(m)\text{ preprocessing},\qquad O(k^{2})\text{ update},\qquad O(k)\text{ query}.

Long et al.
[
20
,
21
]

achieve all four bounds simultaneously up to
\polylog n
factors.
Moreover, each of these bounds is separately conditionally optimal under
standard hypotheses
[
12
,
20
]
. Thus, the main remaining
frontier is to remove the dependence on
n
from the update and query times
while keeping near-linear preprocessing and space.

Our oracle makes progress on this frontier. It has near-linear preprocessing,
uses

O(k^{2}n\alpha_{c}(n))

space, and supports updates and queries in small
\mathrm{poly}(k)
time. Currently,
the two known approaches to
n
-independent update and query times are the

algebraic approach
of
[
24
]
and the

unbreakable-decomposition approach
of

[
23
]
. The following challenges highlight what
seems to require new techniques.

1.

Near-linear space and preprocessing without exponential

k
-dependence.

The algebraic approach uses
\Omega(n^{2})
space, while current
unbreakable-decomposition based oracles incur exponential dependence on

k
in the preprocessing. Can one obtain

\widetilde{O}(n\mathrm{poly}(k))\text{ space}\quad\text{and}\quad\widetilde{O}(m\mathrm{poly}(k))\text{ preprocessing}

together with
\mathrm{poly}(k)
update and query time?

2.

Optimal
k
-dependence for updates and queries.

All known
n
-independent oracles have update time at least

k^{\omega}
or a larger polynomial in
k
. Can one achieve the
conditionally optimal update time
O(k^{2})
? More ambitiously, can this
be achieved simultaneously with the conditionally optimal query time

O(k)
?

3.

Exactly linear space in
n
.

Our shortcutting scheme reduces the space to

O_{k}(n\alpha_{c}(n))
, but still leaves the tiny
\alpha_{c}(n)
factor.
This factor appears tied to the constant-hop tree shortcutting used by
our method; see the shortcutting lower bounds in

[
3
]
. Pilipczuk et
al.
[
23
]
achieve
O_{k}(n)
space, but with
large polynomial preprocessing time and
2^{2^{O(k)}}
update and query
time. Can one obtain

O_{k}(n)\text{ space},\qquad\widetilde{O}_{k}(m)\text{ preprocessing},\qquad\mathrm{poly}(k)\text{ update and query time}?

Such a result would likely require a way to bypass our shortcut-based
technique.

The Query Algorithm.

Consider a query with a given
F\subseteq V
of at most
k
vertices. We want to determine the number of connected components in
G\setminus F
.

Let
{\cal T}
be the collection of subtrees in
T\setminus F
. For each subtree
\tau\in{\cal T}
, let
r_{\tau}
denote its root. Following
[
17
]
, we classify the subtrees into
internal subtree
and
hanging subtree
. A subtree
\tau\in{\cal T}
is a hanging subtree if
\tau
is exactly
T[r_{\tau}]
(equivalently, there is no
F
-vertex in
T[r_{\tau}]
), and all remaining subtrees are internal. For better understanding, we point out that there are at most
k
internal subtrees while the number of hanging subtrees can be very large. The answer to this query is given by the following observation.

Lemma A.2

(
[
17
]
)
.

The number of connected components in
G\setminus F
is the summation of the following.

(a)

The number of connected components in
G\setminus F
which contain at least one internal subtree.

(b)

The number of hanging subtrees
\tau
such that
\textsf{backvertex}(T[r_{\tau}])\subseteq F
.

The intuition behind
A.2
is that each hanging subtree
\tau
either forms a connected component on its own when
\textsf{backvertex}(T[r_{\tau}])\subseteq F
, or else it must connect to some internal subtree through a back edge. In what follows, we discuss how to compute
Item

(a)
and
Item

(b)
respectively.

Computing
Item

(a)
.
We first pick a set
X
of vertices

X:=\{\textsf{par}(v)\mid v\in F\}\setminus F.

Intuitively,
X
hits and only hits all internal subtrees: we can easily observe that
X
is a subset of the union of internal subtrees, and
X
contains at least one vertex from each internal subtree. Therefore,
Item

(a)
now equals the number of connected components in
G\setminus F
which contain at least one
X
-vertex. The latter can be computed by choosing an arbitrary vertex
x\in X
and then querying the vertex-failure connectivity oracle (
Item

1
) for the connectivity between
x
and every other
X
-vertex in
G\setminus F
. This involves one update operation to
Item

1
and
|X|-1=k-1
query operations to
Item

1
. Hence, computing
Item

(a)
takes
O(|F|)+\mathsf{U}+(|F|-1)\cdot\mathsf{Q}
.

Computing
Item

(b)
.
Observe that each hanging subtree
\tau
must have
\textsf{par}(r_{\tau})\in F
. Therefore, we can consider the children of
F
-vertices (called
F
-children
) instead. Note that not every child of an
F
-vertex is the root of a hanging subtree, and we call such children
bad
F
-children
(in fact, a bad
F
-child is either an
F
-vertex or the root of an internal subtree). Now,
Item

(b)
equals (i) the number of
F
-children
v
such that
\textsf{backvertex}(v)\subseteq F
, minus (ii) the number of bad
F
-children
v
such that
\textsf{backvertex}(v)\subseteq F
.

•

To compute (i), we can enumerate all
2^{|F|}
subsets
F^{\prime}
of
F
, and then query the dictionary (
Item

4
) of each
F
-vertex with the subset

. This takes
O(2^{|F|}\cdot k^{2})
time.

•

To compute (ii), we can first get all bad
F
-children explicitly in
O(k^{2})
time, by performing level-ancestor queries between every pair of
F
-vertices, because a vertex
w
is a bad

-child if and only if there exists two
F
-vertices

such that

and an ancestor of

. Then, we just check, for each bad

-child

, whether

or not (using

3

By the analysis above, the query time is bounded by
\mathsf{U}+|F|\cdot\mathsf{Q}+O(2^{|F|}\cdot k^{2})
.
