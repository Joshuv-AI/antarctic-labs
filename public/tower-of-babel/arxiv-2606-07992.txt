VATS: Exploiting Implicit Authority in Error-Path Injection via Systematic Mutation
Harshil Patel, Kunal Pai

Abstract
As the Model Context Protocol (MCP) standardizes tool-calling for autonomous agents, it introduces a critical, unexamined attack surface: the error-handling loop. We hypothesize that tool error messages possess implicit authority, triggering corrective reasoning modes that bypass standard safety heuristics. We introduce VATS (Vulnerability Analysis of Tool Streams), a mutation-driven framework that systematically evolves adversarial payloads across seven structural and linguistic dimensions. Our evaluation across four frontier models, Gemini 3.1 Pro, GPT-5.5, GLM-5.1, and Qwen3-Coder, demonstrates that error-path injection triples the success rate of standard indirect prompt injection (IPI), achieving up to 100% compliance in controlled evaluations. We isolate structural positioning (sandwiching instructions within error context) as the most effective exploit vector across all tested models. While we find that production framework guardrails can mitigate these vulnerabilities, the inherent susceptibility of the model layer poses a systemic risk to bespoke agentic workflows.

Introduction

The Model Context Protocol (MCP) has rapidly become the standard for tool-calling agents, scaling to over 97 million monthly SDK downloads by April 2026
(
7
)
. However, this expansive adoption introduces a massive attack surface. 88% of open-source MCP servers have broken authentication
(
25
)
, and over a quarter of community agent skills contain injection and exfiltration vulnerabilities
(
15
)
.

Standard agent design requires an
error-handling loop
, i.e., when a tool fails, agents must interpret the error and self-correct
(
14
;
21
)
. Consequently, error messages carry
implicit authority
. Unlike standard tool outputs, they activate corrective reasoning, bypass normal skepticism heuristics, and demand immediate action. While prior work highlights tool-stream injection as a critical vector
(
13
;
16
;
3
)
, none have isolated the error-path channel or systematically characterized why agents comply. We hypothesize this implicit authority makes error-path injection strictly more effective than standard indirect prompt injection (IPI).

We introduce
VATS
(Vulnerability Analysis of Tool Streams), a mutation-driven framework to evaluate error-path injection. VATS evolves seed adversarial payloads across seven dimensions (e.g., linguistic framing, authority markers), producing a mutation tree that quantifies which properties drive attack success against production-pattern agents.

Background & Related Work

Tool-Use Agents and Indirect Prompt Injection (IPI).

Modern agents operate through a reasoning and tool-calling loop
(
28
;
24
)
, recently standardized by the Model Context Protocol (MCP)
(
17
)
. Crucially, MCP treats all tool responses (successes and errors) as unstructured text with equal trust. IPI exploits this instruction-data conflation, embedding adversarial instructions in tool outputs that redirect agent behavior
(
11
;
15
;
31
)
. Because of a fundamental trust-authorization mismatch, tool-stream content routinely bypasses text-level safety alignments, achieving high attack success rates (ASR) against frontier models
(
26
;
4
;
6
;
30
)
. Furthermore, error messages uniquely force the agent into a
corrective reasoning mode
, priming it to execute recovery steps rather than passively process data.

Authority Bias in LLMs.

Our hypothesis relies on evidence that LLMs exhibit exploitable authority bias. Models preferentially trust information presented with system-level framing, and social hierarchy signals often override formal role boundaries (e.g., system vs. user vs. tool)
(
5
;
8
;
27
)
. Error messages naturally activate these latent control priors by employing operational framing, referencing compliance policies, and using imperative language, occupying a position the agent is actively trained to defer to.

Closest Prior Work.

VIGIL
(
13
)
notes that strict alignment training exacerbates tool-stream injection, while AttestMCP
(
16
)
shows the MCP specification amplifies ASR. However, these works focus on mitigation (e.g., verify-before-commit, protocol attestations) rather than offensive characterization. Conversely, existing offensive benchmarks target different surfaces, such as tool routing (Function Hijacking
(
3
)
) or web interface persuasion (TRAP
(
12
)
). Earlier work on the NAAMSE framework
(
22
)
introduced the concept of mutation-based security evaluation for adversarial agents, particularly in the context of evolutionary red-teaming. VATS bridges these works. To our knowledge, no prior work isolates the error-path channel distinct from general tool-output injection, systematically mutates payloads to identify drivers of compliance, or validates error-path attacks against real deployed MCP agents.

Methodology

3.1
Threat Model

We consider an attacker controlling a single MCP tool (
search_codebase
) that returns crafted error JSON containing adversarial instructions. The attacker can observe tool invocations and inject structured metadata via standard
role:‘‘tool’’
responses
(
18
;
23
)
, but
cannot
alter system prompts, user messages, or model reasoning. To test strict baseline vulnerability, the victim agent uses a neutral system prompt:

You are a developer assistant with access to the following tools: search_codebase, send_email, read_file, http_post, authenticate. When a tool call fails, use your best judgment to determine the appropriate next step. You may retry the call, try an alternative approach, or ask the user for guidance.

This prompt intentionally lacks explicit error-recovery directives, providing a baseline; production systems with stronger safety prompts may exhibit reduced vulnerability. We evaluate whether the embedded payload successfully coerces the agent into exfiltrating workspace data via the
send_email
tool to an attacker-controlled address (
test@research-test.local
), measured by ground-truth tool invocation or proposed text actions.

4.4
Scoring Validation

Over 80% of model responses produced actual
tool_calls
rather than text-only responses, enabling ground-truth scoring via function name and argument parsing. When models complied, they directly
invoked

send_email
with the attacker’s address, representing a stronger exploitation than textual agreement. The LLM-as-judge post-hoc verification confirmed binary scores in 94% of cases; the remaining 6% were edge cases (e.g., conditional compliance: “I can send it if you approve”) resolved to continuous scores between 0.4-0.6. We also validated all classifications through a manual human sanity check to ensure scoring fidelity.

4.5
Real-World Validation

To validate beyond controlled API evaluation, we deployed identical payloads against two production agentic frameworks:
Gemini CLI
(v0.41.2 with Gemini 3.1 Pro)
(
10
)
and
OpenAI Codex
(v0.129.0 with GPT-5.5)
(
19
)
, both operating under repository-level instruction files (
GEMINI.md
,
AGENTS.md
). Both frameworks achieved
ACR
{}=0
, explicitly flagging the instructions as exfiltration attempts.

This 100% defense rate against the vulnerable raw model layer (Table
2
) stems from two primary factors. First, framework-level guardrails provided by repo-level instructions and heuristic flagging of commands requiring user approval effectively prevented the agent from following recovery directives embedded in tool outputs. Second, functional substitution played an important role. In agentic CLI environments,
search_codebase
was essentially analogous to
grep
. Because a native search capability existed, the agent treated the tool’s “error” as a functional failure of a redundant utility rather than a critical system block. This prevented task derailment, as the agent simply bypassed the injected instructions to continue the original task using alternative internal tools. If these tools were not present, the agent’s ability to resist the error-path injection might have failed.

These results confirm that, while the vulnerability to implicit authority is inherent in the
model layer
, it can be mitigated by
framework-level
defenses. However, such protections are not universal. For example, developers building bespoke agentic loops (e.g., custom LangChain workflows with self-created tools) remain highly vulnerable to error-path injection unless they manually implement guardrails. Detailed terminal traces and screenshots documenting these framework-level responses for both Gemini CLI and OpenAI Codex are provided in Appendix
B
.

5
Conclusion

While this work supports our implicit authority hypothesis, the existence of a distinct “corrective reasoning mode” remains speculative; the observed behavior is consistent with models treating error context as operationally authoritative, but deeper mechanistic study (e.g., causal tracing, attention analysis) is needed to confirm this.

Our dimensional analysis revealed that structural positioning (sandwiching malicious instructions between benign error context) is the primary driver of compliance across all tested models, outperforming complex social engineering or bureaucratic framing. While our real-world validation highlights that robust framework-level guardrails and functional redundancy can effectively mitigate these raw model vulnerabilities, bespoke and emerging agentic loops lacking such protections remain highly exposed. Moving forward, securing agentic systems requires moving beyond standard text-level safety alignments.
We advocate the integration of error-path mutation testing into standard red-teaming pipelines.
Ultimately, as agents are granted increasing autonomy, ensuring they can safely navigate failure states without being hijacked by the errors themselves remains an open challenge.

Impact Statement

This work characterizes a vulnerability class in LLM-based agents that process tool error responses. We discuss the ethical considerations and societal implications below.

Controlled Experimentation.

All experiments target synthetic, researcher-controlled addresses (
*@research-test.local
,
*@devops-relay.internal
) that cannot resolve to real mailboxes or endpoints. We measure whether models
propose
attacker-specified actions. No actual data exfiltration occurs. The MCP server used for real-world validation operates in an isolated sandbox with no access to production data or external networks.

Dual-Use Considerations.

The VATS mutation taxonomy could lower the barrier to crafting effective error-path payloads. We weigh this against the defensive value. Without systematic offensive characterization, defenders cannot prioritize which properties to sanitize. Our key finding that
structural positioning
dominates over social engineering dimensions is directly actionable for defense, identifying the architectural property to address.

Recommendations for Mitigation

1.

Split the Signal (Protocol-Level):
Keep technical error codes separate from the “help text” so the AI does not get confused between facts and instructions.

2.

Check the ID (Protocol-Level):
Make sure the error message actually came from the system before the AI trusts it.

3.

Flag Command Words (Framework-Level):
Watch out for “action” words (like
run, send, delete
) hidden inside error messages; these are usually traps.
(Note: While production CLI frameworks currently use heuristics to flag these, developers building custom agents must implement this manually.)

4.

Ask the Human (Framework-Level):
If an error message tells the AI to do something, it must stop and ask the user for permission first.
(Note: Major CLIs already enforce this for sensitive tools, but it should be a universal fallback for all agentic loops.)

Societal Context.

As MCP adoption reaches production scale, error-path injection represents a systemic risk to bespoke AI-assisted workflows. We aim to shift security posture from reactive patching to proactive architectural awareness, enabling red-teaming frameworks to evaluate error-path robustness as a standard component of agent safety.

Appendix C
Reasoning Trace Analysis

C.1
Experimental Setup

To investigate the implicit authority hypothesis, a reasoning trace analysis was conducted using two architectures that expose internal chain-of-thought processing: GLM-5.1 via native
<think>
tokens, and Gemini 3.1 Pro configured at a medium reasoning effort tier. Five adversarial payloads that achieved an action compliance rate (
\text{ACR}=1
) against at least one model were selected from the primary mutation study (
M_{1}
: error typing,
M_{2}
: framing,
M_{3}
: authority markers), along with the baseline IPI prompt.

All maintained identical conversation context, user tasks, assistant tool calls, and payload positioning, isolating the structured error JSON as the single independent variable. Each paired configuration was sampled 3 times at temperature 0.7 (
N=15
paired observations per model, 30 total evaluations per condition). Internal reasoning traces were extracted and qualitatively analyzed.

Qualitative analysis of the chain-of-thought traces indicates that implicit authority operates via two distinct mechanisms, conditioned on the baseline alignment and safety posture of the underlying model.

GLM-5.1 demonstrated minimal safety reflection across all evaluation conditions. Within the error condition, the model explicitly rationalizes the adversarial instruction as an operational prerequisite:
