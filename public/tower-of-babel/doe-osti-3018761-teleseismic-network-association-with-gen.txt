ABSTRACT
In this report we investigate adapting the Graph Neural Interpretation Engine (GENIE) [1], an
associator developed for three-component dense monitoring networks, to regional to teleseismic
association using a sparse network of array stations. We expand GENIE’s input features to
include first-P detection time, azimuth, and slowness estimates. Additionally, we include a
probability of detection (PDET) term which measures a station’s likelihood of detecting an event.
To assess each feature’s relative importance, we train four models, each using an increasing set of
node features and find that the PDET models perform the best. We define two measures of event
complexity which demonstrate that all GENIE model versions perform better than the standard
backprojection stack.

1. INTRODUCTION

The Global Associator (GA) [2, 3], used for operational monitoring since the late 1990s, is
composed of a series of manually tuned heuristic processing modules to detect events, resolve
their association conflicts, relocate events, and discard events that fail event quality criteria. Due
to the dependencies between these heuristic modules, it is unlikely that adding additional
processing modules will increase performance on the hard-to-build events. Nonetheless, the GA
design provides a good starting point for development of new operational monitoring association
algorithms. For example, the Probabilistic Event Detection, Association, and Location (PEDAL)
[4] algorithm was developed as a candidate replacement for GA, simplifying many of the
processing steps and reducing the tuning parameter set. PEDAL was shown to perform as well as
GA, however, because it also requires manual tuning, optimal performance is unlikely to be
achieved for non-stationary signal environments due to the burden of manual re-tuning. In
contrast, the NETwork Vertically Integrated Seismic Analysis (NET-VISA) [5] associator, a
Bayesian machine learning model, utilizes the analyst-reviewed Late Event Bulletin (LEB) to
automatically tune its parameters, providing the ability to repeatedly re-tune the algorithm as
often as needed. NET-VISA has been shown to outperform GA and is currently in testing for
promotion to operational use [3].
Deep learning approaches have also been recently developed for local to near-regional
association. Of these, the Graph Neural Network Interpretation Engine (GENIE) [1], has
demonstrated state-of-the art results on several regional datasets [1]. We are interested in applying
GENIE to the GA regional to teleseismic network monitoring scenario to see if it can provide
similar performance improvements, however, doing so requires significant effort to update the
codes and develop training datasets. This report addresses some of these challenges as they apply
to GENIE’s spatial fitness modules (see Figure A-1):

 • Input features: GENIE’s input utilizes pick time and a P or S initial phase (iPhase) label
 such as those generated by PhaseNet [6], a deep learning signal detection model. As GA,
 PEDAL, and NET-VISA’s performance is mostly due to array stations, we leveraged the
 signal detection measurements output by the Detection and Feature eXtraction (DFX) [2]
 software that generates the input to GA. The DFX measurements include pick time,
 azimuth, and slowness, their uncertainties, and iPhase.
 • Training data: GENIE is trained using synthetic dataset generation codes designed for
 dense 3-component sensor networks. Similar to NET-VISA, we opted to utilize the LEB
 event locations and associations as our “ground truth.” We merged these data with the
 unassociated DFX arrivals for realistic background signal detection rates.
 • Technical challenges: Applying GENIE to global teleseismic monitoring with
 approximately 7,350 grid locations lead to large graph sizes causing slow model

 11

 convergence and occasional memory allocation errors during training. Sub-sampling the
 number of grid nodes for training corrected these issues.

1.1. GENIE

Figure A-1 shows the GENIE architecture and the subset of “spatial fitness” modules we utilize in
this study: the Data Aggregation, Bipartitie Read-in, Spatial Aggregation, and Spatial Direct
modules. Of these graph neural networks (GNN), the Data Aggregation module is the most
important as it generates the initial backprojection (BP) information from which all other modules

Plot (a) shows the Cartesian product graph in which the BP nodes are composed of arrival and

1.2.2. Node Features

GENIE’s original BP node feature consists of four BP time fitness values: 1) FT (P Phase), 2)
FT (S Phase), 3) FT (unknown as P), and 4) FT (unknown as S) [1]. The arrival’s iPhase which is
generated by the signal detection algorithm (e.g. PhaseNet [6] or DFX) determines the BP node
feature values. When the arrival iPhase is P (or S), the corresponding BP fitness is computed and
stored in index one (or two), and the other indices are set to zero. When an iPhase is not supplied,
indices one and two are set to zero and indices three and four are set to their corresponding BP
fitness values. This construction allows GENIE to optimally balance the use of iPhase
information relative to those arrivals with unknown iPhases, as unknown iPhase detections can
degrade associator performance.
In contrast with the original GENIE application, our BP node features consist of the data utilized
by GA and PEDAL:
 • FT , FAz , and FSlo fitness values.
 • A station-source location dependent probability of detection.
 • Masks indicating when the azimuth and slowness estimates were not measured for a given
 arrival.

 17

 • A station-type mask to differentiate between 3-component and array station backprojected
 data.
 • Time, azimuth, and slowness uncertainties.
Following GA and PEDAL, our single FT term is calculated only with first-P phases, i.e. Pg, Pn,
P, and PKP. GA will establish the event candidates by only using Pg, Pn, P, and PKP iPhase
arrivals, whereas PEDAL ignores the iPhase and backprojects all arrivals as first-P [2, 4]. We
opted to follow GA’s approach as it reduces the number of BP nodes, leading to smaller graph
sizes. As previously mentioned, Figures 1-2 and 1-3 show the utility of the azimuth and slowness
fitness terms. Motivated by PEDAL, the station-source location dependent probability of
detection (PDET) measures a station’s likelihood of being associated with a given source location.
These PDET functions, generated using 20 years of LEB station associations [4], reduce BP stack
sidelobes. Although not implemented in this study, replacing GENIE’s station K-NN graph with
one generated by the PDET information would be another option to explore.
The azimuth and slowness masks indicate when DFX generated a valid azimuth and slowness
measurement, signaling GENIE to ignore these fields when they are not defined. Because array
stations are mostly responsible for GA’s performance, we include a station-type mask to allow the
GNN to weight array station data with more importance, if beneficial. We include the time,
azimuth, and slowness uncertainties directly in the BP node features even though they are
incorporated in the FT , FAz , and FSlo terms (see 1.1). For large uncertainties, we reason GENIE
will better down-weight a given BP node’s influence with these values explicitly specified. The
uncertainties are re-scaled by their max values so their range is closer to [0,1].
To test the relative importance of these features we trained four different GENIE models, each
with an increasing number of features:
 • V1: Only the FT , FAz , and FSlo terms were included in the BP node.
 • V2: V1’s features plus the station-type, azimuth, and slowness masks.
 • V3: V2’s features plus the PDET term.
 • V4: V3’s features plus the uncertainty terms.
Finally, as our BP node features imply, this study will only focus on event detection with first-P
phases. The secondary association of the 20+ additional phases generated by GA will be left for
future work as it likely requires additional architecture updates to GENIE.

2. TRAINING DATA

2.1. Dataset Generation

GENIE’s original application utilized synthetic training data generation incorporating all aspects
of real-world datasets: 1) events are randomly sampled throughout the monitoring region with
various magnitudes; 2) the associated arrival onset times are randomly perturbed from their
predicted times; 3) associated arrivals are randomly dropped; 4) the station network is randomly
decimated; and 5) noise arrivals are randomly injected. To achieve good performance, the data
generation parameters such as the sensor network characteristics (i.e. true detection rate, true
detection observation accuracy, and false detection rates), and event parameters (i.e. location and
magnitude) must approximate the complexity of the real-world signal environment being targeted.
Establishing these parameters for the global regional/teleseismic network we are using would
require a significant effort. Thus, instead of adapting these dataset generation codes to the GA
signal environment, we used one year of analyst-reviewed LEB events, their associated arrivals,
and the unassociated signal detections generated by DFX. Our data generation process is as
follows:
For each LEB origin,
 1. Fetch all DFX arrivals within a 23 minute window from the origin time, OTime . Replace the
 DFX arrivals that were associated to the origin with their corresponding LEB arrivals and
 include LEB associated arrivals that the analyst manually picked. This ensures we have all
 possible first-P detections that can be associated to the origin and that we have the best
 associated arrival data.
 2. Reduce the arrivals to those with a first-P iPhase, i.e. Pg, Pn, P, PKP. This helps reduce each
 training sample’s graph size.
 3. Generate the BP query times centered on OTime . We used a time query range of [OTime - 60
 sec, OTime + 60 sec] sampled at 1 second increments.
 4. All additional origins from the LEB that are within the time query are included as ground
 truth sources for this sample.
 5. To account for iPhase errors, backproject each detection as Pg, Pn, P, and PKP and reduce
 by selecting the maximum combined fitness, i.e. FT FSlo FAz . For arrivals without an azimuth
 or slowness measurement, we set FSlo and FAz equal to 1. Note that for such arrivals, the
 GNN input value is set to -1 and the corresponding mask flag is set so the GNN can learn to
 ignore FSlo and FAz when they are undefined.

 19

 6. Eliminate BP source locations to reduce the graph size. This step can be optional depending
 on the number of arrivals, but we found that using the full set of source locations lead to
 slow training and could, in some instances, cause out-of-memory errors. To expedite our
 exploration, we limited the BP nodes to those with closest 500 source locations to a given
 LEB event. For samples containing multiple events, we include the union of the 500 closest
 grid locations for each event.
The above procedure leverages the best signal detection evidence via the LEB associations
(including analyst picks missed by DFX) while maintaining realistic nuisance signal rates, and
signal detection inaccuracies.

2.2. Dataset Metrics

To ensure our training samples were of sufficient quality, we used the BP stack and an outlier test
to define each training sample event’s level of detectability. Motivated by PEDAL’s event
detection algorithm which iteratively processes a set of arrivals by 1) generating the BP stack, 2)
selecting the maximum fitness grid point as the candidate event location, 3) estimating the event
candidate time, 4) removing all arrivals that associate well enough with this event candidate, and
5) looping back to step 1 to find additional candidates [4], we applied a one-pass Z-score outlier
test to determine likely candidate event locations. This method is simpler than that of PEDAL’s
detection algorithm, however, it proved effective for the purposes of reviewing the nearly 40,000
dataset samples. The candidate event locations, i.e. outlier source event locations, are constructed
as follows:

Using the outlier test and our event detection criteria, we examine the following input
characteristics:

 1. BP fitness value distribution: Ideally the BP detection fitness score would be maximized at
 the grid point closest to the target origin as this would lead to a simple peak finding
 algorithm, i.e. choose the grid location with the maximum fitness value. As noted, PEDAL’s
 event detection algorithm uses this selection criteria [4]. However, it is those events in
 which the closest grid point fitness value is not maximized with respect to other grid
 locations that will indicate 1) the suitability of the origin being a “good” training sample
 and/or 2) signal environment complexity indicating a harder-to-detect event.
 2. Associated arrival to total arrival ratio (AAR): We expect that as the ratio increases to one,
 i.e. 100% of the input arrivals are associated with the sample’s origin, it will be easier to
 detect.
 3. The maximum azimuthal gap between the associated station locations: A standard measure
 for event detectability. Small azimuthal gap events should, on average be easier to detect
 than those events with larger azimuthal gaps.

3. GENIE RESULTS

In this section we have limited our analysis to the GENIE V3 and V4 results as these models
outperformed the no-PDET feature models, i.e. V1 and V2. See Figures B-1 and B-2 in the
Appendix for the comparison.
Figure 3-1 compares the BP stack to the GENIE V3 and V4 model detection scores as they relate
to the AAR for the held-out training dataset test samples. Note that as opposed to the previous
section where the Z-score was applied to limit the candidate source grid nodes from the BP stack,
these distributions were computed from the training sample grid locations which were already
limited to the closest 500 grid points around an event. Hence, these distributions measure the
local fitness data around our test set event locations. As with the previous scaled detection score
box figures, the best possible distribution is a value of 1 with no variance, i.e. the detection grid
location always registers the largest fitness score among all grid locations.
The GENIE models outperform the BP stack for the lowest AAR bins (0 through .35), with
distributions that are more concentrated near the maximum value. The GENIE models also
perform better for AAR bins ≥ .35, relative to the BP stack, though the difference is less
pronounced. The GENIE V3 and V4 models generated comparable distributions across all AAR
bins. The V4 distributions were slightly more concentrated near the maximum values at bins 0
through .15. However, these distributions do not indicate a clear advantage of including time,
azimuth, and slowness uncertainties directly in the BP fitness nodes.
Figure 3-2 shows the BP stack, V3, and V4 fitness surfaces for a sample containing two events
with AAR values of .07 and .08. Both events are marked by an “X.” The northern hemisphere
event (LEB orid 6026204) at latitude 25.88 and longitude 128.5 had seven associations, and
southern hemisphere event (LEB orid 6032334) at latitude -38.48 and longitude -74.3 had eight
associations. As the sample contained 97 total arrivals from 46 stations, orid 6026204’s AAR and
 7 8
orid 6032334’s AAR were 97 = .07 and 97 = .08, respectively. All three fitness surfaces have
peaks around the two events, however the BP stack is spatially irregular, which is not ideal for a
peak finding algorithm. Additionally, its maximum fitness source location was approximately 20
degrees north of the southern hemisphere origin. In contrast the GENIE V3 and V4 models
generated comparable fitness surfaces with peaks concentrated near the two events. GENIE V3’s
maximum fitness was near the southern hemisphere origin (6026204), while GENIE V4’s
maximum was near the northern hemisphere origin. However, both models generated fitness
peaks that would likely lead to both events being detected.
As shown in Figure 3-2, we note that the GENIE models never generated fitness values lower than
.5. We believe this is due to our training examples not including negative samples, i.e. samples
without any events. However, further investigation is warranted.

4. CONCLUSION

In this report, we presented an approach to adapting GENIE, a graph neural network associator
designed for local to near-regional monitoring, to regional and teleseismic association using
arrays, which provide azimuth and slowness measurements in addition to arrival times. We
focused on the BP node features, and generating an effective training dataset from the Late Event
Bulletin (LEB).
Whereas GENIE’s original BP node features consisted of four time fitness values, we updated the
feature set to include several different fitness values, masks, and raw signal measurement data, all
of which are utilized by the Global Associator (GA) and Probabilistic Event Detection,
Association, and Location (PEDAL) algorithms. We trained four different GENIE versions, each
using an increasing number of the BP features to identify each feature’s effect on the spatial
fitness model performance. Of the four GENIE model versions, the PDET feature models, i.e. V3
and V4, performed the best.
In contrast to the original GENIE application in which training data was synthetically generated,
we utilized a year of analyst-reviewed events from the LEB. Our dataset construction method
guaranteed the best signal detections while also including realistic background detections
generated by the Detection and Feature eXtraction (DFX) software. We asserted our training
dataset’s quality by utilizing the Z-score outlier test to generate various event detectability
statistics. We related the stack fitness to each input sample’s associated arrival to total arrival ratio
(AAR). As the AAR increased to its maximum value of one, the BP stack fitness distribution
converged to its maximum value, supporting the claim that the AAR can be used to identify the
harder-to-detect events. We also related the stack fitness to each event’s associated station
azimuthal gap. The fitness distributions for azimuthal gaps ≤ 110 degrees were concentrated at
their maximum value, indicating these events were readily detectable. As the azimuthal gap
increased, the stack fitness distributions exhibited more variance, also suggesting these events
were harder-to-detect.
Using these metrics to compare our GENIE models to the BP stack, we found our models
outperformed the stack across all AAR and azimuthal gap values. Although we trained our
models on reduced set of grid locations, i.e. the 500 closest grid locations to each target event, we
presented an example showing their applicability to global event detection consisting of all 7,350
grid locations. The GENIE models localized the target event better than the BP stack, suggesting
that training with a reduced source location dataset can yield effective models for global event
detection.
Although this work was limited to GENIE’s spatial fitness modules, the results were encouraging
and motivate continued adaptation of GENIE for sparse network teleseismic montoring.
