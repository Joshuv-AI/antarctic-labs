Single-Source Shortest Paths and Almost Exact Diameter in Pseudodisk Graphs
Mark de Berg, Bart M.P. Jansen, Jeroen S.K. Lamme

Abstract
We study Single-Source Shortest-Path ( sssp ) on unweighted intersection graphs whose node set corresponds to a set 𝒟 \mathcal{D} of n n constant-complexity objects in the plane. We prove sssp can be solved in O ⁡ ( U ⁡ ( n ) ​ polylog ⁡ n ) O(U(n)\polylog n) expected time for any class of objects whose union complexity is U ⁡ ( n ) U(n) . In particular, we obtain an O ⁡ ( n ​ 2 α ⁡ ( n ) ​ log 2 ​ n ) O(n2^{\alpha(n)}\log^{2}n) algorithm for arbitrary pseudodisks, and an O ⁡ ( λ s + 2 ​ ( n ) ​ 2 O ⁡ ( log ∗ ⁡ n ) ​ log 2 ​ n ) O(\lambda_{s+2}(n)\hskip 0.56905pt2^{O(\log^{*}n)}\log^{2}n) algorithm for locally fat objects, where s s is the maximum number of intersections between any pair of boundary arcs of the objects, and λ t ​ ( n ) \lambda_{t}(n) is the the maximum length of a Davenport-Schinzel sequence of order t t on n n symbols. This significantly extends the class of objects for which sssp can be solved in O ⁡ ( n ​ polylog ⁡ n ) O(n\polylog n) time: so far, O ⁡ ( n ​ polylog ⁡ n ) O(n\polylog n) sssp algorithms were not even known for pseudodisks that are fat and convex and similarly-sized. Our second result concerns the Diameter problem, which asks for the maximum distance between any two nodes in a graph. Even for intersection graphs, near-quadratic algorithms are already difficult to obtain, and the O ⁡ ( n 2 ​ polylog ⁡ n ) O(n^{2}\polylog n) running time that follows from our sssp algorithm is the first near-quadratic running time for such general classes of intersection graphs. Obtaining subquadratic running time is even more challenging. We prove that the diameter of a set of arbitrary pseudodisks can be computed almost exactly , namely up to an additive error of 2, in O ~ ​ ( n 2 − 1 / 14 ) \tilde{O}(n^{2-1/14}) expected time. This generalizes and speeds up a recent algorithm by Chang, Gao, and Le (SoCG 2024) that works for similarly-sized disks (or similarly-sized pseudodisks that are fat and satisfy a strong monotonicity assumption) and runs in O ~ ​ ( n 2 − 1 / 18 ) \tilde{O}(n^{2-1/18}) time. To this end, we develop a so-called star-based r r -clustering for intersection graphs of pseudodisks—this is similar to an r r -division for planar graphs—which is interesting in its own right. Our star-based r r -clustering can also be used to obtain an almost exact distance oracle for pseudodisks that uses O ⁡ ( n 2 − 1 / 13 ) O(n^{2-1/13}) storage and has O ⁡ ( 1 ) O(1) query time.

Introduction

The
sssp
problem.

Single-Source Shortest-Path
(
sssp
) asks to compute
the distance from a given source node to all other nodes in a graph
\mathcal{G}=(V,E)
.
In an unweighted graph, the problem can be solved in
O(n+m)

time using breadth-first search, where
n:=|V|
and
m:=|E|
.

sssp
is one of the most fundamental algorithmic graph problems—perhaps even
the
most fundamental—and
it shows up as a subproblem in many applications.

We are interested in
sssp
on (unweighted)
intersection graphs
.
Let
\mathcal{D}
be a set of
n
objects in the plane. Then the intersection graph

\mathcal{G}^{\times}[\mathcal{D}]
has
\mathcal{D}
as its node set, and it has an edge between two objects
D,D^{\prime}\in\mathcal{D}

iff
D
intersects
D^{\prime}
. If the objects in
\mathcal{D}
are (unit) disks, then
\mathcal{G}^{\times}[\mathcal{D}]

is called a
(unit-)disk graph
. Similarly,
segment graphs
and

pseudodisk graphs
are intersection graphs where
\mathcal{D}
is a set
of line segments or pseudodisks, respectively.
(A
set of pseudodisks
is a set
\mathcal{D}
of
topological disks such that any two objects in
\mathcal{D}
are either
disjoint or their boundaries intersect in at most two points
[
29
]
.)
Since an intersection graph can have
\Omega(n^{2})
edges, solving
sssp
by
computing its edges explicitly and then running a BFS takes quadratic time in the worst case.
The edges of an intersection graph are defined implicitly, however, so
there is hope that
sssp
on intersection graphs can be solved in subquadratic time.
This is indeed possible for many types of objects.

One approach to obtain a subquadratic
sssp
algorithm is to implement BFS using a dynamic
(deletion-only) data structure for intersection queries
on the set
\mathcal{D}
. Given an object
D\in\mathcal{D}
at distance
j
from the source, we use
the data structure to find the not-yet visited objects that intersect
D

(which thus have distance
j+1
from the source) and delete them from the data structure.
For line segments there exists such a data structure (a partition tree) that has

\tilde{O}(n^{4/3})
preprocessing time
1
1

1

We use the
\tilde{O}

polylogarithmic factors.
and
\tilde{O}(n^{1/3})
query and update time. Thus,
sssp
on segment intersection graphs can be solved in
\tilde{O}(n^{4/3})
time.
This is likely optimal, since Hopcroft’s problem—given a set
L
of
n

and a set
P

n

by running

\mathcal{G}^{\times}[L\cup P]

A running time of

is conjectured to be optimal for Hopcroft’s problem,
and Erickson
[

actually proved an

For other types of objects, however, it is possible to achieve
O(n\polylog n)

For axis-aligned segments, for example, the approach sketched above immediately
gives an
O(n\polylog n)

For unit disks, Cabello and Jejčič

The semi-dynamic data structure of Efrat, Itai, and Katz

For arbitrarily-sized disks, Kaplan

[

Even more recently, Brewer and Wang

The algorithms of Klost and of De Berg and Cabello both rely on an

The algorithm of Brewer and Wang also relies on additively weighted

For pseudodisks, approaches

Observe that convexity of the pseudodisks does not guarantee this property.
Thus, the following question is still wide open: can

O(n\polylog n)

We answer these questions: all that is needed is that the

Our results and techniques on
sssp
.

We define an
object
to be a topological disk whose boundary consists of
constantly many
x
-monotone arcs, each of which is described by a polynomial
of constant maximum degree (plus its endpoints).
The assumption that the boundary arcs are

-monotone is without loss of generality,
since a constant-complexity arc can always be split into
O(1)

-monotone pieces.
We denote the maximum number of intersection points between any two boundary

Our

its expected running time is
O(U(n)\polylog n)

\mathcal{D}

U(|\mathcal{D}^{\prime}|)

It is well known that

for pseudodisks

]
, and that

U(n)=O(n\hskip 0.56905pt2^{O(\log^{*}n)})
for so-called locally

Theorem 1

Let

At a very high level, our algorithm follows the same approach as used by Klost
[
30
]

and by De Berg and Cabello
[
17
]
. Let
D_{\mathrm{src}}
be the source object,
define
L_{j}\subset\mathcal{D}
to be the set of objects at distance
j
from
D_{\mathrm{src}}
, and define

\mathit{union}(L_{j})
to be the union of the objects in
L_{j}
.
Then, instead of querying with each object
D\in L_{j}
to discover the objects in
L_{j+1}
,
we do the following: we identify a set
\mathcal{C}_{j+1}\supseteq L_{j+1}
of
candidate objects
,
and we determine which of them intersect
\mathit{union}(L_{j})
(and are thus in
L_{j+1}
).
The main challenges are
(i) to ensure that each object is a candidate only a few times, and
(ii) to determine efficiently which of the candidates in
\mathcal{C}_{j+1}
intersect
\mathit{union}(L_{j})
.
Klost
[
30
]
, and De Berg and Cabello
[
17
]
, heavily use the fatness of the objects
to overcome (i), and they use Voronoi diagrams (or, for fat triangles, intersection-detection data structures)
to overcome (ii). Hence, we must develop completely different tools.

Our main tool, which is useful to overcome both challenges, is what we call a
random stacking
.
This is a subdivision of
\mathit{union}(\mathcal{D})
obtained by adding the objects “on top of each other”
in random order; see
Figure 1
. The important properties of a random stacking
are that the expected number of faces of the subdivision is
O(U(n))
, that the expected
number of crossings between object boundaries and face boundaries is
O(U(n)\log n)
,
and that each face
f
is fully contained in at least one of the objects.
Our
sssp
algorithm will be guided by the stacking: to compute
L_{j+1}
we determine
the faces of the stacking that intersect
\mathit{union}(L_{j})
, we collect the objects
whose boundaries intersect the faces—these form the candidate set
\mathcal{C}_{j+1}
—and
then we determine which candidates intersect
\mathit{union}(L_{j})
.
The fact that each face is fully contained in at least one object helps us
to guarantee property (i) above. Turning these ideas into an
O(n\polylog n)
algorithm
is not easy, however, and requires several other ideas. For example,
we do not know how to compute the intersections between the object boundaries and the face boundaries
of a random stacking fast enough. Hence, we have to simplify the stacking
so that its faces do not have holes. Second, determining which candidates
intersect
\mathit{union}(L_{j})
is difficult, because
\mathit{union}(L_{j})
need not be connected and so

\mathbb{R}^{2}\setminus\mathit{union}(L_{j})
can have holes.
We therefore do this separately for each face
f
, which helps
because we can prove that each component of
f\setminus\mathit{union}(L_{j})
is simply connected.

The
Diameter
problem.

The
Diameter
problem, which asks for the maximum distance between any two nodes in a graph,
is another fundamental algorithmic problem on graphs. In general graphs, it can be solved
in
O(nm)
time by running
sssp

n
times, once with each node as the source. One can also use fast matrix multiplication
to obtain an
O(n^{\omega})
time algorithm, where
\omega\approx 2.37
is
the matrix-multiplication exponent, which is faster for
dense graphs. A major open problem has been whether there is a truly subquadratic algorithm for
sparse graphs. Cabello
[
8
]
achieved a breakthrough in this area
by showing that
Diameter
on planar graphs can be solved in
\tilde{O}(n^{11/6})
expected time.
(His algorithm even works for weighted graphs.) This was improved to
\tilde{O}(n^{5/3})

by Gawrychowski
et al.

[
26
]
.

For intersection graphs the situation is less rosy: even deciding
whether the diameter of an intersection graph of unit-length segments
is at most 3 cannot be done in
O(n^{2-\varepsilon})
time for any
\varepsilon>0
,
assuming the Strong Exponential-Time Hypothesis
[
6
]
.
The same holds for unit-size equilateral triangles.
For unit disks, Chan
et al.

[
9
]
recently presented
an
O(n^{2-1/18+o(1)})
algorithm for
Diameter
. (For arbitrarily-sized axis-aligned squares
and axis-aligned unit squares, they obtain
\tilde{O}(n^{2-1/12})
and
O(n^{2-1/8+o(1)})

running time, respectively.) It is still open whether
a subquadratic algorithm for
Diameter
exists for arbitrarily-sized disks.
In fact, even near-quadratic algorithms are rare: so far they only exist
for classes of objects for which
sssp
admits a near-linear algorithm.
Thus, our
sssp
algorithm for objects with near-linear union size provides
the first near-quadratic exact algorithm for
sssp
for pseudodisks
and for general fat objects.

The difficulty of
Diameter
led Chang, Gao and Le
[
14
]

to study the problem of computing the diameter
almost exactly
, namely,
up to an additive constant. They presented a subquadratic algorithm for
similarly-sized disks (and for similarly-sized
fat pseudodisks satisfying a strong monotonicity condition; see above). Their algorithm runs in
\tilde{O}(n^{2-1/18})
time
and it computes the diameter up to an additive error of 2. In the arXiv version
of the paper
[
13

, they improve the error to 1.
To obtain this result, they first prove that the so-called
distance VC-dimension

and the

of a pseudodisk graph are at most 4; see
[
14

so they do not require the pseudodisks to be fat, convex, or similarly sized.
They then describe a framework to compute the diameter almost exactly,
which requires two ingredients: an algorithm that computes a so-called

clique-based
r
-clustering
for the given graph class—this is a generalization
of
r
-divisions

[
23
]
for planar graphs—and an
O(n\polylog n)

sssp

They present an algorithm that computes a clique-based clustering
for similarly-sized fat pseudodisks, and an
sssp
algorithm for similarly-sized fat
objects satisfying a monotonicity condition.

Our results on
Diameter
.

To obtain a

algorithm for pseudodisks, we need to supply two
ingredients: a suitable

first contribution of our paper, as discussed above. For the former we observe

Preliminaries.

To focus on the algorithmic and combinatorial aspects of the problem,
and not on algebraic issues, we work in the real-RAM model of computation and
assume that all basic operations on boundary arcs—computing
the intersection points between two arcs, testing if a point lies above
an arc, et cetera—can be carried out in
O(1)
time.
This is common practice in computational geometry.

We denote the boundary and the interior of a compact set
R
—this can be an object,
a union of objects, or a face in a subdivision—by
\partial R
and
\mathit{int}(R)
, respectively.
For a subdivision
\mathcal{S}
, we use
|\mathcal{S}|

to denote its (combinatorial) complexity, that is, its total number of vertices,
edges (which can be constant-complexity arcs), and faces. Similarly,

|f|
denotes the complexity of a face
f
. With a slight abuse of nation,
we sometimes write
f\in\mathcal{S}
when
f
is a face of
\mathcal{S}
.

To simplify the presentation, we assume that the input set
\mathcal{D}
of objects is in
general position.
In particular, no three object boundaries pass through
a common point and all intersections between object boundaries are proper intersections.
(The latter assumption means that for any two distinct objects
D,D^{\prime}\in\mathcal{D}
, the
set
\partial D\cap\partial D^{\prime}
consists of finitely many points and that there are no tangencies
between object boundaries.)

Lemma 3

Let

Proof.

Let

Computing a stacking.

The stacking
\mathcal{S}_{\pi}(\mathcal{D})
can be computed by a divide-and-conquer algorithm.
To this end, let

be the ordering of the objects as specified by
\pi

We recursively compute a stacking

for the ordered set
\mathcal{D}_{1}:=\{D_{1},\ldots,D_{\lfloor n/2\rfloor}\}

\mathcal{S}_{2}
for the ordered set
\mathcal{D}_{2}:=\{D_{\lfloor n/2\rfloor+1},\ldots,D_{n}\}
.
Next, we compute the overlay of
\mathcal{S}_{1}
and
\mathcal{S}_{2}

\mathcal{S}_{1}

This can be done in
O((n_{1}+n_{2})\log(n_{1}+n_{2})+k)

[

where

\mathcal{S}_{1}
and
\mathcal{S}_{2}

and
k
is the number of intersections between the edges of
\mathcal{S}_{1}
and the edges of
\mathcal{S}_{2}

Observe that we can easily compute owners for the new faces:
faces labeled by a face from
\mathcal{D}_{1}
inherit the owner from that face,
and all other faces inherit their owner from the corresponding face in
\mathcal{D}_{2}
.
To finish the construction of
\mathcal{S}_{\pi}(\mathcal{D})

it remains to merge adjacent faces of the overlay that are contained
in the same face of

\mathcal{D}_{2}
hide those of
\mathcal{D}_{1}

so we must undo the partitioning of the faces in

We obtain the following lemma.

Lemma 5
.

Let
\mathcal{D}
be a set of
n
objects from a family of objects with union complexity
U(n)
.
Then we can compute in
O(U(n)\log^{2}n)
expected time a stacking
\mathcal{S}_{\pi}(\mathcal{D})
,
including an owner for each face of
\mathcal{S}_{\pi}(\mathcal{D})
, such that
|\mathcal{S}_{\pi}(\mathcal{D})|=O(U(n))
.

Proof.

Consider the algorithm described above. Because
\mathcal{D}
is randomly ordered,
we can assume in our analysis that
\mathcal{D}_{1}
and
\mathcal{D}_{2}
are randomly ordered as well.
Thus,
\mathbf{E}[|\mathcal{S}_{1}|]=O(U(n))
and
\mathbf{E}[|\mathcal{S}_{2}|]=O(U(n))
.
Now observe that if an edge

of
\mathcal{S}_{1}
intersects an edge

of
\mathcal{S}_{2}

then
e_{1}\cap e_{2}
is a point of one of the sets

defined in
4

Hence,
\mathbf{E}[k]=O(U(n)\log n)
, where
k
denotes the number of intersections between
the edges of
\mathcal{S}_{1}
and the edges of
\mathcal{S}_{2}
. The expected time needed for the merge step
is therefore
O(U(n)\log n)
. Since the recursion depth is
O(\log n)
and each object
is handled once at each level of the recursion, by linearity of expectation
the total expected running time of our algorithm is
O(U(n)\log^{2}n)
.

The algorithm as described so far computes a stacking whose
expected

complexity is
O(U(n))
. This can be turned into an algorithm that is guaranteed
to compute a stacking with the desired complexity in a standard manner:
simply repeat the algorithm until a stacking of at most twice the expected complexity
is reached. This increases the expected running time by a factor 2.
∎

Simplified stackings.

Computing a stacking can be done efficiently, as we just saw, but
computing the conflict lists is more challenging. We would like to do this

\partial D_{i}

n

Theorem 7
.

Let
\mathcal{R}
be a set of
x
-monotone red arcs that are the edges of a connected planar subdivision,
and let
\mathcal{B}
be a set of
x
-monotone blue arcs.

\mathcal{R}\cup\mathcal{B}
.
Then we can solve the red-blue intersection problem on
\mathcal{R}\cup\mathcal{B}
in
O(\lambda_{s+2}(m+k)\log m)

expected time, where
m:=|\mathcal{R}|+|\mathcal{B}|
and
k
is the number of purple intersections.

Proof.

We first sketch the algorithm of Har-Peled and Sharir
[
27
]
,
which was designed for the setting where both
\mathcal{R}
and
\mathcal{B}
are connected sets, and then we
adapt it to our setting.

The algorithm sweeps a vertical line
\ell
from left to right over the plane, with the goal of
maintaining
visibility pairs
, which are pairs consisting of a red arc
\rho

and a blue arc
\beta
that see each other along
\ell

at a given position of
\ell
is a pair
(\rho,\beta)\in\mathcal{R}\times\mathcal{B}
such that both
\rho
and
\beta
intersect
\ell

and the segment that connects
\rho
to
\beta

does not intersect any other arc.)
Observe that for any purple intersection

, the pair

(\rho,\beta)
is a visibility pair just before the sweep line reaches
x
,
so it is enough if we test a pair of curves for intersection
whenever it become a visibility pair.

Maintaining the visibility pairs is done as follows.
Let
\mbox{\sc vd}(\mathcal{R})
denote the vertical decomposition of the red arrangement
\mathcal{A}(\mathcal{R})
,
and let
\mbox{\sc vd}(\mathcal{B})
denote the vertical decomposition of the blue arrangement
\mathcal{A}(\mathcal{B})
.
With a slight abuse of terminology, we refer to the faces in these vertical decompositions
as (red or blue)
trapezoids
. A red trapezoid is called
hot
if it is
intersected by a blue arc, and a blue trapezoid is called hot if it is intersected by a red arc.
The algorithm sweeps over the two arrangements
\mathcal{A}(\mathcal{R})
and
\mathcal{A}(\mathcal{B})

in parallel—in other words, it performs two simultaneous sweeps that use the same sweep line
\ell
—and
while doing so, it constructs the hot trapezoids that intersect the sweep line.
(It does not construct the entire arrangements
\mathcal{A}(\mathcal{R})
and
\mathcal{A}(\mathcal{B})
,
which would be too costly.)
Note that if
(\rho,\beta)
is a visibility pair, then the vertical visibilities between

\rho
and
\beta
occur inside trapezoids that are hot in
\mbox{\sc vd}(\mathcal{R})
as well as in
\mbox{\sc vd}(\mathcal{B})
.
Thus, as explained by Har-Peled and Sharir
[
27
]
,
we can detect all visibility pairs—and, hence, all purple intersections—if we can
construct all hot trapezoids.

Har-Peled and Sharir then argue (Lemma 7.2) that the total number of hot blue trapezoids
is
O(\lambda_{s+2}(m+k))
and that they can be constructed in
O(\lambda_{s+2}(m+k)\log m)

expected time in an online fashion during the sweep. In their argument, it is essential
that the red arcs form a connected set. The red arcs are also connected in our setting, so we can
implement the construction of the blue hot trapezoids in exactly the same manner.
Har-Peled and Sharir can apply the same argument to the hot red trapezoids, because in
their setting the blue arcs also form a connected set. In our setting, the blue set need
not be connected. But since the red arcs
are the edges of a subdivision, the entire vertical decomposition
\mbox{\sc vd}(\mathcal{R})
has

O(m)
complexity.
Thus, the number of hot red trapezoids is not larger than for Har-Peled and Sharir.
This suffices to reach the same time bound, as they present an argument
that charges the time spent for the simultaneous sweep to hot red or blue trapezoids and purple intersections.

We conclude that the expected running time in our setting is the same
as in the setting of Har-Peled and Sharir, namely
O(\lambda_{s+2}(m+k)\log m)
, which
proves the theorem.
∎

3
Almost exact diameter

We now turn our attention to the
Diameter
problem. As explained in the introduction,
we will use the framework of Chang, Gao and Le
[
14
]
. This requires two
main ingredients: a near-linear
sssp
algorithm and a so-called
r
-clustering.
The former was presented in the previous section, the latter will be presented below.

3.1
Star-based
r
-clusterings

Many graph problems can be solved efficiently using a suitable decomposition of the input graph.
For planar graphs, the
r
-divisions introduced by Frederickson
[
23
]

are a widely-used example of such a decomposition.
An
r
-division
of a planar graph
\mathcal{G}=(V,E)
is a pair
(\mathcal{C},S)

where
\mathcal{C}
is a collection of (not necessarily disjoint) subsets of
V
, called
regions
,
and
S\subseteq V
is a set of
boundary nodes
, with the following properties.

1.

Every node in
V
belongs to at least one region
C\in\mathcal{C}
, that is,
\bigcup_{C\in\mathcal{C}}C=V
.

2.

Every region
C\in\mathcal{C}
contains at most
r
nodes.

3.

Let
C^{\circ}:=C\setminus S
be the set of
interior nodes
of a region
C\in\mathcal{C}
.
Then a node
v\in C^{\circ}
does not appear in any other region, and all of its neighbors are contained in
C
.

Lemma 16

(Lemma 2 from
[
23
]
)
.

For any
n
-node planar graph, we can compute in
O(n\log n)
time an
r
-division consisting of

O(n/r)
regions with
O(\sqrt{r})
boundary nodes each.

Intersection graphs do not admit
r
-divisions with the bounds from

16
for
r=o(n)
, since they can have arbitrarily large cliques.
This led Chang, Gao, and Le
[
14
]
to introduce
clique-based
r
-clusterings
,
where the boundary consists of a small number of cliques instead of individual nodes.
We generalize this to
star-based
r
-clusterings
, as defined next.

Let
\mathcal{G}=(V,E)
be a connected graph.
Following Chang, Gao, and Le, we need the regions in our
r
-division of
\mathcal{G}
to be connected.
Thus, we define a
cluster
to be a subset
C\subseteq V
such that
the induced subgraph
\mathcal{G}[C]
is connected, and we use the term
r
-clustering

instead of the term
r
-division. For a node
v\in V
, we define
\mathrm{star}(v)
to be the closed neighborhood of
v
.
With a slight abuse of terminology (since there can be edges between the neighbors
of
v
) we refer to
\mathrm{star}(v)
as a
star
.
Our clustering is
star-based
, meaning that the cluster boundaries
consist of stars. It is defined as
follows; see
Figure 4

Definition 17
.

Let
\mathcal{G}=(V,E)
be a connected graph with
n

be an integer with

.
A

r

consists of a set
\mathcal{C}
of clusters
together with a set

of star centers for each

1.

Every node in
V
belongs to at least
one cluster
C\in\mathcal{C}
, that is,
\bigcup_{C\in\mathcal{C}}C=V
.

2.

Every cluster
C\in\mathcal{C}
contains at most
r

3.

Define the boundary of a cluster

\partial C:=C\cap\bigcup_{v\in S(C)}\mathrm{star}(v)
and define its interior

.
If a node

has a neighbor in

then

also has a neighbor in

We call

of the clustering, we call

of the clustering,
and we call

of the clustering.

In the remainder of this section we will prove the following theorem.

Theorem 18
.

Let
\mathcal{D}
be a set of
n
constant-complexity objects from a family of objects with
union complexity

s

and for which the intersection graph

A star-based
r
-clustering of

and global boundary complexity

It is important to note that while the definition of a star-based

\mathcal{C}
of clusters and the set

Remark.

Chang, Gao, and Le
[
14

presented an algorithm to compute a clique-based

restricted family of objects, namely constant-complexity pseudodisks that are similarly-sized and fat.
Besides the obvious fact that their cluster boundaries consist of cliques

3.2
The
Diameter
algorithm

We now present an algorithm to approximate
the diameter of the intersection graph
\mathcal{G}:=\mathcal{G}^{\times}[\mathcal{D}]
of a set
\mathcal{D}
of pseudodisks, up to an additive error of 2.
Note that the objects in
\mathcal{D}
must be pseudodisks;
it is not sufficient if their union complexity
U(n)
is near-linear.
Also recall that
U(n)=O(n)
for pseudodisks.
In the following, it will be convenient to denote the node set of
\mathcal{G}^{\times}[\mathcal{D}]
by
V

(even though
V=\mathcal{D}
).

Let
d(u,v)
denote the hop distance between two nodes
u,v
in
\mathcal{G}
.
Recall that the
eccentricity
of a node
u
is defined as

\operatorname{ecc}(u):=\max_{v\in V}d(u,v)
. Thus,
\diam(\mathcal{G})=\max_{u\in V}\operatorname{ecc}(u)

and it is sufficient to approximate the eccentricity of each node
u\in V

up to an additive error of 2.
Following the framework of Chang, Gao, and Le
[
14
]

we will approximate the eccentricities using an (in our case star-based)
r
-clustering
and using so-called patterns, as introduced by Fredslund-Hansen, Mozes, and Wulff-Nilsen
[
24
]
.
The concept of patterns has also been used in earlier works
[
31
,
41
]
.

Patterns.

Let
Q=\langle q_{0},\dots,q_{k-1}\rangle
be a sequence of (not necessarily neighboring)
nodes in a given graph
\mathcal{G}
. The
pattern of a node
v
with respect to
Q
is the

k
-dimensional vector
P_{v,Q}
such that

P_{v,Q}[i]=d(v,q_{i})-d(v,q_{0})
for every
0\leqslant i\leqslant k-1
.
The distance between some node
u
and a pattern
P_{v,Q}
is defined as
d(P_{v,Q},u):=\min_{i}\{d(u,q_{i})+P_{v,Q}[i]\}
.

Observe that if two nodes
u,v
have the same pattern with respect to
Q
,
then
d(u,q_{i})=d(v,q_{i})+\delta
for all
i
, where
\delta:=d(u,q_{0})-d(v,q_{0})
.
Hence, either all distances from
u
to the nodes in
Q
are the same as the distances from
v
,
or they are all larger, or they are all smaller.
This can be used to speed up the diameter computation for a planar graph
\mathcal{G}
, as follows.
Let
C
be a region in an
r
-division
(\mathcal{C},S)
of
\mathcal{G}
, and suppose we want to determine
the node
v\not\in C
that is furthest away from any of the nodes in
C
.
Then, by the observation just made, we only need to consider one node for each pattern
with respect to
Q:=C\cap S
, namely the node
v
with the largest distance to that pattern.
This is true because any path from a node outside
C
to a node in
C
must pass through a node in
Q
.

In our setting, we have a pseudodisk graph and we will use a star-based
r
-clustering
\mathcal{C}
.
For each cluster
C
we take
Q
to be an arbitrary ordering of the nodes in
S(C)
.
The properties of a star-based
r
-clustering do not guarantee that any path
from a node outside
C
to a node in
C
must pass through a node in
S(C)
but
observe that for nodes
u
and
v
for which a shortest path
\pi(u,v)

goes through a node (which is a star center) in
Q
, we have
d(u,v)=d(P_{v,Q},u)+d(v,q_{0})
.
When
\pi(u,v)
visits a node adjacent to a node in
Q
,
then we have a slightly weaker guarantee, as stated in the following lemma.
The lemma is similar to Lemma 16 by Chang, Gao, and Le
[
14
]
.

Lemma 22
.

Let
Q
be an arbitrary sequence of nodes in a graph
\mathcal{G}
.

(i)

For any two nodes
u,v\in V
we have
d(u,v)\leqslant d(P_{v,Q},u)+d(v,q_{0})
.

(ii)

If there is a shortest path
\pi(u,v)
that contains a neighbor of
a node in
Q
, then we additionally have
d(P_{v,Q},u)+d(v,q_{0})\leqslant d(u,v)+2
.

(iii)

If there is a shortest path
\pi(u,v)
that contains a node in
Q
, then

d(P_{v,Q},u)+d(v,q_{0})=d(u,v)
.

Proof.

Because
d(P_{v,Q},u)+d(v,q_{0})
is the length of a valid path between
u
and
v
—namely
a path via a node in
Q
—we have
d(u,v)\leqslant d(P_{v,Q},u)+d(v,q_{0})
.
This proves (i).

Now suppose
\pi(u,v)
contains a node
w
that has a neighbor
q\in Q
.
Note that
d(P_{v,Q},u)+d(v,q_{0})\leqslant d(u,q)+d(q,v)

because
q\in Q
. Because
w
and
q
are neighbors, we have

d(u,q)+d(q,v)\leqslant d(u,w)+d(w,v)+2=d(u,v)+2,

which proves part (ii) of the lemma. Part (iii) follows in a similar manner.
∎

To be able to make use of the above lemma we need the following result.

Lemma 23
.

Let

be a path in
\mathcal{G}
that starts at a node

that is a node in

Consider the first node

of

that does not belong to

such a node exists since
v\notin C
. Let

be the predecessor of
w
,
which therefore belongs to

then, by definition,

is in

itself or

.
Hence, we are done in this case. If

then, by Property

∎

23
can be used to argue that patterns can
provide us with a good approximation of distances. To use patterns efficiently, however,
we need that there are not too many patterns for a given sequence
Q
.
Chang, Gao, and Le
[
14

prove that this is indeed the case
for pseudodisk graphs. They show (Theorem 14) that the so-called distance
encoding VC-dimension of pseudodisk graphs is 4—this is where we need
the objects to be pseudodisks and not just any family with near-linear union complexity.
They then combine this
with earlier results on the number of different patterns when the VC-dimension
is bounded (Lemma 15). This results in the following lemma.

Lemma 24

(combines Theorem 14 and Lemma 15 from
[
14
]
)
.

Let
\mathcal{D}
be a set of pseudodisks and
Q
be a sequence of
k
vertices in
\mathcal{G}^{\times}[\mathcal{D}]
.
Let
\mathcal{P}:=\{P_{v,Q}:v\in V\}
be the set of all patterns with
respect to
Q
. If
d(q_{0},q_{i})\leqslant\Delta
for every
1\leqslant i\leqslant k-1
,
then
|\mathcal{P}|=O((k\cdot\Delta)^{4}).

The algorithm.

Our algorithm is the same as that of Chang, Gao, and Le
[
14
]
, except that
we replace their clique-based
r
-clustering with our star-based
r
-clustering
and replace their
sssp
algorithm with ours.

The additive error of 2 in the computation
does not change: they can pick any node in a clique as a representative, while we must take
the center of a star, but the important property is that this representative has distance 1
to all other nodes in the clique or star. This is enough to give an additive error of 2;
see our
22
and their Lemma 16.
We note that the improvement to an additive error of 1, which is described
in the arXiv version of their paper
[
13
]
,
does not apply when working with stars instead of cliques.

Our running time is better than theirs, as explained next.
Recall that we use the nodes in
S(C)
to define the patterns for a cluster
C
.
Our clusters have local boundary complexity
O(\sqrt{r})
and size
r
.
By
24
, this means that the number of different patterns
for a cluster is
O((r\sqrt{r})^{4})=O(r^{6})
. They only have a bound on the
global boundary complexity, so they obtain a bound of
O((r\cdot r)^{4})=O(r^{8})

on the number of patterns. A careful analysis shows that this improves the
running time from
\tilde{O}(n^{2-1/18})
to
\tilde{O}(n^{2-1/14})
.

To keep the paper self-contained, we next describe and analyze the algorithm in detail.

Recall that the goal of the algorithm is to compute the eccentricity of each node.
We start by giving the intuition behind the algorithm.

We use our star-based
r
-clustering
\mathcal{C}
on the intersection graph
\mathcal{G}:=\mathcal{G}^{\times}[\mathcal{D}]
,
which allows us to distinguish two types of shortest paths:
shortest paths that are fully contained in one cluster
C\in\mathcal{C}
,
and shortest paths that leave the cluster.
To handle the first type we can simply do the following for each cluster
C
:
run the
sssp
algorithm from
Theorem 1
on
\mathcal{G}^{\times}[C]
with each
v\in C
as the source.
Because the size of each cluster is
O(r)
and we have
O(n/\sqrt{r})
clusters,
this takes
\tilde{O}(r^{2}\cdot(n/\sqrt{r}))=\tilde{O}(n^{2}/\sqrt{r})
time.

For the other type we use patterns. We first compute, for each node
v
and
each
Q(C)
the pattern
P_{v,Q(C)}
. Here,
Q(C)
denotes an arbitrary ordering of
S(C)
. This requires us to run our
sssp
algorithm
for each node in every sequence
Q(C)
. Since
\sum_{C\in\mathcal{C}}|S(C)|=O(n/\sqrt{r})

we can do this in
\tilde{O}(n^{2}/\sqrt{r})
time in total.

After computing the patterns

P_{v,Q(C)}
for every
v\in V
and
C\in\mathcal{C}
, we can approximate distances achieved by
paths of the second type. Using that the number of different patterns of a cluster
is
O(r^{6})
for each cluster
C
and the bounds from
Theorem 18
,
we can show that the total time to handle paths of the second type is
O(r^{7}(n/\sqrt{r}))
.
Setting
r=n^{1/7}
then gives the final result.

The following algorithm formalizes the intuitive description given above.

1.

(a)

Compute a star-based
r
-clustering
\mathcal{C}
of
\mathcal{G}:=\mathcal{G}^{\times}[\mathcal{D}]

. For each star center

,
run the
sssp
algorithm from
1
on
\mathcal{G}
with source

(b)

For each cluster

by arbitrarily ordering the nodes of
S(C)

For each node

|C|

\mathcal{G}^{\times}[C]

2.

For each cluster

compute the distance

of

to the pattern

.
Let

be a node

that maximizes

.

3.

For each node

\widetilde{\operatorname{ecc}}(v)

.
To this end, we compute for each cluster

to any node in

. More precisely,

\max_{u\in C}d(v,u)\leqslant\Delta(v,C)\leqslant\max_{u\in C}d(v,u)+2.

(5)

After computing all values

, we set
\widetilde{\operatorname{ecc}}(v):=\max_{C\in\mathcal{C}}\{\Delta(v,C)\}
.

Computing

.

.

in

is dominated by the time we already spent in earlier steps.
Since we have the values
d(P,u)
available, computing all
the values
d(u,q_{0})+d(P,u)
in Case (b) takes
O(|C|^{2})
for each cluster. Hence, the total expected time for Case (b)
is
\tilde{O}(\sum_{C\in\mathcal{C}}|C|^{2})=\tilde{O}(r^{2}|\mathcal{C}|)=\tilde{O}(nr\sqrt{r})
.

Summing the bounds for the three steps, we see that the expected total running time
is
\tilde{O}(n^{2}/\sqrt{r}+r^{7}(n/\sqrt{r}))
. Setting
r=n^{1/7}
we get the
claimed running time of
\tilde{O}(n^{2-1/14})
.
∎

The techniques used to obtain
Theorem 2
can also be used to construct a distance oracle,
similarly to what is done by Chang, Gao, and Le
[
14
]
in their setting.
Like for
Diameter
, we not only obtain a more general result but we also get a better bound,
in this case on the amount of storage. Somewhat surprisingly, the storage bound
for our oracle is smaller than the running time of our
Diameter
algorithm.

Corollary 25
.

Let
D
be a set of
n
constant-complexity pseudodisks. Then we can construct
in
\tilde{O}(n^{2})
expected time a distance oracle for
\mathcal{G}^{\times}[D]
that uses
O(n^{2-1/13})
storage,
has query time
O(1)
, and returns the distance between two query nodes up to an additive error of 2.

Proof.

The oracle is constructed as follows.

We first run Step
1
of our
Diameter
algorithm to compute a star-based
r
-clustering
\mathcal{C}
of
\mathcal{G}:=\mathcal{G}^{\times}[\mathcal{D}]

as well as, for each cluster
C\in\mathcal{C}
, the sequence
Q(C)
of star centers and the set
\mathcal{P}_{C}
of patterns.
This time, however, we use a different value of
r
, as specified later.
Recall that each node
u\in V
can be present in several clusters. We designate one of these
clusters as the
home cluster
of
u
, denoted by
\operatorname{home}(u)
. Distinguishing home
clusters allows us reduce the storage of our oracle, compared to the running time of our
Diameter
algorithm.
Our distance oracle now stores the following information.

1.

For each cluster
C\in\mathcal{C}
and each
u,v\in C\times C
, we store
d_{\mathcal{G}^{\times}[C]}(u,v)
.

2.

For each cluster
C\in\mathcal{C}
, each node
u\in C
such that
\operatorname{home}(u)=C
, and each pattern
P\in\mathcal{P}_{C}
, we store
d(P,u)
.
Note that we do not explicitly store the patterns
P
, which can have size
\Theta(\sqrt{r})
; a label identifying each pattern suffices.

3.

For each node
u\in V
and each cluster
C\in\mathcal{C}
, we store a pointer from
u
to the pattern
P\in\mathcal{P}_{C}

such that
P=P_{u,Q(C)}
, and we store
d(u,q_{0})
where
q_{0}
is the first element of
Q(C)
.

The oracle answers a distance query with nodes
u,v\in V
as follows.
Let
C:=\operatorname{home}(v)
, let
q_{0}
be the first element of
Q(C)
, and let
P:=P_{u,Q(C)}

be the pattern of
u
with respect to
Q(C)
.

•

If
u\not\in C
, we return
d(u,q_{0})+d(P,v)
.

•

If
u\in C
, we return
\min\{d_{\mathcal{G}^{\times}[C]}(u,v),d(u,q_{0})+d(P,v)\}
.

The values needed to answer the query have all been precomputed, thus a query takes
O(1)
time.
The correctness proof of the query is similar to the correctness proof of the
Diameter
algorithm.
Indeed, if the shortest path from
u
to
v
visits a node outside
C

then we can use
23

and
22
(
ii
) to conclude that

d(u,q_{0})+d(P,v)\leqslant d(u,v)+2
, which is easily seen to imply that we always report
the distance up to an additive error of at most 2.

It remains to analyze the preprocessing time and the amount of storage.
It follows from the analysis of the
Diameter
algorithm that we need
\tilde{O}(n^{2}/\sqrt{r}+r^{7}(n/\sqrt{r}))
expected time
to construct the oracle.
As for the storage, observe that we require
O(\sum_{C\in\mathcal{C}}|C|^{2})=O(nr\sqrt{r})
storage for the first part of the oracle.
For the second part we require
O(nr^{6})
storage, since there are
O(r^{6})
patterns per cluster and each vertex has only one home cluster.
This is less than the computation time needed for the second part, because
we do not explicitly store each pattern
P\in\mathcal{P}_{C}
and we only store
d(P,u)
for nodes
u
with
\operatorname{home}(u)=C
.
For the third part, we require
O(n^{2}/\sqrt{r})
storage.
In total we need
O(n^{2}/\sqrt{r}+nr^{6})
storage. This is minimized when we set
r:=n^{2/13}
,
leading to a storage bound of
O(n^{2-1/13})
.
The preprocessing time then becomes
\tilde{O}(n^{2})
.
∎

4
Concluding remarks

We presented the first
O(n\polylog n)

sssp
algorithm for arbitrary (constant-complexity) pseudodisks.
This significantly extends the class of objects for which
sssp
can be solved in near-linear time:
so far, the only
O(n\polylog n)

sssp
algorithm for pseudodisks required them to
be similarly-sized, fat, and satisfy a strong monotonicity assumption, or
(for arbitrarily-sized objects) be a Euclidean disk.
Our algorithm not only works for any arbitrary set of pseudodisks, but it works
for any set
\mathcal{D}
of constant-complexity objects whose union complexity is
O(n\polylog n)
.
More precisely, the expected running time of our algorithm is
O(\lambda_{s+2}(U(n))\cdot\log^{2}n)
,
where
U(n)
denotes the union complexity of
\mathcal{D}
and
s
is the
maximum number of intersections between any pair of boundary arcs.

An obvious question is whether the running time can be improved.
We note that until recently
[
5
,
17
]
the fastest

sssp
algorithm for Euclidean disks ran in
O(n\log^{2}n)
time, and that these recent improvements
for disks use techniques that do not apply in our much more general setting.
Hence, improving the
O(\lambda_{s+2}(U(n))\cdot\log^{2}n)
running time that we achieve might
be quite challenging.

Apart from log-shaving, one can also wonder if there are more general families
of objects that admit an
O(n\polylog n)

sssp
algorithm. This
is most likely not possible for segments, because of Erickson’s
\Omega(n^{4/3})

lower bound
[
22
]
for Hopcroft’s problem.
We do not see any natural class of objects that is more general than
objects with near-linear union complexity but less general than segments,
so it is not quite clear what to look for.

We also presented an efficient
star-based
r
-clustering
for objects with
small union complexity; this is a variant of widely used
r
-divisions of
planar graphs
[
23
]
. We expect that
our star-based clusterings may find other applications as well.

Finally, we showed that our
sssp
algorithm and star-based
r
-clusterings
together are enough to run the
Diameter
algorithm of Chang, Gao, and Le
[
14
]

to approximate the diameter of a pseudodisk graph up to an additive factor of 2.
This not only extends the class of objects for which the diameter can be
computed almost exactly, but the stronger complexity guarantees of our
star-based
r
-clustering also mean that the
\tilde{O}(n^{2-1/14})

running time that we achieve is better than what Chang, Gao, and Le obtain.
Can the running time be improved even further? Or can we extend the result
from pseudodisks to objects with near-linear union complexity? For computing
the exact diameter, this is ruled out (under SETH) by the lower bound of
Bringmann
et al.

[
6
]
, but does a subquadratic
algorithm exist that is almost exact?
And can we perhaps even
obtain an exact algorithm with subquadratic running time for pseudodisks? Since this is so
far only known for unit disks and squares, a more modest goal would be to
obtain a subquadratic exact algorithm for (arbitrarily-sized) disks.
