Abstract
. Long-term conversational memory is essential for LLM-based assistants, yet existing benchmarks focus on dyadic, single-topic dialogues that fail to capture real-world complexity. We introduce EverMemBench , a benchmark featuring multi-party, multi-group conversations spanning over 1 million tokens with temporally evolving information, cross-topic interleaving, and role-specific personas. EverMemBench evaluates memory systems across three dimensions through 1,000+ QA pairs: fine-grained recall , memory awareness , and user profile understanding . Our evaluation reveals critical limitations: (1) multi-hop reasoning collapses in multi-party settings, with even oracle models achieving only 26%; (2) temporal reasoning remains unsolved, requiring version semantics beyond timestamp matching; (3) memory awareness is bottlenecked by retrieval, where current similarity-based methods fail to bridge the semantic gap between queries and implicitly relevant memories. EverMemBench provides a challenging testbed for developing next-generation memory architectures.



1.
Introduction

Large language models are increasingly used as conversational agents in settings where interactions extend over time and across contexts
(
3
;
13
)
. In realistic scenarios such as workplace collaboration and personal assistance, conversations are often multi-party, topics are interleaved and revisited, and previously stated information is frequently revised. A memory-capable system in these environments must do more than retrieve a past fact on demand. It must retain fine-grained details, recognize when earlier information becomes relevant in a new situation, and respond in a way that is consistent with user preferences and social context.

Although long-context modeling and memory-augmented agents have advanced rapidly, evaluation remains a bottleneck. Many benchmarks treat memory as recall over long inputs and implicitly equate stronger memory with the ability to handle more tokens

)
. However, real failures often come from different sources: confusion about who said what in group chats, interference across closely related topics, inconsistency in persona and style, and inability to update beliefs when plans change. Meanwhile, recent memory-augmented systems
(
5
;
25
;
22
;
18
;
16
)
increasingly attach external or structured memory to LLMs for long-horizon personalization and task continuity, typically storing user facts and preferences and retrieving and updating them over time. Their rapid adoption makes realistic and diagnostic benchmarks more urgent, since it remains unclear which designs improve behavior under realistic conversational dynamics rather than only improving recall in constructed long contexts. .

A common limitation of existing benchmarks is the reliance on simplified interaction structures
(
11
)
. Many focus on dyadic conversations, while real interactions frequently involve multiple roles contributing to a single decision. Many construct long contexts by adding topic-irrelevant distractors, which tests noise tolerance but does not reflect how real conversations evolve, where topic transitions are usually coherent and interleaved
(
4
;
23
)
. Persona modeling is often shallow, despite the fact that communication style depends on role, expertise, and social power relations. Finally, most benchmarks assume stationary facts, whereas real user knowledge is non-stationary and requires explicit update and conflict resolution.

To address these gaps, we introduce EverMemBench, a memory benchmark designed to better match real conversational dynamics and to evaluate memory beyond surface recall. EverMemBench is built from high information density multi-party dialogues in which multiple roles meaningfully participate. The dialogues exhibit coherent cross-topic interactions, including interleaving and returning to earlier threads, rather than abrupt topic jumps or unrelated padding. The benchmark includes diverse personas with distinct skills and communication styles, and it models style shifts conditioned on social context and role relations. Crucially, it supports dynamic user knowledge updates, where earlier information can be revised as constraints change. The dialogues are additionally grounded with realistic references such as news and calendar-like temporal structure, improving realism of both content and timing. An overview comparison with prior benchmarks is shown in Figure
1
.

EverMemBench also provides an evaluation suite that decomposes memory competence into three task families: fine-grained detailed recall, memory awareness, and user profile understanding. Detailed recall tests precise extraction of specific facts. Memory awareness tests whether the system can identify when historical information is relevant and use it appropriately in a new scenario. User profile understanding tests whether the system can infer and maintain consistent personalization aligned with the user and the social setting. Together, these tasks evaluate not only what the system remembers, but also when memory should be activated and how it should shape behavior.

2.
Related Work

Long-Context Conversational Memory Benchmarks.
Recent benchmarks evaluate long-horizon conversational memory from complementary angles, including long multi-session interaction, capability-factorized assistant memory, and dynamic personalization. LoCoMo
(
19
)
focuses on very long multi-session conversations with tasks such as question answering and event summarization. LongMemEval
(
28
)
decomposes chat-assistant memory into abilities including information extraction, multi-session and temporal reasoning, knowledge updates, and abstention. PersonaMem
(
14
)
emphasizes dynamic user profiling and personalization over multi-session user–LLM histories. More recent efforts broaden coverage of memory abilities and dialogue settings, including MemBench
(
26
)
, MADial-Bench
(
9
)
, and BEAM
(
27
)
. A common simplifying assumption across many benchmarks is that interactions are dyadic or centered on a single assistant and a single user, which can under-stress realistic collaborative phenomena such as dense multi-party attribution, coherent cross-topic interleaving, persona shifts under social context, and non-stationary user knowledge that must be updated and reconciled. EverMemBench complements these benchmarks by explicitly targeting multi-party group chat with high information density, complex cross-topic interactions, diverse personas shaped by role relations, and dynamic user knowledge updates, together with tasks that separate detailed recall, memory awareness, and user profile understanding.

Memory-Augmented Systems and Architectures.

Memory-augmented systems increasingly treat memory as an explicit component that can be persisted, structured, retrieved, and updated, with designs ranging from pragmatic memory layers to more autonomous organization and OS-level management. Mem0
(
5
)
and MemInsight
(
25
)
propose scalable persistent memory layers that extract salient information from conversational histories and retrieve it when needed, reporting gains on long-term memory evaluation such as LoCoMo
(
19
)
. Beyond persistent stores, A-MEM
(
29
)
frames memory as an agentic module that decides what to store and how to use it, while Nemori
(
22
)
proposes self-organizing memory that emphasizes structured organization and evolution. Another line elevates memory to an infrastructure abstraction: MemOS
(
18
)
and MemoryOS
(
16
)
treat memory as an OS-like resource, aiming to unify heterogeneous memories with scheduling and lifecycle management. Many such systems adopt retrieval-augmented generation as a core mechanism for accessing external or long-range information
(
4
;
2
;
30
;
17
;
8
;
31
)
, and RAG-style indexing and retrieval often serve as a backbone for conversational memory pipelines. While these systems are typically evaluated in dyadic or single-user settings, EverMemBench offers a multi-party, high-density environment that more directly stresses attribution, cross-topic linkage, persona consistency under social context shifts, and dynamic knowledge update handling, enabling more diagnostic comparisons of memory mechanisms.

3.
EverMemBench

Figure 2.
Data curation pipeline of EverMemBench.

Stage 1
instantiates a synthetic organization and generates agent profiles, including stable attributes (e.g., roles and hard skills), context-dependent communication styles, and role-consistent sub-tasks.

Stage 2
constructs a globally consistent, calendar-aligned timeline from project plans and dated public news, and incrementally synthesizes long-horizon group-chat dialogue blocks conditioned on profiles and rolling summaries; each block is iteratively validated and repaired via programmatic and semantic checks.

Stage 3
generates evidence-grounded QA items targeting fine-grained recall, memory awareness, and user-profile understanding, and filters them through a three-phase quality control procedure: LLM blind testing, answerability/uniqueness verification, and human audit.

3.1.
Evaluation Dimensions

EverMemBench aims to evaluate LLMs as
long-term collaborators
in complex, dynamic environments. Unlike prior dyadic benchmarks
(
19
;
28
;
14
;
15
)
, real-world collaboration requires navigating dense multi-party coordination, adapting to evolving constraints, and maintaining role-dependent consistency. We instantiate these challenges in a high-fidelity workplace simulation, as it naturally concentrates the core difficulties of realistic memory.

To systematically diagnose these capabilities, we decompose memory competence into three complementary task families:

•

Fine-grained Recall
evaluates direct memory lookups, anchoring queries to specific factual details with definitive answers derived from stored records. Sub-tasks include:
Single-hop
for direct entity retrieval;
Multi-hop
for cross-group reasoning across personas or channels; and
Temporal
for chronological reasoning about version histories.

•

Memory Awareness
tests whether the system can mobilize existing memories to solve problems in unseen situations, differentiating active comprehension from passive storage. Sub-tasks include:
Constraint
for applying implicit rules from prior conversations;
Proactivity
for surfacing relevant context when evaluating proposed actions; and
Updating
for identifying current valid states when earlier decisions have been superseded.

•

Profile Understanding
assesses the ability to maintain distinct user personas by mining implicit habits and long-term traits from dialogue history. Sub-tasks include:
Style
for matching communication patterns;
Skill
for determining responses based on professional expertise; and
Title
for inferring focus areas from organizational role.

3.2.
Task Formulation

We evaluate memory systems via a streaming multi-group protocol.
The benchmark comprises 5
projects
spanning diverse domains to assess cross-domain adaptability; each project maintains isolated dialogue history, memory state, and evaluation queries. Within each project,
N
groups engage in a simulated year of daily conversations. During the
ingestion phase
, the system receives
raw multi-party conversations
organized by day and group: on each day
d
, it observes the daily batch
\{M_{d,g}\}_{g=1}^{N}
, where
M_{d,g}
denotes the chronologically ordered multi-party message list of group
g
on day
d
. The system must autonomously process these interleaved multi-party exchanges to build and maintain its memory state. After full ingestion, the
evaluation phase
poses queries against the complete history. Queries take two forms: (1)
multiple-choice
questions scored by exact option matching, and (2)
open-ended
questions scored by an LLM judge. Each question targets one of the three evaluation dimensions and is annotated with evidence spans for diagnostic analysis.

3.3.
Data Construction

Generating coherent long-horizon multi-party dialogues poses three key challenges:
(1) context-window limits force truncation of early history;
(2) logical inconsistencies emerge as conversations grow;
(3) persona and temporal coherence degrade over extended interactions.
To address these, we decompose data construction into three stages (Figure
2
):

Stage 1
generates a global
blueprint
encoding organizational structure,
individual persona profiles, and a project timeline with main and auxiliary storylines;

Stage 2
synthesizes dialogues in chunks conditioned on the blueprint;

Stage 3
generates evidence-grounded QA pairs from the dialogues and blueprint.
This separation ensures global consistency while enabling scalable, chunk-wise generation.
All generation processes (blueprint, dialogue, and QA) employ Gemini-2.5-Pro
(
6
)
as the backbone model.

3.3.1.
Preliminaries

We first establish the shared foundation for data generation.
We predefine an organizational skeleton
S
comprising 300 employees
\mathcal{E}=\{e_{1},\dots,e_{300}\}
across 7 departments, structured in a three-tier hierarchy (1 CEO, 7 directors, 292 staff), and five projects about different domains
\mathcal{P}=\{p_{1},\dots,p_{5}\}
.
Given
S
, we utilize LLM to generate a persona profile for each employee:

(1)

\pi_{e}=\big(\,\mathrm{rank}_{e},\;\mathrm{dept}_{e},\;\mathrm{role}_{e},\;\mathbf{s}_{e},\;\mathbf{c}_{e}\,\big),

where
\mathbf{s}_{e}
is a skill set (40–60 competencies) and
\mathbf{c}_{e}
is an 8-dimensional communication style vector.

3.3.2.
Blueprint Generation

For each project
p\in\mathcal{P}
, we construct an independent blueprint
B_{p}
that guides all subsequent dialogue generation.
The blueprint encodes:

(2)

B_{p}=\big(\,\mathcal{E}_{p},\;\{(\mathcal{E}_{p,j},\,\mathcal{T}_{p,j})\}_{j=1}^{3}\,\big),

where
\mathcal{E}_{p}\subset\mathcal{E}
is the project team (a subset of 20–60 employees selected from the full pool), and for each of the three sub-projects
j\in\{1,2,3\}
:
\mathcal{E}_{p,j}\subseteq\mathcal{E}_{p}
is the assigned member set (with possible overlaps across sub-projects), and
\mathcal{T}_{p,j}
is the set of sub-tasks generated based on member profiles and sub-project goals.
Together with the shared foundation
(S,\Pi)
, the blueprint
B_{p}
enforces decision-logic consistency, persona consistency, and temporal coherence during dialogue generation.

We construct
B_{p}
through the following steps:
(1) select a project team
\mathcal{E}_{p}
(20–60 members) from the employee pool via skill matching;
(2) decompose project
p
into 3 concurrent sub-projects;
(3) assign members to each sub-project
\mathcal{E}_{p,j}
, where one member may participate in 1–3 sub-projects;
(4) generate sub-tasks
\mathcal{T}_{p,j}
for each sub-project based on member profiles and project requirements.

3.3.3.
Conversation Generation

Dialogues are generated incrementally for each project
p
over a simulated timeline of
D
days.
Each sub-project
j\in\{1,2,3\}
maintains a dedicated group chat; however, since all three serve the same parent project, cross-group information sharing naturally emerges through overlapping membership and inter-dependent sub-tasks.

A key challenge is maintaining coherence over hundreds of days while respecting LLM context limits.
We address this through hierarchical summarization.
Let
C_{p,j}^{(<d)}=\{C_{p,j}^{(1)},\dots,C_{p,j}^{(d-1)}\}
denote the conversation history of sub-project
j
before day
d
.
We compute:

(3)

\displaystyle W_{p,j}^{(d)}

\displaystyle=\mathrm{Summarize}\big(C_{p,j}^{(d-7:d-1)},\;\mathcal{T}_{p,j}^{(d-7:d-1)}\big),

(4)

\displaystyle M_{p,j}^{(d)}

\displaystyle=\mathrm{Summarize}\big(C_{p,j}^{(d-30:d-1)},\;\mathcal{T}_{p,j}^{(d-30:d-1)}\big),

(5)

\displaystyle L_{p,j}^{(d)}

\displaystyle=\mathrm{Extract}_{\text{leader}}\big(C_{p,j}^{(d-1)}\big),

where
W_{p,j}^{(d)}
is a weekly summary capturing recent progress,
M_{p,j}^{(d)}
is a monthly summary preserving high-level milestones, and
L_{p,j}^{(d)}
contains leader instructions (e.g., task assignments) extracted from the previous day.
This multi-scale context compresses unbounded history into a fixed-size window without losing temporal structure.

To avoid error accumulation from turn-by-turn decoding and to enable the model to plan coherent multi-party dynamics holistically, we generate each group’s full daily conversation in a single pass.
Given the scheduled sub-tasks
\mathcal{T}_{p,j}^{(d)}
for day
d
, the dialogue is synthesized as:

(6)

C_{p,j}^{(d)}=\mathrm{LLM}_{\text{dialog}}\Big(\mathcal{T}_{p,j}^{(d)},\;W_{p,j}^{(d)},\;M_{p,j}^{(d)},\;L_{p,j}^{(d)},\;\{\pi_{e}\}_{e\in\mathcal{E}_{p,j}}\Big).

Since LLMs inevitably exhibit hallucination
(
12
)
, we apply a three-stage quality verification to each generated dialogue to ensure data reliability.
First, a
logic check
verifies that the dialogue is consistent with the sub-task specification—correct participants are involved and task details are accurately discussed.
Second, a
profile check
ensures that each utterance aligns with the speaker’s persona, including communication style and domain expertise.
Third, a
progress check
validates that task completion status matches the scheduled timeline—tasks should neither finish prematurely nor be delayed without justification.
Dialogues failing any check are regenerated until all constraints are satisfied.
After acceptance, leader instructions
L_{p,j}^{(d+1)}
are extracted for the next day, and the process repeats until the project concludes.
The complete conversation corpus for project
p
is then:

(7)

\mathcal{C}_{p}=\big\{C_{p,j}^{(d)}:j\in\{1,2,3\},\;d\in\{1,\dots,D\}\big\}.

3.3.4.
Q&A Generation

We construct evaluation items as QAE triples
(q,a,e)
, where
q
is a question,
a
is the answer, and
e\subset\mathcal{C}_{p}
denotes the evidence spans from the dialogue corpus that support the answer. We generate QA pairs through three specialized pipelines corresponding to the three evaluation dimensions, each employing task-specific strategies for both question generation and distractor design.

Fine-grained Recall

We adopt an
outline-driven protocol
combining
structure mining
and
contextual injection
. Given blueprint
B_{p}
and dialogue corpus
\mathcal{C}_{p}
, we traverse the task structure to identify reasoning patterns (e.g., cross-group information chains, temporal update sequences) and extract associated dialogue spans as evidence
e
. An LLM then generates
(q,a)
pairs grounded in
e
. For scenarios requiring constraints absent in the base narrative, we apply
non-conflicting implantation
: supplementary evidence derived from
B_{p}
is embedded into
\mathcal{C}_{p}
without altering existing content, enabling controlled probing of corner cases while preserving conversational coherence.

Memory Awareness

We adopt a
scenario-construction pipeline
. For
Updating
, we locate state transitions in
\mathcal{C}_{p}
where new information supersedes previous states; distractors represent stale information. For
Constraint
, we extract implicit rules (e.g., “always use Python for data tasks”) and construct scenarios requiring their application; distractors involve incorrect rules or constraint violations. To increase difficulty, we apply
adversarial perturbation
:
keyword substitution
removes surface-level cues, and
parameter removal
strips explicit triggers, forcing reliance on semantic understanding over lexical matching.

Profile Understanding

We extract user traits from interaction patterns in
\mathcal{C}_{p}
and generate questions requiring inference of these traits. Distractors are designed to isolate genuine comprehension from heuristic shortcuts. For
Style
, we construct an
adversarial matrix
with options varying along two dimensions (Fact Correctness
\times
Style Match); this
2\times 2
design separates style comprehension from factual accuracy, with deliberate length-bias in incorrect options. For
Skill
and
Title
, distractors are generated via reasoning chains to be “plausible but wrong” (e.g., attributing design tool usage to a backend engineer), testing understanding of role boundaries and professional expertise.

3.3.5.
Q&A Quality Control

We implement a three-phase filtering pipeline to ensure benchmark validity: samples must require memory access and be uniquely grounded in specific evidence.

Phase I: Blind Test

A sample
(q,a)
is discarded if an LLM can predict
a
given only
q
without any dialogue context. This filters out: (1)
parametric memorization
, i.e., answers derivable from world knowledge in model weights; and (2)
annotation artifacts
, i.e., low-quality distractors that make correct answers guessable.

Phase II: Evidence Grounding

We partition
\mathcal{C}_{p}
into segments
\mathbf{S}=\{S_{1},\dots,S_{n}\}
based on dialogue subtasks. For each
(q,a,e)
, let
S^{+}
denote the segment containing evidence
e
, and
S^{-}=\mathbf{S}\setminus\{S^{+}\}
. We enforce dual verification:

•

Sufficiency
: LLM must correctly derive
a
from
(q,S^{+})
, ensuring
e
is self-contained.

•

Uniqueness
: LLM must fail to derive
a
from
(q,S_{j})
for all
S_{j}\in S^{-}
, ensuring no unintended solution paths.

Phase III: Human Audit

Expert annotators review samples surviving automated filters for: (1)
logical incoherence
, i.e., structurally valid but semantically nonsensical questions; and (2)
pragmatic implausibility
, i.e., distractors trivially dismissible via common sense despite satisfying formal constraints.

Experiments

We evaluate LLMs and memory-augmented systems on EverMemBench to diagnose how they handle multi-party, high-density conversational dynamics.

Experimental Setup

Long-context LLMs

(
7
)
, GPT-4.1-mini
(
1
)

This isolates the LLM’s reasoning capability from retrieval quality, revealing whether performance gaps stem from retrieval failures or fundamental reasoning limitations.

4.2.
Performance across Different Tasks

Table
4
presents evaluation results across three task families. We highlight several key findings.

Finding 1: Multi-hop reasoning collapses under multi-party interleaving.

While all systems achieve reasonable single-hop performance (Gemini-3-Flash: 97.65%, memory systems: 49–86%), multi-hop questions cause universal collapse. Gemini-3-Flash drops to 26.51%; the best memory system (EverMemOS) achieves only 17.27%.

This reveals that both long-context LLMs and memory systems struggle with the
interleaved information structure
of multi-party communication. Unlike dyadic settings where facts appear in single exchanges, multi-party scenarios scatter related information across speakers, groups, and time points. A decision may be proposed by one person, debated in another channel, and finalized by a third party days later. Neither brute-force context access nor retrieval-based memory handles this fragmentation adequately.

Finding 2: Temporal reasoning remains unsolved.

Temporal questions yield uniformly poor performance: Gemini-3-Flash achieves only 45.00%, GPT-4.1-mini scores 7.00%, and memory systems range from 2.67% to 21.00%.

In realistic collaboration, decisions evolve—a budget proposed Monday may be revised Wednesday and finalized Friday. Answering “What is the final budget?” requires not just locating mentions but understanding
version semantics
: which statement supersedes which, and what counts as “final.” Current architectures treat memory as a flat store rather than a versioned timeline, leaving temporal reasoning largely unsolved.

Finding 3: Memory awareness requires both precise retrieval and robust reasoning.

Results on Memory Awareness (Table
) reveal a striking gap: Gemini-3-Flash with full context achieves 96–100% across all three subtasks, while memory-augmented systems range from 55–89% (Constraint), 37–90% (Proactivity), and 19–85% (Updating).

The upper-bound performance confirms that LLMs possess the reasoning capability for memory awareness when provided with
strong evidence
(i.e., complete context containing all relevant information). However, retrieval-based systems surface only
weak evidence
: fragments scattered across the conversation history that are semantically related but lack explicit connections. Operating on such incomplete information demands stronger reasoning to recognize latent relevance. This creates a dual bottleneck: (1)
retrieval quality
, as current embedding-based methods fail when relevance is inferential rather than lexical (e.g., connecting a restaurant query to a colleague’s dietary restriction mentioned weeks ago); and (2)
reasoning robustness
, as models must infer correct answers from partial cues rather than explicit statements. Improving memory awareness thus requires advances on both fronts: retrieval systems capable of reasoning about latent relevance, and LLMs robust to evidence sparsity.

Finding 4: Communication style resists extraction under current memory paradigms.

Among Profile Understanding subtasks, Style proves most challenging: memory systems achieve only 11–58%, compared to 25–61% on Skill and 36–70% on Title. Even Gemini-3-Flash reaches only 67.05%.

The difficulty is fundamental: communication style is not a discrete fact but an
emergent pattern
across many interactions. Whether a user is directive versus collaborative, formal versus casual, cannot be captured by any single snippet—it requires aggregating signals distributed across the entire history. Current paradigms, designed to retrieve discrete memories, are structurally ill-suited for pattern abstraction.

Finding 5: Retrieval compensates weak models but bottlenecks strong ones.

Models with weaker long-context reasoning (GPT-4.1-mini, LLaMA-4-Scout) gain 1–7% accuracy with memory augmentation: retrieval filters noise and helps these models focus on relevant content. In contrast, Gemini-3-Flash drops from 72.61% to 52–62%, as retrieval discards information the model could otherwise exploit. However, for strong models, memory systems enable deployment where full-context processing is infeasible, trading accuracy for scalability. This suggests practitioners should match memory strategy to backbone capability: use retrieval to boost weak models, but for strong models, weigh accuracy loss against deployment constraints.

Finding 6: Multi-hop reveals retrieval fidelity as the new bottleneck for strong models.

A striking inversion occurs in multi-hop reasoning: GPT-4.1-mini improves from 2.41% to 8–14% with memory augmentation, while Gemini-3-Flash
collapses
from 26.51% to 3–6% with most memory systems. This paradox—where a stronger model performs worse than a weaker one under memory augmentation—signals a fundamental shift in the evaluation bottleneck from
model reasoning
to
retrieval fidelity
.

For weaker answer models, memory systems primarily serve to “feed relevant information to the model,” and system rankings reflect basic retrieval effectiveness. However, when the answer model approaches the reasoning upper bound, strong models become acutely sensitive to retrieval-induced artifacts: noise from irrelevant snippets, version conflicts from outdated information, and loss of implicit cues from aggressive compression. If retrieval sacrifices contextual coherence for top-
k
coverage, it actively interferes with the model’s native reasoning capabilities.

Notably, EverMemOS achieves 17.27% on Gemini-3-Flash—substantially outperforming other memory systems (3–6%)—because its event-boundary segmentation preserves complete episodic units rather than fragmenting conversations into isolated snippets. This demonstrates that for strong models, retrieval granularity and coherence preservation matter more than raw recall volume. The “chaotic” rankings on Gemini-3-Flash are thus diagnostically valuable: they reveal which memory systems damage critical implicit cues and version semantics during compression and retrieval, validating that EverMemBench remains discriminative even for high-capability models.

In contrast,
Temporal

This reveals a fundamental reasoning limitation: temporal information in multi-party conversations is inherently fragmented—a decision may be proposed on Monday, questioned on Wednesday, and finalized on Friday, with each mention scattered across different speakers and threads. Even when all relevant snippets are provided, LLMs struggle to reconstruct the true temporal narrative from these dispersed cues. The challenge is not merely recognizing that later statements supersede earlier ones, but synthesizing a coherent timeline from information that was never presented as a unified sequence.

For
Multi-Hop
, oracle dramatically improves performance for strong models (GPT-4.1-mini: from 2.41% to 97.99%; Gemini-3-Flash: from 26.51% to 88.37%), but LLaMA-4 still achieves only 37.35% even with oracle evidence. We observe that LLaMA-4 frequently refuses to answer or hedges when presented with oracle snippets, interpreting the fragmented dialogue segments as incomplete information. This behavioral tendency—being overly cautious about answering with perceived partial evidence—significantly degrades accuracy. The finding highlights that oracle evaluation with extracted snippets may disadvantage models that are trained to be conservative when context appears incomplete, even when sufficient information is actually present.

5.
Conclusion

We presented EverMemBench, a high-realism benchmark for long-term conversational memory built from multi-party workplace chats grounded in project timelines and public events. Its curation pipeline yields traceable dialogue logs and QA items that stress realistic memory demands, beyond mere context length. Based on this, we introduced an evaluation suite that factors memory competence into detailed recall, memory awareness, and user profile understanding. EverMemBench thus offers a controlled yet realistic testbed for analyzing memory architectures and retrieval strategies, and we hope it will serve as a shared benchmark to drive progress toward robust, socially aware long-horizon agents.

6.
Limitations

Synthetic Data.

EverMemBench dialogues are generated by Gemini-2.5-Pro rather than collected from real human conversations. While our multi-stage pipeline with quality verification ensures logical consistency and persona coherence, synthetic dialogues may differ from natural human communication in subtle ways—such as the distribution of disfluencies, implicit social cues, or domain-specific jargon. Future work could validate findings on human-generated corpora.

Domain Scope.

The benchmark focuses on workplace collaboration scenarios, which naturally concentrate multi-party coordination and information updates. However, conversational memory demands also arise in personal assistance, social groups, and educational settings, where interaction dynamics may differ. The organizational framing, while providing controlled evaluation, may not fully generalize to all memory-relevant domains.
