 ABSTRACT

AutoSAC is an automated python program to conduct sample activation calculation immediately after
neutron scattering experiment on VULCAN. AutoSAC takes account of sample dimensions,
compositions, forms, sample environments, neutron beam configurations, neutron scattering history, and
proton charged resolved beam power etc., and uses a simplified method to rapidly estimate the
radioactivity at end of beam or after. It generates a draft report per sample and repository of radioactivity
per measurement and provides feedback of current radioactivity and decay time back to a neutron
proposal Slack channel to inform users immediately on sample handling. It also utilizes either the sample
note field in EPICS or sample composition or thickness correction and takes slack prompt or command to
conduct post-beam SAC by demand. The program can be shared to be used in other beamlines at
spallation neutron source with modified instrument configurations including instrument specific
characteristic beam fluxes.

 1. Introduction

Isotopes are activated after neutron beam irradiations, and the radioactivity of sample after beam could be
above sample handling threshold (2mrem/h), and a sample handling process needs to be followed for
sample removal as well as shipping back the users. The radioactivity of a sample after neutron scattering
depends on many factors including materials, beam power, optical configurations, sample environments
and neutron measurement time, and beam fluctuations etc. Right now, before sample could be handled a
RedEye G detector is used to survey sample radioactivity, and if it exceeds the recommended sample
handling limits, users either wait for it to decay or call RCT for a survey. For to be-shipped samples,
sample activation calculation (SAC) is conducted manually by using the web-based calculator after
loading most factors as mentioned above. The process is semiautomatic by loading some stored
information from measurements, but still manual operation is not inevitable. Here, we introduce an
automated sample activation calculation (AutoSAC) by automatically pulling the needed input from
metadata at the end of each saved run and conduct SAC automatically including generating draft SAC
report. More importantly, AutoSAC use matched flux results at sample position to conduct more realistic
sample radioactivity. This program is not currently intended to replace existing SAC process but provide
an informal result for users to predict the sample radioactivity after beam either automatically or on
demand by considering all the history of the sample since the seeing neutron beam first time. However,
since AutoSAC uses the simplified algorithm as in the web-based SAC form, it is not impossible to be
tuned as a formal SAC tool for the facility. In this report, we highlight the design, workflow, access and
execution, controls, and potential failures of AutoSAC. This document is intended as an architecture and
execution map for record use. For implementation details, validation logic, and change history, use the
source files stored in the internal GitLab.

 2. Program Design

2.1 Programming tool and language of choice

The whole program is made by vibe coding with GitHub Copilot AI agent in VS Code, where different
large language modes (LLMs) are accessed, e.g. GPT 5.x, and Claude Sonnet 4.6 etc. The language of
choice is python 3.9.x with relevant libraries. AutoSAC can be invoked by the current VULCAN [1] auto
reduction pipeline after a measurement is finished.

 2

2.2 Sample Activation Calculation method

The SAC method used here was adopted primarily from SAPEU by Lu W. et al. The details of the
method can be found in the reference [2]. AutoSAC accepts CINDER library file, but currently it
implements an isotope library file from open source. The flux of the instrument is measured by an
imaging camera at the sample position, by changing different configurations with instrument guides (high
intensity/ high resolution), incident slits distance from sample position (IX), incident slits openings
(IVA/IHA). The measured flux data are normalized to its slit opening area and beam power. The mathing
fields and the relevant flux data file name are organized in a json file, “vulcan_flux_profiles.json”. The
code first match guide, IX settings, and if found, it will use the beam-aperture-specific flux data or scale
the 12x12mm^2 flux data by the beam aperture. If no matched configuration of guide and IX settings,
AutoSAC uses a master VULCAN flux from SNS SAC recommendation under high intensity mode, and
a scale factor was applied to calculate the master flux at high resolution mode. This HI/HR scale factor is
derived from the second beam monitor data located after the exchangeable guides. The slits opening area
will be used to calculate the neutron flux from the master data. Chopper settings including frequency and
bandwidth are used to select correct energy range and averaged power of neutron flux on sample.

2.3 Sample Information

Sample information is pulled from the meta data saved in each run, which includes sample composition,
sample density, sample thickness, and sample form (solid or powder). Sample composition input varies
from formal input to generic materials names, e.g. ‘steel’. AutoSAC is coded with sample composition
parser to abstract the sample composition from different inputs. And this parsing process is improving
overtime by adjusting to be able to process new format. For generic material names a json file is used to
create local library to specify the compositions for well know materials. For incorrect or non-resolvable
composition AutoSAC accepts add-on formula in the note with ~ as a flagging character for the program
to parse the sample composition input. If density is not specified, AutoSAC will first check local density
json file (sample_densities.json), and if not found, it estimates a density from the formula. For a sample in
powder format, the solid density is scaled down by 50%. For correction of sample thickness, users can
add ‘thickness=###’ mm in the note to correct the one in meta data. If no thickness information is
provided, AutoSAC selects default sample dimension based on the sample environment configuration.
And due to the nature of loadframe orientation of sitting 45o of the beam, the practical neutron path is
calculated by 1.414 times the sample thickness.

2.4 Irradiation History

For samples experiencing multiple irradiation histories, AutoSAC takes it into account by looking up the
prior SAC history in AutoRecord.txt first if no SAC has been done or the AutoSAC.txt for SAC history,
including residual dose rate and the time stamp of the prior SACs. Those histories are considered as prior
segments in the current SAC process. For the case with beam production being down during a
measurement, AutoSAC conducts proton-charge resolved SAC if the beam down time is more than 10%
of the total planned time. This is done by reading the beam energy history in the meta data. The proton-
charge resolved process weighs in the decay during beam down time to have close estimate of the
radiation level of the sample.

2.5 Reporting Results

At the end of the SAC processing, AutoSAC generates a radioactivity report “AutoSac_Full_Report-
<SampleID>.pdf” in PDF format per each sample, in the report, the estimated radioactivity and decay
time to clear the sample are included. Notification of completion of AutoSAC is sent to Slack proposal
channel per run, with estimated radioactivity, and include estimated decay time to be less than 2mrem/h if

the calculated sample radioactivity is more than 2 mrem/h. An example report is shown in Fig 1. A
AutoSAC.txt file including SAC for each run is also produced and saved in the IPTS-{ipts

parsed sample composition.

 3. Access and Execution of AutoSAC

AutoSAC can be accessed by multiple ways. First, AutoSAC is part of reduction service of the beamline,
where it is invoked automatically at the end of data collections. vreduce.py reads metadata, resolves
composition, sample geometry, flux context; builds history and current segments; subprocess call to
vreduce_sac.py with JSON output mode; parses payload, updates AutoSAC.txt and creates PDF in a
specific IPTS proposal folder; it optionally adds AutoSAC completion summary information into ORNL
neutron science Slack channels and provides an estimate about the radioactivity and decay time to be
below 2 mrem/h before removing the samples:

[VReduce] AutoSAC (For finished sample handling, check it with RadEye G and call RCT as needed).
Sample: S3-S4, ITEM: 109631
Radioactivity: approx. 15.4 mrem/h.
Thickness used: 0.6 cm (99-User default).
Decay time to < 2 mrem/h: approx. 11 min after EOB.

 4

Second way is through vbot APP command in ORNL neutron science slack channels (the vbot APP has to
be enabled): the command is parsed in vreduce_vbot_backend.py; invokes vreduce_sac.py for pre sac or
sac requests; and generate text summary and or AutoSac_Full_Report PDF path. To execute such request
in an access specific proposal channel, the users must be an approved channel member of the proposal.

Third way is through direct command line interface (CLI): user runs vreduce_sac.py; - mode 1: direct
formula or mass-fraction plus geometry and flux; - mode 2: history lookup by IPTS and sample IDs; the
code then outputs console table and selected file format. The access to a specific IPTS folder is governed
by the user’s access permission profile on the analysis cluster.

 4. Failure or Degradation Paths

A failure of the execution of AutoSAC could happen due to missing or malformed compositions.
AutoSAC may fail estimate unless formula override by using the note option in above or provided in
calling via CLI. Missing of other key parameters could result in the failure or inaccuracy, including
missing geometry/density, missing flux spectrum. Some of the missing information is handled by falling
back to conservative defaults for mass/thickness/density where possible, and flux estimate is done over
the master flux which may be more conservative by using larger flux values.

 5. Use in Other Beamlines

AutoSAC can be deployed to other beamlines at SNS or HFIR, where auto reduction service is available.
The main setting that needs update is the flux json file and its file path and the relevant flux files in the
json file. Some other specific modifications maybe required to account for different sample types, such as
liquid, and nominal dimension, such as the default sample thickness. These changes can be easily made
by directly changing in the code or requesting a generic AI coding agent to learn and update.
