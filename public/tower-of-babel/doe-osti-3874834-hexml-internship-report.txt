2.2 Optuna
Optuna is a hyperparameter optimization framework for machine learning. It is based on two main
concepts:

 • Study: an optimization process based on an objective function;
 • Trial: a single execution of the objective function with a given set of hyperparameters.

 The goal is to run multiple trials with different hyperparameter configurations in order to analyze
their impact on the objective function. Each study consists of several trials. In general, increasing the
number of trials improves the chances of finding a better-performing configuration.

 Figure 2: General workflow of an Optuna study.

 A key aspect of Optuna optimization is the choice of the objective function. This function is used
as a reference to evaluate each set of hyperparameters and, when necessary, to prune unpromising
trials.
 In the reinforcement learning setting, several objective functions can be considered. For example,
one could optimize the cumulative reward or a domain-specific quality metric. In this work, I chose to
optimize the topological quality.
 The main optimization parameters are:

 • N TRIALS: number of different hyperparameter configurations to sample;

 • N STARTUP TRIALS: number of trials completed before starting pruning;
 • MAX EPISODES / MAX STEPS: number of episodes or steps run for each trial;
 • N EVALUATIONS: number of evaluation points that can be used for pruning decisions;
 • Pruner: Median Pruner (default);

 • Sampler: TPESampler (default).

 When running Optuna studies, choosing an appropriate pruning strategy is crucial. Some training
runs may improve slowly at the beginning but eventually reach a better final score. Therefore, pruning
trials too early may eliminate promising configurations.

3 Reward function investigation
The reward function is a key element in modeling a reinforcement learning problem (RL). Indeed, it
guides the agent throughout the learning process by indicating whether the actions taken are appro-
priate or not. It must therefore be carefully chosen to provide the agent with learning signals that are
consistent with the desired objective.
 In our geometric decomposition problem, the goal is to decompose a given geometric shape into
quadrangular shapes. Ideally, the resulting decomposition should consist solely of quadrilaterals,
achieved in the fewest possible steps. Furthermore, these quadrilaterals should have good geomet-
ric properties: they should be as orthogonal as possible and have sizes that are as regular as possible.
 The central question, then, is this: How can we construct a reward function that takes these
various criteria into account? To answer this question, we experimented with several formulations of
the reward function.

3.4 LDQNTopo
Another possibility would be to define the reward solely based on the current topological quality of
the decomposition. However, this approach does not seem particularly relevant to me, since the same
action can yield very different rewards depending on the configuration in which it is performed.
 For example, if the current decomposition has low topological quality, with q = 0.1, and the agent
creates a new quadrilateral, the reward obtained may remain relatively low, for example r = 0.25.
Conversely, if the agent is nearing the end of an episode, with a decomposition that is already of good
quality—for example, q = 0.7—then creating a single additional quadrilateral can lead to a much
higher reward, for example, r = 0.85.
 Thus, two actions that are similar and equally relevant may be associated with very different
rewards. The reward then depends more on the overall state of the decomposition than on the intrinsic
quality of the action performed, which, in my opinion, can make the learning signal less consistent.

4 Part-GeoNet Agent
Part-GeoNet agent is a reinforcement learning (RL) agent based on the Proximal Policy Optimization
(PPO) algorithm [SWD+ 17]. It uses a GNN to construct a representation of the geometries to be
segmented.
 To segment the geometries, the agent needs information that goes beyond the local neighborhood
of a vertex. This is because each segmentation action performed by the agent will have a global impact
on the geometry. The agent must therefore be able to take into account both local information and
more distant geometric information.
 How can this distant information be easily integrated? GNNs are characterized by their ability to
propagate information between neighboring nodes at each layer. The number of layers in the GNN
thus determines the distance over which information propagates. The more layers added, the farther
the information will propagate. However, this propagation occurs through the topological adjacencies
between vertices. Regions that are geometrically close but topologically distant will not be reachable.
 Increasing the number of layers in the GNN is not necessarily a solution, however. For large
geometries, capturing all the global information would require a very deep network, which would
make the model difficult to scale. Furthermore, too many layers can lead to a phenomenon known
as oversmoothing, where the representations of the nodes gradually become too similar and lose their
discriminative power.
 However, the structure of GNNs makes it possible to consider more sophisticated architectures.
For example, the use of multi-graph GNNs would allow for more direct access to information that is
topologically distant but necessary.

 That is why we have designed a learning agent that incorporates a GNN to represent the charac-
teristics of the geometries to be cut.

4.1 General agent framework
Our learning model, Part-GeoNet, is based on the Proximal Policy Optimization (PPO) algorithm. It
operates in four steps:

 1. Encode the vertex features into a latent space using a GNN
 2. Predict the value of the current state (critic)
 3. Select the vertex from which to perform a cut (actor)

 8

  4. Predict the type of cut to perform (actor)

 Through Part-GeoNet, our agent will then learn both a latent representation of the vertex features
and a global representation of the decomposition. The local representation of the vertices is used by
the actor to select a vertex and perform a cut. The global representation, on the other hand, is used
by the critic to estimate the expected rewards, as illustrated in Figure 6.

Figure 6: Based on the graph representing the geometry, we will use a GNN to generate latent
representations of the geometry. These representations will then be used by the actor to predict the
cut and by the critic to estimate the expected rewards based on a state.

 Below, we’ll go into detail about each of these steps.

4.1.1 GNN Embedding:
We are operating within a partially observable environment; the agent has access only to certain
information about the state in which it finds itself. The actor can do with a local observation of
the shape it need to decompose. In contrast, the critic needs more comprehensive information about
the overall decomposition to correctly predict the expected rewards. To address this constraint, the
GNN will encode geometric information in two forms. First, for each vertex, it will generate a latent
representation through local aggregations of neighboring vertices. Second, to obtain a more global
view, it will combine information from the complete decomposition with an aggregation of information
across all vertices of the current shape being processed.
 This construction enables the implementation of an asymmetric actor-critic architecture, in which
the actor and the critic receive different observations, as illustrated in Figure 7.

 • The critic will use global information about the decomposition state to estimate the rewards it
 can obtain from that state.
 • The actor, on the other hand, will rely on a more local observation of the current shape to be
 decomposed.

 9

Figure 7: Based on the graph representing the geometry, the GNN generates two types of representa-
tions. The first, based on vertices, is constructed through an intuitive aggregation of the characteristics
of neighboring vertices, followed by a second layer of average aggregation to obtain the latent repre-
sentations of each vertex in the geometry. The second is a global representation of the geometry: it is
obtained by aggregating information from all vertices, then combined with global information about
the decomposition.

 The technical details of the aggregations used evolved throughout the internship. The different
implementations are presented in sections 4.2 and 4.3.

4.1.2 Critic estimation:
Based on the global representation of the geometry, the critic estimates the value of the current state,
that is, the expected rewards from that state. The estimation is performed by a two-layer MLP with
128 neurons per layer.

4.1.3 Node selection:
Based on the vertices latent representations produced by the GNN, the agent predicts a value for each
vertex. These values are transformed by the softmax function into a probability distribution. From
this distribution, we sample the vertex to be selected. The prediction of these values is also performed
by a two-layer MLP with 128 neurons.

4.1.4 Cutting choice:
Once the vertex is selected, its latent representation is reused to predict the type of cut to be applied
to the previously selected vertex. The choice of cut is also performed by a two-layer MLP with 128
neurons.

4.2.3 Advantage and limits
The advantage of this aggregation is that the first layer focus on the main features of the node and we
can perform intuitive combinations that fits our problem and generate fixed size vector. So our first
linear layer of the GNN have a concentrated main feature vector with as many concatenated features
as we can. As we know every vertex has only two neighbors, it is easy to concatenate.
 With this architecture, a one-layer GNN is functionally equivalent to manually extracting features
from the local neighborhood.

4.3 Brep and visibility Graph Part-GeoNet
To improve the observation provided to our agent, we want to enhance the geometry representation
by adding informations about visible vertices.
 A vertex is said to be visible from another vertex if the segment connecting these two vertices
encounters no obstacles. We can then construct a visibility graph connecting the vertices that are
visible to one another, as illustrated in Figure 9)

 Figure 9: The visibility graph connecting the visible vertices one to one another.

 Using the visibility graph allows the agent to obtain additional information about areas of the
geometry that are topologically farther away. To exploit both topologically close and distant informa-
tion, we construct a GNN multigraph in which the two graphs,BREP and visibility, share the same
vertices but have different adjacency relationships.
 In practice, to construct this multigraph, we can use the HeteroData class from PyTorch Geometric.
This class allows us to have different types of nodes and different types of edges within the same

 12

graph. In our case, we use a single node type: vertex, and two edge types: brep and visibility,
corresponding respectively to the edges of the BREP graph and the visibility graph.
 To take full advantage of this multi-graph, we have several options for aggregating each layer :
 • An aggregation of all neighboring vertices without distinction of the type of edge.
 • Two separate aggregation for each edge type, then concatenate the results
 • Two nested aggregations. First we aggregate the information from the visible vertices and then
 concatenate the result with the characteristics of the neighboring vertices of brep graph. The
 concatenated result is then passed to a linear layer.
 We chose to use the last method: the information from the B-rep graph and the visibility graph is
aggregated separately, then combined so that the linear layer can produce the final representation of
each vertex.

4.3.1 GNN Aggregation
Aggregation on the multigraph is divided into two parts: First, we will aggregate the features of the
vertices visible via “visibility” edges using an attention layer. Next, we will concatenate the result
with the features of the neighbors via BREP edges to perform the final aggregation.
 Adding the attention layer allows us to better distinguish between visible vertices. In fact, a simple
mean aggregation layer can cause a phenomenon of feature smoothing, known as over-smoothing. For
large geometries, vertices may have many visible neighbors, and the resulting mean may be nearly
identical. The information provided by the visible vertices would then be of limited discriminative
power. The attention layer, on the other hand, learns to assign different weights to each neighbor.
This assigns varying levels of importance to the vertices and should generate better representations.

 Continuing to denote the characteristics xi of vertex i, and Xi the set of characteritics of the graph’s
vertices, we will add a fourth component to the aggregation function :
  
 Agg(Xi ) = CONCAT xi , fneigh (Xi ), fshape (Xi ), fvisi (Xi ) (5)

 This new component fvisi (Xi ) corresponds to the aggregation of visible vertices by an attention
layer. The attention layer used in our implementation is PyTorch’s Geometric GATConv, whose

4.4.1 SB3 PPO Implementation
The original PPO code has been made available in the GitHub repository openai/baselines. However,
there are many implementations of the algorithm with varying performance. The SB3 implementation

5 New environment
To use Part Geo Net, we decided to experiment with a new environment. The previous environment
had several aspects that I couldn’t fully explain. In particular, three elements seem essential to me for
building a coherent learning environment:
 • A good reward function. This guides the agent in its learning; the signals it sends must be clear
 and consistent with the intended goal.
 • A sufficiently rich set of actions. The set of actions must contain a variety of actions sufficient
 to solve the problem.
 • Sufficient observation. The observation must be detailed enough to allow the selection of appro-
 priate actions.

 14

 From these three elements follows a fundamental principle in RL:

 • The same observation-action sequence must always produce the same reward. And this reward
 must be consistent with the objective.

 The agent’s observation must therefore be detailed enough to distinguish between different scenar-
ios. The problem we are trying to solve is all the more complicated because it is multi-objective.
 In fact, the agent must first successfully select the most relevant vertex for a cut and then choose
the appropriate cut. But if the initially selected vertex is incorrect, the cut cannot be correct.
 With the current observation and set of actions, I found it difficult to choose a vertex and even
more difficult to choose the cut. An example is shown in Figure 11

Figure 11: How do you determine the best cut in this configuration? The red action pointing downward
seems more relevant, but what distinguishes it from the red action at the top? Similarly, which vertex
was the best choice to begin with? With the current local observation, nothing distinguishes the three
vertices with obtuse angles.

 These questions motivated the investigation of a new environment.
 The criteria for this new environment:
 • Use a set of actions that seems intuitive

 • Define an observation that allows us to differentiate between good and bad actions, in particular
 by:
 – expanding the observation to better capture distant features of the geometry in order to
 obtain sufficiently distinguishable observations

 • Studying the geometry dataset and considering cleaning it up

5.1 Action Set
The newly selected action set includes two types of cuts:

 • Perpendicular cut: The cut starts at the selected vertex and follows the line perpendicular to
 one of the adjacent edges.
 • Cut at third nodes: The cut starts at the selected vertex and connects to the third nearest vertex
 on either side.

 With this action set, it seemed easier to me to define local heuristics for selecting actions.

5.2 Observation
This new set of actions required us to expand the agent’s observation. We felt it was appropriate to
add information regarding the two third neighboring vertices. So we enriched our observation with:
 • α1 and α2 , the angles at the selected node in both of the newly generated faces,
 • v⃗3p and v⃗3n , the vectors pointing to the previous and next third nodes, respectively,
 • β1 and β2 , the interior angles of the third nodes,
 • whether the two third nodes are visible from the vertex in question.

5.3 Reward function
Adding cuts toward third-neighbor nodes revealed an inconsistency with the previous reward function.
Indeed, a third-node cut always creates a quadrilateral, and is therefore systematically rewarded. As
a result, the agent tends to learn a strategy that selects only third-node cuts, producing final shapes
that necessarily lead to triangles. This behavior is illustrated in Figure 14.
 To avoid this phenomeon, we tried to focus more on the orthogonality of the shapes. The new
reward function introduces an orthogonality score of the entire decomposition. This score is computed
as the sum, over all interior angles, of their deviation from 90◦ :

 The agent is then rewarded according to the improvement in this orthogonality score between two
consecutive steps:

 sortho (t) − sortho (t + 1)

his quantity is positive when the decomposition becomes more orthogonal, and negative when the
orthogonality deteriorates. However, I found out that using only orthogonality criterion as reward led
to many triangles shapes. To address this issue, I added the initial penalties for triangle creation and
invalid cuts, while keeping a small positive reward for the creation of quadrilaterals :

 R(t + 1) = ws (sortho (t) − sortho (t + 1)) + wq Nq − wt Nt − wns δ1N

 The new reward function seems to provide more consistent rewards than the old one.

First, I added an entropy term as described in the paper [SWD+ 17] to obtain a loss function of the

 where c1 , c2 are coefficients, S denotes an entropy bonus, and LVt F is a squared-error loss (Vθ (st ) −
Vttarg )2 .
 I then added gradient clipping before the updates, as well as value function clipping. PPO clips
the value function in the same way as the PPO’s clipped surrogate objective. (No study has proven
that this improves performance. M. Andrychowicz et al. [ARS+ 21] even find that it degrades
performance.)

6.2.2 PPO Asymmetric Observation
After thinking on our agent’s ability to predict the expected rewards of an episode, it seemed to us
impossible to predict the expected rewards by limiting ourselves to the initial local observation. Indeed,
two similar local states can appear at the beginning as well as at the end of an episode. However, the
cumulative rewards necessarily depend on the progression of the episode. This is why we wanted to
provide the critic with a more global observation.
 The critic’s observation will then have access to the following global information, in addition to the
local features of the vertices of the current shape:

  
xglobal = nb parts in queue, nb verts in model, nb quads, nb tris, nb genquads, nb genshapes, topo quality

 The actor, on the other hand, does not need information about the global decomposition. It can
limit itself to the shape selected for cutting. That’s why we tried an asymmetric architecture.

6.2.3 Networks losses.
We used two separate networks for the actor and critic, but the loss function were initially combined.
By default in SB3, the global loss is the weighted sum of the actor loss, critic loss and entropy bonus.
The respective weights are set by default to : 1.0 for the actor loss, 0.5 for the critic and 0.005 for
entropy.
 The problem we encountered with this combined loss was that the critic loss was disproportionately
large compared to the actor loss. Indeed, the rewards ranges from -1000 to +1000 over an episode.
The critic’s predictions, which initially lie in the range [-1, +1], result in enormous squared errors when
compared to these large-scale returns. When comparing the orders of magnitude of the different loss
components (see fig. 15), the imbalance becomes evident.

 18

 Figure 15: While the actor loss is close to 0, the critic loss reaches 1e+5.

 I tried various approaches of adressing this problem.
  1. Normalize the returns. Claude code recommended normalizing the returns to bring them
 to a comparable scale. While it improved the learning, it is conceptually wrong. For the actor
 loss, we compare the actual reward obtained to the critic value estimation. If the critic learns
 on normalized values, the predictions will not reflects anymore the reward scale, corrupting the
 advantage calculation.
  2. Separate actor and critic training. I seperate the two loss functions and their optimization.
 The actor and the critic are then trained independently, with updates based on their own loss
 signal.
  3. Rewards scaling. To help the critic learning the value, I rescales the rewards to bring values
 closer to the range [-1,1].

6.5 New environment and Multigraph PartGeoNet
We then applied PartGeoNet to the new environment. This turned out to be quite complicated and
unsatisfactory. In fact, the “third node cut” action consistently generates a new quad whenever it can
be performed. This makes it the ideal action from our agent’s perspective. By performing this action,
the agent will always obtain a quad—and thus a reward. To avoid this problem, I chose to create a
reward function based on the orthogonality of the interior angles. However, this approach also has a
problem: the triangles are not penalized enough. Consequently, I believe the rewards are consistent,
but the topological quality tends to be too low.

7 Conclusion
After familiarizing with the existing code and integrating TensorBoard and Optuna, we explored
various reward functions. Unfortunately, the results were inconclusive, and no reward function seemed
to outperform the initial one. We therefore decided to completely overhaul the architecture of our RL
agent to use PartGeoNet. PartGeoNet is based on the PPO algorithm and uses a GNN to create a
latent representation of the state. This representation is then used to predict the cuts to be made.
After several adjustments and improvements to the PartGeoNet structure, the results proved to be
slightly better during both training and deployment. However, given the very marginal improvement,
it might be worthwhile to make more significant changes to the problem formulation.

8 Perspectives
Following this work, we can consider various perspectives:

 • Incremental learning. Train the model progressively on datasets of increasing difficulty.
 • Improve evaluation. Add new metrics during evaluation. For example, during stochastic
 evaluation, it would be interesting to know the mean and standard deviation of the topological
 quality obtained for each geometry. It might also be interesting to evaluate the meshability of
 the resulting decomposition.
 • Meshability as an objective. How could we define a meshability index? Could we use this
 criterion for learning?
 • New observations. Use the existing multi-graph GNN structure to test different observations.
 • Analysis of vertex selection. It would be interesting to add metrics to understand and
 evaluate the vertex selection made by the agent.
 • Templates. Use a set of template-based actions to subdivide the geometry.
 • GNN architecture with link prediction. We could construct the BREP graph of the ge-
 ometry, then add vertices at singularities and other points of interest, and then use a GNN to
 predict edges between the vertices, with each new edge corresponding to a cut.
