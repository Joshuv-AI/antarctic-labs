MemCollab : Cross-Agent Memory Collaboration via Contrastive Trajectory Distillation
Yurui Chang, Yiran Wu, Qingyun Wu, Lu Lin

Abstract
Large language model (LLM)–based agents rely on memory mechanisms to reuse knowledge from past problem-solving experiences. Existing approaches typically construct memory in a per-agent manner, tightly coupling stored knowledge to a single model’s reasoning style. In modern deployments with heterogeneous agents, a natural question arises: can a single memory system be shared across different models? We found that naively transferring memory between agents often degrades performance, as such memory entangles task-relevant knowledge with agent-specific biases. To address this challenge, we propose MemCollab , a collaborative memory framework that constructs agent-agnostic memory by contrasting reasoning trajectories generated by different agents on the same task. This contrastive process distills abstract reasoning constraints that capture shared task-level invariants while suppressing agent-specific artifacts. We further introduce a task-aware retrieval mechanism that conditions memory access on task category, ensuring that only relevant constraints are used at inference time. Experiments on mathematical reasoning and code generation benchmarks demonstrate that MemCollab consistently improves both accuracy and inference-time efficiency across diverse agents, including cross-modal-family settings. Our results show that the collaboratively constructed memory can function as a shared reasoning resource for diverse LLM-based agents.

Introduction

Large Language Model-based agents are increasingly applied to solve complex tasks that require multi-step reasoning and tool use. Despite their strong capabilities, they still face the limitations of episodic information: knowledge acquired from previous problem-solving trajectories is not persistently retained, and inference is constrained to a fixed context window
(
15
;
13
)
. As a results, agent may repeatedly explore the similar reasoning strategies, encounter the same error patterns, and fail to utilize the tool feedback from prior executions
(
25
;
1
)
. To address these challenges, memory mechanism is leveraged to enable agents to store and retrieve reusable information when solving related tasks in the future inference
(
40
;
31
)
.

Recent work has shown that augmenting LLMs with memory can improve reasoning ability. For example BoT
(
35
)
distills reasoning template from past experiences and retrieves them at the inference time. Most prior approaches couple memory tightly with the underlying model or agent: the memory is constructed from that model’s own reasoning traces and the agent’s own interaction trajectories, and is then reused by the same model or agent. In contrast, modern deployments increasingly involve heterogeneous model ecosystems: multiple agents with different model sizes or architectures operating within the same application (e.g., via specialization, orchestration, or routing among models). This motivates a natural question:
can a single memory system be shared across different models?

A naive approach is to directly transfer the memory built from one agent to another. In Figure
1
, we study how external memory affects agent performance. We compare the no-memory baseline to variants that use memory built from the same model and memory built from another model. The results indicate that directly utilizing memory across models would lead to worse performance than using memory distilled from own trajectories. This indicates that the memory tends to reflect the originating model’s preferences and reasoning style such as preferred solving strategies and habitual heuristics, rather than objective and transferrable knowledge. This motivates studying whether we can construct more transferable memory by leveraging and contrasting trajectories from different models, extracting shared, reusable guidance while reducing agent-specific bias.

In this paper, we propose
MemCollab
, a memory framework designed to produce
agent-agnostic
memory. Such memory can be reused across heterogeneous models while
outperforming memory distilled from a model’s own trajectories
(Figure
1
).

MemCollab
extracts reusable reasoning guidance and tool-usage instructions by identifying universal invariances and discrepancies across agents instead of encoding model-specific preferences. This contrastive approach filters out agent-specific biases while preserving transferrable reasoning constraints and error-forbidden patterns. To ensure that memory entries capturing task-relevant reasoning procedures and error patterns are retrieved for a specific task, we design our task-aware retrieval mechanism that retrieving memories conditioned on the task’s category. We summarize our contributions below:

•

We identify and systematically study the problem of using a single memory to support multiple LLM-based agents, a setting that is increasingly relevant as modern deployments involve collections of agents with different model sizes, architectures, and roles, but remains unexplored in existing agent-memory works.

•

We introduce a new memory collaboration paradigm that derives memory through contrastive analysis of reasoning traces generated for the same task. Instead of accumulating raw experiences, the memory distills transferrable reasoning strategies and cross-model failure modes. By decoupling the underlying logical structure from individual architectural biases, we produce a refined memory that captures the essence of the problem-solving process.

•

Through rigorous evaluation on complex mathematical reasoning and code generation benchmarks, we show that
MemCollab
consistently enhances the performance of both weaker and stronger models. Beyond accuracy gains, our approach improves inference-time efficiency by providing highly distilled, low-noise reasoning prompts.

Related Works

2.1
Memory for LLM Agents

Memory has become a core module for LLM-based agents, enabling them to address limited context windows and reuse information across episodes
(
39
;
21
)
. Memory content can take the form of free-form text or structured artifacts, and can be retrieved to guide subsequent reasoning and tool use by agents
(
23
;
40
;
24
)
.Existing memory mechanisms include episodic memory that records interactions and manage multi-tier context
(
24
)
, long-term interaction memory that supports continual recall and update
(
40
)
, and reasoning oriented memory that distills reusable guidance to support problem solving
(
35
;
28
;
23
)
. Beyond the types of content stored in memory, many studies investigate memory organization and operations, including agentic linking and evolution of memory graphs
(
31
)
, as well as training-based memory management that learns what to store, update, and retrieve through reinforcement learning
(
41
;
33
;
34
)
. While these approaches demonstrate strong performance, they typically focus on improving a single agent. Memory is synthesized from an agent’s own trajectories and subsequently consumed by the same agent, thereby limiting the scope of the guidance to cross-agent reuse. In contrast to prior approaches, our work investigates how a single memory system can be constructed to benefit multiple agents with different model sizes and architectures. Rather than storing episodic traces or learning agent-specific memory policies, we construct memory by contrasting agent trajectories generated for the same task, distilling normative reasoning constraints and error-forbidden patterns that are invariant to different agents. This design targets transferable reasoning guidance that can be reused across agents, a setting which has received limited attention in existing work.

2.2
Retrieval-Augmented Model Generation

Retrieval-augmented generation (RAG) extends LLMs with access to external corpora and has been widely adopted to improve factuality and coverage by conditioning model outputs on passages retrieved by an auxiliary retriever
(
16
)
. Subsequent work has shown that both the type of retrieval source and the granularity of retrieval units substantially influence generation quality
(
8
)
. Beyond unstructured text corpora
(
17
;
32
)
, retrieval sources have been extended to semi-structured
(
38
;
20
)
and structured data
(
9
;
11
;
7
)
, as well as content generated or distilled by LLMs themselves
(
36
;
5
)
. In parallel, prior studies explore retrieval at different granularities, ranging from coarse-grained units such as full documents or long passages
(
37
;
27
)
to fine-grained units such as sentences, entities, or code snippets
(
4
;
30
)
. In contrast to document-centric RAG, our method retrieves reasoning-oriented memory rather than external knowledge. We adopt a coarse-grained memory representation but perform task-level classification prior to retrieval, allowing the system to restrict the search space and reduce irrelevant or incompatible memory. This design enables precise retrieval of task-relevant reasoning guidance while avoiding the overhead and noise associated with fine-grained retrieval.

3
Methodology

We propose
MemCollab
, a memory collaboration framework that improves the agent’s reasoning by inducing contrast-derived problem-solving strategies from heterogeneous agent trajectories. The core idea is to distill reusable high-level reasoning strategies and error-forbidden constraints that distinguish successful reasoning from failures, while filtering out agent-specific biases.

MEMCOLLAB consists of two stages: (1)
contrast-derived memory construction
, which extracts abstract reasoning constraints from paired agent trajectories; and (2)
task-aware memory retrieval and inference
, which conditions agent reasoning on relevant memory entries at test time. An overview of the framework is shown in Figure
2
.

3.1
Problem Setup and Notation

Let
\mathcal{A}=\{A_{w},A_{s}\}
denote the pair of agents with heterogeneous reasoning capacities (e.g., different model sizes or architectures). Each agent
A_{i}
is instantiated with a base backbone LLM
f_{i}
and produces a multi-step reasoning trajectory when solving a task. Given a task instance
x
, each agent independently generates a reasoning trajectory

\tau_{i}^{(x)}=(r_{1},r_{2},\dots,r_{T_{i}}),

(1)

where each element
r_{t}
represents an intermediate reasoning step, which may incorporate natural language reasoning, code, and code execution feedback. We assume access to a training set of tasks
\mathcal{D}
, each with a ground-truth solution or executable verifier. Our goal is to construct a shared memory bank
\mathcal{M}
that can be retrieved and reused by multiple agents at inference time.

3.2
Contrast-Derived Memory Construction

Algorithm
1
summarizes the detailed procedure for memory bank construction, with major steps explained as below.

Trajectory Pairing and Preference Selection.

For each task
x\in\mathcal{D}
, we collect a pair of trajectories
(\tau_{w},\tau_{s})
by executing both agents on the same input. To determine which trajectory reflects correct reasoning, we employ an indicator model
\mathcal{I}(\cdot)
, which evaluates a trajectory against the task’s ground truth (e.g., by checking the final answer or code execution result). The preferred and unpreferred trajectories are defined as:

(\tau^{+},\tau^{-})=\begin{cases}(\tau_{w},\tau_{s})&\text{if $\mathcal{I}(\tau_{w})=1$,}\\
(\tau_{s},\tau_{w})&\text{otherwise.}\end{cases}

(2)

This formulation allows the preferred trajectory to originate from either agent, ensuring robustness to failures of incorrect trajectories from the weaker agent
A_{w}
.

Contrastive Trajectory Analysis.

Rather than performing step-by-step comparison,
MemCollab
summarizes the trajectory comparison by contrasting trajectories at the structural reasoning level, including the high-level solution algorithms, planning steps, and the interpretation of the tool feedback. Specifically, given a preferred trajectory
\tau^{+}
and an unpreferred trajectory
\tau^{-}
, we summarize their differences into structured guidance, using the backbone model
f_{s}
of agent
A_{s}
(see Appendix
G
for detailed prompt). By contrasting these trajectories, we distill (1)
violation patterns
that characterize systematic reasoning failures in
\tau^{-}
(e.g., premature computation and incorrect symbolic mapping), and (2)
reasoning invariants
preserved in
\tau^{+}
but absent or violated in
\tau^{-}
(e.g., structural principles required to avoid failures). These invariants and discrepancies in the reasoning procedure reflect transferrable guidance that maps correct outcomes to incorrect ones while abstracting away model- or instance-specific content.

Formally, summarization over contrastive pairs could be defined as a discrepancy operator:

\Delta(\tau^{-},\tau^{+})=\{(v_{k},i_{k})\}_{k=1}^{K},

(3)

where
v_{k}
denotes a violated reasoning pattern observed in
\tau^{-}
, and
i_{k}
denotes the corresponding reasoning invariant preserved in
\tau^{+}
. Example pairs are provided in Appendix
F
. The parameter K controls the maximum number of extracted entries per task. This abstraction focuses on guidance of on how the task is solved rather than what specific solution is produced, enabling generalization beyond individual problem instances.

Each contrastive pair is distilled into a normative reasoning constraint of the form:

which jointly specifies a required reasoning invariant and an explicitly forbidden pattern. These constraints are expressed using abstract reasoning concepts (e.g., accumulation, conditioning, proportionality, case enumeration, variable isolation) rather than task-specific details.

(5)

where each task instance

Note that this memory bank stores only
normative, abstract reasoning constraints
, not raw trajectories, demonstrations, or solutions.

3.3
Task-Aware Memory Retrieval and Inference

Algorithm 2 summarizes agent inference procedure, augmented with contrastive memory. Given a new task
q
, the agent
A
now needs to first retrieve task-related memory from the bank
\mathcal{M}
.
Different tasks impose fundamentally different reasoning requirements, including how constraints are represented and how tools are integrated during the problem solving.
Retrieving memory entries that are incompatible with the current task can therefore introduce noise and interfere with inference. To address this challenge, we organize memory bank using task-aware structure and condition retrieval on the query’s task category.

Task Categorization.

We use the agent’s base LLM
f\in\mathcal{F}
as a task classifier. Given a task input
x
, the model classify it into a task category and subcategory:

(c_{x},u_{x})=f(x).

(6)

This task categorization procedure is applied consistently in two stages: (1)
Memory Organization
. During memory construction, each memory entry
m\coloneq m^{(x)}
inherits the task category of the task instance
x
from which it is derived, i.e.,
(c_{m},u_{m})=(c_{x},u_{x})
. These labels are computed once and stored for efficient retrieval.

(2)
Inference-Time Routing
. At inference time, the same model is used to classify the query
q
into categories
(c_{q},u_{q})
, which later determines the subset of memory bank eligible for retrieval.

Memory Retrieval.

During inference, given the predicted task category of query
(c_{q},u_{q})
, the agent retrieves the top-
p
most relevant entries conditioned on the task classification:

\mathcal{M}_{q}=\text{Top-}p\left(\{m\in\mathcal{M}\mid c_{m}=c_{q},\ u_{m}=u_{q}\}\right).

(7)

This two-stage process, task-based filtering followed by relevance ranking, substantially reduces the retrieval search space and mitigates interference from irrelevant reasoning constraints, compared to solely similarity based retrieval.

Memory-Guided Inference.

Finally, the agent reasons and generates the solution by conditioning on the retrieved normative constraints:

y=A(q,\mathcal{M}_{q}).

(8)

The retrieved constraints act as soft guidance that encourages structurally valid reasoning and discourages previously observed failure patterns, including tool-usage mistakes.

3.4
Why Contrast Works

Constructing transferable memory across agents is challenging because raw reasoning trajectories entangle
task-relevant structure
with
agent-specific bias
, such as stylistic preferences and heuristic shortcuts. Memory distilled from a single agent often preserves such bias, limiting its usefulness when transferred to other agents.

Suppose we can model the agent trajectory as
\tau=g(s,b)
, where
s
represents the task-relevant structures required to solve this problem, and
b
captures agent-specific bias.
While
b
varies across agents, successful trajectories for the same task share similar
s
. The goal of collaborative memory is thus to capture the shared invariants
s
while suppressing agent-specific information
b
.
Accordingly, we interpret the distilled memory
m
to be an encoding of the reasoning invariant, i.e.,
m=\phi(s)
.
By contrasting a preferred trajectory against an unpreferred one generated for the same task,
MemCollab
highlights the essential reasoning factors that distinguish success from failure, while suppressing variations that do not affect correctness.
This intuition aligns with principles from
contrastive learning
, where meaningful features emerge by contrasting positive samples from negative ones. Appendix
D
provides more discussions.

Contrastive memory construction is not constrained by the model architectures.

4.4
Case Study

In Figure
3
, we present a case on how
MemCollab
works. For the source problem, the unpreferred response mistakenly assumes independence in a setting with dependencies in a probability problem. In contrast, the preferred response correctly models the joint probability by conditioning on earlier events and systematically enumerating the relevant cases. The resulting memory guidance distills this central distinction between the two reasoning trajectories.

When solving the target problem, the vanilla agent exhibits the same failure mode, again relying on an implicit independence assumption and an underspecified enumeration of cases. After retrieving the contrastive memory, the agent can adopt explicit case analysis, leading to a coherent joint-probability formulation and the correct solution.

4.5
Effect of the Number of Retrieved Memory Entries

Figure
4
shows that agent performance initially improves as the number of retrieved memories increases, but degrades beyond a task-dependent threshold. Since the agent consistently achieves strong performance when retrieving the top three most relevant tasks, we set p = 3 in all experiments.

This behavior can be interpreted from a spatial pruning perspective, where failure patterns stored in memory implicitly constrain the agent’s search space by pruning irrelevant regions, thereby improving the signal-to-noise ratio. Theoretically, let b denote the original branching factor and d the search depth. If k erroneous patterns are identified and disabled through retrieved contrastive memories, the effective search space contracts with ratio

\rho=\left(1-\frac{k}{b}\right)^{d}
.
As long as
k\geq 1
, we have
\rho<1
, implying strict exponential contraction of the search space. However, as the retrieval size increases, additional memories expand the representation subspace to include weakly relevant or noisy directions, weakening the pruning effect and increasing attention dispersion. This trade-off explains the observed non-monotonic trend and the existence of an optimal retrieval budget, which varies across tasks depending on the locality and complexity of their underlying solution manifolds.

5
Conclusions

In this work, we study the problem of constructing a single shared memory to support multiple LLM-based agents. We show that directly transferring memory between agents is ineffective, as agent-specific biases and reasoning patterns can be entangled with reusable knowledge. To address this challenge, we propose a collaborative memory framework that synthesizes memory by contrasting trajectories generated by different agents for the same task, distilling high-level reasoning guidance and error-forbidden patterns. Extensive experiments across mathematical and coding benchmarks demonstrate that the resulting memory generalizes across heterogeneous agents, improving both accuracy and inference-time efficiency. Future work may extend this contrastive formulation to multi-agent settings by selecting a preferred trajectory and treating others as unpreferred, pointing toward shared memory systems that scale to larger collections of interacting agents.

Impact Statement

This paper presents work whose primary goal is to advance the field of machine learning by improving the efficiency and reusability of memory systems for large language model–based agents. By enabling a single shared memory to support multiple heterogeneous agents, our approach has the potential to reduce redundant computation and resource usage in practical deployments, which may contribute to more scalable and energy-efficient AI systems. At the same time, the proposed method operates entirely on model-generated reasoning trajectories and does not introduce new data collection, personalization, or user profiling mechanisms. The memory distilled by our approach focuses on abstract reasoning guidance and error-forbidden patterns rather than storing raw interactions, sensitive information, or task-specific solutions, which mitigates risks related to data privacy or memorization.We do not anticipate ethical concerns beyond those commonly associated with deploying large language models, and the societal implications of this work are consistent with well-established considerations in the machine learning literature.

D.1
Discussion on Contrastive Memory

In this section, we provide analysis for interpreting the validity of constructing our collaborative memory by contrasting agents’ trajectories. Our analysis clarifies the memory synthesized process through the lens of the contrastive learning.

D.2
Contrastive Learning

Contrastive learning provides a statistical framework for understanding how representations can be shaped by the comparison between the positive and negative pairs. The widely used comtrastive objective loss function is the infoNCE loss:

\mathcal{L}_{\mathrm{InfoNCE}}=-\mathbb{E}\!\left[\log\frac{\exp(g(x,x^{+}))}{\exp(g(x,x^{+}))+\sum_{j}\exp(g(x,x_{j}^{-}))}\right],

(9)

where
g(\cdot,\cdot)
denotes the scoring function,
x
and
x^{+}
are from positive pairs, and
\{x_{j}^{-}\}
are negative samples
(
19
)
.

The simplified version of the loss function could be defined as
(
26
)
:

-\mathbb{E}\!\left[\log\frac{\exp(g(x,x^{+}))}{\exp(g(x,x^{+}))+\exp(g(x,x^{-}))}\right],

(10)

D.3
Contrastive Memory Learning

We analyze the behavior of the contrast-derived memory from the perspective of the contrastive learning.

Suppose an agent trajectory is represented as
\tau
, which is composed of two factors: a task-specific reasoning strategies and agent-specific bias. Formally, we assume:

\tau=f(s,b),

(11)

where
s
denotes the underlying reasoning structure required to solve the task, and
b
captures agent-dependent variations such as architectural preferences or stylistic choices. Accordingly, we interpret the contrast-derived memory
m
as a function of the reasoning component, i.e.,
m=\psi(s)
, while being largely insensitive to the bias term
b
. Given these assumputions, we define a proxy optimization objective for the contrastive memory learning as:

\mathcal{L}_{\mathrm{MemNCE}}=-\mathbb{E}\!\left[\log\frac{\exp(g(\tau,m))}{\exp(g(\tau,m))+\sum_{j}\exp(g(\tau_{j}^{-},m))}\right],

(12)

where
\{\tau_{j}^{-}\}
denote false trajectories corresponding to the same task. In our setting, contrast is performed over a single preferred trajectory and a single flawed trajectory, corresponding to the pairwise case with
j=1
negative sample.
22
shows that even with a single negative sample,
pairwise contrast preserves the density-ratio interpretation central to contrastive learning.

Under this view, the
\mathcal{L}_{\mathrm{MemNCE}}
provides an interpretive tool for understanding the effectiveness of the contrast-derived memory. Instead of directly optimizing this objective, our goal is to introduce a proxy learning objective that clarifies the underlying memory extraction mechanism. By contrasting preferred and unlike trajectories, the distilled memory emphasizes reasoning factors and recurring pitfalls that persist across problem-solving processes, while ignoring the agent-specific biases and noises. Unlike episodic storage or direct trajectory reuse, our collaborative memory encourages memory distillation into abstract reusable, high-level guidance. This perspective helps explain why memory constructed through contrast can generalize across tasks and agents.
