Abstract
The Energy Research and Forecasting (ERF) model is a high-performance atmospheric
model built on the AMReX adaptive mesh refinement (AMR) framework, enabling efficient
simulations on heterogeneous computing platforms that combine multicore processors with
hardware accelerators. To support land–atmosphere interactions within ERF’s AMR-based
environment, a land-surface model must be capable of operating directly on hierarchically
refined meshes. In this work, we present a methodology for coupling the Fortran-based
Noah-Multiparameterization (Noah-MP) land-surface model with ERF’s C++ codebase.
Rather than rewriting Noah-MP, we construct a Fortran–C interoperability layer using
CodeScribe, a tool that leverages large language models (LLMs) to automate the generation
of interface code. CodeScribe applies structured prompting techniques to generate bindings
that support efficient data exchange and function calls between ERF and Noah-MP. The
coupling framework also incorporates AMR-aware data handling strategies, allowing Noah-
MP to operate seamlessly within ERF’s hierarchical mesh structure. This work provides a
structured approach for integrating legacy Fortran models into modern C++-based modeling
systems using LLM-assisted code generation.

Keywords: Noah-MP, land-surface model, Energy Research and Forecasting, ERF, Fortran–
C interoperability, adaptive mesh refinement, AMReX, GPU acceleration, large language
models, code generation

1 Introduction
High-resolution regional atmospheric models play a critical role in understanding land-
atmosphere interactions, predicting weather and climate, and informing energy systems risk
from extremes and planning for resilience. While legacy systems such as the Weather Research
and Forecasting (WRF) model [Skamarock et al., 2019] have historically addressed these needs,
they are primarily implemented in Fortran and optimized for CPU-centric computing. As high-
performance computing (HPC) systems evolve to incorporate heterogeneous architectures,
blending multicore CPUs with hardware accelerators such as GPUs, models like WRF face
growing challenges in scalability, extensibility, and performance portability.
To overcome these limitations, the Energy Research and Forecasting (ERF) model has been
developed as a C++-based, performance-portable atmospheric simulation framework [Almgren
et al., 2023, Lattanzi et al., 2025]. Built on AMReX [Zhang et al., 2019], a block-structured
adaptive mesh refinement (AMR) library, ERF supports localized grid refinement, subcycled
time integration, and efficient execution across diverse computing environments. This makes
ERF ideally suited for simulations spanning mesoscale weather to microscale turbulence,
especially in complex terrain or urban canopies where resolution and scalability are critical.
Accurate modeling of land-surface processes is essential for simulating realistic atmospheric
boundary layer dynamics [Santanello et al., 2011, Jaeger et al., 2009]. Among available
LSMs, the Noah-Multiparameterization (Noah-MP) land-surface model is a widely used,
community-maintained Fortran code with over 80 configurable physics modules covering
vegetation dynamics, snow processes, soil thermodynamics, runoff, irrigation, and radiation
[Niu et al., 2011, Yang et al., 2011, He et al., 2023]. However, integrating Noah-MP with
ERF introduces a significant interoperability challenge due to differences in programming
language, memory management, and execution paradigms across CPU/GPU hardware.
Rather than rewriting Noah-MP in C++, a costly and error-prone endeavor, we introduce
a Fortran-C interoperability interface. This interface allows ERF to treat Noah-MP as
a host physics module while maintaining compatibility with AMR, shared memory, and
GPU-resident data structures. Central to this integration is the use of CodeScribe [Dhruv
and Dubey, 2025], a generative AI–based tool that automates interface code generation.
This report describes the system architecture, the use of large language models (LLMs) to
construct interoperable bindings, and the performance considerations for deploying Noah-MP
within ERF’s hierarchical AMR driver.

2 Overview of ERF and Noah-MP land-surface Model
The Energy Research and Forecasting (ERF) model is a modern regional atmospheric
modeling framework designed for scalable, high-fidelity simulations across a range of spatial
and temporal scales. ERF is tailored to simulate atmospheric phenomena such as boundary
layer turbulence, terrain-induced flows, and wind turbine wakes—all of which are essential for
environmental and energy system research. ERF’s dynamical core supports both compressible
and anelastic flow formulations on an Arakawa C-grid. Time integration is performed using
a third-order Runge–Kutta scheme with acoustic substepping for the compressible equations,

while a second-order Runge–Kutta scheme without substepping is used for the anelastic
configuration [Lattanzi et al., 2025].
ERF is built atop the AMReX framework, which provides block-structured adaptive mesh
refinement (AMR) and parallel performance portability. AMReX enables ERF to dynamically
allocate higher resolution in regions of interest, such as near the ground or in areas of
steep terrain, while maintaining coarse resolution elsewhere. This capability, combined
with GPU acceleration through CUDA, HIP, and SYCL, allows ERF to run efficiently on
heterogeneous HPC architectures using hybrid parallelism (MPI + OpenMP/GPU threading).
ERF includes a suite of physics parameterizations for turbulence, cloud microphysics, and
land-surface exchanges, and supports multiple initialization modes, including idealized profiles
and NetCDF datasets.

The Noah-Multiparameterization (Noah-MP) land-surface model complements ERF by
simulating the physical processes at the land–atmosphere interface. These include surface
radiation balance, vegetation dynamics, multi-layer soil and snow hydrology, and carbon
fluxes. Noah-MP divides each grid cell on the surface into vegetated and bare-soil fractions
and computes energy and moisture budgets independently before aggregation. It supports
over 80 configurable multiphysics options, allowing for sensitivity studies and ensemble runs.
Implemented in Fortran with modular interfaces and derived data types, Noah-MP offers a
scientifically robust and complementary component to ERF.

ERF exposes land-surface modeling through a polymorphic plug-in interface that currently
supports four backends: NullSurf (no land model, default), SLM (simple soil diffusion),
MM5 (Monin–Obukhov similarity), and NOAHMP (full Noah-MP). Each backend implements
a common interface—initialize, advance one timestep, and expose surface fluxes—and is
selected at runtime via erf.land_surface_model = NOAHMP with no source changes required.
The NOAHMP backend accepts WRF Preprocessing System input files directly, making it
straightforward for application scientists to run existing WRF real cases within ERF.
As shown in Figure 1, our integration couples ERF with Noah-MP via a shared memory
interoperability interface centered on the NoahmpIO structure. This structure is defined
as a Fortran derived type and mirrored in C++ using a class of the same name. Pointer
casting and memory alignment enable zero-copy data access across the language boundary,
avoiding performance bottlenecks during land-surface flux computations. Specialized container
classes (NoahArray1D, 2D, and 3D) ensure Fortran-style indexing compatibility and seamless
integration with AMReX’s grid data structures.

The split-ownership design reflects the distinct lifetime and layout requirements of each field
category. Scalar domain bounds (ids, ide, jds, jde, kds, kde) and configuration integers
(NSOIL, NSNOW, ITIMESTEP) are lightweight values set once during initialization and naturally
owned by C++, with the Fortran side holding only a C_INT pointer alias. In contrast, large
multidimensional arrays—two-dimensional surface fields such as XLAT, SHBXY, and EVBXY,
and three-dimensional atmospheric forcing arrays including T_PHY, QV_CURR, U_PHY, and
V_PHY—are allocated by Fortran using its native memory manager to preserve the contiguous,
column-major storage order required by Noah-MP’s internal numerical routines. Their base
addresses are subsequently exposed to C++ via C_LOC, enabling direct pointer access with no
data copying across the language boundary. This approach avoids double allocation, preserves
Noah-MP’s existing memory assumptions, and centralizes pointer lifetime management at
the C++ AMR driver layer where ERF controls the simulation lifecycle.

type, public :: NoahmpIO_type
  ! Scalars -- C_INT pointer: memory owned by C++

  integer(C_INT), pointer :: ITIMESTEP, NSOIL, NSNOW
  ! 2D surface fields (xstart:xend, ystart:yend) -- Fortran-allocated
  real(kind=C_DOUBLE), allocatable, dimension(:,:) :: XLAT, WSLAKEXY
  real(kind=C_DOUBLE), allocatable, dimension(:,:) :: SHBXY, EVBXY
  ! 3D atmospheric forcing (xstart:xend, kds:kde, ystart:yend)
  real(kind=C_DOUBLE), allocatable, dimension(:,:,:) :: T_PHY, QV_CURR
  real(kind=C_DOUBLE), allocatable, dimension(:,:,:) :: U_PHY, V_PHY

subroutine NoahmpIOVarInitDefault_fi(noahmpio) bind(C)
  type(NoahmpIO_type_fi), intent(inout) :: noahmpio
  integer(C_INT), pointer :: bid
  call C_F_POINTER(noahmpio%BLKID, bid)
  call NoahmpIOVarInitDefault(NoahmpIO(bid)) ! Fortran allocates arrays
  noahmpio%T_PHY = C_LOC(NoahmpIO(bid)%T_PHY) ! expose address to C++
  noahmpio%SHBXY = C_LOC(NoahmpIO(bid)%SHBXY)
  noahmpio%EVBXY = C_LOC(NoahmpIO(bid)%EVBXY)
end subroutine

// NoahmpIO.cpp -- wrap Fortran-owned pointers with tile bounds
void NoahmpIO_type::VarInitDefault() {
  NoahmpIOVarInitDefault_fi(&fptr);
  XLAT = NoahArray2D<double>(fptr.XLAT, {xstart,ystart}, {xend,yend});
  T_PHY = NoahArray3D<double>(fptr.T_PHY, {xstart,kds,ystart}, {xend,kde,yend});
  SHBXY = NoahArray2D<double>(fptr.SHBXY, {xstart,ystart}, {xend,yend});
}

template <typename T>
struct NoahArray2D {
  std::array<int,2> begin = {1,1};
  std::array<int,2> end = {0,0};
  T* data;

 constexpr NoahArray2D(T* arr,
 std::array<int,2> b, std::array<int,2> e) noexcept
 : data(arr), begin(b), end(e) {}

  T& operator()(size_t i, size_t j) {
    return data[i-begin[0] + (end[0]-begin[0]+1)*(j-begin[1])];
  }
};

Together, these three components—the Fortran bridge module, the C++ class, and the
index-remapping array wrappers—constitute a compact interoperability layer that enables
ERF to drive Noah-MP across the language boundary with no modifications to the underlying
land-surface model source. Pointer ownership is centralized at the C++ layer, Fortran memory
assumptions are preserved for physics arrays, and zero-copy access is maintained throughout
the coupling lifecycle. This design keeps the interface self-contained and straightforward to
extend as new Noah-MP variables or member functions are required.

3 Use of Generative AI for Building Fortran/C++ Interface
The development of a robust interoperability layer between Noah-MP and ERF required
the translation of complex Fortran data types, subroutines, and calling conventions into
corresponding C++ constructs. Rather than manually crafting these bindings, we used
CodeScribe [Dhruv and Dubey, 2025], a Python-based generative AI tool that uses large
language models (LLMs) to help generate interface code. CodeScribe was originally developed
for high-energy physics (HEP) applications and was extended in this work to support Earth
system modeling needs.
As depicted in Figure 2, the CodeScribe workflow begins with static analysis of the Noah-MP
Fortran source tree and the creation of lightweight template files tailored to fit within the
context window of large language models (LLMs). These templates are embedded in chat
completion prompts, referred to as seed prompts, which guide the LLM in generating relevant
code. CodeScribe then extends these templates to produce C++ wrappers, Fortran interface
layers, and pointer-safe bindings for user-specified variables. Interaction with the LLM is
facilitated through its API. Developers review LLM-generated files and accept the output or
modify the seed prompts and metadata to iteratively refine the results.
A central product of this workflow is the NoahmpIO interface, which encapsulates all variables
required for land-surface modeling. CodeScribe generates matching C++ representations of
this structure, enabling direct memory exchange. The interoperability interface is designed to
compile as a standalone library. Our evaluation found that GPT-4o is the most reliable LLM
for generating semantically valid and semantically correct bindings, substantially reducing
the developer burden. A formal model sensitivity study comparing GPT-4o, GPT-3.5 Turbo,
CodeLlama-7B, and Mistral-7B across Fortran–C interface generation tasks is reported in
Dhruv and Dubey [2025], where GPT-4o demonstrated the lowest combined developer time
for code review and testing. This AI-enabled pipeline demonstrates how LLMs can support
scientific software engineering by automating boilerplate and structural code development,
particularly for legacy systems with complex type hierarchies and rigid language boundaries.
Beyond this specific application, CodeScribe is designed as a general-purpose AI-assisted
framework for scientific software development. Unlike commercial tools such as OpenAI
Codex, Claude Code, Cursor, or GitHub Copilot, which prioritize convenience within closed
ecosystems, CodeScribe emphasizes transparency, configurability, and reproducibility. It

Because ERF is designed for execution on GPUs and Noah-MP remains a CPU-based model,
the coupling requires an efficient host–device data exchange mechanism. We employ AMReX’s
pinned memory arena (The_Pinned_Arena()) to allocate host-accessible buffers that support
asynchronous memory transfer of MultiFab data between device and host. In AMReX, a
MultiFab is the fundamental distributed data structure for storing field variables; it represents

 8

ANL/EVS-26/12 4 Integration with Block-Structured Adaptive Mesh Refinement

a collection of Fortran-order, block-structured arrays defined over the computational mesh
and distributed across MPI ranks. The coupling sequence executed per AMR block per
timestep is as follows:
 1. ParallelFor (GPU): extract atmospheric forcing from the device MultiFab into a
 pinned FArrayBox (device-to-host transfer, D2H).
 2. Gpu::streamSynchronize(): stall until the D2H transfer completes before the CPU
 reads the data.
 3. LoopOnCpu: copy pinned data into the NoahmpIO forcing fields (T_PHY, QV_CURR, U_PHY,
 V_PHY, XLAT, etc.).
 4. DriverMain(): execute Noah-MP land-surface model on the host CPU.
 5. LoopOnCpu: copy Noah-MP results (SHBXY, EVBXY, WSLAKEXY, etc.) into pinned output
 buffers.
 6. ParallelFor (GPU): transfer fluxes from pinned buffers back to the device-resident
 MultiFab (host-to-device, H2D).
This design enables land-surface computations to scale with ERF’s AMR resolution while
preserving modularity, maintaining compatibility with Noah-MP’s internal data layout, and
minimizing communication overhead between CPU and GPU components.

GPU Coupling Bottleneck and Path Forward
The current host–device coupling strategy introduces two performance bottlenecks. First,
streamSynchronize() in step 2 stalls the GPU after the D2H copy until Noah-MP finishes on
the CPU, preventing GPU overlap with land-surface computations. Second, Nblocks separate
D2H/H2D round trips are required per timestep; finer AMR levels produce more blocks per
GPU, amplifying this overhead.
Several mitigations are planned. In the near term, all block data will be aggregated into a
single pinned buffer, reducing the D2H and H2D round trips to one per GPU per timestep.
Additionally, because land-surface state evolves slowly (on the order of tens of minutes),
Noah-MP will be called every N atmospheric steps via a ntime parameter rather than every
step. In the medium term, CPU Noah-MP execution will be pipelined asynchronously with
GPU dynamics on independent CUDA/HIP streams. The long-term goal is to port critical
Noah-MP physics kernels to SYCL or OpenMP target offload for direct GPU execution,
leveraging AMReX’s existing SYCL backend for heterogeneous systems including Aurora
(Argonne’s exascale supercomputer).
Together, these optimizations will position the ERF–Noah-MP framework for production-
scale regional climate simulations on DOE leadership computing facilities, where high spatial
resolution and multi-day integration periods demand sustained throughput across thousands
of GPU nodes. The modular interoperability layer also provides a natural foundation for
AI-driven research: the per-block NoahmpIO data streams generated at each AMR level
constitute structured, high-resolution training data for surrogate models of land-surface

5 Example Demonstration
In this section, we demonstrate the ERF–Noah-MP coupling using example forcings for
a simulation near the Columbia River Gorge. This demonstration serves as a functional
integration test, verifying that data exchange, field synchronization, and time-stepping operate
correctly across the interoperability layer. Figure 4 shows the initial conditions stored in
a two-level AMR hierarchy at 06:00:00 UTC on 17 August 2023; results reported here use
AMR level 0 only, with multi-level execution reserved for future work. Figure 6 shows the
corresponding land-surface variables computed by Noah-MP at 06:00:25 UTC. The forcing
fields were generated using the WRF Preprocessing System, and ERF’s Pathway capability
enables the direct execution of WRF real cases using standard WRF input and boundary
files.
The simulation domain covers approximately 400 km × 400 km centered on the Columbia
River Gorge, a geographically complex region characterized by the sharp contrast between the
Pacific-influenced marine climate west of the Cascades and the semi-arid continental climate

6 Conclusions
This work demonstrates a practical and extensible methodology for coupling a legacy Fortran
land-surface model with a modern C++ AMR-based atmospheric model. ERF’s polymorphic
LSM interface supports multiple backends (NullSurf, SLM, MM5, NOAHMP) through a common
base class, and the NOAHMP backend makes Noah-MP’s 80+ physics schemes accessible in
ERF production runs via namelist—with WPS input files read directly and no source changes
required. By using CodeScribe to automate the generation of the three-file interoperability
layer, we reduced the complexity and developer effort typically associated with cross-language
integration. The resulting interface preserves memory contiguity, minimizes data copy
overhead, and enables Noah-MP to operate across ERF’s hierarchical AMR grid.
The six-step host–device coupling protocol enables GPU-accelerated ERF to drive CPU-only
Noah-MP via pinned memory and streamSynchronize. The current bottleneck is per-block
D2H/H2D round trips; batched transfers and a reduced coupling frequency (Noah-MP called
every N atmospheric steps) are near-term mitigations, while GPU-native Noah-MP kernels
via SYCL or OpenMP target offload are the long-term goal.
The functional integration test at the Columbia River Gorge confirms that the coupling
framework handles initialization, field exchange, and time-stepping correctly under real
boundary-layer conditions, with WRF–Noah-MP baseline runs for the Tall Towers problem
available as a reference for planned physical validation. Looking forward, CodeScribe will
continue to be used to support the ERF–Noah-MP interface through porting, restructuring,
and optimization as the codebase evolves [Dubey and Dhruv, 2025].
