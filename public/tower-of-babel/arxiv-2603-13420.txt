Accelerating Suffix Jailbreak attacks with Prefix-Shared KV-cache
Xinhai Wang, Shaopeng Fu, Shu Yang, Liangyu Wang, Tianhang Zheng, Di Wang

Abstract
Suffix jailbreak attacks serve as a systematic method for red-teaming Large Language Models (LLMs) but suffer from prohibitive computational costs, as a large number of candidate suffixes need to be evaluated before identifying a jailbreak suffix. This paper presents Prefix-Shared KV Cache (PSKV), a plug-and-play inference optimization technique tailored for jailbreak suffix generation. Our method is motivated by a key observation that when performing suffix jailbreaking, while a large number of candidate prompts need to be evaluated, they share the same targeted harmful instruction as the prefix. Therefore, instead of performing redundant inference on the duplicated prefix, PSKV maintains a single KV cache for this prefix and shares it with every candidate prompt, enabling the parallel inference of diverse suffixes with minimal memory overhead. This design enables more aggressive batching strategies that would otherwise be limited by memory constraints. Extensive experiments on six widely used suffix attacks across five widely deployed LLMs demonstrate that PSKV reduces inference time by 40% and peak memory usage by 50%, while maintaining the original Attack Success Rate (ASR). The code has been submitted and will be released publicly.

Introduction

Suffix jailbreak attacks, which aim to synthesize jailbreak suffixes to bypass safety guardrails and elicit harmful content, have become a vital component for red-teaming Large Language Models (LLMs)
(
17
;
1
)
.
Current approaches primarily employ heuristic search
(
17
;
16
)
or LLM-based generators
(
9
)
to generate these suffixes.
However, a major bottleneck of these methods is their prohibitively high computational cost.
Standard optimization-based attacks must iteratively evaluate a vast number of
candidate
suffixes against the target LLM to identify effective jailbreaks.
While LLM-based generators offer faster test-time suffix generations, they merely shift the computational burden to the training phase, which still necessitates time-consuming suffix generation to construct training data.

Ideally, Key-Value (KV) caching could accelerate this evaluation process by reusing intermediate tensors.
However, in jailbreak scenarios, the system prompt is typically far longer than the suffix.
Standard KV cache implementations must duplicate this long prompt’s cache for every candidate suffix in a batch, inducing excessive memory consumption that limits batch size.
While state-of-the-art inference systems like vLLM
(
6
)
and SGLang
(
15
)
address these memory constraints through careful memory scheduling, they are designed strictly for forward-pass inference.
Their highly encapsulated interfaces and lack of backpropagation kernels prevent access to gradients, restricting their utility to a subset of gradient-free attacks (
e.g.
, BEAST attack
(
11
)
).
Consequently, these limitations collectively impede the effective acceleration of general suffix jailbreak attacks.

To overcome these limitations, we propose
Prefix-Shared KV Cache (PSKV)
, a lightweight, workload-aware, and plug-and-play framework tailored for accelerating suffix jailbreak attacks.
Our method is motivated by a key
structural redundancy
in jailbreak optimization: while a batch of candidate suffixes varies, they typically share an identical targeted harmful instruction as the prefix.
Standard KV cache implementations ignore this property, redundantly duplicating the long prefix cache for every candidate.
In contrast, PSKV maintains a single, shared KV cache for the invariant prefix and broadcasts it to all candidate suffixes during inference.
By employing a suffix-centric alignment strategy, PSKV supports dynamic expansion and parallel batched loss computation.
Crucially, unlike encapsulated inference engines, PSKV integrates seamlessly into existing attack pipelines, ensuring substantial acceleration and minimal memory overhead while preserving gradient access.

We evaluated PSKV across six widely used suffix jailbreak attacks and five popular open-source models.
We compared our framework against a baseline without KV cache and a standard KV cache implementation.
The results demonstrate that PSKV reduces inference time by approximately
40\%
compared to the no-cache baseline and decreases peak memory usage by
50\%
compared to the standard KV cache implementation.
Furthermore, because PSKV is a drop-in optimization that does not alter the high-level logic of the attack, it maintains the original Attack Success Rate (ASR).
This efficiency enables researchers to scale evaluations to larger models and broader search spaces that were previously computationally prohibitive.

In summary, our contributions are:

•

We identify the inefficiency of general-purpose inference caching when applied to the specific structural patterns of jailbreak suffix optimization.

•

We propose PSKV, a memory-efficient framework featuring virtual cache broadcasting and suffix-centric tensor alignment to eliminate redundant computations.

•

We conduct comprehensive evaluations demonstrating that PSKV substantially reduces both computational and memory costs, paving the way for a scalable LLM vulnerability assessment.

Related Work

Automated Suffix Jailbreaking.

Recent research has transitioned from manual red-teaming to automated adversarial optimization.
The foundational method, GCG
(
17
)
, employs a greedy, gradient-guided search to iteratively refine an adversarial suffix. Building on this, subsequent works have explored more sophisticated search strategies. BEAST
(
11
)
replaces the greedy algorithm with beam search to explore a wider range of promising candidates. Zhu’s AutoDAN
(
16
)
utilizes genetic algorithms to evolve suffixes, mitigating the local optima problem of purely greedy methods. Other variants like GCQ (Gradient-based Attack with Quantization)
(
4
)
focus on improving the efficiency of the core gradient-based update step itself.

An alternative paradigm uses LLMs themselves as generators. AdvPrompter
(
9
)
fine-tunes a language model to automatically compose adversarial prompts. Similarly, AmpleGCG trains a generative model to directly output effective suffixes, amortizing the search cost into a one-time training process
(
7
)
. Although these methods differ, they all require evaluating a large number of candidate suffixes to create a training set during either the model training or data generation phases. Our work presents an orthogonal optimization that accelerates this critical evaluation step, benefiting both categories of attack.

Efficient Inference & KV Caching.

Optimizing Key-Value (KV) cache management is central to high-throughput LLM serving.
vLLM
(
6
)
introduced PagedAttention to mitigate memory fragmentation in multi-user scenarios, while SGLang
(
15
)
employs RadixAttention to automatically detect and share prefixes across diverse incoming requests via a radix tree structure.
ChunkAttention
(
14
)
further optimizes memory locality.
However, these systems are architected for
asynchronous, multi-user serving
, prioritizing request scheduling and fairness over raw batch latency.
Applying them to the
synchronous, tight-loop
nature of adversarial attacks introduces unnecessary overhead (e.g., complex tree lookups, scheduler latency).
In contrast, PSKV is a workload-specific optimization that hard-codes the ”one-prefix-many-suffixes” pattern directly into the inference kernel, bypassing the complexity of general-purpose serving engines to achieve maximum efficiency for attack loops.

Preliminaries

Figure 1:
The computational pipeline of iterative suffix attacks.

As illustrated in Fig
1
, the workflow of a typical suffix-based jailbreak attack operates as an iterative cycle comprising three distinct phases: heuristic candidate generation, batched forward pass evaluation, and candidate selection. This pipeline forms the operational basis for the optimization problem defined below.

Adversarial Suffix Optimization.

We consider an LLM as a conditional distribution
p_{\theta}(y|x)
over a vocabulary
\mathcal{V}
.
Given a harmful query
x^{(h)}
(e.g., “How to build a bomb”) and a target response
y^{(h)}
, the goal of a suffix attack is to find an adversarial sequence
x^{(s)}\in\mathcal{V}^{L}
that maximizes the target probability:

\displaystyle x^{(s)*}=\mathop{\arg\max}_{x^{(s)}\in\mathcal{V}^{L}}\log p_{\theta}(y^{(h)}|x^{(h)}\oplus x^{(s)}),

(1)

where
\oplus
denotes concatenation.
Solving Eq. (
1
) typically involves iterative discrete optimization.
In the
heuristic search
phase, algorithms mutate the current suffix to generate a batch of
N
candidates,
\mathcal{S}=\{s_{1},\dots,s_{N}\}
.
Subsequently, during the
response generation
phase, these candidates are concatenated with the static prompt and the target response to form the batch
\{x^{(h)}\oplus s_{i}\oplus y^{(h)}\}_{i=1}^{N}
. This batch is then fed into the model to compute the prediction logits for the target sequence.
Based on the computed target and perplexity losses, the top-
k
candidates are
selected
in the suffix selection phase to seed the next iteration.
Crucially, this cycle repeats for hundreds of epochs, meaning the static prefix
x^{(h)}
is re-evaluated
N
times per step, creating a massive computational workload.

Standard Attention and KV Cache.

The core operator in Transformer-based LLMs
(
13
)
is the scaled dot-product attention.
For a specific layer and attention head, given a query
q_{t}
, and the key-value pairs for the current sequence history
(K_{<t},V_{<t})
, the attention output
o_{t}
is computed as:

\displaystyle o_{t}=\text{Softmax}\left(\frac{q_{t}[K_{<t};k_{t}]^{\top}}{\sqrt{d}}\right)[V_{<t};v_{t}],

(2)

where
[\cdot;\cdot]
denotes concatenation along the sequence length dimension.
To avoid recomputing
K_{<t}
and
V_{<t}
at every generation step, inference systems employ KV Caching to store these tensors in GPU memory.
Since standard deep learning frameworks require the KV cache batch dimension to align with the input batch size
N
, the KV states for the static prefix
x^{(h)}
must be physically duplicated
N
times:

\displaystyle\mathcal{M}_{prefix}=\text{Repeat}(K^{(h)},V^{(h)},\text{times}=N).

(3)

This results in a memory complexity of
\mathcal{O}(N\cdot L_{prefix})
, which strictly limits the search width
N
and prevents the use of large batch sizes.

4
Methodology

In this section, we first illustrate the redundant computation problem of prefix KV vectors in suffix jailbreaking and then introduce our
PSKV
method to tackle the raised challenge and substantially improve the efficiency of suffix jailbreak attacks.

4.1
Redundant Prefix computation in Suffix Jailbreak Attacks

According to the general jailbreak suffix synthesis process described in Section
3
, the main computational burden of suffix jailbreaking arises from performing
K\cdot q
inference passes (in the response generation phase) in each synthesis iteration, where
K
is the number of candidate suffixes in each iteration, and
q
is the number of new suffixes generated for each candidate.
Larger
K
and
q
usually lead jailbreak attacks to explore more candidate suffixes, thus increasing the chance of finding an effective jailbreak suffix; however, they also result in more LLM inference times.

The most straightforward implementation, which we term the
unaccelerated traditional attack method
, treats each of the
K\cdot q
candidate prompts as independent inputs in every iteration. This approach repeatedly re-computes the KV vectors for the prefix
x^{(h)}
, leading to significant redundant computational overhead.
As a result, when an LLM is performing inference on these prompts in parallel, it will redundantly calculate the same KV vectors for the same prefix
x^{(h)}
for up to
K\cdot q
times at each step.

A more advanced baseline would employ a
standard KV cache
implementation. The KV vectors for the prefix
x^{(h)}
are computed only once before the iterative synthesis process begins. However, to evaluate all
K\cdot q
suffix candidates in a single parallel batch, this pre-computed prefix cache must be duplicated
K\cdot q
times to match the batch dimension of the suffixes, which introduces a severe memory bottleneck. For a batch of
B
prompts, this problem is exacerbated, requiring
B\cdot K\cdot q
copies of the caches.

Furthermore, as shown in Table
1
,
the average token length of instructions in HarmBench is 78.4
(
8
)
, which is significantly larger than the standard jailbreak suffix length in practice (typically set to 20 tokens).
Collectively, these observations suggest that if the KV vectors of the prefix harmful instruction
x^{(h)}
can be calculated only once and used for the inference of different candidate prompts, then both the
computation
and
memory
costs of suffix jailbreaking can be considerably reduced, as a large amount of redundant intermediate KV vectors no longer need to be calculated.

Fortunately, we observe that while the number of candidate prompts that an LLM needs to perform inference on in each jailbreaking iteration is as large as
K\cdot q
, these prompts all share the same prefix,
i.e.
, the original harmful instruction
x^{(h)}
.
Specifically, as illustrated in Fig.
1
, the suffix jailbreak attack only modifies the suffixes of these candidate prompts but keeps the harmful instruction
x^{(h)}
as their prefix intact.

4.2
PSKV for Single Jailbreak Suffixes Synthesis

These observations highlight a clear opportunity for optimization. Based on our previous analysis, we now propose
PSKV
, a method that can substantially accelerate existing suffix jailbreak attacks by reducing redundant computation of prefix KV vectors during the candidate prompt inference process of suffix jailbreaking.

The overall procedures are also illustrated in Figure
2
.
PSKV adopts a lazy, layer-wise expansion strategy. Unlike standard implementations that pre-allocate expanded memory for all layers during initialization, we maintain a compact, single-batch storage of the prefix. Specifically, before a suffix jailbreak attack starts the iterative suffix searching process in Figure.
1
, PSKV runs a single forward pass for the harmful instruction
x^{(h)}
to compute and cache its KV vectors across all attention layers of the targeted LLM.
Then, when the targeted LLM is performing inference on the
K\cdot q
candidate prompts during the iterative suffix searching process, whenever the LLM needs to use the KV vectors of the prefix from an attention layer, PSKV directly retrieves the corresponding KV vectors from its cache and duplicates these vectors
K\cdot q
times for the LLM to support its inference process.
Compared with vanilla suffix jailbreaking, our PSKV method reduces the time-consuming prefix KV cache computation from
K\cdot q
times to only
a single time
, which can significantly improve the computation efficiency of suffix jailbreaking.

Furthermore, we note that the KV vector duplicating procedure in PSKV requires little memory overhead.
This is because during LLM inference, the outputs of all LLM attention layers are calculated in a layer-by-layer manner,
and the computation process only requires the prefix KV vectors from that specific layer.
As a result, the prefix KV vector duplication procedure in PSKV is also performed in a layer-by-layer manner, and at any given time, only KV vectors from a single layer are duplicated. This ensures that at any given moment, the memory-intensive expansion is isolated to a single layer, considerably reducing peak memory overhead compared to the vanilla approach where redundant prefix repetitions persist across the entire network stack simultaneously.

4.3
Suffix-Centric Alignment for Batched Multi-Instruction Attack

In real-world benchmarking, evaluating robust accuracy requires optimizing suffixes for a batch of
B
distinct instruction-response pairs
\{(x_{i}^{(h)},y_{i}^{(h)})\}_{i=1}^{B}
.
A practical challenge arises from the variable token lengths of these pairs, which typically leads to ragged tensors that hinder efficient parallelization.
To resolve this and maximize the utility of PSKV, we implement a
Suffix-Centric Alignment
strategy.

As illustrated in Figure
3
, we normalize the data layout by left-padding all instructions
x^{(h)}_{i}
and right-padding all target responses
y^{(h)}_{i}
.
This alignment ensures that all generated suffixes start at the same column index within the batch tensor.
Consequently, despite the variable input lengths, the suffixes form a single, dense token matrix of shape
(B\cdot K\cdot q)\times N_{s}
.

This design yields two critical benefits. The dense matrix representation allows the massive number of candidate suffixes (
B\cdot K\cdot q
) to be processed using highly optimized vectorized operations in standard frameworks (e.g., PyTorch), eliminating the computational overhead from sequential or irregular batching in loss evaluation and suffix retrieval. Meanwhile, the right-alignment of instructions aligns the memory layout of the static prefixes. This allows PSKV to pre-compute the KV cache once for the
B
instructions and broadcast it efficiently across the massive candidate dimension, as analyzed in the complexity section below.

Complexity analysis (batch).

We analyze the complexity for a batch of
B
distinct prompts, generating a total of
N_{cand}=B\cdot K\cdot q
candidates per iteration (detailed proofs in Appendix
B.2
).
As summarized in Table
2
, the
Standard KV cache
substantially reduces computational costs compared to the unaccelerated baseline, but it requires physically duplicating the prefix KV states for every candidate to match the input batch dimension, resulting in a prefix memory footprint of
\mathcal{O}(N_{cand}\cdot N_{p,\text{max}})
.

In contrast, by sharing the KV cache across all suffixes targeting the same prompt, PSKV reduces the prefix memory term to
\mathcal{O}(B\cdot N_{p,\text{max}})
.
This term scales with the number of prompts
B
, not the much larger total candidate count
N_{cand}
(since typically
K\cdot q\gg 1
).
This optimization effectively removes the memory barrier, making large-scale parallel attacks practical.

K\cdot q
times in GPU memory to match the batch dimension of the suffixes.

Conclusion

The effectiveness of suffix jailbreak attacks is fundamentally tied to heuristic searches that require a vast number of resource-intensive LLM inferences, creating a significant barrier to efficient security evaluation. Our work is motivated by the key observation : for a single harmful prompt, numerous candidate suffixes are generated, yet standard methods create multiple redundant copies of the prompt’s computational state, leading to massive memory waste. To address this inefficiency, we propose the
Prefix-Shared KV Cache (PSKV)
framework. The core principle of PSKV is to maintain only a single, shared, and expandable KV cache for each harmful instruction prefix, which is then efficiently reused for all its corresponding suffix candidates. To enable this sharing mechanism at scale for batches of diverse prompts, we also introduce a suffix-centric alignment strategy. We empirically validated PSKV across six suffix attacks on five LLMs, demonstrating an average reduction of 40% in time and 50% in memory compared to cache-optimized baselines, while preserving the original attack success rate.

B.1
Complexity Analysis for Single Prompt

In this section, we provide the derivations for the computational (
C
) and memory (
M
) complexities presented in Section
4.2
. We let
E
be the number of synthesis iterations;
N_{p},N_{s},N_{t}
be the token lengths of the prefix, suffix, and target, respectively; and
K\cdot q
be the number of candidates evaluated per iteration. Our analysis abstracts away model-specific constants (e.g., hidden dimension, number of layers) as they are common factors across all methods. The core assumptions are that the attention mechanism has a computational cost of
\mathcal{O}(L^{2})
for a sequence of length
L
, and the corresponding KV cache has a memory footprint of
\mathcal{O}(L)
.

B.1.1
Method without Acceleration

Computational Complexity.

This method recomputes the entire sequence of length
N_{p}+N_{s}+N_{t}
for each of the
K\cdot q
candidates in every one of the
E
iterations. The total complexity is the product of the number of operations and the cost per operation:

\displaystyle C_{\text{NoAccel}}

\displaystyle=E\cdot(K\cdot q)\cdot\mathcal{O}((N_{p}+N_{s}+N_{t})^{2})

\displaystyle=\mathcal{O}(E\cdot(K\cdot q)\cdot(N_{p}+N_{s}+N_{t})^{2}).

(4)

Memory Complexity.

The peak memory is determined by the batched inference step, which must hold the KV caches for all
K\cdot q
candidates simultaneously. The memory for each cache is proportional to the full sequence length.

\displaystyle M_{\text{NoAccel}}

\displaystyle=(K\cdot q)\cdot\mathcal{O}(N_{p}+N_{s}+N_{t})

\displaystyle=\mathcal{O}((K\cdot q)\cdot(N_{p}+N_{s}+N_{t})).

(5)

B.1.2
Standard KV Cache

Computational Complexity.

This method involves a one-time prefix computation and an iterative evaluation step over
E
iterations.

•

Prefix Computation (One-time):
A single forward pass over the prefix of length
N_{p}
costs
\mathcal{O}(N_{p}^{2})
.

•

Iterative Evaluation (per epoch):
For each of the
N_{s}+N_{t}
tokens of the suffix and target, attention is computed over a context that grows from
N_{p}
to
N_{p}+N_{s}+N_{t}-1
. The average context length for these tokens is approximately
N_{p}+(N_{s}+N_{t})/2
. The computational cost for each of the
K\cdot q
candidates is thus roughly proportional to the number of new tokens times twice the average context length, giving
\mathcal{O}((N_{s}+N_{t})\cdot(2N_{p}+N_{s}+N_{t}))
.

The total complexity is the sum of the one-time cost and the total iterative cost:

\displaystyle C_{\text{Std}}

\displaystyle=\mathcal{O}(N_{p}^{2})+E\cdot(K\cdot q)\cdot\mathcal{O}((N_{s}+N_{t})(2N_{p}+N_{s}+N_{t}))

\displaystyle=\mathcal{O}(N_{p}^{2}+E\cdot(K\cdot q)\cdot(N_{s}+N_{t})(2N_{p}+N_{s}+N_{t})).

(6)

Memory Complexity.

To achieve parallel computation, the pre-computed prefix cache of length
N_{p}
must be physically duplicated
K\cdot q
times. The total memory is the sum of these duplicated prefix caches and the caches for the suffix and target segments.

\displaystyle M_{\text{Std}}

\displaystyle=(K\cdot q)\cdot\mathcal{O}(N_{p})+(K\cdot q)\cdot\mathcal{O}(N_{s}+N_{t})

\displaystyle=\mathcal{O}((K\cdot q)\cdot(N_{p}+N_{s}+N_{t})).

(7)

B.1.3
PSKV (Ours)

Computational Complexity.

The computational process of PSKV is identical to the standard KV cache approach, as it also performs a one-time prefix computation followed by iterative evaluation of the suffix and target segments.

\displaystyle C_{\text{Ours}}=C_{\text{Std}}=\mathcal{O}(N_{p}^{2}+E\cdot(K\cdot q)\cdot(N_{s}+N_{t})(2N_{p}+N_{s}+N_{t})).

(8)

Memory Complexity.

The key advantage of PSKV is that it avoids the physical duplication of the prefix cache. It stores the prefix cache of length
N_{p}
only once, alongside the caches for the
K\cdot q
suffix and target segments.

\displaystyle M_{\text{Ours}}

\displaystyle=\mathcal{O}(N_{p})+(K\cdot q)\cdot\mathcal{O}(N_{s}+N_{t})

\displaystyle=\mathcal{O}(N_{p}+(K\cdot q)\cdot(N_{s}+N_{t})).

(9)

Appendix C
Computational Efficiency Analysis of AdvPrompter

C.1
Observations

In our experimental evaluation of AdvPrompter (Table
4
), we observed two notable phenomena:

1.

Severe performance degradation without KV caching:
All models exhibit substantially higher latency in the “None” (no acceleration) setting compared to cached configurations. For instance, Llama-2-7B increases from 275s (Standard KV Cache) to over 500s (None), representing an approximately
2\times
slowdown.

2.

Model-specific latency disparities:
Among models of comparable size, Llama-2-7B and Llama-3-8B consistently exhibit higher execution times than Mistral-7B and Qwen2.5-7B across all acceleration settings. Even with our PSKV, Llama-2 (250s) and Llama-3 (282s) remain slower than Mistral (80s) and Qwen (76s).

This section analyzes the algorithmic and architectural factors underlying these observations.

C.2
The Cost of Cache-less Decoding

The severe slowdown in the “None” setting stems from the fundamental inefficiency of autoregressive generation without KV caching.

Quadratic Total Complexity.

With KV caching, generating token
t
requires computing attention only between the new query and cached keys/values, yielding
O(1)
complexity per layer with respect to history length. Without caching, the model must recompute all previous hidden states, requiring
O(t)
operations at step
t
. Summing over a sequence of length
n
, the total complexity degrades from
O(n)
to
O(n^{2})
.

Amplification by AdvPrompter’s Search Strategy.

Unlike gradient-based attacks (
e.g.
, GCG) that perform single forward-backward passes, AdvPrompter employs beam search with sampling during suffix generation. This expands the effective batch size multiplicatively (batch
\times
beam
\times
samples), causing the quadratic recomputation penalty to be incurred across many parallel sequences simultaneously. The resulting computational burden saturates GPU throughput and explains the disproportionate slowdown observed in the “None” setting.

C.3
Architectural Factors in Llama-Series Latency

While all models benefit from KV caching, Llama-2 and Llama-3 exhibit consistently higher latency than Mistral and Qwen. We attribute this to two architecture-specific factors.

Llama-2: Multi-Head Attention Overhead.

Llama-2-7B employs Multi-Head Attention (MHA) with 32 key-value heads, whereas Mistral-7B and Qwen2.5-7B utilize Grouped-Query Attention (GQA) with 8 key-value heads. In cache-less decoding, the model must recompute K and V projections for the entire sequence history at each generation step. With
4\times
more KV heads, Llama-2 incurs proportionally higher memory bandwidth requirements for loading projection weights and storing intermediate KV tensors. This memory-bound overhead is particularly pronounced when batch sizes are large, as in AdvPrompter’s beam search.

Llama-3: Vocabulary Projection Overhead.

Llama-3-8B adopts GQA, mitigating the MHA-related overhead. However, it employs a vocabulary of 128K tokens—approximately
4\times
larger than Llama-2 and Mistral (
\sim
32K). AdvPrompter uniquely requires training a generator model, which involves computing full logit distributions over the vocabulary and backpropagating through the output projection layer. The computational cost of this
\mathbb{R}^{d}\rightarrow\mathbb{R}^{|V|}
projection and its gradient scales linearly with vocabulary size, imposing a persistent overhead on Llama-3 that cannot be alleviated by KV caching alone.

The ”None” baseline forces redundant recomputation across the entire sequence history at each decoding step, a cost amplified by AdvPrompter’s beam search strategy. D.2
Theoretical Memory Complexity: Standard vs. PSKV

We formalize the memory consumption to explain why Standard KV Cache results in OOM errors under beam search settings while PSKV remains efficient.
Let be the batch size (or beam width/number of candidates), be the prefix length, be the generated tokens, be the hidden dimension, and be the number of layers.

Standard KV Cache (Eager Expansion).

Standard implementations (e.g., Hugging Face default) eagerly expand the KV cache to match the batch dimension at initialization. The memory complexity for the cached prefix is:

M_{std}\propto N_{layer}\times\mathbf{B}\times L_{pre}\times H_{kv}\times D

(16)

PSKV (Layer-wise Dynamic Expansion).

Our PSKV implementation maintains a singleton copy of the prefix cache. During the forward pass of the -th layer, the cache is virtually broadcasted or temporarily expanded only for that specific layer’s computation and immediately released. The resident memory footprint is:

M_{pskv}\propto N_{layer}\times\mathbf{1}\times L_{pre}\times H_{kv}\times D

(17)

The temporary expansion memory required during the forward pass is (for the current layer computation). This allows the memory consumption related to the prefix to remain independent of the attack batch size , providing the efficiency gains observed in the main results.
