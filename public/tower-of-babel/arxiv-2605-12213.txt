Goal-Oriented Reasoning for RAG-based Memory in Conversational Agentic LLM Systems
Jiazhou Liang, Armin Toroghi, Yifan Simon Liu, Faeze Moradi Kalarde, Liam Gallagher, Scott Sanner

Abstract
LLM-based conversational AI agents struggle to maintain coherent behavior over long horizons due to limited context. While RAG-based approaches are increasingly adopted to overcome this limitation by storing interactions in external memory modules and performing retrieval from them, their effectiveness in answering challenging questions (e.g., multi-hop, commonsense, etc.) ultimately depends on the agent’s ability to reason over the retrieved information. However, existing methods typically retrieve memory by semantic similarity to the raw user utterance, which lacks explicit reasoning over missing intermediate facts and often returns evidence that is irrelevant or insufficient for grounded reasoning. In this work, we introduce Goal-Mem , a goal-oriented reasoning framework for RAG-based agentic memory that performs explicit backward chaining from the user’s utterance as a goal. Rather than progressively expanding from retrieved context, Goal-Mem decomposes each goal into atomic subgoals, performs targeted memory retrieval to satisfy each subgoal, and iteratively identifies what information from memory should be retrieved when intermediate goals cannot be resolved. We formalize this process in Natural Language Logic, a logical system that combines the verifiability of reasoning provided by FOL with the expressivity of natural language. Through extensive experiments on two datasets, comparing to eight strong memory baselines, we show that Goal-Mem consistently improves performance, particularly on tasks requiring multi-hop reasoning and implicit inference.

Related Work

Retrieval-Augmented Generation (RAG) Based Memory
RAG-based memory retrieves a relevant subset of stored conversational traces or structured records at inference time. This paradigm has been widely studied in recent LLM-agent memory systems, where prior interactions are stored externally and selectively recalled to support long-term or task-grounded responses
[
37
]
. We therefore focus on representative retrieval-augmented memory backbones that cover the major design choices in this line of work. Early work like MemoryBank introduced updatable long-term memory with forgetting mechanisms
[
39
]
. More recent systems focus on advanced structural organization and routing heuristics. For relational structures, Mem0
[
4
]
and A-MEM
[
33
]
utilize dynamic graphs and linked notes, concepts further advanced by agentic graph routing in AdaMem
[
34
]
and causal tool retrieval in AMA-Agent
[
38
]
. To manage abstraction, memory is increasingly structured hierarchically; MemTree
[
24
]
and RAPTOR
[
27
]
construct multi-level trees. Furthermore, methods like MAGMA perform query-adaptive traversal across multi-view graphs
[
10
]
.
However,
Goal-Mem
is orthogonal to all these works. Whereas prior methods primarily focus on memory structure and retrieval, the problem is addressing what information should be queried for the utterance.
Goal-Mem
serves as a structure-agnostic reasoning layer that can be flexibly integrated with these memory backbones to enforce goal-oriented verifiable reasoning.

LLM Reasoning via Backward Chaining
Backward chaining is an established paradigm in logical reasoning. Unlike forward reasoning approaches such as query reformulation
[
20
]
, self-reflection
[
36
,
28
]
, iterative retrieval with LLM reranking
[
13
,
18
]
, and memory-specific methods such as MemGuide
[
5
]
that aim to derive the goal from observed facts progressively, backward chaining works backward from the goal, avoiding exhaustive exploration of facts and thereby yielding substantial efficiency gains
[
26
,
2
]
. This goal-directed approach has recently been used in LLM-based reasoning. LAMBADA
[
12
]
pioneered this integration by prompting the LLM to emulate the backward-chaining process by decomposing complex goals into sub-goals. Symba
[
14
]
leverages a symbolic solver that undergoes backward chaining and calls the LLM to provide additional facts. LLM-TRes
[
29
]
employs theory resolution to unify LLM-derived commonsense axioms into backward chaining.

Despite the collective success of these works in enhancing LLM reasoning efficiency, they remain constrained by a reliance on static knowledge, and to our knowledge, no research has extended the potential of backward LLM reasoning to the dynamic domain of memory-augmented agents, where backward chaining must be tightly coupled with adaptive memory and continual context updates.

Preliminaries

Retrieval-Augmented Generation (RAG) Based Memory

We consider a conversation as a sequence of turns. At turn
t
, the user provides an utterance
u_{t}
, and the agent generates a response
a_{t}
. Let
[(u_{1},a_{1}),\ldots,(u_{t-1},a_{t-1})]
denote the
dialogue history
prior to turn
t
. A RAG-based memory-augmented LLM is additionally equipped with an external long-term memory
\mathcal{M}
that stores episodic traces distilled from dialogue history.

A RAG-based memory backbone
\mathcal{B}
consists of three components: (1) a persistent external long-term memory store
\mathcal{M}
, instantiated as a flat vector database, graph-structured memory, or tree-structured memory; (2) a retrieval function
\mathcal{B}_{\text{retrieve}}(q_{t},\mathcal{M})
that returns memory facts from
\mathcal{M}
given a query
q_{t}
; and (3) an update mechanism to encode information in
u_{t}
into
\mathcal{M}
.
Given the utterance
u_{t}
, the agent first constructs one or more queries
q_{t}
that encapsulate the information needs in
u_{t}
. Each query is passed to the memory backbone
\mathcal{B}
, which retrieves relevant memory facts
\mathcal{M}_{t}
:

\mathcal{M}_{t}=\mathcal{B}_{\text{retrieve}}(q_{t},\mathcal{M}).

The agent then generates a response conditioned on both the current utterance and the retrieved fact,
a_{t}=f^{\mathrm{LLM}}(u_{t},\mathcal{M}_{t})
. The backbone updates
\mathcal{M}
with the new turn.

As noted in
section 2
, choices on what information in dialogue is encoded, how it is organized and updated, and how queries are matched to traces in
\mathcal{M}
are made by
\mathcal{B}
and fall outside the scope of our work. We focus on constructing a sequence of queries
q_{t}
via goal-oriented reasoning.

Natural Language Logic (NL-Logic)

While conversation and memories are inherently expressed in NL, using LLMs for reasoning over pure NL induces the risk of generating ungrounded or hallucinated content. Moreover, NL-based reasoning is often difficult to verify, as the intermediate steps leading to a conclusion are not explicitly structured. Formal logical systems such as first-order logic (FOL)
[
26
]
provide a structured framework with explicit variables, substitutions, and entailment relations, enabling transparent and verifiable reasoning. However, its reliance on predefined symbols limits its expressiveness for memory traces, motivating the need for a hybrid logical NL representation.

To combine the strengths of both paradigms, we extend FOL into NL-Logic, where predicates, objects, and relations are expressed directly in NL, preserving logical structure while maintaining expressiveness.
Let
\mathcal{E}
denote the constants appearing in the current utterance or retrieved memory facts,
\mathcal{V}
a set of variables, and
\mathcal{T}
the set of NL type descriptions.
A typed term is written as
t:\tau
, where
t\in\mathcal{E}\cup\mathcal{V}
and
\tau\in\mathcal{T}
. Unlike conventional typed logical systems, we do not assume that
\mathcal{T}
is a fixed, predefined type vocabulary. Instead, types are open-ended, on-demand NL phrases and type checking is performed by the LLM through NL entailment. This allows more flexible definitions.

In NL-Logic, an atomic formula is

\mathcal{R}(t_{1},\dots,t_{n}),

where
\mathcal{R}
is an NL relational phrase and each argument
t_{i}
is explicitly typed (e.g.,
\text{``}(Alice:\textit{user})\textit{ likes }(x:\textit{flavor})\text{.''}
).
Type constraints are enforced on variables:

x:\tau\Rightarrow x\in\mathcal{E}_{\tau}

meaning that
x
belongs to
\mathcal{E}_{\tau}
, the subset of constants in
\mathcal{E}
with type
\tau
. Type specification for constants (e.g.,
“Alice”
,
“Matcha”
) is optional, as their names implicitly encode their semantic type. Thus, an atomic formula in NL-Logic is represented as a structured NL statement with typed arguments, rather than as a purely symbolic predicate application.
In this logical system, a knowledge base (e.g. Memory) can be represented as a set of ground atoms:

\mathcal{M}=\{\mathcal{R}(e_{1},\ldots,e_{n})\mid(e_{1},\ldots,e_{n})\in\mathcal{E}^{n}\}

(1)

Methodology

Given a user utterance
u_{t}
at turn
t
, the objective is to generate a grounded response.
Goal-Mem
first maps
u_{t}
to a formal NL-Logic goal
\phi_{u_{t}}(x_{1},\dots,x_{m})
, which captures both the semantic intent of the utterance and the set of variables
\{x_{1},\dots,x_{m}\}
that must be instantiated to satisfy the user’s request.

Running Example 1.

User utterance:
u_{t}=
“
Alice: Which drink did I order at cafe Momoco?
”

NL-Logic goal:
\phi_{u_{t}}=
“(
x:drink
) ordered by (
Alice:human
) at (
Momoco:cafe
).”

Answering the user requires resolving variable
x
, whose type is
drink
. The response-generation problem thus reduces to a logical inference: finding a substitution
\theta=\{x_{1}/e_{1},\dots,x_{m}/e_{m}\}
, where each variable
x_{i}
is replaced by a type-consistent constant
e_{i}
drawn from the retrieved memory
\mathcal{M}_{t}
.

Running Example 1 (continued).

\mathcal{M}_{t}=\{
“(
Alice
) ordered (
Kyoto Latte
) at cafe Momoco.”
\}
,

\theta=\{(\textit{x:drink})/(\textit{Kyoto Latte})\}

This formulation grounds the response in facts in retrieved memory, mitigating hallucinations that arise when existing approaches lack explicit verification on what fact should support the answer.

4.1
Goal-Oriented Backward Chaining

In practice, a direct substitution that satisfies
\phi_{u_{t}}
using
\mathcal{M}_{t}
rarely exists when
\phi_{u_{t}}
requires multi-hop reasoning or open-domain knowledge. In these cases,
Goal-Mem
applies backward chaining to decompose
\phi_{u_{t}}
into a series of subgoals, each of which can be independently grounded against
\mathcal{M}_{t}
.

Figure 2:
Overview of
Goal-Mem
. The framework starts from the user utterance and goal initialization (
top
), decomposes the goal into NL-Logic subgoals for memory retrieval from a selected backbone (
middle
), and checks whether the retrieved memory grounds all subgoals through unification. If not, it enters the depth loop (
middle
), identifying new subgoals with targeted retrieval until all variables have been substituted or the maximum depth (
bottom left
) is reached. The failed goal decomposition would then be provided to future decompositions to prevent a duplicate approach.

As illustrated in Figure
2
,
Goal-Mem
operates through two nested iterative procedures. In each
breadth loop
,
Goal-Mem
decomposes the user utterance
u_{t}
into a set of atomic subgoals
\psi^{b}
and retrieves the corresponding memory from the backbone
\mathcal{B}
for each subgoal separately, yielding the aggregated retrieved memory
\mathcal{M}_{t}
. The goal is satisfied when all
\psi^{b}
are grounded by
\mathcal{M}_{t}
under a type-consistent non-conflicting substitution and all variables required by the goal are bound. If not,
Goal-Mem
refines each unresolved subgoal by inferring an intermediate subgoal whose satisfaction is necessary to establish the unresolved subgoal, and retrieves memory facts from
\mathcal{B}
. This
depth loop
repeats until either every variable is successfully grounded or a maximum recursion depth is reached.
We initialize the backward chaining with an empty substitution
\theta^{(0)}=\emptyset
and subgoal set
\psi^{(0)}=\emptyset
.

Goal Decomposition.

At each breadth step
b\in\{1,\ldots,B_{\mathrm{max}}\}
, the agent maintains the current set of subgoals
\psi^{(b)}
, the retrieved memory
\mathcal{M}_{t}^{(b)}
, and the current substitution
\theta^{(b)}
. Given the original goal
\phi_{u_{t}}
,
Goal-Mem
decomposes the goal into a set of candidate subgoals:

\psi^{(b)}=\Psi_{\mathrm{decomp}}^{\mathrm{LLM}}\!\left(\phi_{u_{t}},\{\psi^{(0)},\ldots,\psi^{(b-1)}\}\right),

(2)

where
\Psi_{\mathrm{decomp}}^{\mathrm{LLM}}
is an LLM-based decomposition function that avoids repeating earlier decompositions (i.e.,
\{\psi^{(0)},\ldots,\psi^{(b-1)}\}
) that led to failed subgoals and instead proposes a distinct way to satisfy the goal.
\Psi_{\mathrm{decomp}}^{\mathrm{LLM}}
induces a rule in NL-Logic of the form:

\psi_{1}\land\cdots\land\psi_{k}\Rightarrow\phi_{u_{t}},

where each
\psi_{i}\in\psi^{(b)}
is an atomic NL-Logic formula that must hold for
\phi_{u_{t}}
to be satisfied.

Running Example 2.

u_{t}=\text{``Alice: I like the cafe I went to last week, what drink should I try this time?''}

\phi_{u_{t}}=\text{``Recommend ({x:drink}) to ({Alice}) from the menu of the cafe she went to last week.''}
,

The LLM may generate the following rule:

\displaystyle\text{``({Alice}) likes ({y:flavor})''}\land\text{``({x:drink}) contains ({y:flavor})''}\land\text{``({x:drink}) served in ({z:cafe visited last week})''}

\Rightarrow\text{``recommend ({x:drink}) to ({Alice}).''}

Targeted Memory Retrieval.

Each subgoal
\psi_{i}\in\psi^{(b)}
, an atomic NL-Logic formula, is issued as a query to the memory backbone
\mathcal{B}
to retrieve the corresponding facts:

\mathcal{M}_{t}^{(b)}=\bigcup_{\psi_{i}\in\psi^{(b)}}\mathcal{B}_{\text{retrieve}}(\psi_{i},\mathcal{M}).

(3)

Running Example 2 (continued).

For the subgoal
\psi_{i}=\text{``({x:drink}) contains ({y:flavor})''},
the memory backbone retrieves

\mathcal{B}_{\text{retrieve}}(\psi_{i},\mathcal{M})=\left\{\text{``({Kyoto Latte}) with ({Matcha Powder})''}\right\}.

4.2
Verifiable Unification

Given the subgoals
\psi^{(b)}
and the aggregated retrieved memory
\mathcal{M}_{t}^{(b)}
, the agent grounds each subgoal by assessing whether the retrieved memories provide sufficient facts to satisfy it. Specifically, for each subgoal
\psi_{i}\in\psi^{(b)}
, the agent attempts to unify it with a retrieved memory fact
m_{j}\in\mathcal{M}_{t}^{(b)}
conditioned on the current substitution
\theta^{(b)}
:

\delta_{i}=\operatorname{UNIFY}\!(\psi_{i},m_{j}\mid\theta^{(b)})\quad\text{where}\quad\operatorname{SUBST}(\theta^{(b)}\cup\delta_{i},\psi_{i})=_{\mathrm{LLM}}\operatorname{SUBST}(\theta^{(b)}\cup\delta_{i},m_{j}).

(4)

Here,
\delta_{i}
denotes the candidate substitution induced by
m_{j}
for
\psi_{i}
, and
\operatorname{SUBST}(\delta_{i},p)
denotes the formula obtained by applying substitution
\delta_{i}
to
p
.

Running Example 2 (continued).

Recall a previous subgoal
\psi_{i}
and a retrieved memory
m_{j}\in\mathcal{M}_{t}^{(b)}
:

\psi_{i}=
“(
x:drink
) contains (
y:flavor
)”.

m_{j}=
“The cafe advertised a (
Kyoto Latte
) with (
Matcha Powder:ingredient

To determine whether
\psi_{i}
can be grounded by
m_{j}
, we compute
\mathrm{UNIFY}\!(\psi_{i},m_{j}\mid\theta^{(b)})
.

\mathrm{UNIFY}\!(\psi_{i},m_{j}\mid\theta^{(b)})
proposes a variable substitution:

\delta_{i}=\{x\,/\,\text{``{Kyoto Latte}''}\ ,y\,/\,\text{``{Matcha Powder}''}\}.

Unification succeeds only if three conditions hold: (i) the proposed substitution satisfies type consistency; (ii) the proposed substitution is equivalent to the existing substitution
\theta^{(b)}
; and (iii) the retrieved memory fact
m_{j}
logically entails the grounded subgoal. Because NL-Logic types and relations are expressed in natural language, these checks are performed by an LLM.

Type Consistency.

A variable
(x:\tau)
in the subgoal
\psi_{i}
can be substituted with a constant
e^{\prime}
from a retrieved memory fact
m_{j}
if and only if their types are consistent. If
e^{\prime}
is explicitly typed as
(e^{\prime}:\tau^{\prime})
, we require
\tau^{\prime}\vdash_{\mathrm{LLM}}\tau
; otherwise, the entity must be an instance of the type, i.e.,
\tau_{\text{LLM}}(e^{\prime})
.

Running Example 2 (continued).

Since
\text{``{drink}''}_{\text{LLM}}(\text{``{Kyoto Latte}''})
and “
ingredient
”
\vdash_{\mathrm{LLM}}
“

”,
the substitution
\delta_{i}
is type-compatible.

Equality Checks with Existing Substitutions.

If the substitution assigns a variable already bound in
\theta^{(b)}
, the assigned constants must be equal in the given context. Formally, let
\operatorname{dom}(\theta)
denote the set of variables bound by a substitution

x\in\operatorname{dom}(\delta_{i})\cap\operatorname{dom}(\theta^{(b)})
, the two bindings must agree under the LLM-judged equality relation
=_{\mathrm{LLM}}
:

\delta_{i}(x)=_{\mathrm{LLM}}\theta^{(b)}(x),\quad\forall x\in\operatorname{dom}(\delta_{i})\cap\operatorname{dom}(\theta^{(b)}).

(5)

Running Example 2 (continued).

Let
\theta^{(b)}=\{y\,/\,\text{``{Matcha}''}\}
be an existing substitution. Since

y\in\operatorname{dom}(\delta_{i})\cap\operatorname{dom}(\theta^{(b)})
and
\text{``{Matcha Powder}''}=_{\mathrm{LLM}}\text{``{Matcha}''}
in the given context,
\delta_{i}^{+}
is accepted under this condition.

In contrast, if
\delta_{i}^{-}=\{y\,/\,\text{``{Strawberry}''}\}
, then
\text{``{Strawberry}''}\neq_{\mathrm{LLM}}\text{``{Matcha}''}

Logical Entailment.

We apply the type-consistent and substitution-consistent
\theta^{(b)}\cup\delta_{i}
to obtain the grounded subgoal
\psi_{i}^{\mathrm{g}}=\psi_{i}[\theta^{(b)}\cup\delta_{i}]
. The LLM then checks whether any retrieved memory fact
m_{j}\in\mathcal{M}_{t}^{(b)}
entails the grounded subgoal:
m_{j}\vdash_{\mathrm{LLM}}\psi_{i}^{\mathrm{g}}
.

Running Example 2 (continued).

Given the type-consistent and non-contradictory variable substitution

\delta_{i}=\{x\,/\,\text{``{Kyoto Latte}''},y\,/\,\text{``{Matcha Powder}''}\},

the subgoal

“(
Kyoto Latte

If all three conditions hold, the agent accepts the substitution

inferred from

4.3
Subgoal Refinement via Backward Chaining

If any subgoals in
\psi^{(b)}
fail to unify with
\mathcal{M}_{t}
,
Goal-Mem
enters the subgoal-refinement (depth) loop. At each depth step
d\in\{1,\ldots,D_{\mathrm{max}}\}
,
Goal-Mem
refines the unresolved subgoals as:

\psi^{(b,d)}=\{\Psi_{\mathrm{refine}}^{\mathrm{LLM}}(\psi_{i},\mathcal{M}_{t}^{(b,d-1)}):\psi_{i}\in\mathcal{U}^{(b,d-1)}\}.

(6)

where
\psi^{(b,d-1)}
denotes the set of subgoals that failed to unify at the previous depth step. The operator
\Psi_{\mathrm{refine}}^{\mathrm{LLM}}
is an LLM-based refinement function that generates a requisite antecedent whose grounding is required to satisfy the unresolved subgoal. Given the refined subgoals
\psi^{(b,d)}_{i}=\Psi_{\mathrm{refine}}^{\mathrm{LLM}}(\psi^{(b,d-1)}_{i})
, the agent then queries
\mathcal{B}
to retrieve additional facts as
\mathcal{M}_{t}^{(b,d)}=\mathcal{M}_{t}^{(b,d-1)}\cup\mathcal{B}_{\text{retrieve}}\!(\psi^{(b,d)},\mathcal{M})
. The agent then re-applies the unification procedure over
\mathcal{M}_{t}^{(b,d)}
to ground the unresolved subgoals.
This process continues until all original and newly identified subgoals can be grounded by the accumulated retrieved memory
\mathcal{M}_{t}^{(b,d)}
, no new memory can be retrieved, or maximum depth is reached.

Running Example 2 (continued).

\psi_{i}^{(b,d-1)}=\text{``$(x:\textit{drink})$ served in $(z:\textit{cafe\ visited\ last\ week})$''},

m_{j}=\text{``The $(\textit{Momoco cafe})$ advertised a $(\textit{Kyoto\ Latte})$ as its seasonal drink.''}

Unification fails (
\textit{``Momoco cafe''}\;\nvdash_{\mathrm{LLM}}\;\textit{``cafe\ visited\ last\ week''}
) since the cafe visited last week is unknown.

\Psi_{\mathrm{refine}}^{\mathrm{LLM}}\!(\psi_{i}^{(b,d-1)})=\psi_{i}^{(b,d)}=\text{``$(\textit{Alice})$ visited $(z:\textit{cafe})$ last week.''}

If no new memory can be retrieved or the maximum depth is reached, this decomposition is considered infeasible for the given
\mathcal{M}
and
\mathcal{B}
.. The system then generates a different decomposition
\psi^{(b+1)}
of the original goal. This process continues until the maximum number of breadth steps.

u_{t}

used to ground the subgoals.

RQ3.

We next ablate the two budgets that govern
Goal-Mem
’s search: the maximum depth (subgoal refinement) and the maximum breadth (alternative goal decompositions). Figure
4
shows cumulative LLM-as-judge accuracy as each budget is increased, for two backbone LLMs.
Increasing depth yields accuracy improvements until max depth
\geq
3, and the gains are largest for backbones with weaker baseline performance. When the first retrieved memory is incomplete or noisy, antecedent-guided refinement lets agents navigate the memory space more systematically, recovering missing context that weaker backbones are especially likely to miss.
Increasing breadth produces little additional gain. We attribute this to the strength of SOTA LLMs; at a single goal, decomposition is typically sufficient, and the depth loop also refines potential failures. Allocating the search budget to depth rather than breadth is therefore the more practical strategy.

6
Conclusion

We introduced
Goal-Mem
, a framework that enhances the reasoning capabilities of memory-augmented LLM agents through goal-oriented backward chaining. By converting user utterances into NL-Logic goals and iteratively grounding subgoals via targeted retrieval and verifiable unification,
Goal-Mem
enables more effective use of external memory. In addition, its compatibility with diverse memory backbones makes it broadly applicable across existing RAG-based systems. Experimental results show consistent improvements across benchmarks, with particularly strong gains on tasks requiring multi-step inference. Overall,
Goal-Mem
provides an effective approach for improving memory-grounded reasoning in agentic LLM systems.

Appendix A
Goal-Mem
Algorithm

The workflow of the
Goal-Mem
reasoning framework is summarized in Algorithm
1
. The reasoning process begins by mapping the utterance
u_{t}
into a formal goal
\phi_{u_{t}}
, which specifies the variables that must be instantiated to answer the query. An initially empty substitution
\theta
is maintained to store variable bindings as they are discovered.

The algorithm proceeds through the
breadth loop
. At each breadth step
b
, the goal
\phi_{u_{t}}
is decomposed into a set of subgoals
\psi^{(b)}
using an LLM-based decomposition function, conditioned on previously explored decompositions
\{\psi^{(0)},\dots,\psi^{(b-1)}\}
(with
\psi^{(0)}=\emptyset
). Each subgoal represents a necessary condition for satisfying the original goal.

For each subgoal
\psi_{i}\in\psi^{(b)}
, the algorithm performs
targeted retrieval
by querying the memory backbone. The retrieved facts are aggregated into a memory set
\mathcal{M}_{t}^{(b,0)}
. The algorithm then attempts to ground the subgoals via verifiable
unification
, which matches subgoals against retrieved memory while enforcing three constraints: (i) type consistency between variables and candidate values, (ii) consistency with previously established substitutions, and (iii) logical entailment of the grounded subgoal by the retrieved memory (as judged by the LLM).

This step returns an updated substitution
\theta^{(b,0)}
, a set of unresolved subgoals
\mathcal{U}^{(b,0)}
, and a set of supporting memory facts
\mathcal{F}
that successfully grounded subgoals. We also maintain the accumulated subgoal set
\Psi^{(b,\leq 0)}=\psi^{(b)}
, and define the set of resolved subgoals
\mathcal{S}^{(b,0)}=\Psi^{(b,\leq 0)}\setminus\mathcal{U}^{(b,0)}
.

If all subgoals are successfully grounded (i.e.,
\mathcal{U}^{(b,0)}=\emptyset
), the algorithm terminates and generates the final response conditioned on the utterance, the substitution, and only the supporting memory
\mathcal{F}
.

Otherwise, the algorithm enters a
depth loop
, which performs recursive refinement of unresolved subgoals. At each depth step
d
, only the subgoals from the previous refinement frontier
\psi^{(b,d-1)}
(initialized as
\mathcal{U}^{(b,0)}
) are refined using an LLM-based refinement function, producing a new set
\psi^{(b,d)}
of intermediate subgoals. These refined subgoals are used for additional targeted retrieval, and the newly retrieved facts are accumulated into the memory
\mathcal{M}_{t}^{(b,d)}
.

The accumulated subgoal set is updated as
\Psi^{(b,\leq d)}=\Psi^{(b,\leq d-1)}\cup\psi^{(b,d)}
. The unification procedure is then re-applied over
\Psi^{(b,\leq d)}
and
\mathcal{M}_{t}^{(b,d)}
to attempt further grounding. To avoid redundant computation while preserving correctness, subgoals that have already been successfully grounded (tracked in
\mathcal{S}^{(b,d-1)}
) are skipped during unification, although they remain part of the accumulated subgoal set for consistency. This step produces updated substitution
\theta^{(b,d)}
, unresolved subgoals
\mathcal{U}^{(b,d)}
, and supporting facts
\mathcal{F}
, and updates the resolved set as
\mathcal{S}^{(b,d)}=\Psi^{(b,\leq d)}\setminus\mathcal{U}^{(b,d)}
.

This refinement process continues until either (i) all subgoals are grounded, (ii) no new memory can be retrieved, or (iii) the maximum depth is reached. If grounding succeeds at any depth, the algorithm generates the final response using the grounded substitution and the supporting memory
\mathcal{F}
.

If the current decomposition fails to yield a complete grounding after exhausting the depth budget, the algorithm returns to the breadth loop and considers an alternative decomposition of the original goal, enabling exploration of multiple reasoning strategies.

Appendix B
Complexity

Let
K_{\mathrm{max}}
be an upper bound on the number of subgoals at any depth step. We exclude memory backbone LLM calls, since the latter depend on the implementation of
\mathcal{B}_{\mathrm{retrieve}}
. For each breadth attempt,
Goal-Mem
uses one LLM call for goal decomposition and one batched LLM call for verifiable unification over all retrieved facts and active subgoals. At each refinement depth, it then uses one LLM call to refine the unresolved subgoals and one batched LLM call to re-run unification after the additional retrieval. Thus, the LLM calls is bounded by
1+B_{\mathrm{max}}\bigl(2+2D_{\mathrm{max}}\bigr)
or
\mathcal{O}(B_{\mathrm{max}}D_{\mathrm{max}})
LLM calls.
The memory retrieval is bounded by:

C_{\mathrm{ret}}\leq B_{\mathrm{max}}(D_{\mathrm{max}}+1)K_{\mathrm{max}}.

We conduct various empirical analysis in
Figure 4
and next paragraph. In practice, the realized cost is often lower because it frequently terminates before the algorithm reaches
B_{\mathrm{max}}
and
D_{\mathrm{max}}
(i.e., 95 percentiles of samples have finished within
B=1
and
D=3
across datasets), as soon as all variables in
\phi_{u_{t}}
are grounded. In addition, under batched unification,
Goal-Mem
uses only a constant number of LLM calls per depth step. Thus, since
B_{\mathrm{max}}
and
D_{\mathrm{max}}
are small,
Goal-Mem
has a similar asymptotic per-turn LLM-call complexity as existing forward-reasoning approaches.

B.1
Distribution of Breadth, Depth, and Subgoals in Real Datasets

Figure 5:
Empirical distributions of realized search statistics in
Goal-Mem
. The left panel shows the realized breadth usage, the middle panel shows the realized refinement depth, and the right panel shows the number of subgoals generated per decomposition. Although the search caps are
B_{\mathrm{max}}=3
and
D_{\mathrm{max}}=5
, most examples terminate using substantially smaller realized breadth and depth.

Figure 5
shows that the empirical search cost is concentrated near the smallest possible values. The realized breadth distribution is dominated by breadth
1
, indicating that the first generated goal decomposition is sufficient for most examples. Only a relatively small fraction of cases require additional breadth attempts, and the configured cap
B_{\mathrm{max}}=3
is reached mainly by harder examples for which the first decomposition does not unify with the retrieved memories.

The realized depth distribution is even more concentrated. Most examples terminate at depth
0
, meaning that
Goal-Mem
answers after the initial decomposition, retrieval, and verifiable unification step, without invoking the missing-information refinement loop. A smaller tail reaches depths
1
through
5
, showing that depth search is used selectively for under-specified or partially grounded questions. Thus, while
D_{\mathrm{max}}=5
provides a safety cap for difficult cases, the typical realized depth is far below this maximum.

The subgoal-count distribution further supports the efficiency of the method. Most decompositions contain only a small number of subgoals, with the mass concentrated around two subgoals and only a small tail with more complex decompositions. Since memory retrieval scales with the number of queried subgoals, this concentration keeps the realized retrieval fan-out small. Moreover, because unification is batched over the active subgoals and retrieved facts, additional subgoals do not require separate unification LLM calls within the same depth step.

Overall, these distributions show that the theoretical
\mathcal{O}(B_{\mathrm{max}}D_{\mathrm{max}})
LLM-call bound is a worst-case guarantee rather than the typical operating regime. With
B_{\mathrm{max}}=3
and
D_{\mathrm{max}}=5
, the search space is tightly bounded, but the realized breadth and depth are usually much smaller. This supports the claim that
Goal-Mem
preserves practical per-turn efficiency while still allowing additional breadth and depth when the initial decomposition is insufficient.

B.2
Token Cost and Wall-Clock Time Across Reasoning Baselines

All experiments were run using the OpenAI API (GPT-5.4-mini) and DeepInfra API (Gemma-4-26B-A4B). No local GPU resources were required for backbone LLM inference. Retrieval-based backbones (BM25, Dense) were run on a single CPU machine; graph- and tree-based backbones (Mem0, MAGMA, MemTree, RAPTOR, A-MEM, GraphRAG) were run on a single machine with 16 GB RAM.

Table 3
report the average token cost and wall-clock time across the evaluated forward-reasoning methods using the RAG-BM25 backend. We use RAG-BM25 because it retrieves directly from raw utterances and therefore provides the most consistent token accounting, without additional token overhead introduced by different memory structures. We exclude fixed prompt tokens, since they vary across datasets and use cases and are negligible relative to the retrieved memory facts. We also exclude token usage from memory updating and encoding stages, as these costs depend on the chosen memory backbone and are outside the scope of this work.

Backbone Alone and Query Reformulation incur minimal token cost because they do not require an LLM agent to consume all retrieved memory facts during reasoning. In Query Reformulation, the query is rewritten before the retrieval stage using only the raw user utterance, while Backbone Alone directly retrieves memory facts without an iterative agent loop. In contrast, Self-Reflection, ReAct, MemGuide, and
Goal-Mem
are iterative memory-conditioned approaches: each step must consume retrieved memory facts to perform reflection, action selection, reranking, or unification for subsequent retrieval. Their token usage is therefore naturally higher than Backbone Alone. However, due to batched unification,
Goal-Mem
does not repeatedly call the LLM for every subgoal-condition check, allowing it to maintain a competitive token cost compared with other iterative reasoning methods.

Appendix C
Additional Information on the Evaluation Datasets

We evaluate
Goal-Mem
on two long-term conversational memory benchmarks: LoCoMo
[
21
]
and LongMemEval-Small
[
31
]
. These datasets are designed to assess the ability of LLM-based agents to store, retrieve, and reason over information accumulated across extended interactions.

LoCoMo.

LoCoMo is a benchmark for evaluating long-range conversational memory in multi-session settings. It consists of dialogues that span multiple sessions, where relevant information required to answer a query may be distributed across distant parts of the interaction history. The dataset emphasizes questions that require
multi-hop reasoning
, where the model must retrieve and combine multiple pieces of evidence to arrive at the correct answer. In addition to multi-hop questions,
LoCoMo
includes single-hop, temporal, and open-domain queries, enabling a fine-grained analysis of model performance across different reasoning types. A key challenge in
LoCoMo
is that the information necessary to answer a question is often not semantically similar to the query itself, requiring the model to identify and retrieve intermediate facts. This makes it particularly suitable for evaluating the effectiveness of goal-directed retrieval and backward chaining.

LongMemEval-Small
.

LongMemEval-Small
is a benchmark focused on core memory capabilities of conversational agents. It evaluates a range of skills, including information extraction from dialogue, reasoning across multiple sessions, handling temporal dependencies, updating knowledge over time, and abstaining when sufficient evidence is not available. Compared to
LoCoMo
, this dataset places greater emphasis on the correctness and consistency of memory usage, as well as the ability to track evolving user information. The dataset includes diverse query types that test whether the model can accurately retrieve and ground responses in previously stored memory, rather than relying on parametric knowledge.

Evaluation Protocol.

For both datasets, we evaluate model outputs using an LLM-as-a-judge framework, which assesses the correctness and grounding of generated responses with respect to the reference answers. In addition, we report token-level F1 scores to provide a complementary quantitative measure of answer overlap. These evaluation metrics allow us to capture both semantic correctness and lexical fidelity, offering a comprehensive view of model performance on long-term memory reasoning tasks.

Table 6:
Qualitative examples where all four forward-reasoning baselines fail but
Goal-Mem
returns the correct answer. The examples illustrate different multi-hop patterns: location-granularity bridging, temporal event alignment, distractor disambiguation, breadth search over alternative decompositions, and grounding of underspecified referring expressions.

The forward baselines are strong retrieval-augmented methods, but they primarily decide what to retrieve from the surface form of the question and the currently accumulated evidence. As a result, they often retrieve a salient memory and then answer with the most lexical or locally plausible span. For example , the forward methods retrieve the shelter memory but return the city Stamford, even though the question asks for the state. Or several baselines return the unresolved phrase “my old area,” which is evidence that the flood memory was found but the required referring-expression grounding was not completed.

Goal-Mem
instead of treating retrieved memories as a flat context for generation, it decomposes the question into checkable subgoals and then applies verifiable unification. This allows the model to keep track of answer variables, requested answer types, and unresolved referring expressions. For example, the goal is not merely to find any game-related memory, but to bind the variable corresponding to the game played in James’s April online tournament. The first pass does not directly ground this variable, so the missing-information refinement step asks for the specific game associated with that tournament. The later evidence grounds the same event to Apex Legends, while unrelated games such as Civilization VI are rejected because they do not satisfy the tournament-and-time constraint.

These examples also show depth is useful when the current decomposition is correct but one variable remains ungrounded, as in the April tournament example. Breadth is useful when the first decomposition is too literal or retrieves only weak evidence. The system initially fails to find a direct phrasing of “suggested outdoor activity.” A later breadth attempt reformulates the goal as evidence that Jolene is interested in an activity and wants to do it with Deborah.

The failure cases highlight that multi-hop memory QA is not only a retrieval-volume problem. The relevant evidence is often present in the retrieved pool, but the final answer requires an additional grounding step: resolving a location to the requested granularity, linking a relative time expression to an event month, choosing the memory that entails the queried relation, or replacing a referring expression with its named antecedent.
Goal-Mem
’s decomposition and unification process makes these intermediate requirements explicit, which helps prevent the model from returning a retrieved but ungrounded span as the final answer.

Appendix F
Forward Reasoning Baseline Implementations

This appendix describes the forward reasoning baselines used in RQ2: Query Reformulation, Self-Reflection, ReAct, and MemGuide. All four methods are implemented as wrappers around the same retrieval-augmented memory backbone
\mathcal{B}
used by
Goal-Mem
. Thus, these baselines do not change the memory storage, indexing, or update procedure of the underlying backbone; they only change how queries are generated, how retrieved memory units are accumulated or filtered, and how the final answer is produced.

Shared retrieval protocol.

For a controlled comparison, all baselines use the same inference LLM, decoding configuration, memory backbone
\mathcal{B}
, and answer-generation prompt as the corresponding
Goal-Mem
run. We use a shared retrieved-memory cap of

k_{\max}^{\mathrm{ret}}=60,

(7)

where
k_{\max}^{\mathrm{ret}}
denotes the maximum number of unique retrieved memory units that can be exposed to the final answer stage for one question. This retrieval cap is distinct from
K_{\max}
in the complexity analysis, where
K_{\max}
denotes the maximum number of subgoals produced by a goal decomposition. For iterative baselines, the same cap is distributed across retrieval actions: each retrieval action calls
\mathcal{B}_{\mathrm{retrieve}}
with a bounded per-query fan-out, retrieved units are deduplicated, and the merged pool is clipped to at most
k_{\max}^{\mathrm{ret}}
units before final answer generation or filtering.

Query Reformulation.

The Query Reformulation baseline follows the query-rewriting view of retrieval-augmented generation, where an LLM adapts the user input before retrieval to reduce the gap between the surface form of the question and the information needed by the reader
[
20
]
. Given the user utterance
u_{t}
, the LLM generates
n_{\mathrm{qr}}=5
diverse retrieval queries. The original question is also included as a retrieval query, giving

Q_{\mathrm{qr}}(u_{t})=\{u_{t}\}\cup\operatorname{Rewrite}_{\mathrm{LLM}}(u_{t};n_{\mathrm{qr}}=3).

(8)

The prompt asks the LLM to target different entities, events, temporal expressions, synonyms, and background aspects that may appear in memory, while preserving important entities and events from the original question. The retrieved results from all queries are merged, deduplicated, and clipped to
k_{\max}^{\mathrm{ret}}=60
. The final answer is then generated using the standard answer prompt over the resulting memory pool. This baseline is intentionally simple: it performs no symbolic decomposition, no unification, no missing-slot refinement, and no post-retrieval reranking.

Self-Reflection.

The Self-Reflection baseline adapts the reflective-agent principle of Reflexion to the single-question memory retrieval setting. Reflexion uses verbal feedback and an episodic memory buffer to improve later decisions; in our evaluation, we use the same forward-style reflection idea without carrying reflections across evaluation questions, so that the baseline does not receive extra persistent feedback unavailable to the other methods. The method first retrieves memories using the original question. At each reflection turn, the LLM is shown the question, all previously issued queries, and the accumulated retrieved memory pool. It outputs a JSON decision with three fields: whether the pool is sufficient, one concise next query if more evidence is needed, and a short rationale. If the pool is judged sufficient, the loop terminates; otherwise, the follow-up query is sent to
\mathcal{B}_{\mathrm{retrieve}}
, and the newly retrieved units are merged and deduplicated with the existing pool.

We set the maximum number of reflection turns to
T_{\max}^{\mathrm{sr}}=5
. The method can therefore terminate because the LLM judges the memory pool sufficient, because no new retrieval query is proposed, because retrieval returns no new memory units, or because the turn limit is reached. The final answer is generated from the accumulated memory pool after clipping to
k_{\max}^{\mathrm{ret}}=60
. Unlike
Goal-Mem
, Self-Reflection does not maintain typed variables or substitutions and does not verify that a retrieved memory entails a particular subgoal; each additional query is generated forward from the current question and evidence pool.

ReAct.

The ReAct baseline follows the reasoning-and-acting paradigm in which the LLM alternates between natural-language reasoning traces and actions that interact with an external environment
[
36
]
. In our memory-QA adaptation, the external environment is the shared memory backbone
\mathcal{B}
. At each step, the model emits exactly one
Thought
and one
Action
. The action space is restricted to

\texttt{Retrieve[query]}\quad\text{or}\quad\texttt{Finish[answer]}.

(9)

When the model selects
Retrieve[query]
, the query is sent to
\mathcal{B}_{\mathrm{retrieve}}
, and the returned memories are appended to the trajectory as an
Observation
. When the model selects
Finish[answer]
, the answer is returned directly. This preserves the ReAct design choice of interleaving reasoning traces with environment actions, while making the environment identical to the memory backend used by
Goal-Mem
.

We set the maximum number of ReAct steps to
S_{\max}^{\mathrm{react}}=5
. If the model output does not match the required
Thought
/
Action
format, the implementation retries once with a stricter format reminder. If the step limit is reached before a
Finish
action, the model is forced to produce a final
Finish
answer using only the observations collected so far. Retrieved observations are deduplicated, and the accumulated memory pool is clipped to
k_{\max}^{\mathrm{ret}}=60
. As with Self-Reflection, ReAct is a forward reasoning baseline: it decides the next retrieval action from the current trajectory, rather than decomposing the target answer into subgoals and verifying substitutions.

MemGuide.

MemGuide is a memory-selection method for goal-oriented multi-session LLM agents. The original method introduces a two-stage intent-driven framework: Intent-Aligned Retrieval retrieves memory units that share the current task intent, and Missing-Slot Guided Filtering reranks candidate memory units according to their marginal gain in filling missing task slots
[
5
]
. Our implementation follows this two-stage structure while adapting it to the unified memory-backbone interface used in our experiments.

First, an intent-capture prompt maps the question to a compact intent description and generates
n_{\mathrm{intent}}=5
intent-aligned retrieval queries. The original question is included as an additional seed query. These queries retrieve an initial candidate pool from
\mathcal{B}
. Second, a missing-slot reasoner inspects the current candidate pool and decides whether the pool is sufficient. If not, it enumerates concrete missing fields, such as a date, location, counterpart person, event outcome, or relation, and proposes at most
F_{\max}^{\mathrm{mg}}=5
follow-up queries for the next refinement round. We allow at most
R_{\max}^{\mathrm{mg}}=3
missing-slot refinement rounds.

After retrieval, MemGuide applies slot-guided filtering. Candidate memory units are scored by an LLM judger according to how directly they answer the question or fill the identified missing slots. The implementation combines the LLM score with the retrieval prior,

s(f)=\lambda s_{\mathrm{LLM}}(f)+(1-\lambda)s_{\mathrm{ret}}(f),\qquad\lambda=0.7,

(10)

where
s_{\mathrm{ret}}(f)
favors earlier retrieved candidates. The final selected memory pool is sorted by this score and clipped to
k_{\max}^{\mathrm{ret}}=60
before answer generation. The candidate pool is also clipped to the same cap after retrieval and deduplication.

This adaptation is faithful to the algorithmic role of MemGuide as an intent- and slot-aware forward memory selector, but it does not assume MemGuide’s original task-oriented-dialogue memory format or its task-specific fine-tuned filtering model. Instead, all candidate units are retrieved from the same memory backbone
\mathcal{B}
used by the other baselines, and the slot filter is implemented with the shared inference LLM. This keeps the comparison controlled: MemGuide receives the benefit of intent-aligned retrieval and missing-slot filtering, but it does not receive a method-specific memory representation or extra supervised training signal unavailable to the other methods.

Appendix G
Broader Impacts

Improving the coherence and factual grounding of long-horizon conversational agents has clear positive societal value in applications such as healthcare assistance, education, and personal productivity. By anchoring responses in retrieved memory rather than parametric knowledge,
Goal-Mem
reduces the risk of hallucinated but plausible-sounding responses. However, as with all existing RAG-based memory works and LLM-based systems, there may be concerns about the possibility of mistakes and the risk of over-reliance on the system’s outputs.

Appendix H
Limitations

As we observed in Section
5.1
,
Goal-Mem
consistently improves the performance of existing RAG-based agentic memory systems. At the same time, since it builds upon an underlying memory and retrieval backbone and leverages an LLM for components such as goal decomposition and answer generation, its effectiveness naturally depends on the quality of these components.
