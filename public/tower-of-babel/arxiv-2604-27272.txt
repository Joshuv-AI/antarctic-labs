When 2D Tasks Meet 1D Serialization: On Serialization Friction in Structured Tasks
Chung-Hsiang Lo, Lu Li, Diji Yang, Tianyu Zhang, Yunkai Zhang, Yoshua Bengio, Yi Zhang

Abstract
Large language models (LLMs) conventionally process structured inputs as 1D token sequences. While natural for prose, such linearization may introduce additional representational burden for tasks whose computation depends directly on explicit 2D structure, because row–column alignment and local neighborhoods are no longer directly expressed in the input. We study this setting, which we refer to as serialization friction , on a small diagnostic testbed of synthetic tasks with explicit 2D structure: matrix transpose, Conway’s Game of Life, and LU decomposition. To examine this question, we compare a text-only language pathway over serialized inputs with a vision-augmented pathway, built on the same language backbone, that receives the same underlying content rendered in task-faithful 2D layout, yielding a system-level comparison between two end-to-end input pathways. Across the tasks and settings we study, the visual pathway consistently outperforms the textual pathway; the gap often widens at larger dimensions, and error patterns under serialization become increasingly spatially structured. These findings indicate that the relationship between input representation and model performance on such tasks warrants further investigation, and suggest that preserving task-relevant 2D layout is a promising direction for structured 2D tasks.

Introduction

Large language models (LLMs) have made rapid progress on reasoning over natural language

, yet their dominant interface to input remains a 1D token sequence

This raises a concrete question: when a task’s computation depends on explicit 2D structure, does presenting the same underlying instance in its original 2D layout change model behavior relative to 1D serialization?

We use
serialization friction
as a descriptive lens for this setting. When inputs with explicit 2D structure are cast into 1D form, task-relevant relations are no longer directly expressed in the input and must instead be recovered from token order, delimiters, and formatting cues. Under this lens, part of the difficulty in such tasks may arise from representation in addition to the underlying computation.

3
Concept

This section introduces the conceptual lens that motivates our study and the comparison setup used to operationalize it. We first define serialization friction, the representational burden that can arise when inherently 2D tasks are flattened into sequential form, and then describe the testbed through which we compare textual and visual representations on tasks with explicit 2D structure.

3.1
Serialization Friction in Structured 2D Tasks

We instantiate this comparison between textual serialization and task-faithful visual layout on the same family of tasks with explicit 2D structure. Specifically, we compare a text-only pathway over serialized inputs with a vision-augmented pathway that receives the same underlying content rendered in task-faithful 2D layout. The aim of this setup is not to account for every difference between the two conditions, but to provide a focused comparison between these two representations on tasks where 2D structure is part of the computation. Across the two conditions, we hold fixed the underlying task instances, task definitions, prompts, train/eval splits, and evaluation criteria, so that the comparison centers on how structure is exposed to the model.

Concretely, serialization friction refers to the additional representational burden that arises when task-relevant spatial relations must be recovered from sequential position, delimiters, and tokenized content rather than being made explicit in the input. Under serialization, the model must not only solve the target task, but also reconstruct aspects of the original layout from token order and formatting cues. This framing motivates the central comparison of our study: comparing textual serialization with representations that preserve native layout on tasks where task-relevant structure is part of the computation.

3.2
Representation Comparison Setup

We instantiate this comparison between textual serialization and task-faithful visual layout on the same family of tasks with explicit 2D structure. The aim of this setup is not to account for every difference between the two conditions, but to provide a focused comparison between presenting task-relevant structure in native 2D layout and presenting the same underlying content as serialized text. Across the two conditions, we hold fixed the underlying task instances, task definitions, prompts, train/eval splits, and evaluation criteria, so that the comparison centers on how structure is exposed to the model.

3.2.1
Input Representations

We compare two ways of presenting the same underlying structured problem. In the
textual representation
, the input is serialized into a one-dimensional token sequence and processed by a text-only model. In the
visual representation
, the same structured content is rendered in its original two-dimensional layout and processed by a vision-capable model. This comparison is intended to preserve the task itself while changing the form in which its structure is exposed to the model.

To instantiate this comparison, we use GLM-4-9B-0414
(
8
)
for textual serialization and Glyph
(
3
)
for native 2D layout. Glyph is a visual-text compression method for long context understanding, which connects GLM with a vision encoder. This makes the GLM/Glyph pair a comparatively close match for studying how behavior changes across the two input forms. Concretely, GLM receives serialized text directly, whereas Glyph receives rendered 2D inputs through its visual front end.

3.2.2
Task Suite

We study three tasks whose computation depends on explicit 2D structure: matrix transpose, Conway’s Game of Life
(
4
)
, and LU decomposition. Full task definitions are provided in Appendix
A.2
.

Matrix Transpose.

This setting is governed by explicit row-column correspondence in a 2D layout. The required transformation preserves all values and rearranges them solely according to the transposed structure, without introducing additional arithmetic or rule execution. It lets us examine whether preserving the original 2D layout helps when the desired output follows directly from row–column correspondence.

Conway’s Game of Life.

Here, correctness is determined by local neighborhood interaction on a 2D grid. The next state is produced by applying the same update rule to each cell based on its surrounding neighbors, so the relevant structure lies in spatial adjacency rather than row-column alignment alone. This task remains a one-step structure-driven prediction problem: the output is determined directly from the current grid configuration rather than through a sequence of dependent intermediate transformations. It lets us probe whether the same qualitative difference appears for rule-based computation over local 2D structure. More broadly, cellular-automata-style dynamics have recently been explored as a structured substrate for training and evaluating reasoning systems beyond natural language priors.

LU Decomposition.

In this setting, the relevant structure must be maintained across a sequence of dependent row-column operations. Producing a valid factorization requires the matrix to be progressively transformed while preserving relationships that constrain later steps of the computation. It lets us test whether the representation difference remains visible when 2D structure stays relevant throughout a sustained transformation process.

The first two tasks probe whether task-faithful 2D inputs help when the target transformation is directly tied to spatial alignment or local neighborhood interaction. LU decomposition instead examines a different role of structure, where relevant row–column relationships must be maintained and reused across a sequence of dependent operations.

3.2.3
Instantiation Overview

To support a controlled comparison, all tasks are instantiated from synthetic datasets with programmatically generated inputs and outputs. This design lets us vary task dimensions systematically, generate exact supervision targets, and ensure that the textual and visual conditions are derived from the same underlying task instances. As a result, within each task, the comparison differs in representation rather than in problem content.

We use different training paradigms according to the natural supervision signal of each task. For matrix transpose and Conway’s Game of Life, we adopt supervised fine-tuning, since both tasks admit direct target outputs and primarily serve to test whether the two representations behave differently under matched explicit supervision. For LU decomposition, we instead use reinforcement learning with verifiable reward, following recent work showing that outcome-verified optimization can effectively induce reasoning improvements in domains with objective correctness checks
(
6
;
oneexample_rlvr_2025
)
. Multiple valid intermediate trajectories may lead to a correct decomposition, and success depends on maintaining consistency across a sequence of dependent elimination steps. RLVR is therefore a natural fit for optimizing the task’s outcome-level correctness criterion in this setting
(
23
;
16
;
27
)
. Because the optimization paradigm differs across tasks, we compare representations within each task rather than treating absolute accuracies across tasks as directly comparable.

Evaluation is task-specific but shared across the two representations within each task. For matrix transpose and Conway’s Game of Life, predictions are evaluated against the ground-truth. For LU decomposition, correctness is determined by whether the predicted lower and upper triangular factors satisfy the required structural constraints and can reconstruct the original matrix. Full dataset construction details, hyperparameter settings, and implementation specifics are provided in Appendix
A.3
.

5
Discussion

This section adds context for interpreting the results. We first present a small supportive probe, then examine task-structured error patterns, and finally clarify the scope of the claims supported by the current evidence.

5.1
A within-visual probe for interpretation

Figure 5:
Accuracy of finetuned GLM, Glyph, and disruptive-Glyph models on matrix transpose. Evaluation at each matrix size, where all three models are trained on one matrix size and evaluated on that same size.

Our main comparison between text serialization and original 2D layout is a system-level representation comparison rather than a fully isolated test of layout alone. To narrow the interpretation within a single task, we add a smaller probe on matrix transpose in which only the visual rendering is changed. Specifically, we compare a 2D matrix rendering with a layout-disrupted rendering that presents the same row-major textual content as an image. We use transpose because it provides the most direct test of row–column organization in our task suite. Details of the two rendering strategies are provided in Appendix
A.1
.

Figure
5
shows a clear separation among the three conditions: across all tested dimensions, Glyph performs best, GLM remains in the middle, and disruptive-Glyph performs worst. Although limited to a single task, this more constrained probe helps narrow the interpretation of the main comparison. In the earlier experiments, the visual condition differed from the text condition not only in layout but also in visual encoder and modality. Here, however, transpose performance changes substantially even within the visual condition when only the rendering is altered. This does not isolate a unique mechanism, but within our setting it shows that the observed advantage does not fully arise from visual encoding alone.

5.2
Task-structured error patterns

Aggregate accuracy shows that the two representations behave differently, but it does not by itself explain how those differences arise within each task. We therefore examine finer-grained error patterns. Across the three tasks, the gap does not appear as unstructured noise; instead, it follows the particular kind of 2D structure each task depends on.

Taken together, these error patterns suggest that the representation gap is structured by task rather than appearing as unstructured noise. This supports the usefulness of the serialization-friction lens at a descriptive level, beyond aggregate accuracy alone.

5.3
Limitations

This is a system-level representation comparison rather than a fully isolated test of layout alone. The textual and visual conditions still differ in modality, visual front end, pretraining-derived priors, tokenization regime, and input representation, so the observed gains should not be interpreted as evidence for a unique causal mechanism. The within-visual probe in Section
5.1
helps narrow this interpretation, but remains supportive rather than definitive evidence.

The empirical scope of the paper is also intentionally narrow. We study a small diagnostic testbed of synthetic tasks whose computation depends directly on explicit 2D structure, namely row–column correspondence, local neighborhood interaction, and multi-step elimination over matrix structure. This makes the setup useful for examining serialization friction in a controlled way, but it also limits the range of conclusions that can be drawn.

This limitation is especially important for interpreting the observed advantage of 2D layout. The current paper does not establish that preserving layout is beneficial as a general principle, but studies this effect in a narrow setting of tasks with explicit 2D structure. More broadly, the results suggest that representation-level preservation of task-relevant structure is a promising direction, while leaving open how it extends beyond the 2D setting. A natural next step is therefore to test this perspective across a broader range of tasks and under tighter controls that better separate layout, modality, tokenization, and encoder effects.

6
Conclusion

This paper examines a simple question: when a problem depends on explicit 2D structure, what changes when it is forced into a 1D sequence? Across the small, controlled testbed studied here, we find that explicit 2D layout is consistently associated with stronger performance and more stable error patterns than 1D serialization. These findings suggest that serialization friction is a useful lens for analyzing how representation affects behavior on such tasks, and that preserving task-relevant 2D layout is a promising direction worth investigating further under tighter controls and broader task coverage.

A.2
Task Definitions

We study three structured tasks: matrix transpose, Conway’s Game of Life, and LU decomposition. In all cases, the underlying task is fixed across representations. The same problem instance may be presented either as serialized text or as a rendered 2D input, but the required transformation and correctness criteria remain unchanged.

Matrix Transpose.

Given an input matrix
A
, the model is asked to output its transpose
A^{\top}
. The input is a square numeric matrix with integer entries. The expected output is the full transposed matrix as a 2D array. Correctness requires exact agreement with the ground-truth transpose.

Conway’s Game of Life.

Given the current board state of Conway’s Game of Life, the model is asked to output the full next-generation board of the same size. The input is a binary grid in which 1 denotes a live cell and 0 denotes a dead cell; input cells are sampled with equal probability for the live and dead states. The next board is computed according to the standard Game of Life rules
(
4
)
under zero-padding boundary conditions: each cell is updated synchronously based on the number of live neighbors in its 8-cell neighborhood, a live cell remains live if and only if it has 2 or 3 live neighbors, and a dead cell becomes live if and only if it has exactly 3 live neighbors; otherwise, the cell is dead in the next generation. Cells outside the board are treated as dead. The expected output is the full next-generation grid as a 2D array of binary values, and correctness requires exact agreement at every cell position.

LU Decomposition.

Given an input matrix
A
, the model is asked to produce matrices
L
and
U
such that
A=LU
, where
L
is a lower triangular matrix and
U
is an upper triangular matrix. The input is a square numeric matrix. We use LU decomposition without pivoting, i.e., matrices are constructed such that a valid factorization exists without row permutations. The expected output is the pair
(L,U)
in structured matrix form. Correctness is defined functionally: the predicted factors must satisfy the triangular constraints and reconstruct the input matrix under matrix multiplication, up to a small numerical tolerance.

A.3
Implementation Details

Models.

Across all tasks, we use the same two model families under two representation conditions. The 1D condition uses GLM-4-9B-0414
(
8
)
with serialized textual inputs, while the 2D condition uses Glyph
(
3
)
, which shares the same GLM language backbone but takes rendered 2D inputs through a visual front end. This same GLM/Glyph pair is used for matrix transpose, Conway’s Game of Life, and LU decomposition.

Data generation and splits.

All datasets in this study are synthetic and programmatically generated. For each task, the 1D and 2D conditions are derived from the same underlying task instances, so that the comparison differs in representation rather than in problem content. Training and test instances are generated separately, and evaluation is always performed on held-out test sets.

For matrix transpose, each example consists of a square integer matrix together with its gold transpose. The standard single-size experiments cover matrix sizes from
12\times 12
to
20\times 20
. For each size, data are split into train/test partitions with a ratio of 5:1. The mixed-training setting combines examples from
12\times 12
,
14\times 14
, and
16\times 16
matrices in a 1:1:1 ratio.

For Conway’s Game of Life, each example consists of a binary grid together with its full next-generation grid under standard Game of Life dynamics. The standard single-size experiments cover grid sizes from
4\times 4
to
8\times 8
. For each size, data are split into train/test partitions with a ratio of 5:1. The mixed-training setting combines examples from
4\times 4
,
5\times 5
, and
6\times 6
grids in a 1:1:1 ratio.

For LU decomposition, each example consists of a square integer matrix, that was generated by taking the product of an upper triangular and a lower triangular matrix with integer entries from -9 to 9. The standard single-size experiments cover matrix sizes from
3\times 3
to
6\times 6
. For each size, data are split into train/test partitions with a ratio of 5:1. The mixed-training setting combines examples from
3\times 3
,
4\times 4
, and
5\times 5
matrices in a 1:1:1 ratio.

Input and output format.

Across both modalities, the task instruction remains the same and only the representation of the structured input changes. In the 1D condition, the prompt contains the serialized matrix or grid directly in text. In the 2D condition, the same instruction is used, but the structured input is provided as a rendered image. In both conditions, the model is trained to produce a reasoning trace enclosed in
<think>...</think>
tags followed by the final structured answer. Evaluation is performed only on the extracted answer portion after the closing tag.

Evaluation.

Task definitions and correctness criteria are specified in Appendix
