Haiku to Opus in Just 10 bits: LLMs Unlock Massive Compression Gains
Roy Rinberg, Annabelle Michael Carrell, Simon Henniger, Nicholas Carlini, Keri Warr, [0.5em] Harvard University

Abstract
We study the compression of LLM-generated text across lossless and lossy regimes, characterizing a compression-compute frontier where more compression is possible at the cost of more compute. For lossless compression, domain-adapted LoRA adapters can improve LLM-based arithmetic coding by 2 × 2\times over compression with the base LLM alone. For lossy compression, prompting a model for a succinct rewrite then applying arithmetic coding can achieve compression ratios of approximately 0.03, a 2 × 2\times improvement over compressing the original response. We further introduce Question-Asking compression (QA), an interactive lossy protocol inspired by the game “Twenty Questions”. A small model iteratively refines its response by asking yes/no questions to a stronger model, transferring exactly one bit per answer. On 8 benchmarks spanning math, science, and code, 10 binary questions recover 23% to 72% of the capability gap between a small and large model on standard benchmarks and 7% to 38% on harder benchmarks, achieving compression ratios of 0.0006 to 0.004. This is over 100 × 100\times smaller than prior LLM-based compression ( 9 ) , suggesting that interactive protocols can transfer knowledge far more efficiently than transmitting full responses.



1
Introduction

Machine learning (ML) and data compression are both concerned with exploiting structure in data to reduce uncertainty. ML aims to learn patterns that enable accurate prediction and generation, while compression seeks efficient representations that minimize the number of bits required to encode information. Information theory formalizes this connection, providing insight about the minimum number of bits required to encode some sequence, given that the sequence is drawn from a given distribution.

The source coding theorem, a foundational result in information theory, tells us that in the lossless regime, the minimum compression ratio achievable is determined by the entropy of the data distribution
(
29
)
.
Excitingly, this theoretical lower bound is achievable in practice using compression techniques such as arithmetic coding, provided the compression scheme is given acess to the data distribution

(
8
)
. Thus, achieving the optimal lossless compression ratio is predicated on determining the right probability distribution for a sequence.

At the same time, we observe that the primary goal of Large Language Models (LLMs) is to produce probability distributions from which to sample tokens. Recent work has operationalized the connection between compression and ML by leveraging large language models (LLMs) to produce probability distributions that, when combined with arithmetic coding, enable effective text compression
(
5
;
30
;
9
)
.

These techniques already boast impressive compression ratios; whereas a common compression scheme like GZIP
(
10
)
achieves a compression ratio of around
0.33
on most text, LLM-based arithmetic coding schemes achieve a compression ratio closer to
0.1
on text that is in distribution for the model, like Wikipedia
(
9
)
.

While already impressive, we observe that the requirement of producing a lossless compression scheme is overly restrictive in many textual settings. Most text-based interfaces do not need to produce a specific sequence of tokens, but instead only need to return a response that is useful to the user
(
34
)
. Framed this way, compression only needs to preserve semantic meaning rather than exact text.
This is particularly true in the LLM chatbot setting, where users have no access to the underlying model and therefore cannot tell whether the response they receive differs from the original model output.
Notably, this observation highlights a key distinction between lossy compression for text and for images: image data has a well-defined ground-truth target, so lossy compression necessarily introduces deviations from that target, whereas text can have many semantically similar realizations with no single ground truth.

Modern language models can summarize, rewrite, and edit text in an open-ended manner, enabling a new form of lossy compression in which the surface form of the text may change, but its semantic content and usefulness are largely preserved. Unlike traditional compression schemes, this form of compression does not aim to reconstruct the original string exactly, but instead produces an alternative representation that remains a valid and high-quality response.

More broadly, it has long been recognized that certain forms of knowledge can be compactly represented through interaction. In theoretical computer science, this insight appears in the study of interactive proof systems, where interaction between two parties can dramatically reduce the amount of information that must be communicated to convey or verify a concept
(
13
;
12
)
. We formalize this connection in Section
2.2
and adapt it to text compression in Section
5
.

In this work, we study both lossless and lossy compression schemes enabled by modern large language models. We characterize a tradeoff between computational cost and compression rate, mapping out a Pareto frontier in which achieving greater compression generally requires increased computation. We note that in the lossy setting, this tradeoff is inseparable from a corresponding compression-utility frontier: while aggressive compression can dramatically reduce representation size, it inevitably risks degrading downstream utility.

Contributions

In this work, we characterize a compression-compute spectrum for LLM-generated text, mapping out methods that trade increasing computation for progressively better compression ratios, from lossless arithmetic coding to interactive lossy protocols.
This paper makes the following contributions:

Background & Related Work

2.1
Arithmetic Coding and LLM Compression

The source coding theorem establishes that for a discrete memoryless source with distribution
P
, the minimum achievable expected code length is the entropy
H(P)=\mathbb{E}_{x\sim P}\!\left[-\log_{2}P(x)\right]
. When data are encoded using a probabilistic model
Q
, the expected number of bits required is given by the cross-entropy
H(P,Q)=\mathbb{E}_{x\sim P}\!\left[-\log_{2}Q(x)\right]
. When
Q=P
, the cross-entropy reduces to the entropy, recovering the optimal code length; the gap
H(P,Q)-H(P)=\mathrm{KL}(P\|Q)\geq 0
quantifies the cost of model mismatch. Thus, compression efficiency is directly determined by how closely the model distribution approximates the true data-generating distribution.

Arithmetic coding is an entropy coding technique that achieves near-optimal compression by converting probability estimates directly into code lengths, assigning shorter codes to more likely sequences
(
20
;
27
)
. When applied to language modeling, the code length for a token sequence
x_{1},\ldots,x_{n}
approaches
\sum_{i=1}^{n}-\log_{2}p(x_{i}\mid x_{<i})
, the model’s cross-entropy on the sequence. Building on this, recent work has demonstrated that large language models paired with arithmetic coding achieve strong text compression results
(
5
;
30
;
9
)
.

Challenges: Distribution mismatch and non-determinism.

While LLMs provide powerful probabilistic models for text, their use in arithmetic coding introduces two practical challenges. First,
distribution mismatch
: arithmetic coding achieves optimal compression only when the coding distribution matches the data distribution. When text drawn from
P
is encoded using model
Q
, the expected code length increases by the KL divergence
\mathrm{KL}(P\,\|\,Q)
. A general-purpose LLM may therefore compress domain-specific data suboptimally. We address this through lightweight domain adaptation using LoRA fine-tuning (Section
3
)
(
17
)
.

Second,
non-determinism
: arithmetic coding requires exact agreement between the probability distributions used by the encoder and decoder. Modern LLM inference pipelines are not strictly deterministic; small numerical discrepancies arise from floating-point effects, hardware variation, or batching
(
15
;
26
;
19
)
. Because decoding is autoregressive, even tiny mismatches alter the decoder’s context and cause errors to accumulate, leading to catastrophic decoding failure. PMATIC
(
1
)
addresses this via auxiliary “helper bits” to synchronize distributions. We propose a complementary approach,
block emission encoding
, which periodically emits the current interval midpoint and restarts with a fresh
[0,1]
interval, bounding error propagation to a single block rather than the entire sequence. While robust arithmetic coding is an important practical requirement for LLM-based compression, it is not the central focus of this paper; we provide full algorithmic details in
Appendix

F
as a contribution that may be of independent interest to practitioners. Extended discussion of both challenges appears in Appendix
A.1
.

2.2
Interactive Compression via Binary Questions

The children’s game
20 Questions
illustrates how interaction can drastically reduce communication. One player thinks of an object, and the other identifies it by asking a sequence of yes–no questions, each conveying a single bit of information.By choosing questions adaptively, the player can identify one object among millions using roughly 20 bits—far fewer than would be required to specify the object directly (and on the order of
<2
tokens in an LLM of information).

This game reflects a general principle: interaction enables information to be revealed conditionally, focusing communication on what is most informative given previous answers. In complexity theory, this principle manifests as a separation between non-interactive and interactive verification. Non-interactive proofs, consisting of a single message from a prover to a verifier, characterize the class
\mathrm{NP}
. Allowing the verifier to ask adaptive questions yields interactive proofs, which characterize
\mathrm{IP}=\mathrm{PSPACE}
, a class believed to be strictly larger than NP
(
13
;
28
)
.

In Section
5
, we apply this idea to LLM communication. A small model adaptively asks binary questions that are answered by a large model, allowing substantial knowledge to be transferred using only a small number of bits.

2.3
LoRA and Domain Adaptation

Low-Rank Adaptation (LoRA)
(
17
)
is a parameter-efficient fine-tuning method that adapts a pretrained model by learning low-rank update matrices. For a pretrained weight matrix
W_{0}\in\mathbb{R}^{d\times k}
, LoRA learns
\Delta W=BA
where
B\in\mathbb{R}^{d\times r}
and
A\in\mathbb{R}^{r\times k}
with rank
r\ll\min(d,k)
. This dramatically reduces the number of trainable parameters.

The key insight for compression is that a LoRA adapter fine-tuned on domain-specific text will assign higher probability to in-domain text, thereby reducing the bits required for arithmetic coding. If sender and receiver share a set of domain-specific LoRA adapters, they can achieve better compression by selecting the appropriate adapter for each message.

3
Lossless Compression through Domain-Adapted LoRAs

LoRA has proven particularly effective for domain adaptation, enabling a single base model to be specialized to multiple domains via lightweight adapters. If the sender and receiver share a collection of domain-specific LoRA adapters, they can improve compression by selecting the adapter that best matches the input distribution for each message. We investigate whether domain-specialized language models can achieve better compression rates than general-purpose models.

Experimental Setup.

We use LMSYS-Chat-1M
(
36
)
, a large-scale dataset of real user conversations with LLMs, as our primary testbed. We cluster the dataset into 50 topic clusters using K-means on Qwen embeddings. For ten clusters, we fine-tune a LoRA adapter
(
17
)
on the training split (rank=16,
\alpha
=32) using Mistral-7B-Instruct as the base model
(
18
)
. We evaluate compression performance on held-out test samples with at least 200 tokens, measuring compression ratio using different methods: (1)
Baseline
: the base model without any LoRA, (2)
Gzip
, (3)
Correct LoRA
: the adapter trained on the same cluster, (4)
Wrong LoRAs
: an adapter trained for each of the nine remaining incorrect clusters, and (5)
RAG LoRA
: the adapter selected by a retrieval-based router (described below).

For all methods, we report compression ratio as compressed size divided by uncompressed size.
1
1

1

For GZIP, this is compressed bytes divided by original bytes. For arithmetic coding, this is output bits divided by input bits, where input bits equals
\log_{2}(\text{vocabulary size})\times\text{number of tokens}
. The arithmetic coder’s bitstream can be packed into bytes with negligible overhead (
<1
byte per message), so these metrics are directly comparable.

3.1
RAG-based LoRA Router

In practice, one does not have access to the exact distribution that a text was generated from, so selecting the correct LoRA requires an automatic routing method. We propose an approach akin to retrieval-augmented generation (RAG)
(
21
)
.

Routing Protocol.

We build a FAISS index over representative texts from each cluster using Qwen embeddings. Each index entry maps to the corresponding cluster’s LoRA adapter. For each input text, we embed the text, retrieve the top index, and use the corresponding LoRA adapter.

Routing Accuracy.

We evaluate RAG routing accuracy on held-out test samples using both the full text (prompt and response) and only the prompt. The router correctly identifies the domain cluster approximately 72% of the time with full text and 55% with prompt only. For cluster-specific results, see Appendix
C
.

). The RAG-selected LoRA achieves 0.10 (

Analysis.

The per-cluster results reveal that improvement varies by topic. Crucially, the correct LoRA consistently outperforms the wrong LoRAs across all clusters, validating that topic-matched adapters capture domain-specific patterns that transfer to improved compression. However, the wrong LoRAs still outperform the base model, suggesting the dataset comprises highly-correlated conversational text; a more diverse dataset would show wrong LoRAs having zero or negative effect.

We replicate these results on WildChat
(
35
)
, a dataset of 1M ChatGPT interaction logs (Table
11
, Appendix
C
). The correct LoRA achieves a compression ratio of 0.10, a
1.7\times
improvement over baseline (0.17), slightly lower than LMSYS (
2.0\times
), consistent with WildChat’s greater topic diversity within clusters.

Response Rewriting

A simple approach to lossy compression is to generate multiple candidate solutions and select the one that compresses best. In principle, this should not meaningfully change the distribution of texts that we produce, as we are selecting from texts already generated by the LLM.

5
Interactive Question Asking (Question-Asking compression)

Thus far, we have focused on traditional information-theoretic approaches: optimizing the distributions used to compress text (Section
3.1
) or the text itself to better fit a fixed compression distribution (Section
4
). We now turn to interactive compression via binary questions (Section
2.2
).

We adapt the children’s game 20 Questions to the task of LLM knowledge transfer and compression. Given a prompt, an SLM first generates an initial response and then formulates
N
binary yes/no questions about its solution strategy, for example, “Is my approach to step 3 correct?” The LLM answers each question with yes or no, transferring exactly one bit of information per response.
2
2

2

In principle, the expected cost per question can be reduced below one bit. If the SLM can predict the base-rate distribution of LLM responses, for example that “Yes” occurs with probability 0.8 for a given question, arithmetic coding over the binary answers yields an expected cost of
H(\text{answer}\mid\text{question})
bits per question. This improvement is essentially free: if the SLM’s calibration is incorrect, the LLM can transmit a single extra bit to signal this, ensuring that the protocol never performs worse than the naive one-bit-per-answer scheme.
The SLM then revises its response by incorporating all
N
answers. Crucially, the SLM’s questions are deterministic given its initial response, the prompt, and fixed hyperparameters. As a result, only the
N
binary answers must be transmitted. The receiver can reconstruct the full question-answer transcript by running an identical SLM locally, reducing the communication cost to exactly
N
bits, independent of the response length.

Results.

The central question is whether the QA protocol’s value comes from the
structure
of iterative refinement or from the
content
of the stronger model’s answers. Table
2
reveals that the answer depends on task difficulty.
On easier benchmarks (GSM8K, MATH, GPQA), the majority of the recovery is captured by process of asking questions (BL-CoT), and Haiku does approximately as well as Opus as the LLM or as the Question Asker; the structured protocol alone enables Haiku to self-correct on well-posed math and science problems.

On harder benchmarks, there is a larger gain in recovery rates when the LLM is large model.
Here, we speculate that the SLM lacks the knowledge to self-correct, so the information in Opus’s binary answers becomes more important, and a stronger question-asker (Opus in QA
+
) amplifies the improvement, as it can better identifies the SLM’s failure modes. AIME is an exception, with uniformly low recovery across all configurations, suggesting that competition math resists the binary Q&A format. Example transcripts illustrating the Q&A interaction are provided in Appendix
G.8

improvement over prior SOTA, illustrating the compressive power of interactive protocols that exploit shared priors between models rather than encoding the full response text.

6.1
Applications to Model Security

One promising defense for protecting model weights is
egress limiting
: restricting the total
number of bits that exit a datacenter
(
22
;
3
;
14
)
. This rests on a simple
information-theoretic observation: if only
10
GB leaves a datacenter, an adversary cannot steal more
than
1O
GB of anything, regardless of their attack vector. However, strict bit limits can harm
legitimate users who need to receive model outputs. As we have explored in this paper, natural language is extremely compressible, which can be used to empower defenders to apply stricter egress limits, as model weights are generally more difficult to compress than text.
5
5

5

Though recent research seeks to find more compressible forms of model weights
(
6
)
.

6.2
Limitations

Selection bias in shortest-of-N.

When we select the most compressible response from
N
candidates, we are implicitly biasing toward certain kinds of outputs. We measure accuracy on AIME to verify that compression-selected responses are not systematically worse (Appendix
D
), but other quality dimensions (clarity, completeness, pedagogical value) are not evaluated. It is plausible that optimizing for compressibility selects for responses that are terse or formulaic in ways that standard accuracy metrics do not capture.

Benchmark-specific evaluation.

Our QA-compression results are evaluated on math, code, and science benchmarks with verifiable answers. These domains are well-suited to the binary question format because correctness is unambiguous. The protocol’s effectiveness on open-ended generation tasks (creative writing, summarization, advice) is untested and likely quite different, since these tasks lack clear ground truth against which to evaluate yes/no questions.

LLM-as-judge reliability.

The iterative QA-compression protocol relies on the LLM to answer binary questions about solution correctness. When the LLM is itself wrong (as on very-hard problems), its answers can actively mislead the SLM. We observe this empirically: on frontier benchmarks where the judge fails to reliably evaluate solutions, regression on easy problems is severe (Section
5
). The protocol’s utility is therefore bounded by the LLM’s own accuracy on the task.

6.3
Philosophical Implications

The QA-compression protocol offers a lens on the scientific process itself. When a scientist wants to synthesize a
chemical, they form a hypothesis, run an experiment, and get back a low-bit answer: it worked, or it
didn’t.When an experiment fails, the scientist returns to the
problem with a new question: ”Was the temperature wrong?” ”Did I use the wrong catalyst?” In this
light, each experiment is a yes/no question posed to nature.

This maps onto QA-compression compression: the scientist is the SLM, which formulates candidate solutions and asks binary questions; and nature is the LLM providing yes/no feedback. This framing and this paper provides quantifiable support to the pedagogical adage that
the hard part of science is asking a good question.

6.4
Future Work

Improving question quality for QA-compression.

The QA-compression protocol is inherently limited by the SLM’s ability to ask useful questions and integrate the answers. Our results show that on frontier benchmarks, upgrading the question-asker to a stronger model yields meaningful gains (Section
5
), suggesting that question quality is a bottleneck. Future work could explore improving the SLM’s question-asking ability, whether through prompt engineering, fine-tuning on transcripts from successful QA-compression sessions, or reinforcement learning on recovery rate.

Alternative interactive schemes.

Our QA-compression protocol relies entirely on the SLM’s ability to ask useful questions. However, this is limiting:
consider ”What are the first 5 decimal places of
\sqrt{17}
?” A small model lacks the capacity to
derive the answer, so no sequence of binary questions will help. A natural extension is to allow the
LLM to
inject
information, providing information that the SLM would not discover through questioning alone. Other low-bit interaction schemes are also possible. For example, the SLM could generate
N
candidate
responses, and the LLM could select the best one in
\log_{2}N
bits.
6
6

6

We explored this direction but found that this meaningfully lengthened responses, eliminating compression gains. However, we view this as an
engineering challenge rather than a fundamental barrier, and we believe alternative strategies may yet make such schemes viable.

Improving Robustness to Non-determinism.

In both lossless and lossy compression, achieving meaningful compression ratios requires that the encoder and decoder reproduce identical model
outputs. However, models running on different hardware regularly exhibit non-deterministic outputs at both the logit and token level

(
33
;
15
;
26
;
19
)
. Compression schemes that are robust to small amounts of cross-machine non-determinism would be significantly more practical.
Some work has explored this direction for arithmetic coding
(
1
)
, but the space remains largely unexplored for lossy compression.

Appendix A
Extended Background

This appendix provides extended discussion of background concepts summarized in Section
2
.

A.1
Arithmetic Coding: Extended Discussion

Arithmetic coding is an entropy coding technique that achieves near-optimal lossless compression by encoding a sequence of symbols using a number of bits that approaches the Shannon entropy of the source
(
32
)
. Given a probabilistic model over a discrete alphabet, arithmetic coding converts probability estimates directly into code lengths, assigning shorter codes to more likely sequences and longer codes to less likely ones.

In the context of language modeling, let
p
denote a language model and let
x_{1},x_{2},\ldots,x_{n}
be a sequence of tokens. When arithmetic coding is applied using the model’s conditional probabilities, the resulting code length is approximately

\sum_{i=1}^{n}-\log_{2}p(x_{i}\mid x_{1},\ldots,x_{i-1}),

which corresponds to the model’s cross-entropy evaluated on the sequence. Consequently, compression performance is governed almost entirely by the quality of the language model’s predictive distribution.

Building on this observation, several recent works have demonstrated that large language models can serve as effective entropy models for text compression when paired with arithmetic coding, achieving strong empirical results in both online and offline settings
(
5
;
30
;
9
)
.

A.2
Distribution Mismatch: Extended Discussion

Arithmetic coding achieves optimal compression only when the coding distribution matches the true data-generating distribution. When text drawn from a distribution
P
is encoded using a model
Q
, the expected code length increases by the Kullback-Leibler divergence
\mathrm{KL}(P\,\|\,Q)
, yielding an expected cost of
H(P)+\mathrm{KL}(P\,\|\,Q)
. As a result, a general-purpose LLM may perform suboptimally when compressing domain-specific data whose statistics deviate from those seen during pretraining.

This motivates domain adaptation approaches. We address this challenge through lightweight domain adaptation using LoRA fine-tuning (Section
3
), which significantly improves compression performance by reducing distributional mismatch.

A.3
Non-Determinism in LLM Inference: Extended Discussion

Arithmetic coding requires exact agreement between the probability distributions used by the encoder and decoder. Modern LLM inference pipelines, however, are not strictly deterministic: small numerical discrepancies arise across runs due to floating-point effects, hardware variation, kernel implementations, or batching
(
15
;
26
;
19
)
. Even vanishingly small probability mismatches can cause decoder desynchronization and catastrophic decoding failure.

This fragility is amplified by the sequential nature of arithmetic coding. Because decoding is autoregressive, any mismatch alters the decoder’s context and thus the predicted distribution for all subsequent tokens, causing errors to accumulate over long sequences. Many prior works do not observe this issue because they run compression and decompression on a single machine, where the cross-run non-determinism is very small
(
9
;
30
)
. However, real-world deployments necessarily involve separate encoder and decoder machines, where such discrepancies become unavoidable.

Recent work has addressed this challenge explicitly. In particular, PMATIC proposes communicating auxiliary “helper bits” to synchronize the effective model distributions between encoder and decoder
(
1
)
. Since our focus is not on synchronization mechanisms themselves, we do not propose new solutions in this direction and instead refer practitioners to PMATIC-style approaches when deploying arithmetic coding with LLMs.

Notes on baseline compression.

Our baseline compression ratio of 0.176 is higher (worse) than ratios reported in prior work on neural text compression
9
, which report values closer to 0.1 for the same model size. This discrepancy is likely due to several factors: (1) differences in base models (we use Mistral-7B-Instruct rather than models specifically optimized for compression), and (2) differences in experimental setup (e.g., how text is chunked, minimum token thresholds, evaluation protocol). The key takeaway is not the absolute compression ratio, but rather the
relative improvement
from LoRA adaptation: a consistent 16% reduction in compressed size across all clusters.

Comparison to conversational data.

Interestingly, the conversational datasets (LMSYS and WildChat) achieve substantially better compression ratios than enwik9. LMSYS achieves a baseline ratio of 0.09 and WildChat achieves 0.10 (Tables
9
and
12
), compared to 0.176 for enwik9. This suggests that LLM-generated conversational text is
{\sim}2\times
more compressible than raw Wikipedia text. This is intuitive: conversational text produced by LLMs likely has more predictable patterns and less information density than encyclopedic content, which contains diverse factual information, proper nouns, dates, and technical terminology.

Appendix D
“Just Ask” Compression

D.1
Quality Preservation in Lossy Compression

When using Summarization (Section
4
), a natural concern is whether the succinct rewrite preserves the quality of the original reasoning, or merely preserves enough surface-level information to guess the answer.

Answer-Masking Check.

We implement a simple quality check. Before requesting the succinct rewrite, we mask the final answer in the verbose solution, replacing
\boxed{A}
with
\boxed{???}
. The model then rewrites the masked solution, and must re-derive the correct answer from its own succinct version. If it produces an incorrect answer, we consider the compression too lossy.

Limitations.

This check is imperfect. The succinct version might “leak” information about the answer through numerical patterns or structural cues (e.g., “the answer is a two-digit prime”) without actually preserving the full reasoning chain. A human reader might find the succinct version harder to follow or less informative than the verbose original, even if a language model can still extract the correct answer.

More rigorous assessment would require human evaluation of reasoning quality, or measuring performance on downstream tasks that depend on understanding the solution (not just knowing the final answer). We leave such evaluation to future work. Other work, such as
31
;
11
propose alternative mechanisms for evaluating that a summary retains the core information from the body, largely premised on using an LLM to generate questions about the original text, and then prompting another LLM to answer the questions based on the original and answer the questions based on the summarized text, and comparing alignment.

D.5
Knowledge Density and Compressibility

An interesting phenomenon emerges when we examine what happens to text after summarization: the rewritten text is shorter but
less compressible per character
. Figure

illustrates this on AIME problems using Haiku. The verbose original solutions contain predictable boilerplate (“Step 1:”, “Therefore,”, “Let us consider”) that an LLM easily predicts, resulting in low bits-per-character. When we ask the model to rewrite the solution as succinctly as possible, the boilerplate is stripped away and what remains is denser, less predictable text: variable names, key equations, and compressed reasoning steps that the LLM used for compression cannot as easily anticipate.

However, the reduction in length is larger than the increase in per-character complexity. A typical verbose solution of
{\sim}2{,}100

{\sim}5.3\%

{\sim}590

{\sim}9.5\%
compression ratio. Despite the nearly doubled bits-per-character, the total compressed size drops by roughly
40\%
because the text is
3.6\times
shorter. In other words, summarization increases the density of information of the text while still reducing the total information cost.

Appendix E
Negative Results & Ablations

In this section, we document approaches that did not yield the expected improvements, as well as ablation studies that provide insight into the mechanisms underlying our methods.

E.1
Judge Design

The iterative QA protocol requires a judge to decide whether the SLM’s updated answer is satisfactory (and should be accepted) or whether to continue asking questions. Two natural options arise:

1.

Objective (standalone) judging.
The judge evaluates the SLM’s answer on its own merits, scoring solution quality on a 1–10 scale. This does not require a reference solution, but relies on the judge’s ability to assess correctness independently.

2.

Comparison judging.
The judge compares the SLM’s answer against the LLM’s own solution, scoring how similar or aligned they are. This gives the judge a concrete reference, but the LLM’s own answer may itself be wrong on hard problems.

We evaluate both options below, along with ablations on the quality threshold and gold-answer access.

E.1.1
Quality-Thresholding Judge in QA Compression

A natural idea for improving the QA protocol is to add a
quality-thresholding judge
: after each round of questions, an LLM evaluates the SLM’s updated answer on a 1–10 scale. If the score meets a threshold (
\geq 7
), the protocol accepts the current answer and early-stops; otherwise, it continues asking questions in hopes of further improvement.

We test this by comparing the standard QA protocol against an iterative variant that adds an objective judge. Both protocols use the same model configurations, BL-CoT (Haiku
\to
Haiku
\to
Haiku) and QA (Haiku
\to
Opus
\to
Haiku), evaluated on Claude 4.5 models, with a budget of 10 binary yes/no questions each. The protocols differ in two ways:

1.

Quality thresholding:
The iterative variant adds a judge that evaluates the SLM’s answer on a 1–10 scale (mathematical soundness, calculation correctness, reasoning clarity) after each batch of 5 questions. If the score
\geq 7
, the protocol accepts the current answer and early-stops.

2.

Gold answer access:
In the standard protocol, the LLM answering questions is given the gold answer as reference. In the iterative variant, the LLM generates its own solution first, then uses it as reference for answering questions.

These two changes are confounded: the iterative variant both removes gold answer access and adds judging. However, since QA compression in practice cannot rely on gold answers, the iterative protocol represents the more realistic setting.

Block Emission Arithmetic Coding

This appendix provides detailed pseudocode for our block emission arithmetic coding scheme. The key challenge with standard arithmetic coding is that encoder and decoder must agree exactly on probability distributions. In practice, floating-point non-determinism, hardware differences, and batching effects can cause small mismatches that accumulate over long sequences, eventually causing decoding failures.

Block emission addresses this by periodically emitting the current interval midpoint whenever the range becomes too small, then restarting with a fresh
[0,1]
interval. This limits how much drift can accumulate before being “reset,” making the scheme robust to minor probability discrepancies.

F.2
Design Rationale

Block Emission.

Standard arithmetic coding maintains a single interval
[\textit{low},\textit{high}]
that narrows with each encoded symbol. When encoder and decoder probability distributions differ slightly (due to floating-point non-determinism, hardware variations, or batching effects), these small mismatches accumulate over the sequence. Block emission addresses this by emitting the interval midpoint (quantized to
B
bits) whenever the range falls below threshold
\varepsilon
, then restarting with a fresh
[0,1]
interval. This periodic reset limits how much drift can accumulate, making the scheme robust to minor probability discrepancies between encoder and decoder.

Implementation Details.

In our experiments we use
B=58
bits for each emitted midpoint and allocate additional bits for a per-block token count that records how many tokens are packed into each block. This token count is necessary for the decoder to know when one block ends and the next begins. With
b
bits for the count, each block can encode up to
2^{b}-1
tokens. The total overhead per block is therefore
B+b
bits. We find this overhead negligible in practice: blocks typically contain 15–30 tokens, so the amortized cost is roughly 3–5 additional bits per token beyond the entropy-optimal rate.

On standard benchmarks (GSM8K, MATH, GPQA, MBPP), the QA protocol causes modest regression: 0–17% of easy problems become incorrect, with most datasets below 10%. On these datasets, QA regression is consistently equal to or lower than the BL-CoT self-refinement baseline, indicating that Opus guidance does not introduce additional regression.

On frontier benchmarks (AIME and HLE), regression appears severe (69–83%), but a sanity check reveals that this is largely an artifact of Haiku’s inconsistency rather than the QA protocol. When Haiku simply re-solves these “easy” problems with no protocol at all, 59% of AIME and 83% of HLE problems regress. The QA protocol’s regression rates are comparable to this baseline, confirming that the protocol does not meaningfully increase regression. Rather, the underlying difficulty classification is unreliable for these benchmarks, where a single correct answer at baseline does not guarantee consistent reproducibility.

The following are example transcripts from the Q&A compression protocol (SLM=Haiku, LLM=Opus, Q=Haiku, Claude 4.5). For each dataset, we selected an arbitrary problem where Haiku initially answered incorrectly but produced a correct answer after 10 binary questions, with the additional constraint that the transcript contains both “Yes” and “No” responses. The “No” answers are typically the most informative, as they correct a flawed assumption or redirect the SLM’s reasoning.
