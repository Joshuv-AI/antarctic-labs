The Luna Bound Propagator for Formal Analysis of Neural Networks
Henry LeCates, Haoze Wu

Abstract
The parameterized CROWN analysis, a.k.a., α \alpha -CROWN, has emerged as a practically successful bound propagation method for neural network verification. However, existing implementations of α \alpha -CROWN are limited to Python, which complicates integration into existing DNN verifiers and long-term production-level systems. We introduce Luna , a new bound propagator implemented in C++. Luna supports Interval Bound Propagation, the CROWN analysis, and the α \alpha -CROWN analysis over a general computational graph. We describe the architecture of Luna and show that it is competitive with the state-of-the-art α \alpha -CROWN implementation in terms of both bound tightness and computational efficiency on benchmarks from VNN-COMP 2025.

Preliminaries on Bound Propagation

Let
f:\mathbb{R}^{n}\to\mathbb{R}^{m}
be a feedforward neural network.
Given vectors
\ell,u\in\mathbb{R}^{n}
, define the input box

\mathcal{X}:=\{x\in\mathbb{R}^{n}\mid\ell\leq x\leq u\}
.
The goal of bound propagation is to compute an output box

\mathcal{Y}:=\{y\in\mathbb{R}^{m}\mid a\leq y\leq b\}
,
such that
f(x)\in\mathcal{Y}
for all
x\in\mathcal{X}
.

CROWN

The CROWN analysis
[
25
]
(or equivalent the DeepPoly analysis
[
15
]
) operates by constructing affine relaxations of each nonlinear layer.
For a nonlinear layer
z^{\prime}=\sigma(z)
where
z\in[\ell,u]
,
it builds affine functions
h_{L}(z)
and
h_{U}(z)
such that

h_{L}(z)\leq\sigma(z)\leq h_{U}(z)\text{ for all }z\in[\ell,u]
.
By composing these affine bounds layer by layer, one obtains
global affine lower and upper bounds on the network output.
The concrete output bounds are then obtained by
concretizing the global affine bounds using the input box
\mathcal{X}
.

Parameterized CROWN (
\alpha
-CROWN)

Many nonlinearities admit multiple valid affine relaxations.
For example,
\mathrm{ReLU}(z)=\max(z,0)\geq\alpha\cdot z\text{ for all }\alpha\in[0,1]
.
Instead of fixing the relaxation,
\alpha
-CROWN
[
22
]
considers a family of
linear relaxations parameterized by a variable
\alpha
.
This induces parameterized global bounds

L(x,\alpha)\leq f(x)\leq U(x,\alpha)
where
L(x,\alpha)
and
U(x,\alpha)
are affine in
x
for fixed
\alpha
.
The choice of
\alpha
is then optimized (once for lower bound and once for upper bound) by solving

\max_{\alpha\in\mathcal{A}}\;\min_{x\in\mathcal{X}}L(x,\alpha),\qquad\min_{\alpha\in\mathcal{A}}\;\max_{x\in\mathcal{X}}U(x,\alpha),

where
\mathcal{A}
represents the valid ranges of
\alpha
(e.g.,
[0,1]
for ReLU lower bound). In practice, this nonconvex optimization problem is solved using projected gradient descent
[
11
]
over
\alpha
.

3.1
Bounded Model

Luna
parses the inputs and convert them into (i) a bound-aware computational graph on top of the Torch Deep Learning Library
[
13
]
, (ii) an input domain with element wise lower and upper bounds, and (iii) a set of linear output constraints in the form
\mathbf{C}\mathbf{y}\leq\mathbf{t}
. These three components constitute the Bounded Model, which is an internal representation of the verification problem shared by all analysis routines. App.
0.A.1
provides implementation details on parsing.

The computational graph is a directed acyclic graph whose nodes correspond to layer operations. For each node, three types of bounds are recorded: concrete bounds from interval arithmetic (IBP), linear relaxations from CROWN, and optimized bounds from
\alpha
-CROWN.
The specification matrix
C
represents a collection of linear constraints on the neural network output, which can be viewed as an additional layer following the output layer. During bound propagation,
Luna
treats this additional layer as the actual output layer and seeks to bound its output. For example, for an output constraint
y_{1}\leq y_{2}
,
Luna
seeks to bound the value of an auxiliary variable
a=y_{1}-y_{2}
.

Bounded Node Modules

Each node in the computational graph is associated with a Bounded Node module, which implements operator-specific bound computation. Two types of propagation are implemented: 1) Interval Bound Prorogation (IBP), which is executed before the CROWN and
\alpha
-CROWN analysis to obtain initial bounds on the neurons and detect stable neurons; 2) the CROWN backward propagation, which takes as input affine bounds of the output node in terms of the subsequent node, propagates them backward through the node, and outputs affine bounds of the output node in terms of the current node.

Non-linear optimizable activation nodes inherit from an intermediate base class, which registers each node with the alpha optimization manager and provides the interface for storing and retrieving per-neuron
\alpha
parameters. During backward propagation,
\alpha
is applied only for unstable neurons, while stable neurons use fixed slopes.

Each node contains metadata on its dependencies, to ensure the tightest bounds are used for relaxations. Specifically, each node maintains a list of which inputs require precomputed bounds, and whether IBP is sufficient for computing its intermediate bounds or whether a CROWN backward pass is needed.

Appendix
0.A.2
provides more implementation details on the internal graph representation and node functionality.

3.2
Bound Propagation Engine

The analysis engine forms the core of the verifier. It implements two complementary bound propagation techniques: CROWN, which performs linear relaxations via backward propagation of symbolic coefficients, and
\alpha
-CROWN with learnable relaxation parameter optimized by projected gradient descent.

CROWN

The CROWN analysis module implements linear bound propagation. CROWN processes nodes in a backward topological order, beginning from the output node. While propagating linear bounds backward, before a backward pass through a non-linear node, the engine recursively traverses the dependency graph, computing intermediate bounds for the pre-activation nodes, via separate CROWN backward pass. This lazy intermediate bound computation strategy, avoids unnecessary computation on stable neurons, while ensuring that the unstable neurons receive the tightest available input bounds, directly effecting the quality of the backward relaxation. At the end of the backward propagation process, the symbolic bounds are concretized into concrete numerical bounds.

The CROWN analysis engine also support CROWN-IBP which follows a two-phase approach. First IBP is performed, establishing the intermediate bounds. Second, a backward propagation from the output nodes occurs, using the precomputed IBP bounds as intermediate bounds in the relaxation process. This avoids the cost of running separate CROWN backward passes to tighten each intermediate node’s bounds, requiring only a single IBP forward pass followed by one CROWN backward pass from the output node. This trades bound tightness for computational efficiency. By default
Luna
’s default is standard CROWN, which triggers additional CROWN backward passes for intermediate nodes.

\alpha
-CROWN

The
\alpha
-CROWN module extends CROWN by introducing learnable slope parameters that can tighten relaxations for selected nonlinearities. It wraps the standard CROWN analysis: the underlying CROWN engine performs all bound computation, while
\alpha
-CROWN manages
\alpha
parameter storage and the optimization loop, maintaining separate parameters for lower- and upper-bound optimization. At each optimization step, we collect all gradient-enabled
\alpha
tensors and pass them to the optimizer. Each iteration re-runs the full CROWN backward pass, producing output bounds that depend on the current
\alpha
values. We optimize a simple objective, minimizing the negative sum of lower bounds (or the positive sum of upper bounds), so improving the objective directly tightens the corresponding bounds.

provides additional implementation details of the bound propagation engine.

Appendix 0.A
Architecture and Core Components

This appendix records implementation-level details that complement
Section
3
, focusing on concrete classes, entry points, and
internal data structures.

0.A.1
Input Parsing

Onnx Parser

The
OnnxToTorchParser
converts ONNX models through its main entry point,
OnnxToTorchParser::parse(path)
, which returns a fully constructed
TorchModel
. Internally,
processGraph()
builds a topologically ordered list of nodes:
(i) graph inputs become source nodes with no dependencies,
(ii) ONNX initializers (e.g., weights, biases, and other constants) become nodes that represent fixed tensors, and
(iii) each remaining ONNX operator becomes a corresponding bound-aware operator node.

Dependencies are resolved by mapping each operator’s input tensor names to previously created node indices, naturally supporting general DAG structure. For simple elementwise operators (e.g., Add and Sub), we distinguish between inputs that depend on earlier activations and inputs that are fixed constants; only the former are recorded as bound dependencies, since constant tensors do not require precomputed bounds during propagation.

Shape inference runs before node construction in a separate multi-pass process. Its goal is to attach consistent tensor dimensions to each node so that shape-sensitive operators (e.g., Reshape) can be validated and constructed reliably. The parser validates operator input counts, rejects unsupported data types, and emits operator-specific error messages for malformed graphs.

VNN-LIB Parsing

The
VnnLibInputParser
provides three entry points:

parseInputBounds(path, expectedInputSize)
for input bounds (as a

BoundedTensor
),
parseOutputConstraints(path, expectedOutputSize)
for output constraints (as an
OutputConstraintSet
), and

parseInputAndOutputConstraints(path, inputSize, outputSize)
to parse both in a single pass.

Parsing proceeds in two phases.
readVnnLibFile()
reads the file and removes comments;
tokenize()
then converts the remaining content into a stream of tokens (parentheses, operators, identifiers, and numeric literals). For input bounds, the parser reads declarations of the form
declare-const X_i Real
and extracts interval constraints from
assert
statements, handling nested conjunctions (
and
) via recursion. If an input variable is declared but not constrained, it is treated as unbounded (i.e.,
[-\infty,+\infty]
), which is conservative.

For output constraints,
parseLinearExpression()
recursively evaluates expressions over output variables
Y_{i}
and produces a sparse set of coefficient terms. Constraints are normalized to the form
Cy\leq t
;
\geq
constraints are rewritten by negating both sides. Disjunctions (
or
) are represented as multiple branches collected by
parseOutputBranch()
; verification succeeds if any branch is satisfied.

0.A.2
Bounded Model Representation

Bounded Model

After parsing, the network is stored as a computational graph with explicit dependency information in both directions: a forward map (mappings nodes to their inputs) and a reverse map (mappings nodes to their successors). These maps are constructed by
buildDependencyGraph()
and allow efficient traversal for both forward interval propagation and backward linear relaxations.

The main analysis entry point is
compute_bounds()
, which dispatches to
runCROWN()
or
runAlphaCROWN()
based on the selected method and returns a
BoundedTensor
containing the final lower and upper output bounds.

Bounded Nodes

Nonlinear activations nodes whose relaxations can be optimized (e.g.,
BoundedReLUNode
) inherit from
BoundedAlphaOptimizeNode
. These nodes create learnable slope parameters lazily: during
boundBackward()
. This allocation is only needed for unstable neurons, meaning neurons whose input bounds contain
0
; for stable neurons the ReLU behavior is fixed and no relaxation parameter is required.

To keep memory usage low, nodes store only long-lived information such as registered module parameters, shape metadata, and cached initialization values. Per-run quantities (for example, the symbolic coefficient tensors used in backward propagation) are recomputed on each backward pass, since they depend on the current input bounds and (for
\alpha
-CROWN) the current parametrized slope values.

0.A.3
Bound Propagation Engine

The analysis engine implements two complementary bound-propagation methods. CROWN constructs linear upper and lower bounds by propagating symbolic coefficients backward through the graph, while
\alpha
-CROWN tightens those bounds by optimizing learnable slope parameters for non linear activations.

CROWN

The CROWN analysis module implements linear bound propagation through a three-phase pipeline. First, fast Interval Bound Propagation (IBP) is performed via
computeIBPBounds()
, establishing initial interval bounds for all nodes in the network. The second phase,
backwardFrom(startIndex)
, executes backward propagation from a specified output node, computing linear relaxation coefficients that express the output as a linear function of earlier layers. Finally,
concretizeNode(startIndex)
transforms these symbolic bounds into concrete numerical bounds using the concretization formula.

In the standard CROWN, after the initial IBP pass, only the input node is marked as having concrete bounds. During the backward pass from the output, when a nonlinear node (e.g., ReLU) requires bounds on its inputs to compute relaxations,
checkPriorBounds()
triggers
computeIntermediateBoundsLazy()
for those inputs. This method first attempts to use IBP if the dependency chain consists only of element-wise operations (via
checkIBPIntermediate()
). If the chain contains linear layers, a separate CROWN backward pass is launched for that intermediate node to compute tighter bounds. This lazy computation strategy tightens intermediate bounds beyond IBP where beneficial, producing tighter final bounds at the cost of multiple backward passes.

For CROWN-IBP, after the initial IBP pass, all nodes are marked as having concrete bounds. The single backward pass from the output uses these precomputed IBP bounds as intermediate bounds during relaxations. No additional backward passes are triggered.

The helper
preprocessC()
transforms a specification matrix of the output constraints into the internal representation. If no specification is provided, an identity specification is constructed to bound each output dimension independently.

\alpha
-CROWN

\alpha
-CROWN stores relaxation parameters in a nested map indexed by node and specification branch, with separate parameter sets used when optimizing lower bounds versus upper bounds.
computeOptimizedBounds()
runs iterative gradient-based optimization, where each iteration re-runs CROWN with gradient tracking enabled, extracts the resulting bounds, and defines a loss that encourages tighter bounds (e.g., the negative sum of lower bounds when maximizing lower bounds, or the positive sum of upper bounds when minimizing upper bounds).

When an iteration improves the objective, the current learned slope values and the corresponding bounds are cached as the best-so-far solution. The optimizer follows the standard
zero_grad()
,
backward()
,
step()
sequence, then clips the learned slopes to a valid range (for ReLU, [0,1]). Early stopping with a configurable patience detects convergence and restores the best cached learned slope values.

0.A.4
Front End

Python API

The Python API
lunapy
exposes
TorchModel
and
BoundedTensor
via pybind11 bindings. Users can load a network, specify input bounds, and compute output bounds using a selected analysis method. In addition to direct parsing from

CLI

The CLI executable accepts an ONNX model and a VNN-LIB specification, making it suitable for automated runs and direct integration with the VNN-COMP benchmark format. Below is an example of invoking

Users select the analysis method with

,

, and
--lr-decay
, with additional toggles for optimizing lower and/or upper bounds (
--optimize-lower
/
--no-optimize-lower
,
--optimize-upper
/

) and stability-focused options such as early stopping and retaining the best iteration. For CROWN-style analysis, the configuration exposes a choice between standard CROWN and CROWN-IBP (
