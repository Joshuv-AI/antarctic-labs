Automated Expected Cost Analysis for Quantum Programs
Georg Moser, Michael Schaper

Abstract
In recent years, quantum computing has gained a substantial amount of momentum, and the capabilities of quantum devices are continually expanding and improving. Nevertheless, writing a quantum program from scratch remains tedious and error-prone work, showcasing the clear demand for automated tool support. We present 𝒬 ​ et \mathcal{Q}\texttt{et} , a fully automated static program analysis tool that yields a precise expected cost analysis of mixed classical-quantum programs . 𝒬 ​ et \mathcal{Q}\texttt{et} supports programs with advanced features like mid-circuit measurements and classical control flow. The methodology of our prototype implementation is based on a recently proposed quantum expectation transformer framework, generalising Dijkstra’s predicate transformer and Hoare logic. The prototype implementation 𝒬 ​ et \mathcal{Q}\texttt{et} is evaluated on a number of case studies taken from the literature and online references. 𝒬 ​ et \mathcal{Q}\texttt{et} is able to fully automatically infer precise upper bounds on the expected costs that previously could only be derived by tedious manual calculations.

Introduction

Quantum computing (QC) has advanced rapidly, with competing hardware technologies (ion traps, superconducting circuits, neutral atoms, optics, …) and diverse computational models (MBQC
[
34
]
, QRAM
[

, ZX-diagrams

At the software level, various programming languages and tools have emerged
[

Programmers must master quantum mechanics, algorithms, and programming languages, often without adequate debugging or verification tools, leading to frequent bugs, cf.
[
33
]
.
Consequently, developers face a steep learning curve and limited support for testing, debugging, or automated reasoning.
Automated program analysis for high-level quantum programs is critically lacking, especially for dynamic algorithms, which involve mid-circuit measurements, classical control flow and repetition.

In this context, it is important to distinguish between static analysis of functional properties and non-functional properties.
Further, it is also useful to distinguish between (static) quantum circuits and (dynamic) quantum programs with mid-circuit measurements and classical control flow.
Various tools provide verification of functional properties.
For example,

[

[
28
]

[

However, one of the primary motivations for QC is the potential for computational speed-up, making it essential to reason about non-functional properties including performance and cost of execution.
Existing resource estimation tools such as Microsoft’s

[
36
]
and Google’s
Qualtran

[

They cannot handle dynamic algorithms that leverage mid-circuit measurements.
Examples of such algorithms include

[

weak Grover search

[

This work presents
\mathcal{Q}
et
, a static program analysis tool for mixed classical-quantum programs, focusing on expected cost analysis.
The input is a program written in the
IMQ
language, an extension of Dijkstra’s Guarded Command Language with support for quantum operations and cost annotations, as formally introduced in
[
3
,
4
]
.
The output is either a sound upper bound (i.e. an arithmetic expression over input state variables) on the expected cost of executing the program or
Unknown
if the analysis fails to infer a bound.
It is important to note that the expected cost analysis of quantum programs is, in general, an undecidable problem
[
4
]
.

Figure
1
shows the
-X
program adapted from
[
12
]
, which operates on a two-qubit system (
\mathtt{q}_{1}
and
\mathtt{q}_{2}
).
The program applies a non-standard
-X
gate to the second qubit, which performs the
Pauli-
X
(i.e. the quantum
Not
gate) and negates the amplitude.
For instance, it transforms the quantum state (in Dirac notation)
\alpha\left|10\right\rangle+\beta\left|11\right\rangle
into
-\beta\left|10\right\rangle-\alpha\left|11\right\rangle
.

The program begins by applying the Hadamard gate
\mathtt{H}
to
\mathtt{q}_{1}
, which creates a superposition by transforming basis states as
H\left|0\right\rangle=\frac{1}{\sqrt{2}}(\left|0\right\rangle+\left|1\right\rangle)
and
H\left|1\right\rangle=\frac{1}{\sqrt{2}}(\left|0\right\rangle-\left|1\right\rangle)
.
Next, the controlled-NOT gate
\mathtt{CNOT}
is applied with
\mathtt{q}_{1}
as control and
\mathtt{q}_{2}
as target, which flips the target qubit if and only if the control qubit is in state
\left|1\right\rangle
, creating entanglement between the qubits.
The qubit
\mathtt{q}_{1}
is then measured.
For input state
\alpha\left|00\right\rangle+\beta\left|01\right\rangle+\gamma\left|10\right\rangle+\delta\left|11\right\rangle
the measurement yields
\left|0\right\rangle
with probability
\nicefrac{{1}}{{2}}(|\alpha+\gamma|^{2}+|\beta+\delta|^{2})
and
\left|1\right\rangle
with probability
\nicefrac{{1}}{{2}}(|\alpha-\gamma|^{2}+|\beta-\delta|^{2})
.
Measurements introduce probabilistic branching, reflecting the inherent uncertainty in quantum programming.
If the measurement result is
\left|0\right\rangle
the program enters the while loop with quantum state
\alpha\left|00\right\rangle+\beta\left|01\right\rangle
for some (normalised) amplitudes
\alpha
and
\beta
.
Then gate
\mathtt{X}
is applied to reset
\mathtt{q}_{1}
, and the sequence of
\mathtt{H}
,
\mathtt{CNOT}
, and measurement is repeated.
This loop continues until the measurement yields
\left|1\right\rangle
, at which point the desired
-X
transformation has been successfully applied to
\mathtt{q}_{2}
.
Each iteration consumes one unit of cost (via
{\color[rgb]{0.0039,0.0039,0.0039}{\mathtt{tick}}}\penalty\ 1
).
For the
{-}X
program, the total number of ticks represents the total number of loop iterations executed.
Due to the probabilistic nature of QC, we focus on the
expected
number of iterations.

\mathcal{Q}
et
fully automatically infers the tight bound
2\cdot(\nicefrac{{1}}{{2}}+a_{13}+a_{24})
on the expected cost of executing this program (here
a_{13}
and
a_{24}
are relevant real-valued expressions of the density matrix representation of the initial quantum state).
For the automated analysis of this program,
\mathcal{Q}
et
needs to reason about quantum operations, dynamic probabilistic branching due to measurements, and fixed point computation of loop semantics.
This requires a suitable abstract representation of quantum states and a sophisticated constraint generation and solving procedure.

The implementation automates the formal framework of quantum expectation transformers
[
3

4
]
and is inspired by established techniques for expected cost analysis of probabilistic programs
[
5

]
.
For automation, we introduce a
symbolic transformer
: a syntactic variant of the quantum expectation transformer that operates on symbolic term-expectations (Subsection
5.2
).
To keep analysis tractable, the transformer manipulates a partial, algebraic representation of density matrices and probabilities.
Furthermore, fixed-point computations are avoided by generating upper invariant
term constraints
for loops.
Term constraints generated during symbolic evaluation are refined to
cost constraints
(Subsection
5.3
), which have been successfully used for automation in classical and probabilistic settings
[
5
,
6
,
1
]
.
Then, cost constraints are further simplified into
polynomial constraints
(Subsection
5.4
).
Finally, polynomial constraints are reduced to
certificate constraints
amenable for
SMT
solvers (Subsection
5.5
).

The analysis algorithm is inherently iterative.
The tool decomposes the program into strongly connected components and loops and employs a bottom-up inference strategy.
Inferred certificates are fed back to the symbolic transformer and propagated until a sound bound is inferred for the entire program.
If the polynomial constraints cannot be solved, the tool either reports
Unknown
or backtracks to recover from heuristic choices.

Related Work

Azure Quantum Resource Estimator
[
36
]
and
Qualtran

[
23
]
provide hardware specific resource estimation for quantum programs.
These estimations are based on logical resources, such as the number of qubits and the number of
\tt\begin{array}[t]{@{}>{\tt}l@{}}T\end{array}
gates, which are obtained from static programs (i.e. in which control flow does not depend on measurements).
The tool
\mathcal{Q}
et
complements existing resource estimation tools by providing expected cost analysis (including logical resources) for programs with mid-circuit measurements and classical control flow.

The tools
SymQV

[
9
]
and
Silver

[
28
]
use symbolic execution to infer verification conditions and leverage
SMT
solvers.

SymQV
provides verification of quantum circuits and supports measurements but no classical control flow.

Silver
provides verification of
Silq

[
10
]
programs and supports mid-circuit measurements and classical conditions but not while loops.
Both tools focus on verification of functional properties.
This is performed by encoding symbolic program states, preconditions, and the negation of the postcondition as
SMT
constraints and proving correctness by showing that the resulting formula is unsatisfiable.
The tool
\mathcal{Q}
et
uses symbolic execution to infer input-output relations of expected cost between program locations.
However, the tool focuses on expected cost and automatically infers a suitable
witness
—a bounding function that serves as an upper invariant.
This synthesis problem is inherently more challenging and consequently the generated constraints are more complex and require advanced techniques for constraint solving.
Adding support for while loops further increases the complexity of the analysis as it requires suitable abstractions of loops.
The state representation in related tools as well as
\mathcal{Q}
et
restricts to programs with a finite number of qubits and is fundamentally exponential, while various optimisations are applied to improve scalability.
In practice,
SymQV
and
Silver
can handle larger programs which is due to the increased complexity of expected cost analysis and support for while loops in
\mathcal{Q}
et
.

AutoQ 2.0

[
12
]
(successor of
AutoQ

[
13
]
) provides automated verification of quantum programs using tree automata.
Here, the user provides pre- and postconditions for the quantum program, as well as loop invariants, which are then checked by the tool.
The tool leverages tree automata for efficient representation and manipulation of symbolic quantum states.
While the analysis is still limited to finite-dimensional state spaces, this approach scales in many examples better than the explicit symbolic representation employed in
\mathcal{Q}
et
.

QPMC

[
19
]
is a model checker for quantum programs and quantum protocols described as discrete-time Markov chains in which transitions are labelled with superoperators.
This tool focuses on the verification of quantum protocols, but also motivates verification of programs with loops.
Both tools provide automated verification of quantum programs, with mid-circuit measurements and loops.
While
\mathcal{Q}
et
targets a similar class of programs, it focuses on quantitative analysis, automatically inferring upper bounds on the expected cost.

The formal framework introduced by Avanzini et al. in
[
3
,
4
]
—dubbed
quantum expectation transformer
—
forms an extension of Dijkstra’s
predicate transformer semantics

[
17
]
and is strongly related to
Floyd-Hoare’s logic
[
24
]
for reasoning about imperative programs.
These methodologies have been generalised to the
weakest pre-expectation semantics

[
21
]
for probabilistic programs.
Kaminski et al.
[
25
,
26
]
investigate the expected runtime of probabilistic programs and introduces the
expected cost transformer
for probabilistic programs.
Liu et al.
[
29
]
employ
quantum weakest preconditions
to formally reason about expected runtime;
thereby extending earlier work
[
18
]
.
However, automation is only considered superficially.
Our automation in
\mathcal{Q}
et
employs earlier automation efforts of
[
25
]
’s runtime transformer,
namely
[
30
,
5
,
6
]
.

4.1
Mixed Classical-Quantum Programming Language

Quantum Computing.

Given a totally ordered set of qubits
Q=\{\mathtt{q}_{1},\ldots,\mathtt{q}_{n}\}
, let
\mathcal{H}_{Q}
be the
2^{n}
-dimensional Hilbert space defined by
\mathcal{H}_{Q}\triangleq\otimes_{i=1}^{n}\mathcal{H}_{\mathtt{q}_{i}}
, with
\mathcal{H}_{\mathtt{q}}=\mathbb{C}^{2}
being the vector space with computational basis
\{\left|0\right\rangle,\left|1\right\rangle\}
and
\otimes
being the tensor product.
With
\left\langle k\right|
we denote the conjugate transpose of
\left|k\right\rangle
for
k\in\{0,1\}
.
Let
\mathcal{M}(\mathcal{H}_{Q})
be the set of complex square matrices acting on the Hilbert space
\mathcal{H}_{Q}
, i.e.,
\mathcal{M}(\mathcal{H}_{Q})=\mathbb{C}^{2^{n}\times 2^{n}}
.
Given
M\in\mathcal{M}(\mathcal{H}_{Q})
,
M^{\dagger}
denotes the conjugate transpose of
M
, and
I_{2^{n}}
denotes the identity matrix over
\mathcal{M}(\mathcal{H}_{Q})
.
We will write
I
when the dimension is clear from the context.
Let
\mathfrak{D}(\mathcal{H}_{Q})\subsetneq\mathcal{M}(\mathcal{H}_{Q})
be the set of all
density operators
, i.e., positive semi-definite matrices of trace equal to
1
on
\mathcal{H}_{Q}
.
A
unitary operator

U
is a matrix in
\mathcal{M}(\mathcal{H}_{Q})
such that
UU^{\dagger}=U^{\dagger}U=I
.
We denote the application of a unitary by
\Phi_{U}\triangleq\lambda\rho.U\rho U^{\dagger}
.
Regarding measurements, for each
i
,
1\leqslant i\leqslant card(Q)
, we define
M_{k,i}\in\mathcal{M}(\mathcal{H}_{Q})
, with
k\in\{0,1\}
, by
M_{0,i}\triangleq I_{2^{i-1}}\otimes(\left|0\right\rangle\left\langle 0\right|)\otimes I_{2^{n-i}}
and
M_{1,i}\triangleq I-M_{0,i}
.
The measurement of the qubit
q_{i}
(in the computational basis) of a density matrix
\rho\in\mathfrak{D}(\mathcal{H}_{Q})
produces the classical outcome
k\in\{0,1\}
with probability
tr(M_{k,i}\rho)
.
The measurement
m_{k,i}
, is defined by

\frac{M_{k,i}\rho M_{k,i}^{\dagger}}{tr(M_{k,i}\rho)}
if
tr(M_{k,i}\rho)\neq 0

and
\frac{I}{2^{n}}
otherwise.

Syntax.

The
IMQ
programming language is an imperative mixed classical-quantum language that extends Dijkstra’s Guarded Command Language
[
17
]
with quantum features.
The classical component is largely standard, while the quantum aspects require more detailed attention.
The concrete syntax is available in Appendix
0.A.1
. Partly, the
IMQ
’s syntax was already highlighted in the motivation example above, cf. Figure
1
.
Usually we indicate the type of a variable: Boolean
\mathcal{B}
, integer
\mathcal{I}
, qubit
\mathcal{Q}
.
Program statements are either classical assignments, conditionals, sequences, loops,

quantum assignments

\overline{\mathtt{q}}^{\mathcal{Q}}\mathrel{{\color[rgb]{0.0039,0.0039,0.0039}{\mathtt{{*}{=}}}}}\mathtt{U}
,
or
measurements

\mathtt{x}^{\mathcal{B}}\mathrel{{\color[rgb]{0.0039,0.0039,0.0039}{\mathtt{=}}}}{\color[rgb]{0.0039,0.0039,0.0039}{\mathtt{meas^{\mathit{}}}}}\ \mathtt{q}^{\mathcal{Q}}
.
Furthermore, code is instrumented by
{\tt\begin{array}[t]{@{}>{\tt}l@{}}{\color[rgb]{0.0039,0.0039,0.0039}{\mathtt{tick}}}\penalty\ \mathtt{i}\end{array}}
statements to model resource cost.

Semantics.

A
program state
in
IMQ
is represented by a pair
\sigma\triangleq(s,\rho)\in\mathtt{State}
consisting of a classical state and a quantum state.

The
classical state
is modelled as a (well-typed)
store

s
, that is, a mapping from variables to values.
Let
s[\mathtt{x}:=k]
be the store obtained from
s
by updating the value assigned to
\mathtt{x}
in the map
s
.
Given a store
s
, let
\llbracket-\rrbracket^{s}
denote the interpretation, mapping expressions to values, defined in the obvious way.
For example
\llbracket\mathtt{x}\rrbracket^{s}\triangleq s(\mathtt{x})
,
\llbracket i\rrbracket^{s}\triangleq i
for
i\in\mathbb{Z}
,
\llbracket\mathtt{i}_{1}+\mathtt{i}_{2}\rrbracket^{s}\triangleq{\llbracket\mathtt{i}_{1}\rrbracket^{s}+\llbracket\mathtt{i}_{2}\rrbracket^{s}}
, etc.
The classical assignment
\mathtt{x}:=\mathtt{e}
updates the store
s
by assigning the value of expression
\mathtt{e}
to variable
\mathtt{x}
, denoted
s[\mathtt{x}:=\llbracket\mathtt{e}\rrbracket^{s}]
.

Following
[
4
]
, the
quantum state
is modelled as a density operator.
The quantum assignment
\overline{\mathtt{q}}\mathrel{{\color[rgb]{0.0039,0.0039,0.0039}{\mathtt{{*}{=}}}}}\mathtt{U}
updates the quantum state
\rho
to a new quantum state
\Phi_{U_{\overline{\mathtt{q}}}}(\rho)=U_{\overline{\mathtt{q}}}\rho U_{\overline{\mathtt{q}}}^{\dagger}
, where
U_{\overline{\mathtt{q}}}
is the unitary operator in
\mathcal{M}(\mathcal{H}_{Q})
computed by extending the quantum gate
\mathtt{U}
to the entire set of qubits
Q
.
The measurement
\mathtt{x}\mathrel{{\color[rgb]{0.0039,0.0039,0.0039}{\mathtt{=}}}}{\color[rgb]{0.0039,0.0039,0.0039}{\mathtt{meas^{\mathit{}}}}}\ \mathtt{q}_{i}
updates the state depending on the two possible outcomes,
k=0
and
k=1
:
with probability
tr(M_{k,i}\rho)
, the classical state is updated by
s[\mathtt{x}:=k]
and
the quantum state is set to
m_{k,i}(\rho)
, where
m_{k,i}(\rho)
is the (normalised) quantum state after the measurement.

We introduce the notion of expected cost and expected value informally, for a more formal treatment we refer to
[
3
]
.
The
operational semantics
can be formally expressed as a weighted relation over distributions of configurations.
Let
(\mathtt{stm},\sigma)
denote the initial configuration.
The
expected cost

\mathsf{ecost}_{\mathtt{stm}}(\sigma)
is the expected total cost accumulated over all possible execution paths of
\mathtt{stm}
starting from
\sigma
, weighted by their respective probabilities.
The
expected value

\mathsf{evalue}_{\mathtt{stm}}(f)(\sigma)
is the expected value of a given expectation function
f
over all possible terminal states reached by executing
\mathtt{stm}
from
\sigma
, weighted by their probabilities.

The
quantum expectation transformer
presented by Avanzini et al.
[
3
,
4
]
is a formal framework for reasoning about expectations of quantum programs.
This transformer is a mapping from
expectations
—real-valued functions on program states—to expectations in a continuation-passing style, formally:

\mathtt{qet}\!\left[\,\cdot\,\right]\!\left\{\textstyle f\right\}:\mathtt{Stmt}\to(\mathtt{State}\to\mathbb{R}^{+\infty})\to(\mathtt{State}\to\mathbb{R}^{+\infty})
.
The transformer is defined inductively in Figure
4
, and serves as a semantic model to express properties on expectations, including both expected cost and expected value.

For any expression
\mathtt{e}
,
\llbracket\mathtt{e}\rrbracket
is a shorthand notation for the function
\lambda(s,\rho).\llbracket\mathtt{e}\rrbracket^{s}\in\mathtt{State}\to\mathbb{R}^{+\infty}
.
We also use
f[\mathtt{x}:=\mathtt{e}]
for the expectation
\lambda(s,\rho).f(s[\mathtt{x}:=\llbracket\mathtt{e}\rrbracket^{s}],\rho)
.
For a given map
\chi:\mathfrak{D}(\mathcal{H}_{Q})\to\mathfrak{D}(\mathcal{H}_{Q})
, we define
f[\chi]\triangleq\lambda(s,\rho).f(s,\chi(\rho))
.
We group such state modifications, for instance,
f[\mathtt{x}:=\mathtt{e}\text{; }\chi]
stands for
(f[\mathtt{x}:=\mathtt{e}])[\chi]

and
f[\mathtt{x}:=\mathtt{e},\mathtt{y}:=\mathtt{e}^{\prime}]
stands for
(f[\mathtt{x}:=\mathtt{e}])[\mathtt{y}:=\mathtt{e}^{\prime}]
.
For
p\in\mathtt{State}\to[0,1]
and
f,g\in\mathtt{State}\to\mathbb{R}^{+\infty}
,
f\mathrel{{+}_{p}}g
denotes the
function
\lambda\sigma.p(\sigma)\cdot f(\sigma)+(1-p(\sigma))\cdot g(\sigma)\in\mathtt{State}\to\mathbb{R}^{+\infty}
,
similar we use
f\cdot g
to denote
\lambda\sigma.f(\sigma)\cdot g(\sigma)\in\mathtt{State}\to\mathbb{R}^{+\infty}
.
Thus, for instance,
f[\mathtt{x}:=\mathtt{x}+1]+_{\llbracket\mathtt{x}=1\rrbracket}f
behaves like
f
, except that
\mathtt{x}
is first incremented when applied to states
with classical variable
\mathtt{x}
equal to
1
.
In correspondence to the normalisation of quantum state
m_{k,i}
, we define probabilities
p_{k,i}\triangleq\lambda\rho.tr(M_{k,i}\rho M_{k,i}^{\dagger})
.
We overload this function from
\mathfrak{D}(\mathcal{H}_{Q})
to
\mathtt{State}
so that
p_{k,i}(s,\rho)=p_{k,i}(\rho)
.
In this way,
f[\mathtt{x}:=0\text{; }m_{0,i}]\mathrel{{+}_{p_{0,i}}}f[\mathtt{x}:=1\text{; }m_{1,i}]

computes the expected value of
f
on the distribution of states obtained by measuring the
i
-th qubit and
assigning the outcome to classical variable
\mathtt{x}
.
In the case of loops, the least fixed point
\mathsf{lfp}
is defined with respect to the pointwise ordering on the function space
\mathtt{State}\to\mathbb{R}^{+\infty}
.

Next, we provide key concepts for automating the expected cost analysis of quantum programs.
Let
\mathsf{CostFree}(\mathtt{stm})
replace
{\tt\begin{array}[t]{@{}>{\tt}l@{}}{\color[rgb]{0.0039,0.0039,0.0039}{\mathtt{tick}}}\penalty\ \mathtt{i}\end{array}}
with
{\tt\begin{array}[t]{@{}>{\tt}l@{}}{\color[rgb]{0.0039,0.0039,0.0039}{\mathtt{skip}}}\end{array}}
in
\mathtt{stm}
.
The
quantum expectation cost transformer
and the
quantum expectation value transformer
are:

\mathtt{qect}\!\left[\,\mathtt{stm}\,\right]\!\left\{\textstyle f\right\}\triangleq\mathtt{qet}\!\left[\,\mathtt{stm}\,\right]\!\left\{\textstyle f\right\}\quad\mathtt{qevt}\!\left[\,\mathtt{stm}\,\right]\!\left\{\textstyle f\right\}\triangleq\mathtt{qet}\!\left[\,\mathsf{CostFree(\mathtt{stm})}\,\right]\!\left\{\textstyle f\right\}\hbox to0.0pt{$\;$.\hss}

Proposition 1

For all statements
\mathtt{stm}\in\mathtt{Stmt}
and expectations
f:(\mathtt{State}\to\mathbb{R}^{+\infty})
:

\mathtt{qect}\!\left[\,\mathtt{stm}\,\right]\!\left\{\textstyle\lambda\_.0\right\}=\mathsf{ecost}_{\mathtt{stm}}\quad\mathtt{qevt}\!\left[\,\mathtt{stm}\,\right]\!\left\{\textstyle f\right\}=\mathsf{evalue}_{\mathtt{stm}}(f)\hbox to0.0pt{$\;$.\hss}

Proposition
1
has been stated and proved originally in
[
3
]
.
Crucially, it is enough to focus on the quantum expectation transformer to reason about both the expected cost and the expected value of quantum programs.
Figure
5
depicts a couple of useful laws, which have been stated and proved in
[
3
]
.
We denote by
\geq
also the pointwise extension of the order from
\mathbb{R}^{+\infty}
to functions, that is,

f\geq g
holds iff
\forall\sigma\in\mathtt{State},\ f(\sigma)\geq g(\sigma)
.
The
Law permits us to reason modulo upper bounds—actual expectations can be always substituted by upper bounds.
The
Law constitutes a generalisation of the notion of invariant stemming from Hoare calculus.
It is used to find closed-form upper bounds
g
to expectations
f
of loops and is central to our approach for automating the cost analysis of quantum programs.
The
Law allows us to decompose the expected cost analysis into an expected cost and an expected value analysis.
This modularity is crucial for automation, especially when dealing with complex loop structures and larger quantum programs.
We emphasise that the composability of the semantic expectation transformer (see Figure
4
) is essential here.

In this work, we apply and abstract the density operator formalism.
Selinger
[
35
]
motivates the density operator representation in his seminal work on quantum programming languages:
(i) frequently allows for simpler mathematical expressions,
(ii) has a unique representation of pure states, and
(iii) provides an efficient representation of mixed states.
For automation, we introduce a syntactic expectation transformer (see Figure
6
).
Our initial observations confirmed remark (i), and ambiguity in (ii) may introduce unnecessary complexity when working with symbolic expressions.
Therefore, we have chosen to use density operators.
However, in line with
[
3
,
4
]
, semantics are defined via distributions over density operators rather than mixed state representations.

5
Automation

In this section, we present the main contribution of this work and discuss the implementation of
\mathcal{Q}
et
, an automated expected cost analysis tool for mixed classical-quantum programs written in
IMQ
.
Refer back to Figure
2
for a schematic overview.
For automation, we introduce a syntactic variant

\mathtt{qinf}\!\left[\,\mathtt{stm}\,\right]\!\left\{\textstyle f\right\}
(see Figure
6
) of the expectation transformer

\mathtt{qet}\!\left[\,\mathtt{stm}\,\right]\!\left\{\textstyle f\right\}
(see Figure
4
) to infer constraints on symbolic expressions.
Crucially, its interpretation forms an upper bound
\llbracket\mathtt{qinf}\!\left[\,\mathtt{stm}\,\right]\!\left\{\textstyle f\right\}\rrbracket\geq\mathtt{qet}\!\left[\,\mathtt{stm}\,\right]\!\left\{\textstyle\llbracket f\rrbracket\right\}
.
For loop-free code,
\mathtt{qinf}\!\left[\,\mathtt{stm}\,\right]\!\left\{\textstyle f\right\}
performs symbolic evaluation on a symbolic state representation to form input-output relations.
For while statements, we apply law
to infer term constraints:

\mathtt{b}\vdash G\geq\mathtt{qinf}\!\left[\,{\color[rgb]{0.0039,0.0039,0.0039}{\mathtt{while^{\mathit{}}}}}\ \mathtt{b}\ {\color[rgb]{0.0039,0.0039,0.0039}{\mathtt{do}}}\ \mathtt{stm}\,\right]\!\left\{\textstyle G\right\}\qquad\neg\mathtt{b}\vdash G\geq F\hbox to0.0pt{$\;$.\hss}

Here
G
and
F
represent unknown expectations.
To resolve the inequalities resulting from while statements, we provide a set of inference rules to reduce inequality constraints over expectations to inequality constraints over cost expressions (see Subsection
5.3
).
These constraints are then further reduced to inequality constraints over polynomial expressions with unknown coefficients (see Subsection
5.4
).
Finally, we use known approaches to synthesise certificates for the polynomial constraints, resulting in upper invariants for while statements (see Subsection
5.5
).
Given that, a bottom-up strategy can be implemented to infer upper invariants for loops and propagate the result (see Subsection
5.6
).

5.1
Symbolic Representation

In this subsection, we introduce the symbolic representation that underpins our approach to the automated inference.

Quantum states.

Recall that an expectation is a function from program states
(s,\rho)
to non-negative real numbers.
To ease the representation of expectations within the automation, we model complex numbers as pairs
(a,b)
of real numbers, where
a
is the real part and
b
is the imaginary part.
Since
\rho
is a density matrix, the matrix is Hermitian, that is,
\rho=\rho^{\dagger}
.
The diagonal elements are constrained by
a_{ii}\in\mathbb{R}
,
a_{ii}\geqslant 0
,
\sum_{i=1}^{n}a_{ii}=1
and
b_{ii}=0
.
The off-diagonal elements are constrained by
a_{ij}\in\mathbb{R}
and
b_{ij}\in\mathbb{R}
,
a_{ij}=a_{ji}
and
b_{ij}=-b_{ji}
, for
i\neq j
.
Due to the symmetry we restrict off-diagonal elements to
a_{ij}
and
b_{ij}
with
i<j
.
Given a program acting on the Hilbert space
\mathbb{C}^{m}\times\mathbb{C}^{m}
for
m=2^{n}
, we fix the set of
density matrix variables
by

d_{i}
for diagonal elements and
a_{ij},b_{ij}
for
1\leqslant i<j\leqslant m
for off-diagonal elements.
In what follows, let
\smash{\rho_{in}^{\scriptscriptstyle\sharp}}
denote the symbolic density matrix:

\smash{\rho_{in}^{\scriptscriptstyle\sharp}}\triangleq\begin{pmatrix}(d_{1},0)&(a_{12},b_{12})&\cdots&(a_{1m},b_{1m})\\
(a_{12},-b_{12})&(d_{2},0)&\cdots&(a_{2m},b_{2m})\\
\vdots&\vdots&\ddots&\vdots\\
(a_{1m},-b_{1m})&(a_{2m},-b_{2m})&\cdots&(d_{m},0)\end{pmatrix}

Arithmetic expressions.

We restrict the set of applicable gates to the (approximative) universal set of
Clifford+T
gates, cf.
[
31
]
.
Further, we include gates that can be derived such as
{\tt\begin{array}[t]{@{}>{\tt}l@{}}CCNOT\end{array}}
.
This restriction is not a limitation of the transformer framework, but rather a design choice to restrict the form of symbolic expressions.
The most complex gate in terms of representation is the
{\tt\begin{array}[t]{@{}>{\tt}l@{}}T\end{array}}
gate:

{\tt\begin{array}[t]{@{}>{\tt}l@{}}T\end{array}}\triangleq\begin{pmatrix}1&0\\
0&\frac{1+i}{\sqrt{2}}\end{pmatrix}\triangleq\begin{pmatrix}(1,0)&(0,0)\\
(0,0)&(\frac{1}{\sqrt{2}},\frac{1}{\sqrt{2}})\end{pmatrix}

Taking matrix multiplication and state normalisation into account,
we represent arithmetic expressions, denoted as
\mathcal{A}\mathtt{Exp}
, over the set of matrix and integer variables by:

\nicefrac{{e}}{{f}}\text{\;, $e$ and $f$ are polynomial expressions with coefficients in $\mathbb{Z}[\sqrt{2}]$}
.

Quantum operations.

Next, we provide a symbolic representation of quantum operations as parallel updates.
Let
f
denote an operator from density matrices to density matrices
\rho^{\prime}=f(\rho)
.
In particular, set
f(\rho)=U\rho U^{\dagger}
for any unitary
U
and

f(\rho)=m_{k,i}(\rho)
for any post-measurement operator
m_{k,i}
.
We define the application of
f
as an element-wise mapping from matrix variables to the upper triangle elements of
\smash{\rho^{\scriptscriptstyle\sharp}}^{\prime}=f(\smash{\rho^{\scriptscriptstyle\sharp}})
,
such that
d_{i}
maps to
\mathsf{Real}(\smash{\rho_{ii}^{\scriptscriptstyle\sharp}}^{\prime})
,
a_{ij}
maps to
\mathsf{Real}(\smash{\rho_{ij}^{\scriptscriptstyle\sharp}}^{\prime})
and
b_{ij}
maps to
\mathsf{Imag}(\smash{\rho_{ij}^{\scriptscriptstyle\sharp}}^{\prime})
.
For the rest of the paper we denote the update mapping induced by
\smash{\rho^{\scriptscriptstyle\sharp}}^{\prime}=f(\smash{\rho^{\scriptscriptstyle\sharp}})
as
\{\overline{\mathtt{q}}\mapsto f(\smash{\rho^{\scriptscriptstyle\sharp}})\}
.

Example 1

Consider the application of the Hadamard gate
{\tt\begin{array}[t]{@{}>{\tt}l@{}}H\end{array}}
to a one-qubit system with symbolic density matrix
\smash{\rho_{in}^{\scriptscriptstyle\sharp}}
.

\displaystyle\smash{\rho_{in}^{\scriptscriptstyle\sharp}}\triangleq\begin{pmatrix}(d_{1},0)&(a_{12},b_{12})\\
(a_{12},-b_{12})&(d_{2},0)\end{pmatrix}\qquad{\tt\begin{array}[t]{@{}>{\tt}l@{}}H\end{array}}\triangleq\frac{1}{\sqrt{2}}\begin{pmatrix}(1,0)&(1,0)\\
(1,0)&(-1,0)\end{pmatrix}

\displaystyle H\smash{\rho_{in}^{\scriptscriptstyle\sharp}}H^{\dagger}=\frac{1}{2}\begin{pmatrix}(d_{1}+d_{2}+2a_{12},0)&(d_{1}-d_{2},-2b_{12})\\
(d_{1}-d_{2},2b_{12})&(d_{1}+d_{2}-2a_{12},0)\end{pmatrix}

The inferred update mapping
\{\overline{\mathtt{q}}\mapsto H\smash{\rho_{in}^{\scriptscriptstyle\sharp}}H^{\dagger}\}
of this matrix operation is:

d_{1}\mapsto\tfrac{1}{2}(d_{1}+d_{2}+2a_{12})\quad d_{2}\mapsto\tfrac{1}{2}(d_{1}+d_{2}-2a_{12})\quad a_{12}\mapsto\tfrac{1}{2}(d_{1}-d_{2})\quad b_{12}\mapsto-b_{12}

Symbolic State.

In the constraint inference, symbolic states are used to generate input-output relations between control flow locations.
Let
\mathcal{V}
denote the set of program variables and density matrix variables.
Adapting the notion of quantum program states of Section
4
,
we define a symbolic state
\smash{\mathtt{\sigma}^{\scriptscriptstyle\sharp}}
as a partial store

\smash{\mathtt{\sigma}^{\scriptscriptstyle\sharp}}\mathrel{\mathop{:}}\mathcal{V}\rightharpoonup\mathtt{Exp}

from variables to expressions.
Let
\smash{\mathtt{\sigma}^{\scriptscriptstyle\sharp}}\in\smash{\mathtt{State}^{\scriptscriptstyle\sharp}}
denote a symbolic state.
We define the substitution
\smash{\mathtt{\sigma}^{\scriptscriptstyle\sharp}}\{\mathtt{x}\mapsto\mathtt{e}\}
as the symbolic state obtained by substituting every occurrence of
\mathtt{x}
in expressions of
\smash{\mathtt{\sigma}^{\scriptscriptstyle\sharp}}
with
\mathtt{e}
.
Formally, for all variables
y\in dom(\smash{\mathtt{\sigma}^{\scriptscriptstyle\sharp}})
,

\big(\smash{\mathtt{\sigma}^{\scriptscriptstyle\sharp}}\{\mathtt{x}\mapsto\mathtt{e}\}\big)(y)\triangleq\smash{\mathtt{\sigma}^{\scriptscriptstyle\sharp}}(y)\{\mathtt{x}\mapsto\mathtt{e}\}
.
Let
\mathcal{V}^{\prime}\subseteq\mathcal{V}
be a subset of variables.
The initial symbolic state
\smash{\mathtt{\sigma}_{in}^{\scriptscriptstyle\sharp}}
maps every variable
\mathtt{x}{}\in\mathcal{V}^{\prime}
to itself.

\mathcal{Q}
et
implements a heuristic-driven approach in which often only a subset of variables is tracked in symbolic states, such as, a small set of diagonal/off-diagonal entries.
This greatly reduces expression size and improves scalability.

Context.

The inference system generates constraints of the form
\phi\vdash e\geq f
.
Here
\phi
is a Boolean formula that reflects refinements due to control flow and assumptions in expectation expressions.
This includes inequalities over arithmetic expressions and statements about probabilities.
The latter is used for case distinction in post-measurement operations.
The probability expression
\mathtt{a}\in\mathcal{A}\mathtt{Exp}

evaluates to one
\mathsf{P}_{1}(\mathtt{a})
, or strictly between zero and one
\mathsf{P}_{(0,1)}(\mathtt{a})
.
Furthermore, we set
\neg\mathsf{P}_{1}(\mathtt{a})=\neg\mathsf{P}_{(0,1)}(\mathtt{a})=\bot
.

To decide whether
\phi\vdash e\geq f
holds we make use of additional assumptions that arise from the fact that a quantum state is a density matrix.
We typically keep these constraints implicit if not important.
Further constraints could be imposed.
For instance,
\rho=\rho^{2}
restricts to pure quantum states.
However, we deliberately relax the constraints imposed on quantum states for automation.

Cost Expressions.

A cost expectation is a function from program states to non-negative real numbers.
For automation, we introduce a class of bounding functions, dubbed
cost expressions
(cf.
[
1
,
5

6
]
).
Let
\mathsf{p}_{i}
(probability) and
\mathsf{w}_{i}
(weight) denote arithmetic expressions that evaluate into the non-negative reals.
We introduce cost expressions syntactically as linear combination of norms:

\textstyle\mathsf{Norm}\ni\mathtt{n}\mathrel{\mathop{::=}}[\phi]\cdot\mathtt{a}\qquad\mathcal{C}\mathtt{Exp}\ni\mathtt{c}\mathrel{\mathop{::=}}\sum_{i}\mathsf{p}_{i}\cdot\mathsf{w}_{i}\cdot\mathtt{n}_{i}

A norm is a guarded arithmetic expression
[\phi]\cdot\mathtt{a}
that evaluates to
\mathtt{a}
if
\phi
holds, and
0
otherwise.
We require that
\mathtt{a}
is always non-negative in the given context.
In
\mathcal{Q}
et
, norms are chosen via heuristics and have the form
[\mathtt{a}\mathrel{\geqslant}0]\cdot\mathtt{a}\triangleq\mathsf{max}(\mathtt{a},0)
.
Cost expressions are closed under addition and scalar multiplication with expressions that evaluate to a non-negative number (like probabilities).
We set

[\phi]\cdot(\sum_{i}\mathsf{p}_{i}\cdot\mathsf{w}_{i}\cdot([\phi_{i}]\cdot\mathtt{a}_{i}))\triangleq\sum_{i}\mathsf{p}_{i}\cdot\mathsf{w}_{i}\cdot([\phi\wedge\phi_{i}]\cdot\mathtt{a}_{i})
.

Expectation Terms.

The term structure and the term interpretation are chosen such that they reflect the operations of the expectation transformer.
Further, terms include unknown expectations and cost expressions.

\displaystyle\mathtt{Term}\ni\mathtt{t}_{1},\mathtt{t}_{2}

\displaystyle\mathrel{\mathop{::=}}\mathsf{Fun}\penalty\ \ell\penalty\ \smash{\mathtt{\sigma}^{\scriptscriptstyle\sharp}}\mathrel{\mathop{|}}\mathsf{Cost}\penalty\ \mathtt{c}\mathrel{\mathop{|}}\mathsf{Tick}\penalty\ \mathtt{i}\penalty\ \mathtt{t}\mathrel{\mathop{|}}\mathsf{Ite}\penalty\ \mathtt{b}\penalty\ \mathtt{t}_{1}\penalty\ \mathtt{t}_{2}\mathrel{\mathop{|}}\mathsf{Meas}\penalty\ (\mathtt{a}_{1},\mathtt{t}_{1})\penalty\ (\mathtt{a}_{2},\mathtt{t}_{2})

The term
\mathsf{Fun}\penalty\ \ell\penalty\ \smash{\mathtt{\sigma}^{\scriptscriptstyle\sharp}}
represents an unknown expectation for some while command with location
\ell
.
This is used to form the upper invariant constraints for while statements.
All other terms reflect different operations of the expectation transformer.
For example
\mathsf{Meas}\penalty\ (\mathtt{a}_{1},\mathtt{t}_{1})\penalty\ (\mathtt{a}_{2},\mathtt{t}_{2})
indicates a measurement operation with two outcomes.
With probability
\mathtt{a}_{1}
(
\mathtt{a}_{2}
) the classical outcome of the measurement is
0
(
1
) and
\mathtt{t}_{1}
(
\mathtt{t}_{2}
) is the resulting expectation taking the respective post-measurement state into account.
Let
\alpha\mathrel{\mathop{:}}\mathsf{EFun}\to\smash{\mathtt{State}^{\scriptscriptstyle\sharp}}\to\mathcal{C}\mathtt{Exp}
be an assignment of cost expectation expressions to function symbols
\mathsf{EFun}
.
The interpretation of expectation terms under
\alpha
is defined in the obvious way.
For example

\llbracket\mathsf{Fun}\penalty\ \ell\penalty\ \smash{\mathtt{\sigma}^{\scriptscriptstyle\sharp}}\rrbracket^{\alpha}=\llbracket\alpha(\ell)(\smash{\mathtt{\sigma}^{\scriptscriptstyle\sharp}})\rrbracket
,

\llbracket\mathsf{Ite}\penalty\ \mathtt{b}\penalty\ \mathtt{t}_{1}\penalty\ \mathtt{t}_{2}\rrbracket^{\alpha}=\llbracket\mathtt{t}_{1}\rrbracket^{\alpha}(\mathtt{\sigma})
if
\llbracket\mathtt{b}\rrbracket(\mathtt{\sigma})
and
\llbracket\mathtt{t}_{2}\rrbracket^{\alpha}(\mathtt{\sigma})
otherwise, etc.

In
[
6
]
constraints are directly formed over cost expressions. This makes the representation more succinct.
In
\mathcal{Q}
et
the term structure is used as an intermediate representation, which is useful for automation as it simplifies tracking necessary case distinctions in measurements and allows for useful simplifications.
For brevity, we omit these simplifications here and refer to Appendix
0.A.4
.

5.2
Inference of Expectation Term Constraints

The syntactic variant of the expectation transformer is depicted in Figure
6
.
For while statements an unknown expectation
\mathsf{Fun}\penalty\ \ell\penalty\ \smash{\mathtt{\sigma}_{in}^{\scriptscriptstyle\sharp}}
is introduced.
The location symbol
\ell
is a fresh symbol that represents the location of the loop statement.
The initial symbolic state
\smash{\mathtt{\sigma}_{in}^{\scriptscriptstyle\sharp}}
is the identity mapping for some subset of variables
\mathcal{V}^{\prime}\subseteq\mathcal{V}
and represents program states before evaluating the loop condition.
Further, side-conditions are introduced to form the constraints for the upper invariant.
For measurements both outcomes are considered.
The term
p_{k,i}(\smash{\rho_{in}^{\scriptscriptstyle\sharp}})
for
k\in\{0,1\}
is the probability expression obtained by
p_{k,i}
applied to the symbolic state
\smash{\rho_{in}^{\scriptscriptstyle\sharp}}
.
On the other hand,
\mathtt{t}\{\mathtt{x}\mapsto k\text{\color[rgb]{0.0039,0.0039,0.0039}{;}}\ {}\overline{\mathtt{q}}\mapsto m_{k,i}(\smash{\rho_{in}^{\scriptscriptstyle\sharp}})\}
performs the update to represent the state after the measurement.
Similarly,
\mathtt{t}\{\overline{\mathtt{q}}\mapsto U\smash{\rho_{in}^{\scriptscriptstyle\sharp}}U^{\dagger}\}
performs the update to take the unitary operation into account.
We arrive at our main theoretical contribution, the soundness of the
inference algorithm with the proof in the Appendix
Proof
. In conjunction with Proposition
1
this implies the soundness of
the expected cost analysis provided.

Theorem 5.1
(Soundness Theorem)

Let
\mathtt{stm}
be a program,
f
be a cost expression, and
\alpha
be an assignment.
Then

\llbracket\mathtt{qinf}\!\left[\,\mathtt{stm}\,\right]\!\left\{\textstyle f\right\}\rrbracket^{\alpha}\geq\mathtt{qet}\!\left[\,\mathtt{stm}\,\right]\!\left\{\textstyle\llbracket f\rrbracket^{\alpha}\right\}
, if all side-conditions are met.

5.3
Inference of Expectation Cost Constraints

Let
\mathtt{stm}
be a program.
Then
\mathtt{qinf}\!\left[\,\mathtt{stm}\,\right]\!\left\{\textstyle\mathtt{t}\right\}
returns a set of constraints
\phi\vdash e\geq f
over terms.
Figure
7
provides a set of inference rules to reduce term constraints to cost constraints.
By construction, the left-hand side of the term constraints is always of the form
\mathsf{Fun}\penalty\ \ell\penalty\ \smash{\mathtt{\sigma}_{in}^{\scriptscriptstyle\sharp}}
,
and besides
[FunL]
, all other rules eliminate the term structure of the right-hand side such that all obligations eventually form cost constraints.
Rules affecting the right-hand side can be applied in sub-terms.
For clarity, the term context is omitted in the inference and a meta rule
[Context]
is added.
Further, the inference rule
[CostFree]
voids the cost expressions to implement the expected value transformer
\mathtt{qevt}\!\left[\,\mathtt{stm}\,\right]\!\left\{\textstyle f\right\}
.

\phi\vdash e\geq C[f]\psi\quad\phi\wedge\phi_{i}\vdash e\geq C[t_{i}]\qquad\phi\vdash e\geq\mathsf{Tick}\penalty\ \mathtt{i}\penalty\ \mathtt{c}\penalty\ \mathtt{t}\phi\vdash\mathtt{t}

This set of inference rules transforms term expectation constraints to cost expectation constraints.
Most rules are self-explanatory.
Recall that cost expressions are closed under addition and scalar multiplication (with a non-negative expression).
The inference rule
[Meas]
performs a case distinction on the probability expression.
The inference rule
[MeasP]
resolves the case distinction for measurements if we can infer that the probabilities are non-zero.

Well-definedness.

The symbolic state is well-defined.
The case distinction by
[MeasP]
ensures that the probabilities and the denominators are non-zero.
For cost expressions, we restrict the form of the templates such that the denominator of norms is
1
:
[\mathtt{b}\wedge e/1\mathrel{\geqslant}0]\cdot e/1
.
Therefore, the instantiation of a norm with a symbolic state is well-defined.
Additionally, cost expressions include scaling by non-negative factors and probabilities.

5.5
Inference of Certificate Constraints

The tool reduces upper invariant constraints to polynomial inequalities.
We use an incomplete characterisation of non-negative polynomials based on Handelmann’s Theorem
[
22
]
—and related work on the Positivstellensatz.
This is a commonly used approach for the synthesis of ranking functions (cf.
[
16
,
11
,
5
]
).
First, inequality constraints are transformed using standard equalities into the following form:

\bigwedge p_{i}\geq 0\wedge\bigwedge p_{j}>0\implies p\geq 0
.
Then, constraints for a certificate of non-negativity of
p
are generated.
Here, a certificate is a combination of non-negative polynomials using operations that preserve non-negativity.
The tool uses a non-linear combination of non-negative polynomials from the premise, weighted by non-negative coefficients
c_{i}
with some chosen maximal degree
n
:

C_{n}\triangleq\sum_{i=(i_{1},\ldots,i_{m})\in[0,n]^{m}}c_{i}\prod p_{1}^{i_{1}}\cdots p_{m}^{i_{m}}
.
Then, equality of the generated certificate
C_{n}
and polynomial
p
is checked by comparison of coefficients.
These equality constraints can be expressed by quantifier free non-linear formulae in
QF_NRA
theory.
By default,
\mathcal{Q}
et
uses the
Z3
solver
3

https://github.com/Z3Prover/z3
.

5.6
Algorithm

Recall Figure
2
depicting the workflow of
\mathcal{Q}
et
.
The main algorithm leverages the structure of the transformer framework and implements a
modular bottom-up
analysis.
As outlined, the algorithm alternates between symbolic execution to infer constraints for upper invariants and constraint solving propagating inferred cost expressions through the program structure.
Strongly connected components (SCCs) of the control flow graph are analysed separately, assuming that the cost expressions for the continuation are already inferred.
Additionally, the
law is employed to inspect (nested) loops independently.

A key aspect of the approach is the use of
templates
for cost expressions during constraint generation.
Templates are syntactic forms for candidate invariants and are instantiated with unknown coefficients to be solved for.
They are typically constructed from the guards of loops and the cost of the continuation, capturing relevant program variables and symbolic state components.
Standard templates include linear forms, mixed-linear and non-linear forms.
In the running example, as shown in Example
3
, a linear template is used.
The pseudocode of the algorithm is provided in Appendix
0.A.5
.

6
Conclusion and Future Work

In this work, we have presented the first—to the best of our knowledge—implementation of a recently proposed weakest pre-expectation semantics for mixed classical-quantum programs, cf.
[
3
,
4
]
.
This transformer amounts to a formal framework for the analysis of runtime and costs of quantum programs in expectation.
Our tool
\mathcal{Q}\texttt{et}
is able to fully automatically infer precise upper bounds on the expected cost of quantum programs, like
repeat-until-success
circuits
that feature classical control flow as well as non-trivial features like mid-circuit measurements.

We provide ample experimental evidence of the viability of the prototype implementation.
We emphasise that all quantum programs in our benchmark require a high-level
encoding as a mixed classical-quantum programming language and are not expressible as sole quantum circuits. For almost all cases our tool can fully automatically
derive an expected cost analysis that, so far, could only be obtained manually.

Arguably the biggest challenge to overcome in a verification framework for quantum programs is scalability and improved viability. In our opinion, the best way to tackle this challenge lies in

(i)

the development of suitable abstract state representations and

(ii)

restricting the program to specific classes of high-level quantum programs.

This will be subject to future work.

We observe that even for small programs, reasoning about program properties by hand becomes tedious and is prone to errors.
The quantum state space grows exponentially with the number of qubits, and elementary quantum operations—including application of unitaries and measurements—may affect the state in non-trivial ways.
This requires careful computations with amplitudes and probabilities.
As a result, manual analysis quickly becomes infeasible for realistic programs.
This motivates the need for computer-aided tools to automate the analysis and verification of quantum programs.

Quantum expectation transformer

The
quantum expectation transformer
presented by
[
3
,
4
]
is a formal framework for reasoning about expectations of quantum programs and constitutes our basis for automating the expected cost analysis. This quantum expectation transformer is a mapping from expectations—real-valued functions on program states—to expectations in a continuation-passing style:

\mathtt{qet}\!\left[\,\cdot\,\right]\!\left\{\textstyle f\right\}:\mathtt{Stmt}\to(\mathtt{State}\to\mathbb{R}^{+\infty})\to(\mathtt{State}\to\mathbb{R}^{+\infty})
.
With this framework, it is possible to reason about different program properties including invariants and resource consumption.
This depends on how cost annotations (i.e.
{\color[rgb]{0.0039,0.0039,0.0039}{\mathtt{tick}}}\penalty\ \mathtt{i}
statements) are interpreted and how continuations
f
are defined.

First, let us assume that cost annotations are ignored, that is
\mathtt{qet}\!\left[\,{\color[rgb]{0.0039,0.0039,0.0039}{\mathtt{tick}}}\penalty\ \mathtt{i}\,\right]\!\left\{\textstyle f\right\}(\sigma)\triangleq f(\sigma)
,
then
\mathtt{qet}\!\left[\,\mathtt{stm}\,\right]\!\left\{\textstyle f\right\}
is a function that maps input states
\sigma
to the expected value of
f
applied to the post states after executing
\mathtt{stm}
.
In particular, if
f
is a predicate that maps a state to
\{0,1\}
,
then
\mathtt{qet}\!\left[\,\mathtt{stm}\,\right]\!\left\{\textstyle f\right\}(\sigma)
yields the probability that predicate
f
holds after executing program
\mathtt{stm}
with input state
\sigma
.

If we inspect the expected cost and set
\mathtt{qet}\!\left[\,{\color[rgb]{0.0039,0.0039,0.0039}{\mathtt{tick}}}\penalty\ \mathtt{i}\,\right]\!\left\{\textstyle f\right\}(\sigma)\triangleq\lambda\sigma.\max(0,\mathtt{i}\sigma)+f(\sigma)
,
then
\mathtt{qet}\!\left[\,\mathtt{stm}\,\right]\!\left\{\textstyle f\right\}(\sigma)
yields the expected cost of executing
\mathtt{stm}
with input state
\sigma
with respect to the continuation
f
.
In particular, if
\mathtt{stm}
is the complete program,
then
\mathtt{qet}\!\left[\,\mathtt{stm}\,\right]\!\left\{\textstyle\lambda\_.\ 0\right\}(\sigma)
yields the expected cost of executing
\mathtt{stm}
with input state
\sigma
—the cost of the remaining execution is zero when reaching a final state.
We highlight that the expected cost analysis encapsulates the
expected runtime
analysis, by preceding each statement with a
{\color[rgb]{0.0039,0.0039,0.0039}{\mathtt{tick}}}\penalty\ 1
statement.

For automation, we differentiate between loop-free code and code with (possible nested) loops:

1)

For (sub)programs without loops, we use
symbolic evaluation
to mechanically compute the pre-expectations for a given continuation
f
.
This process handles assignments, quantum gate applications, classical conditional branches, and probabilistic case analyses arising from mid-circuit measurements.

2)

For (sub)programs with loops, we generate
upper-invariant constraints
by introducing unknown expectation functions at control flow points such as loop headers.
Symbolic evaluation is then used to relate these functions at control flow points, resulting in a system of constraints.

Term Constraint Simplifications

We apply several simplification rules to reduce the complexity of the generated constraints.
The inference rules
[Cond-Top]
and
[Cond-Bot]
resolve case distinction in conditional expressions when the truth value of the guard can be inferred from the context.
In practice, this often resolves branching which is due to measurements and conditional branching as it occurs for example for qubit initialisations:

\mathtt{q}^{\mathcal{Q}}\mathrel{{\color[rgb]{0.0039,0.0039,0.0039}{\mathtt{=}}}}\left|0\right\rangle\triangleq\mathtt{x}\mathrel{{\color[rgb]{0.0039,0.0039,0.0039}{\mathtt{=}}}}{\color[rgb]{0.0039,0.0039,0.0039}{\mathtt{meas^{\mathit{}}}}}\ \mathtt{q}\text{\color[rgb]{0.0039,0.0039,0.0039}{;}}\ {}{\color[rgb]{0.0039,0.0039,0.0039}{\mathtt{if^{\mathit{}}}}}\ \mathtt{x}\ {\color[rgb]{0.0039,0.0039,0.0039}{\mathtt{then}}}\ \mathtt{q}\mathrel{{\color[rgb]{0.0039,0.0039,0.0039}{\mathtt{{*}{=}}}}}\mathtt{X}\ {\color[rgb]{0.0039,0.0039,0.0039}{\mathtt{else}}}\ {\color[rgb]{0.0039,0.0039,0.0039}{\mathtt{skip}}}

1

\mathtt{stm}
)
begins with an initial cost of zero, calling
\textnormal{{Infer}}(\mathtt{stm},\mathsf{Cost}\penalty\ 0)
