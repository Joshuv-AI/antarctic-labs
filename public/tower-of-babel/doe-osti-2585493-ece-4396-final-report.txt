 Introduction

 In the summer of 2025, I was fortunate enough intern at Sandia National Laboratories in

Albuquerque, New Mexico. I was hired into the Southwest Analysis Laboratories for

Semiconductor Advancement (SALSA) intern program. In this internship, I applied my

knowledge and skills in electrical engineering to conduct hardware failure analysis. I utilized

various failure analyze techniques involving the use of Infrared Thermography (IRT) and Laser

Scanning Microscopy (LSM) to test different Application-Specific Integrated Circuits (ASIC)

chips that are available in the public market.

 Organization Overview

 Sandia National Laboratories is a multi-mission laboratory managed and operated by

National Technology & Engineering Solutions of Sandia, LLC, a wholly owned subsidiary of

Honeywell International Inc., for the U.S. Department of Energy’s National Nuclear Security

Administration under contract DE-NA0003525. Originally known as Z Division, it was the

ordnance design, testing and assembly arm of Los Alamos National Laboratory. In 1948, it

officially became Sandia National Laboratories, and expanded its capabilities to include weapons

testing and production, as well as research into renewable energy. Some of Sandia’s

accomplishments include the creation and launching of the Defense Support Program satellites,

the development of the B61-12 Life Extension Program, and the creation of the Z Machine, the

world’s largest X-ray generator [1].

 As a SALSA intern, I was placed under Sandia’s Center for Cyber Defense (CCD), a

facility for interns with technical internships to advance national security. All interns under the

CCD are tasked with developing advanced technologies in software, cyber, math and analytics.

It is under the CCD, as a SALSA intern, that I was tasked to stress test different ASIC chips to

then learn how to use different types of failure analysis techniques for hardware. Hardware

 Laser Scanning Microscopy

 Laser Scanning Microscopy (LSM) is a form of optical microscopy where a focused laser

beam scans the surface of a sample material and creates an image. LSM can be used for many

types of failure analysis, but for this project we focused on the use of LSM for backside imaging

of semiconductors, and to create topographical maps of the semiconductors to see material

defects like fractures on the surface [2].

 This project focused on the application of LSM on an ASIC called Tiny Tapeout 6+

(TT6+). Specifically, the project involved the setup of an autonomous, or user-controlled

interface for the TT6+ in order to successfully screen and analyze the ASIC’s behavior under

different script activations. We used micro Python and PySerial to communicate with the TT6+

through a computer’s terminal. TT6+ is manufactured by a company called Tiny Tapeout, which

teaches people about digital design. Part of Tiny Tapeout’s paid course is for each member to

create their own design, which then gets sent to OpenLane, an open-source tool that can convert

a digital netlist in Verilog format to the GDS files needed for ASIC manufacture [3]. Here is an

 The final step is to run the script under the LSM. We used a failure analysis technique

called Light-Induced Capacitance Alteration (LICA). LICA is a non-deconstructive failure

 Infrared Thermography

 Infrared Thermography (IRT) is a non-invasive failure analysis technique used to detect

and spot issues in electronic components. By capturing temperature variations across the surface

of a sample, IRT can diagnose failure mechanisms such as overheating, short circuits, and other

failures, and it is also critical in identifying heat sources and hotspots [5].

 For my individual project, I was tasked to heat up individual Central Processing Unit

(CPU) cores in both the Jetson Nano and the RPi CM4. I began by researching types of ASIC to

install the right Operating System (OS). I installed the Raspberry Imager to flash different OS

into different SD cards to find one that will be the most user friendly. I installed three OS, an

Ubuntu Desktop, a Linux Server, and a Raspberry Pi OS. I focused on the navigation aspect for

each OS, finding that the Raspberry Pi OS was the easiest to maneuver. It is based on Debian,

which comes with a vast library of packages that I will use to create and run scripts inside the

RPi CM4.

 The next step was to now heat up the CPU cores, which was the most difficult challenge.

Sandia policy required that both ASIC’s Wi-Fi capabilities were removed. This meant I could not

use commands such as “sudo apt install …” to install software that is publicly available to heat

up or stress test different parts of ASIC. Another issue that I encountered was that Windows

Subsystem for Linux (WSL) did not have access to physical ports, or hardware components of

the computer. I overcame these challenges by cloning the source code of stress -ng from GitHub,

where the assembly code was located. Then I launched the WSL terminal, where a new file

called cpuburn-a53.S was created using the command “nano cpuburn-a53.S”. The previously

copied assembly code was pasted into this file. To compile the assembly code into an executable,

the necessary tools were installed using sudo apt install gcc make, and the compilation was

executed with the command “aarch64-linux-gnu-gcc -o cpuburn-a53 cpuburn-a53.S”,

specifically targeting the ARM architecture.

 Subsequently, a directory structure was established for creating the .deb package, which

included making directories for Debian and the executable. The compiled executable was moved

to the appropriate directory, and a control file was created and edited to include essential package

information such as package name, version, architecture, dependencies, maintainer details, and a

brief description. The .deb package was then constructed using the command “dpkg-deb --build

~/cpuburn-a53”. After identifying the generated package named “cpuburn-a53.deb” in the home

directory, it was transferred to the Raspberry Pi using SCP from a Windows command prompt.

Once on the Raspberry Pi, an SSH connection was established, and the package was installed by

navigating to the home directory and executing “sudo dpkg -i cpuburn-a53.deb”. Any

dependency issues were resolved with sudo apt install -f. Finally, the CPU stress test application

was executed with “./cpuburn-a53”, while monitoring the CPU temperature using a pre-existing

script to ensure system stability during the stress test. The following is an image of the final

product for the RPi CM4 script:
