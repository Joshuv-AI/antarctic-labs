Aryan Esmailpour, Stavros Sintos

Abstract
. Optimization tasks over relational data, such as clustering, often suffer from the prohibitive cost of join operations, which are necessary to access the full dataset. While geometric data structures like BBD trees yield fast approximation algorithms in the standard computational setting, their application to relational data remains unclear due to the size of the join output. In this paper, we introduce a framework that leverages geometric insights to design faster algorithms when the data is stored as the results of a join query in a relational database. Our core contribution is the development of the RBBD tree, a randomized variant of the BBD tree tailored for relational settings. Instead of completely constructing the RBBD tree, by leveraging efficient sampling and counting techniques over relational joins, we enable on-the-fly efficient expansion of the RBBD tree, maintaining only the necessary parts. This allows us to simulate geometric query procedures without materializing the join result. As an application, we present algorithms that improve the state-of-the-art for relational k k -center/means/median clustering by a factor of k k in running time while maintaining the same approximation guarantees. Our method is general and can be applied to various optimization problems in the relational setting.



1.
Introduction

Optimization problems, such as clustering, are traditionally studied in computer science under the assumption of full access to the input data. However, in real-world applications, data is typically stored in
relational databases
, where information is distributed across multiple interrelated tables. Each table contains a set of tuples, and tuples from different tables may join if they have the same value on the shared attributes.
This relational structure introduces a fundamental challenge: full access to the data is only possible after performing a join operation across the relevant tables. Such joins are computationally expensive, as the output size of a join can be polynomially larger than the size of the input tables
(
ngo2018worst
;
ngo2014skew
)
. Nonetheless, relational data is ubiquitous in practice. According to
(
link1
;
kaggle
;
link:relational
)
, the majority of modern database systems and data science tasks involve relational data.

Machine learning applications over relational data typically involve two stages: (1) data preparation, where multiple tables are joined to construct the feature dataset, and (2) modeling, where machine learning algorithms (for example, clustering algorithms in unsupervised learning) are applied to the resulting data. However, this two-step pipeline can be prohibitively expensive in practice, largely due to the high cost of evaluating large joins.

\bullet
Consider a machine-learning workflow in which feature engineering over relational data is followed by unsupervised learning via clustering, based on the Yelp review dataset
(
yelp2017
)
. This dataset has been used for
k
-means clustering in prior work
(
curtin2020rk
;
chen2022coresets
)
.
The database consists of five relations:
(1)
Review(user_id, business_id, stars, date)
describing individual reviews,
(2)
User(user_id, review_count, fans, yelping_since)
providing reviewer attributes,
(3)
Business(business_id, city, state, avg_rating)
describing business metadata,
(4)
Category(business_id, category)
listing the categories assigned to each business (e.g., “Restaurant”, “Coffee Shop”), and
(5)
Attributes(business_id, attribute)
recording additional business characteristics
(e.g., “OpenLate”, “HasWiFi”).
A typical feature-engineering query joins these relations as follows:

Q=\textsf{Review}\Join\textsf{User}\Join\textsf{Business}\Join\textsf{Category}\Join\textsf{Attributes}
.
Each tuple in
Q
corresponds to a single review enriched with both numerical attributes (e.g.,
review_count
,
avg_rating
) and categorical attributes (e.g.,
category
,
attribute
), which are one-hot encoded before analysis.
Clustering is then performed directly over these joined tuples, meaning that individual review events are grouped according to their joint user attributes, business characteristics, and semantic labels.
In this representation, two reviews are considered similar if they are written by users with similar activity profiles for businesses with similar ratings, categories, and attributes.
As a result, each cluster captures a coherent pattern of reviewer behavior and business semantics, such as highly active users reviewing late-night restaurants with WiFi, or infrequent users reviewing family-oriented dining venues.
Crucially, because businesses often have multiple category and attribute labels, the join result
Q
is much larger than any base relation.
As reported in
(
curtin2020rk
)
, the base Yelp tables contain roughly
8
million tuples in total, whereas the fully materialized join contains approximately
22
million tuples. This significant blow-up highlights the computational cost of materializing relational joins before learning
and motivates the need for algorithms that can operate directly on the underlying tables without explicitly constructing
Q
.

\bullet
Consider a table
\mathsf{Purchase}
with attributes
\mathsf{price}
,
\mathsf{T}
,
\mathsf{item}
, and
\mathsf{category}
, where
\mathsf{price}
is a real-valued attribute,
\mathsf{T}
identifies a transaction,
\mathsf{item}
is a product identifier, and
\mathsf{category}
is a categorical attribute. The goal is to analyze pricing patterns of items that are commonly purchased together. For instance, a
k
-means clustering over the result of the self-join
\mathsf{Purchase}(\mathsf{T},\mathsf{price}_{0},\mathsf{item}_{0},\mathsf{category}_{0})\Join\mathsf{Purchase}(\mathsf{T},\mathsf{price}_{1},\mathsf{item}_{1},\mathsf{category}_{1})
groups co-purchased item pairs according to their joint price characteristics. Each joined tuple represents a pair of items bought in the same transaction, embedded in a two-dimensional price space
(\mathsf{price}_{0},\mathsf{price}_{1})
, possibly enriched with categorical information (for example the categories of the corresponding items). Because a single purchase may contain several different items, each transaction generates many distinct item pairs in the self-join, which can lead to a substantial blow-up in the size of the join result (quadratic with respect to the size of the
\mathsf{Purchase}
table). Even if one subsequently projects the join result onto the price attributes alone, it is crucial to retain duplicate tuples: repeated occurrences of the same price pair correspond to item pairs that are purchased together frequently and therefore carry greater statistical weight in the clustering objective. Clustering in this space can reveal typical price-based co-purchasing patterns, such as low–low, low–high, or high–high price item pairs. Such analyses of commonly bought products are standard in market-basket analysis and retail data mining
(
agrawal1993mining
;
han2000mining
;
leskovec2014mining
)
.

Recent work has aimed to circumvent materializing the full join output by designing
relational algorithms
for optimization tasks such as clustering
(
chen2022coresets
;
curtin2020rk
;
moseley2021relational
)
. However, these approaches often suffer from large constant approximation ratios or expensive runtimes. Moreover, each known method typically relies on a different specialized technique tailored to a specific problem.

In this paper, we introduce a general framework that enables faster algorithms for a broad class of optimization problems on relational data. Given a join query and a database instance, our approach can be used to efficiently solve problems such as clustering, diversity maximization, and fairness-aware selection.
Many of these problems have well-understood and near-linear time approximation algorithms in the standard computational setting, where the input is a single flat table. However, naively applying these techniques in the relational setting is inefficient due to the size of the join output. Our key idea is to simulate the behavior of geometric data structures—particularly those based on hierarchical tree structures such as the
BBD tree

(
arya1998optimal
)
,
without
materializing the entire join result. We present our approach by implementing a relational version of the BBD tree, since it best serves the clustering problems
we aim to solve. However, the same techniques can be adopted to derive a relational version of other commonly used geometric data structures such as quad trees
(
finkel1974quad
)
, kd-trees
(
deBerg2008
)
, or partition trees
(
chan2010optimal
)
.
We introduce a new randomized data structure, the
RBBD tree
, which maintains the desirable properties of the BBD tree but is tailored for relational data. Crucially, we show that given only one node of an RBBD tree (defined over the join results of an acyclic join query), its children can be computed in roughly
O(N)
time, where
N
is the size of the input database. This enables efficient simulation of geometric queries over the join results—including range counting, range reporting, and range sampling queries—as these typically require accessing only a logarithmic number of tree nodes.

Our method is general: any geometric algorithm that interacts with the input data through
\sigma
queries to a BBD tree can be transformed into a randomized relational algorithm (over an acyclic join query) with total runtime
O(\sigma\cdot N)
(ignoring logarithmic factors). As many geometric algorithms fall into this category, our framework yields efficient relational counterparts for a variety of tasks.
As an application, we show that the running time of the state-of-the-art algorithms for all relational
k
-center,
k
-median, and
k
-means clustering can be improved by a factor of
k
.

While in many applications
k
is considered small,
k
-clustering for large
k
has become increasingly relevant in modern applications, such as product quantization for nearest neighbor search in vector databases
(
jegou2010product
)
. This has motivated extensive algorithmic studies of large-
k
-clustering across various computational models
(
ene2011fast
;
bateni2021extreme
;
coy2023parallel
;
czumaj2024fully
;
filtser2025faster
)
.
Furthermore, in the relational setting
k
can be even larger than
N
, because the number of join results might be orders of magnitude larger than
N
.
In the literature on relational clustering
(
curtin2020rk
;
moseley2021relational
;
esmailpour2024improved
;
agarwal2024computing
)
, existing algorithms typically assume that
k
may be large, and successive work has focused on improving the dependency on
k
. We present the first relational clustering algorithms with linear dependency on both
k
and
N
for acyclic queries.

1.1.
Notation and problem definition

Join Queries.

We are given a database schema
{\mathbf{R}}
over a set of
d
attributes
{\mathbf{A}}=\{A_{1},\ldots,A_{d}\}
. The database schema
{\mathbf{R}}
contains
m
relations
R_{1},\ldots,R_{m}
. Let
{\mathbf{A}}_{j}\subseteq{\mathbf{A}}
be the set of attributes associated with relation
R_{j}\in{\mathbf{R}}
. For an attribute
A\in{\mathbf{A}}
, let
{\texttt{dom}}(A)
be the domain of attribute
A
.
Let
{\texttt{dom}}(X)=\prod_{A\in X}{\texttt{dom}}(A)
be be the domain of a set of attributes
X\subseteq{\mathbf{A}}
.
Let
\mathbf{D}
be a database instance over the database schema
{\mathbf{R}}
. For simplicity, we assume that each relation
R_{j}\in{\mathbf{R}}
contains
N
tuples in
\mathbf{D}
.
Throughout the paper, we consider data complexity i.e.,
m
and
d
are constants, while
N
is a large integer.
We use
R_{j}
to denote both the relation and the set of tuples from
\mathbf{D}
stored in the relation.
For a subset of attributes
B\subseteq{\mathbf{A}}
and a set
Y\subset\mathbb{R}^{d}
, let
\pi_{B}(Y)
be the set containing the projection of the tuples in
Y
onto the attributes
B
. Notice that two different tuples in
Y
might have the same projection on
B
, however,
\pi_{B}(Y)
is defined as a set, so the projected tuple is stored once.

Following the related work on relational clustering
(
chen2022coresets
;
curtin2020rk
;
moseley2021relational
)
, we are given a join query
\bm{q}:=R_{1}\Join\ldots\Join R_{m}
. The set of results of a join query
\bm{q}
over the database instance
\mathbf{D}
is defined as
\bm{q}(\mathbf{D})=\{t\in{\texttt{dom}}({\mathbf{A}})\mid\forall j\in[1,m]:\pi_{{\mathbf{A}}_{j}}(t)\in R_{j}\}
. A join query
\bm{q}
is acyclic if there exists a tree, called a join tree, such that the nodes of the tree are the relations in
{\mathbf{R}}
and for every attribute
A\in{\mathbf{A}}
, the set of nodes/relations that contain
A
form a connected component.
All our algorithms are presented assuming that
\bm{q}
is an acyclic join query, however, in the end we extend the results to any general join query.
Let
\rho^{\star}(\bm{q})
be the fractional edge cover of query
\bm{q}
, which is a parameter that bounds the number of join results
\bm{q}(\mathbf{D})
over any database instance: for every database instance
\mathbf{D}^{\prime}
with
O(N)
tuples, it holds that

|\bm{q}(\mathbf{D}^{\prime})|=O(N^{\rho^{\star}(\bm{q})})=O(N^{m})
as shown in
(
atserias2013size
)
.

We use the notation
\mathsf{fhw}(\bm{q})
to denote the
fractional hypertree width

(
gottlob2014treewidth
)
of the query
\bm{q}
.
The fractional hypertree width roughly measures how close
\bm{q}
is to being acyclic.
For every acyclic join query
\bm{q}
, we have
\mathsf{fhw}(\bm{q})=1
.
Given a cyclic join query
\bm{q}
, we convert it to an equivalent acyclic query such that each relation is the result of a (possibly cyclic) join query with fractional edge cover at most
\mathsf{fhw}(\bm{q})
. Hence, a cyclic join query over a database instance with
O(N)
tuples per relation can be converted, in
O(N^{\mathsf{fhw}(\bm{q})})
time, to an equivalent acyclic join query over a database instance with
O(N^{\mathsf{fhw}(\bm{q})})
tuples per relation
(
atserias2013size
)
.
A more formal definition of
\mathsf{fhw}
is given in Appendix
F
. If
\bm{q}
is clear from the context, we write
\mathsf{fhw}
instead of
\mathsf{fhw}(\bm{q})
.

For tuples
p,q\in{\texttt{dom}}({\mathbf{A}})
, let
\phi(p,q)=||p-q||_{2}=\left(\sum_{j=1}^{d}(\pi_{A_{j}}(p)-\pi_{A_{j}}(q))^{2}\right)^{1/2}
denote their Euclidean distance.
If
A_{j}\in{\mathbf{A}}
is a categorical attribute, we apply the
one-hot encoding
(see Appendix
D
) and define

(\pi_{A_{j}}(p)-\pi_{A_{j}}(q))^{2}=1
if
\pi_{A_{j}}(p)\neq\pi_{A_{j}}(q)
, and
(\pi_{A_{j}}(p)-\pi_{A_{j}}(q))^{2}=0
otherwise.
We focus on Euclidean distance for clarity and consistency with prior work, but our algorithms extend to any
\ell_{p}
metric.

Throughout the paper, we use the term
standard computational setting
when we consider the input data to be stored in a single flat table. In contrast, we use the term
relational setting
when the data is the result of a join query as described above.

Clustering

In this paper, we focus on the three classical clustering objectives:

k
-center,
k
-median, and
k
-means clustering.
These formulations capture different ways of measuring the quality of clustering and are among the most widely used models in both theory and practice
(
lloyd1982least
;
gonzalez1985clustering
;
arya2004local
;
har2004coresets
;
ostrovsky2012effectiveness
)
.

k
-center focuses on minimizing the worst-case distance,

k
-median minimizes the total (average) distance,
and
k
-means minimizes the total squared distance.
In applications where we want to ensure that no point is too far from its nearest center (e.g., facility location or coverage problems),
k
-center is preferred.
When we aim to minimize average travel cost or total assignment distance (e.g., clustering customers by proximity),
k
-median is more suitable.
Finally,
k
-means is typically used when distances represent errors or variances, and we care about minimizing overall dispersion (e.g., in statistical data analysis or machine learning applications).

We start with some useful general definitions.
Let
P
be a set of tuples in
{\texttt{dom}}({\mathbf{A}})
and let
C\subset{\texttt{dom}}({\mathbf{A}})

be a set of
k
tuples.
For a tuple
p\in{\texttt{dom}}({\mathbf{A}})
, let
\phi(p,C)=\min_{c\in C}\phi(p,c)
. We define

\textbf{u}_{C}(P)=\max_{p\in P}\phi(p,C),\quad\textbf{v}_{C}(P)=\sum_{p\in P}\phi(p,C),\quad\text{ and }\quad\mu_{C}(P)=\sum_{p\in P}\phi^{2}(p,C).

k
-center clustering
: Given a set of tuples
P
in
{\texttt{dom}}({\mathbf{A}})
and a parameter
k
, the goal is to find a set
C\subseteq P
with
|C|=k
such that
\textbf{u}_{C}(P)
is minimized.
Let
\mathsf{OPT}(P)=\argmin_{S\subseteq P,|S|=k}\textbf{u}_{S}(P)
be a set of
k
centers with the minimum
\textbf{u}_{\mathsf{OPT}(P)}(P)
.
Let

\mathsf{kCenterAlg}_{\gamma}
be a (known)
\gamma
-approximation algorithm for the
k
-center clustering problem in the standard computational setting that runs in
T^{\mathsf{cen}}_{\gamma}(|P|)
time, where
\gamma
is a constant.

k
-median clustering
: Given a set of tuples
P
in
{\texttt{dom}}({\mathbf{A}})
and a parameter
k
, the goal is to find a set
C\subseteq P
with
|C|=k
such that
\textbf{v}_{C}(P)
is minimized.
Let
\mathsf{OPT}(P)=\argmin_{S\subseteq P,|S|=k}\textbf{v}_{S}(P)
be a set of
k
centers with the minimum
\textbf{v}_{\mathsf{OPT}(P)}(P)
.
Let
\mathsf{kMedianAlg}_{\gamma}
be a (known)
\gamma
-approximation algorithm for the
k
-median problem in the standard computational setting that runs in
T^{\mathsf{med}}_{\gamma}(|P|)
time, where
\gamma
is a constant.

k
-means clustering
: Given a set of tuples
P
in
{\texttt{dom}}({\mathbf{A}})
and a parameter
k
, the goal is to find a set
C\subseteq P
with
|C|=k
such that
\mu_{C}(P)
is minimized.
Let
\mathsf{OPT}(P)=\argmin_{S\subseteq P,|S|=k}\mu_{S}(P)
be a set of
k
centers with the minimum
\mu_{\mathsf{OPT}(P)}(P)
.
Let
\mathsf{kMeansAlg}_{\gamma}
be a (known)
\gamma
-approximation algorithm for the
k
-means problem in the standard computational setting that runs in
T^{\mathsf{mean}}_{\gamma}(|P|)
time, where
\gamma
is a constant.

We use the same notation
\mathsf{OPT}(\cdot)
for the optimum solution for
k
-center/median/means clustering. It is always clear from the context whether we are referring to
k
-center,
k
-median, or
k
-means clustering.
Sometimes we call the value of
\textbf{u}_{C}(P)
(or
\textbf{v}_{C}(P),\mu_{C}(P)
) as the clustering cost of
C
in
P
.

Relative approximation

We call a set
C\subset{\texttt{dom}}({\mathbf{A}})
an
\alpha
-approximation for the
k
-center (resp.
k
-median,
k
-means) clustering over a tuple set
P\subset{\texttt{dom}}({\mathbf{A}})
, if
\textbf{u}_{C}(P)\leq\alpha\cdot\textbf{u}_{\mathsf{OPT}(P)}(P)
(resp.
\textbf{v}_{C}(P)\leq\alpha\cdot\textbf{v}_{\mathsf{OPT}(P)}(P)
,
\mu_{C}(P)\leq\alpha\cdot\mu_{\mathsf{OPT}(P)}(P)
). An
\alpha
-approximation algorithm on
P
always returns a set of centers which is
\alpha
-approximation over
P
.

Coreset

A set
\mathcal{C}\subseteq{\texttt{dom}}({\mathbf{A}})
, with
|\mathcal{C}|\ll|P|
, is a coreset for the
k
-center/median/means clustering over
P
, if every
\alpha
-approximation algorithm executed on
C
returns a set of centers which is a
(1+\varepsilon)\alpha
-approximation for
P
. Throughout the paper, we assume that
\varepsilon\in(0,1)
.

In this paper, we study
k
-center,
k
-median and
k
-means clustering on the results of a join query.

[Relational
k
-center/median/means clustering] Given a database instance
\mathbf{D}
, a join query
\bm{q}
, and a positive integer parameter
k
, the goal is to compute a set
\mathcal{S}\subseteq\bm{q}(\mathbf{D})
of size
|\mathcal{S}|\leq k
such that
\textbf{u}_{\mathcal{S}}(\bm{q}(\mathbf{D}))
(resp.
\textbf{v}_{\mathcal{S}}(\bm{q}(\mathbf{D}))
,
\mu_{\mathcal{S}}(\bm{q}(\mathbf{D}))
is minimized.

Remark

While we focus on
k
-clustering over full join results, all our algorithms extend straightforwardly to
k
-clustering over the results of project–join queries under
bag semantics
, where duplicates are preserved (see also Appendix
D
). This setting is particularly useful in applications where the goal is to cluster all tuples in the join result only with respect to a subset of attributes
(for example, using only the price attribute in the earlier
\mathsf{Purchase}
table).
As discussed in Appendix
D
, the ability to perform clustering on project–join queries under bag semantics is also a key ingredient for handling clustering over joins that involve both numerical and categorical attributes.

3.
Overview

In this section, we describe the intuition and the high-level ideas of our approach. In the next sections, we formally prove the claims made in this section.

Previous methods

Most of the previously known methods for relational clustering
(
esmailpour2024improved
;
agarwal2024computing
;
chen2022coresets
;
moseley2021relational
;
curtin2020rk
)
follow the same high-level approach. They first design a constant approximation algorithm with more than
k
centers. Let
Z
be that set. Then
Z
is used to construct a small coreset
\mathcal{C}
for the relational clustering problem. Finally, a known clustering algorithm in the standard computational setting is executed on
\mathcal{C}
to derive the final solution. Interestingly, the coreset construction is
relatively fast. In most cases, the running time is dominated by the first part, i.e., constructing any constant approximation solution with potentially more than
k
points. For example, consider the state–of–the–art algorithms for the relational
k
-center
(
agarwal2024computing
)
and relational
k
-median/means clustering
(
esmailpour2024improved
)
. In these papers, they construct
O(1)
-approximation algorithms with
\tilde{O}(k^{2})
centers in
\tilde{O}(k^{2}N)
time using a
hierarchical aggregation method
.
At a high level, they place all relations from
{\mathbf{R}}
as leaf nodes in a balanced binary tree. For a leaf node
u_{1}
run a standard clustering algorithm
in the standard computational setting, considering only the tuples of the relation stored in
u_{1}
. Let
\mathcal{S}_{1}
be the returned set of
k
centers. Equivalently, they get
\mathcal{S}_{2}
from the sibling node
u_{2}
. Then, they show that
\mathcal{S}_{1\times 2}=\mathcal{S}_{1}\times\mathcal{S}_{2}
is an
O(1)
-approximation solution for the clustering problem on the result of joining the tables in leaf nodes
u_{1}
and
u_{2}
. Then they construct a coreset based on
\mathcal{S}_{1\times 2}
in time
\tilde{O}(|\mathcal{S}_{1\times 2}|\cdot N)
and continue recursively on higher levels of the tree.
While this method is useful to design
O(1)
-approximation algorithms, the drawback is that it constructs intermediate sets of size
\Theta(k^{2})
(for example
\mathcal{S}_{1\times 2}
), leading to
\Omega(k^{2}\cdot N)
time algorithms.

Our approach

We give the high-level idea of our approach using the
k
-center clustering as an example. Let
P
be a set of
n
points in
\mathbb{R}^{d}
and
k
be a positive integer parameter in the standard computational setting.
In computational geometry, there are various efficient constant approximation algorithms for the
k
-center clustering.
While these algorithms are fast in the standard computational setting, it is not clear how to efficiently extend them to the relational setting.
Consider the
following simple algorithm for the
k
-center problem on
P
.
Let
r=\textbf{u}_{\mathsf{OPT}(P)}(P)
be the optimum cost, and assume that
r
is known upfront.
In the first iteration, we add in
\mathcal{S}
any arbitrary point
p_{1}\in P
. We remove all points in
\mathcal{B}(p_{1},2r)\cap P
from
P
, i.e., all points in
P
within distance
2r
from
p_{1}
, and we continue with the next iteration. In the
i
-th iteration we choose an arbitrary point
p_{i}\in P\setminus\bigcup_{j<i}\mathcal{B}(p_{j},2r)
, we remove all points
\mathcal{B}(p_{i},2r)\cap P
and we continue for a total number of
k
iterations.
It is easy to verify that this algorithm returns a
2
-approximation for the
k
-center problem on
P
.
Assuming that the optimum
r
is known, a naive implementation of this algorithm takes
O(nk)
time. If
r
is not known, we need to execute a binary search on the distances of
P
(using a WSPD
(
callahan1995decomposition
;
har2005fast
)
), leading to
O(nk\log n)
running time.
However, there is a faster implementation of this algorithm in the standard computational setting. We build a BBD tree
\mathcal{T}
over
P
. For every node
u
of
\mathcal{T}
, we store a representative point
u.rep
from the points stored in the leaf nodes of the subtree rooted at
u
, i.e.,
u.rep\in P_{u}
(see Section
4
). In the first iteration
p_{1}=\mathtt{root}.rep
, is the representative point in the root. Then we run the query
\mathcal{T}(p_{1},2r)
and we get the set of canonical nodes
\mathcal{U}(p_{1},2r)
. We mark every node in
\mathcal{U}(p_{1},2r)
as
‘inactive’. Then we start from the deepest node in
\mathcal{U}(p_{1},2r)
and we update the representative points of the active nodes to make sure that
no representative point lies in a leaf node of a subtree rooted at an inactive node.
We continue
similarly in the next
k-1
iterations, visiting only active nodes.
This implementation returns a set
\mathcal{S}\subseteq P
such that
\textbf{u}_{\mathcal{S}}(P)\leq 2(1+\varepsilon)\textbf{u}_{\mathsf{OPT}(P)}(P)

with running time
O(n\log n+k(\varepsilon^{-d+1}+\log n))=O(n\log n)
, in standard computational setting. An example of the faster algorithm in the standard computational setting is shown in Figure
3
.

A straightforward implementation of the BBD tree based algorithm for
k
-center clustering will be expensive in the relational setting. Just to construct the BBD tree over all join results, we need
\Omega(|\bm{q}(\mathbf{D})|)
time.
However, we make the following simple but key observation.

We do not really need to construct the entire tree upfront. What if we construct the tree on the fly?

Consider again the standard computational setting. Initially, assume that we have only constructed the root node
\mathtt{root}
of the tree
\mathcal{T}
.
The goal is to compute
\mathcal{U}(p_{i},2r)
.
Let
v
be a node of the constructed part of
\mathcal{T}
that the query procedure traverses. If the children of
v
have not been constructed, we construct the left child
v_{1}
and the right child
v_{2}
, and then we continue with the regular query procedure.
Given a node
v
of the BBD tree, if we can construct its two children
v_{1},v_{2}
in
O(t)
time, then the execution time is bounded by
O(k\cdot t\cdot(\log n+\varepsilon^{-d+1}))
. While this is a loose upper bound in the standard computational setting, we use it to bound the query procedure in the relational setting.

Our core idea is the on-the-fly construction of a new variant of the BBD tree in the relational setting. This enables the design of several new relational oracles, which in turn yield the fastest known approximation algorithms for a variety of optimization problems. While the underlying idea is conceptually simple, constructing a BBD tree in the relational setting requires multiple steps, combining techniques from computational geometry (BBD trees), database theory (relational counting and sampling oracles), and probability analysis (
\varepsilon
-samples).
A key advantage of our approach is generality. Many classical algorithms from standard settings can be directly translated to relational settings with minimal effort using the proposed data structure. This sharply contrasts with previous work on relational clustering (for example
(
agarwal2024computing
;
esmailpour2024improved
;
moseley2021relational
)
), where algorithms are specifically tailored for particular objectives and often differ significantly from their classical counterparts.

In the next section, we propose a new variation of the BBD tree, called randomized BBD tree (or RBBD tree in short) such that if a node
v
of an RBBD tree over
\bm{q}(\mathbf{D})
is given, then the children
v_{1},v_{2}
can be computed in
O(N+\varepsilon^{-2}\log N)
time in the relational setting.

Before we describe the RBBD tree, we give an overview of how standard BBD trees are constructed as described in
(
arya1998optimal
)
.
Then, we introduce a randomized variation of the BBD tree called RBBD tree.
Although the RBBD tree offers no advantage over the BBD tree in the standard computational setting, we show that it can be beneficial in the relational setting, as the children of any node in the RBBD tree over

4.1.
More details on the construction of a BBD tree

Let
P
be a set of
n

\mathbb{R}^{d}
. Recall that every node
u
of the BBD tree is associated with a region
\square_{u}
, which is either a box or a box with a hole, and recall that
P_{u}=\square_{u}\cap P
. In the latter case, let
\square^{+}_{u}
be the outer box and
\square^{-}_{u}
be the inner box (hole).
A
midpoint box
is defined as any box that can be obtained by a recursive application of the following rule, starting from the initial bounding box
\square_{\mathtt{root}}
, then: Let
\rho
be a midpoint box and let
\xi
be the longest side of
\rho
. Split
\rho
into two identical boxes by a hyperplane which is orthogonal to the
\xi
-th coordinate axis, passing through the center of
\rho
. See Figure
5
for an example of midpoint boxes.
The tree is constructed in a way that if
\square_{u}
is a box, then
\square_{u}
is a midpoint box, while if
\square_{u}
is a box with a hole, then both
\square^{+}_{u}
and
\square^{-}_{u}
are midpoint boxes, for any node
u
of the tree.
The children of
u
are constructed using one of the following two methods,
fair split
and
centroid shrink
. At the root of the tree, they apply a fair split to construct its children.
In any other case, if
u
was generated by fair split (resp. centroid shrink) its children are generated by centroid shrink (resp. fair split).

Fair split

They compute a hyperplane that passes through the center of
\square_{u}
and is orthogonal to the longest side of
\square_{u}
(or
\square_{u}^{+}
if
\square_{u}
is a box with a hole). Notice that even if
\square_{u}
contains a hole, then the hyperplane splitting
\square_{u}
into two boxes will not intersect
\square_{u}^{-}
because both
\square_{u}^{-}
and
\square_{u}^{+}
are midpoint boxes. In this case, if
w,v
are the children nodes of
u
, then
\square_{w}
will be a box, and
\square_{v}
will be a box with a hole, having
\square_{v}^{-}=\square_{u}^{-}
.
The fair split is executed in
O(1)
time.

Centroid shrink

On a high level, the goal is to find a midpoint box
\rho^{*}
inside
\square_{u}
such that
|\rho^{*}\cap P|\leq\frac{2}{3}|P_{u}|
and
|(\square_{u}\setminus\rho^{*})\cap P|\leq\frac{2}{3}|P_{u}|
. In order to compute
\rho^{*}
their algorithm works in iterations.
We describe the construction assuming that
\square_{u}
is a box without a hole. In Appendix
A.1
, we discuss the construction when
\square_{u}
is a box with a hole.
Initially, let
\rho=\square_{u}
. They compute the smallest midpoint box that contains all points in
P_{u}\cap\rho
. Let
\rho^{\prime}\subseteq\rho
be this box. They apply
O(d)
fair splits on
\rho^{\prime}
until they find a non-trivial fair split, i.e., a fair split that splits the points in
P_{u}\cap\rho^{\prime}
into two non-empty subsets. Let
\hat{\rho}\subset\rho^{\prime}
be one of the two boxes created by the non-trivial fair split such that
|\hat{\rho}\cap P_{u}|\geq\frac{|\rho^{\prime}\cap P_{u}|}{2}
. We say that
\hat{\rho}
is the majority midpoint box.
The key observation is that
|\hat{\rho}\cap P_{u}|\leq|\rho\cap P_{u}|-1
.
If
|\hat{\rho}\cap P_{u}|>\frac{2}{3}|P_{u}|
, they set
\rho=\hat{\rho}
and they continue recursively.
If
|\hat{\rho}\cap P_{u}|\leq\frac{2}{3}|P_{u}|
, then
\rho^{*}=\hat{\rho}
and then they construct two children nodes
w,v
of
u
such that
\square_{w}=\rho^{*}
is a box (without a hole), and
\square_{v}
is a box with a hole with
\square_{v}^{+}=\square_{u}
and
\square_{v}^{-}=\rho^{*}=\square_{w}
, as shown in Figure
5
.
As shown in
(
arya1998optimal
)
, the smallest midpoint box
\rho^{\prime}\subseteq\rho
that contains all points in
P_{u}\cap\rho
can be found in
O(1)
time.
Since in every recursive iteration
|\hat{\rho}\cap P_{u}|\leq|\rho^{\prime}\cap P_{u}|-1
, the centroid shrink procedure is executed in
O(|P_{u}|)
time.

4.2.
Construction of the RBBD tree

We define a new variation of the BBD tree called RBBD tree in the standard computational setting over a set of
n
points
P\subset\mathbb{R}^{d}
. The construction of the RBBD tree shares most of the steps and properties with the BBD tree. For example, all constructed boxes (both inner and outer) are midpoint boxes. The fair split is identical to BBD tree’s fair split. The only difference is the definition and execution of the centroid shrink procedure, given a node
u
.

We define the
randomized centroid shrink
.
Let
u
be a node.
We get a set
\mathcal{N}_{u}
of
\Theta(\varepsilon^{-2}\log n)
uniform random samples from
\square_{u}\cap P_{u}
.
If
\square_{u}
is a box without a hole, then we simply sample in the box
\square_{u}
.
If
\square_{u}
is a box with a hole, we sample in the region between
\square_{u}^{+}
and
\square_{u}^{-}
. Then the procedure is similar to the centroid shrink from the BBD tree using
\mathcal{N}_{u}
instead of
P_{u}
. We recursively compute the smallest midpoint box
\rho^{\prime}
that contains
\mathcal{N}_{u}
, and we apply
O(d)
fair splits until we find a non-trivial fair split. We recursively continue the construction on the box
\hat{\rho}
created by the non-trivial fair split procedure that contains most of the points in
\mathcal{N}_{u}
(majority midpoint box). We repeat this recursive approach until we find a majority midpoint box
\hat{\rho}
(after a non-trivial fair split) that contains at most
\frac{2}{3}|\mathcal{N}_{u}|
samples from
\mathcal{N}_{u}
.
If
\square_{u}
is a box with a hole, the procedure is shown in Appendix
A.1
.
In Appendix
A.2
, we prove the next theorem using the properties of the BBD and RBBD trees.

Theorem 4.1.

Given a set
P
of
n
points in
\mathbb{R}^{d}
a parameter
\varepsilon\in(0,1)
, and a constant parameter
\zeta>1
, the RBBD tree has height
O(\log n)
, it can be constructed in
O(n\log n+n\cdot(f(n,\varepsilon)+\varepsilon^{-2}\log n))
time with space
O(n)
, where
f(n,\varepsilon)
denotes the running time to sample
\Theta(\varepsilon^{-2}\log n^{\zeta})
points from a box (or a box with a hole), such that given a query ball
\mathcal{B}(p,r)
for a point
p\in\mathbb{R}^{d}
and a radius
r
, a set
\mathcal{U}
of
O(\log n+\varepsilon^{-d+1})
canonical nodes can be found in
O(\log n+\varepsilon^{-d+1})
time such that
\mathcal{B}(p,r)\subseteq P\cap\bigcup_{u\in\mathcal{U}}\square_{u}\subseteq\mathcal{B}(p,(1+\varepsilon)r)
. The height, the space, the construction time of the tree, the size of
\mathcal{U}
, and the query time hold with probability at least
1-\frac{1}{n^{\zeta-1}}
.

4.3.
RBBD tree in the relational setting

Let
\bm{q}
be an acyclic join query over a database instance
\mathbf{D}
.
Due to the size of
\bm{q}(\mathbf{D})
, we cannot construct the entire RBBD tree as described in the previous subsection. Instead, we show how we can construct the children of a node
u
, given that
u
has been constructed and it is a node of an RBBD tree over
\bm{q}(\mathbf{D})
.
More specifically, we show how we can implement the fair split and the randomized centroid shrink of the RBBD tree efficiently in the relational setting.
Furthermore, for every new node
v
of the RBBD tree we show how to compute the count
v.c=|\square_{v}\cap\bm{q}(\mathbf{D})|
and a representative
v.rep\in\square_{v}\cap\bm{q}(\mathbf{D})
.
This information is useful for the design of our algorithms.

Root node

We first show how to construct the root node
\mathtt{root}
of the RBBD tree, which is always a box without a hole. For every attribute
A_{i}\in{\mathbf{A}}
we compute
\pi_{A_{i}}(\mathbf{D})
and we keep the maximum
M_{i}
and minimum value
m_{i}
. We define the
\square_{\mathtt{root}}
as a box without a hole with opposite corners
(m_{1},\ldots,m_{d})
and
(M_{1},\ldots,M_{d})
. This procedure is executed straightforwardly in
O(N)
time.

Fair split

The implementation of the fair split in the relational setting is identical to the fair split in the standard computational setting. We only need to identify the longest side of a box along with its center in
O(1)
time.

Randomized centroid shrink

We only need to show how to implement the sampling procedure since all the other steps can be executed similarly to the standard computational setting.
We need to sample uniformly at random
\Lambda=\Theta(\varepsilon^{-2}\log(N^{m+4}))=\Theta(\varepsilon^{-2}\log N)
points from
\square_{u}\cap\bm{q}(\mathbf{D})
.
If
\square_{u}
is a box (without a hole) then we simply call
\mathsf{SampleRect}(\bm{q},\mathbf{D},\square_{u},\Lambda)
from Lemma
2.1
and we get the set
\mathcal{N}_{u}
in
O(N+\varepsilon^{-2}\log^{2}N)
time.
In Appendix
A.3
, we show how we sample in the same running time from
\square_{u}\cap\bm{q}(\mathbf{D})
, when
\square_{u}
is a box with a hole.

Count and representative tuples in newly constructed nodes

If
\square_{u}
is a box without a hole, we call
u.c=\mathsf{CountRect}(\bm{q},\mathbf{D},\square_{u})
and
u.rep=\mathsf{ReprRect}(\bm{q},\mathbf{D},\square_{u})
from Lemma
2.1
. Both of these procedures run in
O(N)
time. In Appendix
A.4
, we compute the count and the representative point in the same running time, when
\square_{u}
is a box with a hole.

Lemma 4.2.

Let
\bm{q}
be an acyclic join query over a database instance
\mathbf{D}
of size
N
. Given a node
u
of an RBBD tree over
\bm{q}(\mathbf{D})
, the fair split procedure is executed in
O(N)
time, while the randomized centroid shrink procedure is executed in
O(N+\varepsilon^{-2}\log^{2}N)
time.

4.4.
Relational
oracles using a partially constructed RBBD tree

Using Lemma
4.2
and Theorem
4.1
, we derive new oracles that will allow us to solve optimization problems in the relational setting, efficiently.
Let
\mathcal{T}
be a partially constructed RBBD tree over
\bm{q}(\mathbf{D})
, i.e.,
\mathcal{T}
consists of a connected subset of nodes (including the root, denoted by
\mathtt{root}
) of an RBBD tree over
\bm{q}(\mathbf{D})
. Initially,
\mathcal{T}
consists only of the root, as constructed in Section
4.3
.
For every constructed node
u\in\mathcal{T}
, we store i)
\square_{u}
the region corresponding to node
u
which is either a box or a box with a hole, and ii)
u.a
a boolean variable which is
1
if
u
is an
active
node, and
0
if it is an
inactive
node. A point
p\in\bm{q}(\mathbf{D})
is called an
inactive point
if there exists a node
u\in\mathcal{T}
such that
p\in\square_{u}
and
u.a=0
. A point which is not inactive is
active
.
While we do not compute it explicitly, for convenience we use
Q^{\prime}\subseteq\bm{q}(\mathbf{D})
to denote the set of current active points in
\bm{q}(\mathbf{D})
.
Furthermore, in each node
u\in\mathcal{T}
, we store
u.rep
which is an arbitrary representative point from
\square_{u}\cap Q^{\prime}
. Finally, for each node
u\in\mathcal{T}
, we store the number of active points in the region
\square_{u}
, i.e.,
u.c=|\square_{u}\cap Q^{\prime}|
.

Given such a partially constructed tree
\mathcal{T}
, we show how to implement five oracles in the relational setting while maintaining
\mathcal{T}
(new nodes might need to be constructed).
The running time of every oracle in this section holds with probability at least
1-\frac{1}{N^{m+3}}
. Due to space requirements, we show the proofs of all lemmas in Appendix
A.5
.

Make points in a ball inactive

Given a ball
\mathcal{B}(x,r)
, where
x\in\mathbb{R}^{d}
and
r
is a non-negative real number, the goal is to (implicitly) make all points in
\mathcal{B}(x,r)\cap Q^{\prime}
inactive.
Let
\mathcal{T}.\mathsf{inactive}(x,r)
be this oracle, which works as follows.
We first execute a query procedure similar to the query procedure on a BBD tree. Let
\mathcal{U}(x,r)
be the set of canonical nodes we will compute.
Let
u
be a node of
\mathcal{T}
that the query procedure processes. Initially,
u=\mathtt{root}
and
\mathcal{U}(x,r)=\emptyset
.
If
u.a=0
, we stop the execution of the query through this branch of the tree. In the rest, we assume that
u.a=1
.
If the children of
u
have not been constructed in
\mathcal{T}
we use Lemma
4.2
to construct its children.
Next, we continue checking whether
\square_{u}
intersects
\mathcal{B}(x,r)
. If
\square_{u}\subseteq\mathcal{B}(x,(1+\varepsilon)r)
, then we add
u
in
\mathcal{U}(x,r)
and we stop the execution through this branch of the tree. If
\square_{u}\cap\mathcal{B}(x,r)=\emptyset
, we stop the execution of the query through this branch of the tree. In any other case, we continue the query procedure in both children of
u
recursively.
For every added node
u\in\mathcal{U}(x,r)
, we set
u.a=0
. Before we finish the procedure, we need to update the representative points and the counts of the ancestor nodes of
\mathcal{U}(x,r)
.
Starting from the parent node
v
of the deepest node in
\mathcal{U}(x,r)
, we run recursively: Let
u,w
be
v
’s two children. If
u.a=w.a=0
, then we set
v.a=0
. If
u.a=1
and
w.a=0
(resp.
u.a=0
and
w.a=1
), we set
v.c=u.c
and
v.rep=u.rep
(resp.
v.c=w.c
and
v.rep=w.rep
). If
u.a=w.a=1
, we set
v.c=u.c+w.c
and
v.rep=u.rep
. After we process all canonical nodes’ ancestors in one level of the tree, we continue the update of the nodes in the level above.

Lemma 4.3.

\mathcal{T}.\mathsf{inactive}(x,r)
makes all points in
\mathcal{B}(x,r)\cap Q^{\prime}
inactive and might make some points in
\mathcal{B}(x,(1+\varepsilon)r)\cap Q^{\prime}
inactive. Furthermore, in the end of the execution of the oracle, for every node
u\in\mathcal{T}
the values
u.rep,u.c
are correct. The running time is
O((\varepsilon^{-d+1}+\log N)(N+\varepsilon^{-2}\log^{2}N))
.

Approximately count active points in a ball

Given a ball
\mathcal{B}(x,r)
the goal is to compute
|\mathcal{B}(x,r)\cap Q^{\prime}|
approximately. We define the oracle

\mathcal{T}.\mathsf{count}(x,r)
, and run the same query procedure as in
\mathcal{T}.\mathsf{inactive}(x,r)
to compute
\mathcal{U}(x,r)
. We return
\sum_{u\in\mathcal{U}(x,r)}u.c
.

Lemma 4.4.

\mathcal{T}.\mathsf{count}(x,r)
returns a number
c
such that
|\mathcal{B}(x,r)\cap Q^{\prime}|\leq c\leq|\mathcal{B}(x,(1+\varepsilon)r)\cap Q^{\prime}|
in
O((\varepsilon^{-d+1}+\log N)(N+\varepsilon^{-2}\log^{2}N))
time.

Get a representative from
Q^{\prime}

Next, the goal is to return any point from
Q^{\prime}
. We define the oracle
\mathcal{T}.\mathsf{rep}()
. If
\mathtt{root}.a=0
then we return
\emptyset
, i.e.,
Q^{\prime}=\emptyset
. If
\mathtt{root}.a=1
, then we return
\mathtt{root}.rep
.

Lemma 4.5.

\mathcal{T}.\mathsf{rep}()
returns a point in
Q^{\prime}
if
Q^{\prime}\neq\emptyset
, and
\emptyset
otherwise, in
O(1)
time.

Report all points in
Q^{\prime}

Assume that we aim to report all points in
Q^{\prime}
. We define the oracle
\mathcal{T}.\mathsf{report}()
. Starting from the root node
\mathtt{root}
we execute a depth-first search over
\mathcal{T}
. If we reach a node
u
such that
u.a=0
we stop the traversal through this branch of the tree. If we reach a node
u
that we have not constructed its children or
u
is a leaf node of the RBBD tree, we run
\mathsf{ReportRect}(\bm{q},\mathbf{D},\square_{u})
. We continue the depth-first search until we visit all constructed nodes in
\mathcal{T}
.

Lemma 4.6.

\mathcal{T}.\mathsf{report}()
returns
Q^{\prime}
in time
O(|\mathcal{T}|N+|Q^{\prime}|)
, where
|\mathcal{T}|
is the number of nodes in
\mathcal{T}
.

Sample
z
points from
Q^{\prime}

The goal is to sample (with replacement)
z
points from
Q^{\prime}
, uniformly at random.
We describe the oracle
\mathcal{T}.\mathsf{sample}(z)
. We use
\mathcal{T}
to get each sample one by one.
If
\mathtt{root}.a=0
we return no sample because
Q^{\prime}=\emptyset
.
Otherwise we set
u=\mathtt{root}
and we act as follows.
If
u
has two active children
v,w
then we move to the node
v
with probability
\frac{v.c}{v.c+w.c}
and to node
w
with probability
\frac{w.c}{v.c+w.c}
.
If
v.a=1
and
w.a=0
(resp.
v.a=0
and
w.a=1
) we move to the node
v
(resp.
w
). We recursively repeat this process until we reach a leaf node of the RBBD tree or an active node whose children have not been constructed in
\mathcal{T}
. If we have reached a leaf node, then we trivially add the point stored in the leaf node to the sample set. In case we reach a node
u
whose children have not been constructed in
\mathcal{T}
, we sample one point from
\square_{u}\cap\bm{q}(\mathbf{D})
as described in Section
4.3
.

Lemma 4.7.

\mathcal{T}.\mathsf{sample}(z)
returns
z
samples uniformly at random from
Q^{\prime}
in
O(z\cdot N)
time.

5.
k
-Center Clustering

In Section
3
, we already discussed the high-level idea of solving the relational
k
-center clustering efficiently. Here, we describe all the details and the formal proofs.

5.1.
A constant approximation algorithm

We first describe the main part of the algorithm, where given a distance
r
, if
r
is sufficiently large, it returns a set
\mathcal{S}
such that
\textbf{u}_{\mathcal{S}}(\bm{q}(\mathbf{D}))\leq(2+\varepsilon)r
. Later, we run a binary search over the distances in
\bm{q}(\mathbf{D})
to get a constant approximation for the relational
k
-center clustering.

Main algorithm

Let
\mathcal{T}
consist of the root node
\mathtt{root}
of an RBBD tree over
\bm{q}(\mathbf{D})
as shown in Subsection
4.3
.
Initially, we set
\mathcal{S}=\emptyset
.
We run the following steps for at most
k
iterations.
In the
i
-th iteration, we set
p_{i}=\mathcal{T}.\mathsf{rep}()
and we add
p_{i}
in
\mathcal{S}
.
Then we call
\mathcal{T}.\mathsf{inactive}(p_{i},2r)
.
If after
k
iterations
\mathcal{T}.\mathsf{rep}()\neq\emptyset
then
we return an empty set
\mathcal{S}=\emptyset
.
On the other hand, if

\mathcal{T}.\mathsf{rep}()=\emptyset

within the
k
iterations, then we return
\mathcal{S}
.
The pseudocode of the algorithm is shown in Algorithm
1
.

Analysis

If
r\geq\textbf{u}_{\mathsf{OPT}(\bm{q}(\mathbf{D}))}(\bm{q}(\mathbf{D}))
, we show that the main algorithm returns a non-empty set
\mathcal{S}
.
From Lemma
4.3
, for every new point
p_{i}
all (active) points in
\bm{q}(\mathbf{D})
within distance
2r
become inactive (along with some points within distance
2(1+\varepsilon)r
) by
\mathcal{T}.\mathsf{inactive}(p_{i},2r)
.
Hence, in each iteration, all the points of at least one optimum cluster become inactive, as discussed in Section
3
. So after
k
iterations all points in
\bm{q}(\mathbf{D})
are inactive (i.e.,
\mathcal{T}.rep()=\emptyset
) and
\mathcal{S}\neq\emptyset
.
Hence,
\textbf{u}_{\mathcal{S}}(\bm{q}(\mathbf{D}))\leq 2(1+\varepsilon)r
. By initially setting
\varepsilon\leftarrow\varepsilon/2
, we have that if
r\geq\textbf{u}_{\mathsf{OPT}(\bm{q}(\mathbf{D}))}(\mathbf{D})
then
\textbf{u}_{\mathcal{S}}(\bm{q}(\mathbf{D}))\leq(2+\varepsilon)r
.

We run the
\mathcal{T}.\mathsf{inactive}(\cdot,\cdot)
and the
\mathcal{T}.\mathsf{rep}()
oracles
O(k)
times. Each oracle runs in
O((\varepsilon^{-d+1}+\log N)(N+\varepsilon^{-2}\log^{2}N))
time, with probability at least
1-\frac{1}{N^{m+3}}
, as shown in Section
4.4
.
Overall, the main algorithm runs in
O\left(k\left(\varepsilon^{-d+1}+\log N\right)\left(N+\varepsilon^{-2}\log^{2}N\right)\right)=O(k\cdot N\cdot\log N+k\cdot\log^{3}N)=\tilde{O}\left(k\cdot N\right)
time assuming that
\varepsilon\in(0,1)
is an arbitrary constant,
with probability at least
1-\frac{1}{N^{2}}
.

Complete algorithm

Assume that we run a binary search on the pairwise distances of
\bm{q}(\mathbf{D})
. For each distance
r
selected by the binary search we run the main algorithm. If it returns a non-empty set
\mathcal{S}
then we continue the binary search for smaller values of
r
. Otherwise, we continue with larger values of
r
. In the end, the last computed non-empty set
\mathcal{S}
from the binary search is returned as the final set of centers.
From the analysis of the main algorithm along with the discussion in Section
3
, such algorithm returns a set
\mathcal{S}
such that
\textbf{u}_{\mathcal{S}}(\bm{q}(\mathbf{D}))\leq(2+\varepsilon)\textbf{u}_{\mathsf{OPT}(\bm{q}(\mathbf{D}))}(\bm{q}(\mathbf{D}))
.
Unfortunately, we cannot sort all pairwise distances in
\bm{q}(\mathbf{D})
and then run a binary search on them because we would need
\Omega(|\bm{q}(\mathbf{D})|^{2})
time. While it is not straightforward to run a binary search on
\ell_{2}
pairwise distances, the key idea is to run a binary search over the
\ell_{\infty}
pairwise distances of points in
\bm{q}(\mathbf{D})
.
We show the details of the binary search in Appendix
B
.
Using the fact that for any pair of points
t,p\in\mathbb{R}^{d}
,
||t-p||_{\infty}\leq||t-p||_{2}\leq\sqrt{d}||t-p||_{\infty}
, we prove the next theorem in Appendix
B
.

Theorem 5.1.

Given an acyclic join query
\bm{q}
over
d
attributes, a database instance
\mathbf{D}
of size
N
, a parameter
k
, and an arbitrarily small constant parameter
\varepsilon\in(0,1)
, there exists an algorithm that computes a set
\mathcal{S}\subseteq\bm{q}(\mathbf{D})
of
k
points and a real number
r_{\mathcal{S}}
such that
\textbf{u}_{\mathcal{S}}(\bm{q}(\mathbf{D}))\leq r_{\mathcal{S}}\leq(2\sqrt{d}+\varepsilon)\textbf{u}_{\mathsf{OPT}(\bm{q}(\mathbf{D}))}(\bm{q}(\mathbf{D}))
.
The running time of the algorithm is

O(kN\log^{2}N+k\log^{4}N)
with probability at least
1-\frac{1}{N}
.

Notice that our algorithm from Theorem
5.1
returns an estimation
r_{\mathcal{S}}
of
\textbf{u}_{\mathcal{S}}(\bm{q}(\mathbf{D}))
.
This is useful
in order to derive a better approximation for relational
k
-center clustering in Section
5.2
and a constant approximation for the relational
k
-median/means clustering as shown in Section
6
.

5.2.
Better approximation algorithm

Using our result from Theorem
5.1
, along with the coreset construction from
(
agarwal2024computing
)
, we get the fastest known
(2+\varepsilon)
-approximation algorithm for the relational
k
-center clustering problem. First, we execute the algorithm from Theorem
5.1
and we get
\mathcal{S}
and
r_{\mathcal{S}}
.
Both
\mathcal{S}
and
r_{\mathcal{S}}
are given as input to the coreset construction in
(
agarwal2024computing
)
and we get the main result of this section.

Theorem 5.2.

Given an acyclic join query
\bm{q}
over
d
attributes, a database instance
\mathbf{D}
of size
N
, a parameter
k
, and an arbitrarily small constant parameter
\varepsilon\in(0,1)
, there exists an algorithm that computes a set
\mathcal{S}\subseteq\bm{q}(\mathbf{D})
of
k
points such that
\textbf{u}_{\mathcal{S}}(\bm{q}(\mathbf{D}))\leq(1+\varepsilon)\gamma\textbf{u}_{\mathsf{OPT}(\bm{q}(\mathbf{D}))}(\bm{q}(\mathbf{D}))
.
The running time of the algorithm is

O(kN\log^{2}N+k\log^{4}N+T^{\mathsf{cen}}_{\gamma}(k))
with probability at least
1-\frac{1}{N}
.

For example, if Feder and Greene algorithm
(
feder1988optimal
)
is executed on the coreset constructed by
(
agarwal2024computing
)
then we get a
2(1+\varepsilon)
-approximation solution in
O(k\varepsilon^{-d}\log k)
additional time.
By setting
\varepsilon\leftarrow\varepsilon/2
, the approximation factor becomes
2+\varepsilon
.
The overall asymptotic complexity for arbitrarily small constant
\varepsilon\in(0,1)
is
O(kN\log^{2}N+k\log^{4}N)
.
In Appendix
B
we show an alternative
(2+\varepsilon)
-approximation algorithm with the same running time without constructing the coreset from
(
agarwal2024computing
)
.

6.
k
-Median and
k
-Means Clustering

We focus on the relational
k
-means clustering, while the algorithm for
k
-median follows almost verbatim.
In this section, we first describe a constant approximation algorithm returning
\tilde{O}(k)
centers.
Then, the returned set is given as input to the coreset construction in
(
esmailpour2024improved
)
to derive the final approximation algorithm and get exactly
k
centers (Subsection
6.2
).
Our new tools can also improve the coreset construction from
(
esmailpour2024improved
)
, leading to an even faster algorithm.

6.1.
Constant approximation algorithm with
\tilde{O}(k)
centers

High level idea

We first show a constant approximation algorithm for the relational
k
-median/means problem on
\bm{q}(\mathbf{D})
that runs in only
\tilde{O}(kN)
time, returning a set of
O(k\log^{3}N)
centers.
We propose a modification of the algorithm in
(
har2004coresets
)
in the relational setting.
However, the algorithm of
(
har2004coresets
)
is heavily based on the properties of the standard computational setting, and it is not trivial how to extend it in the relational setting. We use our new tools for constructing an RBBD tree on–the–fly to implement an efficient constant approximation for the relational
k
-means/median problem.

We first execute our relational
k
-center algorithm on
\bm{q}(\mathbf{D})
in order to get a polynomial upper and lower bound on the optimum
k
-means/median cost. At first, all the points in
\bm{q}(\mathbf{D})
are considered active.
Then, the algorithm works in iterations. In the
i
-th iteration, we get a small set
X_{i}
of
\tilde{O}(k)
samples from the active points. Next, tuples in
\bm{q}(\mathbf{D})
that are close enough to
X_{i}
are considered assigned to their closest point in
X_{i}
and are implicitly removed (made inactive) from
\bm{q}(\mathbf{D})
. This procedure is repeated until every point in
\bm{q}(\mathbf{D})
is removed. We note that some points that are assigned to the samples might pay a
k
-median/means cost much larger than the cost they pay in the optimum solution
\mathsf{OPT}(\bm{q}(\mathbf{D}))
. These points are called
bad points
, while the rest points are called
good points
. Similarly to
(
har2004coresets
)
, we show that the number of good points in each iteration is much larger than the number of bad points, allowing us to charge the cost of bad points to the good points. In contrast to
(
har2004coresets
)
, where the authors assign each point (in the standard computational setting) to a center, we use our machinery for implementing an RBBD tree in the relational setting to implicitly assign groups of points in
\bm{q}(\mathbf{D})
to approximately closest centers.

Algorithm

First, we compute
|\bm{q}(\mathbf{D})|
running the first phase of the Yannakakis algorithm
(
yannakakis1981algorithms
)
.
We construct the root node
\mathtt{root}
of the RBBD tree
\mathcal{T}
on
\bm{q}(\mathbf{D})
as described in Section
4.3
.
Let
\mathcal{S}
be the set of points we will return as a solution to
k
-means clustering, and let
r_{\mathcal{S}}
be the estimation of the cost

7.
Extensions

Generality

Our method is quite general: Any algorithm in the standard computational setting that has access to the input data through
\sigma
queries to a BBD tree (using the stored information of count and representative point in each node) can be converted to a randomized algorithm in the relational setting with the same approximation guarantee and running time
O(\sigma\cdot N)
(ignoring logarithmic factors).
As many geometric approximation algorithms fall into this category, our framework yields efficient relational counterparts for a variety of tasks. For example, in Appendix
E
, we show that our new method can be used to implement an approximate version of the Gonzalez algorithm
(
gonzalez1985clustering
)
, leading to efficient algorithms for relational diversity and fairness problems.

Cyclic queries

We use the notion of fractional hypertree width
(
gottlob2014treewidth
)
and apply a standard procedure to extend our algorithms to every join query
\bm{q}
.
For a cyclic query
\bm{q}
, we convert it to an equivalent acyclic query such that each relation is the result of a (possibly cyclic) join query with fractional edge cover at most
\mathsf{fhw}(\bm{q})
. We evaluate the (possibly cyclic) queries to get the new relations and then apply our algorithms to the acyclic query.
All the guarantees are the same as in Theorems
5.2
,
6.6
,
D.1
except for the running time, where we simply replace any
N
factor with
N^{\mathsf{fhw}}
.
Since it is a typical method in database theory, we give the details in Appendix
F
.

8.
Future work

This work opens several directions for future research. A central open question is whether our
\tilde{O}(kN)
-time algorithms for
k
-center/median/means clustering are optimal.
Although our methods outperform the current state-of-the-art, it is interesting to study whether other geometric techniques can be adapted to achieve
\tilde{O}(N)
time algorithms in the relational setting.
We also aim to investigate whether known lower bounds for
k
-center clustering in the standard computational setting
(
feder1988optimal
;
bateni2023optimal
)
can be extended to the relational setting, potentially establishing near-optimal results.

Lemma A.3.

Assume that we can get a random sample set
\mathcal{N}_{u}
from a box or a box with a hole, in
f(n,\varepsilon)
time, where
f
is a positive real function that depends on
n
and
\varepsilon
, then the RBBD tree can be constructed in
O\left(n\log(n)+n\cdot\left(f(n,\varepsilon)+\varepsilon^{-2}\log^{2}n\right)\right)
time, with probability at least
1-\frac{1}{n^{\zeta-1}}
.

Proof.

Since the fair split procedure is identical to the standard BBD tree, all fair split procedures are executed in
O(n\log n)
time using the machinery from the standard BBD tree. Next, we focus on the randomized centroid shrink procedure. For a node
u
we get the set
\mathcal{N}_{u}
in
f(n,\varepsilon)
time. We find the smallest midpoint box
\rho^{\prime}
that contains
\mathcal{N}_{u}
along with the inner box
\square_{u}^{-}
in
O(\varepsilon^{-2}\log n)
time since we explicitly know all points in
\mathcal{N}_{u}
and the corners of
\square_{u}^{+}
, using the highest and lowest values in each coordinate as described in
(
arya1998optimal
)
.
After the computation of
\rho^{\prime}
, we execute
O(1)
fair splits in order to find the first non-trivial fair split. The hyperplane in every fair split is computed straightforwardly in
O(1)
time. Using a simple binary search tree over each coordinate of the points in
\mathcal{N}_{u}
, we can check whether a fair split is trivial in
O(\log(\varepsilon^{-2}\log n))
time. After finding the first non-trivial fair split, we compute
\hat{\rho}
in
O(\log(\varepsilon^{-2}\log n))=O(\log n)
time using the search binary tree that corresponds to the last non-trivial fair split by checking whether
|\hat{\rho}\cap\mathcal{N}_{u}|>|(\rho^{\prime}\setminus\hat{\rho})\cap\mathcal{N}_{u}|
. After each non-trivial split, the box
\hat{\rho}
contains at most
|\rho^{\prime}\cap\mathcal{N}_{u}|-1
samples from
\mathcal{N}_{u}
. Hence, this recursive approach runs for at most
O(|\mathcal{N}_{u}|)=O(\varepsilon^{-2}\log n)
times. Thus, each randomized centroid shrink runs in
O(f(n,\varepsilon)+\varepsilon^{-2}\log^{2}n)
time.
From Lemma
A.2
, the RBBD tree has height
O(\log n)
and
O(n)
nodes with probability at least
1-\frac{1}{n^{\zeta-1}}
, so the running time of all randomized centroid shrink procedures is
O(n(f(n,\varepsilon)+\varepsilon^{-2}\log^{2}n))
, with probability at least
1-\frac{1}{n^{\zeta-1}}
.

We consider the more involved case where

\square_{u}^{+}\setminus\square_{u}^{-}

Before we describe the faster coreset construction from
(

)
, we briefly show that the oracles defined in Section
4.4
can also be defined for boxes, instead of balls.

In the standard computational setting BBD tree can also be used for reporting, counting and sampling queries when the query shape is not a ball but a box
\rho
in
\mathbb{R}^{d}
. The query procedure
\mathcal{T}(\rho)
returns a set of
O(\log n+\varepsilon^{-d+1})
canonical nodes
\mathcal{U}(\rho)
such that
\rho\subseteq\bigcup_{u\in\mathcal{U}(\rho)}\square_{u}\subseteq\rho\oplus\varepsilon_{\rho}
, where
\varepsilon_{\rho}=\varepsilon\cdot\mathsf{diam}(\rho)
,
\mathsf{diam}(\rho)
is the diameter of
\rho
, and
\rho\oplus\varepsilon_{\rho}
is a the Minkowski sum of
\rho
with
\varepsilon_{\rho}
, i.e.,
\rho\oplus\varepsilon_{\rho}
is a superset of
\rho
such that every point of
\rho\oplus\varepsilon_{\rho}
is within distance
\varepsilon\cdot\mathsf{diam}(\rho)
from its closest point in
\rho
.

In the relational setting, having a partially constructed RBBD tree, given a box
\square
, the oracle
\mathcal{T}.\mathsf{inactive}(\square)
makes inactive all points in
\bigcup_{u\in\mathcal{U}(\square)}(\square_{u}\cap\bm{q}(\mathbf{D}))
, similarly to the inactive oracle in Section
4.4
.
Similarly,
\mathcal{T}.\mathsf{count}(\square)
counts all active points in
\bigcup_{u\in\mathcal{U}(\square)}|\square_{u}\cap\bm{q}(\mathbf{D}))|
,
Furthermore, we define the oracle
\mathcal{T}.\mathsf{rep}(\square)
that returns an active point from
\square\cap\bm{q}(\mathbf{D})
. We run the
\mathcal{T}(\square)
query constructing new nodes if necessary (as shown in Section
4.4
), skipping nodes that are already inactive. We compute
\mathcal{U}(\square)
and for a node
u\in\mathcal{U}(\square)
we return
u.rep
.
Using the definitions of the RBBD tree (and BBD tree) if
Q^{\prime}
is the set of active points,
\mathcal{T}.\mathsf{inactive}(\square)
makes inactive the set of points
\bigcup_{u\in\mathcal{U}(\square)}\square_{u}\cap Q^{\prime}
, such that
\square\cap Q^{\prime}\subseteq\bigcup_{u\in\mathcal{U}(\square)}(\square_{u}\cap Q^{\prime})\subseteq(\square\oplus\varepsilon_{\square}\cap Q^{\prime})
.
For count, we notice that the oracle returns a number
\sum_{u\in\mathcal{U}(\square)}|\square_{u}\cap Q^{\prime}|
such that
|\square\cap Q^{\prime}|\leq\sum_{u\in\mathcal{U}(\square)}|\square_{u}\cap Q^{\prime}|\leq|\square\oplus\varepsilon_{\square}\cap Q^{\prime}|

\mathcal{T}.\mathsf{rep}(\square)

The running time of each new oracle is
O((\varepsilon^{-d+1}+\log N)(N+\varepsilon^{-2}\log^{2}N))
, with probability at least

.

(

\square_{1}

\square_{i}.c=|(\square_{i}\setminus(\bigcup_{j<i}\square_{j}))\cap\bm{q}(\mathbf{D})|

\square_{i}

that belong in
\square_{i}
but do not belong in any of the previously defined square-boxes

.
While our goal is not to fully describe their coreset construction, intuitively, every square-box

, as described in Section
4.3
. For every new square-box
\square_{i}
we consider, we execute
\mathcal{T}.\mathsf{count}(\square_{i})
to get the count,
\mathcal{T}.\mathsf{rep}(\square_{i})
to get a representative point, and
\mathcal{T}.\mathsf{inactive}(\square_{i})
to make make all points in
\bigcup_{u\in\mathcal{U}(\square_{i})}\square_{u}\cap\bm{q}(\mathbf{D})
inactive.
Such an algorithm constructs the coreset in
O((\varepsilon^{-d+1}+\log N)(N+\varepsilon^{-2}\log^{2}N)|\mathcal{S}|\varepsilon^{-d}\log N)
time, with high probability. In our case
|\mathcal{S}|=O(k\log^{3}N)
so for arbitrarily small constant
\varepsilon
, the running time is

O(kN\log^{5}N+k\log^{7}N)
.
Finally, we notice that in
(
esmailpour2024improved
)
the authors only compute an estimation of
\square_{i}.c
. Using the RBBD tree we also do not compute the count exactly. Instead, using the guarantees of the RBBD tree, we compute the number of points in each square-box assuming that the boundaries of each box are off by an additional term
\varepsilon\cdot\mathsf{diam}
. Recall from our discussion above that each square-box
\square_{i}
is approximated by
\square_{i}\oplus\varepsilon_{\square_{i}}
. However, this only increases the overall cost by a
(1+\varepsilon)^{2}
factor (since the boxes are square-boxes the diameter defines the maximum distance between two points in each square-box, which is used in
(
esmailpour2024improved
)
to bound the overall error). Setting
\varepsilon\leftarrow\varepsilon/4
, we get exactly the same approximation as in
(
esmailpour2024improved
)
.

Appendix D
Relational clustering on categorical and numerical attributes

In this section, we show how our tree data structure can be integrated with the framework of
(
curtin2020rk
)
to obtain the fastest known algorithms for relational clustering in the presence of both numerical and categorical attributes.
Let
{\mathbf{A}}_{(c)}\subset{\mathbf{A}}
denote the set of categorical attributes, and let
{\mathbf{A}}_{(n)}={\mathbf{A}}\setminus{\mathbf{A}}_{(c)}
denote the set of numerical attributes, with
d_{c}=|{\mathbf{A}}_{(c)}|
and
d_{n}=|{\mathbf{A}}_{(n)}|
.
For simplicity, we assume that each categorical attribute in
{\mathbf{A}}_{(c)}
can take at most
z=O(N)
distinct values.
In the next subsections, we first show how our clustering algorithms extend to join-project queries under bag semantics (ignoring categorical attributes from the clustering objective) and then we combine our results with the framework from
(
curtin2020rk
)
to derive a faster algorithm (than
(
curtin2020rk
)
) considering both the categorical and numerical attributes in the objective.

D.1.
Projecting categorical attributes away: join–project queries under bag semantics

Consider a scenario where the database schema includes categorical attributes
{\mathbf{A}}_{(c)}
, but the objective is to cluster the join results only with respect to their numerical attributes.
Formally, for
X\subseteq{\mathbf{A}}
and
Y\!\!\subseteq\!\!\bm{q}(\mathbf{D})
, let
\bar{\pi}_{X}(Y)
be the multiset

\bar{\pi}_{X}(Y)\!\!=\!\!\{\pi_{X}(t)\!\mid\!t\!\in\!Y\}
.
The only difference from the standard projection operator is that
\bar{\pi}
preserves duplicates (this is equivalent to the project operator in
bag semantics
).
Given a join query
\bm{q}
over a database instance
\mathbf{D}
, the goal is to cluster

\bar{\bm{q}}(\mathbf{D})=\bar{\pi}_{{\mathbf{A}}_{(n)}}(\bm{q}(\mathbf{D}))
,
that is, the projection of
\bm{q}(\mathbf{D})
onto the numerical attributes
{\mathbf{A}}_{(n)}
under bag semantics.

All our algorithms from Theorems
5.2
and
6.5
naturally extend to this setting with the same approximation and time guarantees.
The RBBD-tree is now defined only on the
d_{n}
numerical attributes
{\mathbf{A}}_{(n)}
, and for every box (or box with a hole)
\rho
, all operations from Lemma
2.1
can be performed on
\bar{\bm{q}}(\mathbf{D})\cap\rho
in
O(N)
time.
For instance, sampling a tuple uniformly at random from
\bar{\bm{q}}(\mathbf{D})\cap\rho
is equivalent to sampling uniformly at random a tuple from

\{t\in\bm{q}(\mathbf{D})\mid\pi_{{\mathbf{A}}_{(n)}}(t)\in\rho\}
.
More generally, all RBBD-tree operations used by our algorithms, such as counting, reporting, or sampling tuples within a box, on the result of a projected join query
\bar{\bm{q}}
under bag semantics can be straightforwardly implemented on the corresponding join query
\bm{q}
under set semantics.
Therefore, all our algorithms can be executed on join–project queries under bag semantics while preserving the same approximation and time guarantees.

Remark

While our algorithms do not generally extend to join-project queries under set semantics, they remain applicable in cases where tuple multiplicities do not affect the objective value. Notably, this includes the relational
k
-center clustering problem (Section
5
) and the Relational Remote Edge problem (Appendix
E.3
), for which join-project queries under set and bag semantics produce equivalent instances.

D.2.
Clustering with both numerical and categorical attributes

We focus on the
k
-means clustering problem as in
(
curtin2020rk
)
; however, all our results can be extended to relational
k
-center and
k
-median clustering as well.
In machine learning, a common approach for handling categorical variables is to apply
one-hot encoding
, which converts each categorical variable into a binary representation.
For example, consider a categorical attribute
A\in{\mathbf{A}}
that can take
z
distinct values.
Assume an arbitrary but fixed ordering of these values.
Then, the
j
-th value of
A
can be represented by a binary vector with a
1
in the
j
-th position and
0
elsewhere.

Expensive algorithm

In the relational setting we can replace each categorical attribute
A\in{\mathbf{A}}_{(c)}
with
z
binary attributes
A_{1}^{(\mathrm{bin})},\ldots,A_{z}^{(\mathrm{bin})}
.
Each tuple
t
in a relation
R
containing attribute
A
is replaced by a new tuple
t^{\prime}
such that if
\pi_{A}(t)
corresponds to the
j
-th value of
A
, then
\pi_{A_{j}^{(\mathrm{bin})}}(t^{\prime})=1
and
\pi_{A_{h}^{(\mathrm{bin})}}(t^{\prime})=0
for every
h\in[z]\setminus\{j\}
.
After this transformation, the join query
\bm{q}
involves
m
relations and a total of
d_{n}+d_{c}\cdot z
numerical attributes.
Thus, the distance function
\phi(\cdot,\cdot)
remains a Euclidean metric over numerical attributes.
By Theorem
6.5
, we obtain a
5\gamma
-approximation algorithm (for
\varepsilon=1
) for the relational
k
-means problem involving both numerical and categorical attributes, with a data complexity of

\tilde{O}(2^{z}kN+T^{\mathsf{mean}}_{\gamma}(2^{z}k))
.
When
z=O(1)
, this matches the running time established in Theorem
6.5
.
However, in practice,
z
may be large. For instance, a categorical attribute may represent countries, colors, or product categories making the above approach impractical due to its exponential dependence on
z
.
Next, we show an alternative algorithm for relational
k
-means clustering that avoids explicit one-hot encoding and whose running time does not depend exponentially on
z
.

Known algorithm
(
curtin2020rk
)

First, all dangling tuples are removed from the database.
For every attribute
A\in{\mathbf{A}}
, let
S_{A}
denote the set of all values of
A
that appear in the database instance
\mathbf{D}
; that is,
S_{A}=\mathsf{adom}_{\mathbf{D}}(A)
.
For each value
x\in S_{A}
, they compute the weight

w(x)=\sum_{t\in\bm{q}(\mathbf{D})}1[\pi_{A}(t)=x]
,
representing the number of join results whose projection on attribute
A
equals
x
.
Using Yannakakis’ algorithm, all weights
w(x)
over all values
x\in\mathsf{adom}(A)
and attributes
A\in{\mathbf{A}}
can be computed in
\tilde{O}(N)
time.
Then, for each attribute
A\in{\mathbf{A}}
, two cases are distinguished.
If
A\in{\mathbf{A}}_{(c)}
, they apply a simple and efficient procedure to compute the optimal
k
-means clustering of the weighted categorical set
S_{A}
in
\tilde{O}(N)
time.
If
A\in{\mathbf{A}}_{(n)}
, they invoke
(
gronlund2017fast
;
wu1991optimal
;
fleischer2006online
)
to compute the optimal
k
-means clustering of the weighted numerical set
S_{A}
in
\tilde{O}(kN)
time.
In either case, let
C_{A}
denote the resulting set of
k
centers for attribute
A
.
After computing
C_{A}
for all attributes
A\in{\mathbf{A}}
, they construct the grid

C=\bigtimes_{A\in{\mathbf{A}}}C_{A}
,
which contains all possible combinations of centers across attributes.
Note that
|C|=O(k^{d})
, where
d=|{\mathbf{A}}|
is the total number of attributes.
For each center
p\in C
, they compute a weight
\omega(p)
, defined as the number of tuples in
\bm{q}(\mathbf{D})
that have
p
as their closest center.
Using the techniques of Lemma
2.1
, each weight
\omega(p)
can be computed in
\tilde{O}(N)
time.
It is shown that the weighted set
C

(with the weight function
\omega
)
defines a coreset for the relational
k
-means clustering.
Running a
\gamma
-approximation algorithm for
k
-means
on the weighted set
C
yields a set of
k
centers
\mathcal{S}
such that

\mu_{\mathcal{S}}(\bm{q}(\mathbf{D}))\leq(2\sqrt{\gamma}+1)^{2}\,\mu_{\mathsf{OPT}(\bm{q}(\mathbf{D}))}(\bm{q}(\mathbf{D}))
.
The running time of the algorithm is

\tilde{O}(k^{d}N+T^{\mathsf{mean}}_{\gamma}(k^{d}))
.

Our algorithm

We design a faster algorithm by leveraging our new results to handle the numerical attributes more efficiently.
We begin by processing the categorical attributes following the approach of
(
curtin2020rk
)
:
For each
A\in{\mathbf{A}}_{(c)}
, we construct
S_{A}
and compute the weight
w(x)
for every
x\in S_{A}
in the same manner as
(
curtin2020rk
)
.
We then apply the straightforward algorithm for optimal
k
-means clustering on the weighted set
\mathsf{adom}(A)
and let
C_{A}
denote the optimal set of centers.
Next, we process the numerical attributes
{\mathbf{A}}_{(n)}
.
Unlike
(
curtin2020rk
)
, we process all numerical attributes simultaneously.
Specifically, we execute the relational
k
-means algorithm from Theorem
6.5
while skipping the categorical attributes, i.e., we run the algorithm on

\bar{q}(\mathbf{D})=\bar{\pi}_{{\mathbf{A}}_{(n)}}(\bm{q}(\mathbf{D}))
,
as described in Appendix
D.1
.
Let
C^{\prime}
be the resulting set of
k
centers.
It is important to note that we do
not
remove duplicates in
\bar{q}(\mathbf{D})
, since our algorithm inherently accounts for the correct weighting of the tuples.
In particular, running
k
-means clustering directly on
\bar{q}(\mathbf{D})

is equivalent to running
k
-means clustering on the weighted set
\pi_{{\mathbf{A}}_{(n)}}(\bm{q}(\mathbf{D}))
with weights

w(p)=\sum_{t\in\bm{q}(\mathbf{D})}1[\pi_{{\mathbf{A}}_{(n)}}(t)=p]
.

We then construct the set of candidate centers as

C=C^{\prime}\times\left(\bigtimes_{A\in{\mathbf{A}}_{(c)}}C_{A}\right)
.
Unfortunately, unlike
(
curtin2020rk
)
, we cannot directly compute, for each
p\in C
, the exact number of tuples in
\bm{q}(\mathbf{D})
that have
p
as their closest center in
C
.
Instead, we use our ideas from the RBBD-tree construction in the relational setting to approximately count the number of tuples that are closest to each center
p\in C
.
For every
p\in C
, we compute an approximate weight

\bar{\omega}(p)=|\{t\in\bm{q}(\mathbf{D})\mid\iota(t)=p\}|
,
where
\iota:\bm{q}(\mathbf{D})\rightarrow C
is a function assigning each tuple
t\in\bm{q}(\mathbf{D})
to a center in
C
, satisfying

\sum_{t\in\bm{q}(\mathbf{D})}\phi^{2}(t,\iota(t))\leq 2\,\mu_{\mathsf{OPT}(\bm{q}(\mathbf{D}))}(\bm{q}(\mathbf{D}))
.
This is equivalent to the process of first clustering the tuples in
\bar{\bm{q}}(\mathbf{D})
according to Theorem
6.5
with an approximation factor of
2\cdot 5\gamma
(instead of
5\gamma
), and subsequently computing the true weights
\omega(p)
(recall that
\omega(p)
is the number of tuples in
\bm{q}(\mathbf{D})
that have
p
as their closest center).
We show the details of computing the weight
\bar{\omega}(\cdot)
in Appendix
D.3
.
Finally, we run a
k
-means clustering algorithm
on the weighted set
C
, obtaining a set
\mathcal{S}
of
k
final centers.

Theorem D.1.

Given an acyclic join query
\bm{q}
with
d_{n}
numerical and
d_{c}
categorical attributes, a database instance
\mathbf{D}
of size
N
, and a parameter
k
, there exists an algorithm that computes a set
\mathcal{S}\subseteq\bm{q}(\mathbf{D})
of
k
points such that

\mu_{\mathcal{S}}(\bm{q}(\mathbf{D}))\leq\left((\sqrt{10}+1)\sqrt{\gamma}+\sqrt{10}\gamma\right)^{2}\!\!\mu_{\mathsf{OPT}(\bm{q}(\mathbf{D}))}(\bm{q}(\mathbf{D}))
in
\tilde{O}(k^{d_{c}+1}N+T^{\mathsf{mean}}_{\gamma}(k^{d_{c}+1}))
time, with probability at least
1-\frac{1}{N}
.

Proof.

From Appendix
D.3
, we have that

\sum_{t\in\bm{q}(\mathbf{D})}\phi^{2}(t,\iota(t))\leq 2\,\mu_{\mathsf{OPT}(\bm{q}(\mathbf{D}))}(\bm{q}(\mathbf{D}))
.
This is equivalent to the process of first clustering
\bar{\bm{q}}(\mathbf{D})
according to Theorem
6.5
with an approximation error of
2\cdot 5\gamma
(instead of
5\gamma
) and then computing the exact weights
\omega(p)
.
Following the analysis in
(
curtin2020rk
)
, the overall approximation factor becomes

((\sqrt{10}+1)\sqrt{\gamma}+\sqrt{10}\gamma)^{2}
.

For each categorical attribute
A\in{\mathbf{A}}_{(c)}
, the set of centers
C_{A}
is computed in
\tilde{O}(N)
time, as discussed before.
The algorithm from Theorem
6.5
, when applied to
\bar{\pi}_{{\mathbf{A}}_{(n)}}(\bm{q}(\mathbf{D}))
, runs in
\tilde{O}(kN+T^{\mathsf{mean}}_{\gamma}(k))
time with high probability.
Since
|C|=O(k^{d_{c}+1})
, all weights
\bar{\omega}(p)
for
p\in C
is computed in
\tilde{O}(k^{d_{c}+1})
time (see Appendix
D.3
).
Finally, the
k
-means clustering on the weighted set
C
is executed in
\tilde{O}(T^{\mathsf{mean}}_{\gamma}(k^{d_{c}+1}))
time.
Overall, the total running time of our algorithm is

\tilde{O}(k^{d_{c}+1}N+T^{\mathsf{mean}}_{\gamma}(k^{d_{c}+1}))
, with high probability.
∎

D.3.
Approximate Closest Centers

Recall that
\bar{\bm{q}}(\mathbf{D})=\bar{\pi}_{{\mathbf{A}}_{(n)}}(\bm{q}(\mathbf{D}))
, and note that
|\bar{\bm{q}}(\mathbf{D})|=|\bm{q}(\mathbf{D})|
.

We design an algorithm that efficiently computes an estimation
\bar{\omega}(p)
of the weight
\omega(p)
for all
p\in C
.
We use the oracles introduced in Section
4.4
, with a few minor modifications. Recall that for each node
u
of a partially constructed RBBD-tree
\mathcal{T}
, we store the corresponding box (or box with a hole)
\square_{u}
, the binary variable
u.a
, the representative point
u.\mathrm{rep}
, and the counter
u.c
. In our modified version, we additionally store and maintain
k^{d_{c}}
auxiliary counters at every constructed node of
\mathcal{T}
.
More specifically, for each node
u\in\mathcal{T}
, we maintain counters of the form
u(i_{1},i_{2},\ldots,i_{d_{c}})
, where
1\leq i_{j}\leq k
for every
j\in[d_{c}]
. Each counter is defined as

u(i_{1},i_{2},\ldots,i_{d_{c}})\!=\!|\{t\in\bm{q}(\mathbf{D})\!\mid\!\pi_{{\mathbf{A}}_{(n)}}(t)\in\square_{u},\forall A^{(j)}\!\in\!{\mathbf{A}}_{(c)},\phi(\pi_{A^{(j)}}(t),C_{A^{(j)}})=\phi(\pi_{A^{(j)}}(t),C_{A^{(j)}}[i_{j}])\}|,

where
C_{A^{(j)}}[i_{j}]
denotes the
i_{j}
-th point in
C_{A^{(j)}}
(under an arbitrary but fixed ordering).
Intuitively, each counter
u(i_{1},i_{2},\ldots,i_{d_{c}})
stores the number of tuples in
\bm{q}(\mathbf{D})
whose projection on the numerical attributes lies within
\square_{u}
, and whose projection on each categorical attribute
A^{(j)}
is closest to the
i_{j}
-th center in
C_{A^{(j)}}
.

We first describe how to compute
u(i_{1},i_{2},\ldots,i_{d_{c}})
for a newly constructed node
u\in\mathcal{T}
.
Assume that
\square_{u}
is a box without a hole; if it contains a hole, we simply repeat the procedure for each of the
2d_{n}
non-intersecting boxes, as explained in Appendix
A.3
.
Following the approach of Lemma
2.1
(originally described in
(
agarwal2024computing
)
), for every relation
R\in{\mathbf{R}}
we identify all tuples
t\in R
such that: for every
A\in{\mathbf{A}}(R)\cap{\mathbf{A}}_{(n)}
,
\pi_{A}(t)\in\pi_{A}(\square_{u})
, and for every
A^{(j)}\in{\mathbf{A}}(R)\cap{\mathbf{A}}_{(c)}
,
\pi_{A^{(j)}}(t)
has the
i_{j}
-th center in
C_{A^{(j)}}
as its closest center. All other tuples are discarded. Let
R^{\prime}\subseteq R
denote the remaining tuples in relation
R
. We then execute the counting version of Yannakakis’ algorithm on the join
\Join_{R\in{\mathbf{R}}}R^{\prime}
and set
u(i_{1},i_{2},\ldots,i_{d_{c}})=|\Join_{R\in{\mathbf{R}}}R^{\prime}|
in
O(N)
time. The correctness follows directly from the definition of
R^{\prime}
. Since Yannakakis’ algorithm is executed
k^{d_{c}}
times, constructing a new node in
\mathcal{T}
takes
O(k^{d_{c}}N)
time.
We update the value of
u(i_{1},i_{2},\ldots,i_{d_{c}})
similarly to
u.c
after marking new inactive nodes. For instance, consider a node
u
with children
\hat{v}
and
\bar{v}
.
By definition, it holds that
u(i_{1},i_{2},\ldots,i_{d_{c}})=\hat{v}(i_{1},i_{2},\ldots,i_{d_{c}})+\bar{v}(i_{1},i_{2},\ldots,i_{d_{c}})
. If
\hat{v}
becomes inactive, then
u(i_{1},i_{2},\ldots,i_{d_{c}})=\bar{v}(i_{1},i_{2},\ldots,i_{d_{c}})
.

For a ball
\mathcal{B}(x,r)
, let
\mathcal{T}.\widebar{\mathsf{inactive}}(x,r)
be defined similarly to
\mathcal{T}.\mathsf{inactive}(x,r)
, except that it also updates all values
u(i_{1},i_{2},\ldots,i_{d_{c}})
as described above.
Furthermore, let
\mathcal{T}.\widebar{\mathsf{count}}(x,r)
denote an oracle analogous to
\mathcal{T}.\mathsf{count}(x,r)
, with the only difference being that it returns
k^{d_{c}}
counters.
Specifically, for every
(i_{1},\ldots,i_{d_{c}})\in[k]^{d_{c}}
, it returns a counter
\tau(i_{1},\ldots,i_{d_{c}})=\sum_{u\in\mathcal{U}(x,r)}u(i_{1},\ldots,i_{d_{c}})
.

Algorithm

After defining the new oracles
\mathcal{T}.\widebar{\mathsf{inactive}}(x,r)
and
\mathcal{T}.\widebar{\mathsf{count}}(x,r)
, we proceed with the main algorithm for setting the weights.
Initially, we set
\bar{\omega}(c)=0
for every
c\in C
.

As in the first step of the algorithm from Section
6
, we compute a value
L
such that
\frac{L^{2}}{9}\leq\mu_{\mathsf{OPT}(\bar{\bm{q}}(\mathbf{D}))}(\bar{\bm{q}}(\mathbf{D}))\leq\mu_{C^{\prime}}(\bar{\bm{q}}(\mathbf{D}))\leq|\bm{q}(\mathbf{D})|^{3}\cdot L^{2}
.

For every
i\in\{0,1,\ldots,O(\frac{1}{\varepsilon}\log N)\}
, we set
r=(1+\varepsilon)^{i}\frac{L}{9|\bm{q}(\mathbf{D})|}
and repeat the following steps for each
c^{\prime}\in C^{\prime}
.
We call the function
\mathcal{T}.\widebar{\mathsf{count}}(c^{\prime},r)
, and for every
(i_{1},\ldots,i_{d_{c}})\in[k]^{d_{c}}
, we update
\bar{\omega}(p)=\bar{\omega}(p)+\tau(i_{1},\ldots,i_{d_{c}})
, for every
p\in C
such that
\pi_{{\mathbf{A}}_{(n)}}(p)=c^{\prime}
and, for every
A^{(j)}\in{\mathbf{A}}_{(c)}
,
\pi_{A^{(j)}}(p)
is the
i_{j}
-th center in
C_{A^{(j)}}
.
We then call
\mathcal{T}.\widebar{\mathsf{inactive}}(c^{\prime},r)
.

Analysis

Let
\iota:\bm{q}(\mathbf{D})\rightarrow C
be the assignment function that maps each tuple in
\bm{q}(\mathbf{D})
to a center in
C
according to our algorithm. In particular, when a tuple
t\in\bm{q}(\mathbf{D})
contributes to
\bar{\omega}(p)
for a unique
p\in C
, we set
\iota(t)=p
. By definition,
\bar{\omega}(p)=|\{t\in\bm{q}(\mathbf{D})\mid\iota(t)=p\}|
.

Since
\mu_{C^{\prime}}(\bar{\bm{q}}(\mathbf{D}))\leq|\bm{q}(\mathbf{D})|^{3}L^{2}
, we have
\phi(\pi_{{\mathbf{A}}_{(n)}}(t),C^{\prime})\leq|\bm{q}(\mathbf{D})|^{3/2}L
, and the maximum radius considered for
r
is greater than
|\bm{q}(\mathbf{D})|^{3/2}L
. Hence, every tuple
t\in\bm{q}(\mathbf{D})
is assigned to at least one center in
C
.

Lemma D.2.

\sum_{t\in\bm{q}(\mathbf{D})}\phi^{2}(t,\iota(t))\leq(1+\varepsilon)\mu_{\mathsf{OPT}(\bm{q}(\mathbf{D}))}(\bm{q}(\mathbf{D}))
.

Proof.

Let
t\in\bm{q}(\mathbf{D})
be a tuple assigned to a center in
C
for some radius
r>\frac{L}{9|\bm{q}(\mathbf{D})|}
, and let
\bm{q}_{1}(\mathbf{D})\subseteq\bm{q}(\mathbf{D})
be the set of such tuples. By the correctness of the RBBD-tree,
\pi_{{\mathbf{A}}_{(n)}}(t)\notin\bigcup_{c^{\prime}\in C^{\prime}}\mathcal{B}(c^{\prime},r/(1+\varepsilon))
, implying
\phi(\pi_{{\mathbf{A}}_{(n)}}(t),\pi_{{\mathbf{A}}_{(n)}}(\iota(t)))\leq(1+\varepsilon)^{2}\phi(\pi_{{\mathbf{A}}_{(n)}}(t),C^{\prime})
. Moreover, by construction, for every
A\in{\mathbf{A}}_{(c)}
,
\pi_{A}(\iota(t))\in C_{A}
is the closest center of
\pi_{A}(t)
in
C_{A}
. Thus,
\phi(t,\iota(t))\leq(1+\varepsilon)^{2}\phi(t,C)
.

Now let
t\in\bm{q}(\mathbf{D})
be a tuple assigned to a center in
C
for
r=\frac{L}{9|\bm{q}(\mathbf{D})|}
, and let
\bm{q}_{2}(\mathbf{D})\subseteq\bm{q}(\mathbf{D})
denote these tuples. Then, we have
\phi(t,\iota(t))\leq(1+\varepsilon)\frac{L}{9|\bm{q}(\mathbf{D})|}
.

Combining the two cases, we have

\sum_{t\in\bm{q}(\mathbf{D})}\phi^{2}(t,\iota(t))=\sum_{t\in\bm{q}_{1}(\mathbf{D})}\phi^{2}(t,\iota(t))+\sum_{t\in\bm{q}_{2}(\mathbf{D})}\phi^{2}(t,\iota(t))\leq(1+\varepsilon)^{4}\sum_{t\in\bm{q}(\mathbf{D})}\phi^{2}(t,C)+(1+\varepsilon)^{2}\frac{L^{2}}{81|\bm{q}(\mathbf{D})|}\leq(1+2\varepsilon)^{4}\mu_{\mathsf{OPT}(\bm{q}(\mathbf{D}))}(\bm{q}(\mathbf{D}))
.
Setting
\varepsilon\leftarrow\varepsilon/12
yields the desired bound
\sum_{t\in\bm{q}(\mathbf{D})}\phi^{2}(t,\iota(t))\leq(1+\varepsilon)\mu_{\mathsf{OPT}(\bm{q}(\mathbf{D}))}(\bm{q}(\mathbf{D}))
.
∎

The overall running time of the algorithm is
\tilde{O}(k^{d_{c}+1}N)
, since it executes
\tilde{O}(k)
oracle calls, each running in
\tilde{O}(k^{d_{c}}N)
time to compute and update the counters
u(i_{1},\ldots,i_{d_{c}})
.

Appendix E
Extensions to other optimization problems

Using our machinery from the previous sections, we show how we can implement efficient algorithms for various optimization problems in diversity and fairness. First, we show how to implement an oracle that computes (approximately) the farthest point in
\bm{q}(\mathbf{D})
from a given set of points
S
. Then, we show an
\tilde{O}(kN)
time approximate implementation of the well-known Gonzalez algorithm
(
gonzalez1985clustering
)
in the relational setting. Gonzalez algorithm is used to solve various problems in diversity and fairness.

We first start with some definitions.

Gonzalez algorithm

Gonzalez algorithm
(
gonzalez1985clustering
)
is a well-known and powerful algorithm that is used to derive constant approximation algorithms for multiple combinatorial optimization problems such as clustering and diversity problems
(
ravi1994heuristic
;
tamir1991obnoxious
)
. The algorithm is quite simple in the standard computational setting: Let
P
be a set of
n
points in
\mathbb{R}^{d}
and let
C=\emptyset
be an initially empty set to be returned. Gonzalez algorithm runs in
k
iterations. In each iteration, we find the point
\argmax_{p\in P\setminus C}\phi(p,C)
and add it to the set
C
. A naive implementation of the Gonzalez algorithm runs in
O(nk)
time. In the Euclidean space, the running time can be improved to
O(n\log k)
.

Definition E.1 (Relational implementation of Gonzalez algorithm).

Given a database instance
\mathbf{D}
, a join query
\bm{q}
, and a positive parameter
k
, the goal is to implement the Gonzalez algorithm for
k
iterations. Namely, given a set
\mathcal{S}
with
|\mathcal{S}|<k
, compute a point
p\in\bm{q}(\mathbf{D})
such that
\phi(p,\mathcal{S})=\max_{q\in\bm{q}(\mathbf{D})\setminus\mathcal{S}}\phi(q,\mathcal{S})
.

We also define the
\varepsilon
-approximate implementation of the Gonzalez algorithm
. In every iteration of a relational
\varepsilon
-approximate implementation of the Gonzalez algorithm, a point
p\in\bm{q}(\mathbf{D})\setminus\mathcal{S}
is added in
\mathcal{S}
such that
\phi(p,\mathcal{S})\geq(1-\varepsilon)\max_{q\in\bm{q}(\mathbf{D})\setminus\mathcal{S}}\phi(q,\mathcal{S})
.

E.1.
Compute the farthest point

Let
S\subseteq\bm{q}(\mathbf{D})
be a subset of
\bm{q}(\mathbf{D})
with
|S|<k
. The goal is to compute a point
p\in\bm{q}(\mathbf{D})\setminus S
such that
\phi(p,S)=\max_{t\in\bm{q}(\mathbf{D})\setminus S}\phi(t,S)
. We propose an algorithm that runs in
\tilde{O}(kN)
time to solve this problem approximately, i.e., we compute a point
p\in\bm{q}(\mathbf{D})\setminus S
such that
\phi(p,S)\geq(1-\varepsilon)\max_{t\in\bm{q}(\mathbf{D})\setminus S}\phi(t,S)
, for an arbitrarily small constant
\varepsilon
.

High level idea

The high-level idea is to guess
\max_{t\in\bm{q}(\mathbf{D})}\phi(t,S)
running a binary search similar to the binary search in Section
5
. For every distance
r
we guess, we check whether the balls
\bigcup_{s\in S}B(s,r)
cover all points in
\bm{q}(\mathbf{D})
, using the RBBD data structure. If yes, then we continue the binary search for smaller values of
r
. If not, i.e., there are still active nodes in the RBBD tree, we continue the binary search for larger values of
r
. From the last iteration where
\bigcup_{s\in S}B(s,r)
does not cover all points in
\bm{q}(\mathbf{D})
,
we add in
S
any point from
\bm{q}(\mathbf{D})
that does not have an inactive ancestor in the RBBD tree. The distance from this point to
S
will be a good approximation of the maximum distance of any point in
\bm{q}(\mathbf{D})
from
S
.

Algorithm

Let
S\subseteq\bm{q}(\mathbf{D})
.
We construct the root node
\mathtt{root}
of an RBBD tree
\mathcal{T}
over
\bm{q}(\mathbf{D})
as described in Section
4.3
.

We run the binary search as in Section
5
.
The only difference is that if
\hat{r}
is the
z
-th smallest distance returned by
(
salowe1989infinity
)
, we run another binary search in the range
[\hat{r},\sqrt{d}\hat{r}]
. Notice that for any pair of points
t,q\in\mathbb{R}^{d}
,
||t-q||_{\infty}\leq||t-q||_{2}\leq\sqrt{d}||t-q||_{\infty}
. Hence, if we discretize
[\hat{r},\sqrt{d}\hat{r}]
by a relative step
(1+\varepsilon)
, i.e.,
Y_{\hat{r}}=\{\hat{r}(1+\varepsilon)^{0},\hat{r}(1+\varepsilon)^{1},\hat{r}(1+\varepsilon)^{2},\ldots,\hat{r}(1+\varepsilon)^{\log(\sqrt{d})/\varepsilon}\}
and we run a binary search on
Y_{\hat{r}}
in the end the binary search will end up at a distance
r^{*}
where the algorithm satisfies a property at distance
r^{*}
but does not satisfy the same property at distance
(1+\varepsilon)r^{*}
. This is related to the binary search we run in Appendix
B.1
.

Let
r
be one of the distances returned by the binary search.
For every point
s\in S
, we run
\mathcal{T}.\mathsf{inactive}(s,r)
.
After repeating the procedure above for every
s\in S
, we call
\mathcal{T}.\mathsf{rep}()
. If it returns
\emptyset
we continue the binary search with smaller values of
r
, otherwise we continue the binary search with larger values of
r
.
Before we continue in the next iteration of the binary tree we modify
\mathcal{T}
making all its nodes active again and setting the initial representative points on their nodes.
In the end of this binary search, let
r^{\prime}
be the last (largest) distance we found where

p=\mathcal{T}.\mathsf{rep}()\neq\emptyset
. We return
p
.

Correctness

Lemma E.2.

\phi(p,S)\geq\frac{1}{(1+\varepsilon)^{2}}\max_{t\in\bm{q}(\mathbf{D})\setminus S}\phi(t,S)
.

Proof.

The algorithm executes
\tilde{O}(k)
oracles from Section
4.4
. If
r^{\prime}
was the largest distance found by the binary search such that
\mathcal{T}.\mathsf{rep}\neq\emptyset
, we have that
\phi(p,S)>r^{\prime}
.

Recall, that the binary search (as defined in Appendix
B
) is executed on the
\ell_{\infty}
pairwise distances of
\bm{q}(\mathbf{D})
and then discretize the ranges
[r,\sqrt{d}r]
by a factor
(1+\varepsilon)
. By definition, in the execution of binary search, for
r^{\prime\prime}=(1+\varepsilon)r^{\prime}
we had that
\mathcal{T}.\mathsf{rep}()=\emptyset
, otherwise
r^{\prime}
would not be the largest distance we found with
\mathcal{T}.\mathsf{rep}()\neq\emptyset
. By the properties of RBBD tree from Section
4
, we have that
every point
q\in\bm{q}(\mathbf{D})
is inactive, i.e., there exists
s\in S
such that
q\in\bigcup_{u\in\mathcal{U}(s,r^{\prime\prime})}(\square_{u}\cap\bm{q}(\mathbf{D}))
. Since the RBBD tree approximates the balls within a factor
(1+\varepsilon)
, we have that for every
q\in\bm{q}(\mathbf{D})
,
\phi(q,S)\leq(1+\varepsilon)r^{\prime\prime}
. Hence,
\max_{t\in\bm{q}(\mathbf{D})\setminus S}\phi(t,S)\leq(1+\varepsilon)r^{\prime\prime}
.
We conclude that
\phi(p,S)>r^{\prime}=\frac{r^{\prime\prime}}{1+\varepsilon}\geq\frac{1}{(1+\varepsilon)^{2}}\max_{t\in\bm{q}(\mathbf{D})\setminus S}\phi(t,S)
.
∎

Notice that
\frac{1}{(1+\varepsilon/2)^{2}}\geq 1-\varepsilon
, so if we set
\varepsilon\leftarrow\varepsilon/2
, we get
\phi(p,S)\geq(1-\varepsilon)\max_{t\in\bm{q}(\mathbf{D})\setminus S}\phi(t,S)
.

Lemma E.3.

The running time of the algorithm is
O\left(k(\varepsilon^{-d+1}+\log N)(N+\varepsilon^{-2}\log^{2}N)\log N\right)
, with probability at least
1-\frac{1}{N}
.

Proof.

The binary search runs in
O(\log N)
iterations. In order to compute a distance in each step of the binary search we spend
O(N\log N)
time as shown in Appendix
B
. Hence all values for the binary search is computed in
O(N\log^{2}N)
time. For each step of the binary search, the
\mathcal{T}.\mathsf{inactive}(s,r)
oracle runs in
O((\varepsilon^{-d+1}+\log N)(N+\varepsilon^{-2}\log^{2}N))
with probability at least
1-\frac{1}{N^{m+2}}
and the
\mathcal{T}.\mathsf{rep}()
runs in
O(1)
time.
Hence, the overall running time of our algorithms is
O(N\log^{2}N+k(\varepsilon^{-d+1}+\log N)(N+\varepsilon^{-2}\log^{2}N)\log N)=O(k(\varepsilon^{-d+1}+\log N)(N+\varepsilon^{-2}\log^{2}N)\log N)
, with probability at least
1-\frac{1}{N}
.
∎

Theorem E.4.

Given an acyclic query
\bm{q}
, a database instance
\mathbf{D}
of size
N
, an arbitrarily small constant parameter
\varepsilon
, and a set
S\subseteq\bm{q}(\mathbf{D})
with
|S|<k
, a point
p\in\bm{q}(\mathbf{D})\setminus S
can be computed such that
\phi(p,S)\geq(1-\varepsilon)\max_{t\in\bm{q}(\mathbf{D})\setminus S}\phi(t,S)
in
O(kN\log^{2}N+k\log^{4}N)
time, with probability at least
1-\frac{1}{N}
.

Starting from
S=\emptyset
and repeating the algorithm from Theorem
E.4

k
times, we get an
\varepsilon
-approximate implementation of the Gonzalez algorithm in the relational setting in
O(k^{2}N\log^{2}N+k^{2}\log^{4}N)
time.
Next, we show an even faster implementation of the Gonzalez algorithm using our relational
k
-center clustering algorithm from Theorem
5.2
.

E.2.
Implementation of Gonzalez Algorithm in the Relational Setting

We propose an
\tilde{O}(kN)
execution of an
\varepsilon
-approximate implementation of the Gonzalez algorithm. Such an implementation will allow us to derive faster algorithms for multiple diversity and fairness problems in the relational setting.

In the standard computational setting, the next argument is known
(
kurkure2024faster
)
. Let
P\subset\mathbb{R}^{d}
and
S\subseteq P
be a set of
k^{\prime}=O(k\varepsilon^{-d})
centers returned by a
(2+\varepsilon)
-approximation algorithm for the
k^{\prime}
-center clustering problem. An implementation of the Gonzalez algorithm on
S
for
k
steps returns an
\varepsilon
-approximate implementation of the Gonzalez algorithm on
P
.

In the relational setting, given a parameter
k
, we run our algorithm from Theorem
5.2
using the parameter
k^{\prime}=O(k\varepsilon^{-d})
(instead of
k
). Let
S\subseteq\bm{q}(\mathbf{D})
be the set of centers returned by our algorithm with
|S|=O(k\varepsilon^{-d})
such that
\textbf{u}_{S}(\bm{q}(\mathbf{D}))\leq(1+\varepsilon)\textbf{u}_{\mathsf{OPT}(\bm{q}(\mathbf{D}))}(\bm{q}(\mathbf{D}))
, with probability at least
1-\frac{1}{N}
. Finally, we run the geometric implementation of Gonzalez algorithm
(
feder1988optimal
)
on
S
for
k
iterations and let
\mathcal{S}
be the returned set. From
(
feder1988optimal
)
and the correctness of Theorem
5.2
, we get that
\mathcal{S}
is the result of an
\varepsilon
-implementation of the Gonzalez algorithm on
\bm{q}(\mathbf{D})
.
The running time to get
S
is
O(k\varepsilon^{-d}n\log^{2}N+k\varepsilon^{-d}\log^{4}N)
with probability at least
1-\frac{1}{N}
(Theorem
5.2
for
k^{\prime}=O(k\varepsilon^{-d})
instead of
k
). Furthermore, the geometric implementation of the Gonzalez algorithm
(
feder1988optimal
)
on
S
runs in
O(k\varepsilon^{-d}\log k)
time. Overall, the running time of the
\varepsilon
-implementation of the Gonzalez algorithm is
O(k\varepsilon^{-d}n\log^{2}N+k\varepsilon^{-d}\log^{4}N)
with probability at least
1-\frac{1}{N}
.

Theorem E.5.

Given an acyclic query
\bm{q}
, a database instance
\mathbf{D}
of size
N
, and an arbitrarily small constant parameter
\varepsilon\in(0,1)
, there exists an
\varepsilon
-approximate version of the Gonzalez algorithm on
\bm{q}(\mathbf{D})
for
k
steps in
O(kN\log^{2}N+k\log^{4}N)
time. The running time holds with probability at least

.

E.3.
Diversity and fairness problems

Diversity

It is known that the the Gonzalez algorithm can be used to construct small coresets for multiple problems in diversity and fairness
(
indyk2014composable
)
.
More specifically, given a database instance
\mathbf{D}
of size
|\mathbf{D}|=N
, a join query
\bm{q}
, and a positive integer parameter
k
, the goal is to compute a set
\mathcal{S}\subseteq\bm{q}(\mathbf{D})
of size
|\mathcal{S}|=k
such that,

•

\min_{p,q\in\mathcal{S}}\phi(p,q)
is maximized (Relational Remote Edge – RRE).

•

the weight (with respect to the Euclidean distance) of the minimum spanning tree on
\mathcal{S}
is maximized (Relational Remote Tree – RRT).

•

the minimum cost (with respect to the Euclidean distance) of the travelling salesman problem on
\mathcal{S}
is maximized (Relational Remote Cycle – RRC).

•

\sum_{p\in\mathcal{S}}\min_{q\in\mathcal{S}\setminus\{p\}}\phi(p,q)
is maximized (Relational Remote Pseudoforest – RRP).

•

The minimum cost (with respect to the Euclidean distance) of a perfect matching of
\mathcal{S}
is maximized (Relational Remote Matching – RRM).

For each of the defined problem, we run our algorithm from Theorem
E.5
. Then using the results from
(
indyk2014composable
)
, we conclude to the next theorem.

Theorem E.6.

Given an acyclic join query
\bm{q}
, a database instance
\mathbf{D}
of size
N
, and a parameter
k
, there exists an
O(1)
-approximation algorithm for the RRE, RRT, and RRC problem over
\bm{q}(\mathbf{D})
in
O(kN\log^{2}N+k\log^{4}N)
time. Both the aproximation factor and the running time hold with probability at least
1-\frac{1}{N}
.
Furthermore, there exists an
O(\log k)
-approximation algorithm for the RRP, and RRM problem over
\bm{q}(\mathbf{D})
in
O(kN\log^{2}N+k\log^{4}N)
time. The running times hold with probability at least
1-\frac{1}{N}
.

We highlight that the RRE problem has been studied in
(
agarwal2024computing
)
. Agarwal et al.
(
agarwal2024computing
)
designed an
O(1)
-approximation algorithm for the RRE problem over
\bm{q}(\mathbf{D})
(for any acyclic join query
\bm{q}
) in
\tilde{O}(\min\{k^{2}N,kN+k^{d/2}\})
time, where
d
is the total number of attributes,
d=|{\mathbf{A}}|
. Our algorithm improves the running time by a multiplicative factor of
k
or an additive term
k^{d/2}
.

Fairness

Interestingly, the
\varepsilon
-approximate implementation of the Gonzalez algorithm is useful in fairness problems.
We define two problems, the Relational Fair Remote Edge (RFRE) and the Relational Fair Remote Clique (RFRC) problem. Without loss of generality assume that there exists one relation, say
R_{1}
, where in addition to the numerical attributes
{\mathbf{A}}_{1}
, has one additional categorical attribute
A^{\prime}
with
{\texttt{dom}}(A^{\prime})=\{c_{1},c_{2},\ldots,c_{g}\}
, where
g
is the number of different values. Let
Q_{c}=\{t\in\bm{q}(\mathbf{D})\mid\pi_{A^{\prime}}(t)=c\}
, i.e., the tuples in
\bm{q}(\mathbf{D})
that belong to group
c\in{\texttt{dom}}(A^{\prime})
.
Given
g
positive integer parameters
k_{1},\ldots,k_{g}
the goal is to compute a set
\mathcal{S}\subseteq\bm{q}(\mathbf{D})

such that
|\mathcal{S}\cap Q_{c}|\geq k_{c}
for every
c\in{\texttt{dom}}(A^{\prime})
and

•

\min_{p,q\in\mathcal{S}}\phi(p,q)
is maximized (RFRE).

•

\frac{1}{2}\sum_{p,q\in\mathcal{S}}\phi(p,q)
is maximized (RFRC).

The problem of fair remote edge (or fair max-min as it is also called in the literature) has been studied extensively in the standard computational setting
(
kurkure2024faster
;
addanki2022improved
;
moumoulidou2021diverse
)
. It is known that running the Gonzalez algorithm for
O(k\varepsilon^{-d})
iterations, where
k=k_{1}+\ldots k_{g}
, on the element of each group creates a coreset of size
O(gk\varepsilon^{-d})
for the fair remote edge problem. Then an expensive
\frac{1}{2}
-approximation algorithm over the coreset is executed
(
kurkure2024faster
;
addanki2022improved
;
moumoulidou2021diverse
)
.
If our goal is to get an
O(1)
-approximation algorithm then the size of the coreset is
O(gk)
.
Similarly, we can run the
\varepsilon
-approximate implementation from Theorem
E.5
over
Q_{c}
, for each different
c\in{\texttt{dom}}(A^{\prime})
to construct a coreset. Using Theorem
E.5
along with the algorithms in
(
kurkure2024faster
;
addanki2022improved
;
moumoulidou2021diverse
)
, we get the next result.

Theorem E.7.

Given an acyclic join query
\bm{q}
, a database instance
\mathbf{D}
of size
N
, and parameters
k_{1},\ldots,k_{g}
, such that
k=k_{1}+\ldots+k_{g}
, there exists a
O(1)
-approximation algorithm for the RFRE problem over
\bm{q}(\mathbf{D})
in
O(kN\log^{2}N+k\log^{4}N+T_{FRE}(gk^{2}))
time, where
T_{FRE}
is the running time of an
O(1)
-approximation algorithm in the standard computational setting for the fair remote edge problem over
gk^{2}
points.
The running time holds with probability at least
1-\frac{1}{N}
.

Next, the problem of fair remote clique (or fair max-sum) has also been studied in the standard computational setting
(
mahabadi2023core
)
. Mahabadi and Trajanovski
(
mahabadi2023core
)
construct a coreset of size
O(\sum_{i\in[g]}k_{i}^{2})=O(gk^{2})
as follows. They run Gonzalez algorithm for
k_{i}
iterations on the points of the
i
-th group. Then for every point returned by the Gonzalez algorithm they add in their coreset the
k_{i}
nearest neighbors among the points in the
i
-th group.

In the relational setting, for every
c\in{\texttt{dom}}(A^{\prime})
we first run the
\varepsilon
-approximate implementation of the Gonzalez algorithm from Theorem
E.5
over
Q_{c}
. Then, for every point
p
returned by Theorem
E.5
we find the
k_{i}
nearest neighbors in
Q_{i}
using the Euclidean-based oracle presented in
(
agarwal2024computing
)
in
O(N+k_{i}\log N)
. Overall, using Theorem
E.5
,
(
mahabadi2023core
)
, and
(
agarwal2024computing
)
, we get the next result.

Theorem E.8.

Given an acyclic join query
\bm{q}
, a database instance
\mathbf{D}
of size
N
, and parameters
k_{1},\ldots,k_{g}
, such that
k=k_{1}+\ldots+k_{g}
, there exists a
O(1)
-approximation algorithm for the RFRC problem over
\bm{q}(\mathbf{D})
in
O(kN\log^{2}N+k\log^{4}N+T_{FRC}(gk^{2}))

O(1)
-approximation algorithm in the standard computational setting for the fair remote clique problem over

1-\frac{1}{N}
.

Appendix F
Extension to cyclic queries

A fractional edge cover of join query
\bm{q}
is a point
x=\{x_{R}\mid R\in{\mathbf{R}}\}\in\mathbb{R}^{m}
such that for any attribute
A\in{\mathbf{A}}
,
\sum_{R\in{\mathbf{R}}_{A}}x_{R}\geq 1
, where
{\mathbf{R}}_{A}
are all the relations in
{\mathbf{R}}
that contain the attribute
A
.
As shown in
(
atserias2013size
)
, the maximum output size of a join query
\bm{q}
is
O(N^{\lVert x\rVert_{1}})
. Since the above bound holds for any fractional edge cover, we define
\rho^{\star}=\rho^{\star}(\bm{q})
to be the fractional cover with the smallest
\ell_{1}
-norm. Equivalently,
\rho^{\star}(\bm{q})
is the value of the objective function of the optimal solution of linear programming (
\mathsf{LP}
):

\min\sum_{R\in{\mathbf{R}}}x_{R},\;\text{s.t.}\;\forall R\in{\mathbf{R}}:x_{R}\geq 0\;\text{and}\;\forall A\in{\mathbf{A}}:\sum_{R\in{\mathbf{A}}_{R}}x_{R}\geq 1
.

Next, we give the definition of the Generalized Hypertree Decomposition (GHD).
A GHD of
\bm{q}
is a pair
(\mathcal{H},\lambda)
, where

\mathcal{H}
is a tree as an ordered set of nodes and
\lambda:\mathcal{H}\to 2^{{\mathbf{A}}}
is a labeling function which associates to each vertex
u\in\mathcal{H}
a subset of attributes in
{\mathbf{A}}
, called
\lambda_{u}
, such that the following conditions are satisfied:
i) (coverage) For each
R\in{\mathbf{R}}
, there is a node
u\in\mathcal{H}
such that
{\mathbf{A}}_{R}\subseteq\lambda_{u}
, where
{\mathbf{A}}_{R}
is the set of attributes contained in
R
;
ii) (connectivity) For each
A\in{\mathbf{A}}
, the set of nodes
\{u\in\mathcal{H}:A\in\lambda_{u}\}
forms a connected subtree of
\mathcal{H}
.

Given a join query
\bm{q}
, one of its GHD
(\mathcal{H},\lambda)
and a node
u\in\mathcal{H}
, the width of
u
is defined as the optimal fractional edge covering number of its derived hypergraph
(\lambda_{u},\mathcal{E}_{u})
, where
\mathcal{E}_{u}=\{{\mathbf{A}}_{R}\cap\lambda_{u}:R\in{\mathbf{R}}\}
. Given a join query and a GHD
(\mathcal{H},\lambda)
, the width of
(\mathcal{H},\lambda)
is defined as the maximum width over all nodes in
\mathcal{H}
. Then, the fractional hypertree width of a join query follows:
The fractional hypertree width of a join query
\bm{q}
, denoted as
\mathsf{fhw}(\bm{q})
, is

\mathsf{fhw}(\bm{q})=\min_{(\mathcal{H},\lambda)}\max_{u\in\mathcal{H}}\rho^{\star}(\lambda_{u},\mathcal{E}_{u})
,
i.e., the minimum width over all GHDs.

Relational algorithms for
k
-center/median/means clustering

Overall,
O(N^{\mathsf{fhw}})
is an upper bound on the number of join results materialized for each node in
\mathcal{H}
. It is also the time complexity to compute the join results for each node in
\mathcal{H}

(
atserias2013size
)
. Hence, we convert our original cyclic query into an acyclic join query (with join tree
\mathcal{H}
) where each relation has
O(N^{\mathsf{fhw}})
tuples. We execute our algorithms from Theorem
5.2
and Theorem
6.6
(also Theorem
E.6
, Theorem
E.7
and Theorem
E.8
) to the new acyclic join query. The approximation factors remain the same. The running times are adjusted by replacing the
N
factor with an
N^{\mathsf{fhw}}
factor.
