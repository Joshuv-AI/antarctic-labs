Surreal Arithmetic, Lazily
Lloyd Allison

Abstract
. Conway’s surreal numbers were aptly named by Knuth. This note examines how far one can get towards implementing surreals and the arithmetic operations on them so that they execute efficiently. Lazy evaluation and recursive data structures yield a considerable speed up. keywords: surreal numbers, arithmetic, functional programming, circular program, corecursion

1.
Introduction

Conway defined the surreal numbers
as described in his ‘ONAG’ book
2
;
initially he had simply called them ‘numbers’ but Knuth coined
the name ‘surreal numbers’
3

which is very appropriate
given the bewitching universe of numbers that the system created
and it was readily accepted
4
.
From the simplest of beginnings the full surreal numbers propagate
to include integers, rationals, irrationals and even transfinite numbers,
forming the largest ordered field
1
.

Various authors have played more or less deeply in
the
programming
of surreals to
see how much to do with them can be implemented in computer programs.
Perhaps the most practical prior work of this kind, as its title suggests
(although “practically” can be read in two ways),
is by Roughan
5

who used the programming language Julia as the means.
In considering earlier efforts he noted that
“There are several prior implementations of the surreals in
various programming languages … Most of these are very incomplete”
which pretty much holds today.

This note describes a
more
practical way of implementing
surreal numbers that have finite representations,
with the operators
\leq,<,\geq,>,=,\neq,+,-,\times
on them,
as they are specified by Conway,
and that runs quickly through the use of laziness
and mutually recursive data-structures and functions.
An interactive calculator has been programmed and is
available

2.
Surreal Numbers

In ONAG notation
2

a
surreal form
is written
\langle L|R\rangle

where
L
and
R
are sets of surreal numbers –
sets that can be empty, finite or infinite.
If no member of
R
is less than or equal to any member of
L

the surreal form denotes a
surreal number
.
Strictly speaking a surreal number is an equivalence class and
can be represented in many different ways
but it is common practice to gloss over this where possible.
Conway defines

\leq,+,-,\times
(figure
1
) and
shows that they have the
usual properties expected of arithmetic, and then some.
The simplest, and oldest, surreal number is
\langle|\rangle
which can
be called zero or
\underline{0}
because it behaves
like a zero should:

x+\langle|\rangle=x
and

x\times\langle|\rangle=\langle|\rangle

for any
x
.
Zero is said to be
born
in generation 0.
Note that
L=R=\emptyset
in zero and they are omitted traditionally.
Zero has two children born in generation 1,

\langle\langle|\rangle|\rangle
and

\langle|\langle|\rangle\rangle

(or
\langle\underline{0}|\rangle
and
\langle|\underline{0}\rangle
)
which we can call

\underline{1}
and
\underline{-1}
because of their behaviours, e.g.,

\langle\underline{0}|\rangle\times x=x
,

\underline{1}+\langle|\underline{0}\rangle=\underline{0}
, and so on.
After the birth of its two children
there is generation 2 of zero’s four grandchildren including

\underline{2}=\langle\underline{1}|\rangle
and

\underline{1/2}=\langle\underline{0}|\underline{1}\rangle
,
subsequently its eight great grandchildren and so on.

The surreal numbers that are
born
in finite generations
in the above way are equivalent to the
dyadic rationals
–
numbers of the form
i/2^{j}
for integer
i
and non-negative integer
j
.
Each surreal born in a finite generation has a canonical representation

x=\langle L_{x}|R_{x}\rangle
where each of
L_{x}
and
R_{x}

is either empty or contains a single surreal number that was
born before
x
was born.

All attempts at “everyday” programming with surreals
limit themselves to “short” surreals –
those having finite representations.
Values like
1/3,\sqrt{2},e,
and
\pi

do not have finite representations as surreals
although each of these examples is
computable
in that we can write
a program that returns a short surreal that is as close as desired
to the real value.
The focus therefore has been on implementing
the short surreals, the comparisons and the operators
+,-,\times
.

Before getting down to the business,
there is the matter of the rules of the game.
If we just wanted to evaluate expressions with short surreals
as quickly as possible we would likely convert them to rational numbers,
which some languages and some hardware already support,
compute with those and convert the result back to surreals.
However that would be
cheating
.
Instead the ethical path is to implement Conway’s definitions
as far as is possible and to see what emerges from that.

We can define the “Genealogy” Tree of surreals,
SNs
,
as in figure
2
.
It is an infinite Tree but just finite parts are built,
only as necessary from use.
Given an arbitrary representation,
x
,
the function
canonical
searches for the node
where the surreal that
x
represents was born and returns that.

The functions
LE
(
\leq
),
plus
,
times
,
implement Conway’s definitions
2
(and figure
1
)
in the obvious way and

negate
,
minus
and the other comparisons follow on.
However as can be seen,
these definitions are
highly
recursive, for example,
multiplying numbers from generations
i
and
j
can involve
multiplying and adding numbers from generations
i-1
and
j

and from generations
i
and
j-1
, and so on, recursively
until we get down to at least one zero.
Many sub-multiplications and sub-additions appear multiple times
in this process to the extent that, in a naive implementation,

times 3 3
takes a fraction of a second but

times 4 4
takes minutes and

times 5 5
is hardly to be entertained.

The cure for this problem of inefficiency is
to use multiplication- and addition-tables
which are in fact Trees of Trees,
as defined in figure
3
.
Here
map
(apply to all) is the obvious function on
Trees rather than lists.
Two new functions,
(*)
and
(+)
are introduced
which look in the tables for the results of

x\times y
and
x+y
respectively.
Functions
times
and
plus
are rewritten
to call
(*)
and
(+)

internally where they used to call themselves.
This ensures that the result of each
x\times y
and each
x+y

is only ever calculated once and subsequently looked up more quickly
in the tables.

TimesTable = map (\x -> map (\y->times x y) SNs) SNs
PlusTable = map (\x -> map (\y-> plus x y) SNs) SNs

(*) x y = select (select TimesTable x) y
(+) x y = select (select PlusTable x) y

select tr x -- return the elt of Tree tr that corr. to x
let sel (Tree ss sl sr) (Tree ts tl tr) =
if x < ss then sel sl tl
else if x > ss then sel sr tr
else ts -- x=ss, got it
in sel SNs tr

At least one more optimisation is possible.
The
select
operation acts in the style of
canonical

by following the path from zero to the birth of
x
in
SNs

and tracing out a similar path in another Tree,
tr
,
in order to find the node that corresponds to
x
.
To do so it carries out a number of comparison operations,
ultimately
\leq
operations;
these are not atomic operations.
To avoid them where possible,
the
parent
of each child in the
SNs
tree
can be kept within the tree
together with whether the child was the left- or the right-child.
For a canonical surreal in the
SNs
Tree,
knowing parents allows the tracing of the paths in question without
the use of comparisons.
Note that zero and non-canonical representations do not have parents.

3.
Implementation

The methods described above have been implemented in javascript –
which can be used as a quite passable functional programming language.
It is not a lazy languages so the laziness is implemented
explicitly in the code however
javascript does have the advantage of easily
leading to an interactive calculator which runs within a web-page
without having to install any special software.

for Roughan’s Julia implementation

“computation times for
3\times 5

4.
Speculation

The short surreals have finite representations
and are born in finite generations.
Conway
2
(p.12) introduces the first non-finite surreal

\omega=\langle 1,2,3,...|\rangle

born in generation
\omega
.
The surreal
e,\pi,\sqrt{2}
and
\ 1/3
are
also born in generation
\omega

(which is why division has been avoided here
because in general only dividing by a power of
2
yields a short result).
Note that
L_{\omega}
is an infinite set because

\omega
is larger than every finite surreal integer.
It is tempting to wonder if we could somehow program

omega = <nats|>

where we have the well known
nats = 1.(map succ nats)
.
Conway shows that

\epsilon=\langle 0|1,1/2,1/4,...\rangle=1/\omega
,

\omega-1=\langle 1,2,3,...|\omega\rangle
,

\omega+1=\langle\omega|\rangle

and gives many other identities.
It is hard to see how these identities could follow
in a program

from
nats
and the rules for operations
\leq,+,\times
.
We might program in a new special value
\omega
and
with it special rules for how it behaves in the operations
but that sounds like cheating.
There does not seem to be an obvious natural way to programming
infinite and infinitesimal surreals from the basic rules.

5.
Summary

An interactive calculator for short surreal numbers has been created
(sec.
3
),
following Conway’s rules of arithmetic
2
, and
using recursively defined data structures and functions (sec.
2
)
and lazy evaluation to run orders of magnitude
faster than previous implementations of surreal arithmetic.
