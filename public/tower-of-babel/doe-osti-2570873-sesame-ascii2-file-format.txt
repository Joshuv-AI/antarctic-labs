 Abstract
 A new ASCII format for SESAME data is explicitly defined and dubbed ASCII2. This format
 fixes some of the onerous limitations of the legacy ASCII-styled format in addition to relaxing
 the FORTRAN style fixed-format layout of data tables. With the exception of the multi-tiered
 indexes of the legacy binary format, the new ASCII2 is more compatible with the binary in that
 it does not restrict the extent of various integer data (e.g., SESAME material and table numbers)
 to six digits nor does it restrict the extent or precision of the various floating point data. There
 will be very limited support of the legacy ASCII-styled formats in the future.
 Keywords— SESAME, file format, equation of state, ASCII2

1 INTRODUCTION
This report supersedes LA-UR-21-23834 [1] and should be used in its place, because the reference contains
many details that have been determined to be erroneous or incomplete. This document is intended to contain
general descriptions of the fundamental table definitions that are minimally-dependent upon the data that
the tables shall contain. Effort has been made to ensure that the data precision of a SESAME ASCII2 file
is consistent with that which may be stored in an equivalent SESAME 64-bit IEEE binary file. To keep
this document short and accessible, detailed descriptions of data structure and data conventions have been
published in the supporting report LA-UR-25-26258[2]. With the addition of new tables in SESAME to
accommodate the next generation multiphase representations of materials, it is necessary reinvent the more
than forty-year-old ASCII format[3]. While this ASCII2 format does not deviate wildly from the way the old
data was organized and represented, it does relax some of the overly-restrictive FORTRAN fixed-format write
statements while enabling both expanded material identification numbers and expanded table identification
numbering, and outlining a more user friendly whitespace delimited format for the numerical data tables.

2 DESCRIPTION
There exist some generic format descriptions of data stored within a SESAME ASCII2 file that have simi-
larities with the original SESAME ASCII formatted files[3]; however, many of differences exist in order to
extend the data storage features of the contained structures. To increase flexibility, readability and parsing of
the file, the following updated requirements exist, which have resulted in the details described in sections 2.1
to 2.4:
 • A Format_Version label and number must be on the first line of each file. The value of the version
 indicates the ASCII file format version and not the version of the contents of the file.
 • One or more whitespace character(s) (i.e., spaces and/or tabs) must separate each numeric datum from
 its neighbor(s). This also applies for numeric table data as well as any table header.
 • File_Number is only at the beginning of the definition of a table. Remember: File_Number has the
 values:
 ➯ 0 : beginning of a material’s first table header, and
 ➯ 1 : beginning of all subsequent table headers for the same material.

2.1 General record descriptions 2 DESCRIPTION

 • Material_ID, Table_ID, and Number_of_Words are no longer limited to six digits; all can be pos-
 itive values that may be represented by the C programming language’s long int. The maximum
 value of a long int can be attained by writing a small program to print LONG_MAX while includ-
 ing: #include <limits.h>. At the time of writing this document, the maximum of a long int is
        9223372936854775807, which corresponds to 263 − 1.
 • A comment table’s data definition remains the same. The data must be eighty ASCII printable char-
 acters — excluding end of line characters (i.e., new line and carriage return) — per line until the last
 line of the comment, which may be less than eighty characters.
 • Create_Date and Update_Dates are following ISO 8601 Date Standard format: YYYYMMDD.
 • Version is no longer limited to four digits; it is the size of C programming language’s 64-bit long integer.
 • A line containing material data must not be longer than 320 characters,1 including the end of line
 character(s) (i.e., new line and/or carriage return). Assuming an exponential syntax of ±X.Ye±Z
 (where X is one digit, Y is fifty-five digits, and Z is three digits), this obviously supports a ridiculously-
 large data precision (i.e., %.55e) of single-spaced data2 for five numbers per line, and it exceeds any
 known precision requirements of SESAME data.
 • A line containing material data must not exceed five whitespace-delimited numeric values, and these
 data shall be parsed as a 64-bit double precision values as defined for the C programming language.

2.1 General record descriptions
There exist three general record definitions in the ASCII2 format. The first two general record definitions
are comprised of one line of printable ASCII text; whereas, the third general record definition is comprised
of one or more lines of printable ASCII text. The respective descriptions of these general record definitions
are provided as follows:
 1. File format version record : a single line record containing the version number of the current SESAME
 format
 2. Table header record : a single line record containing metadata that defines the following SESAME table
 3. Table data record : a list of printable ASCII characters comprised of one of the following:
 • printable ASCII content that provides key-value pairs of metadata for the material (section 2.4.2)
 • arbitrary printable ASCII content that is used to describe the material data to the reader (sec-
              tion 2.4.3)
 • a list of floating point numbers (section 2.4.4)

2.2 File format version
Exclusive to the first line of any SESAME ASCII2 file there must exist the Format_Version label and number.
For example,

 Version 2.0

 The case of the text on this first line is arbitrary, and a parser must handle it accordingly.

2.3 Table header
A table header line appears as a whitespace-delimited list like the following in a SESAME ASCII2 file:

File_Number Material_ID Table_ID Number_of_Words Create_Date Update_Date Version_Number

 Each of those values are described in Table 1, and they all must be written as positive integers. If
the EOSPAC6[4] package or its associated tools is used to parse an ASCII2 file, then these values shall be
constrained to the 64-bit positive integer range defined by the IEEE 754 standard[5, 6] (e.g., positive integers
up to 263 − 1 = 9223372936854775807) as previously mentioned in the preamble of this section 2.

2.4 Table data
The data in SESAME is organized into two general types of tables; a Comment table and a Numeric table.
Table_ID 100 is reserved for internal use. It is recommended that each table ends with a new line, and no
empty lines may exist between the end of one table and the beginning of the next table header. While not
required for existing parsers, it is also recommended that the end of file marker (EOF) exists immediately
after the final new line in any ASCII2 file — this allows for simplified concatenation of multiple ASCII2 files
in order to aggregate SESAME data.

2.4.1 Comment table
Comment tables shall have a Table_ID with a value in the ranges from 101 to 199 and 10101 to 10199,
and they have their own inherent key-value pair content requirements. A 101-styled comment table must
be present for each material with the Table_ID value of 101. The Table_ID range of 10101 to 10199 are a
relatively new addition to the SESAME data specification, and they are reserved for phase-specific metadata
in the 101-style.
 All comment tables shall contain only printable ASCII characters — excluding any extended or Unicode
characters; therefore, only ASCII decimal character codes 9, 10, 13, and 32-126 are valid (hexadecimal
equivalents are 09, 0A, 0D, and 20-7E), and both the line feed (10) and the carriage return (13) characters
shall be stripped from the end of each line when parsed.
 ➯ The Number_of_Words for a comment table does not include the count of any end-of-line charac-
 ters. None of the end-of-line characters (i.e., new line and/or carriage return) are included in the
 Number_of_Words value in the comment table’s header.

2.4.2 101-styled comment table
The 101 comment table is designed to contain specific metadata for a SESAME material as described in the
following bulleted list. Note that Table_ID 101 and 10101-10199 are specifically reserved for 101 style data.
Each keyword and its associated value are delimited from their neighbors by a singe slash (’/’) character;
thus, the slash character is reserved in the 101-styled comment tables, and it must not be used within the
string values.
 Although it is not strictly enforced in LANL’s3 SESAME parsers, certain conventions are assumed by
LANL EOS software and should be followed. Note that when parsing a keyword from a 101-styled comment
table, the case of the keyword is not enforced (i.e., case-insensitive). The following are the defined keywords
(bold; including period, ’.’) and their corresponding descriptions:
 • material. Material name (z=atomic number, a=atomic weight)
 • source. Author, organization detail.
 • date. Date the material was created.
 • refs. Published references.
 • comp. Composition of the material.

2.4.3 Generic comment table
Generic comment tables are numbered with a Table_ID from 102-199 and have no explicit keywords definitions.
Text in these comment tables are limited to 80 ASCII printable characters per line, not including end-of-line
characters. Only the last line of a comment table can be less than 80 characters. If for some reason there is
a desire to format a comment table for readability in the ASCII2 file the lines need to be whitespace padded
out to the 80 character definition.

2.4.4 Numeric table
A numeric table contains a list of Number_of_Words base-10 floating point numbers that are contained in one
or more lines as required where each line contains contains five whitespace-delimited numeric values except
the last line that may contain from one to five whitespace-delimited numeric values. If the EOSPAC6[4]
package or its associated tools is used to parse an ASCII2 file, then these data values shall be constrained
to the double precision range defined by the IEEE 754 standard[7] (e.g., numbers between 10−308 and 10308 ,
with minimum of 15 decimal digits of precision to the right of the decimal point).
 The internal structuring of the data, where many of the standard tables contain multiple sub-tables with
different material properties, exceed the scope of this document, but can be found in LA-UR-25-26258 [2].

3 Format Conversion Support
Some limited support for conversion between the new ASCII2 format and some of LANL’s legacy formats is
provided by a utility called convert_sesame_data, which is included within the EOSPAC6[4] version 6.5.11
and newer distributions. Previous versions of EOSPAC6 provided limited support as this new ASCII2 format
evolved into the current description. With the exception of the multi-tiered indexes of LANL’s legacy binary
format, all SESAME data in the ASCII2 format is compatible with the binary format. New materials contain
tables that are incompatible with older sesame formats, namely the original ASCII format[3] and the
