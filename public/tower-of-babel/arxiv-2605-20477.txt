Training Language Agents to Learn from Experience
Yuval Shalev, Zifeng Ding, Mateja Jamnik

Abstract
Language agents can adapt from experience in interactive environments, but current reflection-based methods can only self-correct within a single task instance. Whether such experience can be distilled into reusable lessons that improve performance on future unseen tasks remains unclear. We address this problem by introducing the In-context Training (ICT) task, a framework for evaluating cross-task self-improvement in language agents. In ICT, a reflector model observes trajectories collected by an actor model and generates system prompts intended to improve the actor’s performance on future unseen tasks. We then propose an RL-based training pipeline for learning such reflections directly from experience, without human-provided examples. Across ALFWorld and MiniHack, our trained reflectors outperform an untrained baseline on most held-out task families, showing that the ability to learn from experience can itself be learned. In some cases, we observe generalisation beyond the benchmark on which the reflector was trained, to substantially different environments. Finally, we introduce MetaGym, a generic Python library for constructing meta-environments, enabling future research on self-improving language agents.



1
Introduction

In recent years, there has been a growing interest in using large language models (LLMs) as decision-making agents in interactive environments
[
18
,
17
]
.
In this setting, LLMs act as agents that leverage their language capabilities to interact with external environments, producing tokens that are interpreted as actions
[
21
]
.
When faced with an unfamiliar environment, a general-purpose agent should be able to learn and adapt its behaviour from experience in order to find an optimal policy for action
[
16
,
11
,
23
,
14
]
.
Humans handle this task with ease. For example, when playing chess for the first time, a person may begin with an initial strategy in mind and, after each game, reflect on their experience to refine that strategy for future matches.

In LLM-based agents, the agent’s policy is determined not only by the model’s parameters, but also by the prompt provided to the model, which specifies how the agent should act in the environment
[
21
,
3
]
.
Learning and adapting may therefore be achieved by modifying the prompt provided to the model, making prompt optimisation a natural mechanism for self-learning in language agents.
This approach has three main advantages:
(1) it avoids the compute-heavy pipeline of fine-tuning LLMs for each specific task through gradient descent;
(2) it leverages the linguistic abilities of the model to support rapid learning from only a small number of experiences;
and (3) it offers a degree of transparency, since the accumulated experience is represented solely in natural language and can be directly inspected.

Recent studies have explored self-improvement in language agents through autonomous prompt modification, using self-reflection mechanisms
[
14
,
22
,
5
,
6
,
7
]
. In this setting, an LLM generates a reflection following an unsuccessful attempt at an interactive task. The reflection considers both the agent’s actions and the resulting feedback from the environment, and is then used to guide the agent’s next attempt by providing hints and suggesting how to avoid similar mistakes.
This yields a continuous online-learning mechanism, in which each task attempt provides an additional data point for improving behaviour after only a small number of trials.

However, existing work primarily focuses on self-correction by repeatedly attempting the same task until success. This introduces several important limitations.
First, the agent acquires experience only within a single task instance, and the resulting knowledge is not transferred across tasks. Once a task has been solved, the agent must repeat the full reflection process from scratch when encountering a new task.
This is inherently inefficient, since insights from one task could often generalise to similar tasks (e.g.,
“in maze-solving tasks, avoid revisiting the same path”
). Under the current paradigm, however, the agent is forced to relearn such lessons for each task.
Second, in many real-world settings, repeating the exact same task is not possible. For example, in a game of chess one cannot require an opponent to reproduce the same sequence of moves, and in a cooking scenario a mistake may irreversibly consume the available ingredients.

Although the ability to learn online from experience across tasks is highly desirable, it remains unclear whether self-reflection mechanisms can produce reflections that generalise well enough to improve performance on previously unseen tasks.
We therefore ask the following research question:
Can LLMs be trained to generate self-reflections that facilitate cross-task self-improvement, and if so, how?
.

To address this, we first define the
In-context Training
(ICT) task, a framework for evaluating the ability of LLMs to learn from experience for cross-task self-improvement (see
Figure

1
).
The ICT task implements a simple self-learning loop through a dual-LLM design.
The first model is the
actor
, which serves as the operational agent interacting with external environments according to a system prompt.
Crucially, at each turn of the ICT task, the actor faces a new
unseen
batch of tasks and has only
one chance
to solve each task.
The second model is the
reflector
, which evaluates the actor’s performance and proposes an improved system prompt for the the next turn.
The goal of the reflector is to learn from the actor’s collected experiences in order to generate a system prompt that generalises across tasks within a given family of tasks.
For example, in a maze-solving task, the reflector should learn from previously encountered mazes in order to produce a system prompt that enables the actor to solve
any
unseen maze drawn from the same task family in a single attempt.

Next, we demonstrate that the ability to learn from experience is itself a learnable skill by introducing a fine-tuning pipeline to train an LLM to generate reflections that facilitate cross-task self-improvement.
We train a
reflector
to analyse a given system prompt alongside experiences collected under that prompt, and to generate an improved system prompt for future unseen tasks. Our method does not rely on human-provided examples.

We evaluate our approach on ALFWorld
[
15
]
and MiniHack
[
9
]
, two benchmarks comprising diverse interactive environments. Using these benchmarks within the ICT framework, we show that a reflector trained on a set of task types can generalise and improve performance on previously unseen task types using only a small number of gathered experiences.
We also show that, in some cases, the model generalises beyond the benchmark on which it was trained, transferring to substantially different environments.

Finally, we introduce MetaGym, a generic Python library for constructing gym-like meta-environments from any gym-like environment
[
2
]
.
We release MetaGym as a tool to support future research on self-improvement in LLM agents within the ICT framework and beyond (
https://github.com/yuvalshalev1/MetaGym
).

Our contributions can be summarised as follows:

1.

A
training pipeline
for learning reflection strategies for cross-task self-improvement without reliance on human-provided labels.

2.

The
In-context Training
task, a framework for evaluating online self-improvement of LLMs that generalises across task instances.

3.

MetaGym
, a Python library for constructing meta-environments from Gym-like environments.

Related Work

Prompt Optimisation.

Previous studies have demonstrated the potential of LLMs for prompt optimisation in static tasks
[
20
,
4
,
1
]
.

20
optimise prompts for mathematical reasoning and question answering using closed-source LLMs, and
4
propose a bi-level framework that jointly optimises task-specific user prompts and a cross-task system prompt. In both cases, the optimiser observes only final outputs or aggregate accuracy, not
how
its prompts shaped the model’s behaviour during problem solving.
In our setting, however, the optimiser observes full interaction trajectories, enabling us to study its ability to learn from the agent’s behaviour.

1
leverage full reasoning trajectories to optimise prompts through iterative updates to a prompt pool. However, their scoring procedure relies on evaluating multiple candidate prompts on the same batch of task instances. In contrast, our setting assumes that each task is encountered only once and learning must occur online from non-repeatable experience.
More broadly, these works optimise prompts using external procedure rather than fine-tuning the optimiser itself, leaving open whether LLMs can be trained to learn better optimisation strategies.

Prompt Optimisation for LLM-Agents.

Recent work has explored prompt optimisation for LLM agents in interactive environments, while transferring experience across tasks
[
10
,
24
]
.

10
maintain an external database of self-generated successful trajectories and retrieve similar examples as in-context demonstrations for the actor.
This method relies on embedding raw past trajectories directly into the prompt, rather than consolidating them into a structured representation. However, prior work shows that in-context demonstrations are not always effective, even when produced by human experts
[
8
]
.

24
similarly rely on an external mechanism, extracting “insights” from pairs of past experiences and maintaining them through a voting procedure, before combining them with selected raw experiences to construct task-specific prompts during inference time. These methods therefore transfer experience through external memory and retrieval, but leave open the question of whether an LLM can be trained to learn reusable reflective strategies for cross-task self-improvement.

Reflection for Self-Correction.

14
introduce reflection for LLM agents as a feedback loop in which an agent analyses its behaviour after failing a task and uses this analysis to guide subsequent attempts.
Since then, several works have explored how to train LLMs to reflect more effectively in interactive environments.

22
,
6
and
5
use dual-LLM architecture that separates actor and reflector, with the former training only the reflector and the latter training both components jointly using a gradient policy.
Most recently,
7
proposed a meta-RL framework in which a single LLM acts as both actor and reflector.
However, all of these methods focus on self-correction through repeated attempts at the same task. They, therefore, leave open whether reflection can support cross-task improvement by extracting reusable lessons from experience.

The In-context Training Task

Here, we introduce the In-context Training (ICT) task, a framework for evaluating whether large language models can learn from experience to achieve cross-task self-improvement.
ICT is designed to capture a realistic setting in which the same task cannot be repeated, and the only opportunity for improvement lies in future tasks.
The framework is intentionally minimalistic, aiming to measure the model’s intrinsic learning ability rather than optimise performance through external machinery.

4
Training LLMs to Learn from Experience

We now introduce our pipeline for fine-tuning LLMs to generate reflections that facilitate cross-task self-improvement.

Dataset Creation.

To construct the training dataset, we run the ICT loop
r
times for
N
turns each, using a base model.
At the end of each turn
i
, we record the tuple
(sp_{i},obs_{i},e^{(i)}_{0},\dots,e^{(i)}_{k-1})
, consisting of the current system prompt
sp_{i}
, the meta-observation
obs_{i}
, and the batch of tasks
e^{(i)}_{0},\dots,e^{(i)}_{k-1}
used in that turn. Repeating this process yields a fixed dataset
\mathcal{D}
of
r\times N
data points in total.
The motivation is to capture a diverse set of system prompts arising from different stages of the ICT process, which correspond to varying degrees of required improvement. For example, if the reflector receives a system prompt that succeeds on one task in the batch but fails on the others, it should be able to analyse the factors that contributed to the successful case and generalise them to the remaining tasks. Conversely, if the reflector receives a system prompt that succeeds on all tasks in the batch, it should generate a new system prompt that remains highly similar to the previous one, potentially reproducing it exactly.

Reward Signal.

As described in
Equation

2
, the reflector generates a system prompt
sp_{i}
conditioned on the previous system prompt
sp_{i-1}
and the last batch of trajectories
obs_{i-1}
collected by
\text{LLM}_{\text{act}}
under
sp_{i-1}
.
Its immediate task is therefore to analyse how the previous system prompt led to the actor’s observed performance on the previous batch
e^{(i-1)}
, and to improve the prompt in light of the issues revealed by those trajectories.
Put differently, although the reflector’s goal is to improve performance on future unseen tasks, its intermediate objective is to answer the following question:
“If I had the opportunity to try the same batch of tasks again, what would I do differently to improve my performance?”
.

To encourage the model to account for observed performance issues and incorporate corresponding fixes into the new system prompt, we derive the training reward directly from the previous batch of tasks.
Specifically, the reward used to rank
sp_{i}
is the average reward obtained by the actor
\text{LLM}_{\text{act}}
on the batch
e^{(i-1)}
when conditioned on
sp_{i}
, that is, by replaying the previous batch under the new system prompt
sp_{i}
. Formally, the reward function is defined as:

\mathcal{R}(sp_{i})=\frac{1}{k}\sum_{j=1}^{k}R(\text{LLM}_{\text{act}},\,e^{(i-1)}_{j},\,sp_{i}).

(4)

Notably, although the reward signal is derived from the previous batch of tasks, the reflector should be explicitly prompted to analyse those performance issues and generate a system prompt intended for
future
tasks. This is essential to discourage in-context overfitting to the most recently observed batch.

Training Procedure.

We follow a standard training procedure for RL-based fine-tuning, where in each training step, we sample a batch of tuples
(sp_{i},obs_{i},e^{(i)}_{0},\dots,e^{(i)}_{k-1})
from the dataset
\mathcal{D}
and update the parameters of
\text{LLM}_{\text{refl}}
using GRPO
[
12
]
.
The procedure is illustrated in
Figure

2
:
for each tuple, the reflector samples a group of
G
candidate system prompts

\{sp^{(1)},\dots,sp^{(G)}\}\sim\pi_{\theta}(\cdot\mid sp_{i},obs_{i})
,
and each candidate is scored using
\mathcal{R}
as defined in
Equation

4
.
The scores are computed dynamically during training by executing the batch of tasks

e^{(i)}_{0},\dots,e^{(i)}_{k-1}
with
\text{LLM}_{\text{act}}
under each candidate system prompt.

Figure 2
:

MetaGym.
Task execution for both the ICT loop and the fine-tuning procedure is managed by MetaGym, our library for meta-environment construction for LLM-agentic tasks. MetaGym instantiates an interactive meta-environment in which each meta-action is represented by a system prompt, and each returned meta-observation is a batch of rollouts generated by an actor. Internally, it spawns task instances and executes them in parallel. See
Appendix

C

Task Partitioning.

The objective of the proposed training approach is to train a reflector that performs effectively on the ICT task, where the goal is to generate a general system prompt that achieves strong performance across tasks within a given task type.
A straightforward evaluation strategy would be to divide task instances into training and validation sets. However, this is insufficient: a reflector trained on one task type could simply memorise a high-performing prompt for that type and reproduce it at test time, thereby bypassing the in-context reasoning the model is intended to learn.
To mitigate this, we partition tasks by
type
rather than by instance, yielding disjoint
meta-train
and
meta-test
sets, each comprising distinct task types.
Each task type consists of a collection of similar tasks, from which the reflector is expected to extract transferable insights that generalise to other tasks within the same type.
During training, the reflector is exposed exclusively to task types from the meta-train set. At evaluation time, it is required to generalise to previously unseen task types in the meta-test set, generating reflections based solely on in-context observations available at inference time.

Effect of Batch Size.

The batch size plays two important roles that can influence the performance of the reflector.
First, it determines the number of episodes observed by the reflector in each turn, thereby affecting the diversity of experiences from which it can learn.
Notably, when a task is difficult, a small batch size may contain no successful episodes, making it more challenging for the reflector to extract useful lessons in the absence of positive examples.
Second, batch size affects the fine-tuning process of the reflector itself:
during training, if none of the generated candidate prompts is successful on any of the replayed tasks, the GRPO algorithm cannot compute advantages because all rewards are zero.
A larger batch size increases the likelihood of obtaining a positive reward signal, particularly when tasks are difficult and rewards are sparse.

Increasing the reflection batch size from
k{=}3
to
k{=}5
shows different effects across the benchmarks (see
Table

1
and
Figure

4
).
In ALFWorld, performance is similar across batch sizes, suggesting that the quality of individual reflections remains largely unchanged.
Taking into account the total number of tasks experienced,
k{=}3
shows a clear advantage, as adding more episodes appears to be redundant while costing more solving attempts.
In MiniHack, the performance of the
k{=}5
reflector was, in most cases, better than that of the
k{=}3
reflector, suggesting that using larger batches can be more effective for fine-tuning the reflector.

The untrained Qwen2.5-7B-Instruct performs worse under the
k{=}5
condition across almost all tasks.
Notably, in the
Pick Two
task, the prompts it discovers show performance remaining close to the initial prompt.
One possible explanation is that processing five episodes simultaneously presents a workload that is too high for Qwen2.5-7B to handle effectively. One interesting exception is the
Zap
task in MiniHack, where Qwen2.5-7B-Instruct performs better in the k=5 condition, which we attribute to the difficulty of the task.

Limitations

In our experiments, we trained only the reflector model in order to isolate the contribution of prompt evolution to actor performance.
However, maintaining separate actor and reflector models is computationally expensive in practice, as it requires holding two models in memory simultaneously. Training a single model to serve both roles could yield further performance gains.

During the ICT loop, we used a fixed held-out task set to identify the best-performing prompt at the end of each loop.
In real-world settings, such a repeatable evaluation set may not be available, necessitating alternative mechanisms for determining when to stop adaptation.
One such alternative is lifelong learning – continuously updating the system prompt without a fixed stopping criterion – though this raises open questions about the long-term stability of the generated prompts, which we leave for future work.

6
Conclusion

In this work, we investigated whether LLMs can learn from their own experience in-context in the realistic setting of online learning.
We introduced the In-context Training (ICT) task as an framework for evaluating cross-task self-improvement, in which an LLMs repeatedly analyses batches of unseen episodes and generates system prompts intended to improve performance across a task family.
To train models for this setting, we proposed an RL-based fine-tuning approach that derives reward signals from replayed input tasks.
Across held-out task types, our trained reflectors consistently outperform an untrained baseline, showing that leaning from experience is itself a learnable capability.

We believe this has important implications for language agents.
Our work provides both an evaluation framework and a training methodology for cross-task self-learning, a capability likely to matter for general-purpose agents operating in open-ended environments.
We hope it shifts attention from reflection within a single task instance to reflection across tasks.
Because our approach requires no annotated examples and applies directly to agentic benchmarks, it is readily extensible. To support further research, we release MetaGym (see
Appendix

C
), a Python library for constructing meta-environments for LLM agentic tasks.

Appendix C
MetaGym

MetaGym is a Python library designed to support prompt optimisation and self-improvement research for LLM agents.
It natively implements the ICT task from the perspective of the reflector as a meta-agent.
Each meta-action is a system prompt, and each returned meta-observation is a batch of rollouts generated by the actor conditioned on that prompt.
Internally, the meta-environment spawns a batch of task instances and executes them in parallel using a chosen actor, providing native infrastructure for running the ICT loop described in
section

3
.
MetaGym wraps a Gym-compatible environment
[
2
]
inside a Gym-like meta-environment and handles the parallel execution and trajectory collection required by the ICT framework.
In our experiments, all task execution across ALFWorld and MiniHack was managed through MetaGym. The library ships with built-in support for both benchmarks and provides instructions for integrating new environments, with the aim of supporting future research on prompt optimisation and self-improvement in LLM agents. MetaGym is released publicly alongside this work at
https://github.com/yuvalshalev1/MetaGym
.

The following snippet illustrates the MetaGym API using ALFWorld:

MetaGym usage example

from metagym import Actor

from metagym.envs.alfworld import ALFWorldMetaEnv

from metagym.reflector import Reflector

# Actor auto-launches a vLLM server for the model and shuts it down on exit

actor = Actor("Qwen/Qwen2.5-7B-Instruct")

# Initialise the meta-environment

env = ALFWorldMetaEnv(num_envs=3, actor=actor, split="train", seed=42)

trajectories, info = env.reset()

# Reflector: analyses trajectories and rewrites the system prompt

reflector = Reflector("Qwen/Qwen2.5-7B-Instruct", base_url=actor.base_url)

current_prompt = "You are a helpful agent..."

for step in range(4):

trajectories, reward, done, info = env.step(current_prompt)

print(f"Step {step} win rate: {reward:.0%}")

reflection = reflector.reflect(trajectories, current_prompt)

print(reflection.analysis)

current_prompt = reflection.improved_prompt

# Inspect a trajectory

trajectories[0].pretty_print()

Appendix E
MiniHack Details

MiniHack environments are procedurally generated, so task instances are produced by sampling random seeds. The reflector receives task batches sampled from a designated range of training seeds, while a fixed set of 32 seeds is held out and used consistently as the validation set for the ICT loop. Each episode is limited to 25 steps, with the exception of the
k{=}5
training run, where this limit was reduced to 18 steps to keep episode trajectories within the model’s context length.

MiniHack natively exposes a large number of actions, many of which are irrelevant to the tasks in our benchmark. To reduce ambiguity and keep the context concise, we always provide the actor with a curated list of available actions that are suitable for our task set, rather than the full action space.
