 ABSTRACT

 The System Analysis Module (SAM) is being developed as a modern system analysis code for advanced
non-light-water-reactor safety analysis under the U.S. DOE NEAMS program. Previous feasibility studies
have demonstrated that a staggered-grid finite volume method (SG-FVM), implemented under the MOOSE
framework, can deliver more than an order of magnitude speedup over the existing continuous Galerkin
finite element method (CG-FEM) solver for liquid-cooled, incompressible but thermally expandable flow
systems. This work extends the previous effort to compressible, gas-cooled reactor applications, where
pressure couples directly into the mass equation adding additional nonlinearity into the equation system.
New code capabilities are implemented for pebble bed high-temperature gas-cooled reactor (PB-HTGR)
analysis, including a pebble bed CoreChannel component, built-in pebble bed effective thermal conductivity
model and channel-to-channel crossflow model. The capabilities are tested, benchmarked, and demonstrated
for problems with increased level of model and physical complexities, including the HTTU effective thermal
conductivity test, the SANA passive cooling test, and a demonstration case using the GPBR200 reactor
design covering steady-state operation, DLOFC and PLOFC transients. Across all cases, the SG-FVM
solver demonstrated strong robustness and efficiency, and the solutions agree well with reference results and
data. The finding of this work proves that SG-FVM is a viable and efficient solver pathway for compressible,
gas-cooled reactor system analysis in SAM. In addition, work has been done to successfully support SAM-
FVM recover/restart code feature that is essential to reactor safety analysis applications, and MultiApp code
feature that is essential to multi-scale and multi-physics simulations. In summary, this work continued from
previous feasibility studies, and further demonstrated that the SG-FVM will serve as a strong foundation for
SAM’s advanced solver algorithm for future deployment.

1 Introduction

 The System Analysis Module (SAM) [1] is an advanced system analysis tool being developed under the
support of U.S. Department of Energy (DOE) Nuclear Energy Advanced Modeling and Simulation (NEAMS)
program. It aims to be a modern system analysis code, taking advantage of the advancements in software
design, numerical methods, and physical models over the past decades. SAM has been developed based on
an object-oriented application framework, Multiphysics Object Oriented Simulation Environment (MOOSE)
[2], and its underlying meshing and finite-element library and non-linear solvers, to leverage the modern
advanced software environments and numerical methods. The SAM code has been widely adopted and has
been applied to analyses of advanced reactor designs, including sodium fast reactors, fluoride-salt-cooled
high-temperature reactors, molten salt reactors, and high temperature gas-cooled reactors (GCRs).

 The continuous Galerkin finite element method (CG-FEM) adopted in SAM from the MOOSE framework
provides robust and flexible spatial discretizations. However, as discussed in previous studies [3–6], it is
also associated with numerical challenges such as numerical performance and code execution speed. To
address this issue, a staggered-grid finite volume method (SG-FVM) was proposed, and feasibility studies
were carried out to test the effectiveness and robustness of the finite volume method in system-level analysis
of reactor systems [3–6]. The SG-FVM employs a cell-centered pressure and temperature layout with
face-centered velocities, a naturally stable algorithm that automatically addresses the pressure checkerboard
issue. When computing mass and energy fluxes, a slope-limiter based upwind method is used, which reduces
the excessive numerical diffusion in first-order upwind method meanwhile maintains strong spatial stability.
Across a wide range of test cases, the speedup of SG-FVM over CG-FEM was observed to be significant, with
at least one order of magnitude of solving time reduction. Code-to-code comparisons between the SG-FVM
and CG-FEM also showed good consistency in both steady-state and transient solutions, confirming solution
accuracy.

 The previous feasibility studies [3–6], considered only incompressible liquid-cooled systems, where the
fluid density depends only on temperature but not on pressure. For gas-cooled systems, the coolant, such as
helium, often must be treated as compressible to account for the pressure effect on density during events such
as a depressurized loss of forced cooling accident. Although the transition from an incompressible flow model
to a compressible flow model may seem trivial, it introduces subtle changes in many aspects of numerically
solving the system. In an incompressible flow model, pressure does not appear in the mass conservation
equation and is solved to only enforce a divergence-free velocity field; whereas in a compressible flow
model, the role of pressure changes fundamentally as it also affects density. Moreover, for most reactor
thermal-hydraulics analysis, the flow speed is typically much smaller than the sound speed, such that the
system is almost always in the low-Mach compressible regime, with distinct characteristic wave speeds
associated with both the flow speed and the sound speed. This often makes the nonlinear system significantly
stiffer and more difficult to solve using Newton-Krylov method. It is therefore essential to continue the
feasibility study with a focus on the correctness, robustness, and effectiveness of the proposed numerical
methods in applications to gas-cooled systems. In addition, as pointed out in our previous work [6], a few
gaps in code capabilities must be filled to further improve SAM-FVM code maturity. This includes advanced
code capabilities such as code recover/restart feature commonly used in reactor safety analysis, and MultiApp

 1

support for multi-scale multi-physics simulations.

 This report summarizes the work done to fill those important code capability gaps, focusing on code
capabilities on gas-cooled reactor applications, code recover/restart, and MultiApp simulations. To achieve
these goals, we have first focused the efforts on implementing code capabilities necessary for system analysis
of gas-cooled reactor designs, in particular, pebble bed high temperature gas-cooled reactors (PB-HTGRs).
These code capabilities were then applied for selected test cases related to PB-HTGR applications to
demonstrate code robustness and execution efficiency. Additional code developments were then performed to
enable the recover/restart and MultiApp features. The remaining of the paper is organized as follows: Section
2 will provide detailed discussions on the code implementations unique to PB-HTGR applications; the results
and comparison of selected verification, validation and demonstration cases, including HTTU verification
and validation, SANA validation, and GPBR demonstration. Section 3 will discuss the recover/restart
code implementation and testing. Section 4 will discuss the MultiApp capability, and use a coupled multi-
dimensional heat conduction and one-dimensional flow problem as the demonstration and code-to-code
benchmark case. Section 5 provides a summary to this work.

2 GCR Applications

2.1 Code Capability for GCR Applications

 The staggered-grid finite volume method (SG-FVM) implementation for one-dimensional single-phase
flow model and software design to enable the SG-FVM under the MOOSE framework has been thoroughly
discussed in our previous works [3–5], and therefore will not be detailed in this report. Instead, this section
describes the new code capabilities necessary for gas-cooled reactor analysis, focusing on the pebble bed
HTGR modeling and simulation needs, such as built-in pebble bed effective heat conduction and channel-to-
channel crossflow code features. Both phenomena are critical in PB-HTGR safety analysis as they strongly
influence the temperature distributions during safety transients. Details of these code capability enhancements
are provided in the following subsections.

2.1.1 CoreChannel with Pebble Bed Geometry

 The CoreChannel component represents a one-dimensional flow channel with an associated solid (heat)
structure. For pebble bed reactor applications, the basic idea is that a pebble bed core could be represented
as a few concentric cylindrical and annulus ‘rings,’ each of which can be modeled as a one-dimensional
component, as illustrated in Figure 2.1. The fluid side of the CoreChannel is solved using the standard
SG-FVM equations for mass, momentum, and energy conservation. The solid side of the CoreChannel
is solved using the standard one-dimensional heat conduction equation in the spherical coordinates and is
coupled to the fluid side energy equation via a convective heat transfer term.

Figure 2.1: Schematic of a pebble bed (left), which can be modeled as a series of concentric ‘rings’ (middle),
and the pebble bed CoreChannel concept (right).

 In pebble beds, although the main flow direction is mostly aligned with the one-dimensional channels,
heat and mass are not confined in these artificially defined channels, especially during safety transients. In
PB-HTGR, both radial core heat conduction and in-core natural circulation can significantly impact the fuel
temperature distribution, and therefore they must be adequately modeled. It is noted that the one-dimensional
CoreChannel approach for pebble bed reactor applications has been implemented, while the radial core heat

 3

conduction and channel-to-channel crossflow have only been partially addressed in the FEM version of the
SAM code [7].

2.1.2 Pebble Bed Effective Thermal Conductivity

 In pebble bed HTGR designs, during postulated safety events, such as pressurized/depressurized loss
of forced cooling (PLOFC/DLOFC) accidents, the decay heat is transferred from the core region radially
to reactor core vessel surface via a few mechanisms, including heat conduction, heat convection, and
thermal radiation. The collective effect of these heat transfer mechanisms is termed as the effective thermal
conductivity of a pebble bed and can be modeled with empirical correlations such as the Zehner-Bauer-
Schlünder (ZBS) correlation.

 Consider two adjacent annular pebble bed zones represented by CoreChannel 1 and 2, with inner/outer
pebble bed radius r1 /r1−2 and r1−2 /r2 , respectively, as schematically shown in Figure 2.2. The distance
between the radial center of the two CoreChannels is dr. In each cell of the CoreChannels, the total pebble
surface area, A p , can be determined by the volume of the cell, porosity, and pebble diameter. If there
exists a temperature difference between the two adjacent radial cells, heat will be transferred from the
high-temperature cell to the adjacent low-temperature cell. The heat fluxes applied onto pebble surfaces of
the two adjacent cells due to pebble bed effective heat conduction can be found using the following energy

2.1.3 Channel-to-channel Crossflow

 In a multiple CoreChannel pebble bed core simulation, radial pressure gradients can arise for different
reasons. During normal operation condition, such pressure gradients can be caused by non-uniform power
distributions. During safety transients, heating of core center and cooling of core peripheral causes helium
density to change non-uniformly. The buoyancy force due to the uneven density distribution is the main
mechanism that drives in-core natural circulation. Such uneven density distributions also cause radial pressure
gradients, introduces additional radial crossflow on top of the in-core natural circulation, which must be
captured for more accurate simulation of core internal flow and therefore core temperature predictions. The
channel-to-channel crossflow can be evaluated by solving a crossflow momentum equation, equivalent to a
simplified momentum equation in a porous medium flow model [8]:

2.2 Case Studies for PB-HTGR Applications

 In this section, a few test cases were selected to test and demonstrate the new code capabilities dedicated
to pebble bed HTGR simulations, and to evaluate code performance. The first test case is the High Temperature
Test Unit (HTTU) test, a separate effect test that has been performed to investigate the effective thermal
conductivity of the pebble bed. The second test case is the SANA test, a large experimental validation
program conducted to validate the expected thermal stability and heat removal characteristics of pebble bed
HTGRs, including both pebble bed effective heat conduction and in-core natural circulation phenomena.
The last demonstration case is the GPBR200 full core model covering steady state nominal condition and
depressurized/pressurized loss of forced cooling (DLOFC/PLOFC) transients.

2.2.1 HTTU Code-to-code Comparison

 The High Temperature Test Unit (HTTU) facility, developed by the PBMR company in collaboration
with the North-West University and M-Tech Industrial (Pty) Ltd. in South Africa, is an experiment facility
dedicated to study the different thermal-fluid phenomena of pebble bed type of HTGR [9]. A separate effect
test has been performed to investigate the effective thermal conductivity of the pebble bed. As shown in
Figure 2.3, the test facility consists of approximately 25,000 graphite pebbles randomly packed within an

2.2.3 GPBR Demonstration

 The GPBR200 (generic pebble bed reactor 200MWth) reactor design [7, 13] has been chosen as the
demonstration case in this study, focusing on the steady state nominal condition, and the depressurized/-
pressurized loss of forced cooling (DLOFC/PLOFC) events. The reactor has an installed thermal power of
200 MW, cooled by pressurized helium gas with the primary coolant pressure of 6 MPa, inlet and outlet
core temperatures of 533 K and 1023 K, respectively, and a nominal helium mass flow rate of 78.6 kg/s
during steady-state normal operating condition. The pebble-bed core has a packing factor of 0.61 and roughly
223,000 pebbles are loaded. The full model includes both the reactor core and a RCCS (reactor cavity cooling
system). The schematic of the full model and the core is shown in Figure 2.7 and key dimensions of the core
are also tabulated in Table 2.2.

 Using a similar modeling approach as described in our previous work [7], the pebble bed core is modeled
with 5 CoreChannel components, each of which effectively represents a column of cylindrical (the center
one) or annulus of pebble bed. Like the SANA model, each pair of neighboring channels are connected using
both effective thermal conductivity and crossflow model. The full model, including both the reactor core and
RCCS, contains around 3400 unknowns. With the inclusion of these new features, this model is considerably
different than the reference model discussed in [7], and therefore, a one-to-one comparison has not been
performed as it has been done in our previous feasibility study.

 For the steady state nominal operation condition simulation, spatially distributed power is provided, as
shown in Figure 2.8 (left). Steady state results were obtained by using the ‘steady’ solver, which took 60
nonlinear iterations, which is exceptional given the complexity of the model that consists of a helium and a
water loop, and the complexity of thermal fluid behaviors, involving both forced convection in the helium
loop and natural circulation in the RCCS loop. Nevertheless, the simulation is very efficient, which only

3 Restart

 The MOOSE framework provides generic restart/recover mechanisms for MOOSE-based simulations
through its checkpoint outputs or solution files. As defined in MOOSE framework, ‘recover’ is to resume an
existing simulation either due to a fault, or other premature termination such as unexpected code crash or job
wall-time limit. The ‘restart’ has a broader meaning that refers to running a simulation that uses data from a
previous simulation. For reactor safety analysis, ‘restart’ has been commonly adopted as a mechanism to
execute safety transient simulations. Typically, a null transient simulation is executed first to obtain steady-
state solutions to represent the nominal operating condition of a reactor system. A real transient simulation is
then executed, restarted from the existing steady-state solutions, to simulate reactor safety transient events.
This restart mechanism allows safety analysis to be more efficient. Since no actual transient is simulated, the
null transient model does not require complex input blocks associated with transient analyses, such as control
system logic and decay heat models. The real transient input model restarts from the converged steady-state
solution and performs the desired transient simulation, incorporating all necessary transient-specific models
and control logic. This separation results in a cleaner workflow, simplifies debugging and verification of the
steady-state solution. This also allows different transient scenarios to be modeled using the same initialized
reactor state, and avoids the same null transient being repeatedly executed.

 As a system analysis code, SAM deals with data in a very flexible form which is not always mesh based,
for example, water level in a liquid tank or the open/close status of a check valve. Therefore, SAM code
restart capability has mostly relied on MOOSE’s checkpoint option, which not only can use mesh-based data,
but also other flexible data format. SAM-FVM, as detailed in previous studies [3–5], handles interfaces with
the nonlinear solver and therefore requires more flexible data structure. It has built-in functionality to map the
solution vector to local physical quantities such as fluid pressure, temperature, velocity, density, enthalpy, etc.
This functionality perfectly servers the purpose of initialize a simulation from existing old and older solution
vectors, uold and uolder , which can be retrieved from the checkpoint file. At the end of each (successful) time
step, the converged solution vector becomes the old solution, u → uold , and the old solution becomes the
older solution, uold → uolder . Both vectors are declared as ‘restartable’ and saved into the checkpoint file.
When restarting from the saved checkpoint file, the old solution vector, uold , is retrieved to restore the old
status of the system and also to serve as the initial guess for the current time solution. The uolder solution is
restored when a higher order time integration scheme, such as BDF2, is used.

 After the implementation of those minor adjustments to store and retrieve old and older solutions
for recover/restart purpose, the correctness of the recover/restart code capability can be easily checked by
MOOSE’s ‘recover’ test option. By executing the following command line:
 ./ run_tests -j 12 -- recover

4 MultiApp

 The MOOSE framework provides flexible and built-in capability, as referred to as the ‘MultiApp’
 system, to enable multi-scale and multi-physics simulations that are common in nuclear reactor analysis. For
 SAM, such multi-scale and multi-physics simulations have been extensively practiced in the past. Examples
 include multi-scale coupling between one-dimensional (1D) flow channels and three-dimensional (3D) heat
 conduction problem, multi-scale coupling between one-dimensional flow and multi-dimensional flow models,
 multi-physics coupling between SAM thermal-hydraulics and reactor physics simulations. Most of such
‘MultiApp’ simulations are achieved using the method of Picard iterations, and data were transferred between
 different ‘Apps’ using MOOSE’s built-in data transfer mechanisms, or app-customized mechanisms. The
 data being transferred between the ‘Apps’ can also be very flexible, for example, spatially distributed power
 density projected from a source App to a target App based on mesh/geometry, or simply a total power
 integrated from the source App and transferred to a target App.

 For this work, it is not intended to explore and implement codes for all possible multi-scale and multi-
physics simulations. Instead, as SAM-FVM has its own data flow handling functions and timings, it is
essential to ensure these data flow handling process are compatible with data transferring between multiple
Apps handled by MOOSE. The successful code implementation will serve as a template for future code
implementations when more complex data transferring is required. To show that, we selected the coupled
one-dimensional flow channels and three-dimensional heat conduction problem as the demonstration case.
A ‘HeatTransferWithExternalHeatStructure’ component was implemented in SAM-FVM, using the same
name as in the existing SAM-FEM code for backward compatibility purpose. The implementation is rather
simple and straightforward. The component automatically adds an MOOSE AuxVariable for Twall onto the
one-dimensional flow channel, which is only a placeholder, and their values will be populated by a MultiApp
data transfer from the multi-dimensional heat conduction simulation, typically at the beginning of a time
step before the nonliner system is being solved. At the same time, the multi-dimensional heat conduction
simulation declares a fluid temperature, T f luid , as a placeholder AuxVariable whose values are also transferred
from the one-dimensional flow channel. The scheme of the coupling is illustrated in Figure 4.1

5 Conclusions

 In FY26, work has been done to continue the feasibility study of SAM-FVM, focusing on three technical
areas/tasks: 1) implementation and testing of flow model suitable for gas-cooled reactor analysis, 2) code
recover/restart capability essential for reactor safety transient analysis, and 3) code capability to support
MultiApp simulations.

 The first task extends the previous SG-FVM feasibility study in SAM-FVM from incompressible but
thermally expandable, liquid-cooled systems to compressible, gas-cooled systems, with a particular focus on
pebble bed HTGRs. To support PB-HTGR analysis, additional code capabilities were added to the pebble
bed CoreChannel component, including a pebble bed effective thermal conductivity model for radial and
axial heat transfer between adjacent pebble bed solid structures, and a channel-to-channel crossflow model
driven by radial pressure gradients enabling the adequate modeling of in-core natural circulation.

 Three test cases were used to assess code correctness and robustness for PB-HTGR simulations. The
HTTU separate-effects tests provided a code-to-code comparison against SAM’s existing two-dimensional
porous medium model. The 6- and 12-channel CoreChannel models predicted pebble temperatures agreeing
very well with the porous medium model results. For the SANA validation case, using a 12-channel model
to simulate both a helium-cooled and a nitrogen-cooled cases, numerical results on pebble temperatures
showed reasonable agreement against experimental data. The model was also able to capture the strong
in-core natural circulation for the nitrogen case. The GPBR200 demonstration exercised the integrated code
capabilities at a reactor scale, covering the nominal operation steady-state simulation, and the DLOFC and
PLOFC transient simulations. Both transients reproduced expected behaviors, including the characteristic
PLOFC peak-temperature reduction and upward shift of the hot zone driven by in-core natural circulation
that is absent in the DLOFC case.

 The other two tasks were focused on further improving code usability and maturity to support realistic
reactor safety analysis. SAM-FVM has been augmented to leverage MOOSE’s built-in code capabilities
that stores data in its checkpoint files, based on which the solution vectors could be recovered to re-initialize
the simulation to recover/restart. At the current status, all regression tests, around 150 of them, can be
recovered/restarted successfully. For MultiApp capability, code development was done to enable a coupled
3D heat conduction and 1D flow problem. A test case of a prismatic graphite/fuel block cooled by seven
coolant channels was demonstrated. The results were compared with reference results using SAM-FEM and
MOOSE heat conduction model, and the agreement was great.

 To summarize, FY26 SAM-FVM code implementation focused on HTGR applications and code
verification, validation, and demonstration, proves that SAM-FVM a viable and efficient solver pathway
for compressible, gas-cooled reactor analysis, in addition to what has been previously demonstrated with
incompressible flow models. Additional code development to support SAM-FVM recover/restart and
MultiApp capabilities only requires minimal code adjustments to leverage existing MOOSE capabilities.
With all these evidence, it can be concluded that the SG-FVM will form a strong foundation as SAM’s
advanced solver option for future deployment.
