Near-optimal Online Traffic Engineering Conference: ; 2018
Arvin Ghavidel, Pooria Namyar, Nikolai Matni, Walter Willinger, Ramesh Govindan

Abstract




Abstract:

Most deployed WAN Traffic Engineering (TE) systems use a logically centralized controller that periodically gathers traffic demands, runs a TE optimization or heuristic, and then programs the network.
At scale, these solutions can be sub-optimal, and can take minutes to react to demand changes or failures.
In this paper, we introduce OnlineTE, a system that reacts immediately to demand changes and failures, and delivers near-optimal solutions within seconds of a change.
OnlineTE builds on the theory of optimization decomposition to devise scalable, near-optimal, distributed TE solvers for path-based MLU and Max-flow problems.
In OnlineTE, each switch solves part of the optimization, and a central coordinator orchestrates the progress of the switches.
As such, a switch can trigger a re-optimization as soon as it notices a demand change or failure, enabling high reactivity.
OnlineTE scales to large WANs, and its compute requirements are well below the capabilities of modern WAN switches.
It also enables a new opportunity, edge-based TE, which can utilize resources more efficiently than today’s path-based approaches.
On a testbed emulation of a 750-node WAN topology, OnlineTE can outperform the state-of-the-art by up to an order of magnitude.

1.
Introduction

Traffic engineering (TE) is an indispensable component of today’s wide area networks (WANs).
It enables cloud providers and ISPs to route
demands
between each ingress-egress router pair efficiently and fairly, while ensuring good application perceived performance.
At the core of today’s TE systems is an algorithm that routes demands across multiple pre-computed paths. It aims to achieve a global objective, such as maximizing total flow (henceforth, Max-flow) or minimizing maximum link utilization (henceforth MLU) without violating link capacity constraints.
TE is also used in cloud provider private WANs
(
28
;
12
;
21
;
23
)
and in data centers
(
40
)
.
In these settings, TE algorithms must support additional features, such as traffic prioritization and fairness
(
20
;
23
;
21
;
28
;
12
)
, or be designed to co-exist with other techniques like topology engineering
(
40
)
.

1.1.
Centralized TE

Most deployed TE algorithms run on a logically centralized controller (
Fig.

1
).
The controller periodically (
e.g.
, every 5 minutes
(
20
;
35
;
28
)
) (a) collects demands from switches and predicts future demand, (b) runs the TE algorithm on predicted demand, and (c) installs forwarding rules on switches based on the TE algorithm’s output.
These rules
split
the demand between each ingress-egress pair across pre-computed paths between those routers.
With a global view of traffic and topology, centralized TE can make routing decisions across the entire network and utilize network capacity efficiently.
However, there are two limitations.

They trade off optimality for scale.

Optimal algorithms for allocating demands to paths have been widely studied
(
10
;
11
)
.
However, as networks scale, the time to compute these optimal allocations can increase substantially
(
35
;
1
)
.
This can delay the response to demand changes or failures, and significantly impact availability.
To avoid this, most deployed TE algorithms use heuristics to scale
(
27
;
28
;
12
;
23
;
21
)
which can exhibit poor worst-case behavior
(
34
)
.
Some
(
20
;
35
)
use approximation algorithms with bounded optimality gaps.

In response to this, a line of work has explored speeding up TE algorithms by contracting the network
(
1
)
, partitioning
(
37
)
, training ML models
(
39
;
46
)
, or decomposing the optimization
(
45
)
.
Many of these achieve speed at the expense of optimality, and ML-based methods
(
39
)
can also exhibit poor worst-case behavior
(
36
)
.

They are slow to react.

Even with scalable TE algorithms, the overall TE control loop (
Fig.

1
) incurs non-trivial end-to-end latency.
As a result, deployed TE controllers typically re-optimize only once every few minutes
(
46
;
16
)
.
In today’s networks, this can reduce availability.
Traffic demands can change over shorter timescales
(
35
;
16
)
than the periodicity of TE.
If these changes produce a traffic matrix outside the predicted demand used to compute the TE solution, the increased demands can overload links and cause packet drops.
Reaction to failures can also impact availability: when one or more links go down, the residual capacity may be insufficient to accommodate existing demands, so congestion might persist until the next iteration of the control loop.

1.2.
Distributed TE

In response to these shortcomings, other approaches have considered
distributed
approaches to TE.

TeXCP
(
24
)
and MATE
(
13
)
have explored an approach in which each ingress router repeatedly (a) measures congestion on demand paths, (b) locally and independently adapts demand splits based on these measurements.
While these approaches guarantee stability, they can converge slowly and can be sub-optimal because routers do not explicitly coordinate when determining the local splits, but do so implicitly via path congestion measurements.

More recent work, dSDN
(
26
)
, explores a different point in the design space, albeit in the cloud provider setting.
It is motivated by controller complexity, and is predicated on the availability of non-trivial compute on today’s switches.
In dSDN, routers flood link state and demand changes, and each router periodically runs a TE algorithm to compute path splits.
While it can react faster than centralized TE, dSDN requires
every
switch to solve TE for
all
demands in the network.
Routers have modest compute, so dSDN can only run TE heuristics
(
23
)
and can thus be sub-optimal.
Its reaction and convergence time is constrained by how quickly demand information can disseminate through the network and how quickly the TE algorithm completes.

1.3.
OnlineTE

In this paper, we explore a new capability,
near-optimal online TE
(OnlineTE, for short).
OnlineTE decomposes the TE algorithm into two parts (
Fig.

1
), one which, motivated by the availability of switch compute
(
26
)
, runs on switches, and another on a centralized controller (
Section

2
).
Instead of running the TE algorithm periodically, it initiates the TE computation as soon as any demand on any switch changes.
This re-computation finishes
in a few seconds
and is near optimal even on a large WAN (
Section

7
).
At the end of the re-computation, each switch knows the traffic splits for its demands, so it can install them locally.

OnlineTE is currently designed for TE algorithms used in ISP settings, MLU and Max-Flow.
We have left extending to other objectives (prioritization, fairness) to future work.

Our design addresses the three shortcomings discussed above.
Unlike existing centralized or distributed approaches, OnlineTE can quickly compute near-optimal TE solutions even for large WANs because it leverages massive parallelism by distributing the computation across switches (
Fig.

1
).
OnlineTE also reacts much faster than centralized TE for two reasons.
First, OnlineTE’s algorithms can
warm-start
from the most recent solutions, avoiding the cold
-
start overhead that slows down centralized TE methods.
Second, switches compute and install the demand splits locally, whereas centralized TE must program the switches across the entire network, incurring significant latency
(
26
)
.

OnlineTE achieves this by building upon a long line of work on optimization decomposition
(
7
)
.
We explain how these decompositions work with a simple example.

To solve this optimization in a distributed fashion, consider the following iterative approach, which proceeds in rounds.
In the first round, each switch initializes the splits, then sends these to a central coordinator.
The coordinator sets
prices
on path segments on which the demands overlap, where the price reflects the relative utilization on the bottleneck link on the path segment.
In subsequent rounds, each switch updates the splits to lower the prices, then sends these to the coordinator, and the process repeats.
Eventually, the switches find splits that converge to the optimal MLU (0.75 in our example).

Challenges and Opportunities.

The theoretical foundations for decomposing optimizations were developed decades ago
(
7
;
6
)
.
However, we know of no prior work that has exploited optimization decomposition to devise a completely
distributed
algorithm for TE.

Fig.

2
uses the method of
dual decomposition

(
41
)
because the coordination between controller and switches via prices is easier to understand.
OnlineTE, however, uses a variant, the Alternating Direction Method of Multipliers (ADMM)
(
7
)
, to decompose an optimization similar to
Fig.

2
.
ADMM provably converges quickly to a near-optimal solution.
Even so, adapting ADMM to the networking setting presents four major challenges (
Section

2
).

First, TE algorithms often use different objectives (Max-Flow, MLU), and OnlineTE must support these.
In each case, determining the decomposition (
i.e.
, which part of the algorithm runs on the switches, and which on the controller, as in
Fig.

2
) can be tricky and involve complex mathematics.

Second, the decomposition must scale well in the volume of information exchanged between the controller and the switches.
A generalized version of our example in
Fig.

2
requires a price per edge per demand.
In a large ISP network with hundreds of links and tens of thousands of demands, this can be prohibitively expensive.
The decompositions must also be computationally-efficient.
In general, in optimization decomposition, each component also runs an optimization.
The component that runs on the switches must be lightweight enough to run on switch CPUs.

Third, in a large network, switches and the controller might need many more iterations to converge than in our example (
Fig.

2
), which can result in large convergence times especially for continental-scale WANs.
OnlineTE must converge quickly.
In particular, the algorithm described in
Fig.

2
is
synchronous
; the controller must wait for each switch to finish a round before proceeding to the next.
Large delays between a controller and a
single
switch in a large WAN can adversely impact convergence.

OnlineTE Design

In this section, we first introduce ADMM and then provide an overview of OnlineTE.
Subsequent sections describe our solvers’ design.
Our descriptions of ADMM and our designs are informal; appendices contain mathematical details.

2.1.
Introduction to ADMM

ADMM
(
7
)
solves an optimization problem by
decomposing
it into sub-problems, then iteratively solving each sub-problem in turn.
Depending on the optimization problem and its decomposition, it may be possible to solve some of the sub-problems in a distributed manner.

Figure 4.
ADMM decomposition for a simple Consensus problem.

Fig.

4
illustrates an optimization problem for
distributed averaging
,
i.e.
, finding the mean of a set of values distributed across the network.
It is somewhat contrived—there are better ways of averaging—but illustrates ADMM decomposition.
Consider a network with
N
nodes, where each node
i
holds a local value
c_{i}
and a variable
x_{i}
.
Our goal is for every
x_{i}
to converge to the arithmetic mean of the
c_{i}
s, enabling all nodes to compute the global mean in a distributed fashion.

In
Fig.

4
,
Opt
’s objective exploits the property that the sum of the squared deviations of any number
z
from a set of
N
numbers (
i.e.,

c_{i}
s) is smallest when
z
is the mean of the
N
numbers.
The constraint ensures that all
x_{i}
s eventually converge to the mean
z
.

The fundamental problem is that no node in the system knows all the values of
c_{i}
and of
z
.
ADMM allows nodes to iteratively converge on the global mean.
It does so by decomposing the problem into three steps (
Fig.

4
).
These three steps execute iteratively one after another.
At the end of each iteration, intuitively, all nodes move a step closer to
z
, at a rate determined by a step size
\rho
.

In the
k+1
-th iteration, the
x
-update
step, moves
x_{i}
towards the current estimate of the global mean
z^{k}
.
It does this using a
dual variable

y_{i}
for each node, which captures, at any given instant, how far off a node’s estimate
x_{i}
is from
z^{k}
.
Then, each node conveys the updated value of
x_{i}
to a
central coordinator
, which updates the current estimate of
z^{k}
(each node also sends its
y_{i}
estimate to the coordinator), a step called the
z
-update
.
Subsequently, the coordinator sends the new estimate of
z^{k+1}
back to all the nodes.
Each node first updates
y_{i}
(the
dual-update
), then repeats the cycle again.
It is easy to see this
ADMM loop
would eventually result in
x_{i}
s converging to the mean of
c_{i}
s.

This example highlights several properties of ADMM that we exploit for OnlineTE.

•

Given an optimization formulation, an ADMM decomposition consists of three update steps, executed iteratively as described above
(
7
)
.
With rather mild assumptions, the iterations provably converge to an optimal solution; more important, for an appropriate choice of step size
\rho
, the computation gets very close to the optimal in a few steps
(
7
)
.

•

We can
warm-start
the ADMM loop in
Fig.

4
. For example, if
c_{i}
s at some nodes change, the technique can start from the previous values of
x_{i}
to converge to the new optimum.

•

The decomposition in
Fig.

4
is amenable to a distributed implementation: all the nodes can perform the
x
-update and dual-update steps
in parallel
, while the
z
-update is centralized.
This requires modest
communication
: at each iteration, each node sends two values (
x^{k+1}_{i},y^{k}_{i}
) to the coordinator and receives a single value
z^{k+1}
.

•

Each update has lower
computational complexity
than
Opt
, which is a quadratic optimization.
In this example, all the steps have closed-form solutions.
In other cases, the
x
-update and
z
-update may require solving an optimization.

2.2.
OnlineTE Overview

OnlineTE provides a family of distributed TE solvers, each of which is both near
-
optimal and online.
It supports both path
-
based
(
16
;
46
)
and edge
-
based TE formulations.
OnlineTE can also optimize two objectives widely used in TE: MLU and Max-flow (
Section

1
).

Requirements.

In addition to being near-optimal, OnlineTE’s decompositions must enable solvers to be
online
—when a demand change or link failure happens, the solver must (a) start re-optimizing the demand splits immediately, instead of periodically (
Section

1
), (b) the re-optimization must converge quickly and (c) when the re-optimization completes each switch must be able to
effect
the revised demand splits by locally programming its flow tables; in other words, the decomposition should not require coordination between switches to install flow state.
All of these enable fast reactivity to changes.
In general, (b) may not always be possible with ADMM; in each iteration, the
x
-update and the
z
-update may require solving an optimization.
Heavyweight optimization solvers (
e.g.
, those that use interior point methods for linear programs
(
14
)
) re-solve the optimization from scratch at each iteration, and can delay convergence.
OnlineTE must find more computationally-efficient decompositions, especially for the switch-side optimization, and leverage
warm-starting
from previous solutions to speed up convergence.

OnlineTE should
scale
to large networks
(
28
)
.
There are two components to scaling:

Communication efficiency
demands that the communication cost of the distributed computation scales well with network size and the number of demands.

Computation efficiency
requires that the per-switch computations remain feasible given the computing capabilities of today’s network devices.

Our solution must
converge quickly even as the network scales
.
Each iteration can finish only after the coordinator has received updates from all switches, so overall convergence is constrained by the maximum latency between the coordinator and any switch.
As network size increases, so can this latency, and OnlineTE must incorporate techniques to converge quickly despite this increased latency.

Finally, we must preserve
uniformity
to simplify implementation.
This means the ADMM components must be re-usable: where possible,
x
-update or
z
-update steps must be near-identical, or use the same type of solver.
Control structures must follow similar patterns, such as the coordinator-orchestrated pattern of
Fig.

4
.

3.
The Edge-Based Solver for MLU

We first describe OnlineTE’s online edge-based solver for MLU, because this is the easiest to explain intuitively.

Appendix

B
contains the detailed mathematical descriptions.

Edge-Based TE

takes a set of demands as input, each representing traffic between a pair of switches.
It attempts to route these demands while
minimizing
MLU.
Path-based TE assumes a pre-configured set of paths between every switch pair but edge-based TE jointly optimizes the paths and the allocations for every demand.
As a result, the edge-based problem is harder to scale, which has prevented its adoption in deployed systems.
If a scalable solution exists, it would strictly outperform (
e.g.
, have lower MLU or higher total flow) path-based methods.

A solution to the edge-based TE problem that optimizes MLU must satisfy two sets of constraints.
Demand constraints ensure that every demand is
fully routed
: the solver assigns sufficient paths and capacities for each demand.
Flow conservation constraints ensure that, for every demand, the total ingress traffic at every intermediate switch equals the total egress traffic: traffic does not disappear in the network.

A Strawman Distributed Edge-based TE.

With an appropriate ADMM decomposition, edge
-
based TE becomes tractable because the optimization can be parallelized across hundreds or thousands of switches.
However, identifying a decomposition that is both correct and amenable to distributed implementation is challenging.

A strawman approach is to apply an ADMM decomposition similar to that of
Fig.

4
, but with different variables and update steps.
The
z
variable is a matrix representing the total flow per demand on each edge.
The
y
variable encodes the price of sending an additional unit of flow through an edge.
The
x
variable is also a matrix, where the
(i,j)
-th entry denotes the amount of demand
i
routed on edge
j
.

In each iteration, on the controller, the
z
-update uses the current
x
values to update
z
so as to minimize MLU, and the
y
-update sets prices on each edge.
On each switch, the
x
-update adjusts per-edge allocations to minimize the total price.
Specifically, each switch determines how to split each demand across its egress ports.
This moves demands away from heavily congested edges.
The magnitude of each update is controlled by the step size
\rho
(as in
Fig.

4
).

The prices enable ADMM to alternately refine
x
and
z
, allowing each to be updated using a separate optimization.

Unfortunately, this strawman approach
does not scale well
.

z
is a matrix whose dimension grows with the product of number of demands and edges, and
x
i
on each switch grows with the number of demands.
2
2

2

Each switch computes and sends only the columns of the
x
matrix that correspond to its egress edges.

A large WANs with a thousand nodes
(
28
)
can have up to a million demands, so
z
and
x
i
can be matrices with up to a billion and a million entries respectively.
Each ADMM iteration involves sending
z
from the controller to all the switches and
x
i
from all the switches to the controller.
So, transmitting such large matrices significantly slows down convergence.
Furthermore, since transmitting
x
and
z
represents control traffic, this approach would incur significant control overhead.

Towards Practical Edge-based TE.

We improve the communication-efficiency of the edge-based solver as follows.
Observe that a switch does not need to know the per-demand allocation on each edge for
other switches
; it only needs to know the total flow allocated (or the utilization) on each link.
Accordingly, in OnlineTE, the
z
encodes the total flow allocated to each edge.
As a result, the controller sends to every switch a vector whose size scales only with the number of edges rather than with the product of edges and demands.

To reduce the size of
x
, instead of requiring each switch to compute split ratios for all demands, OnlineTE asks each switch to
compute routing decisions only for the demands that originate at that switch
, but across all links.
This design has three advantages.
First, it reduces the size of
x
i
from the number of global demands to the number of edges.
Second, because allocations can be biased to lie on near
-
shortest paths for low latency (see below), the resulting
x
is sparse, making the actual communication cost far smaller.
Finally, at the end of the optimization, each switch (a) can program the demand splits locally (
i.e.
, in a consensus-free manner
(
26
)
) and (b) knows the paths allocated to the splits and can use source-routing to send packets
(
26
)
.
This renders the edge-based solver practicable in WAN settings.

Nested ADMM: Improving convergence further.

We have found that this decomposition converges slowly, because the switches are
chasing a moving target
.
In one iteration,
z
-update sets target utilizations on links that optimize MLU, and the
x
-update moves switch allocations towards these prices.
However, in the next iteration,
z
-update updates these target utilizations, and the switches must now readjust their allocations to move towards these new targets.

We have found that faster convergence can be achieved by introducing a
nested ADMM
loop.
In the inner loop, switches take multiple steps to move towards a given, fixed, target.
Then, the outer-loop iteration runs once to re-adjust the target, and the inner-loop repeats again.

Fig.

7
illustrates the benefit of this approach: the optimality gap (difference between the optimal and the distributed solver’s MLU) decreases much faster over time (y-axis in log-scale) for OnlineTE’s nested approach than a non-nested approach.

In the
inner
ADMM loop, the
x
variable, denoted
x_{inner}
, is the same as the outer ADMM loop’s
x
variable which captures the assignment of demands to network edges.
However,
z_{inner}
is a variable that tracks the target mean of all commodities on an edge, and the dual
inner
variable tracks the difference between this mean and each switch’s assignment.
This effectively ensures that the
x_{inner}
-update is decoupled from the
z
-update.
Specifically, the inner ADMM loop converges to a target mean per edge (using
\rho_{inner}
as the step size), the outer ADMM loop revises that target to move allocations closer to the optimal (using
\rho_{outer}
as the step size), the inner ADMM loop revises allocations to meet the new targets, and so on.
Unlike the Consensus problem of
Fig.

4
, the inner ADMM loop solves a
Sharing
problem
(
7
)
where switches collaborate to share allocations on each edge.

This nested ADMM loop structure does not increase communication complexity relative to the non-nested decomposition.
Each switch send its
x_{inner}
to the coordinator; these contain edges on which the switch’s demands are non zero.
The coordinator sends
z_{inner}
and dual
inner
to the switches, each a vector with one entry per edge.

Fig.

7
depicts where each part of the inner and outer ADMM decompositions is executed, and what information the switches and the coordinator exchange.
Only the
x_{inner}
-update runs on the switches; all other components run on the coordinator.
As discussed above, to achieve fast convergence, we need to iterate on the inner ADMM loop a few times before running one instance of the outer ADMM loop.

Improving Computation Efficiency.

Unfortunately, in the inner ADMM decomposition, the
x_{inner}
-update optimization is too heavy-weight.
It contains numerous variables and constraints to ensure flow conservation and demand satisfaction.
To reduce its computational complexity, we obtain a null space basis of the topology adjacency matrix, which requires a one-time singular value decomposition (SVD).
We then express the demand satisfaction constraint in terms of the basis vectors of this matrix.
This technique reduces the number of variables to
O(|E|-|V|)
, where
|E|
is the number of edges and
|V|
is the number of nodes.
When formulated this way, flow conservation does not require separate constraints.

Appendix

B
describes the mathematical details.

Without this optimization, solving
x_{inner}
-update may require complex interior point methods
(
8
)
using a commercial solver
(
15
;
4
)
.
Such methods cannot be easily warm-started, so our solver cannot run online.
With this optimization, we can use simpler methods described below.

Computational Complexity.

This final decomposition (using nested ADMM and the null space decomposition) also has attractive computational complexity properties.
The most heavyweight component is the
z
-update.
This is an inequality constrained, convex quadratic program (QP) with the number of variables equal to the number of edges.
For
z
-update, we use PDLP
(
4
)
, a recent open-source solver designed for large-scale optimization problems with good warm-start performance.
In OnlineTE, the coordinator can be implemented in an SDN-controller, whose computational resources are sufficient to run PDLP.

The
x_{inner}
-update is a very lightly constrained convex QP with
O(|E|-|V|)
variables.
It can be parallelized across demands at a single node.
Each instance can be solved using simple algorithms like projected gradient descent
(
8
)
, which can easily be warm-started.
As we show in
Section

7
, these can run on moderately powerful switch CPUs
(
26
)
.
The
z_{inner}
-update has a computationally lightweight closed-form solution, and the dual variable updates for both ADMM loops involve simple vector operations.

Controlling path stretch.

Edge-based TE can better optimize the global objective than path-based TE, but may allocate long paths to some demands, increasing latency.
To address this, our edge-based solver adds an
\ell_{1}
-norm regularizer to the
x_{inner}
-update.
This has the effect of incentivizing the solver to return
sparse
allocations (those with mostly zero entries).
A parameter
\kappa
controls the degree of sparsity, and indirectly, the path stretch, since if demands are allocated to fewer edges, they are less likely to encounter long paths.
This regularizer applies both to edge-based Max-flow (
Section

4
) and MLU.

\kappa
is a function of the topology, not the objective.

The regularizer increases the computational complexity of the
x_{inner}
-update slightly, so that, instead of projected gradient descent, it requires a more complex coordinate descent
(
44
)
solver.
This can run on switch CPUs and can warm-start.
Regularization does not change communication complexity.

4.
Extensions: Max-flow and Path-based TE

The Edge-based Max-flow solver.

Edge-based Max-flow requires relatively small changes to the nested ADMM structure of
Fig.

7
.
Specifically, it introduces a new variable
\beta
to the
x_{inner}
-update, a vector of dimensionality equal to the total number of demands.

\beta_{k}
specifies what fraction of the demand is currently being routed.
This is paired with an
\alpha
vector in the
z
-update which tracks target fractions.
These terms appear in the dual variables as well.

These additions do not significantly increase the communication cost.
After the
x_{inner}
-update, the switch must send the
\beta
values for its own demands to the controller.
The number of demands at a switch is proportional to the number of nodes in the network.
The computational complexity of all components remains the same as for MLU, except for the
x_{inner}
-update.
This is a QP with a coupling term (
x_{inner}
and
\beta
are coupled), for which we use coordinate descent
(
44
)
which can also be warm-started.

Path-based TE.

OnlineTE includes MLU and Max-flow solvers for path-based TE.

Appendix

C
describes the mathematical details underlying these solvers.

Both use the nested decomposition described in
Fig.

7
.
More important, the
z
-update in the outer ADMM loop is identical to that in edge-based TE.
This is possible because a path-based assignment can be converted into an edge-based assignment.
There are two benefits to this.
It allows us to re-use components from edge-based solvers thereby addressing our uniformity requirement.
Moreover, it preserves the communication complexity of edge-based solvers which scales with the number of edges.

The inner ADMM loop changes slightly.
Specifically,
x_{inner}
now encodes demand splits per path instead of per edge, and
z_{inner}
encodes the capacity headroom available per path.
The dual variables do not change.
Finally, the complexity of
x_{inner}
-update changes slightly.
Recall that this step uses projected gradient descent.
In the path-based solvers, the projection step is more expensive because the
x_{inner}
-update problem is more constrained; the projection for edge-based TE in contrast is very trivial.
Despite this, the path-based solver is still faster, as it handles much fewer variables.

Finally, the inner ADMM converts the path-based assignments to an edge-based assignment.
To do this, in practice, each switch could monitor the edges on its pre-configured paths using MPLS traceroute.
In settings where tunnels are configured by an SDN controller
(
12
;
28
)
, the switch agent would have this information.

5.
Ensuring Fast Convergence at Scale

As described so far, the inner ADMM loop is
synchronous
; the coordinator must wait for all switches to respond before processing a
z
-update.
As the network scales, the time to complete one iteration is a function of the maximum latency between a switch and a coordinator.
A
straggler
can significantly slow convergence, a problem faced by many synchronous distributed computations (
e.g.
, LLM training).

Asynchronous ADMM.

To address this drawback, prior work
(
47
;
43
)
has considered methods that introduce asynchrony in ADMM loops.
In these methods, the coordinator runs a
z
-update even without receiving updates from all switches.
For OnlineTE, we have adapted the
partial-barrier
asynchronous ADMM technique designed for consensus problems
(
47
)
to our inner ADMM loop which solves a sharing problem.
In partial-barrier, the coordinator can apply a
z
-update after a
minimum
of
k
nodes respond.
It then sends the updated
z
only to the responders.
In addition, any given node must respond at least once within
\tau
iterations.
Partial-barrier still ensures convergence to the optimal
(
43
)
, and convergence time is proportional to
\tau
and inversely proportional to
k
.It can be used in all the solvers discussed above, edge-based or path-based, for MLU and Max-flow.

Unfortunately, even this asynchronous ADMM is insufficient to ensure fast convergence.
On a large WAN with over 700 nodes (
Section

7
), we were unable to observe convergence with the partial-barrier method unless
k
was very large.

Exploiting Network Structure with Hierarchical ADMM loops.

Due to geographical constraints, switches naturally cluster into
regions
, with the property that switches within a region (
e.g.
, a metro area or a state) are closer to each other than to switches in other regions.

To speed up convergence, OnlineTE structures large-scale edge-based or path-based TE problem as a
hierarchy of ADMM loops
(
Fig.

7
).
Within a region, a region coordinator and switches within the region run the nested ADMM loop of
Fig.

7
.
A second
inter-region ADMM loop
between a global coordinator and the region controllers coordinates inter-region allocations. All intra-region ADMM loops are synchronous, and the inter-region ADMM loop is asynchronous.
If one, or a few regions are stragglers, asynchronous ADMM will still permit fast convergence on allocations that impact only the non-straggler regions.
For example, in path-based TE, if a path traverses regions A, B, and C, a straggler region D cannot impact the convergence of allocations on that path.

This inter-region ADMM loop solves a consensus using a structure identical to
Fig.

4
.
Each region coordinator (
Fig.

7
) runs an
x_{hier}
-update, where the
x_{hier}
is a vector which contains the total flow allocated for traffic originating within this region on all edges in the network.
The global coordinator runs the
z_{hier}
-update, in which the
z_{hier}
is an
R\times|E|
matrix, where
R
is the number of regions.
The
(i,j)
-th entry in this matrix is the amount of flow on edge
j
that region
i
may
not
allocate,
i.e.
, it is reserved for other regions.
Intuitively, the
x_{hier}
-update step allows regions to use available capacity without violating capacity constraints.
A region does not need to know how many demands each other region has, and how these demands are allocated.
The
z_{hier}
-update step sets reserved capacities to bias allocations towards the global objective (MLU or Max-flow).
The dual variable incentivizes
lagging
regions—those whose allocations have not fully utilized available capacity—to catch up.

The inter-region loop’s
x_{hier}
and
z_{hier}
are the same for all solvers.
Different solvers would update these variables differently, depending on the problem or objective.
The communication complexity of the inter-region ADMM loop is proportional to
R\times|E|
; each region coordinator sends and receives a vector of length
|E|
.
In a network with a thousand edges, this information is about 4-8 KB.
The computational complexity of the
x_{hier}
-update and the
z_{hier}
-update is also minuscule.
In fact, these complete quickly enough that we do not need a solver with warm-start capabilities.
Moreover, these updates run on coordinators that can be co-located with SDN-controllers with sufficient compute capacity.

6.
Failure Handling

Switch or Link failures.

In addition to demand changes, OnlineTE can also react immediately to link and switch failures and converge to near-optimal allocations.
Consider a link failure.
In path-based TE, if a switch has a path traversing the failed link, it can detect the failure using BFD
(
18
)
, set the demand allocation on that path to be zero, redistribute that allocation locally, then trigger the ADMM loops to ensure convergence.
This approach would also apply to TE systems that pre-configure backup paths
(
12
;
28
)
; prior to the failure, OnlineTE would not allocate demand on these paths, but would do so after the failure.
In edge-based TE, a link failure changes the topology adjacency matrix, and the switch re-factorizes the previous allocations to the new adjacencies.
This re-factorization percolates to other switches (and other regions) during the ADMM iterations, resulting in a near-optimal allocation.
A switch failure can be treated as the simultaneous failure of its attached links, and the steps described above would apply.

Coordinator failure.

When a coordinator fails, a backup coordinator can resume from a
snapshot
of the ADMM computation.
After every iteration, region coordinators can snapshot the most recent
x_{inner}
s from all the switches, the
z_{inner}
and the outer-loop
z
, and its own inter-region
x_{hier}
as well as all dual variables.
The global coordinator can snapshot, after every iteration, the most recent
x_{hier}
’s from the regions, the
z_{hier}
, and the dual variable.
Switches do not need to snapshot state; we assume the switch’s ADMM computation shares fate with the switch.

Packet losses.

Switch-to-coordinator communication can use RPC, as can coordinator-to-switch communication in the inter-region loop.
In regions with many switches, using RPCs between a coordinator and each switch can introduce overhead, so OnlineTE’s current implementation uses multicast.
This is possible because
z_{inner}
is small (about 4-8KB in a network with a thousand links).
In this case, to counter packet losses, the coordinator repeats the multicast transmission a few times, then retransmits if some switches do not respond within a fixed timeout.

Metrics.

For MLU-based problems, the solution quality is measured by the MLU.
For Max-Flow, solution quality is determined by
Demand Satisfaction
, defined as the ratio of total routed flow to total demand.
However, since OnlineTE adapts online to demand changes and failures, but the baselines do not, we use a
regret
metric that captures the performance of the solver over time (instead of at a single instant).

We define two kinds of regret:
objective regret
and
capacity regret

(
Appendix

A
describes these formally).
To understand objective regret, consider an MLU experiment in which we induce traffic changes every 20 seconds.
At each traffic change, we compute the instantaneous
optimal
MLU, and compute, for OnlineTE and the baselines, the instantaneous MLU optimality gap (the difference between the baseline’s MLU and the optimal).
For other baselines, this instantaneous gap remains the same until the next demand change (
e.g.,
after 20 seconds), or until when they recompute a new solution (e.g., after 5 minutes).
For OnlineTE, this instantaneous gap remains until it converges after a demand change, at which point it changes because OnlineTE will have computed a near-optimal allocation.
The objective regret is the integral (the area under the curve) of the instantaneous gaps.
We compute objective regret for Max-flow in the same way, with the appropriate definition of optimality gap.

To understand capacity regret, consider a Max-Flow solver.
When a demand increases, it may cause a capacity violation until the solver installs a new allocation.
To capture this, at each 20-second mark, we compute the amount by which MLU exceeds 1.
Capacity regret is the sum of these across the duration of the experiment.
These definitions are consistent with those used in convex optimization
(
17
;
30
)
.

Finally, when evaluating OnlineTE’s edge-based solver (
Section

7.3
), we also report the
average stretch
per commodity, defined as the sum of path lengths used by a commodity, weighted by the demand split routed on that path and normalized by the shortest path.

For both, synchronous ADMM has very high latency, almost 40 s for cold-start, since the coordinator needs to wait to hear from all switches.
Asynchronous ADMM converges faster, but can incur long convergence due to a large update from a far away switch.
As a result, it exhibits high variability (over 10s warm-start at p75).
OnlineTE’s hierarchical ADMM dampens stale updates from domains by only passing relatively stable aggregate updates between domains, resulting in faster warm-start (about 7s at p75).

Conclusions and Future Work

OnlineTE is a qualitatively different approach to WAN traffic engineering, in that it is near-optimal, can react to failures and demand changes in seconds, and can support more efficient edge-based TE. On the largest publicly available WAN, its objective regret is sometimes an order of magnitude better than the state of the art. Future work can explore how OnlineTE scales, how its edge-based solver performs on other topologies, and how to further optimize its convergence.

B.1.
Transit Loops in Edge-Based Solutions

Before we describe how to decompose the problem, we must emphasize that the edge-based formulation requires a bit of care to make sure transit loops (
i.e.,
loops over vertices other than the source or destination) do not happen.
A feasible solution can be easily checked for lacking loops by looking at the sub-graph induced by the support of
X_{k}
(
i.e.,
all edges with positive flow assignments) and verifying that it is acyclic.

Figure A.1.
An optimal edge-based MLU solution need not be free of loops if the cost depends only on the MLU. The notation
x/c
means one routes
x
flow units over a link with capacity
c
.

However, as-is nothing stops an edge-based solution from creating transit loops.
This is especially the case for MLU, where the cost is determined only by the most congested path, and assignments over non-congested links can easily contain loops.

Fig.

A.1
shows a very simple example of this.

This is where our edge-commodity cost functions,
f_{e}
and
f_{ek}
, come to help us.

Theorem 1.

If
f_{e}
and
f_{ek}
are convex, strictly increasing functions on
\mathbb{R}^{+}
, then the optimal edge-based solution
X^{*}
cannot contain a loop.

Proof.

This can be shown by contradiction. Since
X^{*}
is feasible, then all of its entries are non-negative and do not create a loop that crosses the source or destination nodes.
As such, we need only focus on transit loops.
Assume one such loop exists for some commodity
k
, thus it must be possible for one to create a cyclic graph using edges from the support of
X_{k}^{*}
.
Let
\mathcal{C}
denote the set of edges on this cycle.

Now, let
\nu
be the smallest flow assignment for
k
over the cycle
\mathcal{C}
.
Since
\mathcal{C}
is a subset of the support of
X_{k}^{*}
, then
\nu>0
.
The idea is to subtract
\nu
from all assignments over this cycle.
Thus we can define:

\displaystyle\tilde{X}_{k}=\begin{cases}X_{ek}^{*}-\nu&e\in\mathcal{C}\\
X_{ek}^{*}&\text{O.W.}\\
\end{cases}

It is easy to see that
\tilde{X}_{k}
is still a feasible assignment.
The demand loop and leak constraints remain satisfied, as
\tilde{X}_{k}
agrees with
X_{k}^{*}
on the associated edges.

Since all edges in
\mathcal{C}
must carry at least
\nu
units of flow, then the entries of
\tilde{X}_{k}
are still non-negative.
Since we have also only decreased the total routed flow, the capacity constraint cannot be violated as the total flow on each edge is no larger than before.

Finally, flow conservation remains satisfied. We need only look at the expanded constraint in
Eq.

2
for any vertex that is part of the cycle
\mathcal{C}
, and note that both sums have been decremented by
\nu
and thus the equality still holds.

The new solution
\tilde{X}_{k}
also must contain at least one edge from
\mathcal{C}
with a zero assignment (which previously routed exactly
\nu
units), thus
\tilde{X}_{k}
breaks the cycle be removing one of the edges.
We can now repeat this for all
k
and get a full feasible solution
\tilde{X}
, which given the assumptions on
f_{e}
and
f_{ek}

must
have a smaller objective.
Thus
X^{*}
could not have been the optimal solution which is a contradiction.

Therefore, no such loop like
\mathcal{C}
can exist in the optimal solution for us to take as witness.
∎

The proof above remains sound if one were to remove the functions
f_{e}
.
The proof however breaks if one were to remove the functions
f_{ek}
as well.
For this reason, these functions are not just for regularization, but are necessary in preventing loops in the final edge-based solution.

B.2.
The ADMM Decomposition

One source of difficulty across both edge-based and path-based formulations of all objectives is the capacity constraint.
This constraint couples every individual assignment across commodities, and as such, if we could push it away into somewhere else, things will become much easier.
ADMM is a reasonable choice for this (note that related work TEAL has also observed this
(
46
)
).

To do this, introduce
Z_{e}:=\sum_{k}X_{ek}
as the aggregate flow over edge
e
across commodities. We can rewrite the problem as:

minimize

\displaystyle\quad g(U)+\sum_{e}f_{e}\Big(Z_{e}\Big)+\sum_{e}\sum_{k}f_{ek}\Big(X_{ek}\Big)

s.t.

\displaystyle\quad\sum_{k}X_{k}-Z=0

\displaystyle\quad\mathcal{F}_{X}\penalty\ \text{and}\penalty\ \mathcal{F}_{Z}\penalty\ \text{hold}.

Where the constraints over
X
are defined as:

\displaystyle\mathcal{F}_{X}=\begin{cases}&\forall k:MX_{k}=B_{k}\\
&\forall k:0\preccurlyeq X_{k}\\
&\forall k,e\in\text{$E^{\text{in}}_{\mathcal{S}(k)}$}:X_{ek}=0\\
&\forall k,e\in\text{$E^{\text{out}}_{\mathcal{T}(k)}$}:X_{ek}=0\end{cases}

And over
Z
:

\displaystyle\mathcal{F}_{Z}=\begin{cases}&0\leq U\\
&Z\preccurlyeq uC\end{cases}

Note that besides the consensus constraint, the other constraints separate into distinct sets, one of which only depends on
Z
and
u
, and the other on
X
.
In this format, we can write this as an ADMM loop by creating the augmented Lagrangian with the first constraint and distributing the two constraint sets over appropriate updates.
Let
X_{k}^{(m)}
be the value of
X_{k}
during ADMM iteration
m
(the same applies for
Z
and
r
).

To do this, introduce the dual variable
r\in\mathbb{R}^{n}
for that constraint, and we get the following steps:

X-update:

\displaystyle X^{(m+1)}

\displaystyle:=\argmin_{\mathcal{F}_{X}}\;\sum_{e}\sum_{k}f_{ek}(X_{ek})+

\displaystyle\quad\penalty\ \penalty\ \frac{\rho}{2}\Big\|\sum_{k}X_{k}-Z^{(m)}+r^{(m)}\Big\|_{2}^{2}

Z-update:

\displaystyle Z^{(m+1)}

\displaystyle:=\argmin_{\mathcal{F}_{Z}}\;g(U)+\sum_{e}f_{e}(Z_{e})+

\displaystyle\quad\penalty\ \penalty\ \frac{\rho}{2}\Big\|\sum_{k}X_{k}^{(m+1)}-Z+r^{(m)}\Big\|_{2}^{2}

Dual Update:

\displaystyle r^{(m+1)}

\displaystyle:=r^{(m)}+(\sum_{k}X_{k}^{(m+1)}-Z^{(m+1)})

The above is the scaled ADMM form
(
7
)
and
\rho
is a step size that must be carefully chosen.
This constitutes the
Outer Loop
of our algorithm, where assignments are made and the matrix
X
decided upon, then fine-tuning on aggregate flow is done such that the utilization is lowered.

The update on
Z
is simple, as it only has variables in number of edges.
The
X
update however is still a monster due to how many variables it has; we note however that besides the linear constraint, the other constraints are
simple
and can be handled with projection,
and
they also separate over
k
.

We must now scale the problem such that it can be solved quickly.
Assuming
f_{ek}
isn’t an extremely complicated function, the
X
update is mostly defined by its quadratic objective and the non-negativity constraint.
However, if we shuffle the summation on
f_{ek}
, we see an important structure.

minimize

\displaystyle\sum_{k}\Big(\sum_{e}\ f_{ek}(X_{ek})\Big)+\frac{\rho}{2}\Big\|\sum_{k}X_{k}-Z+r^{(m)}\Big\|_{2}^{2}\

s.t. …

From now on, we define
F^{(m)}:=Z^{(m)}-r^{(m)}
. Define the following as well:

\displaystyle\tilde{f}_{k}(X_{k}):=\sum_{e}f_{ek}(X_{ek})\quad\text{and}\quad\tilde{g}(X_{k}):=\frac{\rho}{2}\Big\|X_{k}-F^{(m)}\Big\|_{2}^{2}

The problem is then:

minimize

\displaystyle\quad\sum_{k}\tilde{f}_{k}(X_{k})+\tilde{g}(\sum_{k}X_{k})

s.t. …

A creature of this structure is more commonly known as a
Sharing
problem
(
7
)
.
Typically, such problems are unconstrained, but here the existence of the non-negativity constraint is not too bad, since it too separates over commodities.
We are quite fortunate, since ADMM just happens to lend itself very well to solving a problem like this. If we introduce the pairing
P_{k}
for
X_{k}
such that
P_{k}-X_{k}=0
, (scaled) ADMM gives the following update steps:

\displaystyle X_{k}^{(m+1)}

\displaystyle\coloneq\argmin_{\mathcal{F}_{X}}\sum_{e}f_{ek}(X_{ek})+

\displaystyle\quad\penalty\ \penalty\ \penalty\ \frac{\eta}{2}\Big\|X_{k}-X_{k}^{(m)}+\bar{X}^{(m)}-\bar{P}^{(m)}+u^{(m)}\Big\|_{2}^{2}

\displaystyle\bar{P}^{(m+1)}

\displaystyle\coloneq\argmin_{\bar{P}}\frac{\rho}{2}\Big\|K\bar{P}-F^{(m)}\Big\|_{2}^{2}+

\displaystyle\quad\penalty\ \penalty\ \penalty\ \frac{K^{2}\eta}{2}\Big|\Big|\bar{P}-u^{(m)}-\bar{X}^{(m+1)}\Big|\Big|_{2}^{2}

\displaystyle u^{(m+1)}

\displaystyle\coloneq u^{(m)}+\bar{X}^{(m+1)}-\bar{P}^{(m+1)}

Where
\eta
is the step size of this second ADMM loop,
\bar{P}
and
\bar{X}
are column-wise averages of their respective variables and
u
is a dual variable.

The mean update has a closed form solution:

\displaystyle\bar{P}^{(m+1)}\coloneq\frac{\frac{F^{(m)}}{K}+\frac{\eta}{\rho}(u^{(m)}+\bar{Y}^{(m+1)})}{1+\frac{\eta}{\rho}}

Thus, we end up with:

\displaystyle X_{k}^{(m+1)}

\displaystyle\coloneq\argmin_{\mathcal{F}_{X}}\sum_{e}f_{ek}(X_{ek})+

\displaystyle\quad\penalty\ \penalty\ \penalty\ \frac{\eta}{2}\Big\|X_{k}-X_{k}^{(m)}+\bar{X}^{(m)}-\bar{P}^{(m)}+u^{(m)}\Big\|_{2}^{2}

\displaystyle\bar{P}^{(m+1)}

\displaystyle\coloneq\frac{\frac{F^{(m)}}{K}+\frac{\eta}{\rho}(u^{(m)}+\bar{Y}^{(m+1)})}{1+\frac{\eta}{\rho}}

\displaystyle u^{(m+1)}

\displaystyle\coloneq u^{(m)}+\bar{X}^{(m+1)}-\bar{P}^{(m+1)}

Take note that we only need to keep
\bar{P}^{(m)}
, not the individual
P_{k}
.
The above constitutes as our
Inner ADMM Loop
, together with our Outer Loop, they form an intertwined procedure that nudges our assignment matrix closer to examples with less and less maximum utilization.
The outer loop provides an algorithmic benefit by decoupling aggregate flow from individual assignments, and the inner loop provides scalability by decoupling across commodities.

B.3.
A Useful Trick

The previous decomposition (the outer and inner loop) are core to our suite of solvers, regardless of objective.
There is another trick that we also employ many times for edge-based solvers, and that concerns the linear constraint within
\mathcal{F}_{X}
.
Recall that the update to
X_{k}
finally takes the form of:

minimize

\displaystyle\quad\sum_{e}f_{ek}(X_{ek})+

\displaystyle\quad\penalty\ \penalty\ \penalty\ \frac{\eta}{2}\Big\|X_{k}-X_{k}^{(m)}+\bar{X}^{(m)}-\bar{P}^{(m)}+u^{(m)}\Big\|_{2}^{2}

s.t.

\displaystyle\quad MX_{k}=B_{k}

\displaystyle\quad 0\preccurlyeq X_{k}

\displaystyle\quad\forall e\in\text{$E^{\text{in}}_{\mathcal{S}(k)}$}:X_{ek}=0

\displaystyle\quad\forall e\in\text{$E^{\text{out}}_{\mathcal{T}(k)}$}:X_{ek}=0

We can make the linear constraint implicit!
In particular, assume that some feasible solution to the linear constraint like
X_{k}^{(0)}
is known:

(3)

\displaystyle\forall k:MX_{k}^{(0)}=B_{k}

Let
\mathcal{N}\in\mathbb{R}^{n\times T}
be a matrix whose columns form a basis for the null space of
M
and
T
is the null space dimension of
M
.
Such a matrix can be easily found with SVD (with the added bonus that we can have
\mathcal{N}^{T}\mathcal{N}=I
, which we also assume).
Then every solution to the linear constraint would be of the form:

\displaystyle X_{ek}=X_{ek}^{(0)}+\sum_{t}\mathcal{N}_{et}Y_{tk}

We can substitute this into the
X
update and get the following:

minimize

\displaystyle\quad\sum_{e}f_{ek}(X_{ek}^{(0)}+\mathcal{N}Y_{k})+

\displaystyle\quad\penalty\ \penalty\ \penalty\ \frac{\eta}{2}\Big\|X_{k}^{(0)}+\mathcal{N}Y_{k}-X_{k}^{(m)}+\bar{X}^{(m)}-\bar{P}^{(m)}+u^{(m)}\Big\|_{2}^{2}

\displaystyle\quad 0\preccurlyeq X_{k}^{(0)}+\mathcal{N}Y_{k}

etc.

This problem is small and manageable, any algorithm like Projected Gradient Descent (PGD) or Coordinate Descent can be used to solve it.
OnlineTE by default uses PGD.

As a final note, the choice of the initial feasible solution
X_{k}^{(0)}
can be helpful.
We consider mostly two choices:

•

Uniform routing on shortest paths
. This is the simplest, and generates sparse assignments that we can keep in small memory and do quick arithmetic on (in particular, the products
\mathcal{N}^{T}X_{k}^{(0)}
do appear in many formulations, which itself is actually quite dense no matter the sparsity pattern of
X_{k}^{(0)}
).

•

Least squares solution
. In particular, let
X_{k}^{(0)}\coloneq M^{\dagger}B_{k}
, where
M^{\dagger}
is the Moore-Penrose pseudo-inverse of
M
. The result will be a dense matrix often, but it brings with itself many computational boons, the main one being that
\mathcal{N}^{T}X_{k}^{(0)}=0
holds.

In what follows, we assume that the least squares solution is always used.

B.4.
\ell_{2}
Regularized Form

We can let the functions
f_{ek}
be small quadratic functions.
As long as their values remain comparatively small and obey the assumptions in
Theorem

1
, their exact structure won’t matter.

One simple case is to consider functions
f_{ek}(x)=\frac{\epsilon}{2}(x)^{2}
for a small
\epsilon\geq 0
.
By expanding these
f_{ek}
we can see that the update to
Y_{k}^{(m+1)}
turns to
7
7

7

If we didn’t use the least-squares feasible assignment, then the expansion also generates a linear term in
Y_{k}
. This does not change the structure of the final problem and the same methods can be applied to it.
:

minimize

\displaystyle\quad\frac{\epsilon}{2}\Big|\Big|Y_{k}\Big|\Big|_{2}^{2}+\frac{\eta}{2}\Big|\Big|Y_{k}-Y_{k}^{(m)}+\bar{Y}^{(m)}-\bar{P}^{(m)}+u^{(m)}\Big|\Big|_{2}^{2}

s.t.

\displaystyle\quad\forall k:0\preccurlyeq X_{k}^{(0)}+\mathcal{N}Y_{k}

\displaystyle\quad\forall k,e\in\mathcal{S}(k)\cup\mathcal{T}(k)\penalty\ :0=X_{k}^{(0)}+\mathcal{N}Y_{k}

Or in a slightly more standard form:

minimize

\displaystyle\quad\frac{1}{2}\Big|\Big|Y_{k}\Big|\Big|_{2}^{2}-\frac{\eta}{\eta+\epsilon}Y_{k}^{T}(Y_{k}^{(m)}-\bar{Y}^{(m)}+\bar{P}^{(m)}-u^{(m)})

s.t.

\displaystyle\quad\forall k:0\preccurlyeq X_{k}^{(0)}+\mathcal{N}Y_{k}

\displaystyle\quad\forall k,e\in\mathcal{S}(k)\cup\mathcal{T}(k)\penalty\ :0=X_{k}^{(0)}+\mathcal{N}Y_{k}

Among the easier ways to solve this problem, PGD seems suitable, but the projection that has to be done to make the solution feasible can get quite expensive.

We can make the projections trivial by solving the dual instead.
If we introduce the dual variable
\lambda_{k}\in\mathbb{R}^{n}
and exchange the objective sign to get another minimization problem, we end up with:

minimize

\displaystyle\quad\frac{1}{2}\Big|\Big|\mathcal{N}^{T}\lambda_{k}+C_{k}^{(m)}\Big|\Big|_{2}^{2}+\lambda_{k}^{T}X_{k}^{(0)}

s.t.

\displaystyle\quad\forall k,e\notin\mathcal{S}(k)\cup\mathcal{T}(k)\penalty\ :0\leq\lambda_{ek}

Where for compactness, we let
C_{k}^{(m)}:=\frac{\eta}{\eta+\epsilon}(Y_{k}^{(m)}-\bar{Y}^{(m)}+\bar{P}^{(m)}-u^{(m)})
.
The KKT conditions give the following relation to retrieve the primal solution from the dual:

\displaystyle Y_{k}^{*}=\mathcal{N}^{T}\lambda_{k}^{*}+C_{k}^{(m)}

PGD is very well suited to solve this problem, especially because the projections needed are trivial.
When sparsity isn’t needed and we want to retrieve the
true
edge-based optimal, this is the method that we employ.

B.5.
\ell_{1}
Regularized Form

The constraints
MX_{k}=B_{k}
and the non-negativity constraints, gives a very under-determined system, and we are interested in the most sparse solutions.
This can be achieved by penalizing the problem with an
\ell_{1}
norm cost.
The lowest hanging fruit here would be to let:

f_{ek}(x)=\epsilon\;|x|

It is easy to verify that the sharing problem has not changed, the update to
\bar{P}
and the dual update remain the same as with the

norm, but the updates to
Y

minimize

\displaystyle\epsilon\;\Big\|X_{k}\Big\|_{1}+\frac{\eta}{2}\Big\|Y_{k}-Y_{k}^{(m)}+\bar{Y}^{(m)}-\bar{P}^{(m)}+u^{(m)}\Big\|_{2}^{2}

\displaystyle\text{s.t.}\quad...

Which is a constrained LASSO.
It is not the easiest thing to solve in general, but our saving grace is that the switch problems are usually quite small.
There are multiple ways to solve these (coordinate decent is often used, and we also use it as well), but ADMM can also be used again

Which solidifies the hunch that the writer is a one-trick pony.

\displaystyle X_{k}^{(m,i+1)}

\displaystyle:=\argmin_{0\preccurlyeq X_{k},etc.}\frac{\epsilon}{\eta}\Big\|X_{k}\Big\|_{1}+

\displaystyle\quad\penalty\ \penalty\ \penalty\ \frac{\gamma}{2}\Big\|X_{k}-X_{k}^{(0)}-\mathcal{N}Y_{k}^{(m,i)}+t_{k}^{(i)}\Big\|_{2}^{2}

\displaystyle Y_{k}^{(m,i+1)}

\displaystyle:=\argmin\frac{1}{2}\Big\|Y_{k}-C_{k}^{(m)}\Big\|_{2}^{2}+

\displaystyle\quad\penalty\ \penalty\ \penalty\ \frac{\gamma}{2}\Big\|X_{k}^{(m,i+1)}-X_{k}^{(0)}-\mathcal{N}Y_{k}^{(m,i)}+t_{k}^{(i)}\Big\|_{2}^{2}

\displaystyle:=t_{k}^{(m,i)}+(X_{k}^{(m,i+1)}-X_{k}^{(0)}-\mathcal{N}Y_{k}^{(m,i+1)})

The second step has the same solution as we discussed in the

The first problem however has a non-smooth objective. If we write it in an unconstrained form using the identifier function for the positive orthant, we get:

\displaystyle X_{k}^{(m,i+1)}

\displaystyle:=\argmin\frac{\epsilon}{\eta\gamma}\Big\|X_{k}\Big\|_{1}+\mathcal{I}_{+}(X_{k})+

\displaystyle\quad\penalty\ \penalty\ \penalty\ \frac{1}{2}\Big\|X_{k}-X_{k}^{(0)}-\mathcal{N}Y_{k}^{(m,i)}+t_{k}^{(i)}\Big\|_{2}^{2}

This is exactly the Proximal Operator of the function
\frac{\epsilon}{\eta\gamma}\|x\|_{1}+\mathcal{I}_{+}(x)
. Both of these functions are applied element-wise and are summative, thus the proximal composition rule applies to them. This gives the following:

\displaystyle X_{k}^{(m,i+1)}

\displaystyle:=\text{Prox}_{+}(\text{Prox}_{\epsilon/\eta\gamma||.||_{1}}(X_{k}^{(0)}+\mathcal{N}Y_{k}^{(m,i)}+t_{k}^{(i)}))

The proximal operator of

, and the proximal operator of the non-negative orthant is just clipping the negative values to zero.
Thus, the final solution involves the following:

\displaystyle X_{k}^{(m,i+1)}

\displaystyle:=\Big[\mathcal{S}_{\epsilon/\eta\gamma}(X_{k}^{(0)}+\mathcal{N}Y_{k}^{(m,i)}+t_{k}^{(m,i)})\Big]_{+}

\displaystyle Y_{k}^{(m,i+1)}

\displaystyle:=\frac{C_{k}^{(m)}-\gamma\;\mathcal{N}^{T}(X_{k}^{(0)}+t_{k}^{(i)}-X_{k}^{(m,i+1)})}{1+\gamma}

And

We want to emphasize that the above is slightly abusing notation.
In practice, we don’t just clip the entries of

Finally, note that while we let

This is because adding a simple

Notation for our path-based formulation.

We first define how commodities can make use of available paths:

Definition 1.

The path dictionary
\mathcal{I}:\{1,..,K\}\times\{1,..,T\}\to\mathbb{P}
is the mapping that given a commodity and path index, outputs the associated path in
\mathbb{P}
.
In the case where less than
T

\emptyset

To handle capacity constraints, we also need to define which path crosses which edge:

Definition 1.

The mapping
\mathcal{P}:E\times\{1,..,K\}\to\textbf{PS}(\{1,..,T\})
gives all path indices crossing an edge
e
and (potentially) serving a commodity
k
(note that there is at most
T
such paths, thus the indexing
\mathcal{I}
can be used to convert to the actual path).

Instead of a pure path-based formulation, we opt to use a formulation that has an edge-based
flare
to it.
In particular, note that given a path-based assignment, it is trivial to recover an edge-based assignment.
To formalize this, we define the path mask matrix:

Definition 1.

For each commodity
k
define
\alpha^{(k)}\in\{0,1\}^{n\times T}
such that for each column
\alpha_{t}^{(k)}
we have:

\displaystyle\forall e\in E:\alpha_{et}^{(k)}=\begin{cases}1&t\in\mathcal{P}(k,e)\\
0&\text{O.W.}\end{cases}

It is easy to see that an edge-based assignment
X
can be created from a path-based assignment
Y
with:

\displaystyle\forall k:X_{k}=\alpha^{(k)}Y_{k}d_{k}

By adding this constraint into any edge-based problem, a path-based equivalent is created.
There is one small change compared to the previous edge-based solver, where we may elect to introduce functions
f_{tk}
indexed per-path, per-commodity instead of per-edge, per-commodity.
If we desire strong convexity, these functions are enough for that purpose, since a path-based assignment uniquely defines an edge-based assignment.
In such a setting, being loop-free follows from the paths in
\mathcal{P}
being loop-free and have no relation to what choice of
f_{tk}
or
f_{e}
we make.

It may appear vexing that we would combine edge-based and path-based problems like this, but it has two main advantages:

•

It simplifies the capacity constraint greatly, allowing us to recover our outer and inner ADMM loops with hardly any difference compared to the edge-based case.
From an implementation point of view, we may use any existing code that implements our edge-based backend for our path-based solvers.

•

It pushes any consideration about paths and their availability, into the switches alone, sparing the controller from having to contend with it.

As such, a path-based solver is a very intuitive restriction of our edge-based solver.
Essentially, it is the exact same solver, but for each iteration, the switches project their edge-based solution onto the available paths.
For this reason, the path-based algorithm has the exact same message complexity as the edge-based solver.
The main benefit comes from the computation complexity, as the
Y_{tk}
matrix is much smaller than the
X_{ek}
matrix that we had to use previously and we also have no possibility of a loop (unless a configured path has a loop, which we assume never happens).

C.1.
Path-Based PGD Solution

For the path-based solver, only the switch problem changes.
It is very easy to show that the problem would become:

minimize

\displaystyle\quad\sum_{t}f_{tk}\Big(d_{k}Y_{tk}\Big)+

\displaystyle\quad\frac{\eta}{2}\Big\|\alpha^{(k)}Y_{k}d_{k}-X_{k}^{(m)}+\bar{X}^{(m)}-\bar{P}^{(m)}+u^{(m)}\Big\|_{2}^{2}

s.t.

\displaystyle\quad\sum_{t}Y_{tk}=1

\displaystyle\quad\forall t>p_{k}:Y_{tk}=0

\displaystyle\quad 0\preccurlyeq Y_{k}

Let
A^{(k)}:=\Big((\alpha^{(k)})^{T}\alpha^{(k)}\Big)
be the
T\times T
Gram matrix of the path mask.
How easy we can solve this problem, depends completely on what
f_{tk}
is and what paths we use.
If
f_{tk}
is smooth, then the gradient is:

\displaystyle\nabla_{k}=

\displaystyle d_{k}f^{\prime}\Big(d_{k}Y_{tk}\Big)+\eta d_{k}^{2}A^{(k)}Y_{k}-

\displaystyle\eta d_{k}(\alpha^{(k)})^{T}\Big(X_{k}^{(m)}-\bar{X}^{(m)}+\bar{P}^{(m)}-u^{(m)}\Big)

And we can proceed as before.
The projection step is projection onto a
reduced
probability simplex, where some of the entries are pinned to zero beforehand.
This is mathematically equivalent to just projecting onto the Simplex in terms of the algorithm, but there are some small practical considerations that we won’t discuss here.

However, we will take time to emphasize a certain case where the solution becomes much simpler.
That is the case of
edge-disjointed
paths, meaning that for each commodity, none of the at most
T
paths share any edges.

Equivalently, this means that the Gram matrix
A^{(k)}
is actually
diagonal
.
With this, all previous formulations simplify greatly, however, it is understandable that we may be hesitant to limit ourselves to such a path selection.
An almost equally efficient way of handling the general case is possible by taking advantage of two things about
\alpha^{(k)}
, its
sparsity
and being Boolean valued.

Essentially, in order to implement the multiplications with
\alpha^{(k)}
, we need only know the positions where we know
\alpha
is not zero, and then we can just accumulate the sums over these indices.
In the particular case of Python, this can be done very efficiently using JIT compilation (our implementation currently uses
Numba
).

We finally close by making a critical remark about the PGD step size,
\gamma_{k}
. Unlike the edge-based solver, PGD step size must be adjusted per commodity.
This is because the matrix
A^{(k)}
has very different dominant eigenvalues for each commodity (the largest eigenvalue is loosely dependent on the length of the longest path).
This consideration wasn’t needed in the edge-based case, since the matrices we work with in that case have already been normalized.

If
\Lambda_{k}
is the largest eigenvalue of
A^{(k)}
, one good choice is to let
\gamma_{k}\coloneqq\frac{1}{\Lambda_{k}}
. To calculate
\Lambda_{k}
for large topologies, we use a few power method iterations (10 or 20 are enough for KDL).

Appendix D
Adding Hierarchy

Consider the following setting:

•

The network is partitioned into
\mathcal{D}
domains. A variable is indexed for domain
d
using brackets. For example,
X[d]
denotes the matrix
X
for domain
d
.

•

The notation
X[!d]
denotes sum over all partitions except
d
(i.e.
X[!d]\triangleq\sum_{d^{\prime}}X[d^{\prime}]-X[d]
.)

•

Each domain will have one controller, which can freely and efficiently communicate with its set of switches.

•

Each domain can
only
manipulate its set of assignment variables,
X[d]
, and may only rely on estimates or aggregate values received from other domains.

We already have full decomposition over the demand/flow-conservation/non-negativity constraints.
The only thing that we must handle, is the capacity constraint and utilization objective.

One way to handle this is as follows.
Define:

•

The domain aggregate flow as
Z[d]:=\sum_{k}X[d]_{k}
.

•

The pairing
R[d]=Z[d]
(this allows us to pass information about other domain aggregates within loops).

•

The domain MLU,
u[d]
and its consensus variable
U
.

The original MLU problem can be rewritten as:

minimize

\displaystyle\quad\frac{1}{\mathcal{D}}\sum_{d}g(U[d])+\sum_{e}f_{e}(\sum_{d}R[d])+

\displaystyle\quad\sum_{d}\sum_{e}\sum_{k}f[d]_{ek}(X[d]_{ek})

s.t.

\displaystyle\quad R[!d]+Z[d]\preccurlyeq u[d]C

\displaystyle\forall d

\displaystyle\quad MX[d]_{k}=B[d]_{k}

\displaystyle\forall d,k

\displaystyle\quad 0\preccurlyeq X[d]_{k}

\displaystyle\forall d,k

\displaystyle\quad 0\leq U[d]

\displaystyle\forall d

\displaystyle\quad\sum_{k}X[d]_{k}-Z[d]=0

\displaystyle\forall d

\displaystyle\quad Z[d]-R[d]=0

\displaystyle\forall d

\displaystyle\quad U[d]-O=0

\displaystyle\forall d

The most important part of this rewrite is in the capacity constraint.
Exchanging
Z[d]
with
R[d]
for any domain except the
current
one means that we can pass estimates of other domain aggregates without having to optimize them.
The price that we pay for this however, is that the capacity constraint now exists over every domain
and
across anything that solves for
R[d]
or
Z[d]
.

We can attack the last two constraints with ADMM.
Introduce the dual variables
l[d]
and
v[d]
in turn for these two constraints.

We first optimize over
X[d]
,
Z[d]
and
U[d]
by doing:

minimize

\displaystyle\quad\frac{1}{\mathcal{D}}\sum_{d}g(U[d])+\sum_{d}\sum_{e}\sum_{k}f[d]_{ek}

\displaystyle\Big(X[d]_{ek}\Big)

\displaystyle\quad\sum_{d}\frac{\beta}{2}\Big(U[d]-O^{(m)}+v[d]^{(m)}\Big)^{2}+

\displaystyle\quad\sum_{d}\frac{\beta}{2}\Big\|Z[d]-R[d]^{(m)}+l[d]^{(m)}\Big\|_{2}^{2}

s.t.

\displaystyle\quad R[!d]^{(m)}+Z[d]\preccurlyeq U[d]C

\displaystyle\forall d

\displaystyle\quad MX[d]_{k}=B[d]_{k}

\displaystyle\forall d,k

\displaystyle\quad\sum_{k}X[d]_{k}-Z[d]=0

\displaystyle\forall d

\displaystyle\quad 0\leq U[d]

\displaystyle\forall d

\displaystyle\quad 0\preccurlyeq X[d]_{k}

\displaystyle\forall d,k

Crucially, this problem completely separates over domains (everything is indexed with
d
, including objective and constraints).
This gives us the
Domain Optimization
problem (we can do away with domain indices to see the problem better).

minimize

\displaystyle\quad\frac{1}{\mathcal{D}}g(U)+\sum_{e}\sum_{k}f_{ek}(X_{ek})

\displaystyle\quad+\frac{\beta}{2}\Big(U-O^{(m)}+v^{(m)}\Big)^{2}

\displaystyle\quad+\frac{\beta}{2}\Big\|Z-R^{(m)}+l^{(m)}\Big\|_{2}^{2}

s.t.

\displaystyle\quad R[!]^{(m)}+Z\preccurlyeq UC

\displaystyle\quad MX_{k}=B_{k}

\displaystyle\forall k

\displaystyle\quad 0\preccurlyeq X_{k}

\displaystyle\forall k

\displaystyle\quad 0\leq U

\displaystyle\quad\sum_{k}X_{k}-Z=0

This is pretty much the synchronous problem that we aimed to solve previously,
except here, we can get away with optimizing only copies of our own assignment, leaving only some headroom for other domains.
This problem we know very well how to solve efficiently.

The new part now, is the
Domain Consensus
problem over
R[d]
and
O
, which takes the form:

minimize

\displaystyle\quad\sum_{e}f_{e}\Big(\sum_{d}R[d]\Big)+

\displaystyle\quad\sum_{d}\frac{\beta}{2}\Big(U[d]^{(m+1)}-O+v[d]^{(m)}\Big)^{2}+

\displaystyle\quad\sum_{d}\frac{\beta}{2}\Big\|Z[d]^{(m+1)}-R[d]+l[d]^{(m)}\Big\|_{2}^{2}

s.t.

\displaystyle\quad R[!d]+Z[d]^{(m+1)}\preccurlyeq U[d]^{(m+1)}C

\displaystyle\forall d

The problem is unconstrained over
O
, admitting a simple closed form solution of:

\displaystyle O^{(m+1)}\leftarrow\overline{U[d]}^{(m+1)}+\overline{v[d]}^{(m)}

And simplifying the remaining problem to:

minimize

\displaystyle\quad\sum_{e}f_{e}\Big(\sum_{d}R[d]\Big)+

\displaystyle\quad\sum_{d}\frac{\beta}{2}\Big\|Z[d]^{(m+1)}-R[d]+l[d]^{(m)}\Big\|_{2}^{2}

s.t.

\displaystyle\quad R[!d]\preccurlyeq U[d]^{(m+1)}C-Z[d]^{(m+1)}\quad\forall d

This problem isn’t too big, thus we can afford to add one new constraint to make it a bit more pleasant to look at.
Define
F:=\sum_{d}R[d]
to be the total reserved flow, then:

minimize

\displaystyle\quad\sum_{e}f_{e}(F)+\sum_{d}\frac{\beta}{2}\Big\|Z[d]^{(m+1)}-R[d]+l[d]^{(m)}\Big\|_{2}^{2}

s.t.

\displaystyle\quad F-R[d]\preccurlyeq U[d]^{(m+1)}C-Z[d]^{(m+1)}\quad\forall d

\displaystyle\quad F-\sum_{d}R[d]=0

This is then finally finished with a dual update:

\displaystyle v[d]^{(m+1)}

\displaystyle=v[d]^{(m)}+\Big(u[d]^{(m+1)}-U^{(m+1)}\Big)

\displaystyle l[d]^{(m+1)}

\displaystyle=l[d]^{(m)}+\Big(Z[d]^{(m+1)}-R[d]^{(m+1)}\Big)

We now take a moment to recognize that this solution meets our requirements:

•

Assignments decompose over domains, and only demands specific to that domain are required.

•

Each domain can optimize for utilization based on its own demands. Since this part never leaves that domain, we can reconvene in the domain controller as much as we like.

•

The more the domains optimize, the better! The Domain Consensus problem benefits from it.

To some degree, this method is close in spirit to
(
1
)
, with the crucial difference that we do not heuristically break the capacity constraint into
\mathcal{D}
inequalities for each domain and instead cut the link capacities with the same factor.
