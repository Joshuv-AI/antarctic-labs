CCMnet : A Software Package for Network Generation with Congruence Class Models
Ravi Goyal, Victor De Gruttola, Natasha K. Martin, Lior Rennert, Jukka-Pekka Onnela

Abstract
We introduce CCMnet , an R package designed to generate network ensembles that accurately reflect the uncertainty inherent in empirical data. While traditional network modeling often results in ensembles with fixed property values or model-determined levels of variability, CCMnet enables a continuous spectrum of variability for network properties, including edge counts, degree distribution, and mixing patterns. By defining probability distributions directly over congruence classes of networks, the package allows researchers to specify the uncertainty in network properties across the generated ensemble to match a specific sampling design or empirical distribution. Furthermore, this formulation provides a principled framework that encompasses several classic models (e.g., Erdős–Rényi model, stochastic block models, and certain exponential random graph models) that implicitly share this structural basis, while offering the flexibility to specify arbitrary, even non-parametric, distributions for network properties. CCMnet implements a Markov chain Monte Carlo (MCMC) framework to sample from these models. The utility of the package is illustrated by generating posterior predictive network ensembles representing school friendship networks.

1
Introduction

Often research questions in network analysis require the ability to generate realistic network ensembles rather than a single representative graph
(
24
;
17
;
37
)
. Ideally, the network ensemble should appropriately reflect the estimated uncertainty in the network structure
(
35
)
; this uncertainty can arise from the nature of the sampling of the population of interest
(
21
)
or from stochasticity in the generation process
(
33
)
. In this paper, we present the
CCMnet
package that enables generating networks with investigator specified uncertainty in network properties within the Congruence Class Model framework.

The level of uncertainty associated with a particular network property derived from a network ensemble can be view as a spectrum, from zero to a high degree of uncertainty. For many probabilistic models, the uncertainty they generate for a given network property occupies a specific point along this spectrum. At one end of this spectrum, a hard constraint specifies that the distribution of a network property from repeated realizations is a point mass, that is, it has zero variability
(
2
)
. In network models with variability in the structure, that variability is often fixed by model-imposed constraints; therefore, these models still reside at a single point on this spectrum. For example, exponential-family random graph models (ERGMs) define probability distributions on graphs by maximizing entropy
(
25
)
, which results in a fixed and model-imposed level of uncertainty determined by sufficient statistics
(
31
)
. This is analogous to a Poisson distribution where, although individual realizations vary, the variability across an ensemble of realizations is linked to the mean; once the mean is specified, the variance of the ensemble is fixed. In many empirical contexts, such as an epidemiologist modeling disease transmission within a school, a fixed variability may be inadequate if the model must reflect the specific margin of error or uncertainty inherent in the underlying survey data.

Figure
1
(Panel A) provides an illustration of this limitation by displaying the distributions of a network property under different modeling regimes. When the model imposes a hard constraint on the property, the distribution is a point mass (dark blue distribution); that is, the values for all the network realizations are the same. In the models where a soft-constraint is imposed, the values of the property will vary across networks within the ensemble, but typically the model imposes a fixed level of uncertainty on the distribution (green distribution). Although these models provide valuable tools for network simulation, they do not offer a mechanism for adjusting the degree of uncertainty in network properties to reflect the amount of information available in the empirical data. By allowing for a continuous spectrum of variability, researchers can tune the ensemble to more accurately reflect the structural uncertainty present in real-world observations.

Congruence Class Models (CCMs) were developed to address this shortcoming by providing a framework for generating network ensembles that explicitly propagate uncertainty in network properties estimated from data
(
8
)
. CCMs assign probability distributions to network properties; the concentration of these distributions reflects the amount of available information. When data are sparse or noisy, constraints are loose, yielding high-variance ensembles; as data become more informative, constraints tighten, yielding network ensembles that increasingly resemble a hard constraint. This perspective allows the network simulation to incorporate sampling variability and statistical uncertainty. Furthermore, CCMs provides a common framework for characterizing a number of existing network models as special or limiting cases. Figure

(Panel B) provides a conceptual depiction of how different levels and types of variability can be captured (red curves). Panel C maps the network property distributions in Panels A and B to where they reside on a conceptualized uncertainty spectrum.

2
Constraints on Network Properties

Network generation is a broad area of research, but for the purposes of contextualizing CCMs, it is useful to focus on statistical or probabilistic models, rather than mechanistic network models. Statistical models differ from mechanistic models in that they define probability distributions over networks rather than simulating networks from generative processes or behavioral rules
(
28
)
. Importantly, network properties associated with statistical models can also be classified according to whether their value is exactly the same for all realizations (hard constraints) or vary across realizations (soft constraints).

2.1
Hard-Constraints on Network Properties

A hard constraint specifies that all network realizations will have an identical value for a given property, even if other properties or network structure vary. Two canonical examples are the number of edges in the
G(n,m)
model
(
5
)
and the degree sequence in the configuration model
(
1
;
6
)
. In the
G(n,m)
model, a network of
n
nodes is sampled uniformly from the set of all graphs that contains exactly
m
edges. This ensures the total edge count is identical across all realizations, resulting in a variance of zero for that property. Several software libraries implement this, such as the
sample_gnm
function in the
igraph
package
(
4
)
. Similarly, the configuration model preserves each node’s degree exactly;
igraph
provides the
sample_degseq
function for this purpose
(
4
)
.

2.2
Soft-Constraints on Network Properties

Soft constraints define the distribution of a network property in expectation rather than exactly. The Erdős–Rényi–Gilbert
G(n,p)
random graph model
(
7
)
, wherein each edge is present independently of others with probability
p
, is the simplest example of a model with soft constraint
(
2
)
. The
G(n,p)
model allows for control of the expected number of edges while allowing variability in individual network realizations; specifically, the number of edges follows a binomial distribution, which is in contrast to the
G(n,m)
model where the number is fixed. There are several
R
software libraries available to simulate from the
G(n,p)
model, including,
igraph
(
sample_gnp
)
(
4
)
. Stochastic Block Models (SBMs) extend this idea by specifying probabilities of connection among predefined groups, allowing the number of edges within and between groups to vary probabilistically based on a binomial distribution
(
18
)
; see the
R
packages
sbm
,
blockmodels
, and
igraph
for examples of implementation of this model
(
3
;
23
;
4
)
. Exponential Random Graph Models (ERGMs) generalize further, allowing flexible parametric specification of network statistics such as edge counts, degree distributions, or triadic closure, to be specified in expectation
(
33
)
; the variance of these statistics follows from entropy maximization
(
25
)
. The
statnet
package in
R
is the primary software to fit and simulate from ERGMs
(
20
)
.

2.3
Spectrum of Constraints on Network Properties

The network models reviewed above implicitly partition the space of all possible networks into congruence classes defined by properties such as edge counts, degree sequences, or mixing matrices. Each model induces a probability distribution over these classes, while treating individual networks within the same class as equally likely. Figure
2
provides an illustration of the idea by presenting all undirected binary graphs of size equal to
4
. The networks are colored-coded on the basis of their number of edges; hence, the colors correspond to unique congruence classes defined by edge count. This visualization demonstrates the structural grouping underlying many network models, including the
G(n,m)
model,
G(n,p)
model, and ERGMs with a single term for the number of edges. For example, the
G(n,m)
model would assign probability
0
to classes associated with graphs that have edges not equal to
m
and one to the class with networks with
m
edges, each graph within this class has probability
{n\choose m}^{-1}
. By defining user-specified probability distributions directly on the property-based classes themselves, it is possible to have a spectrum of constraints on a network property.

, partitioned into congruence classes based on edge count. Each cell represents a unique graph, with colors and red boundaries indicating the seven distinct congruence classes (0 to 6 edges).

3
Congruence Class Models

CCMs formalize the perspective of equivalence classes, which is an implicit framework of many existing network models. Rather than beginning with a probability distribution on individual graphs, CCMs start by specifying a probability distribution over congruence classes
(
8
)
. A probability distribution on individual networks is then induced by assigning equal probability to all networks within each class. This inversion makes explicit the probabilistic assumptions that are only implicit in many network models and provides a unifying framework encompassing both hard- and soft-constraint approaches. By specifying distributions at the class level, CCMs can reproduce the behavior of classical network models such as
G(n,p)
, configuration models, SBMs, and ERGMs, while also allowing for more flexible modeling probability distributions. In the following subsection, we formalize the CCM framework.

3.1
Congruence Classes of Networks

Let
\mathscr{G}_{n}
denote the collection of all undirected binary networks with
n
nodes. Let
\phi
denote an algebraic mapping from
\mathscr{G}_{n}
to network summary statistics of interest
x\in\mathbb{R}^{s}
. Let
c_{\phi}(x)=\{g:\phi(g)=x,g\in\mathscr{G}_{n}\}
represent the inverse image corresponding to
\phi
. These inverse images are the congruence classes, which partition the network space
\mathscr{G}_{n}
according to structural features of interest, such as degree sequences, mixing patterns, or subgraph counts. Let
U_{\phi}=\{x\colon g\in\mathscr{G}_{n},\phi(g)=x\}
denote the set of all possible property values, which index the congruence classes.

3.2
Congruence Class Models

A CCM specifies a probability distribution
P_{\phi}(x|\theta)
over congruence classes
U_{\phi}
. As the probability of two graphs within the same class are equal, the probability of observing a particular network is

P_{\mathscr{G}_{n}}(g|\theta)=\left(\frac{1}{|c_{\phi}(\phi(g))|}\right)P_{\phi}(\phi(g)|\theta),

(1)

where
|c_{\phi}(x)|
denotes the cardinality of the congruence class
c_{\phi}(x)
. This construction ensures that networks within the same class are equally likely, while allowing flexible specification of class-level probabilities to capture diverse network-generating mechanisms. The choice of
P_{\phi}(x|\theta)
can be based on empirical data and either be parametric, such as Poisson, binomial, or multinomial distributions, or nonparametric. This flexibility allows researchers to incorporate empirical uncertainty directly into the generation process.

4
CCMnet
Software Architecture

The
CCMnet
package is designed with an architecture that separates model input and output in
R
from intensive computations in
C
. This separation ensures a user-friendly interface while maintaining the performance required for network simulation. Figure
3
provides a schematic overview of this flow.

Figure 3
:
The modular architecture of
CCMnet
. The model is specified via the
R
interface, where input validation occurs. The Markov chain Monte Carlo (MCMC) algorithm is implemented in the
C
backend. Resulting network and MCMC diagnostics are then returned to
R
for analysis.

4.1
Interface and Input Validation

The
R
layer serves as the primary user interface to call the network generation function; syntax for the function is provided in Section
6
. Its main role is to facilitate model specification and ensure input integrity before the Markov chain Monte Carlo (MCMC) algorithm is executed. The interface performs input validation on the chosen network properties and the parameters of the probability distribution, which are both described in Section
5
. Once validated, the model configuration and initial network state are passed to the compiled
C
backend.

4.2
Computational Backend

The core of
CCMnet
is a Metropolis-Hastings MCMC procedure written in
C
.
CCMnet
leverages internal structures and change-statistic logic developed for the
statnet
suite
(
19
)
. In addition, the sampler utilizes the Tie-No-Tie (TnT) toggle algorithm to efficiently propose network updates
(
30
)
. Sampling from a CCM is computationally nontrivial because the acceptance probability depends on the ratio of the cardinalities of the congruence classes; below depicts this ratio for a network property defined by
\phi
and classes with values
x_{a}
and
x_{b}
for that property:

\frac{|c_{\phi}(x_{a})|}{|c_{\phi}(x_{b})|}.

(2)

The backend implements specialized combinatorial algorithms to evaluate these ratios
(
8
)
, which are essentially graph enumeration problems
(
13
)
. By calculating these ratios at each toggle, the sampler maintains detailed balance and ensures convergence to the target distribution defined over the congruence classes.

4.3
Output and Diagnostics

Upon completion of the MCMC chain, the resulting network and a diagnostic matrix of MCMC summary network statistics are returned to
R
and encapsulated in a
"sample_ccm"
object. The network within this object is represented as an igraph object, allowing users to transition from network generation to network analysis using the tools available in the
igraph
package
(
4
)
. Each row of the MCMC sample matrix represents the summary statistics of the selected network property modeled; the number of rows is governed by user specified
sample_size
MCMC parameter. Furthermore, the returned object is designed to work with standard
R
methods for visualization and assessment. Users can generate trace plots and density estimates to monitor sampler convergence and verify that the simulated network properties align with the target distribution; additional details are provided below.

5
Network Properties Implemented

The network properties implemented in
CCMnet
are motivated by the
dk
-series framework, which defines increasingly constrained random graph ensembles
(
26
;
32
)
; additional details of the
dk
-series framework are provide below.
CCMnet
extends this framework in two important ways. First, rather than holding their values fixed, tunable soft constraints are placed on the network properties. These constraints are governed by user-specified probability distributions, allowing for a flexible representation of structural uncertainty. Second,
CCMnet
supports network properties that depend on node-level covariates. This extension is particularly significant for empirical research wherein network structure is often driven by node-level attributes, such as homophily or social stratification
(
29
)
.

5.1
Topological-based Network Properties

The
dk
-series framework defines a systematic hierarchy of random graph ensembles.
CCMnet
implements the
0k
-,
1k
-,
2k
-, and
2.1k
-distributions, which correspond, respectively, to the following network properties: the number of edges, degree distribution, joint degree distribution, and the joint degree distribution together with average clustering
(
26
;
32
)
. Below we provide details of these properties:

•

Edges (0k):
The total number of edges within the graph.

•

Degree distribution (1k):
A vector where the
j^{th}
entry represents the number of nodes having degree
j
.

•

Joint degree distribution (2k):
Represented as a degree mixing matrix, where the
(i,j)
entry represents the number of edges between nodes having degree
i
and degree
j
, capturing degree-degree correlations (degree assortativity).

•

Joint degree distribution and clustering (2.1k):
Includes the joint degree distribution along with the total number of closed triads (triangles) in the network.

5.2
Covariate-based Network Properties

CCMnet
incorporates node-level attributes by defining congruence classes based on categorical or discretized covariates. In this framework, network structure is summarized by the mixing patterns within and between covariate-defined groups. These covariate-based properties can be implemented independently or in combination with topological properties. The following covariate-based summarizes are currently implemented:

•

Attribute mixing matrix:
A matrix where the
(i,j)
entry represents the number of edges between nodes belonging to covariate groups
i
and
j
.

•

Attribute mixing matrix and degree distribution:
A combination property that includes the attribute mixing matrix alongside separate degree distributions calculated for each distinct covariate group.

6
CCMnet Syntax and Workflow

This section outlines the practical workflow for using
CCMnet
. We begin with installation requirements and the computational environment necessary to run the package. We then detail the syntax for model specification of the MCMC sampling procedure (Section
6.2
). Next, we demonstrate the package’s diagnostic and verification capabilities. Finally, we illustrate how the statistics of the networks generated by
CCMnet
are validated against theoretical distributions across various network properties. Section
8
provides an illustrative analysis using
CCMnet
based on networks that represent friendship networks in schools.

6.1
Installation and Requirements

CCMnet
is available on the Comprehensive
R
Archive Network (CRAN); version 1.0.0 or higher should be used. Because the core sampling engine is implemented in
C
, users installing from source must have a
C
compiler installed on their system (e.g.,
Rtools
). The package can be installed and loaded using the following commands:

install.packages(’CCMnet’)

library(’CCMnet’)

6.2
CCM Specification and Syntax

The primary function for sampling networks from a CCM in
CCMnet
is
sample_ccm()
. The function syntax is:

sample_ccm(network_stats, prob_distr, prob_distr_params, population, cov_pattern,

burnin, sample_size, interval, initial_g, use_initial_g, stats_only)

The arguments define the CCM and the sampling parameters as follows:

•

network_stats
: A vector of character strings specifying the network properties that define the congruence classes (e.g.,
"edges"
,
"degreedist"
,
"degmixing"
).

•

prob_distr
: A vector of character strings defining the probability distributions placed on each property in
network_stats
(e.g.,
"poisson"
,
"beta"
,
"normal"
,
"mvn"
).

•

prob_distr_params
: A list containing the parameters for each specified distribution.

•

population
: An integer specifying the number of nodes in the network.

•

cov_pattern
: A vector of node-level covariates, required when
network_stats
includes covariate-based properties.

•

burnin
: An integer specifying the number of initial MCMC iterations to discard to ensure the sampler has reached the target distribution before a network is generated.

•

sample_size
and
interval
: Parameters used primarily for sampler verification; they define the total number of networks to collect and the MCMC thinning interval used to construct the empirical distribution of network properties.

•

initial_g
: An optional
igraph
graph object providing the starting state for the MCMC algorithm.

•

use_initial_g
: A logical value; if
TRUE
, the sampler begins at
initial_g
. If
FALSE
, the sampler generates its own starting graph.

•

stats_only
: A logical value; if
TRUE
, only the MCMC chain of network statistics is returned and final network. If
FALSE
, the function returns a list of networks, where each is an individual
igraph
object (from the
igraph
package).

The function
sample_ccm()
returns an S3 object of class
sample_ccm
. This object is a list containing the generated network(s) as a list (
g
), where each network is represented as an
igraph
object
(
4
)
. The object also contains the matrix of MCMC sampled statistics (
mcmc_stats
) and the model metadata (population size, probability distributions, and covariates). Users can apply standard
igraph
functions, such as
plot()
or
degree()
, to the resulting network(s). Furthermore, to facilitate standard
R
workflows,
CCMnet
provides several methods for interacting with
sample_ccm
objects:

•

print(x, \ldots )
: Displays a concise summary of the model configuration, including the targeted network properties and the number of MCMC samples collected.

•

summary(object, \ldots )
: Provides descriptive statistics (minimum, maximum, mean, and quartiles) for each sampled network property in the MCMC chain.

•

plot(x, stats, type, include_theoretical, \ldots )
: Generates visualizations of the empirical distributions derived from the MCMC samples. The supported plot types include histograms (
‘‘hist’’
), density plots (
‘‘density’’
), and trace plots (
‘‘trace’’
).

6.3
Diagnostics and Verification

Before using a generated network for analysis, it is important to verify that the MCMC sampler has converged and that the resulting empirical distribution matches the theoretical specification.
CCMnet
provides two specialized functions for these purposes:

•

sample_theoretical(ccm_sample, n_sim)
: Facilitates statistical verification by drawing
n_sim
independent samples directly from the theoretical distributions defined in the
sample_ccm
object. These samples are stored within the object and serve as a reference independent of the network MCMC process.

•

plot(ccm_sample, type = "trace")
: The
plot
method generates trace plots for the specified network statistics. This allows the user to visually inspect the mixing behavior of the MCMC chain and determine if the
burnin
parameter is sufficient to achieve stationarity.

Once the theoretical samples are generated, they can be visualized alongside the MCMC output using the
plot()
method:

ccm_sample <- sample_theoretical(ccm_sample, n_sim = 1000)

plot(ccm_sample, stats, type = ‘‘hist’’, include_theoretical = TRUE).

When
include_theoretical = TRUE
, the
plot
method overlays the theoretical samples (or quantiles in trace plots) on the MCMC results. Close agreement between the MCMC-derived densities and the theoretical densities provides a direct diagnostic of sampler correctness. This verification step is a core feature of the
CCMnet
workflow, ensuring that the target distribution on the network properties specified by the user align with the empirical distribution.

6.4
Illustrative Examples

We demonstrate the utility of
CCMnet
through a series of examples using topology-based specifications, ranging from simple edge counts to complex joint degree distributions with clustering. Each example follows a consistent workflow: model specification, MCMC sampling, verification, and generate network ensemble. Verification is performed by comparing the empirical distribution of network properties obtained from the MCMC to the corresponding theoretical target distribution. These examples serve both as a guide for users to construct their own models and to validate the software implementation of the MCMC theory that underpins CCMs across different congruence class definitions. Following these example demonstrations, Section
8
provides an applied analysis using school friendship networks to illustrate the package’s utility in a real-world research context.

6.4.1
Edge Count

We first consider a CCM in which a soft constraint is placed on the total number of edges. In particular, suppose the number of edges follows a Poisson random variable with mean
\lambda=350
. Under this model, the probability of sampling a network with
k
edges is:

P(k\mid\lambda)=\frac{\lambda^{k}e^{-\lambda}}{k!}.

(3)

The CCM assigns this probability to the congruence class consisting of all networks with
k
edges and assigns equal probability to each network within that class. Using the following specification of
sample_ccm
, we sample a network from this model:

ccm_sample <- sample_ccm(

network_stats = c("edges"),

prob_distr = c("poisson"),

7
Sampling Posterior Predictive Networks

This section describes the application of
CCMnet
for the generation of posterior predictive networks. While the previous examples focused on function syntax and verifying the sampler, a primary use case for CCMs is to generate network ensembles that reflect the uncertainty in properties estimated from empirical data. We first define two common sampling regimes and sensible corresponding Bayesian approaches for estimating posterior distributions for network properties. We then describe a comparison framework to evaluate how
CCMnet
performs relative to traditional benchmark models in capturing both population-level heterogeneity and sampling-induced uncertainty. These methodologies are subsequently demonstrated in Section
8
through an analysis of networks representing school friendships.

7.1
Sampling Designs

Network data are typically obtained through sampling, and the choice of sampling design influences the estimation process, including which network properties can be estimated and the appropriate distributional assumptions for the observed data. For our illustration, it is useful to distinguish between two common sampling regimes, as they induce different forms of uncertainty in network property estimation:

Whole-network sampling across populations.
In this first sampling regime, entire networks are observed from multiple distinct populations. Each observed network is considered a realization from a super-population of networks, and uncertainty in network properties arises from heterogeneity across these populations. This sampling regime has been use to investigate brain connectivity across regions among distinct individuals
(
34
)
, within-host HIV viral migration across tissues among distinct individuals
(
10
)
, and friendships between students by classroom or school
(
15
)
.

Individual-level sampling within a single network.
In this second sampling regime, data are collected by sampling individuals (nodes) from a single network. Here, uncertainty arises from the partial observation of the network structure rather than population-level heterogeneity. Common single network sampling designs including ego–centric sampling
(
27
)
and respondent–driven sampling
(
16
)
, both of which have been used to investigate sexual partnerships
(
22
;
21
)

7.2
Network Property Estimation

For both sampling regimes, we investigate the estimation of network density from observed data to define the property distributions required for
CCMnet
. Under the whole-network sampling regime, we use the densities observed across multiple schools to inform a posterior distribution. To account for school-specific deviations and population heterogeneity, we model the school-level densities using a Normal likelihood. Using a Normal conjugate prior, the resulting Normal posterior captures both the mean density and the between-school variability.

For the individual-level sampling regime (partially observed networks), we assume a homogeneous tie-formation propensity. We model the observed edges using a Bernoulli likelihood with a Beta conjugate prior.
CCMnet
then propagates this posterior distribution into a posterior predictive network ensemble, producing networks that reflect the uncertainty inherent in the sampled data.

These approaches demonstrate the flexibility of the CCM framework. While these examples utilize conjugate priors for simplicity, the framework is agnostic to the source of the property distribution; researchers can utilize complex hierarchical, multi-level, or even non-parametric models to specify property distributions that reflect their scientific knowledge or observed data.

7.3
Comparison to Existing Network Models

To assess the utility of
CCMnet
, we compare the resulting posterior predictive distributions to networks generated under two alternative benchmark models: the
G(n,m)
model and an ERGM with a single term for edges. The
G(n,m)
model imposes a fixed constraint on the number of edges, while the ERGM imposes a soft constraint with a fixed level of variability. For both benchmark models, parameters are fixed such that the exact (
G(n,m)
) or expected (ERGM) network density is equal to the mean of the estimated posterior distribution.

These comparisons highlight that while
G(n,m)
and ERGM specifications target a fixed point estimate (e.g., the posterior mean),
CCMnet
allows the generated network ensemble to reflect the level of uncertainty induced by the sampling design.

In the following section, we apply these comparison frameworks to networks representing school friendships to demonstrate how
CCMnet
captures the varying degrees of uncertainty inherent in real-world network data.

Additional Applications

CCMs have been utilized in a variety of settings where network structure is partially observed, uncertain, or evolving. Prior work has applied the framework to network model selection
(
12
)
, the integration of multiple heterogeneous data sources to estimate network properties
(
9
)
, and the prediction of future structure in dynamic settings
(
11
)
. By placing probability distributions directly on network properties,
CCMnet
provides a practical implementation for these tasks, allowing researchers to incorporate information from disparate data sources and propagate uncertainty into predictive network ensembles.

10
Discussion

This paper introduces
CCMnet
, a software framework for specifying, sampling, and assessing CCMs for networks. CCMs provide a principled method for explicitly modeling structural uncertainty. While traditional approaches often result in ensembles with fixed properties or model-determined levels of variability,
CCMnet
allows researchers to define a continuous spectrum of uncertainty—ranging from near-exact constraints to broad empirical distributions. Furthermore, this flexibility provides a transparent framework that unifies and extends several classic network modeling approaches.

A central contribution of
CCMnet
is the translation of this theoretical framework into a practical tool. Implementing CCMs requires evaluating ratios of congruence class sizes to ensure correct MCMC sampling—a task closely connected to graph enumeration problems that are not supported by existing network modeling software.
CCMnet
implements these calculations, allowing researchers to apply CCMs without coding the combinatorial ratios or MCMC proposal algorithm for each new property specification.

While this paper focuses on edge counts, degree distributions, and mixing patterns, the CCM framework is not limited to these properties. In principle, any network summary for which the graph space can be partitioned into congruence classes may be incorporated. However, extending CCMs to additional network properties requires deriving and implementing the corresponding congruence class size ratios, which remains a mathematically challenging task. As a result, further methodological work on graph enumeration and combinatorial approximations will directly expand the scope of the CCM framework.

In summary,
CCMnet
provides a practical implementation of Congruence Class Models. These models effectively address the modeling gap between hard and soft constraints by enabling the generation of posterior predictive network ensembles that incorporate uncertainty in empirical estimates.
