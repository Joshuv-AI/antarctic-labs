Subject: CPT Testing in Cassio with Analytic Results
My work this summer was focused on charged particle transport testing in the Cassio code. Some goals included
modeling test problems with known analytic solutions, and adding tests to the Cassio testing suite for verification
purposes. Additionally, stress-testing the code to identify any bugs/weak points was of interest.
I was successfully able to model a test problem with a known analytic solution, and have submitted a merge request
for the test to be added to the Cassio testing suite. The problem I modeled this summer is an infinite, homogeneous,
fusing deuterium-tritium plasma. The goal was to look at the steady-state velocity distribution of the alpha particles in
such a plasma. The analytic equation assumed the following about the plasma:
 • Te = Ti = 6keV
   •   ρ = 50 g/cm3
   •   50% D, 50% T by number
The velocity distribution of α particles is given by

 Sα
                                                     f (v) =                     H(v0α − v),                                       (1)
                                                               4πναs (v3 + v3c )

where Sα is the birth rate of αs, να is the slowing down frequency, vc represents the slowing down contribution on αs
by ions, and H is the Heaviside step function.
The dE/dx slowing down tables used for this analysis were generated by Erica Fogerty, assuming αs slowing down
on electrons only. These slowing down tables are located at /usr/projects/data/nuclear/ndi/special/
efogerty/2026 02 11/gendir.efogerty.2026.02.11.all on Rocinante. These tables assume a 50:50 DT
mix at 50 g/cm3 and at a temperature of 6 keV. We can modify the above equation by setting vc = 0. Additionally,
since this is an isotropic, infinite medium, we can account for the isotropy (by multiplying by 4πv2 ). We then end up
with the following equation, to which we will compare our Cassio results:

 Sα
                                                           g(v) =         H(v0α − v).                                              (2)
 ναs v

Cassio Settings
The following settings were used in the Cassio input file, in addition to the plasma parameters listed above:
 • Periodic boundary conditions (to model the infinite medium)
 • 1D slab geometry
 • No burn feedback or CPT feedback (to keep the DT population constant, instead of depleting as it burns)
 • Only modeling the reaction D + T → n + α

 • The CPT package only transported α particles
 • A thermalization cutoff of 2kT = 12keV
 • 105 CPT particles per timestep
 • A timestep of 10−13 seconds
 • The stopping power tables used were generated by Erica Fogerty, to account for α particles slowing down

 following variables:
 – cpt dedx dir = "/usr/projects/data/nuclear/ndi/special/efogerty/
            2026 02 11/gendir.efogerty.2026.02.11.all"
 – cpt dedx library = "efogerty"
This simulation was added to the Cassio testing suite. This problem tests the capability of Cassio to use custom stop-
ping power tables, and also tests the functionality of the output files, in addition to verifying the integral functionalities
of settings such as turning off feedback that typically updates particle populations. If this test were ever to fail, it might
be a result of the output files changing how the particle data is written out, something to do with the slowing down
tables (perhaps the location of the files changed, or permissions were changed, or the ability to use custom dE/dx
tables was modified), or perhaps the code handling the boundary conditions was modified. Even though this test is
relatively simple, it is not a true unit test, and instead tests the interfaces between many simple functionalities of the
code, in a simple integral form.
Best Practices for Running this Simulation
For running this specific simulation, there are a few notable practices to make it easier and faster for the user. As
seen in later results, there is no notable difference between 1D and 3D, as this problem is infinite, isotropic, and
homogeneous. As such, using a 1D simulation enables a much faster runtime (for example, a 1D simulation took
roughly 36 seconds of Cassio runtime, whereas the same simulation in 3D took roughly 760 seconds, over 20 times
longer).
While running this simulation, I tried a few different timesteps to see how that would affect the results. The typical
timestep I used for most of the simulations was 10−13 seconds. The alpha slowing-down time on electrons for this
setup is roughly 1/ναs ≈ 6.4 × 10−12 s. As such, I chose a timestep that was small enough to resolve the time evolution
of the velocity distribution of the particles. Something of note is that even if it is not desirable to resolve the time
evolution of the velocity distribution (e.g. if one is only concerned with the steady-state distribution), a small timestep
is still recommended. This is due to the nature of the output file from Cassio - called the ”census” file. The census
file only records the data of particles that are alive and still in flight at the end of the timestep. A large timestep would
thus include particles that are born and die within the timestep, but whose data would not be recorded to the output
file at the end of the timestep - effectively losing out on particle counts and having poorer statistics. This is exactly
what we see in Figure 4. The larger timesteps have the same number of particles per timestep, but a smaller fraction
of those particles are being recorded in the output file, leading to much noisier data. A much much smaller timestep
would surely lead to the best particle statistics, capturing the data of every single particle in the output file, but it may
take too much computational time to reach a steady state.
Processing the Data: Results & Discussion
For this analysis, we used the output census file. Included in the particle properties in the census file is the energy,
which we can simply convert to the particle speed. We then create a histogram in velocity-space to plot the velocity
distribution of α particles, as seen below in Figure 1. We also looked at how other variables influenced the results.
Additionally, we looked at the ratio of the Cassio results to the analytic Equation 2, to obtain a quantitative metric for
the error. These results are shown in Figure 5.
Figure 1 shows good agreement between the Cassio results and Equation 2. Figure 2 also shows good agreement,
though it was run in 3D geometry. We would expect similar results to the 1D case in Figure 1, because this problem
is infinite, isotropic, and homogeneous - it’s direction-agnostic, so additional dimensions don’t provide any more new
information.
The boundary conditions also do not affect the result. Figure 1 has periodic boundary conditions in 1D slab geometry,
and Figure 3 has reflecting boundary conditions in 1D slab geometry. Both capture the infinite-ness of the problem
accurately.

As mentioned before, the timestep used in the simulation does have a large effect on the results - but likely not
because it affects the physics of the simulation. Instead, larger timesteps do not capture as many particles in the
output file - data from fewer particles leads to poorer statistics and noisier results, as seen in Figure 4.
Figure 5 shows the ratio between the Cassio data and the analytic solution (Equation 2). The data from Cassio is
consistently higher than the analytic solution predicts. I am frankly not sure why this behavior arises from the data.

Future Work
There are many more tests and many more input variables that could be explored. Some include:
 • Extending the problem to other geometries. I looked at the difference between 1D slab and 3D rectilinear ge-
 ometry, but what about 2D cylindrical geometry? 3D spherical geometry? So long as the boundary conditions
 are chosen such that the problem is effectively infinite, I would not expect any deviation from the results shown
 here, but it would be good to ensure that some geometries do not break the results.
 • The output file is fairly limited, in that it only records data at the end of the timestep. Perhaps there is another
 way to collect the particle data throughout the timestep to enable data that is more continuous without needing
 an exceedingly small timestep.
 • Investigating how or if the results change based on how the data is binned. Cassio samples the particle birth
 energy from a histogram-based energy distribution (I believe it’s based on neutron multigroup energy bins), so
 perhaps changing the birth and/or tallying binning may affect the results.
 • Equation 1 accounts for the slowing down of αs on ions and electrons. If we were able to generate dE/dx tables
 that matched these assumptions, would Cassio be able to accurately reproduce the results?
Conclusion
Cassio is able to accurately match the analytic solution for α particles born from DT fusion slowing down on electrons,
assuming an infinite homogeneous plasma. We looked at a number of input variables, and showed that Cassio is
relatively robust to changing said variables, so long as they are simply different ways to express the assumptions of
the analytic problem (e.g. using reflecting vs periodic boundary conditions to simulate the infinite medium).
It appears that one of the limiting factors in the accuracy of the results is the generation of the output census file,
rather than any inherent physics inaccuracies that Cassio may be simulating.
Additionally, this test problem was added to the Cassio testing suite to enable more robust verification efforts for the
CPT capabilities of the code. There are many more tests and variations of the test described here that could be
performed to enhance verification efforts even further.
