TextBFGS: Quasi-Newton Optimization for Discrete Executable Text via Gradient-Operator Retrieval
Zizheng Zhang, Yuyang Liao, Chen Chen, Jian He, Dun Wu, Qianjin Yu, Yanqin Gao, Jin Yang, Kailai Zhang, Eng Siong Chng, Xionghu Zhong

Abstract
Optimizing discrete executable text such as prompts and code has recently been framed as a gradient-based process, effectively translating backpropagation concepts to the semantic space. However, existing methods predominantly operate as first-order optimizers akin to Stochastic Gradient Descent, which are suffering from slow convergence and instability because they neglect the semantic curvature of the optimization landscape. To bridge this gap, we introduce TextBFGS, a second-order framework to implement a Quasi-Newton optimization method for discrete text. Unlike traditional memory-based approaches that retrieve similar textual instances, TextBFGS approximates the inverse Hessian matrix by retrieving Gradient-Operators from the memory of pre-learned successful trajectories. Specifically, given a textual gradient feedback, TextBFGS identifies historical correction patterns from the optimization knowledge base and tries to apply these abstract operators to the current variable. This mechanism enables a One-Pass Update, combining feedback generation and second-order correction into a single inference step. Empirical evaluations on code optimization across diverse domains (e.g., HumanEval, MBPP) demonstrate that TextBFGS significantly outperforms first-order baselines. It achieves superior pass rates with fewer model calls and exhibits strong cross-task transferability, thus establishes a mathematically grounded paradigm for efficient, memory-aware text optimization.

Introduction

Large Language Models (LLMs) have demonstrated remarkable capabilities across diverse tasks, particularly in code generation and complex reasoning. However, their performance heavily relies on the precise formulation of input prompts. Consequently, prompt or code optimization has evolved from a manual trial-and-error process into a systematic optimization problem
49
. Early works such as OPRO
41
and MIPRO
29
explored automatic prompt generation using LLMs as meta-optimizers. While TextGrad
44
, have formalized this paradigm by treating LLM-generated textual feedback as “gradients” (
\nabla
), enabling the optimization of discrete textual variables through iterative backpropagation, akin to training neural networks.

Despite these advancements, existing textual optimizers, like GEPA
2
, still predominantly operate as first-order methods, conceptually equivalent to Stochastic Gradient Descent (SGD)
3
. While effective in simple scenarios, first-order approaches in the discrete semantic space suffer from significant limitations. First, they are stateless: each optimization run begins tabula rasa, failing to leverage insights from previous successful refinements. Second, they neglect the semantic curvature of the optimization landscape. In numerical optimization, the Hessian matrix describes local geometry, indicating how aggressively parameters should be updated. In textual optimization, naive gradient descent treats all errors with uniform step logic, often leading to inefficient “zig-zagging”—where the model operates without addressing the underlying misconceptions—or requiring excessive token consumption to converge.

To address the statelessness of SGD, recent frameworks like REMO
38
have attempted to incorporate memory modules by retrieving successful correction traces. However, these methods typically rely on input similarity for retrieval (e.g., retrieving similar code problems). We argue that this approach limits generalization. A “boundary error” in a sorting algorithm shares the same structural defect as one in a pathfinding algorithm, even if their problem descriptions are textually disjoint. By binding retrieval to surface-level content rather than the gradient dynamics (i.e., the nature of the error), existing memory-augmented methods fail to facilitate effective transfer learning across different task domains. We reproduce this finding using TextBFGS.

In this paper, we introduce TextBFGS, a Quasi-Newton optimization framework designed for discrete executable text. Drawing inspiration from the BFGS
18
algorithm—which approximates the inverse Hessian matrix using historical gradient differences—TextBFGS approximates semantic curvature via a novel Gradient-Operator retrieval mechanism. Instead of retrieving input based on problem similarity, we construct a knowledge base mapping specific feedback patterns (gradients) to abstract modification strategies (operators). Crucially, TextBFGS operates in a One-Pass manner. Upon receiving feedback, it retrieves high-order “correction operators” from its trajectory memory and fuses the gradient generation (perception) and variable modification (update) into a single inference step. This design not only injects second-order guidance to accelerate convergence but also significantly reduces the computational overhead compared to multi-step optimization pipelines.

Our contributions are summarized as follows:

•

Gradient-Operator
Retrieval:
We bridge the gap between numerical second-order optimization and discrete text optimization, proposing TextBFGS, a Quasi-Newton method that approximates semantic curvature through gradient-based retrieval, and a robust baseline, TextBFGS-REMO, adapting the existing input-based retrieval method into our efficient One-Pass architecture to enable a rigorous comparison between retrieval paradigms (Gradient vs. Input)

•

One-Pass Update & Online Learning:
We propose the One-Pass update mechanism, which unifies feedback diagnosis and operator application into a single LLM inference step, significantly reducing computational overhead. This is coupled with an Online Learning loop where successful optimization trajectories—consisting of gradients and abstract operators—are dynamically injected back into the memory. This allows the optimizer to continuously refine its knowledge base.

•

Empirical Superiority & Efficiency:
Experiments on rigorous code optimization benchmarks (hard subset from HumanEval and MBPP) demonstrate the superiority and efficiency of TextBFGS. It achieves superior pass rates (+20.5% in MBPP) with fewer token counts (-50.6% in HumanEval) compared to TextGrad-based approaches and exhibits strong cross-domain transferability (+16.2% in MBPP) compared to input-based retrieval, effectively applying debugging logic learned from one codebase to another codebase.

Related Work

We categorize the landscape of automated text optimization into three distinct paradigms based on the utilization of feedback and geometric insight: Zero-Order (search-based), First-Order (gradient-based), and Second-Order (curvature-Aware) Optimization.

2.1
Zero-Order Optimization: Heuristic Search

Early approaches treated LLMs as black-box functions, navigating the optimization landscape through iterative mutation and selection without explicit directional guidance (gradients). OPRO
41
pioneered using LLMs as meta-optimizers to generate prompts based on the scalar trajectory of past scores. DSPy
15
;
14
introduced a declarative programming model where the MIPRO
29
optimizer employs Bayesian-inspired search strategies. These methods, including PromptBreeder
9
and EvoPrompt
13
, rely fundamentally on blind trial-and-error. They suffer from high sample complexity because they lack a diagnostic mechanism to explain why a candidate failed, relying solely on scalar rewards to guide the search.

2.2
First-Order Optimization: Textual Gradients

To introduce directionality, recent works
24
formalize the use of natural language feedback as “Textual Gradients.” TextGrad
44
treats the LLM’s critique of an output as a gradient (
\nabla
), mathematically updating the variable akin to SGD
3
.

Although originally framed as evolutionary, AlphaEvolve
28
and GEPA
2
also fall under this feedback-driven paradigm. Unlike blind mutation, they utilize feedback to guide its genetic crossover and mutation operations, effectively performing population-based gradient descent. While these methods introduce directionality, they remain strictly first-order.

Besides, TextGrad’s “momentum” variant is a simple linear aggregation of past critiques, lacking the geometric interpretation of curvature found in text optimization. Consequently, first-order methods treat the semantic landscape as Euclidean and flat, often leading to inefficient “zig-zagging” in complex reasoning tasks where the steepest descent direction does not point to the global optimum.

2.3
Second-Order Optimization: Memory as Curvature

Addressing the statelessness of gradient descent, recent research integrates memory to approximate higher-order geometric information. In numerical optimization
27
, the Hessian matrix (curvature) captures the relationship between parameter updates (
\Delta x
) and gradient changes (
\Delta g
). In the semantic space, historical optimization trajectories—tuples of mistakes and their successful corrections—serve as a proxy for this curvature information.

Reflexion
33
, REVOLVE
46
, and HessianGrad
45
utilize short-term memory or meta-prompt optimization
34
to avoid repeating immediate errors. However, it limits the fidelity of Hessian approximation. If the optimization stagnates early or fails to discover valid paths, the history remains sparse. Consequently, the optimizer cannot derive curvature information from an empty buffer, leaving it blind to the landscape’s geometry even though such structural properties objectively exist.

To overcome this limitation, REMO
38
couples TextGrad with a Retrieval-Augmented Generation (RAG)
16
module acting as a “mistake notebook.” By retrieving past corrections, REMO implicitly approximates the inverse Hessian, guiding the optimizer with historical structural wisdom. However, REMO relies on
input semantic similarity
for retrieval, restricting generalization across domains. TextBFGS bridges this gap by shifting the retrieval paradigm to
gradient space
. By retrieving abstract operators based on error dynamics, our method explicitly approximates the inverse Hessian action, enabling true Quasi-Newton optimization with robust cross-task transferability.

3.1
Problem Formulation

We consider the optimization of a discrete textual variable
x
(e.g., a prompt or code snippet) to maximize an objective function
f(x)
, which represents the performance score on a downstream task (e.g., unit test pass rate or reasoning accuracy). Since
f(x)
is non-differentiable with respect to discrete tokens, we adopt the Textual Gradient framework
44
;
30
.

Let
g_{t}
be the feedback signal generated by an LLM-based evaluator, which serves as the negative gradient
\nabla f(x_{t})
. In standard TextGrad, the update follows a SGD scheme:

x_{t+1}=\text{LLM}_{\text{update}}(x_{t},g_{t})

(1)

where
\text{LLM}_{\text{update}}
is an LLM call that applies the feedback to the variable.

3.2
Semantic Curvature and the Newton Step

A critical limitation of the SGD update above is its assumption of an isotropic optimization landscape. In reality, the semantic sapce of text exhibits high curvature
8
;
26
. First-order methods, lacking knowledge of this geometry, often overshoot or oscillate, as shown in Figure
2
.

In numerical optimization, Quasi-Newton methods such as BFGS
5
;
10
;
12
;
32
approximate the inverse Hessian matrix to capture local curvature information, enabling faster convergence than first-order methods, while modern adaptations
19
;
42
;
25
have demonstrated the effectiveness of second-order methods in deep learning. Drawing inspiration from BFGS, we adapt the philosophy to the discrete semantic domain.

To accelerate convergence, we theoretically aim to perform a Quasi-Newton step in the semantic space:

x_{t+1}=\text{LLM}_{\text{update}}(x_{t},H^{-1}_{t},g_{t})

(2)

where
H^{-1}_{t}
represents the inverse Hessian matrix. In numerical optimization,
H^{-1}_{t}
acts as a geometric transformation matrix that rotates and scales the raw gradient
g_{t}
to point towards the optimum. In our discrete text optimization, explicitly calculating this matrix is impossible. Instead, we propose that the retrieved optimization operator transformation as a local approximation of the inverse Hessian.

Since the current gradient
g_{t}
is unknown prior to generation, we utilize the “Semantic Momentum” derived from the previous step (
g_{t-1}
) to estimate this curvature matrix. This concept draws inspiration from the classical Momentum method and its recent textual adaptation in TextGrad
44
, assuming that error directions in the semantic space exhibit local persistence
8
:

H^{-1}_{t}\approx\mathcal{T}(g_{t-1};\mathcal{M})

(3)

Here,
\mathcal{T}
denotes the retrieval-based transformation function and
\mathcal{M}
denotes the Hessian-Proxy memory. Unlike standard RAG which retrieves content, our
\mathcal{T}
retrieves a
successful operator
based on the historical error dynamics.

Consequently, the One-Pass inference of TextBFGS can be formalized as:

\Delta x_{t}\approx\underbrace{\mathcal{T}(g_{t-1})}_{\text{Hessian Proxy}}\otimes\underbrace{g_{t}}_{\text{Current Gradient}}

(4)

where
\otimes
represents the LLM’s internal reasoning process that applies the abstract operator (
\mathcal{T}
) to the specific current diagnosis (
g_{t}
) to generate the final variable update.

3.3
Approximating Hessian via Gradient-Operator Retrieval

TextBFGS approximates
H^{-1}_{t}
using a retrieval-augmented mechanism
11
. We construct a Hessian-Proxy Knowledge Base (HPKB), denoted as
\mathcal{M}
, which stores pre-learned successful optimization trajectories as tuples:

\mathcal{M}=\{(g_{i},\mathcal{O}_{i})\}_{i=1}^{N}

(5)

Here,
g_{i}
is the textual gradient (the feedback/error description) from a historical iteration, and
\mathcal{O}_{i}
is the Optimization Operator—the abstract logic or pattern used to resolve
g_{i}
(e.g., “Insert boundary check” or “Break down reasoning steps”), rather than the raw content change.

The Retrieval Process:

As mentioned before, we utilized the previous gradient
g_{t-1}
as the current query gradient
g_{t}^{\text{query}}
based on the concept of Semantic Momentum, which also facilitates One-Pass inference thus reduces token consumption. We then query
\mathcal{M}
to find the
k
nearest neighbors
48
based on gradient similarity:

\begin{split}\mathcal{O}_{\text{ref}}&=\text{Retrieve}(\mathcal{M},g_{t}^{\text{query}},k)\\
&=\operatorname*{Top-}k_{(g_{i},\mathcal{O}_{i})\in\mathcal{M}}\left(\text{CS}(\text{Embed}(g_{t}^{\text{query}}),\text{Embed}(g_{i}))\right)\end{split}

(6)

where
\text{Embed}(\cdot)
is a dense vector embedding of the gradient text, and
\text{CS}(\cdot)
denotes the cosine similarity.

Why this matters:
Unlike REMO
38
which retrieves based on
input
similarity (
\text{sim}(x_{t},x_{i})
), TextBFGS retrieves based on
gradient
similarity (
\text{sim}(g_{t},g_{i})
). This enables cross-task generalization. For instance, an “Index Error” gradient in a sorting algorithm can retrieve a “Boundary Check” operator originally learned from a string parsing task, effectively transferring the curvature information across distinct coding domains.

3.4
One-Pass Update Loop

To ensure efficiency, TextBFGS fuses the gradient generation and the variable modification into a single LLM inference step. We design a specialized prompt structure that forces the LLM to explicitize the gradient and operator.

Let
\mathcal{P}
be the system prompt, which optional background information can be injected. The update rule is formally:

g_{t},\mathcal{O}_{t},x_{t+1}=\text{LLM}(\mathcal{P}(x_{t},E_{t},\mathcal{O}_{\text{ref}}))

(7)

Where
E_{t}
is the execution result. The model performs the following internal Chain of Thought(CoT)
37
:

1.

Gradient Analysis (
g_{t}
):
The model analyzes the error pattern between the current output and the expectation, generating the textual gradient
g_{t}
(wrapped in
<GRADIENT>
tags).

2.

Opearator Application (
\mathcal{O}_{t}
):
The model generates the hybrid operator from the generated gradient
g_{t}
and the retrieved set
\mathcal{O}_{\text{ref}}
(wrapped in
<OPERATOR>
tags).

3.

Newton Update:
The model applies this operator to
x_{t}
to generate
x_{t+1}
(wrapped in
<IMPROVED>
tags).

This mechanism reduces the computational cost by 50% compared to standard TextGrad, REMO and other variant methods
39
(which requires separate calls for gradient and update) while injecting second-order guidance.

3.5
Online Learning: Self-Evolving Memory

TextBFGS mimics the self-correcting nature of Quasi-Newton methods by dynamically updating its HPKB during optimization. In numerical optimization, Quasi-Newton methods (e.g., BFGS) achieve self-correction by iteratively refining an approximation of the Hessian matrix using historical gradient and parameter changes (
\Delta g
and
\Delta x
). This allows the algorithm to continuously adjust its estimate of local curvature, gradually converging toward the true second-order geometry and guiding more efficient update directions. TextBFGS transfers this principle to the semantic space: its HPKB continuously self-improves through accumulating gradient‑operator pairs, making the estimation of semantic curvature increasingly accurate as optimization proceeds.

Upon a successful update (e.g.,
f(x_{t+1})>f(x_{t})
), the system abstracts the specific transformation into a generalized optimization operator
\mathcal{O}_{t}
. Instead of storing raw code differences, the LLM extracts the underlying fix logic (e.g., “Add boundary condition”). The resulting tuple
(g_{t},\mathcal{O}_{t})
is then injected into the HPKB. This continuous injection enriches the gradient‑space coverage with diverse error‑solution pairs. It enables TextBFGS to retrieve precise operators for recurring errors across different contexts, transforming the optimizer from a stateless solver into a self‑evolving agent that progressively masters the optimization landscape
16
;
23
.

Knowledge Base Construction.

One-Pass Inference Reduces API Overhead.

A distinct advantage of our framework is the One-Pass architecture. Methods like TextGrad, REMO operate in a two-stage manner: one API call to compute the textual gradient and a second separate call to apply the update. In contrast, TextBFGS integrates the gradient computation (via internal CoT) and the operator execution into a single inference step.

As shown in Table
5
, although TextGrad has the lowest tokens per call (863.9), it requires significantly more API calls (35.8). While both TextBFGS (w/o KB) and TextGrad achieve identical performance (82.22%, Table
1

18.4%
cost reduction compared to TextGrad (25.2k vs. 30.9k), proving that One-Pass inference saves substantial overhead. TextBFGS-REMO is also implemented using One-Pass architecture, whereas the original REMO typically requires multiple steps.

Token Consumption and Retrieval Granularity

We analyze the trade-off using Tokens/Task metric. As shown in Table
5
and Table
6
, two distinct patterns emerge:

•

Inefficiency of Stateless Momentum:
While TextGrad-Momentum improves pass rates over vanilla TextGrad, it incurs the highest computational cost (43.7k). This is because Momentum simply concatenates the optimization history. Since this history is stateless and unfiltered, it may contain irrelevant or redundant information that bloats the context without proportionally reducing the number of iterations.

•

Efficiency via Knowledge-Retrieval:
In contrast, although retrieving knowledge increases the input size, the injected operators are highly relevant ”high-utility” priors that guide the model to the correct solution much faster. This drastically cuts the iteration count (e.g. down to 13.6), achieving higher performance (from 86.67% to 93.33%, Table
1
), resulting in the lowest total token consumption (21.6k), effectively saving total
50.6%
tokens compared to Momentum.

Furthermore, we observe a granularity preference across domains. Retrieve-based methods consumes obviously fewer tokens per call on HumanEval (Cross-Domain, 1582 tokens) than on MBPP (In-Domain, 2104 tokens). We attribute this to the nature of retrieval: In-domain queries tend to fetch lengthy, specific information, whereas cross-domain queries retrieve shorter, more abstract information. This suggests that in cross-domain learning, generalizable knowledge and experiences are matter, and retrieve-based methods naturally adapt its retrieval granularity, maintaining efficiency even when transferring knowledge across disjoint domains.

6
Conclusion

We introduced TextBFGS, a Quasi-Newton framework addressing the inefficiencies of first-order text optimization. By shifting to Gradient-Operator retrieval, we approximate semantic curvature, enabling robust cross-domain transfer of debugging logic. Our One-Pass update and Online Learning mechanisms significantly enhance efficiency and performance compared to baselines. TextBFGS establishes a mathematically grounded paradigm for self-evolving, memory-aware text optimization.
