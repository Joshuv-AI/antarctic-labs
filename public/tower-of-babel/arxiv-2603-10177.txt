κ \kappa -Join: Combining Vertex Covers for Parallel Joins
Simon Frisk, Austen Fan, Paraschos Koutris

Abstract
. Significant research effort has been devoted to improving the performance of join processing in the massively parallel computation model, where the goal is to evaluate a query with the minimum possible data transfer between machines. However, it is still an open question to determine the best possible parallel algorithm for any join query. In this paper, we present an algorithm that takes a step forward in this endeavour. Our new algorithm is simple and builds on two existing ideas: data partitioning and the HyperCube primitive. The novelty in our approach comes from a careful choice of the HyperCube shares, which is done as a linear combination of multiple vertex covers. The resulting load with input size n n and p p processors is characterized as n / p 1 / κ n/p^{1/\kappa} , where κ \kappa is a new hypergraph theoretic measure we call the reduced quasi vertex-cover. The new measure matches or improves on all state-of-the-art algorithms and exhibits strong similarities to the edge quasi-packing that describes the worst-case optimal load in one-round algorithms.



1.
Introduction

The MPC model, or
massively parallel computation model
, is frequently used to theoretically study algorithms to compute database queries in clusters of processors
(
5
)
. In this model, an algorithm consists of several rounds, where each round consists of exchange of data between processors, followed by local computation. Guided by the observation that performance often is bottlenecked by communication cost and synchronization cost, an algorithm in this model should minimize the number of rounds as well as the load of each round, defined as the maximum amount of data received by any processor in the round.

There has been extensive research into understanding the cost of computing a join query in the MPC model, as a function of the query, the input size
n
, and the number of processors
p
. Early work on the MPC model focused on algorithms with one round of communication
(
5
)
and input data without skew, and built on the HyperCube algorithm to process joins
(
3
)
.
For arbitrary database instances, a tight bound of
n/p^{1/\psi^{*}}
, where
\psi^{*}
is the quasi-edge packing, was obtained
(
17
)
. More recent work focused on algorithms where the number of communication steps is constant in
n
and
p
. A tight bound of
n/p^{1/\rho^{*}}
, where
\rho^{*}
is the fractional edge cover of the query, has been obtained for cyclic queries
(
11
)
and queries over binary relations
(
15
)
. Similar techniques have been used to improve the load on other classes of queries
(
20
)
. The quantity
n/p^{1/\rho^{*}}
is a known lower bound on all queries
(
17
)
, which builds on a counting argument using the AGM bound
(
4
)
. A higher lower bound was described on the boat query, showing
n/p^{1/\rho^{*}}
cannot be matched in general
(
11
)
. A recent state-of-the art improvement gave an algorithm matching the best known load on all queries except for the Loomis-Whitney join
(
1
)
. Whereas prior work uses heavy-light partitioning, this more recent work uses a more fine-grained data partitioning.
Despite all these research efforts, the general worst-case optimal load remains open.

Our Contributions

In this paper, we present a new join algorithm, called
\kappa
-Join, establishing an upper bound of
\tilde{O}(n/p^{1/\kappa})
on the load required to compute a join query in the MPC model, where
\tilde{O}
hides a polylogarithmic factor in
n,p
. Here,
\kappa
is a graph-theoretic quantity defined over the hypergraph of the query, which we call the
reduced quasi vertex-cover
.
Our algorithm is relatively simple, but builds on several key ideas not found in previous work.

The definition of
\kappa
bears strong similarities to the edge quasi-packing
\psi^{*}
, which describes the worst-case optimal load achievable with one-round algorithms in the MPC model. For a join query described by a hypergraph
\mathcal{H}=(V,E)
, the edge quasi-packing is defined as
\psi^{*}:=\max_{S\subseteq V}\tau^{*}(\mathcal{H}[S])
, where
\tau^{*}(\mathcal{H}[S])
denotes the value of the minimum vertex cover on the subhypergraph induced by the vertex set
S
. Similarly, the new measure
\kappa
is defined as
\max_{S\subseteq V}\textsf{red}(\tau^{*}(\mathcal{H}[S]))
, meaning the only difference is that any relation that is contained in another relation in
\mathcal{H}[S]
is removed before finding the minimum vertex cover.

In addition, we present some arguments on why we believe that the derived upper bound of
\tilde{O}(n/p^{1/\kappa})
might be optimal. Even though we do not show a tight lower bound for all queries, we provide a concrete worst-case instance construction that we conjecture to lead to it.

Technical Overview

Our algorithm builds on several concepts that exist in previous work, but also integrates multiple new key insights. A central primitive in the MPC model is the
HyperCube
algorithm. Many algorithms in previous work have the following overarching approach
(
1
;
17
;
15
)
. First, the input data is partitioned based on the degrees of different values, and the query is then computed in parallel for each partition. For each partition, certain join attributes, called
heavy
, may have high degree. Each possible tuple
t_{H}
over the heavy variables gets assigned a dedicated set of machines, which compute the part of the output where the heavy variables have values
t_{H}
. The query is often computed using some semijoins and then invoking HyperCube.

Our algorithm also starts by performing data partitioning, but we perform a very fine-grained partitioning, which gives us precise control over the degrees occurring in each partition. To compute the join for a fixed data partition, our approach is quite different from previous work. We first identify and perform some binary joins that only grow the intermediate result size by a small factor. We then invoke the HyperCube algorithm on the intermediate results, instead of on the input relations. The shares used in the HyperCube algorithm are picked as a linear combination of vertex covers for different subqueries, each vertex cover corresponding to a hypergraph
\textsf{red}(\mathcal{H}[S])
for some subset
S\subseteq V
.

Comparison to State of the Art

Our algorithm improves upon the state-of-the-art algorithm, known as
PAC

(
1
)
, in two major ways. First, we prove that our algorithm achieves a load that is always at least as good as PAC, and other algorithms from previous work
(
1
;
20
;
15
;
11
)
. Furthermore, there is at least one class of queries, the Loomis-Whitney joins, where our algorithm gives a strict improvement. A fundamental reason for this is that previous algorithms allocate to each heavy tuple a dedicated set of machines, an approach we argue cannot work in general.
Second, the load of the
PAC
algorithm is
n/p^{1/\gamma}
, where
\gamma
is the
PAC
-number. The
PAC
-number has a complex definition, where given a query
Q
it is non-trivial to determine what the
PAC
-number of
Q
is, and if a candidate
PAC
-number is known, it is very hard to determine if a better one is possible. Furthermore, a lot of the complexity in the definition of
\gamma
is inherited into the algorithm. In contrast, our algorithm has the load
n/p^{1/\kappa}
, where
\kappa
has a straight-forward hypergraph-theoretic definition and can be computed with a mixed integer-linear-program. Our algorithm is also simpler, removing many of the different cases in the
PAC
-algorithm.

A related line of work generalized the MPC model to optimize query processing with respect to the topology of the compute cluster

2.
Preliminaries

A
relation

R
with schema
\textsf{vars}(R)
is a set of tuples, where
each tuple maps each variable in
\textsf{vars}(R)
to an element of the domain
\mathbf{dom}
. We will use
x,y,z,\dots
to denote variables. A
natural join query

Q
can be defined as a set of relations, denoted as
\Join_{i}R_{i}
. We will use
\textsf{vars}(Q)
to denote the variables that occur across all relations in
Q
. The input size of a query is defined as the total number of tuples across all relations.

We will assume that
Q
has no self-joins, i.e., no relations can repeat in the query. This assumption is w.l.o.g. for any upper bound, since we can simply create a copy of the repeated relation. We will also assume w.l.o.g. that no two relations can have the same schema.

Hypergraphs and Measures

We can now associate with each natural join query
Q
a hypergraph
\mathcal{H}=(V,E)
such that
V=\textsf{vars}(Q)
and
E=\{\textsf{vars}(R)\mid R\in Q\}
.
For
S\subseteq V
, we define
\mathcal{H}[S]
to be the vertex-induced subgraph of
\mathcal{H}
, i.e., the hypergraph
\mathcal{H}^{\prime}
with vertex set
S
and edge set
\{S\cap e\mid e\in E,e\cap S\neq\emptyset\}
.

Definition 2.1 (Reduced Hypergraph).

Let
\mathcal{H}
be a hypergraph. The reduced hypergraph, denoted
\textsf{red}(\mathcal{H})
, is a hypergraph
(V,E^{\prime})
, where
E^{\prime}\subseteq E
is a subset obtained by removing any edge
e\in E
such that there is another
e^{\prime}\in E
with
e\subseteq e^{\prime}
.

In combinatorics, a
clutter
or
Sperner family
is a pair
(V,E)
, where
V
is a set and
E
is a set of subsets of
V
, such that for no
e,e^{\prime}\in E
, is
e\subseteq e^{\prime}
. A reduced query forms a Sperner family.

Definition 2.2 (Edge Packing & Covering).

Let
\mathcal{H}=(V,E)
be a hypergraph. Let
\mathbf{u}
be a (non-negative) weight assignment on the hyperedges
E
. Then,
\mathbf{u}
is a:

•

fractional edge packing (or matching)
if for every vertex
v\in V
,
\sum_{v\in e}u_{e}\leq 1
. The total weight of the maximum fractional edge packing is denoted by
\tau^{*}(\mathcal{H})
.

•

fractional edge covering
if for every vertex
v\in V
,
\sum_{v\in e}u_{e}\geq 1
. The total weight of the maximum fractional edge covering is denoted by
\rho^{*}(\mathcal{H})
.

In general, there is no relationship between the two quantities. We will also be interested in
fractional vertex covers
of a hypergraph
\mathcal{H}
: these are weight assignments
\mathbf{v}
on the vertices
V
such that for every hyperedge
e\in E
,
\sum_{v\in e}\mathbf{v}_{v}\geq 1
. By the duality principle in linear programming, the total weight of the minimum fractional vertex cover is equal to
\tau^{*}(\mathcal{H})
.

The MPC Model

The MPC model, or
Massively Parallel Computation model
, is a theoretical model to analyze the cost of distributed algorithms. It uses a cluster of
p
machines, and the input, whose size is
n
, is initially partitioned across the machines, with each machine storing
n/p
data in local memory. The computation is synchronous and proceeds in
r
rounds, where each round consists of message passing between the machines, and computation on data in local memory. By the end of the algorithm, we require that union of the output across each machine forms the desired output. The cost of an algorithm is modeled as the number of rounds
r
and the maximum data size
L
that any machine receives in any round. An ideal MPC algorithm works in a constant number of rounds and achieves linear load, i.e.,
L=O(n/p)
.

We are interested in using the MPC model to analyze join processing, and in particular we focus in the regime where the number of rounds
r
is constant in
n
and
p
, but may depend on the query. We will also work in the regime where
n\gg p
, i.e., the data size is much bigger than the number of processors (we will specify the exact requirement in each theorem statement).
Given a hypergraph
\mathcal{H}
, our main question is:
what is the smallest exponent
\epsilon(\mathcal{H})
such that for every natural join query
Q
with hypergraph
\mathcal{H}
and input size at most
n
, we can compute its output in constant rounds and load
O(n/p^{\epsilon(\mathcal{H})})
?
This is what we call a worst-case optimal setting, since the goal is to match the cost of the worst-behaved instance with size
\leq n
.

In this section, we define our new measure of the hypergraph of a join query.

Definition 3.1.

Let
\mathcal{H}=(V,E)
be a hypergraph. The

is defined as

\kappa(\mathcal{H}):=\max_{S\subseteq V}\tau^{*}(\textsf{red}(\mathcal{H}[S])).

In other words, to compute

Upper Bound

4.1.
A Partitioning Step

Let
R
be a relational instance with schema
\textsf{vars}(R)
. Let
X,Y\subseteq\textsf{vars}(R)
be two subsets of variables. Let
\mathbf{y}
be a tuple over
Y
. Define

\deg_{R}(X\mid Y=\mathbf{y}):=|\pi_{X}(\sigma_{Y=\mathbf{y}}R)|.

Furthermore, define
\deg_{R}(X\mid Y):=\max_{\mathbf{y}}\deg_{R}(X|Y=\mathbf{y})
. For convenience, we will sometimes use the shorthand notation
\deg_{R}(X)=\deg_{R}(\textsf{vars}(R)\mid X)
.

Next, we define a type of constraint. This constraint is similar to the property we get in a uniformized instance, where we would replace the inequalities below with equalities.

Definition 4.1.

A
constraint set
for a relation
R
is a total function
\sigma:\mathcal{P}(\textsf{vars}(R))\rightarrow\mathbb{R}^{\geq 0}
.

Definition 4.2.

We say that a relational instance
R
satisfies a constraint set
\sigma
if for every pair of subsets
X\subseteq Y\subseteq\textsf{vars}(R)
it holds:

\deg_{R}(Y\mid X)\leq 2\frac{\sigma(X)}{\sigma(Y)}.

Below we see a partitioning method for a relation
R
. Let
\mathcal{S}\subseteq\mathcal{P}(\textsf{vars}(R))
be an ordered set of subsets that is sorted in increasing order of cardinality.

Algorithm 1

Partitioning Procedure

1:

function

Partition
(
R:\text{relational instance},\mathcal{S}:\text{remaining sets }\subseteq\mathcal{P}(\textsf{vars}(R))
)

2:

if

\mathcal{S}=\emptyset

then

return

R

U\leftarrow\text{first item in }\mathcal{S}

In the above, some partitions may be empty, if the constraints are picked in an incompatible way. Such partitions can be disregarded.

Lemma 4.3.

Let
\mathcal{R}
be the output of Algorithm
1
when it runs with input a relation
R
of size
n
and
\mathcal{S}=\mathcal{P}(\textsf{vars}(R))
. Then,

(1)

|\mathcal{R}|\leq\log^{|\mathcal{P}(\textsf{vars}(R))|}n
;

(2)

every instance
T\in\mathcal{R}
satisfies a constraint set
\sigma_{T}
with
\sigma_{T}(\emptyset)=n
and
\sigma_{T}(\textsf{vars}(R))=1
.

Proof.

We show both items of this lemma in sequence.

1)
In each step, we create at most
\log n
subinstances, and the algorithm runs recursively for at most
|\mathcal{P}(\textsf{vars}(R))|
steps.

2)

We will construct the constraint set for any subinstance following the recursive process. Consider the step where the algorithm partitions on some set
U\subseteq\textsf{vars}(R)
: then, for the subinstance
R^{i}
, we will pick
\sigma(U)=2^{i}
. Observe that during the first step, when
U=\emptyset
, all tuples fall in the subinstance with the largest value, hence
\sigma(\emptyset)=n
. During the last step, when
U=\textsf{vars}(R)
, all degrees are
1
and hence every subinstance will set
\sigma(\textsf{vars}(R))=1
.

It remains to show that the desired inequality holds for any subinstance
T\in\mathcal{R}
and every
X\subseteq Y\subseteq\textsf{vars}(R)
. Indeed, consider the step of the algorithm just after
R
was partitioned on
Y
. Let
\mathbf{x}
be any tuple over
X
. For any tuple
\mathbf{y}
over
Y
where
\pi_{X}(\mathbf{y})=\mathbf{x}
, since we just partitioned using
Y
,
\deg_{R}(\textsf{vars}(R)\mid Y=\mathbf{y})\geq\sigma(Y)/2
. Thus, we can write:

\deg_{R}(\textsf{vars}(R)\mid X=\mathbf{x})=\sum_{\mathbf{y}\in Y|\pi_{X}(\mathbf{y})=\mathbf{x}}\deg_{R}(\textsf{vars}(R)\mid Y=\mathbf{y})\geq\frac{\sigma_{R}(Y)}{2}\cdot\deg_{R}(Y\mid X=\mathbf{x}).

We now claim that
\deg_{R}(\textsf{vars}(R)\mid X=\mathbf{x})\leq\sigma_{R}(X)
. This holds since the inequality
\deg_{R}(\textsf{vars}(R)\mid X=\mathbf{x})\leq\sigma_{R}(X)
holds right after we partitioned on
X
, and when we repartition the degree can only grow smaller. Reorganizing we obtain:

\deg_{R}(Y\mid X=\mathbf{x})\leq 2\frac{\sigma_{R}(X)}{\sigma_{R}(Y)}.

Finally, observe that this inequality will hold after Algorithm
1
has completed, since the degree can only become smaller by removing tuples during repartitioning.
∎

Suppose we are given a query
Q
. Let
\Sigma=\{\sigma_{R}\}_{R\in Q}
be a set of constraint sets, one for each relation
R
in the query. We will say that
Q
is
\Sigma

\Sigma

\Sigma
. Thus, from here on we will focus on a
\Sigma
-uniformized query
Q
.

Proposition 4.4.

Let

4.2.
Vertex Weight Mappings

We define a
vertex weight mapping
of a query
Q
with hypergraph
\mathcal{H}=(V,E)
to be a function
v:V\rightarrow\mathbb{R}_{\geq 0}
.

Definition 4.5.

Let
\mathbf{v}
be a vertex weight mapping of a
\Sigma
-uniformized query
Q
with hypergraph
\mathcal{H}
. For a relation
R
in
Q
of size
n
and
U\subseteq\textsf{vars}(R)
, we say that
U
is:

•

light in
R
if
\sigma_{R}(U)<\frac{n}{p^{\sum_{i\in U}v_{i}}}
;

•

heavy in
R
if
\sigma_{R}(U)\geq\frac{n}{p^{\sum_{i\in U}v_{i}}}
;

•

consistent in
R
if
\sigma_{R}(U)\leq\frac{n}{p^{\sum_{i\in U}v_{i}}}
.

Notice that the difference between light and consistent is merely strictness of the inequality. We can also view consistent as being light or heavy with equality. This will be useful later on.

The above definition and Lemma
4.3
tells us that for a light
U
in
R
, the degree of
U
in
R
is bounded as
\deg_{R}(U)\leq 2\sigma_{R}(U)<{n}/{p^{\sum_{i\in U}v_{i}}}
. In addition, for any relation
R
, the empty set is always heavy but consistent, and
\textsf{vars}(R)
is always light.

For readers familiar with previous work, we note that we will often normalize our vertex weight mappings for convenience. This means we will often have terms on the form
n/p^{v_{x}}
, instead of
n/p^{v_{x}/\sum_{x}v_{x}}
as in some previous work.

Definition 4.6 (Consistent Vertex Weight Mapping).

Let
Q
be a
\Sigma
-uniformized query, and
\mathbf{v}
be a vertex weight mapping of
Q
. We say that
\mathbf{v}
is
consistent
with
Q
if for every
R\in Q
and every
U\subseteq\textsf{vars}(R)
,
U
is consistent in
R
.

Our goal is to use HyperCube with shares picked using a consistent weight mapping, because then there are no values that can individually break the load requirement. Consistency means that the allocated shares are not too big - as shares increase, the heavy thresholds decrease. This means there is some point when the shares can become too big. Later, we will also need that the shares are not too small, so the load is not too high.

Definition 4.7 (Heavy Sets).

Let
Q
be a
\Sigma
-uniformized query, and
\mathbf{v}
be a vertex weight mapping of
Q
. We denote by
\mathcal{U}[{\mathbf{v}}]=\{(U,R)\mid U\subseteq\textsf{vars}(R)\text{ and }U\text{ is heavy in }R\}
the collection of all heavy sets in
Q
, and by
H[\mathbf{v}]=\bigcup_{(U,R)\in\mathcal{U}[{\mathbf{v}}]}U
the set of all variables that occur in some heavy set.

Lemma 4.11.

Let

(2)

(3)

Proof.

We separately prove the items in the lemma.

(1)

(2)

Before the first iteration, this is true because

(3)
We can write the norm of

|\mathbf{V}(\psi)|_{1}=\sum_{x\in V}\mathbf{V}_{x}(\psi)=\sum_{x\in V}\sum_{U\in\mathcal{P}(V)}\psi_{U}(\mathbf{v}^{*}_{U})_{x}=\sum_{U\in\mathcal{P}(V)}\psi_{U}|\mathbf{v}^{*}_{U}|_{1}\leq\kappa(\mathcal{H})\cdot|\psi|_{1}\leq\kappa(\mathcal{H}).

Here the first inequality comes from the fact that

, and the second inequality from item (1).
∎

Lemma 4.12.

Let
Q
be a
\Sigma
-uniformized query. Let
\psi
be the vector returned from Algorithm

. Then for every

Proof.

First, we have

Let

\mathbf{v}^{*}_{L_{1}},\dots,\mathbf{v}^{*}_{L_{t}}

\delta_{1},\dots,\delta_{t}

Let

. The following observation will be critical: if
\textsf{vars}(R^{\prime})\cap L_{j}\supseteq\textsf{vars}(R)\cap L_{j}
then
\textsf{vars}(R^{\prime})\cap L_{i}\supseteq\textsf{vars}(R)\cap L_{i}
for any

. Let us define the following:

if there exists

and

Consider now any relation
R\in Q
. At the end of the algorithm, the light variables are exactly
L_{t}
. Pick

to be a maximal relation w.r.t.

\sum_{x\in\textsf{vars}(R^{\prime})}\mathbf{V}_{x}(\psi)\geq 1
.

We claim that the following holds: for any

\sum_{x\in\textsf{vars}(R^{\prime})\cap L_{j}}\mathbf{v}^{*}_{L_{j}}\geq 1.

To show that the above holds, it sufices to prove that the hypergraph
\mathcal{H}_{i}=\textsf{red}(\mathcal{H}[L_{i}])
has a hyperedge

\displaystyle\sum_{x\in\textsf{vars}(R^{\prime})}\mathbf{V}_{x}(\psi)

\displaystyle=\sum_{x\in\textsf{vars}(R^{\prime})}\sum_{j=1}^{t}\delta_{j}(\mathbf{v}^{*}_{L_{j}})_{x}=\sum_{j=1}^{t}\delta_{j}\sum_{x\in\textsf{vars}(R^{\prime})}(\mathbf{v}^{*}_{L_{j}})_{x}

Discussion

For certain instances, we may have
|\mathbf{V}(\psi)|_{1}<\Delta
when picking
\Delta=\kappa
. This will cause the algorithm to use less than

\Delta
. If we pick

. By picking

by doing binary search, finding the

. This way, some instances, or partitions within instances, may obtain a better load than

We will denote by
\mathbf{v}=\mathbf{V}(\psi)/\Delta
, where

.

4.3.
One Key Lemma

Let us fix a
\Sigma
-uniformized query
Q
with constraint sets
\Sigma=\{\sigma_{R}\}_{R}
, and a consistent weight mapping
\mathbf{v}
as chosen by the algorithm above. We define the
heavy relation
:

R_{H}=\Join_{(U,R)\in\mathcal{U}}\pi_{U}(R).

The heavy relation
R_{H}
has variables
H[\mathbf{v}]
. The next important lemma shows that
R_{H}
also behaves in a (somewhat) uniformized way.

Lemma 4.13.

For any
X\subseteq H
, we have
\deg_{R_{H}}(H\mid X)\leq 2^{|H|}p^{\sum_{i\in H-X}v_{i}}
.

Proof.

Consider any ordering
(U_{1},R_{1}),\dots,(U_{k},R_{k})
of the elements in the set
\mathcal{U}
. Let
H_{0}=\emptyset
, and
H_{j}=\bigcup_{i=1}^{j}U_{i}
for
j=1,\dots,k
. Note that
H_{k}=H
.
We will inductively show that for every
j=0,\dots,k
, we have
\deg_{R_{H}}(H_{j}\cup X\mid X)\leq 2^{j}p^{\sum_{i\in H_{j}-X}v_{i}}
.

In the base case
j=0
, the statement is true since
\deg_{R_{H}}(X\mid X)=1
. For the inductive case
j\geq 1
,

\displaystyle\deg_{R_{H}}(H_{j}\cup X|X)

\displaystyle\leq\deg_{R_{H}}(H_{j-1}\cup X|X)\deg_{R_{j}}(U_{j}|U_{j}\cap(H_{j-1}\cup X))

\displaystyle\leq 2^{j-1}p^{\sum_{i\in H_{j-1}-X}v_{i}}\deg_{R_{j}}(U_{j}|U_{j}\cap(H_{j-1}\cup X))

(Inductive Assumption)

\displaystyle\leq 2^{j}p^{\sum_{i\in H_{j-1}-X}v_{i}}\cdot\frac{\sigma_{R_{j}}(U_{j}\cap(H_{j-1}\cup X))}{\sigma_{R_{j}}(U_{j})}

(Definition
4.2
)

\displaystyle\leq 2^{j}p^{\sum_{i\in H_{j-1}-X}v_{i}}\frac{n}{p^{\sum_{i\in U_{j}\cap(H_{j-1}\cup X)}v_{i}}}\frac{p^{\sum_{i\in U_{j}}v_{i}}}{n}

(Consistency, Definition
4.5
)

\displaystyle=2^{j}p^{\sum_{i\in H_{j}-X}v_{i}}

This concludes the proof.
∎

4.4.
The
\kappa
-Join Algorithm

The algorithm has 4 phases. The first phase uses
O(1)
rounds, the remaing three phases need
4
rounds. We first give some intuition behind the algorithm, and then describe it more precisely.

Intuition

Because we picked
\mathbf{v}
as a consistent weight mapping, there are no sets that are heavy with a strict inequality (see Definition
4.5
). Our main concern is then that there may be relations that are not "covered" by
\mathbf{v}
, which means that if we apply HyperCube directly, the load will be too high.
To solve this problem, for such a relation
R
that is not "covered", we can create an intermediate relation
R^{\dagger}
, by effectively joining
R
with another relation
S
, which is the guard. This intermediate relation turns out to have a cardinality that grows very little compared to the input size, but it is guaranteed to be "covered". We can therefore directly use HyperCube on all these intermediate relations, which solves the query. From a technical perspective, we do not just join
R
with its guard
S
, but instead with the heavy relation
R_{H}
. In fact, we may not need to use the whole relation
R_{H}
for all
R
, but it never hurts to do so. We discuss this further later.

1-Preprocessing

Partition the input using Algorithm
1
. The remainder of the algorithm runs in parallel for each
\Sigma
-uniformized query
Q
.

Use Algorithm
2
with
\Delta=\kappa(\mathcal{H})
to find a consistent vertex weight mapping
\mathbf{v}=\mathbf{V}(\psi)/\Delta
.

2-Broadcasting Heavy Sets

For every
(U,R)\in\mathcal{U}[{\mathbf{v}}]
, broadcast
\pi_{U}R
to all machines. The heavy relation
R_{H}=\Join_{(U,R)\in\mathcal{U}}\pi_{U}(R)
can now locally be computed in each machine.

3-Semijoins

In parallel, for every relation
R\in Q
, do the following:

•

If
\textsf{vars}(R)\setminus H[\mathbf{v}]\neq\emptyset
, let
S
be the relation that guards
R
. Compute the join
R^{\dagger}\leftarrow(S\Join R_{H})\lJoin R
using
p
machines

•

If
\textsf{vars}(R)\setminus H[\mathbf{v}]=\emptyset
, compute the semijoin
R^{\dagger}\leftarrow R_{H}\ltimes R
using
p
machines

4-HyperCube

Perform HyperCube partitioning on every intermediate relation
R^{\dagger}
using the share
p^{v_{x}}
for variable
x
.

Example 0.

We now continue Example
4.9
. The heavy sets are here
\mathcal{U}[\mathbf{v}]=\{(\{X\},R),(\{X\},S)\}
.

Broadcasting Heavy Sets: We broadcast the heavy sets to all machines, after which each machine can compute the heavy relation
R_{H}
(which only has variable
X
).

Semijoins: We will compute two intermediate relations, both with variables
X,Y,Z
. These are
(T\bowtie R_{H})\ltimes R
, and
(T\bowtie R_{H})\ltimes S
. The intermediate results are at most
np^{1/6}
, since there are only
p^{1/6}
values on
X
.

HyperCube: We finally intersect the two intermediate relations with hypercube partitioning.

We notice that the algorithm we get for the triangle query in the example is very similar to the one previously described
(
17
)
. Also, note that the algorithm above only uses
p^{1.25/1.5}<p
machines, since
|\mathbf{v}|_{1}=1.25
but we use
\Delta=1.5
.

Discussion

Here, for some relation
R
, we use the relation
S\bowtie R_{H}
and semijoin with
R
. Here, we could replace
R_{H}
with
R_{H}^{\prime}
, where
R_{H}^{\prime}
is different for each
R
, and only has a subset of variables in
H[\mathbf{v}]
. It suffices that
R_{H}^{\prime}
is a join of heavy sets such that
\textsf{vars}(R_{H}^{\prime})\supseteq\textsf{vars}(R)\cap H[\mathbf{v}]
. For binary relations, we can always pick
R_{H}^{\prime}
such that
\textsf{vars}(R_{H}^{\prime})=\textsf{vars}(R)\cap H[\mathbf{v}]
, which gives a nice interpretation that the semijoin phase effectively joins
R
with its guard
S
, and semijoins on
R_{H}
, but for general arities, this may not be possible. Another thing we could have done is that for relations
R
that are self-guarded, we can directly partition them with HyperCube. We have chosen to simplify the algorithm by always joining with
R_{H}
which has all heavy sets, allowing us to have fewer cases and to use the same relation
R_{H}
for all relations
R
.

4.5.
Correctness and Load Analysis

Correctness

To prove correctness of the above algorithm, we need to show two things.

Lemma 4.15.

The total number of machines allocated is at most
p
.

Proof.

To show this, it suffices to bound the number of machines used during HyperCube partitioning in Round 3. Indeed, the number of machines used to hash a relation
R^{\dagger}
is

p^{\sum_{x\in\textsf{vars}(R^{\dagger})}\mathbf{v}_{x}}\leq p^{|\mathbf{v}|_{1}}=p^{|\mathbf{V}(\psi)|_{1}/\Delta}=p^{|\mathbf{V}(\psi)|_{1}/\kappa(\mathcal{H})}\leq p.

The last inequality follows from Lemma
4.11
, item (3).
∎

Lemma 4.16.

Let
Q
be
\Sigma
-uniformized query. Then, the algorithm reports a tuple
t
if and only if
t
is in the output of
Q
.

Load Analysis

To analyze the load, we will need to use the following two results from prior literature.

Lemma 4.17.

Consider a relation
R
with arity
r
and cardinality
\leq N
. Suppose we wish to partition
R
with
p
machines, organized into a grid
[p_{1}]\times\dots\times[p_{r}]
with
r
hash functions. If for every
U\subseteq[r]
, we have
\deg_{R}(U)\leq\frac{N}{\prod_{i\in U}p_{i}}
, then with high probability the maximum load is
\tilde{O}(N/p)
.

Lemma 4.18.

The semijoin
R\lJoin S
can be computed in two rounds with load
\tilde{O}(\max\{|R|,|S|\}/p)
.

Equipped with these two lemmas, we can show the crucial load result.

Theorem 4.19.

Let
Q
be a
\Sigma
-uniformized query, and require
n\geq p^{3}
. Then, the algorithm runs with load
\tilde{O}(n/p^{1/\kappa(\mathcal{H})})
.

Proof.

We analyze the load across all three phases. For simplicity, let
H=H[\mathbf{v}]
.

In the first phase, we broadcast all heavy sets. We know that for each
(U,R)\in\mathcal{U}[\mathbf{v}]
,
|\pi_{U}R|\leq p
. Each machine receives a constant number of heavy sets, each of size
p
, from at most
p
machines. Hence, assuming
n\geq p^{3}
, this load is smaller than
n/p
.

For the semijoin phase, if
\textsf{vars}(R)\setminus H=\emptyset
, then
R_{H}\ltimes R
is performed with load
n/p
by Lemma
4.18
.

If
\textsf{vars}(R)\setminus H\neq\emptyset
, we now bound
|S\Join R_{H}|
for any relation
S
. Lemma
4.13
tells us that
\deg_{R_{H}}(H\mid\textsf{vars}(S)\cap H)=O(p^{\sum_{i\in H\setminus\textsf{vars}(S)}v_{i}})
. Hence,
|S\Join R_{H}|=O(np^{\sum_{i\in H\setminus\textsf{vars}(S)}v_{i}})
. Using Lemma
4.18
, we obtain that the load for the semijoin operation is
\tilde{O}(n/p^{1-\sum_{i\in H\setminus\textsf{vars}(S)}v_{i}})
. To show the required bound, it suffices to prove that
\sum_{x\in H\setminus\textsf{vars}(S)}\mathbf{V}_{x}(\psi)\leq\kappa-1
. The key observation is that
S
is a guard, and thus from Lemma
4.12
,
\sum_{x\in\textsf{vars}(S)}\mathbf{V}_{x}(\psi)\geq 1
. Hence,

\sum_{x\in H\setminus\textsf{vars}(S)}\mathbf{V}_{x}(\psi)\leq\sum_{x}\mathbf{V}_{x}(\psi)-\sum_{\textsf{vars}(S)}\mathbf{V}_{x}(\psi)=\kappa-\sum_{\textsf{vars}(S)}\mathbf{V}_{x}(\psi)\leq\kappa-1.

Finally, we bound the load for the HyperCube phase. If
\textsf{vars}(R)\setminus H=\emptyset
, then
|R^{\dagger}|\leq|R_{H}|\leq O(p^{\sum_{i\in H}v_{i}})\leq O(p)
by Lemma
4.13
. This means that no matter how
R^{\dagger}
is partitioned by HyperCube, the load is lower than
n/p
.

If
\textsf{vars}(R)\setminus H\neq\emptyset
, consider
R^{\dagger}
from the semijoin phase. First, note that
|R^{\dagger}|\leq|S\Join R_{H}|=O(np^{\sum_{x\in H\setminus\textsf{vars}(S)}v_{x}})
from Lemma
4.13

\sum_{x\in\textsf{vars}(R^{\dagger})}v_{x}=\sum_{x\in\textsf{vars}(S)}v_{x}+\sum_{x\in H\setminus\textsf{vars}(S)}v_{x}\geq 1/\kappa+\sum_{x\in H\setminus\textsf{vars}(S)}v_{x}
.

Third, we will bound

for every subset

\displaystyle\deg_{R^{\dagger}}(U)

\displaystyle\leq\deg_{S\Join R_{H}}(U)\leq\deg_{S}(U\cap\textsf{vars}(S))\cdot\deg_{R_{H}}(U\setminus\textsf{vars}(S))

\displaystyle\leq\frac{n}{p^{\sum_{x\in U\cap\textsf{vars}(S)}v_{x}}}\cdot p^{\sum_{x\in H\setminus(U\setminus vars{S})}v_{x}}=\frac{np^{\sum_{x\in H\setminus\textsf{vars}(S)}v_{x}}}{p^{\sum_{x\in U}v_{x}}}

We now can get the desired load by applying Lemma
4.17
with
N=O(np^{\sum_{x\in H\setminus\textsf{vars}(S)}v_{x}})
.
∎

5.
Towards A Tight Lower Bound

In this section, we study the optimality of the
\tilde{O}(n/p^{1/\kappa})
load with respect to lower bounds.

We will restrict our attention to the class of
tuple-based MPC algorithms
, where we have to transmit tuples in their entirety. Tuples can be copied in each machine, and a machine is only allowed to output a tuple
t
if it has received all the tuples of the form
t[\textsf{vars}(R)]
, for every
R\in Q
. The restriction that only input tuples can be transmitted is not material: we can loosen this restriction and allow also transmitting intermediate tuples. These are the same within a constant factor in load, since when transmitting an intermediate tuple, we can always just transmit a set of input tuples that witness the intermediate tuple. We also note that all known MPC algorithm for joins (including
\kappa
-Join) can be captured by the tuple-based variant.

Prior work
(
17
)
has shown a straightforward
\Omega(n/p^{1/\rho^{*}})
lower bound for any join query. This immediately implies the following corollary.

Proposition 5.1.

Let
Q
be a query with hypergraph
\mathcal{H}
such that
\kappa(\mathcal{H})=\rho^{*}(\mathcal{H})
. Then, the
\kappa
-Join algorithm is optimal for
Q
within a polylogarithmic factor in the tuple-based model.

We have already seen two families of hypergraphs that have the above property: binary and acyclic hypergraphs (see Lemmas
and
3.7
). For Loomis-Whitney joins with
k
variables, their hypergraphs also satisfy the above property:
\kappa=\rho^{*}=k/(k-1)
. Below, we show a hypergraph from
(
1
)
where
\kappa
-Join achieves optimality and, to the best of our knowledge, no such algorithm was known before.

Example 0.

Consider the hypergraph
\mathcal{G}
with the following hyperedges:

\{a,b\},\{b,c,d,e\},\{b,e,f\},\{e,f,g\},\{g,h\},\{g,i\},\{h,i\}.

For this example, we have
\rho^{*}(\mathcal{G})=\kappa(\mathcal{G})=4
(the hypergraph
\mathcal{G}[a,c,d,f,h,i]
has
\tau^{*}=4
). Thus, the above proposition gives an optimal load of
\tilde{O}(n/p^{1/4})
.

A more involved lower bound that is higher than
\rho^{*}
was given in
(
11
)
for the class of boat queries
\mathcal{H}_{k}^{B}
,
k>0
, with hyperedges:

\{\{x_{1},x_{2},\dots,x_{k}\},\{y_{1},y_{2},\dots,y_{k}\},\{x_{1},y_{1}\},\{x_{2},y_{2}\},\dots,\{x_{k},y_{k}\}\}.

For this class of hypergraphs, the lower bound shown is
\Omega(n/p^{1/k})
. Note that
\kappa(\mathcal{H}_{k}^{B})=\psi^{*}(\mathcal{H}_{k}^{B})=\tau^{*}(\mathcal{H}_{k}^{B})=k
(but
\rho^{*}=2
), hence the lower bound can be matched even by a 1-round MPC algorithm.

We show next how to extend the above lower bound to the family of hypergraphs
\mathcal{H}_{k}^{\dagger}
. For this, we need the following general observation.

Lemma 5.3.

Let
\mathcal{H}=(V,E)
be a hypergraph, and
S\subseteq V
. If
\textsf{red}(\mathcal{H}[S])
admits a lower bound of
\Omega(n/p^{\epsilon})
, then
\mathcal{H}
also admits the same lower bound.

Observe that
\mathcal{H}_{k}^{B}=\mathcal{H}_{k}^{\dagger}[V\setminus\{z\}]
. Thus, the
\Omega(n/p^{1/k})
lower bound transfers to
\mathcal{H}_{k}^{\dagger}
, showing that
\kappa
-Join is optimal for this family of queries as well. Together with Proposition
3.10
, this proves that the worst-case optimal load for join queries cannot be characterized as
n/p^{1/\max\{\tau^{*},\rho^{*}\}}
.

Candidate Lower Bound

We now describe a concrete direction towards constructing a matching lower bound. Recall that
\kappa(\mathcal{H})=\max_{S\subseteq V}\tau^{*}(\textsf{red}(\mathcal{H}[S]))
. Applying Lemma
5.3
, it would suffice to prove a
\Omega(n/p^{1/\tau^{*}})
lower bound for every reduced hypergraph.

Conjecture 5.4.

Let
\mathcal{H}
be a hypergraph s.t.
\mathcal{H}=\textsf{red}(\mathcal{H})
. Then, there exists a query
Q
with hypergraph
\mathcal{H}
and input size
n
s.t. any tuple-based algorithm needs load
\Omega(n/p^{1/\tau^{*}})
to compute
Q
.

Proving this conjecture would immediately give a matching
\Omega(n/p^{1/\kappa})
lower bound. We should note here that the requirement that
\mathcal{H}
is reduced is critical; for instance, the conjecture fails for the non-reduced hypergraph with hyperedges
\{x\},\{x,y\},\{y\}
, for which there is an MPC algorithm with load
\tilde{O}(n/p)
.

Although we could not prove the conjecture, we describe below a candidate family of hard instances. For a query with (reduced) hypergraph
\mathcal{H}=(V,E)
, let
\mathbf{v}
be a minimum fractional vertex cover, which has total weight
\tau^{*}
. A
sparse product query
is defined as follows:

•

For a variable
x\in V
, define
N_{x}=\{1,\dots,n^{v_{x}}\}
.

•

For relation
R
, include each tuple in the cross product
\bigtimes_{x\in\textsf{vars}(R)}N_{x}
independently with probability

P_{R}=n^{1-\sum_{x\in\textsf{vars}(R)}v_{x}}.

We call a relation
R
where
P_{R}<1
as
sparse
, and if
P_{R}=1
as
dense
. Note that with high probability, every relation has size
O(n)
.
Additionally, the expected output of the query is
n^{\tau^{*}}\prod_{R\in Q}P_{R}
. Finally, if we consider a machine that receives
L
tuples at most from each relation, then we show in Appendix
F
that the expected number of outputs it can produce is
L^{\tau^{*}}\prod_{R\in Q}P_{R}
.

The above in-expectation bounds do not suffice to prove the desired lower bound. Instead, we would want them to hold with enough high probability such that there is a non-zero probability of the existence of an instance of sparse relations such that for every possible combination of
L
tuples a machine can produce
O(L^{\tau^{*}}\prod_{R\in Q}P_{R})
results. We leave that as an open problem, that, if resolved, would prove the desired matching lower bound. Specifically, we present in Appendix
C
a concrete hypergraph for which we do not know how to prove the desired lower bound using the aforementioned sparse product construction.

6.
Conclusion

In this paper, we presented a new algorithm,
\kappa
-Join, for computing join queries in the MPC model with load
n/p^{1/\kappa}
. The algorithm improves upon previous results and is relatively simple. It remains an open problem whether this upper bound is tight, or if there exists another algorithm that can achieve a better load.

Consider any query

\mathcal{H}

\tau^{*}(\textsf{red}(\mathcal{H}[S]))
. Consider a database instance where all variables outside
S

are heavy.

v

Appendix F

Lemma F.1.

For a query
Q
, let
\mathbf{v}^{*}
be an optimal solution to the following linear program.

(2)

\displaystyle\min_{\mathbf{v}}\sum_{x\in\textsf{vars}(Q)}v_{x}

\displaystyle s.t.\quad\forall R\in Q:

\displaystyle\sum_{x\in R}v_{x}\geq 1

\displaystyle\forall x:

\displaystyle v_{x}\geq 0

Consider now the following linear program

(3)

\displaystyle\max_{\psi}\sum_{x\in\textsf{vars}(Q)}\psi_{x}

\displaystyle s.t.\quad\forall R\text{ where }\sum_{x\in R}v_{x}=1:

\displaystyle\sum_{x\in R}\psi_{x}\leq 1

\displaystyle\forall x|v_{x}=0:

\displaystyle\psi_{x}\leq 0

\displaystyle\forall x:

\displaystyle\psi_{x}\geq 0

Then, the optimal solution
\mathbf{v}^{*}
in the first LP is also optimal in the second LP.

Proof.

\mathbf{v}^{*}
is feasible in LP
3
since LP
3
does not have a constraint
\sum_{x\in R}\psi_{x}\leq 1
for
x
where
\sum_{x\in R}v_{x}>1
.

Suppose for contradiction that
\mathbf{v}^{*}
is not optimal in LP
3
. Then, there exist a vector
\Delta
such that
\mathbf{v}^{*}+\Delta
is a better solution.

We claim that then, for some
\epsilon>0
,
\mathbf{v}^{*}-\epsilon\Delta
is a solution to LP
2
. To show this, we will argue that all constraints are satisfied. First, for any
R
where LP
2
has a tight constraint,
\sum_{x\in R}\Delta_{x}\leq 0
, so the corresponding constraint in LP
2
is satisfied. For any
R
such the constraint in LP
2
is slack, then there exists an
\epsilon
such that
\sum_{x\in R}(v_{x}-\epsilon\Delta_{x})\geq 1
.

Lastly, we argue that the constraints
v_{x}\geq 0
are satisfied, even if
\Delta_{x}\geq 0
. We know that if
v_{x}=0
, then
\Delta_{x}=0
. If
v_{x}>0
, then we can pick
\epsilon
sufficiently small such that
v_{x}-\epsilon\Delta_{x}\geq 0
.

Notice that
\mathbf{v}^{*}-\epsilon\Delta
is a lower vertex cover than
\mathbf{v}^{*}
. This is a contradiction, since
\mathbf{v}^{*}
was picked because it is the smallest vertex cover.
∎

Lemma F.2.

Let
Q
be a sparse product query with a reduced hypergraph
\mathcal{H}
.
Consider a machine which is permitted to load
L
tuples from each relation.
Then, in expectation (over the randomness of the sparse relations) the number of tuples the machine will produce is at most

L^{\tau^{*}(\mathcal{H})}\prod_{R\in Q}P_{R}

Proof.

For each of the deterministic relations, we can load at most
L
tuples.
This means that the maximal number of output tuples that can be produced is given by

\displaystyle\max_{\Psi}\prod_{x\in\textsf{vars}(Q)}\Psi_{x}

\displaystyle s.t.\quad

\displaystyle\forall R|\sum_{x\in R}v_{x}=1:\prod_{x\in R}\Psi_{i}\leq L

\displaystyle\forall x:\Psi_{x}\leq n^{v_{x}}

By taking the logarithm with base
L
, we get the following linear program, which is a vertex packing problem

\displaystyle\max_{\psi}\sum_{x\in\textsf{vars}(Q)}\psi_{x}

\displaystyle s.t.\quad

\displaystyle\forall R\text{ where }\sum_{x\in R}v_{x}=1:\sum_{x\in R}\psi_{x}\leq 1

\displaystyle\forall x:\psi_{x}\leq v_{x}\log_{L}n

Note that
\log_{L}n>1
since
L<n
. Instead of the last constraint, we will have the constraint
\forall x|v_{x}=0:\psi_{x}\leq 0
. The LP obtained by changing the constraints in this way keeps all feasible solutions feasible, but makes some infeasible points feasible. This means that if we can prove that the new LP satisfies the bound, so does the original LP.

We now apply Lemma
F.1
, which gives that the above optimization problem has optimal solution
L^{\tau^{*}}
. We obtain the desired result by summing over the expectation that any tuple formed by the dense relations survives to the ouput, which is
\Pi_{R}P_{R}
.
∎
