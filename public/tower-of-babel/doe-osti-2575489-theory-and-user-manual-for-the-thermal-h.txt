 ABSTRACT
 A theory and user manual of thermal hydraulic code SE2-ANL was prepared in this work, to
resolve the missing documentation. SE2-ANL, a special version of SUPERENERGY-2, is a multi-
assembly steady-state Liquid Metal Reactor (LMR) core thermal hydraulic analysis code, and it
was developed in the 1980s, but no complete documentation was ever made. This report describes
the detailed methodology of the temperature calculation, inherited from (original)
SUPERENERGY-2, and fuel and cladding temperature calculation capabilities as well as many
other features which were incorporated in SE2-ANL. The input and output of SE2-ANL are also
demonstrated in detail, using some simple models. The orificing zone capability as well as some
other useful features of SE2-ANL are discussed.

1. Introduction
 SE2-ANL[1] is a steady state thermal hydraulics analysis code that was developed by interfacing
the multi-assembly, steady-state Liquid Metal Reactor (LMR) code SUPERENERGY-2 [2] with
the heating calculations performed with the Argonne National Laboratory (ANL) reactor physics
codes. SUPERENERGY-2 is a multi-assembly, steady-state analysis code based on the subchannel
methodology. For a given power and flow distribution, it can calculate core-wide coolant
temperature profiles where the primary geometric assumption is that the domain consists of a
hexagonal array of ducted assemblies that limit fluid based interassembly heat transfer. It obtains a
solution efficiently by disposing of all but the temperature equation in the Navier-Stokes (NS) fluid
dynamics modeling system of equations. The temperature equation is modified to incorporate two
correlated parameters to account for the mixing of power between adjacent subchannels:
dimensionless (enhanced) eddy diffusivity of heat and ratio of transverse velocity in the bundle
periohery to the average axial velocity in that region. SUPERENERGY-2 can compute problems
as small as a single fuel bundle up to a full core hexagonal reactor with thousands of ducted
assemblies. Its main purpose is to compute the steady state domain coolant temperature distribution
with interassembly heat transfer such that peak coolant temperatures can be identified for use as
constraints on the orifice design process.
 The SUPERENERGY-2 code has user inputs for the power distribution which for each assembly,
consists of an axial power profile and a radial power profile. At ANL, a special version of
SUPERENERGY-2 was developed, named SE2-ANL, which interfaces the SUPERENERGY-2
code with the heating calculations performed using the DIF3D/REBUS/GAMSOR [3, 4] based
upon the DIF3D-FD solver [3]. Thus, for SE2-ANL, the power profiles and core layout required
as part of the SUPERENERGY-2 input are obtained using data from the DIF3D model. This avoids
the user having to prepare the complicated SUPERENERGY-2 input manually and thus reduces
the source of errors. In addition, the SUPERENERGY-2 code was altered to include fuel and
cladding temperature models as well as reactor hot spot analysis method [15]. With these latter
capabilities, SE2-ANL can be used to assess peak temperatures for both the nominal and two-sigma
temperatures of the fuel and cladding. These peak temperatures are taken as the main constraints
on design and operations for the reactor system.
 The SUPERENERGY-2 code was first released in 1980 [2] and was developed over the
preceding 10 year period as part of the Clinch River Breeder Reactor project. The SE2-ANL
software was developed in the early 1980s with the last significant modifications occuring in the
late 1990s. While the SUPERENERGY-2 manual does detail the methodology and equations, they
have typos and the figures and equations were prepared with old documentation tools such that they
are hard to understand today. No documentation was ever created for SE2-ANL and only sparse
internal ANL memos exist that indicate what work was ever done on it or to create it. The focus
of this manuscript is to provide the complete documentation of the SE2-ANL code, covering both
the methodology and acting as the user manual. In this report Section 2 and 3 describe the features

and methodology of SUPERENERGY-2, while Section 4 introduces the new capabilities added in
SE2-ANL. Section 5 and 6 detail the input and output specification of SE2-ANL.

2. Code Overview of SUPERENERGY-2
 The SUPERENERGY-2 [2] code used in SE2-ANL was originally released in 1980 and the
version delivered to Argonne National Laboratory had fixed dimension arrays. In the early 1990s,
after it was interfaced as SE2-ANL, those hard wired dimensioned arrays were replaced with the
BPOINTER infrastructure available in the Argonne Reactor Code (ARC) system. Currently, SE2-
ANL is an easily redimensionable, multiassembly code with many user convenience features that
help minimize the effort and time associated with setting up large problems. SE2-ANL
automatically generates the geometry and subchannel meshing for a given number of single- or
double-ducted assembly types based upon a few critical dimensions. Radial meshing options
include either a standard fine-meshed subchannel layout based on the number of fuel pins or a
lumped representation of one to eight rings formed at the user's request. The latter of these is not
available through the SE2-ANL interface. To account for interassembly heat transfer, either a
conduction assumption (stagnant bypass) or a bypass flow rate in the interassembly gap can be
modeled. Generalized boundary conditions can be applied to the noncoupled bundle faces. Power
is generally assumed to only be delivered to the array of pins in the pin lattice but there is an input
option to deliver power to the duct wall in each assembly.
 SUPERENERGY-2 has input checking to minimize input errors and assure the validity of the
code output, but they are incomplete such that it will easily allow the user to provide non-physical
geometries where the array of pins intersect the duct wall. The limit on non physical geometries is
typically accompanied by a invalid floating calculation and infinity outputs. SE2-ANL has built in
sodium and stainless steel property correlations, mixing parameter correlations, flowsplit
correlations, and heat transfer correlations, all of which can all be controlled via the regular input.
There is no verification history of any of these correlations, and no indication that they were ever
consistent with the reference documents although there is no reason to believe they are implemented
incorrectly. The output includes a listing of the input provided to SUPERENERGY-2 which
provides a means of verifying the input. Because the SUPERENERGY-2 methodology is built on
assuming that all assemblies are in a forced convective flow regime, a critical modified Grashoff
number output is provided to indicate to the user whether the model provided to SE2-ANL is
invalid. The code-calculated bundle temperature profiles are displayed in map form for easy reading
at user-specified axial locations. Each planer output is followed by an energy balance output table.
 SUPERENERGY-2 is applicable to steady-state forced-convection problems consisting of
bundles with standard pin geometries. It is not a benchmark code and should not be assumed as
such. Off-normal geometry calculations will provide questionable results since the accuracy of the
output depends strongly on the experimentally determined mixing parameters.

2.1 Geometry and Noding Generation
 The SUPERENERGY-2 code can compute the temperature distributions in a full core that
contain single-ducted and double ducted (control) assemblies with wire-wrapped fuel pins. The
physical geometry is broken into subchannels as shown in Error! Reference source not found..
In Error! Reference source not found., the left-hand picture is a single ducted assembly while the
right-hand one is a double ducted assembly, and the coolant region (blue) is broken into distinct
meshes. Both assembly types assume a central wire-wrapped fuel pin bundle surrounded by a
hexagonal duct (can). The double ducted assemblies are designed to allow the inner duct and pin
bundle to move axially and thus there is a small bypass gap region sandwiched between the two
ducts. The SUPERENERGY-2 input can contain any number of these two major duct types, the
quantity limited only by the code dimensions. The variations may include different bundle
dimensions, noding or pin numbers. SUPERENERGY-2 generates the noding, connection logic
and geometry for the different assembly types based on a few critical input parameters. These are
the pin pitch, pin diameter, wire-wrap lead length, wire wrap diameter, duct flat-to-flat distance,
duct wall thickness, and number of fuel pin rings. If the assembly is double ducted, the gap
thickness between the ducts and interior duct thickness are also necessary.

 Figure 2.1. Subchannel Definition for a 7-pin assembly

 The region within the innermost duct, in which the pin bundle is located, is referred to hereafter
as the assembly internal. Three types of coolant subchannels are present in the assembly interior:
   Type 1 : The interior subchannels adjacent to three pins and is only connected to three other
 subchannels with only two distinct connection types (either to an interior or edge
 subchannel).

   Type 2 : The edge subchannels located between pins adjacent to the duct wall. Each edge
 subchannel mesh is always connected to three subchannels with three possible
 configurations: 1) two edge and one interior channel; 2) one edge, one corner, and one
 interior channel; and 3) two corner and one interior channel.
   Type 3 : The corner subchannels only connects to a single pin adjacent to two duct walls. The
 corner subchannel does not connect to interior subchannels but can beconnected to 1) two
 edge subchannels (in assemblies with 7 or more pins) or 2) two corner subchannels (single

the interior except there are only edge and corner subchannels as seen in Error! Reference source

as one moves outward from the assembly interior.
 For a given bundle type, the subchannel setup is similar such that the interior subchannels are
numbered sequentially in a counter-clockwise outward spiral starting with the two o'clock node
neighboring the center pin. Next, the edge subchannels are numbered followed by the corner
subchannels in the same counter-clockwise pattern. The duct wall subchannels, duct bypass gap
subchannels, and interassembly gap subchannels are numbered similarly to the edge and corner
subchannels. An example of a subchannel noding scheme is shown for a 61-pin assembly in the
left-hand picture of Figure 2.2. If the bundle is a double-ducted bypass (37-pin) bundle, the noding
is extended to include two more layers of subchannels as shown then in right-hand picture of Figure
2.2. For both of the two figures in Figure 2.2, pink is used for the pins, yellow for the coolant, blue
for the duct and green for the duct and assembly bypass coolant gap.
 The noding configuration is determined internally by the value of NRING for each bundle type,
which defines the number of pin rings in the bundle. The user provides the number of pins in each
bundle in the input which must equate to 3·NRING·(NRING-1)+1 (=1, 7, 19, 37, 61, 91, 127, 169,
217, 271, …). If the number of pins and rings do not match, SE2-ANL will not fail but give
undesirable results.
 SUPERENERGY-2 also has an user input option to use a lumped mesh which allows the user
the option of using coarse meshes in bundles where fine detail are not necessary. The lumped mesh
option was developed in 1980s, when computer resources were much more limited than today and
thus this can save both computational time and memory. To use this option requires specific input
of linear heat generation rates (W/m) in the SUPERENERGY-2 input which is not supported as
part of the SE2-ANL interface.

2.2 Interassembly Heat Transfer and Facial Boundary Conditions
 One very important feature of the original SUPERENERGY code was its ability to couple
assemblies and allow interassembly heat transfer with only minimal user input. The other aspect
was truncating the system of equations to yield a fast running lower triangular sweeping algorithm
over the whole domain, the accuracy of which is limited by the axial mesh size (and whether the
assumptions about flow rates are valid). These features were retained and generalized in
SUPERENERGY-2 which includes two separate interassembly heat transfer models, generalized
boundary conditions on the noncoupled faces, a method of coupling neighboring assemblies with
inconsistent subchannel meshing, and a less restrictive interassembly gap subchannel meshing
scheme.
 The work done with SUPERENERGY indicated that the interassembly gap was the primary
restriction for solution stability (axial mesh size must be constrained to avoid divergence). This
restriction is directly tied to the mesh size and flow rate both of which are small in the bypass gap.
SUPERENERGY-2 resolved this limitation in two ways:
  1) In SUPERENERGY, the assembly bypass gap between assemblies was split in half consistent
 with the assembly pitch. In SUPERENERGY-2, the subchannel mesh was altered to eliminate
 the artificial split on the assembly pitch leading to larger meshes.

                                                   9                                ANL/NSE-25/44

  2) The gap can be treated assuming stagnant sodium. To do this, the connection between
 adjacent assemblies is handled by using a simple conductive resistance connection to the
 adjacent assembly coolant channels rather than to the assembly duct wall, then bypass gap.
 This eliminates the stability constraint from the interassembly gap (and duct wall regions)
 since the temperatures are calculated after the edge and corner interior subchannel
 temperatures are known.
 The bypass gap flow rate is typically designed to be less than 5% of the total flow rate with a
desired flow rate less than 1%. This amount of flow, spread out over the entire core, accounts for a
small fraction of the energy removal from the reactor. Because stagnant flow is an unrealistic design
outcome, using the stagnant model is inadvisable although it typically gives a solution very similar
to a bypass gap model with a low flow rate. Because SE2-ANL does not have a means to
automatically compute the bypass flow rate, one can use the stagnant model for the initial work
and, given SE2-ANL will detail the total flow rate for a given model, one can then compute the
area of the bypass gap and the leakage loss flow rate (i.e. 1% of the total flow rate) to determine
the bypass gap flow rate input to SE2-ANL.
 SUPERENERGY-2 allows neighboring assemblies with different subchannel meshing to be
coupled. This mismatch occurs when the adjacent assemblies have a different number of pin rings
or simply a different pin pitch. When this occurs, SUPERENERGY-2 performs an interpolative
averaging technique to project (coarse mesh to fine mesh) or restrict (fine mesh to coarse mesh) the
temperature solution between adjacent assemblies. The averaging must be done on each surface
with every axial mesh solved. Any energy error resulting from this interpolation procedure shows
up in the energy balance summary that accompanies the temperature map output at each printout
location. Usually the error introduced is small (less than 2%) because of the relatively flat facial
temperature profiles in most problems.

 An option to deposit some of the power to the duct wall is available when the flowing bypass
gap model is used. The power is specified for each surface using radial and axial volumetric heat
generation rate multipliers. This can be important in low-power assemblies when the distribution
of power from gamma heating is high. Gamma energy deposition in the coolant can be simulated
by increasing the radial power factor to include the desired effects.

 For the domain surfaces (those assembly faces ajacent to the core barrel), the user can specify
a radial and axial varying heat flux or a temperature boundary condition. In SUPERENERGY-2,
the boundary condition type, heat flux or temperature, is specified by assembly and the axial and
radial forcing function profiles are specified by surface. These are applied at the duct wall when
the conduction model has been specified or at the opposite face of the interassembly gap in the case
of the flowing gap model. A summary of the available boundary conditions (B.C.) is shown in
Table 2.1. It should be pointed out that not all options of SUPERENERGY-2 work with the SE2-
ANL interface, and SE2-ANL by default will set a zero heat flux on all domain surfaces.

2.3 User Convenience Features
 The input to SUPERENERGY-2 is set up to minimize the required user input in some sense
with respect to geometry construction. There are some checks done on the user input to ensure the
problem is valid but those checks are not complete which are described in the following subsections.

2.3.1 Modified Grashoff Criteria

 The SUPERENERGY-2 solution methodology is only applicable to forced convection flow
regimes. For most cases, the transition to mixed convection occurs at flow rates well below those
of interest for fuel assemblies in a powered reactor. For shield and control assemblies, this is not
the case and mixed convection flow can occur although its impacts are typically negligible. It is
possible that a derated power reactor can have an assembly with a severe enough power skew and
low flow that buoyancy effects are important. In the SE2-ANL, this limit was considered a hard
limit and the code would abort with an error message but that approach was eliminated at some
point as the types of reactors being studied would routinely report issues and not provide a solution.

further work should be done on a specific assembly geometry to confirm that 0.025 is appropriate
for all assemblies. That work was never completed of course.

consistent with a commercial power reactor (i.e. greater than 100 MWt and not 2 MWt). For shield

peripheral assemblies along the core barrel, greater than 2.0. As stated, it is not clear what the true
impact is on accuracy for these assemblies nor is it well documented how 0.02 was chosen as the

2.3.2 Mixing Parameters
 SUPERENERGY-2 uses two mixing parameters to account for intra-assembly mixing: eddy
diffusivity and swirl velocity. The first models the wire wrap sweeping effects. The second is the
superficial peripheral swirl flow velocity. Assuming this swirl flow to be independent of the wire
wrap position has been shown to induce little error by Basehore and Todreas [6].
 The mixing parameters were first correlated as a function of geometry by Khan [5] using the
bundle average velocity as a nondimensionalizing parameter. These correlations provided the basis
for the original SUPERENERGY model input. Later the mixing parameters were recorrelated by
Chiu, Rohsenow and Todreas [7], based on an expanded database of experimental data, using the
local subchannel velocity as a nondimensionalizing parameter, which made the resulting correlation
independent of bundle size. The range of the correlations was extended into the blanket bundle
region. These correlations are for mixing parameters built into SUPERENERGY-2 but they lack a
good open literature reference. The correlations for eddy diffusivity and swirl velocity are shown
in Equations 2.5 and 2.6, respectively.

2.3.4 Stability Limited Axial Noding
 Because of the formulation, the computational time required for a given SUPERENERGY-2
problem is directly proportional to the number of axial meshes used in the problem (there is only a
single radial mesh allowed in the domain). A problem-dependent, maximum axial mesh size is
needed to assure a non divergent solution of the temperature equations. The user can provide a
mesh size as part of the input, but SUPERENERGY-2 calculates the maximum mesh size required
to guarantee convergence and will replace the user value (or abort) if it is inappropriate. This
calculation is done before the temperature solution is initated using the relationships shown in
Section 3 of this report.

4. Pin Power and Temperature Calculation
 As discussed, the SE2-ANL code is a modified version of the SUPERENERGY-2 code, which
was interfaced with the heating calculation in GAMSOR. (The standalone SUPERENERGY-2
code takes the power distribution as user input (magnitude and spatial profiles). In SE2-ANL, a
reactor hot spot analysis methodology was added along with fuel and cladding temperature
calculation models. An orificing scheme was also incorporated to determine coolant flow rates that
yield a desired peak temperature distribution. This section briefly describes the methodology and
heating (pin power) and pin temperature calculations.
  The heat generation rate in SUPERENERGY-2 is a combination of radial and axial power
profiles for each assembly [13]. SE2-ANL only accepts DIF3D-FD outputs for the triangular mesh
option with six triangles per hexagon. The neutron and gamma flux solutions from DIF3D must be
provided to SE2-ANL along with the geometry (GEODST), composition (NDXSRF, LABELS,
ZNATDN) and cross section data (PMATRX) in order to compute the radial and axial power
profiles needed by SUPERENERGY-2 for the temperature calculation.

4.1 Pin Power Calculation
 The DIF3D calculations can be three-dimensional full core, 60 degree periodic, and 120 degree
periodic models. The mesh wise output from each of these changes (60 degree periodic will only
provide a single triangular mesh for the central assembly while full core will provide 6 triangular
meshes). The 60 degree and 120 degree periodic options were set up because of the computational
time required to get REBUS to complete a depletion calculation in the past. Because of swirl flow,
the temperature distribution is neither 60 or 120 degree periodic and thus it is inadvisable to use
those options. Today it is recommended to exclusively use full core models as the REBUS,
GAMSOR, and SE2-ANL steps all can be completed very quickly (less than 1 hour). As a
consequence, only the full core pin power calculation is discussed here.
 Given the DIF3D calculated triangular mesh neutron and gamma flux solutions, the mesh-wise
power density for the neutron and gamma components are computed in SE2-ANL. The axial profile
is obtained by averaging the neutron+gamma power density of all six triangular meshes at each
axial (DIF3D) mesh.
 To reconstruct the pin power within a hexagonal assembly, SE2-ANL needs to reconstruct
neutron and gamma flux at each pin location. For each axial (DIF3D) mesh of each assembly, the
radial (neutron or gamma) flux is approximated for each energy group by a 2 nd order set of
monomials (1, x, y, x2, y2, x·y). The coefficients are determined by a least squares fit of the mesh-
wise fluxes and because six data points is insufficient SE2-ANL uses the flux solution from the
meshes adjacent to each fuel assembly. Figure 4.1 shows how the surrounding 18 triangular meshes
are included in the least squares fit. It is important that the fit corresponds to the flux and not the
power distribution as the latter can be disjoint at the assembly interface.

                                                  43                                 ANL/NSE-25/44

 SE2-ANL assumes the flux solution is smooth and after obtaining the 2 nd order fit, it reconstructs
the pin flux solution by evaluating the 2nd order fit at the center coordinates of each pin and converts
that to power corresponding to the axial DIF3D mesh being worked upon. That process is repeated
for every axial DIF3D mesh and the calculated pin powers are averaged to come up with a single
radial profile for each assembly. The power distribution is normalized such that the radial pin power
value is ~1.0 (a flat radial power profile would have 1.0 for all pins).

4.2 Fuel and Clad Temperature Calculation
 After the coolant temperature calculation is done in SE2-ANL for a given axial mesh, SE2-
ANL will compute the clad and fuel temperatures [13]. Both nominal and hot-channel factor based
two-sigma temperatures are calculated for the clad and fuel. Six coolant subchannels surround each
fuel pin in the interior region and five coolant subchannels for fuel pins that lie along the duct wall.
The procedure in SE2-ANL does not calculate the clad and fuel temperatures corresponding to a
real pin and instead calculates it for each interior coolant subchannel assuming that coolant
subchannel completely surrounds a fuel pin. The power for each interior subchannel is calculated
in SE2-ANL as 1/6th of the power of three pins connected to that subchannel. Assuming that each
interior coolant subchannel completely envelopes a fuel pin would result in the power of that pin
being ~2 times the power of the interior subchannel, as shown in equation (4.6. Because the pin
compositions are assumed to be identical in the assembly, using this approach does not constitute
a large error in the clad and fuel temperature calculation.
 The nominal clad and fuel temperature are calculated using a steady state one-dimensional
conduction model. For metallic fuel, the fuel thermal conductivity is assumed to be a 2 nd order
polynomial expansion with respect to temperature and a correlation taken from the IFR Metallic
Fuels Handbook [14] is built into SE2-ANL to provide this fit. This correlation represents the
thermal conductivity as a function of temperature, weight fractions of zirconium and plutonium,
and porosity. The clad thermal conductivity is assumed to be a linear function of temperature, and
correlations are built into SE2-ANL for SS316, D9, and HT9. Standard correlations for the
cladding-to-coolant heat transfer coefficients based upon the Nusselt number are included in SE2-
ANL.

 The two-sigma temperatures are calculated using the semi-statistical method described in
reference [15]. These temperature data are edited by the code for the peak two-sigma cladding
mid-wall temperature and peak two-sigma fuel centerline temperature. For the cladding
temperature calculation, the horizontal and vertical methods are available where the horizontal
method was recommended in reference [15]. In the vertical method the two-sigma temperatures
are calculated as specified in the conceptual design study ground rules outlined in reference [16].
This method employs four combined hot channel factors for the axial coolant, film, and cladding
temperature rises and the heat flux variation. These hot channel factors are supplied by the user.
Ortherwise, the CDS driver and blanket hot channel factors are used as default values. In the
horizontal method, on the other hand, the two-sigma temperatures are calculated as described in
CRBRP-ARD-0500 [17] using hot channel subfactors. Eleven direct and thirteen statistical
subfactors are available for the coolant, film, and cladding temperature rise. Two sets of hot channel
subfactors taken from the CRBRP driver and blanket assemblies are available in the code as the
default values. The hot channel subfactors for the peak cladding midwall temperature calculation
can be overridden by the user.
 For the fuel centerline temperature, only the horizontal method is available. Eleven direct and
fifteen statistical subfactors are used for the coolant, film, and cladding temperature rise. Two sets

of hot channel subfactors taken from the CRBRP driver and blanket assemblies are available in the
code. These subfactors are hard-wired for metal fuel and cannot be overridden by the user via the
input. The coolant, film, and cladding factors can be overridden by the user via the A.THINP input
for SE2-ANL.
 The nominal operation of a fast reactor requires the operating details to ensure fuel pin integrity.
This means the operating conditions will prevent the fuel from melting and the coolant from boiling
for normal operations and adequte safety margins are built in to handle various accident scenarios.
As cladding damage is the primary path to result in loss of fuel containment within the fuel pin (the
first safety barrier), it is typically the most limiting operational parameter. Given this, an automatic
orificing scheme was incorporated into SE2-ANL that determines the necessary coolant flow rates
that yield a peak 2-sigma cladding midwall temperature in each fueled orificing zone that is the
same. This typically means that the temperature rise on those orifices can be different and because
the power generated by each assembly is different the temperature rise on each assembly within an
orifice can be different. For a given total domain flow rate, the equalization of peak two-sigma
cladding midwall temperatures should result in the lowest peak two-sigma cladding midwall
temperature. The present orificing scheme solves the system of nonlinear equations representing
the equalization of peak two-sigma cladding midwall temperatures of individual orificing zones,
with the conservation of the total flow rate. It should be noted that this is applied to a single time
point in SE2-ANL and that SE2-ANL does not consider all time points in the fuel cycle operation.
Because there is no hard limit applied to the peak 2-sigma temperature in SE2-ANL when
determining the orifice flow rate assignment, when such a limit is applied, the entire reactor may
have to be derated (decreased nominal power level) if the 2-sigma temperature is violated.

5. Input Specification of SE2-ANL
 The input of SE2-ANL consists of two parts: 1) SUPERENERGY-2 like input and 2) pin details
and DIF3D interfacing setup. The first part of the input is provided via the A.SE2ANL input block
and specifies just part of the original SUPERENERGY-2 input. This input exactly follows the input
format of the standalone SUPERENERGY-2, but eliminates many of the later input lines. This
input also includes an optional block of input appended to the end which defines the assembly flow
rate. The second part of the input is provided via the A.THINP input and contains the SE2-ANL
input that was not originally included in SUPERENERGY-2.
  It should be noted that all the SE2-ANL inputs require the user to use British engineering units.
This means that all of the output is forced to be in British engineering units. Internally,
SUPERENERGY-2 is built on international engineering (SI) units and it simply does the input and
output conversions internally.

5.1 Truncated Input for SUPERENERGY-2
 The input for SUPERENERGY-2 is arranged into four functional groups which are detailed here
in Table 5.1 to Table 5.4. The first group is covered by Table 5.1 and is called “General Input Data.”
As seen, it consists of 9 sections of input and allows the user to select the basic model options,
output options, and interassembly gap model. The second group is given in Table 5.2 and is called
“Bundle type data.” This section of input allows the user to define the bundle geometry and consists
of 5 sections of input, some of which repeat for each bundle type. This group is where pin geometry,
dimensions and correlations are selected by the user.
 The third group is given in Table 5.3 and is called “Forcing Functions and Profiles.” This input
consists of 8 sections of input and allows the user to define the various axial and radial forcing
functions and mixing parameter profiles. The fourth group of input is given in Table 5.4 and is
called “Bundle Specific Data.” This section of input consists of 9 parts and allows the user to assign
parts of the second and third groups to specific assemblies and specify operating conditions such
as boundary conditions.
 In SE2-ANL, the input for group 3 and 4 are automatically filled in by the interface routine. In
effect, the interface routine takes the user A.SE2ANL input and generates a complete
SUPERENERGY-2 input called SE2OUT at run time. In SE2OUT, the group 2 input data is
slightly different from the defined SUPERENERGY-2 in A.SE2ANL as it includes additional
A.THINP input corresponding to the fuel pellet conductivity. Because SUPERENERGY-2 is a
subroutine in SE2-ANL, it is called and simply reads in SE2OUT as it would originally as a separate
functional code. It should be clear that only some of the setup options are available through the
SE2-ANL input. One particular problem is that the SE2-ANL interface only works with English

5.2 Orificing Flow Rate
 An optional input block can be added at the end of A.SE2ANL to provide the orifice coolant
flow rate of each assembly. If this block is missing, SE2-ANL will apply the built-in orifice scheme
to determine the coolant flow rate that yields a equalized peak two-sigma cladding midwall
temperature in each fueled orifice zone. It is noted that for a given total flow rate, the equalization
of peak two-sigma cladding midwall temperatures should result in the lowest peak two-sigma
cladding midwall temperature.
 A simple model was created to demonstrate the SE2-ANL input. The radial configuration of the
model is shown in Figure 5.3. As seen, this model has three assembly types and 19 total assemblies.
The driver assemblies were set up to contain 19 and 37 fuel rods while a double ducted control rod
assembly with 7 rods was also included for completeness. The active length of this sample model
is 180 cm, and the total thermal power is 30 MW. It is noted that a GAMSOR calculation was
executed to provide the necessary DIF3D interface files needed to run SE2-ANL.

It is noted that this defines an overconstrained geometry as the assembly pitch is available in the
GEODST file and the gap thickness between assemblies earlier was sufficient to deduce the outer
duct flat-to-flat distance for every assembly. There is no real input checking and this is the first spot
where the SE2-ANL input can be defined inconsistently. The next real value of 0.6 corresponds to
the clad outer diameter (inches) and the two values 0.0984 and 0.0984 specify the wire wrap
diameter (inches) in the interior and that of the pins adjacent to the inner duct wall. The last real
value of 1.1 corresponds to the shaping factor and is an arbitrary multiplier applied to the coolant
conductivity connection between assemblies. The correlated value of mixing is added to the simple
coolant conductivity connection. There is no input checking on the shaping factor and completely
unrealistic values of 1010 can be specified as an example. There is also no input checking on whether
the thickness of the wire wrap can fit between the cladding or within the duct wall or that the pin
lattice can fit within the duct. In many cases the code will run and produce erroneous results and
other cases it will die with invalid floating point operations (square root of negative numbers or
1/0).
 The first example INPUT 2.5 input contains two integer values of 0 and -1 and are used to select
the correlations. The first input value of 0 will select the MIT correlation for mixing that is included
in SE2-ANL and all other options are not known to work. The second input value of -1 will select
the MIT correlation for flow split while the option 0 will select the NOVENSTERN correlation.

 The card type 03 input allows the user to map the assembly types from A.SE2ANL to the
GAMSOR model. As stated earlier, the zone names at plane 30 will be used. The first card 03 input
provides an integer value of 1 followed by the label MICORE. The 1 indicates that assembly type

  The card type 04 input specifies five real numbers of 671.0, 950.0, 0.0, 1.0, and 1.0. The first
value of 671.0 is the inlet temperature in Farenheit. The second input of 950.0 is the desired mixed-
mean outlet temperature in Farenheit. The temperature rise between inlet and outlet is thus 279 F.
The total power (30 MW) is taken from the RTFLUX file (or sum of PWDINT file) and combined
with this temperature rise to determine the total coolant flow rate for the domain. The third real
value of 0.0 corresponds to the cold bypass flow as a percentage of the total flow rate. The cold
bypass flow is typically associated with in vessel storage and is assumed to not remove significant

                                                  78                               ANL/NSE-25/44

power but it impacts the total power delivered to the heat exchanger in that the temperature change
across the heat exchanger is less than the temperature change across the core. If the cold bypass
flow is 10% of the total flow, then this input should be 10.0. The fourth real value of 1.0 is a
multiplier applied to the power distribution on PWDINT. The last real value of 1.0 is a multiplier
applied to the power distribution at the end of the calculation. If not 1.0, this will result in SE2-
ANL determining the flow rate necessary for the PWDINT case and then determine the
temperatures if that flow rate is preserved and the power is adjusted by the factor.

 There is no card type 14 input in A.THINP. The card type 15 input is used to specify the fraction
of gamma derived power that is deposited in the duct wall. As seen, there is no example of this card
type in Figure 5.5 which means the power is fully deposited in the pins of each assembly. The
values on this input card are intended to be fractions and thus if 5% of the gamma power is delivered
in the duct wall, then the input value should be 0.05. Unlike the card type 03 input, which selects
zones, this card input selects the user regions and it should come as no surprise that it is rarely used.
 There is no card type 16 input in A.THINP. The card type 17 input is used to specify the stage
factor power adjustment. As was the case with card type 15, the region name is used to assign the
factor rather than the zone name. In the first example shown in Figure 5.5 the label ICOREA and
real value of 1.01 appear on the input line. The first is of course a region name from the problem
of interest and the factor 1.01 is the stage factor. As implemented, the intention of this is to alter
the power in each region to change the definition of the nominal power distribution. If all fueled
regions were multiplied by a flat 1.03 stage factor, then the actual power would not be 30 MW but
closer to 30.9 MW. Because the nominal total flow rate is dependent upon the nominal power level
                                                  80                                   ANL/NSE-25/44

of 30 MW, using the altered power level in SE2-ANL causes the total flow rate to be increased and
thus defines a different nominal state. Because this is not the nominal state of the reactor, it is
suggested that one alternatively include the stage factor as a modified direct factor in the horizontal
method for the “coolant delta T” or the coolant temperature rise from the inlet to the hot spot point.
This will only impact the 2-sigma cladding and fuel temperatures in the output and the nominal
coolant temperatures will still be reported. Using the stage factors allows a more precise spatial
distribution of power adjustment than the suggested hot channel factor methodology but neither are
a good substitute of modeling a discrete shuffling scenario versus the equilibrium cycle in REBUS.
For the last card type 17, the region label is blank while the stage factor is 1.0. This input means
the given factor of 1.0 will be applied to all regions not appearing on another type 17 card.
 There is no card type 18 or 19 in A.THINP. The card type 20 input is used to specify a gap
between the fuel pellet and the conductivity of the gap. This input is primarily used for oxide fuel
but if the input card is not present then the fuel pin temperature will not be specified. In the Figure
5.5 example, an integer value of 0 is followed by real values of 0.0 and 1000000.0 are observed.
The integer value of 0 indicates that this line will correpond to all assembly types (3 of them) in
this model. The first real value of 0.0 indicates that there is no gap between the fuel pellet and the
cladding. The last value of 1000000.0 is the conductivity in Btu/(hr·ft·°F).
 The card type 21 input allows the user to specify the fuel temperature model for each assembly
type. In the first example in Figure 5.5, the input line contains integer values of 1 and 1 followed
by real values of 1.0, 0.10, 0.18, and 0.25. The first integer value of 1 selects the first assembly
type. The second integer value of 1 selects the mesh number in the fuel. In the Figure 5.5 example,
three lines are provided for the first assembly type which means there are 3 radial meshes in the
fuel. The first line has a real value of 1.0 while the second and third have values of 0.66667 and
0.33333, respectively. This input defines three meshes with radii fractions of discrete values of
(1.0,0.66667,0.33333,0.0). It is important that the numbering matches the radial fractions as
misordered input will result in an error. The remaining real values of 0.10, 0.18, and 0.25 specify
the weight fraction of zirconium, weight fraction of plutonium, and porosity of the pellet,
respectively. If a card type 22 is included, which only inputs the number of radial nodes in the fuel
pellet, it will trigger the oxide fuel correlation instead of the metal fuel one. For the 3rd assembly
type, a double ducted control rod assembly, a negative value of plutonium weight fraction is given
which indicates that the fuel temperature calculation will be skipped.

24 characters and will appear in the output as a name for the assembly type.

7. Summary and Conclusions
 The SE2-ANL code was developed by interfacing the multi-assembly, steady-state Liquid
Metal Reactor (LMR) core thermal hydraulic analysis code SUPERENERGY-2 with the heating
calculations performed by using ANL reactor physics codes. While SE2-ANL was created in the
early 1980s, no documentation was ever created for it and this manuscript serves as the manual.
 For SE2-ANL the temperature calculation capability is inherited from SUPERENERGY-2,
which is based upon the subchannel method. Section 2 gives an overview of SUPERENERGY-2,
describing 1) geometry and meshing, 2) interassembly heat transfer, and 3) user convience features.
Section 3 derives the detailed subchannel equations for 1) meshes internal to the inner duct, 2)
meshes in the double ducted duct bypass gap, 3) the inter-assembly gap, and 4) the duct walls. Most
of the equations were borrowed from the DASSH-F manual with detailed explanation of each term,
and some further derivation was performed to make them have the similar formulation as those
appearing in the original SUPERENERGY-2 manual.
 The fuel and cladding temperature calculation in SE2-ANL is shown in section 4. The power
distribution is derived from ANL reactor physics calculations with DIF3D and explicit details of
the pin power evaluation were given. The calculated power profiles are fed directly into
SUPERENERGY-2 as input and thus the modeling accuracy is limited by the SUPERENERGY-2
methodology. The 1-D fuel pin temperature scheme was displayed. The 2-sigma temperature
methodology was also discussed and the detailed methodology behind it can be found in the
provided references.
 Sections 5 and 6 discuss the input specification and output details of SE2-ANL, respectively.
The SE2-ANL input is composed of A.SE2ANL and A.THINP. A.SE2ANL is a truncated
SUPERENERGY-2 input while A.THINP is a standard BCD formatted input consistent with the
rest of ARC. A simple 19-assemblie model was used to demonstrate the input and output features.
Many of the features of SE2-ANL, e.g. zone orificing and stage factors, were discussed.
