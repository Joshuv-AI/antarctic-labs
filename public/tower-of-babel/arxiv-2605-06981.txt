Bridging Textual Profiles and Latent User Embeddings for Personalization
Zhaoxuan Tan, Xiang Zhai, Yan Zhu, Meng Jiang, Mohamed Hammad

Abstract
Personalized systems rely on user representations to connect behavioral history with downstream recommendation applications. Existing methods typically employ either supervised latent user embeddings, which are effective for retrieval but difficult to interpret, or textual user profiles, which are interpretable but challenging to optimize for downstream utility due to lack of direct supervision. To bridge this gap, we present BLUE , a reinforcement learning framework that unifies these two forms of user representation by aligning language-based user profiles with embedding-based recommendation objectives. Given a user’s interaction history, BLUE leverages a profiler Large Language Model (LLM) to generate textual profiles, while an embedding model provides reward signals. This encourages the resulting textual representations to move closer to positive items and farther from negative ones in the embedding space. We further introduce a text-space supervision signal based on next-item prediction, ensuring the learned profiles remain both semantically meaningful and highly effective for downstream retrieval. Experiments on Amazon Reviews 2023 and Google Local Reviews in zero-shot sequential recommendation settings demonstrate that BLUE consistently outperforms strong baselines under both frozen and trainable embedding conditions. Notably, BLUE achieves clear gains in cross-domain transfer, highlighting the strong generalization ability of the learned user profiles. Furthermore, these generated profiles provide superior personalized context for question answering compared to raw user histories or alternative profile optimization methods. Overall, these results show that BLUE provides an effective way to unify interpretable textual profiling with discriminative latent embeddings for personalization.

A central design choice in personalization is how to represent the user. Existing methods mainly rely on two forms of user representation: textual user profiles and latent user embeddings. Textual user profiles describe user preferences in natural language
(

, while latent user embeddings map users into dense vectors learned from sequential interaction histories, often with dual-encoder architectures

(
53

. However, latent embeddings have limited interpretability. They compress complex and noisy interaction histories into a single dense vector, which makes it hard to distinguish high-level preferences from behavioral noise. As a result, they often act as a black box: strong for ranking, but offering little insight into what the model has learned about the user or why a recommendation is made
(
55
;
28
)
. This compression can also lose semantic information about long-term preferences and behavioral patterns. In contrast, language-based user profiles offer a more interpretable representation in text space. With the help of large language models (LLMs), a system can summarize user interests and behavioral patterns into concise and human-readable descriptions
(
43
;
55
)
. Such profiles are easier to inspect, can capture richer semantics, and can support reasoning over sparse or noisy histories. However, existing profile generation methods still face a key challenge. Most rely on manually crafted prompts and predefined profile formats, which may not align well with downstream personalization tasks. More importantly, training an LLM to generate high-quality user profiles is difficult because there is often no single ground-truth profile for a user
(
27
)
. Unlike embedding learning in sequential recommendation, where the next interacted item provides a clear supervision signal, user preferences, habits, and intent in user profiles can be summarized in many valid ways in natural language
(
44
)
.

This creates a gap between the two dominant forms of user representation. Latent embeddings are strong for retrieval but weak in interpretability, while textual profiles are interpretable but difficult to optimize for downstream utility. In this work, we aim to bridge these two representations. We propose to

Specifically, given a raw user behavior sequence, we prompt a profiler LLM to generate multiple candidate user profiles. We then combine the generated profile with the user history and feed them into an embedding model to obtain a user representation for ranking against item embeddings. The embedding model is kept frozen while the profiler LLM is optimized with Group Relative Policy Optimization (GRPO)
(
31
)
. The reward is defined from contrastive signals in the latent space, encouraging generated profiles whose induced user embeddings are closer to the positive item and farther from negative items. We further include a text-space supervision signal based on next-item multiple-choice prediction, where the generated user profile is fed back into the profiler LLM and perform multiple choice on the next item prediction task, and obtain binary correctness reward. As a result, the profiler learns to generate user profiles that are both semantically meaningful in text space and useful for retrieval in embedding space. These generated profiles can be used as concise personalized context for downstream personalized question answering, and they can also improve recommendation performance under both frozen and fine-tuned embedding settings.

We evaluate our framework on Amazon Reviews 2023
(

and Google Local Reviews
(
18
)
data under the zero-shot sequential recommendation setting
(
20
)
. Specifically, we train the profiler model on the Amazon Clothing_Shoes_and_Jewelry domain and test on out-of-domain Books, Electronics, Sports, and Google Reviews data. Our results show that
BLUE
consistently outperforms strong baselines while keeping the embedding model frozen. Furthermore, by further finetuning the embedding model,
BLUE
can achieve additional gains while still maintaining its advantage over competing methods. We also show that the generated textual user profiles provide better personalized context for question answering than raw history or alternative profile optimization methods. Extensive experiments further demonstrate strong in-domain performance across datasets, a favorable Pareto trade-off between effectiveness and efficiency, and improved latent user structure in both quantitative analysis and qualitative case studies.

To summarize, our contributions are twofold. First, we propose
BLUE
, a reinforcement learning framework that jointly connects textual user profiling and latent embedding optimization for personalization, showing that latent-space contrastive reward can serve as an effective supervision signal for training a profiler LLM without requiring ground-truth user summaries. Second, we demonstrate that the resulting profiles support two complementary personalization goals: improving retrieval quality for sequential recommendation and providing high-quality, interpretable user context for personalized question answering.

2
Methodology

We aim to bridge latent user embeddings and textual user profiles by connecting them during training. Instead of treating profile generation as a standalone language task, we model it as a policy that summarizes user history into a concise natural language profile, which serves both as an interpretable description and as input to an embedding model for recommendation. The key idea is to use the downstream utility of the induced embedding as supervision: rather than matching a ground-truth summary, the profiler is optimized to generate profiles that improve downstream prediction. In this pipeline, a user’s interaction history is first converted into a textual profile, which is then encoded into a latent representation for retrieval, and the resulting performance signal is fed back to refine the profile generation. This allows the learned profiles to remain semantically meaningful while also capturing preference information that is useful for personalization.

2.1
Problem Formulation

Let
\mathcal{U}
and
\mathcal{V}
denote the sets of users and items, respectively. For a given user
u\in\mathcal{U}
at time
t
, let
\mathcal{H}_{u}=\{h_{u}\}^{\leqslant t}
denote the user’s historical interaction sequence before time
t
. Each interaction is represented as a tuple
h_{u}=(v,s)
, where
v\in\mathcal{V}
is the interacted item and
s
is the associated score or rating. The item interacted with after time
t
is treated as the target positive item and denoted by
v_{pos}
. Our goal is to learn a profiler model
\pi_{\theta}
that maps raw user history to a textual user profile,

\displaystyle p_{u}=\pi_{\theta}(\mathcal{H}_{u}),

such that the user profile serves two roles:
(1)
an interpretable summary of user preferences for downstream language tasks, and
(2)
an effective representation for sequential recommendation when encoded by an embedding model. Instead of relying on ground-truth summaries, we optimize
\pi{\theta}
using downstream signals that capture both text-space and embedding-space usefulness.

Figure 2:
Overview of
BLUE
. Given a user history, a profiler generates a textual user profile and is optimized with reinforcement learning using a text-space next-item prediction reward and an embedding-space contrastive reward from a frozen embedding model. The learned profile can then be used to train the embedding model with InfoNCE loss, yielding user representations that are both interpretable and effective for sequential recommendation and personalized question answering.

2.2
Bridging Texutal User Profile and Latent User Embeddings (
BLUE
)

Figure
2
illustrates the overall framework of
BLUE
. Starting from the raw user behavior sequence
\mathcal{H}_{u}
, we prompt a profiler LLM to generate a textual profile
p_{u}
that summarizes the user’s interests, preferences, and behavioral patterns:

\displaystyle p_{u}\sim\pi_{\theta}(\cdot\mid\mathcal{P}_{\mathrm{Gen}}(\mathcal{H}_{u})).

This generated profile is not treated as the final output by itself. Instead, it functions as a bridge between the user’s raw behavioral history and two downstream personalization spaces. In the text space, it provides an explicit natural language summary that can support personalized question answering. In the latent space, it is encoded into user representations that can be used for item retrieval and ranking. To preserve both short-term behavioral evidence and high-level preference abstraction, we construct two user embedding variants using a frozen embedding model
\mathrm{Emb}_{\phi}(\cdot)
:

\displaystyle e_{u}^{(1)}=\mathrm{Emb}_{\phi}(\mathcal{H}_{u}^{\prime}\;||\;p_{u}),\;\;\;e_{u}^{(2)}=\mathrm{Emb}_{\phi}(p_{u}).

Here,
e_{u}^{(1)}
combines recent behavioral context
\mathcal{H}_{u}^{\prime}
(the most recent 10 interactions) with the generated profile, while
e_{u}^{(2)}
reflects how much useful preference information is captured by the profile alone. The profile encodes long-term user preferences and behavior patterns, while the recent history captures short-term dynamics.

Embedding-Space Reward.

To encourage the generated profile to induce a user representation that is effective for sequential recommendation, we define an embedding-space reward based on bidirectional contrastive alignment between the user representation and the target item embeddings. For each embedding variant
e_{u}^{(k)}
, where
k\in{1,2}
, we consider the average of user-to-item and item-to-user contrastive objectives under an InfoNCE-style formulation
(
40
)
. The user-to-item term pulls the user embedding closer to the positive item while pushing it away from negative items, whereas the item-to-user term separates the target item from other users in the batch. Assuming a symmetric similarity function
\mathrm{sim}(\cdot,\cdot)
, instantiated as cosine similarity, the objective is

\displaystyle R_{\mathrm{avg}}(e_{u}^{(k)})=\frac{1}{2}\Big(R_{U\to I}(e_{u}^{(k)})+R_{I\to U}(e_{u}^{(k)})\Big)=\log\frac{\exp(\mathrm{sim}(e_{u}^{(k)},h_{v^{+}})/\tau)}{\sqrt{Z_{U}(e_{u}^{(k)})\cdot Z_{I}(e_{u}^{(k)})}}.

where the
h_{v^{+}}
is the positive next interacted item of user
u
,
\mathcal{V}^{-}
is the set of negative items,
\tau
is the temperature for contrastive reward,
\mathcal{U}^{-}
denotes all other users in batch. The corresponding partition functions
Z_{U}(e_{u}^{(k)})
and
Z_{I}(e_{u}^{(k)})
are given by

\displaystyle Z_{U}(e_{u}^{(k)})

\displaystyle=\exp(\mathrm{sim}(e_{u}^{(k)},h_{v^{+}})/\tau)+\sum_{j\in\mathcal{V}^{-}}\exp(\mathrm{sim}(e_{u}^{(k)},h_{j})/\tau),

\displaystyle Z_{I}(e_{u}^{(k)})

\displaystyle=\exp(\mathrm{sim}(h_{v^{+}},e_{u}^{(k)})/\tau)+\sum_{j\in\mathcal{U}^{-}}\exp(\mathrm{sim}(h_{v^{+}},e_{j}^{(k)})/\tau).

This reward encourages the generated profile to align the user representation with the ground-truth next item while separating it from negative items and users. We then aggregate the rewards from the two representation variants:

\displaystyle R_{\mathrm{emb}}^{u}=R_{\mathrm{avg}}(e_{u}^{(1)})+R_{\mathrm{avg}}(e_{u}^{(2)}).

This term provides supervision from the latent space, guiding the textual profile to improve downstream retrieval performance rather than only optimizing for surface-level fluency.

Text-Space Reward.

While the embedding-space reward improves retrieval quality, it does not explicitly ensure that the generated profile is informative and usable in natural language. To maintain the semantic quality of the profile, we introduce a text-space reward that directly evaluates whether the profile contains sufficient information to support language-based reasoning about user behavior.

Concretely, we formulate next-item prediction as a multiple-choice question answering task. Given the generated profile
p_{u}
as context, we construct a prompt
\mathcal{P}_{\mathrm{pred}}(p_{u})
that asks the model to select the next interacted item from a candidate set. The profiler model
\pi_{\theta}
then produces a prediction:

\displaystyle\hat{y}_{u}\sim\pi_{\theta}(\cdot\mid\mathcal{P}_{\mathrm{pred}}(p_{u})).

where
\hat{y}_{u}
denotes the predicted item. The ground-truth label is the actual next item in the sequence, denoted by
y_{u}=v_{u}^{+}
.

\displaystyle R_{\mathrm{text}}^{u}=\mathbbm{1}(\hat{y}_{u}=y_{u}),\quad\text{where}\quad y_{u}=v_{u}^{+}.

This reward encourages the generated profile to contain explicit and usable preference information that supports language-based reasoning. In contrast to the embedding-space reward, which operates in a latent space, this term directly evaluates whether the profile alone provides sufficient information to infer the user’s next action in natural language. As a result, it helps maintain the interpretability and practical usefulness of the generated profiles for downstream LLM-based personalization tasks.

Final reward and policy optimization.

We combine the embedding-space and text-space signals into a unified reward for each sampled profile. For a given user
u
and a sampled profile
p_{u}^{(i)}
from the current policy
\pi_{\theta}
, the total reward is defined as

\displaystyle R_{\mathrm{final}}^{u}(p_{u}^{(i)})=R_{\mathrm{text}}^{u}(p_{u}^{(i)})+R_{\mathrm{emb}}^{u}(p_{u}^{(i)}),

where
R_{\mathrm{text}}^{u}
evaluates next-item prediction accuracy in text space, and
R_{\mathrm{emb}}^{u}
measures contrastive alignment quality in embedding space. To optimize the profiler model
\pi_{\theta}
, we adopt Group Relative Policy Optimization (GRPO). For each user
u
, we sample a group of
G
candidate profiles
\{p_{u}^{(i)}\}_{i=1}^{G}
from the current policy. The objective is defined as

\displaystyle\mathcal{J}_{\mathrm{GRPO}}(\theta)=\mathbb{E}_{u}\left[\frac{1}{G}\sum_{i=1}^{G}\left(\min\!\big(r_{u,i}\hat{A}_{u,i},\mathrm{clip}(r_{u,i},1-\epsilon,1+\epsilon)\hat{A}_{u,i}\big)-\beta\,\mathbb{D}_{\mathrm{KL}}(\pi_{\theta}\,\|\,\pi_{\mathrm{ref}})\right)\right],

where
r_{u,i}
is the probability ratio defined as

\displaystyle r_{u,i}=\frac{\pi_{\theta}(p_{u}^{(i)}\mid\mathcal{P}_{\mathrm{Gen}}(\mathcal{H}_{u}))}{\pi_{\mathrm{ref}}(p_{u}^{(i)}\mid\mathcal{P}_{\mathrm{Gen}}(\mathcal{H}_{u}))},

which compares the likelihood of the sampled profile under the current policy
\pi_{\theta}
and a reference policy
\pi_{\mathrm{ref}}
. The clipping parameter
\epsilon
controls the trust region of policy updates, and
\beta
balances the strength of the Kullback–Leibler (KL) regularization term
\mathbb{D}_{\mathrm{KL}}(\pi_{\theta}\,\|\,\pi_{\mathrm{ref}})
, which stabilizes training by preventing large deviations from the reference policy. The normalized advantage
\hat{A}_{u,i}
is computed within each group as

\displaystyle\hat{A}_{u,i}=\frac{R_{\mathrm{final}}^{u}(p_{u}^{(i)})-\mu_{u}}{\sigma_{u}+\epsilon},

where
\mu_{u}=\frac{1}{G}\sum_{i=1}^{G}R_{\mathrm{final}}^{u}(p_{u}^{(i)})
and
\sigma_{u}
is the corresponding standard deviation across the
G
sampled profiles for user
u
. This group-wise normalization reduces variance and enables stable comparison among candidate profiles generated from the same user history. Overall, this formulation does not assume a single correct textual profile for each user. Instead, profiles are optimized based on their functional quality: a profile is preferred if it yields higher reward by being both informative in text space and effective in embedding space. By jointly optimizing these signals,
BLUE
learns profiles that support both interpretable reasoning and accurate personalized retrieval in text and latent space.

2.3
Embedding Model Optimization

The embedding model in
BLUE
primarily serves as a source of supervision for guiding profile generation. In many practical scenarios, the embedding model is a fixed component, such as a deployed retrieval system or a closed-source service, and cannot be updated. In this setting, our method already improves personalization by optimizing textual profiles to better align with the existing embedding space. However, the learned textual profiles can also be viewed as structured and denoised summaries of user behavior, which may provide higher-quality supervision signals than raw interaction histories. This motivates a second setting where the embedding model is further finetuned using the generated profiles, while the profiler model is frozen. Importantly, this step is optional, but it allows us to study whether improved profiles can also enhance the embedding space training.

Specifically, we consider supervised contrastive learning
(
16
)
to adapt the embedding model. Given a mini-batch of
B
user-item pairs, let
e_{u}
denote the user embedding derived from the profile-augmented context, and let
h_{u,v^{+}}
denote the embedding of the corresponding ground-truth next item. The user-to-item and item-to-user objectives are:

\displaystyle\mathcal{L}_{U\to I}=-\frac{1}{B}\sum_{u=1}^{B}\log\frac{\exp(\mathrm{sim}(e_{u},h_{u,v^{+}})/\tau)}{\sum_{j=1}^{B}\exp(\mathrm{sim}(e_{u},h_{j,v^{+}})/\tau)},\;\;\mathcal{L}_{I\to U}=-\frac{1}{B}\sum_{u=1}^{B}\log\frac{\exp(\mathrm{sim}(h_{u,v^{+}},e_{u})/\tau)}{\sum_{j=1}^{B}\exp(\mathrm{sim}(h_{u,v^{+}},e_{j})/\tau)}.

The overall embedding optimization objective is

\displaystyle\mathcal{L}_{\mathrm{emb}}=\mathcal{L}_{U\to I}+\mathcal{L}_{I\to U}.

By minimizing
\mathcal{L}_{\mathrm{emb}}
, we adapt the embedding model so that user profiles and item representations lie in a more discriminative shared space. This setting allows us to evaluate whether the generated textual profiles not only improve retrieval as fixed inputs, but also act as effective supervision signals for learning better embedding functions.

5.2
Efficiency Analysis

Efficiency analysis is important in our setting because a practical personalization method should improve both recommendation and question answering quality without adding too much inference cost. We define the quality score in sequential recommendation as
\text{Quality}=(\text{N@10}+\text{R@10})/2
, where
N@10
and
R@10
come from the query-adaptive sequential recommendation setting with a frozen embedding model. For personalized question answering
\text{Quality}=\left(\text{Acc}+\frac{1}{1+\text{MAE}}\right)/2
, , and
Acc
and
MAE
come from accuracy of next item prediction and MAE of the user rating prediction. As shown in Figure
4
,
Raw User History
is the fastest method because it does not require profile generation, but it also gives the lowest quality score, which suggests that raw interaction sequences are efficient yet weak at organizing user preference signals for both retrieval and downstream applications. Profile-based methods require more inference time, but they achieve better quality by compressing and denoising user history into a more informative textual summary. Among them,
Base Profile
,
RLAIF
, and
RLPF
have similar runtime because they all add one profile generation step, yet their quality remains clearly below
BLUE
. In contrast,
BLUE
reaches the highest quality score while staying in the same general efficiency range as the other profile-based methods, showing that its gains come from better profile optimization rather than a much more expensive inference pipeline. Overall, the results show that
BLUE
provides the best balance between effectiveness and efficiency, making it the strongest operating point on the quality-efficiency frontier.

5.5
Ablation Study

We conduct an ablation study to examine how each component of
BLUE
affects sequential recommendation and personalized question answering. As shown in Table
6
, the two reward terms play distinct but complementary roles. Removing the embedding-space reward
R_{\mathrm{emb}}
causes the largest and most consistent degradation, with sharp drops in frozen-embedding retrieval across Clothing, Books, and Google Reviews, together with substantial declines in personalized QA, especially for rating prediction, suggesting that latent-space supervision is the main signal for learning profiles that induce strong user representations. In contrast, removing the text-space reward
R_{\mathrm{text}}
has only a limited effect on retrieval, and even slightly improves retrieval on Google Reviews, but it consistently weakens personalized QA across all domains, indicating that this reward mainly helps preserve profile content that is useful for downstream language understanding and reasoning. Removing either the
e_{u}^{(1)}
reward or the
e_{u}^{(2)}
reward also reduces performance, showing that the two embedding views provide complementary supervision:
e_{u}^{(1)}
helps retain short-term behavioral evidence by combining recent history with the generated profile, while
e_{u}^{(2)}
encourages the profile itself to encode sufficient preference information as a compact standalone summary. We also find that removing
R_{U\to I}
leads to a larger retrieval drop than removing
R_{I\to U}
, while both directions hurt personalized QA, suggesting that the two alignment directions are complementary rather than redundant. Finally, replacing GRPO with REINFORCE++
(
14
)
yields weaker results on most metrics, with especially clear drops on personalized QA, although it remains competitive on a few retrieval numbers. Overall, the full model achieves the best balance between retrieval quality and personalized reasoning, which supports the value of jointly optimizing user profiles in both embedding space and text space.

Related Work

Latent User Representation Learning for Recommendation.

Sequential recommendation has long relied on latent user representations learned from historical interaction sequences
(
9
;
2
)
. Early neural approaches focused on modeling user dynamics with architectures such as recurrent networks
(
11
;
49
;
22
)
and self-attention
(
15
;
32
;
50
)
, capturing short- and long-range behavioral dependencies. More recent work has moved beyond pure ID-based modeling and introduced semantic signals from item text or pretrained representations to improve generalization
(
24
;
10
;
12
;
35
;
6
;
23
)
. For example, UniSRec
(
13
)
learns transferable sequence representations from item descriptions for cross-domain recommendation, while LLM-enhanced representation learning methods such as RLMRec
(
29
)
align collaborative signals with semantic information derived from language models. Although these methods improve recommendation quality and transferability, they still primarily represent users as dense latent vectors, which remain difficult to inspect or edit directly. Our work is related to this line of research, but differs in that we explicitly optimize a textual user profile and use the embedding model as a reward provider, thereby connecting interpretable language-space summaries with latent retrieval-oriented representations.

Language-Based User Profiles for Personalization.

A growing line of work studies user representations in natural language rather than only in latent space. Recent methods show that LLMs can summarize a user’s historical interactions into compact textual profiles that are easier to inspect, edit, and use for downstream reasoning
(
26
;
55
;
28
;
37
;
42
)
. Such profiles have been explored for recommendation, transparency, and scrutability, showing that language-based user modeling can make personalized predictions more understandable and controllable
(
28
)
. However, most early approaches rely on zero-shot prompting or manually designed profile templates, which makes profile quality highly dependent on prompt design and often weakly tied to downstream utility. To address this, newer methods begin to optimize generated profiles more directly. LangPTune
(
8
)
trains LLM-generated user profiles end-to-end for recommendation, and recent profile optimization work studies feedback-driven profile generation under adaptive or task-aware settings
(
44
;
43
)
. Instead of optimizing profiles only from language-space feedback or recommendation labels, our proposed
BLUE
jointly optimize them using both text-space supervision and latent embedding-space reward, so that the resulting profile is both interpretable and directly useful for retrieval.

Reinforcement Learning for Language Models.

Our method is also related to reinforcement learning for optimizing language models under weak or indirect supervision. When there is no single gold output, policy optimization offers a natural way to improve generation using task rewards rather than imitation targets alone. Early reinforcement learning from human feedback (RLHF) work for language models commonly used PPO to optimize responses against learned reward models while constraining policy drift from a reference model
(
30
;
25
)
. More recent work has studied simpler or more efficient variants, including GRPO for group-relative reward optimization over multiple sampled outputs
(
31
)
, and critic-free methods such as REINFORCE++
(
14
)
and DAPO
(
48
)
. In recommendation and personalization, related studies use reinforcement learning to optimize prompts, summaries, or profile formats according to downstream utility rather than human-written profile references
(
44
;
43
)
. Our work extends this line by treating textual user profiling itself as a policy optimization problem, with reward defined jointly in text space through next-item prediction and in latent space through contrastive embedding alignment.

7
Conclusion

In this work, we introduced
BLUE
, a reinforcement learning framework that bridges textual user profiles and latent user embeddings for personalization. Our method uses a profiler LLM to generate interpretable natural language user profiles, while a latent embedding model provides contrastive reward signals that guide profile generation toward downstream retrieval utility. By combining embedding-space reward with a text-space next-item prediction reward,
BLUE
learns profiles that are both semantically meaningful and effective for recommendation. Experiments on Amazon Reviews and Google Local Reviews showed that our method consistently improves query-adaptive retrieval under frozen embedding models, strengthens cross-domain and in-domain recommendation when the embedding model is trained, and provides better personalized context for downstream question answering. These results suggest that textual profiles and latent embeddings should not be viewed as competing forms of user representation, but as complementary spaces that can be jointly optimized to support both interpretability and predictive performance in personalized systems.

Appendix A
Baseline Details

A good summary is a shorter piece of text that has the essence of the original. It tries to accomplish the same purpose and conveys the key information from the original input text. Below we define four evaluation axes for summary quality: coherence, accuracy, coverage, and overall quality.

Coherence: This axis answers the question “how coherent is the summary on its own?” A summary is coherent if it’s easy to understand when read on its own and free of English errors. A summary is not coherent if it’s difficult to understand what the summary is trying to say. Generally, it’s more important that the summary is understandable than it being free of grammar errors.

Accuracy: This axis answers the question “does the factual information in the summary accurately match the input user history?” A summary is accurate if it doesn’t say things that aren’t in the input user hisory and generally is not misleading.

Coverage: This axis answers the question “how well does the summary cover the important information in the input user history?” A summary has good coverage if it mentions the main information from the input user history text that’s important to understand the situation described in the user history. A summary has poor coverage if someone reading only the summary would be missing several important pieces of information about the situation in the input text.

Overall quality: This axis answers the question “how good is the summary overall at representing the input user history?” This can encompass all of the above axes of quality, as well as others you feel are important. If it’s hard to find ways to make the summary better, the overall quality is good. If there are lots of different ways the summary can be made better, the overall quality is bad.

Appendix D
In-Domain Sequential Recommendation Performance Analysis

To better understand domain-wise differences in in-domain sequential recommendation performance (Section
5.1
), we define a
recent-dominance score
. Specifically, we use
Qwen3-Emb-0.6B
to embed the target item title and the titles of the most recent 10 user interactions, and compute their mean cosine similarity, denoted as
s_{\text{recent}}
. We similarly compute the mean similarity between the target item and all previous user interactions as
s_{\text{long}}
. The recent-dominance score is then defined as
s_{\text{recent}}-s_{\text{long}}
, which quantifies the extent to which the next item is driven by recent behavior rather than long-term preference. We observe that domain-wise performance differences are primarily influenced by two factors. First, domains vary in the relative importance of long-term preference versus short-term sequential intent. Our recent-dominance analysis shows that Google Reviews and Books exhibit lower reliance on recent interactions, suggesting that user behavior in these domains is more driven by stable preferences. This aligns with the strong performance of BLUE, as textual profiles can effectively summarize long-term user interests. Second, domains differ in the degree to which success depends on fine-grained item distinctions. In Electronics, despite relatively low recent-dominance, BLUE is less competitive than classical sequential models. This suggests that the main challenge is not short-term intent modeling, but preserving fine-grained signals such as brand, model, and compatibility during embedding adaptation. In contrast, Clothing and Sports lie between these extremes: while BLUE consistently improves over other profile-based methods, sequential models remain competitive due to the stronger role of recent transition patterns. Overall, these results indicate that the effectiveness of profile-based methods depends not only on temporal dynamics but also on the granularity of item-level distinctions required by the domain.

Appendix E
Implementation Details

In our implementation, both the maximum input and output generation lengths are constrained to 2048 tokens. We train the model for one epoch on the Amazon Clothing dataset. For Group Relative Policy Optimization (GRPO) training, we set the learning rate to 1e-6 and the batch size to 64. During this phase, we employ a sampling temperature of 1.0 with 8 rollouts per user, and sample 128 negative items per positive item to provide abundant negative feedback for user profile generation. For the KL divergence, we set the coefficient to 0.01 to keep the profiler model generating fluent user profiles. For the embedding model training via supervised contrastive learning, we use a batch size of 512 and a learning rate of 1e-6, restricting training to a single epoch to achieve domain adaptation while preserving generalization capabilities. The temperature for both the InfoNCE-style reward and the supervised contrastive loss is set to 0.07. Finally, during inference, the temperature is set to 0.7 for profile generation, whereas the decoding temperature is strictly set to 0 for the text-space next-item prediction task to eliminate randomness during evaluation.

Appendix H
Discussion on Potential Data Contamination

Large language models and embedding models are commonly pretrained on large-scale public web corpora. Since Amazon Reviews and Google Local Reviews are public datasets, we cannot rule out the possibility that some item descriptions, reviews, or related textual content were included in the pre-training data of the backbone models used in this work. This creates a potential data contamination concern: a pretrained model may have seen part of the benchmark text before evaluation, which could inflate absolute performance, especially in tasks that rely heavily on textual semantics.

Following prior work on zero-shot cross-domain sequential recommendation
(
20
)
, we use the term “zero-shot” to describe the evaluation protocol rather than the pre-training history of the backbone models. Specifically, zero-shot in our setting means that the model is trained on the source domain and evaluated on target domains without target-domain fine-tuning or task-specific training. It does not imply that the pretrained language or embedding models had no possible exposure to public benchmark data during pre-training.

This limitation affects the interpretation of absolute performance numbers. In particular, if the backbone models have memorized public item text or reviews, the reported results may overestimate performance compared with a fully unseen private benchmark. However, our main conclusions are based on relative comparisons under the same pretrained backbones, datasets, and evaluation protocol. All profile-based baselines and BLUE use the same profiler and embedding models, so possible pre-training exposure is shared across methods. Therefore, while potential contamination may affect the absolute scale of performance, it is less likely to fully explain the relative gains of BLUE over baselines.

To further reduce this concern, future work should evaluate BLUE on temporally held-out data released after the backbone models’ pre-training cutoff, newly collected private interaction logs, or benchmarks with controlled data provenance. Such evaluation would provide a stricter test of whether optimized textual profiles generalize beyond public benchmark exposure.

Appendix I
Ethical Considerations

Privacy and user data protection.

BLUE
is trained from user interaction histories, which may contain sensitive signals about personal interests, habits, purchases, or visited locations. Although the model generates concise textual profiles instead of exposing raw histories directly, these profiles can still reveal private information if they are stored, inspected, or shared without proper safeguards. In addition, the learned embeddings and generated profiles may retain behavioral patterns that enable user inference. Any deployment should therefore apply strong privacy protections, including data minimization, secure storage, controlled access, anonymization where possible, and clear user consent and data retention policies.

Bias, fairness, and harmful inferences.

User histories often reflect existing social and platform biases, and a profiling system trained on such data may reproduce or amplify these patterns. This can lead to unfair personalization outcomes, overgeneralized user summaries, or the implicit inference of sensitive attributes that users never explicitly provided. Because
BLUE
optimizes profiles for downstream utility, it may also learn predictive shortcuts that improve recommendation performance while encoding undesirable correlations. Careful evaluation is therefore needed to examine bias in both generated profiles and downstream predictions, especially across different user groups and behavioral patterns.

Transparency, user control, and responsible use.

A key motivation of
BLUE
is that textual profiles are more interpretable than latent embeddings, but interpretability alone does not guarantee correctness. Generated profiles may still omit important context, overstate weak preferences, or reflect temporary behaviors as if they were stable traits. In downstream personalization, such errors can mislead users or produce undesirable system behavior. For this reason, profile-based systems should treat generated profiles as editable summaries rather than authoritative descriptions. When possible, users should be allowed to inspect, revise, or reset their profiles, and deployments should avoid manipulative or high-stakes uses without additional safeguards and human oversight.

Appendix J
Limitations

Our work has several limitations. First, the current study focuses on sequential recommendation and personalized question answering built from user interaction histories in Amazon Reviews and Google Local Reviews, so it does not yet test broader personalization settings such as long-horizon dialogue, agent memory, or multimodal user behavior. Second, the reward design is still relatively simple: the text-space signal is based on next-item multiple-choice prediction, and the embedding-space signal is defined by a fixed contrastive objective, which does not directly optimize other desirable properties such as faithfulness, calibration, robustness to noisy histories, or long-term user satisfaction. Because the model is optimized for downstream reward, it may also under-represent subtle but relevant user traits that are less useful for the current objectives. Third,
BLUE
adds extra training and inference cost compared with directly encoding raw user history, since it requires profile generation, multiple rollouts during reinforcement learning, and additional reward computation. Although the method shows a good quality-efficiency trade-off in our experiments, this extra cost may still limit deployment in high-throughput settings.
