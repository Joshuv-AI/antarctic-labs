ABSTRACT
The U.S. Strategic Petroleum Reserve (SPR) is a crude oil storage system administered by the U.S.
Department of Energy. Only three caverns had substantial raw water injected in CY25, totaling about
1 MMB. An additional five caverns had sonars performed in CY25, one of which followed new
leaching, which allowed for studying of the effects of leaching from previous years. Leaching effects
were monitored in these caverns to understand how the sales operations may impact the long-term
integrity of the caverns. The leaching effects were modeled here using the Sandia Solution Mining
Code (SANSMIC). The Python notebook template has been expanded to allow for automated input
file creation, running, and post-processing with a single button press. This streamlining of the
SANSMIC run process allows for easier setup and analysis of “what-if” leaching calculations beyond
the annual monitoring. Additionally, the OBItool was created to calculate real-world OBI depths with
time, so that more accurate estimates of initial OBI depths would be available for input into leaching
calculations.
The results indicate no new leaching induced features of concern and therefore the monitoring list
remains unchanged this year. Twenty-four caverns still have features that should be monitored in
future leaching efforts. For the one cavern with a CY25 sonar that followed leaching (WH103),
SANSMIC was able to capture the leaching well. These results suggest SANSMIC is a useful tool for
monitoring changes in cavern shape due to leaching effects related to sales and exchanges.
Additionally, the calculation of nearest approaches for all caverns is included. This was done for a
subset of caverns in the previous report but has been extended to a baseline for all caverns now. The
purpose of calculating the nearest approaches is that there are potential ramifications on cavern
integrity if the stress fields from adjacent caverns interact, which can lead to inter-cavern
communication. There are eight closest approaches less than 300 ft across all sites. There are five
closest approaches less than 200 ft. As leaching proceeds in SPR caverns, nearest approach differences
will change and will be monitored in this annual report.

EXECUTIVE SUMMARY
The U.S. Strategic Petroleum Reserve (SPR) is a crude oil storage system administered by the U.S.
Department of Energy. The reserve consists of 60 active storage caverns located in underground salt
domes spread across four sites in Louisiana and Texas, near the Gulf of Mexico. Beginning in 2016,
the SPR started executing Congressionally mandated oil sales. The configuration of the reserve, with
a total capacity of greater than 700 million barrels (MMB), requires that unsaturated water (referred to
herein as “raw” water) is injected into the storage caverns to displace oil for sales, exchanges, and
drawdowns. As such, oil sales will produce cavern growth to the extent that raw water contacts the
salt cavern walls and dissolves (leaches) the surrounding salt before reaching brine saturation.
Only three caverns had substantial raw water injected in CY25, totaling about 1 MMB. An additional
five caverns had sonars performed in CY25, one of which followed new leaching, which allowed for
studying of the effects of leaching from previous years. Leaching effects were monitored in these
caverns to understand how the sales operations may impact the long-term integrity of the caverns.
While frequent sonars are the most direct means to monitor changes in cavern shape, they can be
resource intensive for the number of caverns involved in sales and exchanges. An intermediate option
is to model the leaching effects and see if any concerning features develop.
The leaching effects were modeled here using the Sandia Solution Mining Code (SANSMIC). The
results indicate no new leaching induced features of concern and therefore the monitoring list remains
unchanged this year. Twenty-four caverns still have features that should be monitored in future
leaching efforts. For the one cavern with a CY25 sonar that followed leaching (WH103), SANSMIC
was able to capture the leaching well.
The latest version of the Python version of the code was used for this annual report. The Python
notebook template has been expanded to allow for automated input file creation, running, and post-
processing with a single button press. This streamlining of the SANSMIC run process allows for easier
setup and analysis of “what-if” leaching calculations beyond the annual monitoring. Additionally, the
OBItool was created to calculate real-world OBI depths with time, so that more accurate estimates of
initial OBI depths would be available for input into leaching calculations.
A new feature of the leaching report is the calculation of nearest approaches for all caverns. This was
done for a subset of caverns in the previous report but has been extended to a baseline for all caverns
now. The purpose of calculating the nearest approaches is that there are potential ramifications on
cavern integrity if the stress fields from adjacent caverns interact, which can lead to inter-cavern
communication. There are eight closest approaches less than 300 ft across all sites. There are five
closest approaches less than 200 ft. As leaching proceeds in SPR caverns, nearest approach differences
will change and will be monitored in this annual report.

1. Introduction to Cavern Leaching Monitoring
The U.S. Strategic Petroleum Reserve (SPR) is a crude oil storage system run by the U.S. Department
of Energy (DOE). The reserve consists of 60 active storage caverns spread across four sites near the
Gulf of Mexico. The Big Hill (BH) and Bryan Mound (BM) sites are in Texas, and the Bayou Choctaw
(BC) and West Hackberry (WH) sites are in Louisiana. The storage capacity of the SPR is more than
700 million barrels (MMB).
The purpose of the SPR, as it was designed, is to mitigate emergency supply disruption of crude oil
within the U.S. and to also fulfill International Energy Agency treaty obligations. Because of the large
size of the reserve, brine drive has never been a part of the SPR; instead, oil is withdrawn – or drawn
down – using raw water. Raw water is local surface water that is fresh to saline in its salt content and
is highly undersaturated when compared to (fully saturated) brine and readily available at rates
necessary to support drawdown. Annual raw water injections across all sites since 2017 are shown in
Figure 1-1. Annual leaching reports began with raw water injections in 2017.
The purpose of this report is to document the continued monitoring of cavern geometries, as they
can have a direct impact on cavern stability. Cavern geometries change due to leaching, so leaching is
monitored from two aspects: 1) projecting the areas of cavern growth due to raw water injections
since the last sonar (Section 2); and 2) examining sonar studies that show the actual cavern growth
(Section 3). Additionally, this report uses sonar data to monitor the closest approach of caverns to
each other; as inter-cavern distances decrease with leaching, the potential for inter-cavern
communication increases (Section 4).

1.1. Partial Drawdowns Used to Deliver Oil for Sales and Mandated
 Drawdowns
The SPR is currently involved in crude oil sales mandated by Congress but has also participated in
additional mandated drawdowns [1]. In CY25, the mandated drawdowns were temporarily suspended,
so the overall volume of raw water injections is lower than in previous years. To sell oil from the
reserve, oil is withdrawn using water displacement where water is injected into the cavern pushing oil
out of it (Figure 1-2). Raw water is obtained from naturally occurring surface water near the sites, and
it is not saturated brine. Raw water injection during oil withdrawal reduces the salinity of the brine in
the cavern below the oil. The now-undersaturated brine in contact with the cavern walls dissolves the
salt at the cavern walls, and this process constitutes cavern leaching.

 Figure 1-2. Schematic of drawdown configuration which results in cavern wall leaching.

With respect to the SPR, when a cavern is fully emptied of oil all at once it is referred to as a full
drawdown. When only part of the oil within a cavern is removed followed by an extended waiting
period, then it is called a partial drawdown. While a full drawdown may have short breaks between oil
removal activities, or delivery batches, multiple partial drawdowns can be identified by the presence
of waiting periods that are long enough that the brine sump equilibrates back to a fully saturated state.
The impact of leaching on cavern shape depends on the type of leaching that occurs. Sales generally
involve partial drawdowns of the oil inventory in several caverns. The leaching pattern for a single-
phase partial drawdown generally involves a “flare” pattern with the greatest growth at the depth of
the end of the brine string tubing (EOT) that tapers up to the final oil-brine interface (OBI) depth
(Figure 1-3) [2][9]. This pattern reflects the concentration of salt in the injected water over time, as the
well-mixed brine in the region between the EOT and OBI is lower in concentration compared to the
rest of the cavern brine—with greater exposure times to undersaturated brine near the EOT, there is
a resultant greater radial growth. If the EOT is relatively high above the cavern floor, the flared part
of the cavern is not at the cavern floor and a feature, referred to here as a shelf, may form.
Many SPR caverns have multiple phases of leaching and the final leaching pattern depends on the
cumulative effects for all phases. This and previous SNL annual leaching reports show that caverns

 17

with multiple leaching phases have a range of leaching outcomes which deviate from the single-phase
flare pattern and are difficult to predict a priori from any single metric. Thus, SANSMIC modeling has
been particularly helpful in understanding the potential leaching outcomes for these caverns.

 Figure 1-3. Schematic of leaching pattern from a partial drawdown.

Longer time exposure to brine with undersaturated salt concentrations will produce the greatest
leaching of the salt walls and corresponding radial growth of the cavern. Thus, the greatest radial
growth for a partial drawdown is at the depth of the end of tubing, as shown schematically by the
difference in position between the pre- (grey) and post- (orange) cavern shapes in Figure 1-3.
A full drawdown, while still having more leaching at the bottom of the cavern than the top, is
sufficiently fast that the entire cavern sees relatively more evenly distributed leaching in terms of
changing cavern radius. The contrast between the resulting cavern geometry for a cavern undergoing
a full drawdown and one that exhibits “flaring” due to partial drawdowns can be quite dramatic,
particularly when a cycle of small partial drawdowns followed by refilling the cavern results in the
“flare” being applied multiple times at the same depth.

The actual leaching history for each cavern with 2025 raw water movements was examined here by
comparing past sonars (additional caverns were analyzed based on obtaining cavern sonar data from
2025). This comparison was used to understand if historically leaching has occurred in the caverns
and if it was radial or asymmetric. If it was generally radial in the past, it may also be radial in the

future. Comparison of past sonars can also give an indication of floor rise (which can be due to creep
and/or salt falls) in a cavern.
An example leaching history is shown in Figure 1-4 for cavern BH101. Sonars taken in well A from
2000 and 2012 are shown on the left, with the surface color coded by depth with blue being the
deepest. A comparison of vertical cross sections through each sonar are shown in the middle, with
the 2000 sonar represented by the blue line and the 2012 sonar represented by the orange line. The
change in vertical profile from 2000 (blue) to 2012 (orange) in this cavern indicates that the cavern

1.3. Monitoring Leach Effects Using SANSMIC
Changes in cavern shape may impact the integrity of the cavern over time if features are introduced
into the cavern geometry that concentrate stress. The most direct means to monitor for adverse
leaching effects on the caverns is to take regular sonar measurements of the cavern geometry; however,
this is resource intensive and may not be necessary for all caverns. Instead, leaching effects are being
modeled in all caverns involved in raw water injections to monitor changes in caverns which may be
less geomechanically favorable. These simulations can then inform decisions regarding the choice of
caverns to receive sonar studies; i.e., to direct limited resources where they are needed most to ensure
long term cavern integrity while executing mandatory sales.
Leaching effects are modeled with the Sandia Solution Mining Code (SANSMIC) [10]. SANSMIC
was developed in the early 1980’s to model the effects of leaching on the cavern shape and volume.
The most recent version of the code was issued in 2024 [18]. SANSMIC uses standard salt dissolution
models that account for the salinity of the injected water, temperature, and flow velocity [10].
Simulations use sonar derived cavern shapes at the start of the simulation, the actual casing depths
(EOT), the initial OBI depth based on log data and any subsequent fluid movements, and the field-
reported injected water volumes. The model computes the effects of leaching on cavern shape and
volume, treating the cavern as a stack of cylindrical disks and limiting leaching to cavern depths below
the OBI. The OBI moves as fluids are moved into the cavern.
SANSMIC was validated for conventional leach (both direct and reverse) capabilities by comparison
with cavern creation data [11]. Subsequent comparisons between SANSMIC modeled cavern
geometries and sonar measurements following the 2011 oil sale and subsequent remedial leach
activities indicated the simulated cavern radius is within 5% of the measured cavern radius and the
leached volumes are within 10% [2]. A re-validation of SANSMIC in withdrawal, direct and reverse
leach modes for caverns leached by SPR indicated that simulated radial profiles match sonar
observations within 1.5% - 12 % and the observed leach volume was simulated within 1% -13% [5].
It is important to note that, after discussion with sonar vendors, Sandia uses an assumed volumetric
accuracy for a sonar survey of ±1% of the volume. With older sonar surveys, irregularly shaped
caverns, and with very wide caverns, the error bounds increase. SANSMIC predictions also depend
on the vertical resolution of the input cavern geometry; EOT depths, OBI depths, and final depths
are rounded to the nearest cell boundary, which can impact results depending on the cell size chosen.
For SANSMIC calculations performed for some prior annual leaching reports [7][9][13], the vertical
resolution of 10-ft was used. In the four most recent annual reports [14][15][16][17] and this report,
for SANSMIC calculations performed based on sonars that were not used for baseline cavern
geometries in previous reports, vertical resolution of 1-ft was used. Although a sonar may only report
the cavern geometry with a 10-ft sonar resolution, a 1-ft resolution is derived via interpolation prior
to running SANSMIC.
SANSMIC simulations start from a known cavern geometry, EOT and OBI depths, and injected water
volumes. The cavern geometry is usually taken as the last sonar prior to injection. A 2-D, axisymmetric
representation of the cavern geometry with an equivalent cavern volume is then calculated and used
as the initial geometry. A comparison is shown in Figure 1-5 of the 3D sonar (blue lines) and the 2D
axisymmetric representation (orange lines) for BH101. For this cavern, the lateral cross sections show
that the circular cross section assumption was likely a reasonable approximation as the cavern only
has small variations from circular.
The EOT depths are taken from the weekly site reports, which have historical records of when EOT
depths have changed by accident (i.e., salt fall), due to a string cut, or due to reestablishment of a lower

 20

EOT during the filling process. The OBI depths had previously also been taken from the weekly site
reports, which estimate the OBI depths based on 1) the most recent OBI log data; 2) oil movements
since the most recent OBI log; and 3) the strapping curve from the most recent cavern sonar. For this
report, the initial OBI depths are calculated using a new utility code OBIdepth.py that calculates the
OBI based on these same three types of information. See Appendix B.2 for additional discussion of
the new utility code.
The daily raw water injection amounts are taken from CAVEMAN and stages of water injection are
identified based on time periods of similar injection rates. For a previous annual report [16],
considerable time was spent reviewing the daily injection volumes to investigate any large discrepancies
between raw water injection volumes and oil exit volumes (they should be similar), as an issue was
noticed in reviewing an earlier report. In some cases, issues were found (e.g., missing data) and fixed
when possible (e.g., by discussing with cavern engineers and finding correct numbers via daily site
readiness reports). Results from those fixed issues were carried forward to the current work. Raw
water volumes continue to be compared to oil exit volumes as a data quality check.
For each stage (consisting of two phases, injection and equilibration), an average injection rate is
calculated from the daily rates over the injection phase duration. SANSMIC results appear sensitive
to monthly variations, hence the incorporation of separate stages, but insensitive to daily variations,
hence an average rate used for each day. For 2025 leaching calculations and in the previous two reports
[16][17], injection phases were defined based on attempting to generally match the cumulative
injection volume curves (Figure 1-6). In some previous reports, phases were sometimes defined by
the duration of spring, fall, or yearly sales [7][9][13][14]. Results have not been shown to be sensitive
to phases defined in any of these ways. An automation of the input file creation process (first
implemented for CY22 runs) has made the use of many stages more manageable than in previous
years.
Leaching occurs during the injection phase as well as the equilibration phase (EP). The duration of
the EP has been taken to be the time between the final date of the injection phase and the start of the
new injection phase (see Section 1.4.3 for discussion of a modification made to this assumption for
the current report). The final EP is then chosen as 60 days to ensure the simulations have enough time
to reach equilibrium as indicated by the specific gravity of the fluid in the outlet reaching a value of
1.2, the expected value for fully saturated brine (temperature dependent) [12]. The injection history is
therefore composed of injection phases followed by equilibration phases as shown in Figure 1-6. The
simulation results are evaluated using the efficiency of the leach, the ratio of the change in cavern
volume to the volume of injected water, which is expected to be around 15-17% (in the actual caverns,
the leaching efficiency is dependent on the initial specific gravity and the cavern temperature; in
SANSMIC, brine in each cavern is given the same initial specific gravity and temperature).
Additionally, the OBI depths are tracked with time and compared with available site data accessed via
the SPR Well Log (SPRWL) database at SNL.

1.4. Use of SANSMIC Code in Leaching Calculations
A stable version of the SANSMIC code was released in 2024 and is publicly available [18]. The code
has been tested and shown to reproduce results from previous modeling runs. This version of the
code has an advantage over earlier versions, as it is run in a Python environment, which allows for
easier analysis and post-processing of results with existing Python codes previously developed by SNL.
Version 1.0.7 was used here, as well as the previous annual report [17].

1.4.1. Improvements to Leaching Calculation Workflow for CY25
The following improvements were made to the leaching workflow for CY25:
 1. The Python notebook template has been expanded to allow for automated input file
 creation, running, and post-processing with a single button press. A limited amount of initial
 information gathering (e.g., EOT and initial OBI depths) is necessary, but geometries are
 automatically generated from sonar files. Additional details of the notebook template are
 discussed in Section 1.4.2.
 2. Daily fluid movements from a CAVEMAN database are now used. These new data have
 more fidelity than those downloaded in the Excel spreadsheet, since those from the

 24

 spreadsheet were limited to a single fluid type per day for fluids in and a single fluid type per
 day fluids out; in cases where there were multiple fluid types in (or out) in a day, some of
 that data was lost in the transfer to the spreadsheet.
 3. The OBItool (see Appendix B.2) was created to calculate real-world OBI depths with time, so
 that more accurate estimates of initial OBI depths would be available for input into leaching
 calculations. Previously, initial OBI depths relied on the estimated OBI depths provided in

 4. Additional context for the annual monitoring reports has been included by adding a table of

 5. Dates have been added to the top of the leaching efficiency and OBI plots to align with real
 world injection/equilibration dates. Also, the delineation of injection periods is now more

1.4.2. Continued Development of Python Notebooks for Each SANSMIC Run
A Python notebook is an interactive environment that allows for code to be combined with textual
comments and visual results in a single package. The interactive nature makes iterative changes easier
for the user. Textual comments allow for context to be included immediately alongside inputs and
results, which aids in interpreting results. Having visual results from multiple analytical tools packaged
together also helps in interpreting results and the impacts of changes to input. With SANSMIC now
available for running directly in a Python environment, all stages of an analysis (i.e., model setup, run,
and post-processing) can be packaged into a single file for each cavern leaching modeling run.
For the previous annual report [17], a template Python notebook was developed and used for each
leaching run. That version of the notebook template incorporated each aspect of the SANSMIC run
in some form, but in some cases, the functionality was incorporated via the creation of a “command
line” that could be run in a separate Python terminal—the results were then read back into the
notebook so that all results (i.e., tables and figures) were viewable in the notebook. For the current
report, significant effort has been made to incorporate all aspects of the SANSMIC run in the
notebook, now including the running of the SANSMIC code from the notebook, allowing for a
streamlined analysis. All of the utility codes previously run outside of the notebook have now been
incorporated into the notebook.
The organization from using a Python notebook has improved the efficiency of setting up, running,
and post-processing cavern leaching runs for CY25 caverns and will continue to be useful for both
annual reports and ad hoc leaching analyses. The user can now input only a few key inputs upfront
(e.g., EOT and OBI depths), then a single button press will set up the run (including the extraction of
information from sonar files), run the code, and generate tables and figures for the analysis. This
streamlining of the SANSMIC run process allows for easier setup and analysis of “what-if” leaching
calculations beyond the annual monitoring. Appendix A contains additional details on the capabilities
and use of the Python notebook template for SANSMIC leaching runs.

1.4.3. Impact of Bug Discovered in Current Version of SANSMIC Code
An error was found in the use of SANSMIC that leads to continued leaching at equilibration times
(i.e., times without raw water injection) much greater than are reasonable. The comprehensive
approach that we take to incorporating real-world fluid movements into leaching calculations has

 25

included the use of equilibration times equal to the real-world time between raw water injection
days. For the CY25 leaching calculation for the BM110 cavern, a 887-day equilibration period was
initially used to represent the time between the end of the first stage (12/31/22) and the beginning
of the second stage (6/6/25). However, it was noticed in the SANSMIC results that leaching
continued well past the expected 60-90 days required for “full” equilibration and the leaching
efficiency climbed above 30%, much higher than the expected 16-17%. Additionally, it was noticed
that the leaching efficiency curve became approximately linear after about 60 days into the
equilibration phase.
Digging deeper into the SANSMIC output files revealed that as soon as the injection phase ends and
the equilibration phase begins, the output variable Qout (i.e., flow out of the system) goes from zero
(the expected value) to a negative value, meaning that water is entering the system. It is a relatively
small amount of water entering the system, but it is consistent and results in undersaturation that
leads to additional leaching beyond what was deliberately input into the system. Analysis of a
separate experimental SANSMIC run confirms that the model system is introducing fresh water
during the equilibration period. Some additional work is necessary to correct the error in the code.
The impact of the error is judged to be minimal, as the flow rate is small. The impact is bigger for
longer equilibration periods, so the impact can be reduced by reducing the length of the
equilibration phase. Based on the observed results, limiting the equilibration phase to 60 days results
in the expected leaching efficiency curve (i.e., nonlinear, decreasing with time) and a final leaching
efficiency that matches the expected values of 15-16%. In this report, the equilibration phases for
caverns BM103, BM110, and WH103 were reduced to 60 days. As a result, the dates in the figures
for those caverns do not match the real-world dates. The reduction in equilibration time results in
minimization of the impact of the error.

4. NEAREST APPROACHES BETWEEN CAVERNS
Taking into account cavern growth observed in recent sonars, we have calculated nearest approaches
for each of the SPR caverns. The CY24 report included these calculations for a subset of caverns, but
this report establishes a baseline reference for inter-cavern distances. 2 The baseline will be updated in
subsequent annual reports when new data on cavern geometries (e.g., sonars) become available. The
purpose of calculating the nearest approaches is that there are potential ramifications on cavern
integrity if the stress fields from adjacent caverns interact, which can lead to inter-cavern
communication. The calculation of these 3D distances between caverns at all sites will aide in assessing
cavern integrity.
A Python program was developed for the CY24 report (which continues to be used for this report)
to calculate nearest approaches between two caverns based on sonar geometries. The distance between
each data point from each sonar is calculated and the shortest distance is kept for each cavern pair. In
each case, the latest sonar is used, except where a partial sonar is the latest, in which case, a full cavern
representation is created based on combining the partial sonar with the next oldest sonar. Tables of
nearest neighbors are presented for each cavern. Also, figures showing the closest approach are
presented. In the figures, any section of the cavern displayed as white is from a previous sonar that
was combined with the latest partial sonar.
As part of the sonar setup, the nodal data were resampled in order to get higher resolution input files
for the nearest approach calculations. This process was done using the Earth Volumetric Studio (EVS)
Triangle Refinement module. For the individual sonar files, the maximum edge length between nodes
was set to 25 feet. For the dome files, the maximum edge length between nodes was set to 100 feet to
accommodate the larger dome file sizes. An example of sonar nodal data before and after the
refinement process for BM5 can be seen in Figure 4-1 below. The post-refinement nodes show more
detail in the cavern geometry, especially in areas with irregular shapes or anomalous features. This
process allows for higher resolution nodal data, which is able to better represent the cavern geometry
and provide more accurate nearest approach values.

2 In addition to SPR cavern locations, the edge-of-salt location and nearby non-SPR caverns are also used to determine

the nearest approaches.

Leaching predictions, such as those produced from SANSMIC runs, have the potential to impact
nearest approach calculations as cavern walls from adjacent caverns can become closer. The current
approach only considers cavern geometries based on the most recent sonars. However, substantial
leaching may occur in the future after a sonar, so the Python program can be modified to incorporate
calculated cavern growth from SANSMIC calculations.

5. SUMMARY AND CONCLUSIONS
Only three caverns had substantial raw water injected in CY25, totaling about 1 MMB. An additional
five caverns had sonars performed in CY25, one of which followed new leaching, which allowed for
studying of the effects of leaching from previous years. Leaching effects were monitored in these
caverns to understand how the sales operations may impact the long-term integrity of the caverns.
While frequent sonars are the most direct means to monitor changes in cavern shape, they can be
resource intensive for the number of caverns involved in sales and exchanges. An intermediate option
is to model the leaching effects and see if any concerning features develop.
The leaching effects were modeled here using the Sandia Solution Mining Code (SANSMIC). The
results indicate no new leaching induced features of concern and therefore the monitoring list remains
unchanged this year. Twenty-four caverns still have features that should be monitored in future
leaching efforts. For the one cavern with a CY25 sonar that followed leaching (WH103), SANSMIC
was able to capture the leaching well.
Several improvements have been made to the leaching calculation workflow. Most importantly, the
Python notebook template has been expanded to allow for automated input file creation, running, and
post-processing with a single button press. This streamlining of the SANSMIC run process allows for
easier setup and analysis of “what-if” leaching calculations beyond the annual monitoring.
Additionally, the OBItool was created to calculate real-world OBI depths with time, so that more
accurate estimates of initial OBI depths would be available for input into leaching calculations.
A new feature of the leaching report is the calculation of nearest approaches for all caverns. This was
done for a subset of caverns in the previous report but has been extended to a baseline for all caverns
now. The purpose of calculating the nearest approaches is that there are potential ramifications on
cavern integrity if the stress fields from adjacent caverns interact, which can lead to inter-cavern
communication. There are eight closest approaches less than 300 ft across all sites. There are five
closest approaches less than 200 ft: 1) BC20 and the edge of the BC Dome (80.8 ft); 2) WH8 and
WH9 (127.5 ft); 3) BC15 and BC17 (163.2 ft); 4) BM1 and BM107 (183.9 ft); and 5) BC18 and BC17
(184.4 ft). As leaching proceeds in SPR caverns, nearest approach differences will change and will be
monitored in this annual report.

APPENDIX A. WORKFLOW FOR SETTING UP, RUNNING, AND POST-
 PROCESSING SANSMIC RUNS
This appendix describes the steps for setting up, running, and post-processing a SANSMIC leaching
run using new Python notebook template.

A.1. Setting Up SANSMIC Input
The setting up of a SANSMIC run using the notebook template includes the following steps:
 1. Use copy of Python notebook template for each cavern.
 2. Create file structure with four folders.
 a. 01-fluidmovements for pre-run fluid movement analysis
 b. 02-sonar for pre-run sonar analysis
 c. 03-setup_SANSMIC for pre-run input file creation and simulation input table
 d. 04-run_sansmic for output data and post-processing analysis
 3. Obtain most recent sonar file prior to raw water injection time of interest (a separately-
 processed layer-cake.LAS file has the sonar data in 1-ft depth increments).
 a. Input sonar file in 02-sonar and filename in notebook.
 b. Repeat this step if there is a follow-up sonar at the end of raw water injection.
 4. Obtain fluid movement data from CAVEMAN (download daily fluid movements
 spreadsheet or get data using SQL query—see Appendix B.1).
 a. Determine first and final raw water injection times.
 b. Divide raw water injection history into stages based on similar injection rates and
 taking into account long times without injection.
 c. Create text file of daily data entries (fluid_year.dat) including: stage, date, injection
 volume and put in 01-fluidmovements.
 5. Obtain OBI log data from the closest time before the first raw water injections following the
 most recent sonar (use SPRWL database and also check sonar report).
 a. Use OBItool (see Appendix B.2) to determine OBI depth at the beginning of raw
 water injection and at the beginning of any other subsequent stage when there has
 been non-water fluid movements between stages.
 b. Input OBI depths into notebook for each stage.
 c. Put OBItool output over entire injection time period into text file for comparison in
 post-processing (CAVEMANobiTrack.txt).
 d. Put any available OBI log data during injection time period into text file
 (OBIdata.txt).
 6. Obtain EOT depths in the range of raw water injection times from weekly site reports.
 a. If there are more than one distinct EOT during a currently-defined stage, divide that
 stage so that there is only one EOT per stage.

 125

 b. Input EOT depths into notebook for each stage.
 7. Obtain UCS (User Coordinate System) coordinates for x- and y-positions of the cavern from
 latest sonar (these are used to create a text file for using in generating a cavern shape—see
 Appendix B.3).
 a. Input coordinates into notebook.

A.2. Running SANSMIC
The running of a SANSMIC run using the notebook template includes the following steps:
 1. Decide whether SANSMIC is to be run in the notebook or outside of the notebook.
 a. If so, set runsansmicinnotebook variable to True.
 b. The running of SANSMIC inside the notebook is more convenient, but can take
 more time. In some cases of longer runs, the computer may run out of memory
 space to continue performing the calculation. In this case, the runsansmicinnotebook
 variable should be set to False and the notebook should be restarted. It will run
 through the setup section. Then, SANSMIC will need to be run outside of the
 notebook using the command line provided in the notebook and the input file
 created by the notebook (located in 03-setup_SANSMIC). After completion of the
 SANSMIC run, the post-processing section can be run to completion.
 2. Run the notebook from the beginning. This will run the pre-run steps to import fluid
 movement data and sonar geometry data (set up in A.1 above). Then it will run SANSMIC.
 Then it will run the post-processing steps (described in A.3 below).
 3. Whether SANSMIC is run inside or outside of the notebook, results are written to .csv files
 that are then read in by the notebook for post-processing.
 4. A .toml file is created that shows the input parameters for the SANSMIC run, but SANSMIC
 is not run using that .toml file.

A.3. Post-processing SANSMIC Results
The post-processing of a SANSMIC run using the notebook template includes the following steps:
 1. Review the output automatically generated from the running of the notebook. The outputs
 include:
 a. Raw water movement figure in 01-fluidmovements (fluid_year.png). This shows the daily
 and cumulative raw water movements for all stages in the SANSMIC run.
 b. Simulation output table text file, including specific gravity and leaching efficiency for
 each stage (final.stats; this and the remaining figures and output text files are located
 in 04-run_sansmic).
 c. Geometry text file for use in generating cavern shape (Profile.txt; see Appendix B.3).
 d. Geometry figure including original and final cavern geometry (i.e., radius with depth)
 (geometry.png).
 i. Additional geometry figure including geometry of follow-on sonar, if
 available (sonarcomp.png).

 126

 e. Cavern growth figure showing radial growth with depth between the original and
 final geometries (growth.png).
 i. This growth figure includes growth between sonars, if follow-on sonar is
 available.
 f. Leaching figure including leached volume and leaching efficiency with time
 (leaching.png).
 g. OBI history figure including simulated and any real OBI data (obi.png).
 h. OBI output text file including SANSMIC OBI depths at the time of any OBI log
 data for comparison (obicomp.txt).
2. After reviewing, adjust the locations of any text on the figures using preset variables at the
 top of the notebook.
 a. Rerun individual post-processing sections to update figures.
 b. All figures are shown in the notebook in addition to the creation of stand-along
 figure (.png) files.

APPENDIX B. DETAILED INSTRUCTIONS FOR SOME PRE- AND POST-
 PROCESSING STEPS

B.1. SQL query for extracting fluid movement data from SPR-CAVEMAN
 database.
An SPR fluid movement SQL database is available at SNL and can be queried. The database is called
SPR_CAVEMAN. Use of a query like that shown in Figure B-1 will return daily fluid movement
data, for each day that there is some fluid movement, in the following categories: brine, brackish,
raw_water, and oil. The raw_water values are used for raw water volumes (i.e., SANSMIC injection
input) and oil values are used by the OBItool (see B.1 below) to calculate OBI depths with time.
SELECT TOP (1000) [name]
 ,[date]
 ,[brine]
 ,[brackish]
 ,[raw_water]
 ,[oil]

B.2. Instructions for using OBItool spreadsheet to calculate OBI depths at
 any time.
The OBItool is an Excel spreadsheet that calculates OBI depths given the following information:
 1. Cavern volume with depth (i.e., “strapping curve”), likely taken from most recent sonar.
 2. Initial OBI depth from log taken at time of (or subsequent to) sonar used for strapping
 curve.
 3. Oil movement data (see B.1 above).
The OBItool simply tracks the movement of the OBI depth up and down in the cavern as oil goes
out and into the cavern. It does not consider any changes in the cavern shape or size due to leaching
or salt creep.

B.3. Instructions for generating .dxf file for use in EVS figure creation.
Cavern shape figures like those shown in Figure 1-5 are created using the EVS software. To produce
a 3-D cavern shape figure from the 2-D geometry calculated by SANSMIC, the SANSMIC output
must first be converted to a 3-D shape using the CloudCompare software. The SANSMIC geometry
is output along with the UCS coordinates into a text file that can be read into CloudCompare where
a .dxf file can be exported. The .dxf file can then be read by the EVS software. The steps for using
the CloudCompare software to create a .dxf file are:
 1. Load 2D file of a surface of revolution (i.e., profile) from an ASCII file (icon shaped like red
 squiggly line).

 128

2. Loading of the profile generates a “vertices” component. Select both the profile and vertices
 (while holding down the CTRL key).
3. Compute radial distance between a cloud and a surface of revolution (icon shaped like red
 squiggly line with colored balls).
4. Answer yes to question about generating a 2D deviation map and accept comment that
 “cloud is flat.” This will open the 2D distance map box.
5. Select Apply, then Mesh, then Close. This will generate the vertices.map.
6. Select the vertices.map, then choose File, then Save, and choose a location to store the .dxf
 file. With the standard amount of data in a SPR cavern geometry, the .dxf file is about 300-
 400 MB in size.
