Project Overview

 1. Problem / Opportunity
The newest neutron analysis methods have surpassed the capabilities of the IAEA’s neutron
measurement software INCC5. Some of the latest measurement instruments have required custom
software to implement their measurement algorithms, and some techniques have no software
implementation. Requiring custom software adds project costs and complexity for the IAEA to
understand, use, and manage more pieces of software. Custom software also misses the familiar and
standard INCC features such as standard report formats, normalization, and background subtraction,
that should be identical across all instruments. Further, custom software isn’t readily adaptable to new
instruments.
One example is the Uranium Cylinder Verification Station (UCVS) for cylinders at gas centrifuge
enrichment plants (GCEPs). UCVS uses custom software with a novel position corrected efficiency (PCE)
technique to measure the distribution of UF6 within an item and correct for the detection efficiency.
Another example is the Glovebox Unattended Assay and Monitoring system (GUAM) for plutonium
holdup in gloveboxes at Japan’s JMOX facility. The GUAM evaluation demonstrated a novel local
coincidence veto (LCV) technique to balance the sharp increase in efficiency as material gets closer to
the detectors on the glovebox walls, but to our knowledge the custom LCV source code has been lost.
Another technique, which is instrument agnostic, is distributed source term analysis (DSTA) which was
created for mapping uranium distributions in facilities such as GCEPs but can be applied to any
distributed nuclear material in any 3D space.
These techniques have and would enhance the effectiveness of the IAEA’s neutron NDA capabilities by
improving accuracy and precision for challenging, novel applications. They rely on list mode data
collection, which records data from individual sensors within an instrument, providing spatial

 3

distributions. INCC6 was created primarily to be compatible with the modern IAEA software suite (for
example, using new unattended measurement data formats), but an additional new feature is that it can
collect, analyze, and report list mode data.
INCC6 is undergoing active development, and integrating these methods would enable their use in all
past and future list mode instruments. It would also increase operational efficiency by consolidating the
IAEA’s capabilities into their already-adopted software.

 2. Proposed Solution
We propose to incorporate the following three techniques into INCC6. The LCV technique will also result
in a robust “coincidence matrix” feature (see below):

 1. Position Corrected Efficiency uses the distribution of measured counts to infer a distribution of
 material and thus detection efficiency. Without this technique the average efficiency must be
 assumed, but the increased precision of PCE can reduce positional errors by 10s of percent in
 applications like waste drums.

 2. Local Neutron Coincidence Veto is an existing data filtration technique that identifies and
 rejects neutron signals that originate from areas of poor efficiency. This reduces uncertainty and
 enables more accurate background subtractions. For unattended measurements in complex
 spatial environments stabilization of detector efficiency is critical for meaningful calibrations and
 assays.

 LCV requires the production of a coincidence matrix, which will be a byproduct of this work. A
 coincidence matrix is a calibration-free measurement of the distribution of material which is an
 additionally useful system integrity and diagnostic signature.

 3. Distributed Source Term Analysis can be used to estimate locations of holdup or quantities of
 bulk material in large, complex environments without direct measurement of each individual
 piece of equipment. Minimal design information is needed as a priori for modeling. Identifying
 locations of source material improves the accuracy of background subtractions and
 consequently mass assay.

Note, including all planning/testing, we can implement each feature for $75k each
INCC is known for its useability, where non-experts can set up new instrument calibrations in just a few
minutes. Once set up, verification measurements take just a few button presses, complex physics
calculations happen behind the scenes, and the results are automatically stored and organized in the
software’s database. We will apply this same philosophy to these new features, ensuring that they
happen seamlessly to allow inspectors to focus on their other tasks. The features will be instrument
agnostic. Further, we will incorporate the features into the INCC command line capability to allow
integration with the IAEA’s unattended monitoring software suite.

 4. Innovation / Best Approach
This approach combines the latest measurement analysis algorithms with tried-and-true IAEA software,
increasing the reach of existing recent innovations. Recent developments in multichannel assay systems
creates an opportunity to develop features in the INCC6 software to improve measurement data. Data
from the existing UCVS and GUAM systems, and future advanced systems, could be processed with
efficiency correction methods which would increase accuracy and reduce errors. This approach is a step
towards fuller utilization of list-mode data. We believe that providing robust list mode software
capabilities will result in far better advancements created by IAEA and national lab experts than we
would ever create on our own.

This project team is suited to complete this work because the members are the INCC software
developers and the measurement SMEs have significantly contributed to the development of UCVS and
GUAM.

 5. Outcomes
The proposed work would add the three analysis methods as tools to the IAEA’s INCC software.
Implementing these features would allow lower uncertainty in list mode measurements due to source

 5

material position. This will save time and improve efficiency for inspectors working in the field. The
product would be a new version of INCC6 with these features.
At the direction of NPAC, the IAEA and JMOX will be able to receive an updated version of INCC6 with
these features implemented. There will be an included API so that the IAEA can integrate the new
features into IRAP.

 6. Project Risks and Planned Mitigation
Our FY25 work to add other features has gone smoothly and so we do not anticipate major risks. The
major risk of FY25 was the senior software developer’s likely retirement. That may occur in FY26 but the
knowledge transfer to Megan under the FY25 project has already ensured a smooth transition.

 10. Supplemental Task Details
Task 1: Develop Software Requirements

The document will contain:
 • Essential required features, the “must have” features
 • Optional features that may be useful, or fall out of the required features, “good to have”
 • Performance metrics (time to run on various channel sizes, e.g., 1 channel v. 96 channels)
 • Host machine recovery metrics (restarts automatically, catches up on skipped or missing data)
 • Correctness: Calculations must be correct, compared with simulation and manual calculations.
 • Novel algorithms to be described in detail for implementation.
 • Test procedures and expected test outcomes, as far as can be specified at an early stage
Task 1 Deliverable/Milestone: Software Requirements Report

Task 2: Incorporate features into INCC6
 • All new features, e.g. PCE, LCV, DSTA, will be integrated into the application codebase. Each new
 diagnostic feature will have a graphical display for analysis setup and data display.
 • Reporting, persistence, and retrieval of calculated diagnostic intermediate and final results will
 be to added to the application codebase.
 • Updated user documentation will be created as the above features are completed.
Task 2 Deliverable/Milestone: The completion of the features into INCC6

Task 3: Test and Finalize Features
The new features of INCC6 will be tested with existing systems. The team has access to a variety of
neutron counters detector arrays. These systems will be leveraged to test the new INCC6 features.
Measurements with a variety of samples (different matrices, impurities, strengths, etc.) will be
performed and the automated results from INCC6 will be compared to known values for PCE, LVC and
DSTA.
Based on the results of this task, the software will be updated as required. These updates will be tested
through repetition of the steps outlined above, and the results will be documented for dissemination to
the broader scientific community, and to guide future activities.
Task 3 Deliverable/Milestone: Acceptance Tests of features (also serves as Final Report)
