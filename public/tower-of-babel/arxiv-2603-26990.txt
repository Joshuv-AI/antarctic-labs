Agentic Diagrammatica: Towards Autonomous Symbolic Computation in High Energy Physics
Tony Menzo, Alexander Roman, George T. Fleming, Sergei Gleyzer, Konstantin T. Matchev, Stephen Mrenna

Abstract




Abstract

We present
Diagrammatica
, a symbolic computation extension to the HEPTAPOD agentic framework, which enables LLM agents to plan and execute multi-step theoretical calculations.
Symbolic computation poses a distinctive reliability challenge for LLM agents, as correctness is governed by implicit mathematical conventions that are not encoded in a form that can be easily checked in the computational backend.
We identify two complementary remedies, tool-constrained computation and targeted knowledge grounding, and pursue the first as the primary architecture.
Concretely, we concentrate the agent’s action distribution onto tool calls with convention-fixing semantics, in which the agent specifies a compact, human-auditable diagram specification and a trusted backend performs the symbolic or numerical manipulations exactly.
The toolkit provides two complementary calculation paths consuming a shared diagram specification: Naive Dimensional Analysis (NDA) for order-of-magnitude rate estimates and Exact Diagrammatic Analysis (EDA) for tree-level symbolic calculations via automatic FeynCalc code generation, both supplemented by automatic Feynman diagram enumeration and a navigable theory knowledge base.
The architecture is validated on two benchmarks:
(1) an exhaustive catalog of all tree-level, single-vertex
1\to 2
partial decay widths across scalar, fermion, and vector parents, with complete massless and threshold limits and Standard Model validation; and
(2) an NDA sensitivity study of the muon decay multiplicity
\mu\to\nu_{\mu}\bar{\nu}_{e}+n(e^{+}e^{-})+e^{-}
, determining the maximum observable
n
at current and planned muon experiments.

Agentic symbolic programming

2.1
Reliability, uncertainty, and the case for tool-constrained calculation

The primitive outputs of an LLM agent, operating at decision step
t
with context
C_{t}
, are sequentially and recursively generated token sequences
x_{t+1:t+m}
of varying length
m
over some
vocabulary

\mathcal{V}
, sampled from a
\theta
-parameterized autoregressive distribution

p_{\theta}(x_{t+1:t+m}\mid C_{t})

(2.1)

representing the probability of the next token sequence
x_{t+1:t+m}
, given the previous context
C_{t}
. In practice, the actual quantity of interest isn’t the raw token sequence but the
action
,
\mathcal{A}
, it implements
i.e.
the code block it produces, the natural-language instruction it conveys,
etc
.
Agentic programming fundamentally operates on this action abstraction.
Many distinct ‘microscopic’ token sequences can implement the same ‘macroscopic’ action, so a given action naturally forms an equivalence class whose probability is obtained by marginalizing over all implementing sequences of any length
m
,

p(\mathcal{A}_{t}\mid C_{t})\;=\;\sum_{m=1}^{\infty}\;\sum_{\{x_{t+1:t+m}\,\mapsto\,a\}}p_{\theta}(x_{t+1:t+m}\mid C_{t}).

(2.2)

A particularly important action in agentic programming is the
tool call
.
A tool is an external computational backend—a function, script, or service—exposed to the agent in the initialization context
C_{0}
through a convention-dependent schema specifying its name, inputs, and return types. A tool call is then a token sequence that forms a structured JSON object matching this schema, which the inference serving infrastructure can intercept and route to that backend (typically the user’s machine).
Importantly, adding or removing tools doesn’t change the model’s token vocabulary, but for particular tasks it can significantly reshape the conditional distribution of
eq.

2.2
by concentrating probability mass onto the structured subset of the action space corresponding to valid tool invocations.
Some inference providers enforce this concentration even more strongly through constrained decoding
[
47
]
, in which tokens incompatible with the tool schema are masked to zero probability at each generation step.

The practical value of concentrating
p(\mathcal{A}_{t}\mid C_{t})
depends on the task.
The obvious candidates are exact arithmetic, external state access, and formal grammar adherence.
More subtle, and more relevant here, are tasks where the correctness criteria are implicit — nowhere encoded in a form the computational backend can check against reliably.
Symbolic computation occupies this category.
Unlike compiled code, where type errors and syntax violations halt execution and provide immediate feedback, a computer algebra system has no equivalent system to check its input against. Correctness is defined
implicitly
by the mathematical conventions of the domain, which are external to the system itself.
An LLM navigating this space without external structure can only rely on statistical correlations in its training data, correlations that are themselves unreliable, since conventions in the literature are not always unanimous.

A high-energy physics symbolic calculation is a particularly acute instance, where conventions are numerous, interrelated, and drawn from a literature in which different sources make incompatible choices.
A correct calculation may have to simultaneously respect consistent choices for the metric signature (
+{-}{-}{-}
vs.
-{+}{+}{+}
), spinor normalization (
\bar{u}u=2m
vs.
\bar{u}u=1
), the sign of the covariant derivative, the normalization of
\mathrm{SU}(N)
generators (
\operatorname{Tr}[T^{a}T^{b}]=\delta^{ab}/2
vs.
\delta^{ab}
), the choice of gauge, and the phase conventions in CKM and PMNS matrices, among others.
An LLM trained on the full literature will have seen all of these conventions represented, often without explicit declaration, and the statistical correlations it relies on are precisely the wrong tool for enforcing internal consistency across a multi-step calculation where every convention choice must be made once and propagated uniformly.

Trusted symbolic computation with LLM agents therefore requires that the action space be restricted to tools where a fixed set of conventions is encoded in the computational backend, or that additional context be provided to the agent fixing the conventions explicitly.
Developing tools that provide these semantic constraints reliably for common HEP computations is the main focus of this work.
The simplest way to realize this is to alter what inputs the agent operates on: instead of asking the model to realize the calculation directly in free-form symbolic text, one asks it to specify a typed action whose arguments correspond to physically meaningful choices—vertex class, external spins, topology, mass assignments, and other convention-fixing data—and the backend performs the algebra exactly.
In this design, the LLM is responsible for selecting the correct calculation, while the symbolic engine is responsible for executing it.
A similar principle underlies the reliability of LLM-based theorem proving in Lean
[
49
]
, where probability mass is concentrated on valid proof tactics verified against a structured proof state rather than on free-form natural-language reasoning.
The resulting
verification asymmetry
shifts the locus of human oversight from a high-dimensional verification problem to a low-dimensional one. It is easier to audit a compact, human-readable diagram specification with a few physically meaningful fields than a full generated script.

To organize the case for tool-constrained calculation quantitatively, it is useful to decompose the uncertainty of the agent’s action distribution, measured by the conditional Shannon entropy

\Delta_{\mathcal{A}}(C_{L})\;\equiv\;H(\mathcal{A}_{t}\mid C_{L})\;=\;-\sum_{a}p(a\mid C_{L})\,\log_{2}p(a\mid C_{L}),

(2.3)

where
L
denotes the amount of context provided, into three components with qualitatively distinct origins and architectural remedies:

\Delta_{\mathcal{A}}(C_{L})\;\approx\;\underbrace{\Delta_{T}(C_{0})}_{\begin{subarray}{c}\text{task}\\
\text{uncertainty}\end{subarray}}\;+\;\underbrace{\Delta_{C}(L)}_{\begin{subarray}{c}\text{context}\\
\text{uncertainty}\end{subarray}}\;+\;\underbrace{\Delta_{E}}_{\begin{subarray}{c}\text{execution}\\
\text{uncertainty}\end{subarray}}.

(2.4)

This decomposition is approximate (ignoring possible correlations between components, for example) but it identifies three distinct failure modes of free-form agentic generation, each mapping onto a concrete design decision in the toolkit.

\Delta_{T}(C_{0})
captures ambiguity in

.

\Delta_{T}
decreases as relevant task-specifying context (

Below

the agent is genuinely uncertain about what it is computing; above

\Delta_{E}
is the variability introduced by generating the calculation as unstructured token-by-token output.

\Delta_{E}
is largely
independent of how much documentation is in the context
.
Reference material loaded in bulk does not suppress token-level variability at critical positions (function names, index placements, sign choices, convention-dependent prefactors) because the agent must still retrieve and apply the right convention at the right moment from a long context, so
\Delta_{E}
appears as a roughly constant offset in the

The most direct remedy is to constrain the action space

, replacing free-form generation with a schema-validated tool call that limits every feasible completion to a physically meaningful choice and eliminates the silent-error modes described above.
A qualitatively different mechanism is to deliver targeted domain knowledge

\Delta_{C}(L)
is the degradation of attention and retrieval fidelity as context length grows
[

.
Unlike
\Delta_{T}
, this term
increases
with

, introducing a fundamental tension in which adding context to resolve task ambiguity simultaneously inflates context-induced errors.
There is a natural scale

marking the onset of this degradation.
When
L_{T}\ll L_{C}
, the task is fully resolved before degradation sets in and reliable operation is possible.
When
L_{T}\gtrsim L_{C}
, the documentation needed to resolve the task pushes the context past the degradation onset, and the workflow becomes unreliable regardless of how much reference material is provided.
The remedy is to increase the information density of each context token by structuring domain knowledge as compact, retrievable nodes rather than raw long-form text
[
24
]
, exposing exactly the information the agent needs in a small number of tokens and shifting
L_{C}
to larger values.
Crucially, when such a node is retrieved
on demand at the moment
the agent faces a convention-dependent choice, it not only avoids inflating
\Delta_{C}
but also partially suppresses
\Delta_{E}
by resolving the specific ambiguity at the point where execution variability originates.
It is the
timing of delivery
, not the content, that distinguishes this from bulk documentation (see
section

2.3
).

Finally, it is reasonable to expect an irreducible floor
\varepsilon>0
in the action entropy of any finite autoregressive model. Even with perfect context and a fully constrained action space, the stochastic sampling procedure and finite model capacity prevent the conditional distribution from collapsing to a delta function on the correct action.
Whether such a floor can be made rigorous, and how it scales with model size, is an open question; for the present purposes it suffices to note that the three architectural remedies above—structured specifications, tools, and skills—are designed to reduce the
controllable
components of
\Delta
as far as possible, leaving whatever irreducible residual remains as the dominant source of uncertainty.

2.2
A token-level illustration

The suppression of each uncertainty component by the corresponding architectural remedy can be made explicit at the level of individual token predictions.
Consider an agent that receives the prompt:

User

Compute the tree-level partial width for a scalar particle
S
decaying to a fermion–antifermion pair via a Yukawa interaction
\mathcal{L}\supset\bar{\psi}(g_{S}+g_{P}\gamma_{5})\psi\phi
.
Retain general masses and both scalar and pseudoscalar couplings.

For a well-posed prompt like the one above, the task uncertainty
\Delta_{T}
is already small, the parent particle, daughters, vertex type, and desired output are all explicitly stated.
How small depends on the model’s pretraining corpus and resulting familiarity with the domain, a model without QFT in its training data would have high
\Delta_{T}
regardless of how precise the prompt is.
A correct response using FeynCalc
[
27
,
40
]
requires the following six steps, common to every
1\to 2
decay supported by the toolkit.

1.

Write the invariant amplitude.

For a general scalar–pseudoscalar Yukawa vertex,

i\mathcal{M}=\bar{u}(p_{1})\,i(g_{S}+g_{P}\gamma_{5})\,v(p_{2}).

(2.5)

This is the
only
process-specific ingredient; all subsequent steps are determined by it.

2.

Form the spin-summed squared amplitude.

Square
\mathcal{M}
, sum over final-state spins, and apply the completeness relations
\sum_{s}u\bar{u}=\not{p}_{1}+m_{1}
and
\sum_{s}v\bar{v}=\not{p}_{2}-m_{2}
.
No initial-state spin averaging is needed for a scalar parent.

3.

Evaluate the Dirac trace.

The spin sum produces a single trace,

\sum_{\text{spins}}|\mathcal{M}|^{2}=\operatorname{Tr}\!\bigl[(\not{p}_{1}+m_{1})(g_{S}+g_{P}\gamma_{5})(\not{p}_{2}-m_{2})(g_{S}-g_{P}\gamma_{5})\bigr],

(2.6)

which separates into
g_{S}^{2}
and
g_{P}^{2}
contributions; mixed
g_{S}g_{P}
terms vanish by the trace of an odd number of gamma matrices.

4.

Apply two-body kinematics.

All scalar products reduce to masses:
p_{1}\cdot p_{2}=(M^{2}-m_{1}^{2}-m_{2}^{2})/2
.

5.

Assemble the partial width.

\Gamma=\frac{|\vec{p}\,|}{8\pi M^{2}}\sum_{\text{spins}}|\mathcal{M}|^{2},\qquad|\vec{p}\,|=\frac{\lambda^{1/2}(M^{2},m_{1}^{2},m_{2}^{2})}{2M},

(2.7)

where
\lambda(a,b,c)=a^{2}+b^{2}+c^{2}-2ab-2bc-2ca
is the Källén function.

6.

Simplify and extract limits.

For equal daughter masses
m_{1}=m_{2}=m_{f}
,

\Gamma(S\to f\bar{f})=\frac{M}{8\pi}\sqrt{1-\frac{4m_{f}^{2}}{M^{2}}}\left[g_{S}^{2}\!\left(1-\frac{4m_{f}^{2}}{M^{2}}\right)+g_{P}^{2}\right].

(2.8)

The massless limit gives
\Gamma=(g_{S}^{2}+g_{P}^{2})\,M/(8\pi)
.

Steps 2–6 are purely mechanical, determined entirely by the vertex structure and external-state quantum numbers chosen in step 1, yet generating them as free-form FeynCalc code requires the agent to make approximately
N_{c}\sim 15
critical token-level decisions: the relative sign in the
v
-spinor completeness relation (
\not{p}-m
, not
\not{p}+m
), the sign of
\gamma_{5}
in the conjugate vertex, the correct FeynCalc function for trace evaluation, the kinematic substitution rule for
p_{1}\cdot p_{2}
, and the phase-space prefactor with the correct power of
M
, among others.
At each such position, different token choices produce physically distinct amplitudes so the token-level entropy at critical positions is a reasonable proxy for the action-level entropy of
eq.

2.2
.
The joint entropy of the full output sequence satisfies the chain rule
H(x_{1},\ldots,x_{m})=\sum_{i}H(x_{i}\mid x_{<i})
, but the conditional entropy is near zero at the majority of positions, where the next token is determined by syntax and code structure.
The sum is dominated by the
N_{c}
critical positions where convention-dependent choices arise, precisely because these are the positions at which the training corpus contains multiple incompatible conventions and the model’s conditional distribution reflects this ambiguity.
Under the simplifying assumption that critical-token errors are approximately independent, which should be reasonable when they occur in distinct algebraic steps, the total execution entropy is bounded by
N_{c}\cdot h
, where
h
is the local conditional entropy at each critical position.
At each such position,
h\sim\mathcal{O}(\text{few})
bits, set by the effective vocabulary of
n\sim 10
–
30
plausible alternatives that carry non-negligible probability mass after the softmax
2
2

2

The effective vocabulary
n
at a given position refers not to the full token vocabulary
|\mathcal{V}|
, which is typically
\mathcal{O}(10^{5})
, but to the number of tokens with logit values within a few units of the maximum. The remaining tokens contribute negligibly to the conditional entropy.
.
This gives an upper bound on the total execution entropy,

\Delta_{E}^{\text{free-form}}\;\lesssim\;N_{c}\cdot h\;\sim\;45\text{--}75\penalty\ \text{bits}.

(2.9)

A more direct measure of the practical impact is the success probability. Assuming a per-position error rate of
\epsilon\sim 0.05
, the probability that all
N_{c}
critical tokens are correct is
(1-\epsilon)^{N_{c}}\approx 0.46
.
The conclusion is insensitive to the precise value of
\epsilon
, even at
\epsilon\sim 0.02
, the success rate is only
\sim\!74\%
, a failure rate that compounds rapidly when sweeping systematically over many processes.
The situation worsens if the agent resolves FeynCalc conventions by ingesting raw documentation, where the relevant formula is buried among thousands of tokens
[
25
]
, inflating
\Delta_{C}
simultaneously.

Schema-validated tools reduce the viable token vocabulary at two levels.
First, the tool definitions injected into
C_{0}
make a structured tool invocation the natural next action given the context, concentrating probability mass away from free-form symbolic code generation entirely.
Second, the tool call schema constrains each argument to a small enumerated set of valid field values.
Much like integrating out heavy degrees of freedom in an effective field theory collapses the path integral onto a smaller set of dynamical variables, the combined effect suppresses the next-token probability for the vast majority of
|\mathcal{V}|
, leaving an effective vocabulary of
n^{\prime}\sim 10
tokens per decision point.
The agent specifies only
N_{c}^{\prime}\sim 3
–
5
such fields (parent spin, daughter spins, vertex type), each drawn from an enumerated set of
n^{\prime}\sim 10
valid values.
The local conditional entropy per field is
h^{\prime}=\log_{2}n^{\prime}\approx 3.3
bits, so the total execution entropy is bounded by

\Delta_{E}^{\text{tool}}\;\lesssim\;N_{c}^{\prime}\cdot h^{\prime}\;\sim\;10\text{--}17\penalty\ \text{bits}.

(2.10)

Crucially, all of this residual uncertainty is concentrated in a human-readable specification that a domain expert can audit at a glance, while a targeted skill retrieval of
\sim\!200
tokens replaces the raw documentation, suppressing
\Delta_{C}
and partially concentrating the distribution at convention-dependent decision points.
The compression is not a consequence of a more capable model; it comes from shrinking the space of actions the model can take, so that even a mediocre distribution over it has low entropy.
This observation motivates the architecture described in
section

3
: a shared structured specification that minimizes
\Delta_{T}
, schema-validated tools that compress
\Delta_{E}
, and a navigable theory knowledge base that suppresses
\Delta_{C}
while also partially addressing
\Delta_{E}
through targeted knowledge injection (
section

2.3
).

2.3
Tool constraints versus knowledge grounding

The execution uncertainty
\Delta_{E}
identified in the previous section admits two complementary remedies that, despite both involving the delivery of information to the agent, operate through qualitatively different channels and offer fundamentally different tradeoffs.

The first mechanism, emphasized in this paper, is
tool-constrained computation
.
Instead of asking the agent to generate the symbolic calculation, the action space is restricted to schema-validated tool calls that fix conventions by construction.
The agent specifies
what
to compute through a diagram specification, and a trusted backend determines
how
to compute it by performing the algebra exactly.
This drives
\Delta_{E}
to near zero
structurally
, since correctness is a consequence of the interface design rather than the model’s knowledge, and holds regardless of what context the agent has seen.
The cost is that the agent’s capabilities are bounded by the tool designer’s foresight.
It can compute any decay width the tools support, but it cannot notice that two seemingly unrelated results satisfy an unexpected identity, propose a novel parameterization, or derive a relation that the tool vocabulary does not anticipate.
The tools define the ceiling.

The second mechanism is
knowledge-grounded computation
.
As discussed in
section

2.1
, bulk reference material loaded into context does not suppress
\Delta_{E}
because the agent must still retrieve and apply the right convention at the right moment from a long context, which is essentially a
\Delta_{C}
problem.
What distinguishes
targeted
knowledge injection is timing.
A skills-graph node retrieved on demand at the exact moment the agent faces a convention-dependent choice directly concentrates the token distribution at that position, resolving the specific ambiguity that drives execution variability.
This is not “more context” in the sense of the
\Delta_{C}
analysis but rather context that acts at the
locus
of
\Delta_{E}
.
The distinction from task-specifying context, which reduces
\Delta_{T}
by clarifying
what
to compute, is equally important.
Targeted knowledge addresses
how
to execute a step that is already specified, not what the step should be.
The result is a partial, probabilistic suppression of
\Delta_{E}
, not the structural guarantee of tool constraints, but a genuine reduction that scales with the quality and specificity of the injected knowledge.
The advantage is that the full action space remains available.
A knowledge-grounded agent could in principle recognize patterns across calculations, derive new identities from first principles, or explore parameterizations that the tool designer never considered.
The ceiling is set by the model’s reasoning capability, not by the tool vocabulary.

In practice, the choice between these mechanisms is not binary but a spectrum, and the optimal design point depends on the nature of the task.
Mechanical steps where creativity adds no value and errors are catastrophic (Dirac traces, spin sums, polarization averaging, phase space integration) should be tool-constrained.
Strategic steps where judgment and exploration are valuable (which process to study, what limits to take, how to organize a survey of many processes) benefit from free-form reasoning grounded in domain knowledge.
The Diagrammatica toolkit already makes this split implicitly: the agent reasons freely about strategy while using tools for tactical execution.
Naming it explicitly as a design principle clarifies both the strengths and the limitations of the current architecture.

The two approaches are also complementary in practice, since an agent that explores freely with knowledge grounding can confirm its results via EDA tool calls, combining the discovery potential of the first approach with the reliability guarantees of the second.
This suggests a natural trajectory for future agentic systems, beginning with the tool-constrained architecture presented here and progressively expanding the boundary of free-form reasoning as the knowledge base deepens and verification tools mature.

3
Architecture and design

The uncertainty decomposition of
section

2.1
identifies three architectural requirements for a reliable agentic symbolic toolkit: a compact structured representation that the agent can construct with low task uncertainty
\Delta_{T}
, a skills layer that supplies targeted domain knowledge to suppress context uncertainty
\Delta_{C}
, and schema-validated deterministic tools that drive execution uncertainty
\Delta_{E}
toward zero for the mechanical steps of the calculation.
The six-step calculation procedure introduced in
section

2.2
for
S\to f\bar{f}
is universal, since every
1\to 2
decay follows the same sequence.
Step 1, writing the invariant amplitude, is the only process-specific ingredient.
Steps 2–6 are identical for every supported topology and are automated entirely by the
ComputeSymbolicAmplitude
tool (see
fig.

2
), which maps a structured diagram specification to a complete, self-contained FeynCalc script.
This division, where the agent selects the physics and the backend executes the algebra, is the concrete realization of the
\Delta_{E}
suppression argued for in
section

2.1
.
The key architectural enabler is a shared
Diagram
specification (
section

3.1
), a JSON dataclass consumed by all toolkit components that provides a common structured representation of the physics across stages.

Beyond the three entropy-motivated requirements, the architecture is organized around two additional design principles:

1.

Persistent artifacts and provenance.

Generated scripts, parsed result sidecars, and exported Python functions are saved as concrete artifacts in the agent’s session sandbox rather than discarded as transient outputs.
Downstream tools consume results by reference, enabling auditable multi-step pipelines without manual transcription of symbolic expressions.

2.

Multi-fidelity pathways.

The toolkit provides two calculational paths at different fidelity levels, both consuming the same diagram specification.
NDA (
section

3.2
) produces order-of-magnitude decay width and cross section estimates from dimensional analysis, phase space volumes, and coupling power counting, requiring no external software and applicable to arbitrary
n
-body final states.
The EDA path (
section

3.4
) produces exact tree-level symbolic results via automatic FeynCalc code generation.
The current scope of the EDA path is restricted to
1\to 2
decays and
2\to 2
scattering processes, where the phase space integration is analytic and the matrix element dependence on final-state kinematics drops out (for
1\to 2
) or reduces to Mandelstam variables (for
2\to 2
).
Extension to
n\geq 3
final-state particles, where phase space integration over non-trivial matrix elements is required, is left to future work.
For such processes, where exact analytic phase space integration is generally not available, numerical Monte Carlo tools such as MadGraph
[
4
]
, already integrated into the HEPTAPOD framework
[
26
]
, become the primary calculational path.
MadGraph also serves as an independent numerical cross-check on the EDA and NDA results for simpler processes.
Both paths can be fed by automatic Feynman diagram enumerations engines, here we use FeynGraph
[
12
]
(
section

3.3
).
Agreement in scaling and order of magnitude between paths provides an internal consistency check; disagreement identifies where assumptions, topology assignments, or kinematics require inspection.

The remainder of this section describes each component in turn.

3.2
Estimating diagrams with NDA

The NDA component provides rapid order-of-magnitude estimates of decay widths and cross sections directly from the diagram specification, requiring no external software.
The approach follows the spirit of Ref.
[
5
]
, with a slightly different phase-space prescription and also adapted for cross-section estimation.
Its role is to resolve task-level parametric questions before the EDA path is invoked, and to provide an independent scaling check on exact results after the fact.
The formalism applies equally to decays (
\Gamma\propto\Phi_{n}\cdot|\mathcal{M}|^{2}/2M
) and scattering (
\sigma\propto\Phi_{n}\cdot|\mathcal{M}|^{2}/2s
), differing only in the flux prefactor and initial-state averaging.
For simplicity, we present the decay width form and focus on decay processes throughout this work.
The central approximation is that
\overline{|\mathcal{M}|^{2}}
, which generically depends on the point in phase space, is evaluated at a single characteristic energy scale
E\sim M
and pulled out of the phase-space integral.
This renders each diagram component independent of the final-state kinematics, so that for a
1\to n
decay of a parent with mass
M
the width factorizes as

\Gamma_{\text{NDA}}=\frac{1}{2M}\cdot\Phi_{n}(M)\cdot\overline{|\mathcal{M}|^{2}}_{\text{NDA}}\cdot C_{\text{color}},

(3.1)

where
C_{\text{color}}
is the color factor.
The
n
-body phase space
\Phi_{n}
uses the exact two-body result
\Phi_{2}=|\vec{p}\,|/(8\pi M)
for
n=2
; for
n\geq 3
final-state particles assumed massless, the analytic volume
[
20
,
23
]

\Phi_{n}(M)=\frac{1}{2^{4n-5}\,\pi^{2n-3}}\,\frac{M^{2n-4}}{(n-1)!\,(n-2)!}

(3.2)

is used.
The squared matrix element is further factorized into a modular product of Feynman diagram components
[
5
]
, with no Lorentz contractions and no interference between diagrams:

\overline{|\mathcal{M}|^{2}}_{\text{NDA}}\;\sim\;\frac{N_{\text{color}}}{N_{\text{spin}}}\left(\prod_{\text{vertices}}|C_{i}|^{2}\right)\left(\prod_{\text{internal}}|P_{i}|^{2}\right)\left(\prod_{\text{external}}\mathcal{P}_{i}\right)\left(\frac{1}{16\pi^{2}}\right)^{\!L}.

(3.3)

Here
C_{i}
are vertex couplings drawn from the enumerated set in
table

1

(shared between NDA and EDA),
P_{i}=1/(q^{2}-m_{\text{prop}}^{2})
are propagator
denominators evaluated at the characteristic scale
E\sim M
(so that
|P_{i}|^{2}\sim 1/m_{\text{prop}}^{4}
in the heavy regime and
|P_{i}|^{2}\sim 1/E^{4}
in the light regime),

\mathcal{P}_{i}
are external-state polarization factors, and
L
is the loop order.
The full prescription for propagator regimes, external-state factors, and higher-dimensional operator scaling is given in appendix
A
.

Before evaluating any estimate, the NDA tools run a series of validation checks on the diagram specification, including topology consistency (vertex, propagator, and external-leg counts), graph-theory constraints (
I=(\sum n_{i}V_{i}-E)/2
), Lorentz invariance (fermions in pairs with allowed spin combinations), quantum number conservation, and kinematic threshold (
M>\sum m_{i}
).
These checks catch specification errors before they propagate to the calculation, providing early structured feedback to the agent on malformed inputs.

3.3
Enumerating diagrams with FeynGraph

FeynGraph
[
12
]
is an efficient Feynman diagram enumeration engine written in Rust with Python bindings.
It serves as a common entry point to both calculation paths, automatically enumerating all Feynman diagrams contributing to a given process (though the agent can also construct diagrams manually when the process is known in advance).
The Standard Model vertex set is available by default; BSM models can be loaded via UFO
[
2
]
model files.

Given initial- and final-state particle lists, FeynGraph enumerates all topologically distinct diagrams consistent with the model vertices.
The Diagrammatica wrapper around FeynGraph then converts each enumerated diagram to the shared
Diagram
dataclass of
section

3.1
via automatic vertex-type inference, mapping SM particle content to the vertex vocabulary of
table

1
without requiring the agent to know the Lorentz structure in advance (e.g., a
W
boson coupled to a fermion pair is assigned
"left-handed"
, a
Z
boson
"vector-axial"
).

The converted diagrams are ranked by physics importance using a scoring function implemented in Diagrammatica.
The ranking is dominated by the number of heavy internal propagators, since each propagator with mass
M_{\text{prop}}\gg E
contributes a suppression factor
(E/M_{\text{prop}})^{4}
to
|\mathcal{M}|^{2}
(from squaring the propagator denominator at the characteristic scale).
The ranking score

\text{score}=10^{\,3-2n_{\text{loops}}-3n_{\text{heavy}}}\cdot\prod_{i}g_{i}^{2}

(3.4)

penalizes loop order (
100^{n_{\text{loops}}}
), weights by vertex coupling strengths (
\prod_{i}g_{i}^{2}
), and applies a proxy suppression per heavy propagator (
10^{-3n_{\text{heavy}}}
).
The proxy factor
10^{-3}
is chosen conservatively to ensure that diagrams with fewer heavy propagators always rank above those with more, regardless of coupling variations.

The Diagrammatica enumeration tool organizes the output into classes grouped by heavy-propagator count, with each class directory containing individual diagram JSON files, visualizations, and a representative diagram suitable for passing directly to the NDA or EDA tools.
A per-class summary table recording diagram counts and coupling structures is saved alongside the enumeration, providing the structured metadata that downstream tools and plotting scripts consume.

3.4
Computing diagrams with EDA

The EDA path generates complete, self-contained Mathematica/FeynCalc scripts from symbolic diagram specifications, executes them via
wolframscript
, and returns parsed structured results.
The code generator maps the abstract diagram description to concrete FeynCalc function calls covering the procedure outlined in
section

2.2
, handling three topology classes: direct
1\to 2
decays,
1\to 2
decays with one internal propagator, and
2\to 2
scattering with
s
-,
t
-, or
u
-channel exchange.

Each call computes a single diagram for a specific set of particles, a single vertex type, and a single coupling symbol per chiral projection.
When different final-state flavors do not interfere (e.g.,
Z\to e^{+}e^{-}
vs.
Z\to\mu^{+}\mu^{-}
), inclusive widths are assembled by the agent through multiple tool calls, keeping each individual computation simple and auditable.
A notable limitation of this single-coupling-per-vertex design is that it does not capture the flavor structure arising from non-diagonal coupling matrices.
For example, a scalar
\phi
with a general Yukawa interaction
c_{ij}\phi\bar{\psi}_{i}\psi_{j}+{\rm h.c.}
induces
\psi_{j}\to\psi_{i}\phi
through two interfering amplitudes proportional to
c_{ij}
and
c_{ji}^{*}
respectively, producing a width
\Gamma\propto(|c_{ij}|^{2}+|c_{ji}|^{2})(\ldots)+\mathrm{Re}(c_{ij}c_{ji})(\ldots)
where the cross term between distinct matrix entries cannot be obtained from a single coupling symbol.
Extending the vertex specification to accept flavor-indexed coupling matrices, and the code generator to coherently sum the resulting amplitudes before squaring, would enable the toolkit to derive such expressions directly.
We leave this for future work.

Phenomenological analysis

Beyond computing the formulas, the agent identified several physical patterns that emerge from surveying the full catalog.
The threshold behavior (
fig.

3
) classifies all vertices by their near-threshold power law, and the agent’s analysis connects this classification to the underlying angular momentum structure:

Agent

1. Threshold classification by partial wave

The near-threshold behavior
\Gamma\propto\beta^{2\ell+1}
encodes the orbital angular momentum
\ell
of the decay products. From our catalog:

S-wave
(
\beta^{1}
): SSS, pseudoscalar SFF (
S\to f\bar{f}
), all VFF gauge vertices (
V\to f\bar{f}
,
f\to V\bar{f}^{\prime}
), SVV and
\phi FF
operators, VVV.
These dominate near threshold and are the first channels to “turn on” above the kinematic limit.

P-wave
(
\beta^{3}

S\to f\bar{f}
), SSV (
V\to SS
),
\phi F\tilde{F}
.
These are suppressed near threshold by centrifugal barrier effects.
The P-wave nature of
V\to S_{1}S_{2}
in the SSV vertex comes from the derivative coupling
g\,\varepsilon\cdot(p_{1}-p_{2})
.

The scalar-vs-pseudoscalar threshold dichotomy in SFF is a direct consequence of parity: a
0^{+}

\beta^{3}

0^{-}

\beta^{1}

The agent derived a CP discriminant directly from the equal-mass limit of the SFF formulas:

Agent

3. Scalar vs. pseudoscalar discrimination

The ratio
\Gamma_{g_{S}}/\Gamma_{g_{P}}
at fixed
|g|^{2}
provides a clean discriminant of the CP nature of a scalar coupling:

\frac{\Gamma_{g_{S}}}{\Gamma_{g_{P}}}=\frac{m_{S}^{2}-4m_{f}^{2}}{m_{S}^{2}}=\beta^{2}\,.

Near threshold (
\beta\to 0

1/\beta^{2}
. Far above threshold (
\beta\to 1
), the scalar and pseudoscalar rates coincide—the chirality flip becomes kinematically inexpensive. This ratio is observable through angular distributions and threshold scans.

The agent also identified a longitudinal polarization enhancement in channels with massive vector daughters:

Agent

2. Longitudinal mode enhancement

Channels with massive vector bosons in the final state exhibit growth
\propto M^{2n}/m_{V}^{2n}
for
M\gg m_{V}
, driven by the longitudinal polarization vector
\varepsilon_{L}^{\mu}\sim k^{\mu}/m_{V}

S\to V_{1}V_{2}
(SVV) grows as
m_{S}^{4}/(4m_{V_{1}}^{2}m_{V_{2}}^{2})

\Gamma\propto m_{S}^{5}/m_{V}^{4}
at large
m_{S}/m_{V}

V\to V_{1}V_{2}
(VVV) shows even steeper growth,
\Gamma\propto m_{V}^{5}/m_{V_{1}}^{4}
.
This growth signals the breakdown of perturbative unitarity: a renormalizable coupling
g
of dimension [mass] produces a width growing faster than
M

\Gamma<M
. In the Standard Model, this is cured by the Higgs mechanism, which relates
g\propto m_{V}
, so that
\Gamma/M
remains finite.

Finally, a universal feature noted across all VFF vertices is the interference term
\pm 6\,m_{f}m_{\bar{f}}m_{V}^{2}
that distinguishes vector from axial couplings:

Agent

4. The
6m_{f}m_{\bar{f}}m_{V}^{2}
interference term

A universal feature of VFF vertices is the interference term
\pm 6\,m_{f}m_{\bar{f}}m_{V}^{2}
that distinguishes vector from axial (or
g_{L}
from
g_{R}

m_{V}

Conclusions

In this work, we introduced
Diagrammatica
, a symbolic computation extension to the HEPTAPOD agentic toolkit that enables LLM agents to plan and execute multi-step theoretical calculations in high-energy physics.
The conceptual backbone of the architecture is an entropy decomposition of the agent’s action distribution into task, context, and execution components (
\Delta_{T}
,
\Delta_{C}
,
\Delta_{E}
), which identifies execution uncertainty as the primary obstacle to reliable agentic symbolic computation.
Unlike traditional programming, where compilers and runtime checks can at least enforce syntactic and type correctness, symbolic computation is governed by implicit mathematical conventions that no computational backend can efficiently verify independently.
We argued that this challenge admits two complementary remedies, tool-constrained computation that drives
\Delta_{E}
toward zero structurally and targeted knowledge grounding that suppresses it probabilistically, and pursued the first as the primary architecture.

The toolkit is organized around a shared LLM-friendly diagram specification that serves as a single source of truth across two complementary calculation paths.
Naive Dimensional Analysis provides order-of-magnitude rate estimates applicable to arbitrary final-state multiplicities, while Exact Diagrammatic Analysis produces complete tree-level symbolic results through automatic FeynCalc code generation.
Both paths consume the same structured JSON specification and are fed by FeynGraph for automatic Feynman diagram enumeration, with a navigable theory knowledge base exposed through the same tool interface.
By treating diagram specifications, symbolic results, and generated scripts as persistent, referenceable artifacts within the agent’s orchestration loop, the architecture preserves transparency, provenance, and human oversight throughout multi-step workflows.

Two benchmarks, each completed autonomously from a single user prompt, validated the architecture.
Task 1 exercised the EDA path on an exhaustive catalog of all tree-level, single-vertex
1\to 2
decay widths, producing 19 independent formulas across 6 vertex families with complete massless and threshold limits, chiral cross-checks, and Standard Model validation at the few-percent level.
Task 2 exercised the NDA path and FeynGraph on the muon decay
\mu\to\nu_{\mu}\bar{\nu}_{e}+n(e^{+}e^{-})+e^{-}
, enumerating over 150,000 tree-level diagrams across four multiplicities to map the experimental frontier from established measurements through the reach of Mu3e and HiMB, with MadGraph cross-checks confirming both the NDA scaling and published data.
Both tasks are specified with sufficient detail to serve as reproducible test cases for other agentic platforms, and we encourage other groups to attempt them and report their results.

Several design principles emerged from this work:

1.

The reliability of agentic symbolic computation is determined less by the model’s familiarity with domain conventions than by whether the tool interface encodes them. Concentrating convention-dependent choices into schema-validated fields eliminates entire classes of silent errors by construction, independently of model capability.

2.

A multi-fidelity organization, in which approximate and exact calculations consume the same structured specification, lets the agent match computational cost to the question being asked while providing internal consistency checks.

3.

Treating generated scripts, symbolic results, and intermediate outputs as persistent, referenceable artifacts rather than transient context allows downstream tools to consume results by reference, avoiding the context-window inflation that would otherwise degrade attention and retrieval fidelity over multi-step pipelines.

4.

Co-locating procedural tools and theoretical reference material in the same tool interface allows the agent to look up conventions at the moment of each critical decision, suppressing execution uncertainty through targeted retrieval rather than bulk documentation.

These principles point to a broader observation about the role of tools in agentic scientific computation.
The growing literature on LLM agents in HEP
[
16
,
46
,
34
,

,

,

has predominantly adopted a
code generation
paradigm: the agent writes free-form scripts or shell commands that are executed against existing software, with the reliability burden falling entirely on the model’s ability to produce correct code from context.
This approach inherits the full execution uncertainty
\Delta_{E}
analyzed in
section

2.1
, since the agent must independently resolve every domain-dependent choice at the token level.
The HEPTAPOD framework
[
26
]
was designed from the outset around schema-validated tool invocation rather than code generation, and Diagrammatica continues this approach into the domain of symbolic computation, where the stakes are particularly high because correctness is governed by implicit mathematical conventions rather than compiler-enforceable rules.
The key is to design tool schemas whose valid completions fix not only the format but the
domain conventions
of the calculation, so that every schema-compliant invocation maps to a correct computation by construction.
This yields two distinct advantages.
The first is
reliability
: correctness of the mechanical steps becomes a property of the interface rather than of the model, eliminating entire classes of silent errors independently of model capability.
The second is
interpretability
: because the agent’s decisions are compressed into a small number of human-readable fields, a domain expert can audit the full specification at a glance, in sharp contrast to reviewing pages of generated code where errors may be invisible without re-deriving the calculation from scratch.
We believe convention-fixing tool design, in which the structure of the action space encodes as much domain knowledge as the model that navigates it, deserves wider adoption in agentic HEP workflows.

More broadly, the tool-constrained and knowledge-grounded approaches discussed in

Multi-agent configurations, where specialized agents for symbolic calculation, Monte Carlo validation, and data comparison are coordinated by a planning agent, represent a natural evolution toward this goal.

Diagrammatica provides the symbolic computation layer required for increasingly capable AI-assisted research in high-energy physics.
The design principles identified here, including convention-fixing semantics, multi-fidelity tool hierarchies, shared structured specifications, and theory-grounded interfaces, offer a blueprint for reliable agentic computation that can extend a researcher’s effective capabilities beyond what either the researcher or the agent could achieve working independently.

Appendix A
NDA prescription for decay rates and cross sections

This appendix summarizes the explicit NDA prescription implemented by the toolkit. See also Ref.
[
5
]
.

A.1
Exact starting point

For a
1\to n
decay of a mother particle
A
with mass
M
,

\Gamma(A\to a_{1}a_{2}\cdots a_{n})=\frac{1}{2M}\int d\Phi_{n}\,\overline{|\mathcal{M}|^{2}}.

(A.1)

For a
2\to n
scattering process in the center-of-mass frame,

\sigma(AB\to a_{1}a_{2}\cdots a_{n})=\frac{1}{F}\int d\Phi_{n}\,\overline{|\mathcal{M}|^{2}},

(A.2)

with flux factor

F=4E_{A}E_{B}|\vec{v}_{A}-\vec{v}_{B}|.

(A.3)

In the center-of-mass frame with relativistic incoming particles,
E_{A}=E_{B}=\sqrt{s}/2
and
F\to 2s
.

A.2
Phase-space estimates

For two-body decays, the toolkit uses the exact phase-space factor

\Phi_{2}=\frac{|\vec{p}\,|}{8\pi M},

(A.4)

where
|\vec{p}\,|
is the daughter three-momentum in the parent rest frame.
For
n
-body final states with approximately massless daughters, the phase-space volume is estimated by

\Phi_{n}(M)=\frac{1}{2(4\pi)^{2n-3}}\frac{M^{2n-4}}{\Gamma(n)\Gamma(n-1)}.

(A.5)

For
2\to n
scattering in the center-of-mass frame, the same massless phase-space scaling gives

\Phi_{n}(\sqrt{s})\propto s^{\,n-2}.

(A.6)

These forms are adequate for NDA purposes, but should not be interpreted as precision approximations near threshold or when several final-state masses are comparable to the available energy.

A.3
Matrix element factorization

The squared matrix element is estimated as a modular product of diagram components,

\overline{|\mathcal{M}|^{2}}_{\text{NDA}}\sim\frac{N_{\text{color}}}{N_{\text{spin}}}\left(\prod_{\text{vertices}}|C_{i}|^{2}\right)\left(\prod_{\text{internal}}|P_{i}(E)|^{2}\right)\left(\prod_{\text{external}}\mathcal{P}_{i}(E)\right)\left(\frac{1}{16\pi^{2}}\right)^{L},

(A.7)

where:

•

N_{\text{spin}}
denotes the average over initial-state spin multiplicities;

•

N_{\text{color}}
denotes the color multiplicity of the diagram;

•

C_{i}
are the vertex couplings or operator coefficients;

•

P_{i}(E)
are propagator suppression factors evaluated at a characteristic scale
E
;

•

\mathcal{P}_{i}(E)
are rough external-state polarization or spinor factors;

•

L
is the loop order.

The characteristic scale is taken to be
E\sim M
for decays and
E\sim\sqrt{s}
for scattering in the center-of-mass frame.

A.4
External-state factors

The rough external-state factors used by the toolkit are chosen to reproduce the energy scaling of the standard spin sums and polarization sums:

\mathcal{P}_{s=0}(E)\sim 1,\qquad\mathcal{P}_{s=1/2}(E)\sim 2E,\qquad\mathcal{P}_{s=1}(E)\sim\begin{cases}1+E^{2}/m^{2},&m\neq 0,\\
1,&m=0.\end{cases}

(A.8)

These factors should be interpreted as scaling surrogates for the exact tensor and spinor structures.
They are not intended to reproduce chiral suppressions, gauge cancellations, or interference effects.

A.5
Propagator regimes

For an internal propagator with mass
m_{\text{prop}}
, the toolkit distinguishes three regimes:

•

heavy
:
m_{\text{prop}}\gg E
, giving

|P_{i}|^{2}\sim 1/m_{\text{prop}}^{4}
;

•

light
:
m_{\text{prop}}\ll E
, giving
|P_{i}|^{2}\sim 1/E^{4}
;

•

intermediate
: use the full scaling

|P_{i}|^{2}\sim 1/|q^{2}-m_{\text{prop}}^{2}|^{2}
at the characteristic kinematic scale.

These suppressions are applied diagram by diagram.
They should not be used when the resolved propagator is better described by an effective local operator; in that case the operator coefficient already encodes the heavy-scale suppression.

A.6
Higher-dimensional operators

For an operator of mass dimension
d>4
with coefficient
C^{(d)}/\Lambda^{d-4}
, the amplitude scales as

\mathcal{M}^{(d)}\sim C^{(d)}E^{\,d-N}\Lambda^{\,4-d},

(A.9)

where
N
is the total number of external particles in the process.
This reproduces the correct mass dimension
4-N
for the amplitude.
For local contact interactions of this type, it is often more transparent to estimate the energy scaling directly from
eq.

A.9
rather than separately keeping resolved propagator denominators.

A.7
Final NDA forms

With these ingredients, the decay width estimate becomes

\Gamma_{\text{NDA}}\sim\frac{1}{2M}\Phi_{n}(M)\overline{|\mathcal{M}|^{2}}_{\text{NDA}},

(A.10)

and for scattering in the center-of-mass frame,

\sigma_{\text{NDA}}\sim\frac{1}{2s}\Phi_{n}(\sqrt{s})\overline{|\mathcal{M}|^{2}}_{\text{NDA}}.

(A.11)

The two-body forms used in the main text are recovered as special cases of these expressions.
