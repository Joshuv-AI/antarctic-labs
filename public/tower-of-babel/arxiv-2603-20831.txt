Abstract
. We investigate well-known verification (decision) problems concerning graph properties in distributed networks, where nodes are augmented with labels (or proofs) that provide auxiliary information to assist local computation. These problems are commonly formalized in the framework of locally checkable labeling : if a graph satisfies a given property, then there exists a labeling under which all nodes accept using a local verification algorithm, whereas if the property is not satisfied, then for every labeling of the graph, at least one node must reject. In this computation, nodes generally access a particular local neighborhood to decide whether to accept or reject (equivalent to LOCAL model). In this domain, O ⁡ ( log ⁡ n ) O(\log n) works like a gold standard of labeling size (the maximum number of bits for labels), in the sense that O ⁡ ( log ⁡ n ) O(\log n) label-size is often the best we can hope for most of the fundamental verification problems. Our focus is twofold. First, among multiple properties we mention in the paper, we put particular emphasis on verifying whether the graph has a cycle or not, majorly because this can be verified with only 3 3 labels and access to 1 1 hop neighborhood, with a matching lower bound. What is more interesting is that, we introduce a novel gadget for encoding direction along a path using only 2 2 labels and a 3 3 -hop neighborhood accessibility for each node, which enables a cycle-detection labeling scheme with just 2 2 labels. This gadget may be of independent interest for other verification tasks. Second, we consider adversarially corrupted labelings, in which each node has access to a local neighborhood, within which a fraction of nodes may receive erroneous labels . We introduce a general algorithmic framework, called refix , which transforms a base (error-free) verification algorithm for a property 𝒫 \mathcal{P} operating on labels within d d -hop neighborhood, into one that tolerates up to i i erroneous labels within a neighborhood of radius d + 2 ​ i d+2i , at the cost of accessing the labels within the d + 2 ​ i d+2i -hop neighborhood. We illustrate the applicability of our framework on several graph properties, including cycle detection, cycle absence, and bipartiteness. In presence of erroneous labels, we provide lower bounds to establish the correlation between the number of errors and accessibility of the required neighborhood.

Introduction

In many distributed systems, nodes are required not only to compute a solution, but also to
locally verify
that a desired global structure or property is present in the network. Such tasks give rise to
verification problems
, where the goal is to determine whether a graph satisfies a specified property using only local information, where the term
graph property
corresponds to a family of graphs closed under isomorphism. In the context of yes–no verification problems, a standard and well-accepted model requires the following: (i) for a yes-instance, all nodes must output
1
; and (ii) for a no-instance, at least one node must output
0
.

In distributed graph algorithms, the model in which nodes are provided with task-specific auxiliary information is well established and widely studied
(
6
;
23
;
3
;
4
;
8
;
15
)
. This auxiliary information appears in the literature under various names, including
advice

(
2
)
,
labels
,
certificates

(
9
)
, and
proofs

(
12
;
22
;
23
)
.
A local verification of a property consists of assigning labels to the nodes of a graph so that nodes can collectively check the correctness of the property by inspecting the labels within their (possibly larger-radius) neighborhoods. This notion has been studied under several closely related names, including
proof labeling schemes

(
23
)
, locally checkable proofs
(
21
)
, local decision
(
20
)
, local certification scheme
(
9
)
etc.
Despite the differing terminology, these models share the same underlying goal: enabling nodes to locally verify global graph properties, see a survey by Feuilloley
(
18
)
.
A graph property is
locally verifiable
if it can be checked by a local verification algorithm (formally defined later in Section
2
), also known as
a verifier
, that accepts every graph satisfying the property and rejects every graph that does not.
Throughout this paper, we adopt a consistent terminology among these closely related notions. We refer to the information provided to nodes as
labels
, the collection of all node labels as a
labeling
of the graph
G
, and the combination of a labeling with a local verification algorithm as a
locally checkable labeling scheme
(or simply a
labeling scheme
).

In continuation of the above discussion, a line of work focuses on verifying properties or solving graph problems using small (size with respect to the number of required bits) labels.
Although certain graph problems, such as computing a minimum spanning tree in weighted graphs, have been studied in
(
19
)
with constant-size advice (on average per node), a labeling size of
O(\log n)
has emerged as a near gold standard for most local verification problems
(
20
;
16
)
, including verifying the existence of a unique leader
(
17
)
, checking acyclicity
(
1
;
25
)
, non-bipartiteness
(
22
)
and minor-freeness
(
7
)
.
In a recent line of works
(
11
;
13
;
14
)
, it has been shown that planar graphs and graphs of bounded genus can be verified with
O(\log n)
bits.
Some verification problems requires even larger labels: for example, MST-verification problem
(
24
)
requires even larger labels of size
O(\log n\log W)
, where
W
is the largest weight of an edge.
In this direction, Balliu et al.
(
5
)
characterize the power of local distributed verification through a hierarchy of decision classes.
It is common intuition that hereditary properties, i.e., removing a node or an edge may yield a graph that falls in the same class as the original one, are easier to certify (using
O(\log n)
size labels) in the sense that information about every single node or edge is not required to be encoded in the labeling.
However, certain fundamental verification problems—such as determining whether a graph contains a cycle—remain particularly interesting when restricted to constant-size labelings. We talk more about this in Section
1

In another aspect, when it comes to providing labels, we distinguish between two entities in our model: an oracle and an adversary. The oracle provides a correct labeling, referred to as the oracular labeling, under which the verification algorithm operates without errors. In contrast, we consider a setting where an adversary may corrupt parts of this labeling with the goal of misleading the verifier.
As usual, each node has access to the labels within a
d
-hop neighborhood (
d\geq 1
) and outputs
1
(accept) or
0
(reject) based on this local
d
-hop view.
In our paper, we capture this notion by saying that each node has a view-distance
d
, which means it can ’see’ the labels on any node within
d
-hop neighborhood. This model is equivalent to the LOCAL model
(
26
)
, since a verifier with view distance
d
can be implemented in
d
synchronous communication rounds
(
21
)
.
In our setting, the adversary may introduce erroneous labels within the view distance of each node. This pictures towards a prediction model, which is relatively recent topic among the distributed community. Despite some differences with our model, Boyar et al.
(
10
)
studied a prediction model on classical graph problems like maximal independent set, maximal matching, and coloring.

Our Results

In verification problems (e.g. checking acyclicity, uniqueness of leader etc.) under labeling schemes that are solvable using
O(\log n)
bit labels, a common and natural approach is to designate a node as a root, assign it label
0
, and label every other node by its distance from this root.
An appealing feature of this scheme is that it implicitly encodes an orientation of the edges (from child to parent): every node except the root has exactly one neighbor with a smaller label, while all other neighbors have larger labels.
Restricting attention to constant-size labelings—specifically, schemes using only
2
or
3
distinct labels—we ask whether it is possible to encode such an orientation.

This is indeed possible and we show it for cycle detection.
Using
3
distinct labels and a
1
-hop view, such an orientation can be defined naturally in this setting. However, we show that reducing the number of labels to
2
under the same constraints is impossible.
What is more interesting in our consideration is that, with cost of
3
-hop view distance, we present a non-trivial way to encode orientation using only
2
labels, which solves cycle detection.
This technique may be of independent interest for other verification problems that can be done using constant-size labeling schemes.

We have another vertical of results, which concerns erroneous labelings.
We study a setting where the adversary is allowed to modify labels of at most
i
nodes within the
d+2i
-hop neighborhood for each node, where
d
is the view distance of the nodes in an error-free instance.
To tackle this, we introduce an algorithmic framework
refix
that tolerates up to
i
erroneous labels with a
d+2i
-hop neighborhood for every node with the help of the base (error-free) algorithm to verify a graph property
\mathcal{P}
.
In this context, we establish a lower bound to demonstrate a correlation between
i
and the view distance.

We conclude by outlining a potential research direction: studying verification problems with erroneous labels under the CONGEST model. A central challenge in this setting is encoding the information of a large
d
-hop neighborhood within the limited per-edge bandwidth. As an initial step, we show that under a stronger local error assumption—namely, that at most half of the immediate neighbors of any node receive corrupted labels—bipartiteness can still be verified efficiently in the CONGEST model.

Verification Problems with Oracular Labelings

We begin with oracular labelings for three verification problems: cycle detection, cycle absence, and bipartiteness. Our main focus is cycle detection; the other two problems admit standard constructions and will serve as base cases for the error-resilient framework

Let us start with the

To overcome this, we encode a directed structure toward a cycle. The specifics can be found in Subsection

3.2.
Impossibility for Cycle Detection with 2 Labels and View Distance 1

The

Is it possible to have a labeling scheme with only

Theorem 2.

There is no algorithm

3.4.
Cycle Absence & Bipartiteness with Oracular Labels

3.4.1.
Cycle Absence:

By cycle absence, we refer to the problem of verifying whether the graph
G
is acyclic or not. That is, if
G
is acyclic, there must exist a labeling such that all nodes accept, and if
G
has a cycle, for any labeling on

An well-known labeling used for cycle absence is selecting an arbitrary node

as the root and assign label
0

We refer to this oracular labeling for cycle absence by

Since an acyclic connected graph is a tree, a simple algorithm can be derived from Line

It is seen that the verification problems like cycle absence (or leader election) requires

3.4.2.
Bipartiteness:

Since any bipartite graph

assigns label

5.2.
Cycle Absence with Erroneous Labeling

We now apply the
refix

and the corresponding base algorithm (in Section

) to yield a
(L_{adv},

\mathcal{A}_{i})_{n,2i+1}^{i}
-system that detects cycle absence. It is sufficient to show that Proposition
4
holds. The argument closely parallels the cycle detection case. The structure of the oracular labeling and the behavior of the base verifier induce the same type of parent-child orientation along paths. Consequently, the notions of
long path
,
short path
,

,

, and designated root nodes (denoted

and

) carry over verbatim. Likewise, the structural properties captured in Remark

and

The notion of the

is a tree and the argument proceeds as in the cycle detection case.

Consider arbitrary adjacent nodes

Proof of Proposition
4
.

Consider arbitrary adjacent nodes

and

exist and we have

5.3.
Bipartiteness with Erroneous Labeling

In the absence of adversarial errors, we already have a trivial oracular labeling
L_{O}^{3}
using only
2
labels for verifying bipartiteness.
In the presence of erroneous labels, the proof of Proposition
4
is considerably simpler than in the case of cycle detection (Section
5.1
), and therefore we present only a concise argument.
The following simple observation forms the foundation of the proof.

In any labeling that satisfies the local verification condition for bipartiteness, the labels along every simple path must alternate between
0
and
1
; equivalently, once the label of a single vertex on the path is fixed, the labels of all other vertices on that path are uniquely determined by the parity of their distance from it.

To prove Proposition
4
, consider a simple path
P=(v_{1},\dots,v_{k})
with
2i+2\leq k\leq 4i+2
nodes such that
u=v_{2i+1}
and
v=v_{2i+2}
.
In particular,
P
contains strictly more than
2i
nodes.
Each of the nodes
u
and
v
may modify the labels of at most
i
nodes on
P
. Hence, together they can disagree on at most
2i
nodes of
P
.
Since
|P|>2i
, there exists at least one node
w\in P
such that
l_{u}(w)=l_{v}(w)
.

Fix such a node
w
, and consider the subpath of
P
that connects
w
to
u
and
v
. By the observation above, once the label of
w
is fixed, the alternating structure of valid bipartite labelings uniquely determines the labels of all vertices along this subpath. Consequently,
l_{u}
and
l_{v}
must agree on every vertex of this subpath, and in particular on
u
and
v
.
This proves Proposition
4
.

6.
Impossibility Results for Erroneous Labelings

We now investigate how the parameters
i
(the number of errors) and the view distance
d
relate when an adversarial labeling of the graph
G
differs from an oracular labeling in at most
i
nodes within the neighborhood
N_{d}(v)
of every node
v
.
To gain more insight into this, we phrase our question in the following (possibly simpler) way:
Can a verification problem be solved if the adversary introduces at most
i
errors in the whole graph, while each node has view distance at most
i
, even if we allow any number of labels?

The answer is negative for this. To prove the impossibility, a natural instinct is to consider a graph with the property.
Since the graph has the property, there must exist a labeling such that all nodes accept even if the adversary is allowed to introduce errors. Using the labeling, we construct a labeling for another graph that does not have the property, violating soundness.

\blacktriangleright

Impossibility in Cycle Detection:

Theorem 1.

Consider any adversarial labeling
L_{adv}
on a graph
G
that differs from an oracular labeling
L_{O}
(consisting of any number of labels) in at most
i
nodes of the whole graph
G
. Then there exists no verification algorithm, together with
L_{adv}
, that constitutes a locally checkable labeling scheme for cycle detection in which every node has a view distance at most
d\leq i
.

Proof of Theorem
1
.

Assume, for the sake of contradiction, that such a verification algorithm
\mathcal{A}
exists.
Consider a graph
G_{1}
that is a simple path of
3i+1
nodes, denoted by
(u_{1},u_{2},\dots,u_{3i+1})
.
Let
G_{2}
be a graph consisting of a path
(v_{1},v_{2},\cdots,v_{3i+1})
together with an additional triangle formed by three nodes
x,y
and
z
, where node
x
is connected with
v_{3i+1}
.
We will show that if all the nodes in
G_{2}
accept according to the algorithm
\mathcal{A}
, then all nodes in
G_{1}
must also accept, thereby violating the soundness property.

Let us focus on the sequence (sub-path)
S=(v_{i+1},\dots,v_{2i+1})
of
i+1
nodes in
G_{2}

Every node in
S
is at distance at least
i

v_{1}
and the triangle.
Hence, within the view distance
d=i
, each such node sees
2i+1
nodes (including itself), all of which have degree
2
.
For convenience, let us denote
l_{j}=L_{O}(v_{i+j})
for
j=1,2,\dots,i+1
.
Thus
(l_{1},\dots,l_{i+1})
is the sequence of labels on the block
S
under the labeling
L_{O}
. We now prove the following lemma.

Lemma 0.

Any node that sees
2i+1
nodes in a path and sees a consecutive sequence of labels
l_{1},\dots,l_{i+1}
must accept.

Proof.

Fix a node
v\in S
.
Its
d
-hop neighborhood consists of at most
2i+1
consecutive path nodes.
Under the adversarial influence, at most
i

L_{O}
.
Therefore, within
N_{d}(v)
, at least
i+1
labels must remain unchanged.
In particular, the adversary may arbitrarily modify any
i

N_{d}(v)

i+1
labels on the central block
(l_{1},\dots,l_{i+1})

Since
v

L_{O}
in at most
i
nodes, its decision cannot depend on those
i
potentially corrupted labels. Hence acceptance of
v
is determined solely by the central
i+1
consecutive labels
(l_{1},\dots,l_{i+1})
.
Consequently, any such node must accept according to the algorithm
\mathcal{A}
.
∎

Let us create a (partial) labeling
L

that will have all the nodes that see

L(u_{i+j})=l_{j}

. By Lemma

Now consider any node

The set of these

Lemma 0.

Any node of

Now let us complete our labeling

Impossibility in Cycle Absence:
Theorem
1
holds for cycle absence as well. The core idea remains the same. Hence, we briefly present the argument here due to page restriction.

Suppose, for contradiction, that there exists a verification algorithm

with view distance

Impossibility in Bipartiteness:
The same construction presented in cycle absence works for bipartiteness as well. Since with view distance

, nodes cannot distinguish between being in the middle

7.
Discussion on Future Direction: CONGEST Implementation with Errors

In this section, we attempt for an implementation of erroneous labeling or its probable landscape under the well-known CONGEST model with bipartiteness, rather as a simple exercise.
We believe that this opens up potential directions in the domain of local verification problems with labelings.

When dealing with erroneous labelings, suppose we wish to implement in the CONGEST model an error-resilient verification algorithm for a graph property that requires
t
rounds in the LOCAL model (i.e., a
t
-hop view distance). The main challenge is encoding the information of a
t
-hop neighborhood within the limited per-edge bandwidth of CONGEST. This motivates a stronger local error assumption: instead of allowing arbitrary corruptions within
N_{t}(v)
for each node
v
, we restrict the adversary to modifying the labels of at most half of the nodes in the immediate neighborhood
N_{1}(v)
. As a starting point, we examine this setting for bipartiteness, which in the LOCAL model requires only
2
labels.

\blacktriangleright

Bipartiteness:
Suppose that for every node
v
, at most
\deg(v)/2
nodes in
N_{1}(v)
have erroneous labels. Then bipartiteness can be verified in
2
rounds, with each edge transmitting only
2
bits. Locally, there are only two valid configurations: either
v
has label
1
and all neighbors have label
0
, or vice versa.

Let
x
denote the number of
0
’s in
N_{1}(v)\setminus{v}
if
v
has label
0
; otherwise
x
is one plus that number.

In the first round, each node sends its label to its neighbors and computes
x
. If
x>(\deg(v)+1)/2
, it updates its label to
1
; if
x<(\deg(v)+1)/2
, it updates to
0
; if equality holds,
v
rejects.

In the second round, every node (that did not reject yet) sends out its corrected label to its neighbors and verifies whether or not, its own label differs from the labels of all of its neighbors. If so, it accepts; otherwise, it rejects.

We conclude by pointing to error-resilient local verification in the CONGEST model as a natural next step. While refix tolerates adversarial corruption in LOCAL, extending it to CONGEST faces the fundamental limitation of per-edge bandwidth. In LOCAL, a node with view distance
d
can access its entire
d
-hop neighborhood. In CONGEST, this information must be communicated using
O(\log n)
-bit messages per round, and enlarging the view distance to
d+2i
makes such compression the main challenge.

As an initial step, we discuss above a stronger local error assumption: for every node
v
, at most
\deg(v)/2
of its immediate neighbors are corrupted. We see that bipartiteness remains verifiable in CONGEST using
2
labels and in
2
rounds.

Although we do not provide formal proofs, we conjecture that cycle detection in CONGEST may also be achievable, particularly using the
2
-label encoding scheme of Section
3.3
. Finally, establishing correctness of the
refix
-framework for constant-size label schemes in this setting remains an interesting open problem.
