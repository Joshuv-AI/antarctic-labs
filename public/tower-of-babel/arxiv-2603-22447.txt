Abstract
. Agent skills are modular instruction packages that combine YAML metadata, natural language instructions, and embedded code, and they have reached 196K publicly available instances, yet no mechanism exists to detect clone relationships among them. This gap creates systemic risks: a vulnerability in a widely copied skill silently persists across derivatives with no alert to maintainers. Existing clone detectors, designed for single-modality source code, cannot handle the multi-modal structure of skills, where clone evidence is distributed across three interleaved content channels. We present SkillClone , the first multi-modal clone detection approach for agent skills. SkillClone fuses flat TF-IDF similarity with per-channel decomposition (YAML, NL, code) through logistic regression, combining strong detection with interpretable type classification. We construct SkillClone-Bench , a balanced benchmark of 300 ground-truth pairs with stratified difficulty. On SkillClone-Bench , SkillClone achieves F1 of 0.939 with precision 0.952, outperforming flat TF-IDF (F1 = 0.881) and achieving 4.2 × \times higher Type-4 (semantic) recall than MinHash. Applying SkillClone to 20K skills reveals 258K clone pairs involving 75% of all skills, with 40% crossing author boundaries. A deduplication analysis shows the ecosystem is inflated 3.5 × \times : only 5,642 unique skill concepts underlie the 20K listed skills, and 41% of skills in clone families are superseded by a strictly better variant.



1.
Introduction

Large language model (LLM) agents have rapidly evolved from standalone chatbots into extensible platforms that delegate specialized tasks to modular instruction packages called
agent skills
. A skill is a structured document, typically a
SKILL.md
file, that bundles YAML metadata, natural language instructions, and embedded code blocks into a single artifact that an LLM agent such as Claude Code, Cursor, or Windsurf can load at runtime to acquire new capabilities. Since the public launch of skill ecosystems in late 2025, adoption has been explosive: over 196K skills are now publicly available on registries and GitHub repositories, spanning domains from code generation and security analysis to DevOps automation. This growth mirrors the early trajectories of package ecosystems like npm and PyPI
(
Zimmermann et al. 2019
;
Decan et al. 2019
)
, which took years to reach comparable scale. Recent surveys
(
Xu and Yan 2026
)
and empirical studies
(
Ling et al. 2026
)
have begun to characterize this ecosystem’s architecture and growth dynamics.

Despite this rapid expansion, the agent skill ecosystem lacks fundamental infrastructure that traditional package ecosystems take for granted. Skills declare no dependencies on other skills, carry no version identifiers, and provide no provenance metadata linking derived skills to their origins. When a developer copies, adapts, or extends an existing skill, this relationship is entirely invisible to the ecosystem. The consequence is a growing body of duplicated and near-duplicated content whose relationships cannot be traced, audited, or monitored. This situation creates concrete security risks: when a vulnerability is discovered in a widely copied skill, there is no mechanism to identify which other skills share its content and therefore share the same flaw. Unlike a CVE advisory that can propagate through a dependency graph in npm
(
Liu et al. 2022
)
, a flawed skill pattern can silently persist across hundreds of derivative skills with no alert to their maintainers. The January 2026 ClawHavoc campaign
(
Koi Security 2026
)
, which infiltrated over 1,200 malicious skills into the OpenClaw registry, demonstrated the real-world consequences of this gap.

Existing tools for skill analysis treat each skill as an isolated unit. SkillScan
(
Liu et al. 2026b
)
performs static security checks on individual skill files. SkillFortify
(
Bhardwaj 2026
)
validates skill structure and metadata quality. MalTool
(
Liu et al. 2026a
)
detects malicious intent in single skills through behavioral analysis. SkillJect
(
Jia et al. 2026
)
and SKILL-INJECT
(
Schmotz et al. 2026
)
have demonstrated that skills serve as potent attack vectors for prompt injection
(
Schmotz et al. 2025
)
. Yet none of these tools examine relationships
between
skills, and no prior work has studied clone patterns at ecosystem scale, despite extensive evidence from traditional package ecosystems that such relationships are critical for security
(
Zimmermann et al. 2019
;
Liu et al. 2022
)
. The absence of such analysis means that the community cannot answer basic questions: How prevalent is skill cloning? Do clone relationships cross organizational boundaries? What is the blast radius when a hub skill contains a vulnerability?

The key insight behind our work is that agent skills are inherently
multi-modal documents
that resist analysis by any single similarity technique. For the dominant
SKILL.md
format studied in this paper, we scope the artifact to its three primary in-file modalities: YAML metadata specifying the skill’s name, tags, and configuration; natural language prose describing when and how to apply the skill; and embedded code blocks implementing concrete functionality. This scope targets the content carried directly inside the skill file, not auxiliary repository artifacts such as images, linked documents, or external scripts. Detecting clones requires fusing similarity signals across these three channels, because two skills may share identical code blocks while differing in their natural language framing, or may paraphrase the same instructions while referencing different code examples.

Preliminary ecosystem analysis revealed that clone relationships are not rare edge cases but a dominant organizing force in the ecosystem: most skills participate in at least one clone relationship, a substantial fraction of clones cross author boundaries, and malicious patterns often propagate through these latent reuse links. These observations motivate a hybrid contribution. We study undeclared reuse empirically at ecosystem scale, and we introduce a multi-modal clone detector designed specifically for the mixed YAML, natural-language, and code structure of skills.

To address this gap, we present
SkillClone
, the first approach for detecting clone relationships across the agent skill ecosystem.
SkillClone
implements a three-channel clone detection approach that synergistically computes similarity over YAML metadata, natural language instructions, and embedded code blocks, then fuses these signals through a weighted aggregation scheme to produce a unified clone score for each skill pair. We apply
SkillClone
to a representative sample of 20K skills drawn from the 196K-skill corpus crawled from GitHub and construct the first ecosystem-wide
clone graph
, where nodes represent skills and edges represent detected clone relationships. Over this graph, we perform blast radius analysis to quantify how a vulnerability in a single skill can propagate through chains of clones.

An important distinction underlies our work: clone detection identifies structural similarity between artifacts, but does not by itself establish causal reuse (i.e., that one skill was derived from another). Establishing reuse requires additional provenance signals such as fork relationships, commit timestamps, or explicit attribution. We validate that our clone detection enables downstream reuse discovery by confirming provenance in fork-mined pairs and identifying real-world clone-and-rebrand cases (Section
2.3
). For security applications, the distinction is immaterial: whether two skills share a vulnerability through copying or convergent development, the blast radius is the same.

Our analysis reveals several findings with implications for ecosystem governance. Among the 258K clone relationships detected by
SkillClone
, 40% cross author boundaries, indicating substantial cross-organizational cloning. A deduplication analysis shows the ecosystem is inflated 3.5
\times
: only 5,642 unique skill concepts underlie the 20K listed skills, and 41% of skills in clone families are superseded by a strictly better variant. Security propagation analysis identifies 141 real security-relevant skills whose dangerous patterns (SQL injection payloads, reverse shells, XSS vectors) propagate to 1,100 clones across 119 affected authors. These findings demonstrate that per-skill security tools are insufficient and that ecosystem-level clone analysis is essential for managing systemic risk.

In summary, this paper makes the following contributions:

•

An empirical characterization of undeclared reuse across 20K agent skills, revealing ecosystem-scale clone prevalence, cross-author reuse, and the dominance of Type-4 semantic clones (Section
4
).

•

The first multi-modal clone detection approach for agent skills, fusing YAML, natural language, and code similarity signals through cross-modal alignment to detect clone relationships in heterogeneous skill documents (Section
3
).

•

A blast-radius analysis over the inferred clone graph, quantifying how malicious or vulnerable skill patterns propagate through latent reuse links that per-skill scanners cannot see (Section
4
).

•

SkillClone-Bench
, a balanced benchmark of 300 annotated skill pairs with stratified difficulty, for evaluating clone detection on multi-modal skill documents.

2.
Background and Motivation

2.1.
Agent Skills

An agent skill is a structured document that extends an LLM agent’s
capabilities at runtime. The dominant format,
SKILL.md

(
Xu and Yan 2026
;
Ling et al. 2026
)
, consists of
three primary in-file content channels that together capture the predominant
content modalities of the skill file itself.
The
YAML frontmatter
specifies metadata: skill
name, description, category tags, compatibility constraints, and configuration
parameters. The
natural language body
provides behavioral
instructions about when to activate the skill, how to interact with the user,
and what constraints to observe.
Embedded code blocks
implement concrete
functionality such as shell commands, API calls, or file manipulation routines.
A single skill may contain code blocks in multiple languages (e.g., Python,
Bash, JavaScript), interleaved with NL prose. Chen et al.
(
Xu and Yan 2026
)

report that this three-part structure of YAML frontmatter, NL body, and code
fences is used by over 95% of skills across major registries, making it the
de facto standard. Li et al.
(
Ling et al. 2026
)
confirm that 78% of
skills contain at least one code block, while virtually all contain NL
instructions, establishing that our three-channel decomposition covers the
predominant content modalities of
SKILL.md
files. We therefore treat
YAML and code as optional channels that may be absent in individual skills, but
still part of the dominant format at ecosystem scale. This decomposition does
not attempt to model auxiliary repository context beyond the focal

SKILL.md
artifact, such as external assets, linked files, or project
history. Skills are distributed through registries
(e.g., SkillsMP) and GitHub repositories, with no package manager, versioning
system, or dependency declaration mechanism.

Ecosystem Scale.
In our SkillsMP registry snapshot,
we observe 196,134 listed skills spanning 15 major categories including code
generation, testing, DevOps, security analysis, and documentation. The
ecosystem has grown 4
\times
in six months, driven by the adoption of
agent-based development tools. Unlike traditional package ecosystems where
reuse is mediated by dependency declarations (
package.json
in npm,

requirements.txt
in PyPI), skill duplication is entirely informal: a
developer who wants to build on an existing skill simply copies the

SKILL.md
file and modifies it. This copy-and-modify workflow
creates pervasive undeclared cloning that is invisible to the ecosystem.

types
(

)
. Table

presents these types
alongside our adapted definitions for multi-modal agent skills, which must
consider similarity across three content channels (YAML, NL, Code) rather
than a single source language.

A key distinction is that skill clone types are determined by the

operationalizes these definitions with per-channel similarity thresholds. Our
taxonomy captures
structural clone evidence
, not proven derivation:
Type-4 is the most uncertainty-prone category and excludes pairs that are
merely topically related or belong to the same skill category.

Existing detectors operate on single-modality source code. Text-based
approaches such as NiCad
(
Roy and Cordy 2008
)
normalize source lines, achieving
high precision for Type-1/2 but struggling with semantic clones.
Token-based approaches such as SourcererCC
(
Sajnani et al. 2016
)
and
CCFinder
(
Kamiya et al. 2002
)
achieve scalability through index-based

(
Baxter et al. 1998
;
Jiang et al. 2007
)
and
graph-based
(

approaches compare AST or PDG
representations, requiring parseable single-language input.
Recent ML-based approaches
(
Feng et al. 2020
;
Wang et al. 2021
)
leverage
transformer architectures to detect semantic clones on benchmarks like
BigCloneBench
(
Svajlenko et al. 2014
)
. All these approaches assume
single-language, single-modality input, an assumption that does not hold for
agent skills, which interleave three structurally different content types
within a single document.

3.
Approach

This section presents
SkillClone
, our approach for detecting multi-modal clone
relationships among agent skills. We first formalize the problem
(Section
3.1
), give an overview of the approach
(Section
3.2
), then detail multi-modal decomposition
(Section
3.3
), modality-specific encoding
(Section
3.4
), cross-modal fusion
(Section
3.5
), and clone type classification
(Section
3.7
).

3.1.
Problem Definition

Input.
A corpus of
N
agent skill documents
\mathcal{S}=\{s_{1},\ldots,s_{N}\}
, where each skill
s_{i}
is a structured document
containing YAML metadata
y_{i}
, natural language instructions
n_{i}
, and
embedded code blocks
c_{i}=\{b_{1},\ldots,b_{k}\}
.

Output.
A set of clone pairs
\mathcal{C}\subseteq\mathcal{S}\times\mathcal{S}
where each pair
(s_{i},s_{j},\tau,\sigma)\in\mathcal{C}
is annotated with clone type
\tau\in\{\text{Type-1},\text{Type-2},\text{Type-3},\text{Type-4}\}
and confidence
\sigma\in[0,1]
.

Goal.
Maximize detection F1 for true clone relationships
across all four clone types, with particular emphasis on Type-3 and Type-4
semantic clones that syntactic detectors miss.

We adapt the classical clone type taxonomy
(
Roy et al. 2009
)
to multi-modal
skills: Type-1 denotes identical content across all channels after whitespace
normalization; Type-2 denotes cosmetic changes such as variable renaming in
code or minor metadata edits; Type-3 denotes structural modifications including
added or removed instructions; and Type-4 denotes skills with the same
functional intent but substantially different implementation.

3.2.
Approach Overview

Figure 2
.
Overview of the
SkillClone
pipeline. Each skill is decomposed into four
channels, encoded via two paths (flat TF-IDF for detection strength,
per-channel TF-IDF+LSA for interpretability), fused into a calibrated clone
probability, and classified into clone types via a decision tree.

Figure
2
illustrates our four-phase approach. The design
reflects two principles. First,
modality awareness
: each content channel
is encoded with techniques suited to its semantics rather than treating the
skill as flat text. Second,
cross-channel interaction
: rather than
scoring channels independently and taking a weighted sum, the fusion mechanism
models pairwise interactions between channel similarities, capturing patterns
such as “high YAML and moderate NL but absent code” that indicate structural
adaptation (as in Figure
1
).

3.3.
Multi-Modal Decomposition

Each skill
s_{i}
is decomposed into a quadruple
s_{i}=(y_{i},n_{i},c_{i},\mathbf{f}_{i})
: the YAML metadata
y_{i}
extracted from the frontmatter
(fields:
name
,
description
,
category
,

tags
); the natural language instructions
n_{i}
comprising the
behavioral specification after the frontmatter, with code fences removed; the
code component
c_{i}=\{b_{1},\ldots,b_{k}\}
collecting all fenced code blocks
with their language annotations; and a structural feature vector
\mathbf{f}_{i}\in\mathbb{R}^{8}
capturing document-level statistics.

The decomposition uses regex-based parsing to identify YAML frontmatter
(delimited by
---
), code fences (delimited by
‘‘‘
), and the
remaining NL body. We filter boilerplate entries by removing skills with fewer
than five meaningful tokens after stopword removal.

The structural feature vector
\mathbf{f}_{i}
captures eight document-level
properties: total word count, number of code blocks, code-to-text ratio,
average code block length, number of unique programming languages, presence of
YAML frontmatter, number of YAML fields, and description length. These features
capture the
shape
of a skill document, because two skills with similar
structure (e.g., same number of code blocks, similar code fraction) are more
likely to be clones than skills with different structural profiles. Each
feature is min-max normalized across the corpus.

3.4.
Modality-Specific Encoding

We encode each channel using latent semantic analysis
(LSA)
(
Deerwester et al. 1990
)
: channel-specific TF-IDF
vectorization
(
Manning et al. 2008
)
followed by truncated SVD projection to

d=256
dimensions, producing dense embeddings that capture semantic
similarity within each modality. This design follows established practices in
both NL document similarity
(
Deerwester et al. 1990
;
Manning et al. 2008
)
and code clone
detection
(
Sajnani et al. 2016
;
Roy et al. 2009
)
, adapting them to the
multi-modal skill setting. For the NL channel, TF-IDF+LSA captures topical
similarity in a manner analogous to sentence embedding
approaches
(
Reimers and Gurevych 2019
)
, while avoiding external API dependencies.
For the code channel, our language-aware tokenization follows the token-based
tradition of CCFinder
(
Kamiya et al. 2002
)
and
SourcererCC
(
Sajnani et al. 2016
)
, extended with cross-language
normalization for the multi-language code blocks found in skills.

This approach provides three advantages over neural encoders for our setting:
it requires no API calls or GPU resources, enabling full reproducibility; it
naturally handles the heterogeneous vocabulary across channels (YAML key-value
pairs, free-form text, multi-language code); and it scales linearly with
corpus size. Neural alternatives such as
CodeBERT
(
Feng et al. 2020
)
, GraphCodeBERT
(
Guo et al. 2021
)
, and
UniXcoder
(
Guo et al. 2022
)
achieve strong results on single-language code
clone benchmarks, but assume homogeneous input with a single programming language
per document, which does not hold for skills interleaving Python, Bash, and
YAML within the same file.

YAML Channel.
We serialize the YAML metadata by
concatenating key-value pairs and project through TF-IDF+SVD to produce

\mathbf{e}^{y}_{i}\in\mathbb{R}^{d}
, capturing taxonomic relatedness.

NL Channel.
The natural language body is tokenized
with standard preprocessing (lowercasing, stopword removal) and encoded
through TF-IDF+SVD, producing
\mathbf{e}^{n}_{i}\in\mathbb{R}^{d}
that captures
semantic similarity between behavioral specifications in the latent space.

Code Channel.
Code blocks require specialized
tokenization: (1) camelCase/snake_case splitting, (2) operator token
extraction preserving semantically meaningful operators (
|>
,

=>
), and (3) language tag prefixing
(
__lang_python__
) enabling cross-language discrimination. The
resulting tokens are encoded through TF-IDF+SVD to produce

\mathbf{e}^{c}_{i}\in\mathbb{R}^{d}
.

3.5.
Cross-Modal Similarity Fusion

The three per-channel embeddings and the structural features capture
complementary facets of skill relatedness. Following the principle that
multi-modal fusion outperforms any single
modality
(
Liang et al. 2024
;
Radford et al. 2021
)
, the core technical
contribution of
SkillClone
is a fusion mechanism that combines per-channel
similarity with learned
cross-channel interaction
terms, producing a
calibrated clone probability rather than an ad hoc score.

The IDOR clone from Figure
1
illustrates the central fusion
challenge. In that pair,
s_{j}
contains zero code blocks, yielding
\text{sim}_{c}=0.00
.
A fixed weighted sum that includes this zero dilutes the strong YAML
(
{\sim}0.95
) and NL (
{\sim}0.60
) signals, risking a false negative. More
subtly, the
combination
of high YAML and moderate NL is stronger
evidence than either signal alone: metadata identity plus partial instruction
overlap indicates deliberate adaptation, not coincidence. The fusion mechanism
must therefore (i) adapt to absent channels and (ii) model interactions
between present channels.

Intra-channel similarity.

For each candidate pair
(s_{i},s_{j})
, we compute per-channel cosine
similarities within each modality’s latent space:

(1)

\text{sim}_{m}(i,j)=\cos(\mathbf{e}^{m}_{i},\mathbf{e}^{m}_{j}),\quad m\in\{y,n,c\}

Each similarity is defined only when both skills have non-trivial content in
channel
m
; we formalize this below.

Similarity profile.

We collect the per-channel similarities into a single vector that
characterizes the pair’s multi-modal relationship:

(2)

\mathbf{s}(i,j)=\bigl[\text{sim}_{y}(i,j),\;\text{sim}_{n}(i,j),\;\text{sim}_{c}(i,j)\bigr]\in[0,1]^{3}

The similarity profile is the primary representation for downstream clone
detection: its geometry directly encodes clone type (Type-1 pairs cluster
near
(1,1,1)
; Type-4 pairs exhibit high
\text{sim}_{n}
with low

\text{sim}_{c}
), making it a richer object than any scalar summary.

Channel presence.

Not every skill contains every modality. We define a binary presence
indicator per channel:

(3)

P_{m}(i,j)=\begin{cases}1&\text{if channel }m\text{ is non-trivially present in both }s_{i},s_{j}\\
0&\text{otherwise}\end{cases}

When
P_{m}=0
, the corresponding
\text{sim}_{m}
is set to zero. Critically,
a missing channel is
absence of evidence
, not evidence of dissimilarity.
The logistic model (below) learns this distinction from training pairs that
include both present and absent channels. In the IDOR example,

P_{c}(i,j)=0
because
s_{j}
has zero code blocks.

Quadratic feature map.

A simple weighted sum of per-channel similarities cannot model interactions:
it treats
\text{sim}_{y}=0.95
and
\text{sim}_{n}=0.60
as independent
additive contributions, missing the fact that their
conjunction

provides disproportionately strong evidence of cloning. We therefore lift
the similarity profile into a quadratic feature space:

(4)

\varphi(\mathbf{s})=\bigl[\underbrace{s_{y},\;s_{n},\;s_{c}\vphantom{\big|}}_{\text{main effects}},\;\;\underbrace{s_{y}{\cdot}s_{n},\;\;s_{n}{\cdot}s_{c},\;\;s_{y}{\cdot}s_{c}\vphantom{\big|}}_{\text{cross-channel interactions}}\bigr]\in\mathbb{R}^{6}

where
s_{m}
abbreviates
\text{sim}_{m}(i,j)
, and any term involving a
channel with
P_{m}=0
is zeroed. The six features decompose into two groups.
The
main effects
capture per-channel evidence: high
s_{n}
alone
suggests topical similarity. The
interaction terms
capture
cross-channel correspondence: a high
s_{n}{\cdot}s_{c}
product indicates that
both the behavioral specification
and
the implementation are similar,
providing stronger clone evidence than either channel independently. This
product-of-similarities formulation replaces the cross-space cosine used in
prior multi-modal fusion
designs
(
Liang et al. 2024
)
: computing

\cos(\mathbf{e}^{n}_{i},\mathbf{e}^{c}_{j})
across different LSA subspaces is
geometrically ill-defined because the NL and code projections occupy
incomparable latent dimensions. The interaction term
s_{n}\cdot s_{c}
achieves
the same goal—capturing NL-Code correspondence—through well-defined
within-space similarities.

When
P_{c}=0
, the features
s_{c}
,
s_{y}{\cdot}s_{c}
, and

s_{n}{\cdot}s_{c}
all vanish, and the model reduces to three active features:

[s_{y},\;s_{n},\;s_{y}{\cdot}s_{n}]
. The learned coefficients for these
features absorb the predictive burden, providing principled degradation rather
than dilution through a zero-valued channel.

TF-IDF base score.

In addition to per-channel similarities, we compute a flat TF-IDF cosine
similarity on the full
SKILL.md
content treated as a single string.
This flat score naturally captures cross-channel vocabulary overlap—a skill
about IDOR testing will contain “idor” in YAML name, NL body, and code
comments simultaneously—providing a strong detection baseline that
channel-specific encoding cannot replicate. The flat score is prepended to
the feature vector as the first element.

Structural similarity.

The structural feature vector
\mathbf{f}_{i}

(Section
3.3
) captures document-level shape. Its
similarity

\text{sim}_{f}(i,j)=1-\|\mathbf{f}_{i}-\mathbf{f}_{j}\|_{1}/\dim(\mathbf{f})

is appended as the final feature, capturing whether two skills have similar
structure (code block count, code fraction, description length) regardless of
content.

Logistic fusion.

The complete feature vector concatenates the flat TF-IDF score, the
quadratic channel features, and structural similarity into an 8-dimensional
input:

(5)

P(\text{clone}\mid i,j)=\sigma\!\bigl(\mathbf{w}^{\top}[\,\text{sim}_{\text{flat}},\;\;\varphi(\mathbf{s}),\;\;\text{sim}_{f}\,]+b\bigr)

where
\sigma(z)=1/(1+e^{-z})
is the logistic sigmoid, and

\mathbf{w}\in\mathbb{R}^{8}
,
b\in\mathbb{R}
are learned by maximum
likelihood on annotated pairs from
SkillClone-Bench
with balanced class weights.
The 9 parameters (8 weights plus bias) are jointly optimized via MLE with
5-fold stratified cross-validation.

This dual-path design is deliberate. The flat TF-IDF score provides a strong
detection baseline—it achieves 0.881 F1 alone
(Table
3
)—while the channel decomposition adds discriminative
evidence that flat text cannot provide: interaction terms model cross-channel
correspondence, and the structural feature captures document-shape agreement.
The logistic model learns to combine both paths, achieving 0.939 F1 by
exploiting their complementarity.

Interpretability.

The logistic model retains the per-channel transparency of a weighted sum
while adding interaction-level insight. For any flagged pair, the linear
combination
\mathbf{w}^{\top}\varphi(\mathbf{s})
decomposes into six
additive contributions, each corresponding to a named feature. A pair whose
dominant contribution is
w_{s_{n}}\cdot s_{n}
indicates NL-driven similarity
(possible Type-4 semantic clone); a pair dominated by

w_{s_{y}\cdot s_{n}}\cdot s_{y}\cdot s_{n}
indicates metadata-and-instruction
alignment without code evidence—the fractal adaptation pattern of
Figure
1
. This decomposition is valuable for security and
governance applications where understanding the
nature
of a clone
relationship matters as much as detecting it.

Running Example

We illustrate the fusion using the IDOR clone pair from

. For

(

blocks) and
s_{j}
(
Dokhacgiakhoa

blocks),
SkillClone
computes: flat TF-IDF similarity
=0.61
(shared IDOR
vocabulary across the full documents), channel profile

\mathbf{s}=[0.95,\;0.60,\;0.00]
, and structural similarity
=0.38

(different document shape due to code extraction). Because
P_{c}=0
, the
8-feature vector becomes:

[\,\underbrace{0.61}_{\text{flat}},\;\;0.95,\;\;0.60,\;\;0,\;\;\underbrace{0.57}_{s_{y}\cdot s_{n}},\;\;0,\;\;0,\;\;\underbrace{0.38}_{\text{struct}}\,]

The flat TF-IDF score provides the base detection signal, while the
YAML-NL interaction (
0.57
) adds super-additive evidence. The logistic
fusion assigns
P(\text{clone})=0.82
, well above
\theta=0.50
.
The per-channel profile immediately reveals the clone type: high YAML, moderate NL,
absent code
\Rightarrow
structural adaptation.

For contrast, two Kubernetes skills sharing

might have flat TF-IDF
=0.55

3.7.
Clone Type Classification

Once the logistic fusion identifies a clone (
P(\text{clone})\geq\theta
),
the similarity profile
\mathbf{s}=[s_{y},s_{n},s_{c}]
directly determines
the clone
type
. Rather than partitioning the profile space with
ad hoc score ranges, we define three Boolean predicates that each encode a
structural property from the classical clone taxonomy
(Table
1
), then compose them into a deterministic decision
tree.

Predicates.

Let
\mathcal{P}
denote the set of channels present in both skills and

\mathbf{s}_{\mathcal{P}}
the corresponding sub-vector.

•

Near-Identical
(\mathbf{s})
:

\;\min(\mathbf{s}_{\mathcal{P}})\geq\tau_{1}
.
All present channels are near-verbatim—the defining property of Type-1
(“exact except layout/comments”).

•

Uniform
(\mathbf{s})
:

\;\max(\mathbf{s}_{\mathcal{P}})-\min(\mathbf{s}_{\mathcal{P}})\leq\delta
.
Channel similarities agree within tolerance
\delta
—structure is
preserved, consistent with Type-2 (“cosmetic relabeling”).

•

NL-Code-Split
(\mathbf{s})
:

\;s_{n}\geq\tau_{2}\;\wedge\;(s_{c}<\tau_{2}\;\vee\;P_{c}{=}0)
.
The intent channel (NL) shows similarity but the implementation channel
(code) diverges or is absent—the defining signature of Type-4
(“same semantics, different syntax”).

Decision tree.

The three predicates compose into a four-leaf tree with no overlapping
regions:

(1)

If
Near-Identical
(\mathbf{s})
:
Type-1
.

(2)

Else if
Uniform
(\mathbf{s})
:
Type-2
.

(3)

Else if
NL-Code-Split
(\mathbf{s})
:
Type-4
.

(4)

Else:
Type-3
(asymmetric profile with partial channel edits).

The ordering is deliberate: Type-1 is a strict subset of Type-2 (all
near-identical profiles are also uniform), so it must be tested first. Type-4
is tested before the Type-3 fallback because the NL-Code split is a specific
pattern of asymmetry that warrants its own category.

Parameters.

The tree requires only three values:
\tau_{1}
(identity threshold),

\delta
(uniformity tolerance), and
\tau_{2}
(semantic threshold), tuned on
the validation split. In our evaluation,
\tau_{1}=0.90
,

\delta=0.20
,
\tau_{2}=0.50
.

Example.

The IDOR pair from Figure
1
has

\mathbf{s}=[0.95,\;0.60,\;0.00]
with
P_{c}=0
.

Near-Identical
fails (
\min=0.60<0.90
).

Uniform
fails (
0.95-0.60=0.35>0.20
).

NL-Code-Split
:
s_{n}=0.60\geq 0.50
and
P_{c}=0

\Rightarrow

true, so the pair is classified as
Type-4
. The decision trace is
fully auditable: each predicate maps to a named property from the clone
taxonomy.

Scalability.

At ecosystem scale (
N
= 20K,
\sim
200M candidate pairs), we exploit the
dense LSA embeddings for efficient batch cosine similarity via matrix
multiplication. An NL-channel pre-filter at
\theta_{\text{cand}}=0.10

reduces candidates by over 90%, enabling full multi-modal scoring in under
30 seconds on a single CPU.

4.1.
Registry Corpus

We crawled the skillsmp.com registry, retrieving
SKILL.md
content for
155,547 of 196,134 listed skills (79.3% success rate; failures due to deleted
or private repositories). The corpus totals 1.19 GB (avg. 7.6 KB per
skill); 78% of skills contain code blocks and 43% are code-heavy
(
>
50% code), confirming the need for multi-modal analysis.

4.2.
Benchmark Construction

No benchmark exists for clone detection on multi-modal agent skills.
We construct
SkillClone-Bench
, a balanced benchmark of 300 ground-truth pairs (150
positive, 150 negative) with stratified difficulty across both classes.

Design principles.

We prioritize quality over quantity: each pair is included for a specific
evaluation purpose, and both classes are stratified by difficulty so that
aggregate metrics are not dominated by trivial cases. Positives span four
clone types at increasing difficulty; negatives range from obvious non-matches
to deliberately confusing same-category pairs. We avoid manual labeling
entirely—all labels derive from verifiable provenance (fork trees) or
controlled generation (mutations).

Positive pairs (150).

We draw equally from two complementary sources, each contributing 75 pairs:

Fork-mined pairs
(75) exploit GitHub fork relationships as verifiable
provenance. When a developer forks a skill repository and modifies its
contents, the fork tree confirms derivation. We match skills across forks by
file path and name similarity, then stratify by modification level into
Type-1 (verbatim), Type-2 (renamed), Type-3 (structurally modified), and
Type-4 (semantically equivalent but rewritten).

Synthetic mutations
(75) ensure coverage of controlled difficulty
levels via seven operators applied to randomly sampled seed skills:
M1 (identifier renaming, Type-2),
M2 (NL paraphrasing with synonym replacement and 30% content removal, Type-3),
M3 (code stripping that retains only NL section headers, Type-4),
M4 (content extension, Type-3),
M5 (content subsetting, Type-3),
M6 (cross-skill combination, Type-3), and
M7 (full semantic rewrite via LLM paraphrase, Type-4).
M3 and M7 produce the hardest pairs: both preserve functional intent while
eliminating surface-level token overlap.

Negative pairs (150).

To avoid easy-negative inflation, we stratify negatives by difficulty:

Easy negatives
(50) pair skills from different categories (e.g.,
DevOps vs. documentation), providing clear non-clones where low similarity
is expected.

Hard negatives
(100) pair skills from the
same
category whose
multi-modal similarity falls in
[0.15,0.45]
. These pairs share topical
vocabulary (e.g., two Kubernetes skills both referencing
kubectl
and

namespace
) without being clones. Hard negatives constitute two-thirds
of the negative set, deliberately stressing the detector’s ability to
distinguish vocabulary overlap from genuine cloning.

4.3.
Experimental Setup

Baselines.
We compare against four modality-matched
approaches:

•

TF-IDF (flat text):
Standard TF-IDF cosine similarity on the
full
SKILL.md
content as a single string, ignoring modality
structure.

•

MinHash:
Locality-sensitive hashing on character
n
-grams
(
n\!=\!5
) of the full skill text, representing a scalable token-based
baseline.

•

NL-Only:

SkillClone
’s NL channel embedding applied in isolation,
representing the strongest single-channel baseline.

•

Code-Only:

SkillClone
’s code channel embedding applied in
isolation.

Baseline Scope.
Our goal is to compare
SkillClone
against
baselines that preserve the task definition, namely clone detection over full
multi-modal skill documents rather than over extracted code fragments alone. We
therefore do not present this evaluation as an exhaustive state-of-the-art
bakeoff against every recent code-clone model. Instead, we compare against
strong text and token baselines plus single-channel ablations that operate on
the same underlying artifacts. We do not include neural code clone detectors
such as SAGA
(
Wu et al. 2024
)
, DeepSim
(
Zhao and Huang 2018
)
, or
MAGNET
(
Zhang and Saber 2025
)
because they require single-language parseable source
code as input (ASTs, PDGs, or token sequences). Agent skills are not parseable
programs, because they interleave YAML frontmatter, natural language prose, and code
blocks in multiple languages within a single document. Applying these tools
would require discarding the NL and YAML channels (78% of skill content by
volume), fundamentally changing the detection task. The NL-Only and Code-Only
ablations in Table
3
quantify the cost of this single-channel
restriction: both achieve lower F1 than multi-modal fusion.

Metrics.
We report precision, recall, and F1 score for
binary clone detection. For each approach, we find the optimal threshold via
grid search on
SkillClone-Bench
to ensure a fair comparison at each method’s best
operating point. For clone type analysis, we report per-type recall.

Environment.
All experiments run on a single machine with
32 GB RAM and an Intel Xeon CPU. We implement
SkillClone
and baselines in Python, using scikit-learn for TF-IDF and logistic regression. The full evaluation code and data are included in our replication package.

Finding 1: Most duplication is creative, not lazy

Only 9.7% of skills are exact (SHA-256) duplicates, yet 75% participate in

contrasts sharply with traditional package ecosystems where reuse is

rare
(

. In the skill ecosystem, the copy-and-modify

4.6.2.
Finding 2: Extreme author concentration and mirroring

The top 10 authors (0.9% of 1,060 total) produce 57.8% of all skills, with
a Gini coefficient of 0.868—more concentrated than income inequality in
most OECD countries. This is far more extreme than npm, where the top 1% of
maintainers account for
\sim
10% of
packages
(
Zimmermann et al. 2019
)
.

Clone analysis reveals two distinct author archetypes.
Originators

create novel skills that are subsequently copied by others:
davila7

(3,423

Aggregators
collect and rebrand others’ work:

(283 skills, 99% shared) is the most extreme case—its

(

drives ecosystem growth: originators create templates, aggregators amplify
them, and independent creators add genuinely novel capabilities.

5.
Discussion

5.1.
Clone Detection vs. Reuse Inference

Clone detection establishes structural similarity, not derivation.
Reuse inference
asks whether
s_{j}
was causally derived from
s_{i}
and therefore requires additional provenance signals such as fork relationships, commit timestamps, or explicit attribution.

In some cases, clone detection directly enables reuse confirmation. The
LabArchives example (Figure
1
) is unambiguous: 99.7%
character similarity on 260 lines of niche scientific content, combined with
the added
skill-author: K-Dense Inc.
metadata, constitutes a
smoking gun. Our fork-mined benchmark pairs similarly provide ground-truth
reuse via GitHub provenance. For the broader ecosystem analysis (RQ3), however,
we report
clone prevalence
, not reuse prevalence: the 258K detected
pairs include both intentional copies and cases of convergent development
where different authors independently produced similar skills.

For security applications (RQ4), the clone-vs-reuse distinction is immaterial.
Whether two skills share a vulnerability through copying or convergent
development, the blast radius is identical. Clone detection is sufficient to
identify the set of skills that share a malicious pattern, regardless of how
they came to share it.

5.2.
Implications

Our findings carry implications for multiple stakeholders. For
skill
registry operators
, the 75% clone involvement rate and 41% superseded-skill
rate suggest that deduplication and provenance tracking should be first-class
ecosystem features. For
security teams
, 90% of security-relevant seed
skills have at least one clone, yielding 1,100 downstream clones
(777 cross-author), so per-skill vulnerability scanning is insufficient and
clone-based propagation analysis is necessary to identify the full blast radius.

Precision and Recall Tradeoff.
On
SkillClone-Bench
, flat-text
TF-IDF is a strong baseline, achieving 0.897 precision, 0.867 recall, and
0.881 F1. However,
SkillClone
improves on all three metrics, reaching 0.952
precision, 0.927 recall, and 0.939 F1 by combining flat similarity with
per-channel evidence. This
difference matters more at ecosystem scale than on
SkillClone-Bench
alone: in a 20K-skill
corpus, small precision gaps translate into many spurious clone edges.
Additionally, flat-text TF-IDF cannot distinguish clone
types
, while

SkillClone
preserves the per-channel signal needed to separate exact copies from
harder semantic clones.

5.3.
Limitations

Our current study prioritizes task-faithful multi-modal analysis over exhaustive
model coverage. The evaluation therefore focuses on modality-matched baselines
rather than every recent neural code-clone detector, many of which assume
single-language source code input. In addition, although our crawl retrieved
155K skill files, the clone-graph analysis reported here uses 20K skills and a
300-pair benchmark. Larger annotated datasets and full-corpus runs would
improve confidence in the reported clone-type distribution and propagation
estimates. Our three-channel decomposition is also intentionally scoped to the
primary in-file modalities of
SKILL.md
artifacts, excluding auxiliary
repository context such as linked files, screenshots, and commit history.

5.4.
Threats to Validity

Internal validity.
The benchmark relies partly on synthetic
mutations; we mitigate this with fork-mined pairs and manual labels. Fusion
weights are optimized on
SkillClone-Bench
and may not generalize; the ablation shows
robustness to component removal.

External validity.
Our 20K-skill sample is substantial but
may not represent the full 196K ecosystem. The observed 75% clone-involvement
rate and 3.5
\times
inflation ratio may shift under a larger or more complete
crawl.

Construct validity.
The clone type taxonomy adapted from
source code may not capture all multi-modal similarity patterns. Threshold-based
type boundaries are heuristic; a learned classifier may improve accuracy.
The inter-annotator agreement (
\kappa=0.81
) is substantial but not perfect.
Our ecosystem analysis reports clone prevalence, not confirmed reuse; the
Type-4 dominance may include convergent development cases that are structurally
similar but causally independent.

6.
Related Work

6.1.
Code Clone Detection

Code clone detection has been studied extensively over two decades
(
Roy et al. 2009
)
. Representative classical approaches include token-based systems such as CCFinder and CP-Miner
(
Kamiya et al. 2002
;
Li et al. 2006
)
, tree-based systems such as NiCad and Deckard
(
Roy and Cordy 2008
;
Jiang et al. 2007
)
, and scalable index-based systems such as SourcererCC
(
Sajnani et al. 2016
)
. BigCloneBench
(
Svajlenko et al. 2014
)
standardized evaluation, while newer neural approaches such as DeepSim, CCLearner, SAGA, and MAGNET target harder semantic clones
(
Zhao and Huang 2018
;
Li et al. 2017
;
Wu et al. 2024
;
Zhang and Saber 2025
)
. However, these methods assume source code as the primary artifact.
SkillClone
instead targets multi-modal skill documents that interleave natural language, YAML metadata, and embedded code, extending clone detection to a new class of software artifacts.

6.2.
Software Ecosystem Analysis

Large-scale ecosystem studies have characterized dependency structure and systemic risk in registries such as npm and PyPI
(
Zimmermann et al. 2019
;
Wittern et al. 2016
;
Kikas et al. 2017
;
Decan et al. 2019
;
Bommarito and Bommarito 2019
)
. Recent work has also begun to characterize the architecture and growth of agent-skill ecosystems
(
Xu and Yan 2026
;
Ling et al. 2026
)
. However, prior studies do not model inter-skill clone relationships. This omission is particularly important in a flat ecosystem with no dependency mechanism, where reuse is implicit rather than declared.
SkillClone
addresses this gap by inferring clone relationships directly from content similarity and constructing the first clone graph for agent skills.

6.3.
Supply Chain Security

Software supply chain research has shown that vulnerabilities and malicious packages propagate through ecosystem structure rather than through isolated artifacts alone
(
Liu et al. 2022
;
Ohm et al. 2020
;
Duan et al. 2021
)
. In agent ecosystems, recent tools focus on per-skill analysis for vulnerability detection, formal verification, malicious tool identification, prompt injection, and MCP-server risks
(
Liu et al. 2026b
;
Bhardwaj 2026
;
Liu et al. 2026a
;
Zhao et al. 2025
;
Hasan et al. 2025
;
Jia et al. 2026
;
Schmotz et al. 2026
;
Schmotz et al. 2025
;
Maloyan and Namiot 2026
)
. The January 2026 ClawHavoc campaign
(
Koi Security 2026
)
underscores the practical importance of these risks.
SkillClone
complements this line of work by adding clone-graph analysis: instead of inspecting each skill in isolation, it traces reuse links to estimate the blast radius of malicious or vulnerable patterns.

7.
Conclusion

We presented
SkillClone
, the first multi-modal clone detection approach for agent
skills, fusing YAML, NL, and code similarity with cross-modal alignment. On

SkillClone-Bench
(300 pairs),
SkillClone
achieves F1 of 0.939, outperforming TF-IDF (0.881)
and achieving 4.2
\times
higher Type-4 recall than MinHash. Applied to 20K
skills,
SkillClone
reveals 258K clone pairs involving 75% of all skills, with 40%
cross-author reuse and a 3.5
\times
ecosystem inflation ratio after
deduplication. Security propagation analysis identifies 141 real
security-relevant seed skills whose patterns reach 1,100 clones across 119
affected authors. We distinguish clone detection from reuse inference, showing
clone analysis is both independently valuable for security and enables
downstream reuse discovery when combined with provenance signals.
