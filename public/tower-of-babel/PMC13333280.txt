Letter to the Editor. Re: “AI-driven Internet of Things (IoT) dataset for remote health monitoring and fall detection in elderly people,” Data in Brief 66 (2026) 112641
Authors: M. Sabrigiriraj, K. Manoharan
Published: 2026

Dear Editor,

Overview

We read with interest the article by Islam et al., “AI-Driven Internet of Things (IoT) dataset for remote health monitoring and fall detection in elderly people,” published in Data in Brief 66 (2026) 112641 [1]. The authors presented a simulated IoT dataset for elderly health monitoring and fall detection. The dataset contains physiological and motion-related measurements. It also includes labels for health condition, fall detection, and health risk. According to the article, the dataset contained 612 records from 17 synthetic subjects, with 36 records per subject.

This is an important topic. Open datasets for elderly care, remote monitoring, and fall detection are still limited. Synthetic datasets can also be useful when real-world elderly-care data are difficult to collect or share. However, when we tried to reuse the originally released CSV file, we found a structural problem that could affect machine-learning benchmarking.

Our exact row-duplicate analysis showed that the originally released CSV file [2] had 612 rows, but only 36 unique rows. The other 576 rows were exact duplicate rows beyond the first occurrence. Each unique row appeared 17 times. This repetition pattern matched the reported number of synthetic subjects. Therefore, the originally released CSV file appeared to contain the same 36-record sequence repeated across 17 subject cycles, rather than 17 distinct subject-level trajectories.

During editorial handling, the original authors reviewed their data-generation process and acknowledged that the exact row-level repetition in the originally released CSV file was valid. They explained that an incorrect intermediate file had been used at the dataset release stage. According to their clarification, this file kept the intended 36-record simulation cycle but repeated it across the 17 synthetic subject cycles without the final subject-level perturbation step.

The authors later updated the Mendeley Data record to Version 2. The Version 2 record was published on 11 May 2026 and has the DOI 10.17632/tf56mbyg69.2 [3]. We appreciate this response and the update. However, Version 2 contains two CSV files. Our analysis shows that one file appears to be the corrected dataset, while the other file still appears to be the earlier duplicate-containing dataset. This should be stated clearly in the repository record so that future users select the correct file.

Details

The dataset record is titled “Remote Health Monitoring and Fall Detection in Elderly People.” The comparison page for the Mendeley Data record shows Version 1 published on 21 October 2025 with DOI 10.17632/tf56mbyg69.1 and Version 2 published on 11 May 2026 with DOI 10.17632/tf56mbyg69.2 [2,3]. The comparison page shows that a new version was added, but it does not clearly explain the file-level correction.

We checked the originally released CSV file by comparing all columns of each row. This simple check showed that the file had only 36 unique rows. Each of these rows was repeated exactly 17 times, giving 612 rows in total. The duplicate structure was systematic and followed the same number as the reported 17 synthetic subjects.

This matters for benchmarking. If identical rows are repeated in a dataset, a random or stratified train-test split may place the same record in both the training and testing sets. In that case, high model performance may partly reflect repeated records rather than real generalization. This does not mean that the dataset has no value. It means that the originally released file should not be treated as 612 independent observations.

Our concern is also not about the dataset being synthetic. The article clearly states that the dataset was simulated. The concern is that the originally released file gave a higher impression of record-level diversity than it actually had. If users downloaded that earlier file and used ordinary splitting methods, they could obtain overly optimistic results.

The published article stated that the repository included one CSV file and a README, and it named the CSV file as healthmonitoringandfalldetection.csv. In the Version 2 repository, however, two CSV files are present. Our audit showed that Health Monitoring and Fall detection dataset.csv appears to be the corrected file, while healthmonitoringandfalldetection.csv still contains the earlier duplicate structure. This file-level distinction should be clearly stated in the repository record.

We also inspected the two CSV files now available in Version 2. The file named “Health Monitoring and Fall detection dataset.csv” contained 612 rows, 16 variables, 612 unique rows, and no exact duplicate rows. This file therefore appears to be the corrected dataset file. The file named “healthmonitoringandfalldetection.csv” contained 612 rows and 16 variables, but only 36 unique rows and 576 exact duplicate rows. This file therefore appears to be the earlier duplicate-containing file.

This distinction is important. Version 2 is useful because it includes a corrected dataset file. At the same time, keeping the earlier duplicate-containing file in the same version may confuse users if the repository does not clearly identify the corrected file. A user who downloads the wrong CSV file from Version 2 may still reproduce the original duplication problem.

We repeated the experiment using the corrected file, “Health Monitoring and Fall detection dataset.csv.” The corrected file retained the expected structure of 612 records and 16 variables. It had no missing values in the variables inspected. The health-condition distribution was Normal = 187, Hypertension = 85, Hypotension = 85, Fever = 85, Hypoxia = 85, and Fall = 85. The fall-detection distribution was 527 records with fall_detected = 0 and 85 records with fall_detected = 1. The health-risk distribution was 187 records with health_risk = 0 and 425 records with health_risk = 1.

The repeated experiment using the corrected file continued to show high classification performance for the main prediction tasks. This supports the authors’ statement that the broad purpose of the dataset remains unchanged. However, our repeated experiment may not exactly match the full original analysis pipeline used by the authors. For this reason, an author-provided short comparison using the original analysis settings would be useful.

The authors also stated that the earlier file missed the final subject-level perturbation step. This explanation is important, but it needs a little more detail. A short description of this step would help users understand how Version 2 differs from Version 1. It would also help users understand how subject-level variation was introduced into the corrected file.

Suggestions

We welcome the authors’ acknowledgement of the issue and their update of the Mendeley Data repository. This is a constructive response. It helps future users, provided that the corrected file is clearly identified.

First, the Version 2 repository record should state that “Health Monitoring and Fall detection dataset.csv” is the corrected dataset file. It should also state that “healthmonitoringandfalldetection.csv” contains the earlier duplicate structure, if that file is retained for transparency.

Second, the repository record or a linked correction note should clearly explain why Version 2 was created. Third, the documentation should include a short duplicate-audit summary for both CSV files in Version 2. This would help users understand which file should be used for new analyses.

Fourth, the authors should briefly explain the subject-level perturbation step. It would be useful to know which variables were perturbed, whether the perturbation was applied separately to each synthetic subject, and whether the corrected records remain clinically and physiologically reasonable within the intended simulation design.

Finally, a short validation summary would be useful. Since the article reported machine-learning results, a short comparison of key results before and after correction would help readers understand whether the corrected file gives broadly similar findings. Our own repeated experiment using the corrected file still showed high classification performance, but the authors are best placed to provide a direct comparison using their original settings.

In summary, our analysis found exact row-level repetition in the originally released CSV file. The authors acknowledged the issue and released Version 2 of the dataset. Our inspection of Version 2 shows that it contains both a corrected CSV file and a duplicate-containing CSV file. We respectfully suggest that the repository should clearly identify the corrected file, explain the purpose of the second file, briefly describe the missing subject-level perturbation step, and provide a short validation summary. This would improve the transparency and reuse value of the dataset.

Ethics Statement

This letter is based on analysis of a publicly available dataset article and dataset files. It did not involve human participants, animals, or social media data.
