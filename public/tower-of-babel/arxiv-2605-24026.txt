A Per-Access Upper Bound for Shared-Resource Interference in Direct-Mapped Multicore Architectures
Felipe T. Pedroni

Abstract
We present a formal bounding analysis for maximum credible interference in multicore processors under strict architectural invariants: direct-mapped L2 cache (1-way associativity), disabled Miss Status Handling Registers (MSHRs), single-bank main memory, deterministic pinned tasks with fixed physical memory mapping, and a pessimistic L2/memory arbitration policy. We prove that, under these invariants, the per-critical-access stall imposed on a target task T T is bounded above by ( N − 1 ) ​ L mem (N-1)L_{\text{mem}} , and that this bound is attained by a synchronized adversarial workload of N − 1 N-1 congruent-different-tag memory requests issued in phase with T T ’s critical accesses. The argument is per-access and direct, requiring no informal multiplicative interference function. The derivation is purely analytical and discussed in the context of DO-178C/CAST-32A certification objectives for airborne software. Limitations and conditions for applicability are explicitly stated. This work provides a traceable method for separating multicore interference from Worst-Case Execution Time (WCET) budgets under fixed architectural constraints.



Keywords:
Multicore interference, WCET analysis, DO-178C, CAST-32A, formal bounding, cache contention, real-time systems, RISC-V safety-critical extensions

1
Introduction

Multicore processors introduce shared-resource contention channels that complicate timing analysis for safety-critical systems. Certification standards such as DO-178C with CAST-32A guidance require demonstration of “maximum credible interference” for shared resources including caches, buses, and memory controllers
[
1
]
. However, existing approaches often rely on empirical measurement or conservative pessimism without formal closure of the adversarial search space.

This work addresses the following question:
Given a fixed architectural configuration and arbitration policy, can we formally bound the worst-case shared-resource interference on a target task and exhibit an adversarial workload that attains the bound?

We answer affirmatively under a well-defined constraint space. Our contribution is threefold:

(i)

A formal system model capturing hardware invariants, workload determinism, an arbitration policy, and configuration parameters (
Section

3
);

(ii)

Three lemmas establishing per-dimension upper bounds on spatial, temporal, and pattern-based interference (
Section

4
);

(iii)

A main theorem proving a per-access stall bound of
(N-1)L_{\text{mem}}
, attained by a synchronized congruent-different-tag adversarial workload (
Section

5
).

The result may support certification evidence packages requiring traceable, analytically justified interference bounds, provided the target platform is independently characterized to satisfy the stated invariants. It also aligns with pre-silicon verification workflows for customizable ISAs (e.g., RISC-V extensions) where timing predictability must be established before tape-out.

Related Work

Interference analysis in multicore real-time systems has been extensively studied. Pellizzoni et al.
[
2
]
introduced a framework for bounding memory contention in COTS multicore platforms. Schranzhofer et al.
[
3
]
developed timing analysis models for shared buses and caches. More recent work by Kelter et al.
[
4
]
and Bhattacharjee et al.
[
5
]
addresses cache partitioning and interference-aware scheduling.

However, most prior approaches either: (a) assume set-associative caches with replacement policies that complicate worst-case analysis; (b) rely on probabilistic or measurement-based bounds without formal closure; or (c) treat interference dimensions independently rather than proving joint maximality. Our work differs by establishing a
direct per-access bound
under explicitly stated architectural invariants and a documented arbitration assumption, providing a formally closed adversarial search space for certification purposes.

The CAST-32A guidance
[
1
]
emphasizes the need for “credible” worst-case scenarios but does not prescribe methods for proving maximality. This work fills that methodological gap for a well-defined architectural subclass.

3
Formalization of the Search Space

We define the system as a closed tuple
S=\langle H,W,R,C\rangle
, separating the arbitration policy
R
from the configurable adversarial parameters
C
:

Definition 1

(Hardware Invariants
H
)
.

The hardware platform satisfies the following invariants:

•

N
processor cores:
C_{0},C_{1},\dots,C_{N-1}

•

Private L1 instruction and data caches per core

•

Shared L2 cache: direct-mapped (1-way associative), no MSHRs

•

Main memory: single-bank architecture, shared across all cores

•

Fixed latency per L2 miss:
L_{\text{mem}}
(includes dirty write-back + read + bus turnaround)

•

Address decomposition: every physical address
a
admits a decomposition into a set index
\sigma(a)
and a tag
\tau(a)
. The cache-set mapping function is
S(\cdot)(a):=\sigma(a)
.

Definition 2

(Workload
W
)
.

Target task
T
with deterministic address sequence per period:

\mathcal{A}_{T}=\langle a_{1},a_{2},\dots,a_{k}\rangle

The
critical access set

\mathcal{P}_{\text{crit}}\subseteq\mathcal{A}_{T}
comprises those accesses that lie on the data/control dependency chain determining
T
’s WCET. All instances of
T
are pinned to cores, have identical period, worst-case execution time, and start synchronized at time
M
.

Definition 3

(Arbitration Model
R
)
.

The L2/memory arbitration policy is a function that, at each scheduling decision, selects one core’s pending request among the contending requests. We say the policy is
pessimistic for
T
if, whenever
T
’s request contends simultaneously with one or more adversarial requests,
T
is selected last; equivalently,
T
is served only after all contending adversarial requests have been completed.

Assumption 4

(Pessimistic Arbitration)
.

The arbitration policy
R
is pessimistic for
T
. This is a worst-case modeling assumption used throughout the proofs: under any policy that is not pessimistic for
T
(e.g., fixed priority favoring
T
’s core, round-robin starting at
T
, age-based with
T
arriving first), the stall on
T
is less than or equal to the bound established here.
4
therefore yields a sound upper bound and, when the implemented arbiter is not characterized, is the appropriate certification-time abstraction.

Definition 5

(Configuration
C
)
.

Parameters defining
N-1
adversarial tasks:

•

Memory mapping: physical-to-cache-set function
S(\cdot)

•

Start time offset relative to
T

•

Access pattern (address sequence)

Definition 6

(Admissible Configuration)
.

A configuration
C
is
admissible
if it satisfies all of the following:

•

Each of the
N-1
adversarial tasks is pinned to a distinct core and shares the same period and worst-case execution time as
T
;

•

Each adversarial core holds at most one in-flight L2 request at any instant (consistent with the no-MSHR / blocking miss-handling property of
H
);

•

Each L2 miss incurs the fixed latency
L_{\text{mem}}
defined in
H
;

•

No data sharing exists between
T
and the adversaries, and no out-of-model interference channels (DMA, asynchronous interrupts, power management transitions, TLB pressure, coherence traffic) are active during the analysis window.

All bounds in this paper are stated over admissible configurations.

Definition 7

(Interference Metric)
.

Total interference on
T
’s execution time:

I_{T}=\sum_{i=1}^{k}\Delta t(a_{i})

where
\Delta t(a_{i})
is the additional stall imposed on access
a_{i}
due to contention on shared resources (L2 arbiter, memory bus, memory controller).

Assumption 8

(Architectural Invariants)
.

The hardware configuration
H
is fixed and documented. No dynamic reconfiguration, power management, or thermal throttling occurs during the analysis window.

Assumption 9

(Workload Determinism)
.

Task
T
exhibits deterministic control flow and memory access patterns for a given input. No data-dependent branching affects the critical path under analysis.

Objective
: Prove that, under
H
,
W
,
R
, and the assumptions above,

I_{T}(C)\;\leq\;|\mathcal{P}_{\text{crit}}|\cdot(N-1)\,L_{\text{mem}}\quad\text{for every admissible }C,

and exhibit a Baseline configuration
C_{\text{base}}
that attains this bound:

C_{\text{base}}=\{\text{start\_sync}=M,\;S(\cdot)_{\text{adv}}=S(\cdot)_{T},\;\mathcal{A}_{\text{adv}}=\mathcal{A}_{T}\}.

The bound is tight but not uniquely attained: any adversarial configuration that issues, synchronously with each
a_{i}\in\mathcal{P}_{\text{crit}}
,
N-1
congruent-different-tag requests reaches the same value (see
Remark

17
).

Remark 10

(Interpretation of
\mathcal{A}_{\text{adv}}=\mathcal{A}_{T}
)
.

The equality
\mathcal{A}_{\text{adv}}=\mathcal{A}_{T}
is to be interpreted at the granularity of
cache-set indices and access phases
, not as bit-identical physical addresses. Each adversarial task issues a request whose set index
\sigma(a^{\prime})
matches that of the corresponding
T
access, while tags are chosen to differ from
\tau(a_{i})
and from one another (e.g., by allocating each adversary on a private physical page with the same cache-color as
T
’s). This is the standard outcome of running
N-1
copies of
T
on private memory with controlled physical placement, as discussed in
Section

8
. The address-level interpretation
same physical address
is excluded: it would produce shared cache hits rather than evictions and is therefore not what the baseline denotes here.

4
Per-Dimension Lemmas

4.1
Lemma 1: Spatial Sufficiency (Direct-Mapped L2)

Lemma 11

(Spatial Sufficiency for Miss)
.

Consider an access
a_{i}\in\mathcal{A}_{T}
and an adversarial address
a^{\prime}
. Then:

1.

If
\sigma(a^{\prime})=\sigma(a_{i})
and
\tau(a^{\prime})\neq\tau(a_{i})
, the adversary’s fill displaces
a_{i}
’s line. A single such adversary, issued before
T
’s access to
a_{i}
, is sufficient to force
T
’s access to miss in the L2.

2.

If
\sigma(a^{\prime})\neq\sigma(a_{i})
, the adversary does not touch the set holding
a_{i}
and contributes no eviction pressure on
a_{i}
.

3.

If
\sigma(a^{\prime})=\sigma(a_{i})
and
\tau(a^{\prime})=\tau(a_{i})
, the adversary requests the same line; after fill, both cores observe a hit on that line and no eviction of
T
’s data is generated.

Proof.

A direct-mapped cache has set capacity
=1
. The three cases follow directly from the displacement rule of the cache: a fill into a set with a different tag than the resident line evicts that line; a fill with the same tag is a hit; an access to a different set does not interact with the resident line of the set holding
a_{i}
.
∎

Remark 12

(Eviction vs. Serialization Pressure)
.

Lemma

11
establishes that
one
congruent-different-tag adversary is sufficient to guarantee that
T
’s access to
a_{i}
misses in the L2. Additional congruent-different-tag adversaries do not produce further evictions of
T
’s line—once evicted, it cannot be evicted again until refilled—but they do contribute
serialization pressure
: each such adversary issues its own L2 miss that must be serviced ahead of
T
under
4
and the blocking miss model. The Temporal lemma (
Lemma

13
) quantifies this serialization. The Theorem proof (
Theorem

16
) uses spatial sufficiency to guarantee a miss on
T
’s access and serialization pressure to bound the stall.

A superset coverage
\mathcal{S}_{\text{adv}}\supset\mathcal{S}(T)
does not strengthen the spatial condition: an adversary issuing requests to sets unused by
T
contributes neither eviction pressure on
\mathcal{S}(T)
nor serialization on
T
’s pending miss.

4.2
Lemma 2: Temporal Bound (Serialization without MSHRs)

Lemma 13

(Temporal Maximality)
.

Given a set of
R
conflicting requests, the serialization latency experienced by
T
is maximized when all requests arrive simultaneously at the L2 arbiter.

Proof.

With MSHRs disabled, the controller processes misses sequentially under
4
. Let
t_{T}
denote
T
’s arrival time at the arbiter, and let
t^{(1)},\dots,t^{(R)}
denote the adversarial arrival times, with
\delta_{m}=t^{(m)}-t_{T}
.

Synchronous case (
\delta_{m}=0
for all
m
).
All
R+1
requests contend simultaneously. By
4
,
T
is served last; its stall is
R\cdot L_{\text{mem}}
.

Positive offset (
\delta_{m}>0
).
Adversary
m
arrives
after

T
. By
4
,
T
is served last only among requests
currently
contending; if adversary
m
has not yet arrived, it cannot delay
T
. Its contribution is at most
L_{\text{mem}}
(only if it arrives before
T
is granted) and possibly zero. This is bounded above by the synchronous contribution of
L_{\text{mem}}
.

Negative offset (
\delta_{m}<0
).
Adversary
m
arrives
before

T
. Under blocking miss handling and the no-MSHR assumption, each adversarial core can hold at most one in-flight request; hence the residual queue at
T
’s arrival contains at most
R
pending or in-service adversarial requests. If adversary
m
’s service has already completed by
t_{T}
, its contribution to
T
’s stall is zero. Otherwise,
T
inherits the residual queue and is served after it (by
4
); the contribution of any single adversary remains bounded by
L_{\text{mem}}
. In particular, if
\delta_{m}\leq-m\,L_{\text{mem}}
, adversary
m
completes before
T
contends and contributes zero.

In all three cases, each adversary’s stall contribution under any non-synchronous schedule is bounded above by its synchronous contribution of
L_{\text{mem}}
. Summing over
R
adversaries:
\Delta t(T;\text{any schedule})\leq R\cdot L_{\text{mem}}
, with equality attained in the synchronous case.
∎

4.3
Lemma 3: Pattern Sufficiency (Critical-Path Alignment)

Lemma 14

(Pattern Sufficiency)
.

Suppose, for every critical access
a_{i}\in\mathcal{P}_{\text{crit}}
, the adversarial schedule issues exactly
N-1
congruent-different-tag requests (in the sense of
Lemma

11
) synchronously with
T
’s issue of
a_{i}
. Then, under
4
, the per-access stall attains the bound of
Lemma

13
:

\Delta t(a_{i})=(N-1)\,L_{\text{mem}}\quad\text{for every }a_{i}\in\mathcal{P}_{\text{crit}},

and consequently
I_{T}=|\mathcal{P}_{\text{crit}}|\cdot(N-1)\,L_{\text{mem}}
.

Proof.

Fix any
a_{i}\in\mathcal{P}_{\text{crit}}
. By hypothesis,
N-1
adversarial requests arrive at the L2 simultaneously with
T
’s request for
a_{i}
, each congruent with
a_{i}
and carrying a distinct tag. By
Lemma

11
, each adversarial request results in an L2 miss (its set has a different resident line). By
4
,
T
’s request is served last among the
N
contending requests. By
Lemma

13
, applied in the synchronous case with
R=N-1
, the stall on
T
’s access to
a_{i}
equals
(N-1)\,L_{\text{mem}}
. Summing the equality over
\mathcal{P}_{\text{crit}}
yields
I_{T}=|\mathcal{P}_{\text{crit}}|\cdot(N-1)\,L_{\text{mem}}
.
∎

Remark 15

(Sufficiency, not Maximality)
.

Lemma

14
is deliberately phrased as an attainment (
sufficiency
) statement, not a maximality statement. We do not claim here that every alternative adversarial pattern produces strictly lower interference.
Theorem

16
below establishes that no admissible configuration exceeds
|\mathcal{P}_{\text{crit}}|\cdot(N-1)\,L_{\text{mem}}
;
Lemma

14
shows that this bound is attained by the schedule above. Together these two statements suffice to conclude that the bound is tight, without requiring a strict-domination argument over arbitrary patterns. As noted in
Remark

17
, multiple configurations attain the same bound.

Main Theorem: Per-Access Stall Bound

Theorem 16

(Monotonic Interference Upper Bound (MIUB))
.

Under hardware invariants
H
(
Definition

1
), workload
W
(
Definition

2
), arbitration model
R
(
Definition

3
), and
8
,
9
and
4
, every admissible adversarial configuration
C
satisfies

I_{T}(C)\;\leq\;|\mathcal{P}_{\text{crit}}|\cdot(N-1)\,L_{\text{mem}}.

The Baseline configuration
C_{\text{base}}
attains this bound:
I_{T}(C_{\text{base}})=|\mathcal{P}_{\text{crit}}|\cdot(N-1)\,L_{\text{mem}}
.

Proof.

We proceed in two parts: an upper bound for arbitrary
C
, and attainment by
C_{\text{base}}
.

Part 1: Upper bound.
Fix a critical access
a_{i}\in\mathcal{P}_{\text{crit}}
. Under blocking miss handling and the no-MSHR assumption (
Definition

1
), each adversarial core can hold at most one in-flight L2 request at any instant; hence at most
N-1
adversarial requests can contend with
T
’s request for
a_{i}
. By
Lemma

13
, the stall on
a_{i}
contributed by these contending requests is bounded by their count times
L_{\text{mem}}
:

\Delta t(a_{i};C)\;\leq\;(N-1)\,L_{\text{mem}}.

Summing over
\mathcal{P}_{\text{crit}}
:

I_{T}(C)\;=\;\sum_{a_{i}\in\mathcal{P}_{\text{crit}}}\Delta t(a_{i};C)\;\leq\;|\mathcal{P}_{\text{crit}}|\cdot(N-1)\,L_{\text{mem}}.

Part 2: Attainment by
C_{\text{base}}
.
Under
C_{\text{base}}
, for every
a_{i}\in\mathcal{P}_{\text{crit}}
:

•

Each adversarial task accesses an address congruent with
a_{i}
(
\sigma(a^{\prime})=\sigma(a_{i})
) with a distinct tag (from
\tau(a_{i})
and from one another), per
Definition

5
and
Remark

10
;

•

All
N-1
adversarial requests are issued synchronously with
T
’s issue of
a_{i}
, per the synchronized-start clause of
Definition

2
.

The hypothesis of
Lemma

14
is therefore satisfied. Applying
Lemma

14
:

I_{T}(C_{\text{base}})=|\mathcal{P}_{\text{crit}}|\cdot(N-1)\,L_{\text{mem}},

matching the upper bound from Part 1. ∎∎

Remark 17

(Tight but not unique)
.

The Baseline
C_{\text{base}}
is one configuration that attains the bound, not the unique one. Any adversarial configuration that, for every
a_{i}\in\mathcal{P}_{\text{crit}}
, issues
N-1
congruent-different-tag requests synchronously with
T
’s access to
a_{i}
achieves the same total interference. In particular: permuting which physical core hosts which adversary, replacing one congruent-different-tag address by another, or substituting any synthetic adversarial trace satisfying the same per-access conditions, all yield the same value
|\mathcal{P}_{\text{crit}}|\cdot(N-1)\,L_{\text{mem}}
. The contribution of this paper is the bound and one realizable construction (code replication with controlled physical placement; see
Section

8
), not a uniqueness claim.

6
Analytical Applicability Discussion

This section discusses the conditions under which the MIUB bound is applicable and how it integrates into certification workflows. No empirical measurements or simulation results are claimed; all reasoning is derived analytically from the stated invariants.

6.1
Applicability Conditions

The MIUB theorem holds if and only if all architectural invariants from
Section

3
are satisfied:

•

Direct-mapped L2
: Set-associative caches (
>1
way) allow co-residence of multiple tasks’ data, invalidating the binary eviction model.

•

Disabled MSHRs
: Enabling MSHRs permits parallel miss handling, breaking the strict serialization assumption.

•

Single-bank memory
: Multi-bank or interleaved architectures enable concurrent accesses, reducing contention.

•

Deterministic, pinned tasks
: Data-dependent branching, dynamic scheduling, or task migration introduce variability not captured by the model.

If any invariant is relaxed, the bound must be re-derived under the modified constraints. This is a feature, not a limitation: the methodology demonstrates how to formally close the interference search space for any fixed architecture.

6.2
Integration with Certification Workflows

For DO-178C/CAST-32A compliance, the MIUB bound can be used as follows:

1.

Evidence artifact
: Include this analysis as an appendix to the Timing Analysis Report, explicitly linking the bound to documented hardware invariants.

2.

Margin allocation
: Subtract the analytically derived interference bound from the total timing budget to obtain a clean WCET estimate for the application logic.

3.

Change management
: If the hardware configuration changes (e.g., L2 associativity increased), re-apply the methodology to derive a new bound; the structure of the proof remains reusable.

4.

Tool independence
: Unlike measurement-based approaches, this bound does not require proprietary tools or extensive empirical calibration, reducing long-term maintenance burden.

7
Limitations and Scope

The MIUB theorem is intentionally scoped to a well-defined architectural subclass. This focus enables a formally closed proof but requires explicit acknowledgment of boundaries:

•

Scope is the contribution.
The result targets
exactly
the architectural class defined in
Definition

1
: direct-mapped L2, no MSHRs, single-bank memory, deterministic pinned tasks. Generalizations to set-associative caches, non-blocking miss handling, multi-bank memory, or non-deterministic schedules are explicitly out of scope and reserved for future work. Critiques that target the realism of these invariants for modern COTS multicore processors are addressing a different problem than the one formalized here.

•

Not a universal bound.
The result does not apply outside the stated invariants. It is intended as a precise lemma for a constrained design point relevant to safety-critical custom processors (e.g., RISC-V cores intentionally configured for timing predictability), not as a general theory of multicore interference.

•

Analytical, not empirical.
All derivations are analytical. Application to real hardware requires independent verification that the target platform satisfies the stated invariants. Empirical validation is a separate engineering activity, complementary to but distinct from the analytical bound established here.

•

Static contention only.
The bound addresses worst-case shared-resource contention under fixed scheduling. Dynamic interference sources outside the cache/bus/bank model—DMA, asynchronous interrupts, power management, TLB pressure, coherence traffic in the presence of data sharing—are out of scope and must be analyzed separately and added to the MIUB bound for a complete certification artifact.

•

Pessimistic arbitration.
The bound depends on
4
: the arbiter serves
T
last whenever its request contends with adversarial requests. For platforms with a guaranteed non-pessimistic policy (e.g., fixed priority favoring
T
’s core), the bound remains a sound upper bound but may overestimate observed stall.

These limitations are consistent with CAST-32A guidance, which permits bounding analyses conditioned on documented architectural assumptions.

8
Certification Relevance (CAST-32A)

CAST-32A Objective 5.2.2 requires demonstration of maximum credible interference for shared processor resources. The MIUB theorem provides:

•

A
traceable
analytical bound, explicitly linked to hardware invariants;

•

A
structured
upper limit (relative to the assumed architectural class), avoiding arbitrary inflation of WCET budgets;

•

A
maintainable
artifact, with clear conditions for re-derivation if architecture changes;

•

A
tool-agnostic
methodology, reducing dependency on proprietary measurement infrastructure.

Practical realization of
C_{\text{base}}
on a target platform consists of executing
N-1
copies of
T
’s binary on private physical memory pages chosen (e.g., via page coloring or linker-script-controlled placement) such that the cache-set indices of homologous accesses match while tags differ. This construction is platform-dependent and requires sufficient control over physical placement, cache-index bits, and synchronized task initiation; it is achievable on platforms exposing physical-to-cache-set mapping, as is typical of safety-critical processors with controllable MMU configuration, but should be validated against the target processor’s reference manual and verified on the integrated configuration.

We recommend including this analysis as an appendix to the Timing Analysis Report, with cross-references in the System Safety Assessment and Certification Plan.

9
Conclusion

We have presented a formal bounding analysis proving that, under strict architectural invariants and a pessimistic arbitration model, the per-critical-access stall on a target task is bounded by
(N-1)L_{\text{mem}}
, and that this bound is attained by a synchronized adversarial workload of
N-1
congruent-different-tag memory requests. The proof is direct and per-access, with the spatial, temporal, and pattern lemmas serving as the structural ingredients.

This work provides a methodological template for certification evidence requiring traceable, analytically justified interference bounds. Future work will extend the approach to set-associative caches, enabled MSHRs, and multi-bank memory architectures, and explore integration with pre-silicon verification flows for customizable ISAs.
