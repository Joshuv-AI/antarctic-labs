Project Summary

As computational models scale to larger computers, the rate at which they produce data
has far outstripped the same computers ability to write that data and further the file
systems ability to store that data. Almost all of the SciDAC applications, but especially
those related to fusion solve very large scale PDEs whose scientific output his impacted
by this problem. To gain access to dynamics in an exascale simulation that are not
identifiable a priori and to make that dynamical data available to machine learning
requires fundamental research in the area of in situ data data analytics. Here data
analytics includes compression, visualization, uncertainty quantification, and machine
learning. This in situ data analytics will enable on-the-fly spatial and temporal
compression of solution dynamics, expose that space-time compressed field to machine
learning algorithms that have been specialized to work with dynamically evolving data
(existing machine learning algorithms treat data sets as static), greatly improving the
opportunity for machine learning to provide feedback to the compression, all within an
ongoing simulation, without the need to write data to files. The same concepts are also
being applied to uncertainty quantification and multi-fidelity modeling which have similar
needs for spatial and temporal compression of the ongoing exascale simulation to
perform either without the typical, unacceptable writing of data to files.

Accomplishments

Over the course of this project, two types of data compression have been explored. The
first uses convolutional neural nets which use many snapshots of the data to train the
network to represent the data in a compressed basis. The second approach develops
restriction and prolongation operators based on agglomerations of the mesh used to
solve the partial differential equation. As our funding is below the level that can support
a full time student, the theory portion of this was developed primarily under a separate
DOE award and thus this report will not go into the detail of those developments. They
are mentioned because this project is focused on taking these development into
software libraries and applications which we made great progress on in this project. It is
also important to point out that, while the software developed is impactful and will
receive many citations as applications use these libraries, the supported effort was not
amenable to a large number of journal publications. To be clear, three papers
associated with other DOE projects are currently in revision and these papers will
acknowledge that this grant developed the aforementioned libraries to support
massively parallel applications. Furthermore, as noted below, this work has been
showcased at several conferences including three invited talks. It is also important to
note that we did examine alternative, publicly available approaches, and while these
show some promise we are most optimistic about the agglomeration approach since it
exploits directly the partial differential equation solver mesh. This is important because it
extends more efficiently to three dimensions and unstructured data sets than the other
approaches that have been largely optimized for two dimensional structured data sets.

In addition to work on compression, in the past two years we have turned our attention
to extending our prior success with off-line machine learning to work with in situ data.
This effort was done in two steps. First we have made great progress porting our
machine learning libraries to make use of the open source package SmartSim.
SmartSim has two useful components -- a database manager (SmartSim Orchestrator)
that can store PDE solution snapshots from the ongoing simulation and a second
package to perform inference from machine learned models.

In a successful demonstration of the integration of SmartSim we integrated it with our
groups PDE solver, PHASTA. The online training of the deep learning model is
performed in a distributed fashion through data parallelism (the networks that will be
used are small enough to not require model parallelism). The input and target data for
the learning task are created by PHASTA (the data producer) and transferred to other
processes (in the same node allocation) to the SmartSim Orchestrator. The ML side of
the application (the data consumer) retrieves the data from the database and performs
the supervised training in parallel using common python libraries like Horovod, PyTorch
DistributedDataParallel, and DeepSpeed. After completing and validating the
implementation into PHASTA we ported all of these algorithms into libCEED. Thus
these capabilities are not only available to all of the DOE applications that make use of
these that ECP projects libraries, but also other GPU-focused solvers (which is basically
all applications targeted for Exascale). Further we have used PETSc as the
driver/interface to these libraries which further expands accessibility. This is important
because we now have validated open source examples of this capability in both legacy
(PHASTA) and GPU-centric (libCEED) which cover the two major DOE lab software
types. This work has also been released into two separate open source projects as
noted below.

Describing in a bit more detail the capability that has been developed, the data parallel
libraries enable effective performance of the following operations: (i) sample and
distribute the data from the database to the ML ranks, ensuring a balanced subdivision
among all the ranks; (ii) retrieve and aggregate the gradients produced by the forward
and backward passes computed on each rank; (iii) distribute the aggregated gradients
to all ranks, which will perform identical updates of the model parameters, ensuring that
an identical copy of the model is present in all ranks.

The above capabilities have been demonstrated at scale on Polaris and Sunspot. In
particular we have studied the impact of transferring the data from the solver to a
clustered database at two different scales as the size of the database is increased. In
these studies we were able to show that that the data transfer time was less than 10%
of the the simulation cost which we regard as an acceptable cost at this stage.
Considering that training data is not sent every time step but rather closer to every 50 to
100 steps, the overhead on the simulation becomes negligible, even at full machine
scale.

The impact of the second SmartSim capablity (online inference) on the overall cost of
the simulation was also measured. The data was collected from a simulation.
Depending on the approach used for inference, the application required between 5 to
10% of the computational nodes. Model inference with SmartSim was studied in two
forms -- evaluation at quadrature points vs. evaluation at nodal points. The latter
substantially reduces the number of data transfers to and from the database.
Additionally, with SmartSim, the NN model is loaded onto the database as a jit compiled
script, and inference is performed using PyTorch ML libraries on the inference data
being transferred there by the solver. Finally, it is important to note that when the node-
hour contribution of performing online inference with a co-located database is
normalized by the total cost of the simulation, the contribution is less than 1% and
therefore highly efficient.

The second major thrust in the project was an initial prototype of computational steering
of in situ machine learning. While the previous text described in-situ machine learning, it
assumed that all the learning hyper parameters (e.g., architecture of the neural network,
the learning rate, etc.) were defined before the simulation begins and are not able to be
changed. In practice, the best choices of these parameters are not known when offline
machine learning is applied to a new data set. Even very experienced modelers will
typically try a few different choices of parameters, examine the progress of the model
learning, and then gradually “human-learn” the best choices.

To enable in-situ machine learning to have this same capability we started development
of computational steering of machine learning. There are two key components -- ability
to change the hyper-parameters and real-time feedback of the learning rate and other
measures of the model performance. In addition to the usual hyper- parameters one can
tune in offline machine learning, new ones appear in online machine learning like the
frequency of transfer of streaming data and number of snapshots to use in training, and
proper selection of these hyper-parameters is even less intuitive than the usual hyper-
parameters. In the project we have developed and tested this approach on up to 128
nodes of Theta and then migrated this workflow to Polaris, Sunspot, and ultimately
Aurora. We also expect to incorporate this software with FASTMath co-PI Juliane
Mueller’s work on optimization. Indeed we are part of her ASCR-DS4MEMS project.
