ABSTRACT
This report details seismic ambient noise analysis to improve seismic velocity estimates of the
southeastern Nevada National Security Site (NNSS). We compare two different methods for
estimating surface wave dispersion curves from ambient noise cross-correlations: frequency time
analysis (FTAN) and Aki’s cross-spectral method (XSpec). We find that XSpec performs better for
our local-regional dataset and frequency content. Using phase velocity estimates from XSpec, we
build a preliminary phase velocity dispersion dataset, which contains data for 1,054 station pairs and
8,905 discrete phase velocity measurements for periods between 0.5 and 13 s. This phase velocity
dataset will be incorporated into an updated local-regional P and S wave velocity model of the
southeastern NNSS in the future and is expected to improve upon shallow velocity estimates.

1. INTRODUCTION
The Rock Valley Direct Comparison Experiment (RV/DC) aims to compare shallow earthquakes
that occurred in 1993 to underground chemical explosions detonated at select earthquake epicenters.
One of the key aspects of this effort is subsurface characterization, including seismic tomography,
which is vital for accurate local and regional earthquake location and for enhancing our
understanding of subsurface geology. In this report, we outline our work to add dispersion curves
derived from ambient noise data to our set seismic observations used in our 3-D tomography
models of the southeastern Nevada National Security Site (NNSS) region. Ambient seismic noise,
which is generated by a variety of natural and anthropogenic sources, can be analyzed in months-
long continuous time segments to infer subsurface seismic velocity structure and is especially useful
for improving shallow seismic velocity estimates in the absence of shallow earthquake or active
sources. Complementing surface wave dispersion curves from ambient noise analysis with other
seismic datasets, like first arrival times of P and S phases, is expected to improve the shallow velocity
estimates for the southern NNSS region.
We use three months of continuous seismic data from the Southern Nevada (SN) and Northern
Nevada (NN) regional network seismometers as well as the Large Array for Seismic Sensing and
Observation (LASSO) geophones over the central RV region of interest. After ambient noise
preprocessing, outlined in Chapter 2, we compared two different methods for obtaining surface
wave dispersion curves: Frequency Time Analysis (FTAN) and Aki’s cross-spectral method (here
referred to as XSpec), which we outline in Chapter 3. We then generated a preliminary dataset of
phase velocity dispersion curves using the XSpec method, which has 1,054 station pairs for input
into tomography, outlined in Chapter 4. We discuss our preliminary dispersion results in Chapter 5,
as well as future directions for work.

2. AMBIENT NOISE PREPROCESSING
This chapter outlines data collection and preprocessing of ambient noise seismic data for the
RV/DC Experiment. The long-term goal of this work is to produce surface wave dispersion curves
from ambient noise data to incorporate into a local-regional joint tomographic inversion along with
P- and S-wave travel times, differential travel times, and gravity for a 3D model of P- and S-wave
seismic velocities of the southeastern NNSS.
First, we will describe the data collection process and data sources. Then, we will review the
organization and processing of the data that yields a standardized waveform dataset along with
ambient noise data preprocessing and cross-correlation, which feeds into dispersion analysis
methods.

2.1. Data Collection
We collated data from multiple repositories in the Southern NNSS area (Figure 2.1) from Feb 1
(Julian day 32) to May 1 (Julian day 121 of 2023). The continuous seismic data were recorded on
several different instruments with differing sampling rates, which is summarized in Table 2-1.
Station locations were obtained from the file headers. In total, there are 75 stations within the local-
regional tomography study area, the bounding box for which is the map area of Figure 2.1.We note
that the SN station RTPP is actually two sensors: a seismometer on the surface and a geophone
~100 m beneath the surface. For MSNoise to properly use the data from both locations, we
appended a “0” and “1” to the station names to denote the surface and downhole location,
respectively. We also note that the LASSO network and station names have since been updated after
these data files have been downloaded to SNL servers. Additionally, a timing error for LASSO
stations was discovered after the data files were retrieved [1], and we manually corrected waveform
start times to account for this error.

2.1.1. SN and NN Network
The Southern Nevada (SN) and Northern Nevada (NN) regional network stations, which are
maintained by the University of Nevada Reno (UNR) and NNSS, were pulled from the
UNR/NNSS server (nnss.seismo.unr.edu, which is now deprecated). We found that some of the SN
station data are uploaded to the Seismological Facility for the Advancement of Geoscience (SAGE)
Data Management Center (DMC), but these continuous data have variable gaps on the order of
hundreds of seconds, whereas the data on the UNR/NNSS server do not. Moreover, there are data
for more stations on the UNR/NNSS server, so we opt to only use these data and not the SAGE
data. These data are in miniseed format in day-long files for each station. Instrument response files
were pulled from the SAGE DMC for each station in xml format. Instrument response files for five
stations were not found on the on the SAGE DMC nor the UNR/NNSS server, but they were
found on the PE1 UNR server and then added to the UNR/NNSS server. The instrument response
files for these five stations are in dataless seed format and had to be converted to station xml format
using obspy to ensure data format consistency required by subsequent analysis using MSNoise.

2.1.2.     LASSO
The Large Array for Seismic Sensing and Observation (LASSO) data was pulled from the tri-labs
filesystem hosted by Lawrence Livermore National Labs (LLNL) by Rose Borden and Kathleen
Hodgkinson, members of the Data Working Group (DWG) for RV/DC. These data are managed
by Eric Eckert at the NNSS Mission Support and Test Services (MSTS) and were reformatted into
an hdf5 format from the original segy. Only the hdf5 files are on the tri-labs system. There are gaps
in the continuous data due to station health checks at 9 am daily, which last up to ~1000 seconds.
These gaps are recorded as “nans” in the hdf5 waveform data. Instrument response files are
available for all stations in xml format. We have identified additional gaps on the order of minutes
during our analysis time period, which thus far consist of: stations 1-70 and 3-2 on 2/15 at around 6
am, station 2-30 on 2/28 at around 5 am, and station 1-76 on 4/2 at around 5:40 am and 4/21 at
around 8:50 am. Some stations on certain days also failed to record or the data failed to convert
from the original segy format, resulting in all nans. These data were not written out and were
recorded in a log file. Additionally, an error in the start time of the waveforms was discovered after
the data were retrieved from the tri-labs filesystem. Due in part to a non-standard segy trace header
definition, the microsecond header was not carried over to the hdf5 format, resulting in a 66 ms
shift in the start times of the waveforms in our hdf5 data.

2.2. Data Preprocessing
After pulling the data from disparate repositories, the files were converted into day-long miniseed
files for each station and channel, renamed, and organized in the directory structure within each data
archive (e.g, LASSO, SN):
NETWORK/STATION/NETWORK.STATION.CHANNEL.YEAR.DAY.mseed.

 16

The waveforms are then preprocessed for ambient noise cross-correlation using the packages obspy
[2] and MSNoise [3]. Figure 2.2 shows the general workflow to obtain surface wave dispersion
curves from Bensen, et al. [4]. The following sections outline the preprocessing for each data
archive. For the regional tomography work, only the vertical component of the ambient noise will be
utilized.

2.2.1. SN and NN Network

2.3. Cross-Correlation
Once the ambient noise seismic data has been preprocessed via station response removal, 1-bit
normalization, and spectral whitening, as shown in the examples in the previous section and in the
Phase 1 steps in Figure 2.2, the next step is to cross-correlate the preprocessed seismogram windows
and stack these cross correlations to produce daily cross correlation functions (CCFs). MSNoise
requires as input any preprocessing filters, time domain normalization choices, and spectral
whitening choices, all of which have been explored in the previous section. The cross-correlation
parameters have been briefly explored to find optimal results and are outlined in Appendix C. We
chose a correlation duration in time of 3600 s windows with a maximum lag computed of 100 s and
a sample rate of 50 Hz. We also used a filter from 0.01-10 Hz before cross-correlating, as this is
where the majority of the signal was found to lie. The daily CCFs were then stacked together to
enhance the Green’s function signal.
Appendix B shows a working document that outlines the overall workflow in MSNoise and the
different database requirements and useful commands that we employ. See Appendix C for a full list
of MSNoise parameters used to compute the daily cross correlation functions, some of which are
parameters used in other analyses we don’t perform. Each day of cross correlation computation
(which includes all preprocessing steps) took approximately 20 minutes using three cores on a
remote Linux high-performance workstation.
Figure 2.15, Figure 2.16, and Figure 2.17 show examples of daily CCFs for the entire three-month
period for station pairs NN.CPYB-SN.AMD, SN.LSM-SN.SOUF, and SN.AMD-SQ.1-29. Figure
2.18 shows the spectra of the daily CCFs for station pair NN.CPYB-SN.AMD, and Figure 2.19
shows the stacked CCFs for all station pairs with station SN.AMD, plotted with interstation
distance. The majority of the CCF signals lie between 0.07 and 0.5 Hz, which informed the optimal
periods to pick using both dispersion analysis methods outlined in the following section.
Figure 2.20 shows how the mean SNR of the CCFs varies with azimuth, both including and
excluding the LASSO stations, following a similar analysis to [5]. Since methods to estimate
dispersion rely on the assumption that there is a homogeneous azimuthal distribution of noise, we
wanted to ensure that the directionality of the noise in our data is not extremely heterogeneous. The
symmetry of the daily CCFs is variable, but generally asymmetry can be observed for more distal
station pairs than nearer station pairs, as nearer pairs have overlapping causal and acausal signals that
could mask any asymmetry. Additionally, asymmetry is more apparent for more N-S oriented station
pairs than E-W. While we don’t have perfectly homogeneous noise, based on these plots and
subsequent results, we conclude that our noise coverage is sufficient, despite individual CCFs with
large signal on one side only.

3. DISPERSION ANALYSIS METHODS
We compared two different methods for analyzing the CCFs to obtain dispersion curves. Frequency
time analysis (FTAN) applies a series of Gaussian filters of different center frequencies to the
vertical-vertical (ZZ) component CCFs to generate dispersion maps on which to pick peaks and
obtain group velocity dispersion curves [e.g., 4, 6]. Aki’s cross spectral method fits the zero crossings
of a Bessel function of the first kind and zero order to the real part of the ZZ component cross-
spectra, generating an array of candidate phase velocities from which to pick phase velocity
dispersion curves [e.g., 7, 8, 9].
Comparisons of various dispersion analysis methods have been explored in other works, including
Barone, et al. [10] and Nishida, et al. [11]. These studies, however, are for station pairs with different
interstation scales, frequency content, and data quality than our local-regional ambient noise dataset.

the input data to ambient noise or joint tomography and are measurements of the Rayleigh wave

4.2. XSpec Dispersion Curves
Figure 4.6a shows the average dispersion curve computed using only SN and NN station pairs (351
pairs), which was used as a reference curve when manually picking the phase velocities for each
individual station pair. Station pairs that include LASSO stations exhibited different Bessel function
trends to the regional network station pairs, so were excluded. This may be due to other
components overpowering the ZZ Rayleigh wave components.
To obtain this average phase velocity dispersion curve, we deviated from the GSpecDiff
methodology, which fits Bessel functions controlled by the phase velocity to the cross-spectra data
points for each user-defined period by minimizing the L2 norm of the residuals via grid search.
Instead, we forward modeled Bessel functions with an additional distance-dependent damping term,
as in [9]. Figure 4.6c-j shows the fits for select periods. The fits at both extremes of our range of
periods (0.5-13 s) are visually worse than the rest, and some of the data appear to have a linear trend
superimposed on the Bessel behavior (e.g., the 3-5 s periods shown in Figure 4.6d,e). Nevertheless,
getting the phase velocities that yielded the best visual fits via forward modeling provided us a
reasonable average dispersion curve to use as a guide when picking the phase velocities for
individual station pairs. We also obtained the damping parameter that could be used to understand
average attenuation, as shown in Figure 4.6b, although we hesitate to over-interpret these forward-
modeled results. Additionally, we observe a general correlation between the modeled damping
parameter and the spectra of our ambient noise dataset, so SNR may be the main factor controlling
the modeled damping parameter.
Figure 4.7, Figure 4.8, Figure 4.9, Figure 4.10, and Figure 4.11 show individual phase velocity
dispersion results with the same station pair examples as shown for FTAN in Figure 4.1 to Figure
4.5. We generally picked a phase velocity curve from the set of candidate curves by looking for the
most reasonable result at the higher periods where the curves are more separated, then following
that same curve down to the lower periods. We opted to discard points from the preferred
dispersion curve that fell outside of the overall trend or exhibited unrealistic phase velocities for the
period, as is shown in Figure 4.8, Figure 4.10, and Figure 4.11. There was some ambiguity in picking

mostly smooth with velocity increasing with period, and do not display the extreme “bouncing”

4.3. FTAN-XSpec Comparison
Before we can directly compare the dispersion curves obtained from FTAN and XSpec, we need to
convert the XSpec phase velocities to group velocities. We did this using the equation in [4] relating
the group velocity to the partial derivative of phase velocity with respect to angular frequency (or
wavenumber). We also did additional cleanup of the dispersion curves. For the phase velocities
obtained by XSpec, we interpolated in wavenumber space, took a moving average, and then
resampled to our desired output periods. For the FTAN group velocities, we removed outliers using
a distance threshold from a moving average in two phases, then used a moving average of the
remaining points to obtain a smoother curve. Figure 4.12 shows these refined dispersion curves
from FTAN and XSpec for the same examples shown in Figure 4.1 to Figure 4.5 and Figure 4.7 to
Figure 4.11. The XSpec dispersion curves are smoother and more realistic than the smoothed
FTAN curves, which are noisier and inconsistent across CCF type (one-sided maximum vs. mean-
symmetric) and choices of period (filter center frequency vs. instantaneous frequency). For the
examples shown, the XSpec group velocities do not consistently follow one of the FTAN curves,
but overall, the two methods are reasonably consistent with each other.

5. DISCUSSION
In this chapter, we discuss the dispersion analyses comparison results between FTAN and XSpec
and directions for future work.

5.1. Dispersion Analyses Comparison
FTAN and XSpec generally yield similar dispersion curve results for individual station pairs. Out of
the four smoothed curves we generate using FTAN, which are the group velocity curves using the
four combinations of mean-symmetric CCFs, one-sided maximum CCFs, center period, and
instantaneous period, one usually is close to the group velocity curve calculated from the XSpec
phase velocity curve. We observe the same steep jump in velocity at 2-3 s for both the FTAN and
XSpec individual station-pair dispersion curves, which also exists in the average curve calculated
using XSpec.
While the FTAN and XSpec dispersion curve results are largely consistent with each other, we find
the phase velocity curves from XSpec superior to the group velocity curves from FTAN in a
number of ways. Most FTAN results are choppy, or bumpy, with group velocity jumps much as ~ 5
km/s between consecutive defined periods. This effect is especially observed at the lower periods
and more pronounced at shorter interstation distances. In contrast, XSpec candidate phase velocity
curves are smoother, with smaller jumps between consecutive whole periods on the order of ~0.5
km/s and with no bouncing between higher and lower values like the jumps in FTAN dispersion
curves. Additionally, FTAN requires more subjective input and parameter tuning than XSpec.
FTAN has many choices for analysis, including whether to use the mean-symmetric or one-sided
maximum CCFs, the center period or instantaneous period, and the alpha for controlling the
gaussian filter widths, where the optimal choices may vary with interstation distance and other
factors. The only choice one makes with XSpec is the phase velocity curve to pick out of the set of
candidate curves, but there are no input parameters to tune. XSpec picking can be ambiguous, but
results in smoother curves and more reasonable velocities that instill more confidence in the
method, despite the results from the two methods being reasonably consistent for most station
pairs. Both methods, however, are difficult to automate for ideal results and require human input
and subjective decision-making.
Based on results from our comparison of FTAN and XSpec, we prefer the smoother, more
reasonable dispersion results and the less subjective methodology of XSpec, at least for this dataset.
Additionally, we gain confidence in our XSpec dispersion results from the fact that dispersion curves
are fairly consistent with those from FTAN, and that the average and reference XSpec dispersion
curves match well (see Figure 4.14).

5.2. Future Work
To progress this preliminary analysis, future work will include estimating error on the phase velocity
dispersion curves, which can then be incorporated via weights in tomography. We can also
investigate other methods, such as emerging ML-based methods [e.g., 14]. ML methods may be
beneficial in removing the subjective human input from the dispersion analysis workflow but may
also be dangerous if there is no traceability or transparency in how dispersion curves are estimated
and what data features control the dispersion output.

APPENDIX B. MSNOISE WORKFLOW
  1. Organize data into structure and define in the config within admin (msnoise admin)
  2. Set correct config parameters in admin (like start and end time)
  3. Run msnoise scan_archive --path /path/to/archive --recursively --init for each data folder (i.e. LASSO
 and NNSS) to populate data table
 a. This should probably be done on the HPC for kahuna but could be done locally on a
 HPWS and gpfs
  4. Run msnoise populate --fromDA to populate the station table
  5. Run python script populate_station_locations.pyI to properly encode the station locations in the
 MSNoise station table
  6. Set config parameters to prepare for cross correlation step
 a. Set remove instrument response parameters
 b. Set the hpc to Y if running on HPC in parallel
 c. Set channel to *Z to only use Z component
 d. Set preprocess filter highpass and lowpass frequencies
 e. Set windsorizing to the desired time-domain normalization technique/value to
 remove earthquake signals
 f. Set whitening parameters, including whitening type (which defaults to Brutal with an
 amplitude of 1)
 g. Set filter(s) for the CC job, which includes parameters for spectral whitening step
 (low and high frequencies), the MWCS high and low frequencies, window length,
 and windowing time step
 h. Set CC parameters: CC time window corr_duration (in seconds, defaults to a half
 hour), maxlag (in seconds, defaults to 120)
  7. Submit cross correlation job (which includes preprocessing steps) to compute and save daily
 cross correlation functions (CCFs)
 a. First use msnoise new_jobs to create CC jobs
 b. Then msnoise compute_cc where N is the number of cores/parallel processes to process
 the CC jobs on the hpc my submitting a batch submission script
 c. If there aren’t instrument responses in the provided files, they will be skipped in the
 compute_cc step
 d. Data is output as day means of the CCs computed for the designated window length
 for the daily CCF
  8. Submit stack job that stacks the CCF across days
 a. Set stack config parameters: ref_start and ref_end to define start and end time to
 compute reference stack, mov_stack to define number of days for moving window
 stacks, and the stack method (linear or phase weighted)

 56

 b. msnoise new_jobs –hpc CC:STACK to create new stack jobs
 c. To run reference stack jobs: msnoise stack -r
 d. Then reset the stack jobs using msnoise reset STACK
 e. Then run moving window stacks using msnoise stack -m
9. Compute doublet using moving window cross-spectral (MWCS) method. This is not
 necessary to compute dispersion curves, but is a step in the process to look at relative
 velocity changes over time, which could be useful
 a. If MWCS jobs were automatically created from stacking, run msnoise compute_mwcs
10. Compute the dt/t (slope of delays vs. time lag) (not necessary for dispersion curves)
11. Compute dispersion curves. This requires the installation of an MSNoise plugin called
 MSNOISE-TOMO (http://msnoise.org/plugins/msnoise-tomo/doc/). Follow the
 workflow instructions to perform FTAN and obtain dispersion curves with extra details
 below to make up for poor documentation.
 a. Need to update the stations table in the database with the lat, lon, and elevation
 values. I wrote a script called ‘populate_station_locations.py’ that does this
 b. msnoise p tomo iftan runs a GUI that helps set different parameters that will be used in
 the automated batch calculations. You can visualize dispersion curve results resultant
 from the parameters.
 i. The most important parameters are Bmin and Bmax (which correspond to
 alpha in the Bensin paper and original Levshin and paper) and these set the
 width of the different narrow gaussian filters. Bmin and Bmax are linearly

 c. Then run msnoise p tomo ftan to run the complate ftan job on all CCFs
