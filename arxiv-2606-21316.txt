Large Language Model-Assisted Framework for BSM Model Building
Shaikh Saad Jožef Stefan Institute, Jamova 39, P. O. Box 3000, SI-1001 Ljubljana, Slovenia shaikh.saad@ijs.si

Abstract
Recent advances in artificial intelligence (AI), particularly large language models (LLMs), have created new opportunities for natural-language interaction with scientific software, but reliable theoretical model building still requires deterministic symbolic calculations. We present bsm_agent , an open-source symbolic framework for beyond the Standard Model (BSM) model building that combines a deterministic physics backend with an LLM chat interface. Starting from the SM field content and a user-specified set of additional scalars and/or fermions, the package constructs renormalizable Lagrangian, performs gauge-anomaly checks, expands operators into component fields, and derives electroweak symmetry breaking stationary conditions and tree-level mass matrices. The key novelty of the framework is that all of these tasks are performed automatically once the user specifies the quantum numbers of the new fields through a natural-language interface, eliminating the need for manual model construction. The symbolic calculations are performed entirely by the Python backend to ensure the correctness and reproducibility of the physics results; the LLM is used only as an orchestration layer that interprets natural-language requests, manages confirmation steps for ambiguous inputs, triggers backend tools, and formats report-ready summaries. The package supports three provider classes: local Ollama inference, remote self-hosted model servers accessed through the implemented remote provider interface, and commercial hosted APIs via OpenAI and Anthropic. This separation between conversational control and deterministic computation preserves reproducibility while making interactive BSM model construction substantially more convenient. bsm_agent

I
Introduction

A central goal of particle physics is to construct theoretical models that describe and explain the fundamental constituents of nature and their interactions. At present, the Standard Model (SM)
[
1
,
2
,
3
]
of particle physics provides the most successful description of elementary particles and their interactions. The SM is based on a gauge-invariant Lagrangian containing a large number of interaction terms and has been remarkably successful in explaining a wide range of experimental observations.

Despite its tremendous success, the SM is known to be incomplete. Among its most important shortcomings are: (i) the prediction of massless neutrinos, whereas neutrino-oscillation experiments have firmly established that neutrinos possess non-zero masses; (ii) the inability to account for the observed matter–antimatter asymmetry of the Universe; and (iii) the absence of a viable dark matter candidate. These observations strongly suggest the existence of physics beyond the SM (BSM).

One of the simplest approaches to BSM model building is to extend the particle content of the SM through the addition of new scalar and/or fermionic fields while leaving the gauge structure unchanged. This class of models encompasses a large variety of phenomenologically interesting scenarios and serves as a common starting point for theoretical investigations.

Constructing such models, however, can be a laborious and error-prone process. For a given set of new fields, one must identify all renormalizable gauge-invariant operators, verify gauge-anomaly consistency, derive the full Lagrangian, expand operators into component fields for phenomenological studies, and obtain the corresponding mass matrices after electroweak symmetry breaking. As the number of new fields increases, the number of allowed interaction terms grows rapidly, making it increasingly difficult to ensure that all relevant operators are included in the Lagrangian and that only linearly independent operators are retained.

To address these challenges, we introduce
bsm_agent
, an open-source Python framework for symbolic BSM model building. The package combines a deterministic physics backend with a large-language-model
[
4
]
(LLM) chat interface, enabling users to construct and analyze models through natural-language interactions while retaining the reliability and reproducibility of symbolic computations. Given the SM field content and a user-specified set of additional scalar and/or fermionic fields, the framework automatically generates the complete renormalizable operators, performs gauge-anomaly diagnostics, expands the Lagrangian into component fields, inserts vacuum expectation values (VEVs) of color and charge neutral states, lists the stationary conditions, and derives tree-level mass matrices, requiring no manual model construction beyond the specification of the new fields’ quantum numbers through a natural-language chat interface. All physics calculations are carried out by the symbolic backend, while the LLM serves exclusively as an orchestration and user-interface layer.

The primary objective of this software package is to enhance the accessibility of intricate model-building methodologies, rendering advanced theoretical frameworks manageable for students and pedagogical use while maintaining the rigor required by research professionals. III.2
Gauge-Anomaly Checks

Before discussing operator generation, it is useful to note that anomaly checking is implemented natively in the backend. The code computes the standard anomaly coefficients by summing over the left-handed Weyl fermions present in the model. The reported coefficients are

\displaystyle\mathcal{A}_{SU(3)^{3}},\qquad\mathcal{A}_{SU(2)^{2}U(1)},\qquad\mathcal{A}_{SU(3)^{2}U(1)},\qquad\mathcal{A}_{\text{grav}^{2}U(1)},\qquad\mathcal{A}_{U(1)^{3}}.

(1)

For each fermion representation, the appropriate Dynkin-index and hypercharge weights are accumulated, and the final report states whether all five coefficients vanish.

If non-vanishing anomaly coefficients are detected, the package may suggest the addition of conjugate fermionic representations associated with the fields responsible for the anomaly. Such suggestions are intended only as a convenience for exploratory model building and should not be interpreted as a complete solution to the anomaly-cancellation problem. Indeed, gauge anomalies can be cancelled in many different ways, and the introduction of conjugate representations represents only one possible strategy.

III.3
Automatic Generation of the Renormalizable Lagrangian

Once the field content is fixed, the package constructs the full renormalizable gauge-invariant operator basis. Importantly, the user is not required to specify any interaction terms manually. The complete renormalizable Lagrangian is derived directly from the field content and gauge quantum numbers. The generation step is centered on the model container and proceeds by operator class.

Scalar sector.

All scalar monomials containing up to four scalar fields are enumerated using combinations with replacement. For each candidate monomial, the backend checks whether the product contains at least one gauge singlet and whether its total mass dimension is at most four. Allowed singlets are then added to the scalar potential. The corresponding coefficient symbols are assigned automatically with prefixes that reflect the degree of the operator, namely

\displaystyle\xi^{3},\qquad m^{2},\qquad\mu,\qquad\lambda,

(2)

for linear, quadratic, cubic, and quartic terms, respectively. If a given field product admits several independent gauge contractions, the package indexes them explicitly. For example, consider a scalar quartic interaction with coupling
\lambda_{i}
. If three independent gauge-invariant contractions exist for this interaction, the package labels the corresponding couplings as
\lambda_{i,c1}
,
\lambda_{i,c2}
, and
\lambda_{i,c3}
.

For every scalar field added to the model, the package automatically assigns a symbolic identifier
{\color[rgb]{0,0,1}\phi_{i}}
(for clarity, the package uses
BLUE
to denote any BSM scalar field), with the index
i
distinguishing different scalar species.

Fermion mass sector.

All bilinears constructed from Weyl fermions are tested for gauge invariance. Whenever a singlet exists, a fermion-mass operator is generated with an automatically named coefficient
M_{i}
or
M_{i,c}
when several contractions are present.

For every Weyl fermion added to the model, the package automatically assigns a symbolic identifier
{\color[rgb]{1,0,0}\psi_{i}}
(for clarity, the package uses
RED
to denote any BSM fermion field), with the index
i
distinguishing different Weyl-fermion species.

Yukawa sector.

The Yukawa sector is generated by combining two Weyl fermions with one scalar factor and again testing for singlet multiplicity. If the product is gauge invariant, the corresponding Yukawa operator is added with a coefficient
Y_{i}
or
Y_{i,c}
.

It is important to note that, in all Yukawa terms, the family/generation indices are suppressed.

Hermitian-conjugate handling and deduplication.

The generator explicitly avoids double counting. Operators are ordered canonically, compared against their Hermitian conjugates, and only added once when the conjugate term is not independent. The resulting Lagrangian therefore has a deterministic and stable symbolic representation.

The output of this stage is a symbolic Lagrangian object partitioned into scalar-potential, Yukawa, fermion-mass, and gauge-kinetic sectors. This representation serves as the common input for component-field expansion, electroweak-symmetry-breaking analysis, mass-matrix derivation, and report generation.

III.4
Computational Scaling with Large Gauge Representations

The runtime of the automatic model-construction stage depends not only on the number of new fields but also on the sizes of their gauge representations. In particular, fields transforming in higher-dimensional
SU(2)_{L}
and/or
SU(3)_{c}
representations generally require longer execution times than singlets, doublets, or triplets. This behavior is expected, because the operator generator must test a larger set of candidate renormalizable field combinations and, for each candidate, determine whether one or more independent gauge-singlet contractions exist.

The underlying group-theoretic cost also increases rapidly with representation size. Larger multiplets produce larger tensor-product spaces, a greater number of admissible index contractions, and, in some cases, a higher multiplicity of independent invariant tensors. The scalar sector is particularly demanding in this respect, since repeated scalar fields require an additional projection onto the Bose-symmetric subspace in order to retain only linearly independent operators. Consequently, even models containing only a small number of new fields can exhibit noticeably longer runtimes when those fields belong to large non-Abelian representations. This is therefore a computational consequence of the exact symbolic construction of the operator basis, rather than an indication of any inconsistency in the model itself.

To mitigate this growth, the implementation includes several representation-aware optimizations for the cases that are known to arise frequently in phenomenological studies. In the weak sector, repeated identical scalar multiplets are treated in a reduced Bose-symmetrized basis rather than in the full tensor-product basis, which is particularly beneficial for large real
Y=0
multiplets such as quintuplets and septuplets. For selected self-interaction structures of real weak triplets, quintuplets, and septuplets, the expansion backend also uses direct closed-form constructions of the corresponding invariant combinations. In the color sector, octet contractions are handled through a dedicated adjoint-basis construction together with pruning of redundant contraction patterns. These optimizations substantially improve performance for several computationally demanding cases, although the runtime can still increase appreciably for models containing large non-Abelian representations. III.5
Expansion into Component Fields

Motivation.

A compact gauge-invariant operator basis is useful for classification, but phenomenological calculations often require explicit expressions in terms of component fields. The package therefore provides a deterministic expansion backend that maps every supported scalar, Yukawa, and fermion-mass operator to its corresponding sum of component-field terms.

Algorithmic Structure.

The component-expansion module acts directly on the gauge-invariant operator object. For scalar operators, it constructs the relevant
SU(2)
and
SU(3)
singlet structures and enumerates the contributing weak-isospin and color assignments. The implementation employs explicit Clebsch–Gordan coefficients for weak contractions together with an explicit color-singlet basis. Each resulting term is assigned the appropriate numerical or symbolic coefficient, including the phase conventions associated with the chosen basis.

For Yukawa and fermion-mass operators, the same procedure is applied while accounting for fermion ordering, possible dual-basis slots, and the phase conventions required to maintain consistency with the internal symbolic representation. It is important to note that, in all Yukawa terms, family/generation indices are suppressed.

Mathematically, the expansion is implemented as a multilinear-algebra problem in the representation spaces associated with the gauge quantum numbers of the fields. Each operator is viewed as a tensor product of field factors carrying weak-isospin and color indices, and the backend constructs the corresponding gauge-singlet tensors by combining the relevant Clebsch–Gordan structures for
SU(2)_{L}
with explicit invariant tensors for
SU(3)_{c}
. The component expressions are then obtained by contracting these invariant tensors with the field-component basis in a fixed convention. In this way, the expanded terms are derived directly from the representation theory of the gauge group rather than from hand-written case-by-case rules.

The resulting output is not a heuristic rewriting of the operator name but an explicit decomposition of the gauge singlets into their field components. This representation is subsequently reused by the mass-matrix extractor, avoiding the need for a separate EWSB expansion stage.

Compact and Fully Expanded Reports.

The report backend exposes both a compact and a fully expanded representation of the Lagrangian. The compact form preserves the gauge-invariant operator notation, whereas the expanded form writes each supported operator class explicitly in terms of component fields. The current
L
a
T
e
X
report output organizes the material by sector, namely Yukawa and fermion-mass terms, the scalar potential, and gauge/kinetic terms.

III.6
Electroweak Symmetry Breaking and Mass Matrices

EWSB Workflow.

The package supports an EWSB reporting stage in which all scalar components that are simultaneously color neutral and electrically neutral are shifted by their corresponding VEVs, and the resulting tree-level mass matrices are derived. In the Standard Model this reduces to the usual Higgs neutral component, while in BSM models the same procedure is applied automatically to every additional neutral color-singlet scalar component. For each such field, the component-level shift takes the form

\displaystyle\phi_{i}^{0}

\displaystyle\rightarrow\phi_{i}^{0}+\frac{v_{i}}{\sqrt{2}},\quad{\phi_{i}^{0}}^{\dagger}\rightarrow{\phi_{i}^{0}}^{\dagger}+\frac{v_{i}}{\sqrt{2}}.

(3)

This shift is inserted directly at the component level rather than replacing the field by its vacuum value only. All VEVs are treated as real parameters.

Stationary Conditions.

From the scalar potential, the package constructs the vacuum potential by replacing the shifted neutral components by their VEV parts and summing the resulting terms, including Hermitian conjugates when appropriate. The stationary condition is then written as

\displaystyle\frac{\partial V}{\partial v_{i}}=0,

(4)

for every VEV symbol
v_{i}
associated with a color- and charge-neutral scalar component. In the simplest Standard Model-like configuration this reduces to the Higgs tadpole equation, while in extended models the package reports one stationary condition for each independent neutral VEV generated by the field content.

Mass-Matrix Extraction.

For
the mass-matrix extraction, the VEV substitutions are applied term by term. The resulting expressions are scanned for contributions with exactly two surviving fields. These bilinears define the quadratic part of the shifted Lagrangian and are accumulated into symbolic matrices.

For general scalar sectors, the backend stores hermitian blocks of the form
\phi_{i}^{\dagger}\phi_{j}
. This is a natural representation in the original complex component basis. However, neutral scalar fields are presented in a combined real basis for readability. If the model contains neutral complex fields
H^{0},\phi_{1}^{0},\phi_{2}^{0},\dots
, the report constructs the neutral scalar mass matrix in the basis

\displaystyle\big(\mathrm{Re}\,H^{0},\,\mathrm{Re}\,\phi_{1}^{0},\,\mathrm{Re}\,\phi_{2}^{0},\dots,\mathrm{Im}\,H^{0},\,\mathrm{Im}\,\phi_{1}^{0},\,\mathrm{Im}\,\phi_{2}^{0},\dots\big).

(5)

If a neutral field is real, it contributes only to the real part of the basis. Charged or otherwise non-neutral scalar sectors remain listed in their residual hermitian and holomorphic blocks.

The fermion mass matrices are obtained analogously by collecting the bilinears left after the VEV shifts in the Yukawa and fermion-mass sectors. The entire procedure is therefore algorithmic and model independent within the renormalizable scope of the code.

IV
LLM-Assisted Interaction Layer

IV.1
Tool-Calling Design

The conversational layer is built around a tool-calling interface. The symbolic backend exposes a small number of high-level actions, most importantly a model-construction tool and a report-generation tool. The LLM receives a system prompt describing when to call these tools and is expected to return either plain text or a structured tool invocation with a machine-readable argument payload. In practical terms, the LLM is responsible for tasks such as

1.

interpreting a natural-language description of BSM field content,

2.

translating that description into the structured field schema expected by the backend,

3.

asking follow-up questions or triggering a confirmation stage if the user input is ambiguous,

4.

selecting whether the user is requesting model construction, report generation, or a follow-up action on the current model,

5.

formatting the deterministic tool output into a concise human-readable answer.

What the LLM does
not
do is equally important: it does not derive the gauge singlets, compute anomaly coefficients, expand the operators, or calculate the mass matrices. Those tasks remain entirely within the backend code.

IV.2
Conversation State and Confirmation Workflow

The chat controller maintains a conversation history, the most recent current-model state, and any pending confirmation request. If the user supplies an incomplete field description, the system can infer a candidate structured interpretation and then explicitly ask for confirmation before creating the model. This guardrail is particularly useful in BSM model building, where a missing statement about whether a field is scalar or fermionic, real or complex, or the sign of a hypercharge can materially change the generated theory. More specifically, the user can define a new field through natural-language input by specifying only:

{\color[rgb]{1,0,1}\blacklozenge}

its quantum numbers under the SM gauge group;

{\color[rgb]{1,0,1}\blacklozenge}

its spin assignment (scalar or fermion);

{\color[rgb]{1,0,1}\blacklozenge}

whether the scalar is real, if applicable.

Once the user confirms the interpretation, the controller calls the backend tool, stores the resulting structured state, and allows subsequent requests such as report generation or EWSB analysis to operate on the same model context.

After a model has been constructed, the same state mechanism also supports resetting the active model context. The user may explicitly ask the package to clear the current model, in which case the controller discards the stored model state and returns the conversation to a fresh construction state. This allows the user to start over and define a different BSM model without residual fields, assumptions, or analysis results from the previous model carrying over.

IV.3
Supported LLM Backends

The provider layer is backend agnostic and separates the symbolic workflow from the underlying language model implementation. The package supports three provider classes: local Ollama inference, remote self-hosted model servers accessed through the implemented remote provider interface, and commercial hosted APIs via OpenAI and Anthropic.

1.

Local self-hosted models.
The model is served on the same machine as the symbolic package, typically through Ollama. In this mode, the user must first pull a compatible local model, for example,

ollama pull gpt-oss:20b

and then invoke the installed CLI with the corresponding model name; for example,

bsm-agent --model gpt-oss:20b

2.

Remote self-hosted models.
The model is served on a user-managed remote server and accessed through the implemented remote provider interface. In the current implementation, this corresponds to a remote self-hosted deployment configured through the appropriate provider-prefixed model target together with the remote server settings; for example,

bsm-agent --model openai:qwen3.6:35b-a3b --api-base <server-url> --api-key <token>

3.

Commercial API models.
The framework can also connect to third-party hosted language models through commercial provider APIs, in particular OpenAI and Anthropic endpoints. Backend-specific wrappers translate the internal conversation history and tool schema into the format required by the selected service. For example, an OpenAI model may be accessed through

bsm-agent --model openai:gpt-4.1 --api-key <token>

Because the orchestration logic is independent of the provider implementation, the symbolic model-building workflow remains unchanged across backends. Users may therefore switch between local self-hosted models, remote self-hosted deployments, and commercial API services without modifying the symbolic model-construction code.

VII.6
Basis Choice, Normalization, and Phase Conventions

It is important to clarify that when the user asks the package to construct a model,

•

The package uses general group-theoretical rules to construct the full Lagrangian. In doing so, it correctly determines the number of independent terms of each type and lists all of them. This part of the construction depends only on group theory and is therefore free from any arbitrariness.

•

On the other hand, when the user asks the package to
expand
the Lagrangian, the result necessarily depends on a particular choice of basis, normalization, and phase conventions. Therefore, if the user wishes to compare their results with those reported by the package, an appropriate mapping between conventions must be established. For any meaningful comparison, the user should be aware of the following points.

\star

The package always uses canonical normalization for all fields. Consequently, the quadratic term for a scalar field
\phi_{i}
is written as
\phi_{i}\phi_{i}^{\dagger}
. If
\phi_{i}
carries
SU(3)
and/or
SU(2)
charges, each component field within
\phi_{i}
is also normalized canonically.

\star

When writing terms in the Lagrangian, the package does not introduce any numerical factors in front of the corresponding coupling coefficients. Therefore, if a scalar field is real, such as
(1,1,0)
, the package does not include the conventional factor of
1/2
multiplying the quadratic term. Similarly, no numerical factors are inserted in front of cubic or quartic interaction terms.

\star

When comparing results, the user should be aware that the package may employ phase conventions different from their own. For example, under a rephasing of a component field,

\phi_{i}^{\alpha}\to e^{i\varphi_{\alpha}}\phi_{i}^{\alpha},

where
\alpha
labels a component field, the canonical normalization remains unchanged. Although different users may adopt different phase conventions, the physical predictions remain identical.

\star

The package lists only independent terms in the Lagrangian; redundant or dependent terms are never included. Consequently, when more than one independent term exists for a given operator structure, comparisons between expanded expressions must be performed with care. For example, suppose the package identifies two independent quartic couplings,
\lambda_{k,c1}
and
\lambda_{k,c2}
, for a scalar field
\phi_{i}
. If, in a different convention, the user instead works with couplings
\lambda_{k}
and
\lambda_{k}^{\prime}
, then the two sets of parameters are related through a linear transformation,

\displaystyle\lambda_{k}

\displaystyle=A_{1}\lambda_{k,c1}+B_{1}\lambda_{k,c2},\qquad\lambda_{k}^{\prime}=A_{2}\lambda_{k,c1}+B_{2}\lambda_{k,c2},

where
A_{i}
and
B_{i}
are numerical coefficients.

IX
Conclusion

We have introduced a framework that combines AI-driven natural-language interaction with symbolic BSM model building. The main novelty of this work is that the user only needs to specify the quantum numbers of the new fields in natural language, after which the framework automatically constructs and analyzes the corresponding renormalizable Standard Model extension. From this minimal input, the package performs the core symbolic stages of model building, including operator generation, anomaly checks, electroweak symmetry breaking, and tree-level mass-matrix extraction. The examples presented throughout the paper demonstrate that sophisticated model-building tasks can be carried out with substantially reduced user effort compared to traditional workflows.

More broadly, this work illustrates a practical paradigm for integrating large language models into scientific software. Rather than replacing established symbolic calculations, the LLM serves strictly as an interface and orchestration layer between the user and a deterministic computational engine. This separation preserves transparency, reproducibility, and scientific rigor while making advanced model-building tools more accessible to researchers and students. In this sense,
bsm_agent
fills a distinct niche in the BSM software ecosystem: it automates the pre-implementation stage of model building, transforming a specification of new field quantum numbers into a reproducible symbolic model analysis without requiring the user to manually enumerate the operator content of the theory. The package is freely available at

bsm_agent

and is built entirely on open-source software.

Future directions.

Future developments include support for even higher-dimensional SM representations beyond those currently implemented, additional gauge groups such as Pati–Salam,
SU(5)
, and
SO(10)
, incorporating discrete and continuous global symmetries, higher-dimensional operators, and the extension of the framework to supersymmetric theories. Further developments may also include more automated phenomenological analyses.
