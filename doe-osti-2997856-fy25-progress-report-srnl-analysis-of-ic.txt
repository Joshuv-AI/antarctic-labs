 EXECUTIVE SUMMARY
Algorithms for Machine Learning (ML) and image analysis for the 3013 Surveillance Program have been
developed in an ongoing collaborative effort by the Savannah River National Laboratory (SRNL) and the
University of South Carolina (USC). The objective of the algorithms is to automate the identification of
corrosion and cracks in the Inner Container Closure Weld Region (ICCWR) of the canister system used to
store Pu-bearing material. Data for corrosion and cracking is collected from large binary files generated by
a Laser Confocal Microscope (LCM), the Wide Area 3D Measurement System (WAMS), or, in a recent
proposal, by a Scanning Electron Microscope (SEM). The ML software uses the physical attributes in the
data files (e.g., one or more of: height, color, and 16-bit grayscale values as functions of position in a plane
projection) to detect signs of surface corrosion and cracking after being trained on similar data with the
features to be detected. Although the initial scope included screening for broader indicators of corrosion,
e.g., pitting, the identification of potential cracks was prioritized for the past several years at the request of
program leadership.

Labeled training data is essential to developing the ML algorithm, and enhancements to data labeling
capability have been developed to address this essential precursor to application of ML routines. Efficient
labeling is particularly important in view of the large volume of data required to train ML algorithms and
the relative rarity of cracks in the ICCWR data set. Matlab programs have been developed to read binary
data from LCM, WAMS or SEM files, interrogate data attributes, facilitate user labeling of data for training
ML algorithms, train and deploy ML algorithms, output parameters from trained ML algorithms, report ML
model accuracy with respect to labeled data, and generate graphical representations for various analyses.

In FY25, the focus was finalization of the machine learning architecture and algorithms for the analysis of
the 3013 canister scans, improvement of the labeled training data set, and the preparation of the Crack
Feature Identifier Graphical User Interface (GUI).

ML architecture/algorithm improvements included the Hourglass Neural Network (HNN) structure being
compared to and then replaced with a similar U-Net algorithm, and addition of attention layers. Bayesian
optimization techniques were implemented to adjust various model hyperparameters to optimize the
model’s performance. New data preprocessing and augmentation techniques were tested and applied to help
to address some issues and limitations of the data.

To improve the training set, the LCM data annotations were carefully evaluated for accuracy and
completeness via a blind evaluation process by the Image Analysis team members. This helped to address
features that were believed to be missed in the previously provided annotated data and provided additional
crack features for training the model. A data set of cropped cracks was created to focus the model on
identifying the crack features and help combat the extreme imbalance in the ratio of crack pixels to non-
crack pixels, which tends to bias the model towards false negatives if not accounted for in the training
strategy. This provided a significant improvement to the model’s performance as measured by the Fβ
metrics.

The GUI program was rebuilt to best deploy model(s) and provide a convenient, streamlined program to
automate the evaluation of the 3013 scan data. Multiple versions of the program were demonstrated to the
program management and delivered for testing.

1.0 Introduction.
Through-wall penetration from stress corrosion cracking (SCC) has been identified as the most credible
condition for failure of the inner container in the 3013 canister system used throughout the DOE complex
to store plutonium-bearing material within its 50-year lifetime1. Chlorides contained in Pu-bearing material,
together with intra-canister humidity levels, metallurgical conditions, and internal stresses have been found
to produce corrosion in the Inner Container Closure Weld Region (ICCWR) of the 3013 canister system.
Microscopy is used as part of the 3013 Surveillance Program protocol to identify the prevalence of corrosion
and corrosion-related cracking in the ICCWR as part of destructive evaluation of canisters opened after a
storage period2. With the microscope, a close visual examination is made of the ICCWR surface along with
measurements of corrosion-related features2. Laser Confocal Microscopy (LCM) was previously the
primary microscopy technique used. LCM inspections produce immense amounts of image data:
approximately 6000 LCM images per can, having 786,432 pixels per image, with 8 layers of data for each
pixel. More recently, other imaging approaches, using the Wide Area 3D Measurement System (WAMS)
and scanning electron microscopy (SEM) were introduced with the aim of improving the time-consuming
imaging process. There is currently a 10-year backlog of images, with approximately 56 canisters that must
be evaluated, approximately seven per year. Simplistic computer-aided image analysis can flag some basic
surface characteristics, such as pit depth, to guide manual examinations for corrosion. However, while this
approach greatly improves the efficiency of the examination process compared to unaided manual
screening, it remains excessively time consuming. A more efficient and sophisticated approach is to assess
the data using Machine Learning (ML) algorithms to identify corrosion without manual intervention.

The objective of this project is to develop computer-facilitated methods to enable rapid identification of
corrosion and corrosion-related damage (especially cracks) in 3013 canisters from very large sets of LCM
(vk4 files), WAMS (ZON files) and, most recently, SEM images. The LCM data includes channels for red-
green-blue (RGB) optical, RGB + laser intensity, laser intensity, and height. Data from WAMS files
includes height and RGB data. The SEM provides grayscale optical data. The labeled cracks are divided
equally into three categories: training, validation, and testing, to allow for proper training of the model,
validation that the model is not overfitting to the training data and testing to evaluate the model’s
performance.

In FY25, the development of ML algorithms built on the work done in FY243, FY234, FY225, FY216, and
FY207. In FY25, the focus was on finalization of the machine learning architecture and algorithms for the
analysis of the 3013 canister scans, improvement of the labeled training set, and the preparation of the Crack
Feature Identifier Graphical User Interface (GUI).

Several improvements were made to the model and process which improved results significantly. The ML
architecture has been modified, hyperparameter optimization has been improved, and new datasets have
been curated for improved model performance.

The GUI for 3013 scan evaluation, which has been named the “Crack Feature Identifier” (CFI), has been
updated to accommodate the recent developments in feature labeling and graphical highlighting, along with
new ML algorithms and training methods, and versions were demonstrated and delivered to team members
responsible for ICCWR screening for user testing and feedback.

3.0 Approach
3.1 Background
Corrosion is strongly, but not exclusively, associated with surface pitting and cracking, coloration, and
surface feature geometry. However, not all pits and surface lesions are the result of corrosion: some are
artifacts of fabrication, impact, scoring, or other non-corrosion events. Corrosion is identified via the
combined properties of pit depth, area, edge contour, color, and clustering. Software was developed to
extract these features from large binary files generated by the LCM and analogously will apply to images
from WAMS and SEM data. The individual LCM images, which collectively span the ICCWR, were
stitched together and corrected to eliminate the effect of the canister surface curvature on measurement of
the local height. Various image processing methods were tested for identifying the presence of cracks and
corrosion. The methods included Hourglass Neural Networks (HNNs), Deep Neural Networks (DNNs),
Convolutional Neural Networks (CNNs), gradient methods, statistical characterization, correlations, and
filters8,9,10,11.
Samples of LCM image data taken for the 3013 Surveillance Program containing identified cracks, pits and
other features characteristic of corrosion were used as training data for ML algorithms. To provide an
efficient means for handling large amounts of binary image data, the GUI that was previously developed
for this application is being updated. As for the prior GUI, the upgrade will to serve to interface with the
data files, manipulate and group images, correct for sample tilt and curvature, stitch images, and apply
trained algorithms for crack and corrosion identification. Methods have been developed in prior years to
read binary WAMS data and will be extended to read and process SEM data. After preprocessing, images
are partitioned into tiles (rectangular blocks of pixels of consistent size) to serve as input to the ML
algorithms. Image data used for training and testing CNN and DNN ML algorithms was labeled and
classified on a per-tile basis, i.e., the algorithm input was an image, and its target and output were a
classification. Labeling for HNN networks employs a more detailed, pixel-level labeling of cracks to
effectively use the HNN structure, i.e., both the input and target/output of the HNN are images of the same
number of pixels.
Cracks, pits, and color patterns all may be associated with various forms of corrosion. Pits can readily be
detected using height data thresholds or have their edges defined from optical data through a band pass
filter that incorporates a discrete Fourier transform. However, cracks, particularly “hairline” cracks, do not
always have a definitive height signature. Rather, crack identification is a combination of grayscale image
intensity (pixel value) and height data. Initially, it was hypothesized that standard edge detection methods
 2

could be used with optical data to extract crack edges. Methods considered include erosion and dilation,
blurring, Fourier and Gaussian filters, and gradient methods. Unfortunately, other surface features
combined to create background noise that was similar in frequency to that associated with crack edges,
preventing these methods from effectively discriminating cracks from the background.
To overcome the problems with using feature morphology directly, crack identification is approached via
ML methods. Over the course of this task, the training of the ML algorithms has suffered due to the small
amount of labeled crack data available, uncertainty about the consistency of labeling (e.g., whether all
cracks in a given training image have been labeled), and the severe imbalance between the amount of
labeled crack data and the much larger amount of “non-crack” surface (this imbalance tends to skew the
algorithm towards false negatives, i.e., identifying no cracks, resulting in high overall accuracy but no
useful predictive capability). This was particularly true in the early stages of algorithm development. The
low fraction of the surface corresponding to labeled cracks was previously somewhat offset by augmenting
the crack tiles via a combination of rotation, translation (vertical and horizontal) and/or oversampling to
synthesize additional labeled crack data. Recently, the approach has moved away from augmentation;
refined cropped data sets have improved the model performance without augmentation due to the increased
crack to non-crack pixel ratio.
The model architecture used as of FY24 was the HNN, a CNN encoder-decoder that employs residual (or
skip) connections between symmetric encoding and decoding layers. Encoders, decoders, and residual units
are discussed in Géron9. A schematic of the hourglass network and its training and application is shown in
Figure 1.

3.2.1 Model Metrics

Continuing concepts developed in FY24, scoring methods were employed in FY25 to quantify the accuracy
of ML algorithms. This approach uses metrics to measure the ability of an algorithm to detect a surface
defect, say a crack, vs. the propensity of the algorithm to falsely indicate a defect where none exists.

 3

The current ML models classify individual pixels, but the practical objective is to successfully identify all
discrete crack morphologies to flag them for the attention of the user and to minimize the amount of time
and effort spent by the user to examine areas without cracks. Therefore, an algorithm that successfully
marks a portion of each true crack while minimizing false positives has more practical value than an
algorithm that flags every pixel of a crack with a correspondingly higher number of false positives, since
false positives must be examined and ruled out by the user. As such, we separately evaluate the models
relative to their pixel-level accuracy and their crack-level accuracy.

We define a feature as a spatially contiguous set of crack pixels in the labeled data or in the model’s output

3.2.3 Bayesian Optimization for Hyperparameter Selection
The U-Net architecture, depicted in Figure 3, provides a versatile framework for creating diverse network
configurations to balance computational cost and accuracy. The model can be tailored using the following
hyperparameters:
 • Input tile size: Square tiles with edge lengths as powers of 2 (to accommodate the progressive
 halving of the image size as it progresses through the network). This effort tested tile sizes 32×32,
        128×128, 256×256, and 512×512 pixels.
 • Network depth: Number of downsampling and upsampling stages (or “chunks”), tested in the
 range 3 to 5. Each stage reduces the image size at the network’s midpoint by a factor of 2, so the
 tile size and network depth must be compatible. For instance, a 32×32 tile (the smallest tested here)
 in a 5-stage network (the largest tested here) would be reduced to a single pixel at the midpoint.
 • Number of filters: Number of filters in each bottleneck layer, tested in the range 8 to 128.
 • Class weights: Weights assigned to each class in the cross-entropy loss function during training.
 • Learning rate: The rate at which model parameters are updated during training, tested in the range
        0.0001 to 0.01.
 • Pixel threshold: The minimum output value required to classify a pixel as a crack pixel, ranging
 from 0 to 1 (i.e., the output range of U-net).

To optimize these hyperparameters, we used Bayesian Optimization to maximize the pixel-based F1 score
on the validation set. The process involves sampling from the hyperparameter space and training a model
for each configuration. A Gaussian process models the relationship between hyperparameters and the F1
score, capturing the current understanding of the objective landscape. An acquisition function selects the
next hyperparameter set by balancing exploration (sampling uncertain regions) and exploitation (targeting

 6

promising regions). As shown in Table 1, this approach yielded models with test F1 scores ranging from
63% to 76%.

3.2.4 Background preprocessing
When training models developed over the previous project year, we applied new data preprocessing and
augmentation techniques to the tiles in the dataset. These include random flips, contrast limited adaptive
histogram equalization, gamma correction, and horizontal feature suppression. These techniques were
evaluated for their ability to enhance features obscured by variations in lighting, texture, and orientation.
They include:
 • Random flips: This augmentation method involves randomly mirroring the image tiles
 horizontally or vertically during training, which has the potential to reduce overfitting and improve
 generalization.
 • Contrast Limited Adaptive Histogram Equalization (CLAHE): As a preprocessing step,
 CLAHE adaptively enhances local contrast in the image tiles by redistributing pixel intensities
 within small regions while clipping excessive amplification to minimize noise. This can potentially
 highlight fine microstructural details against the background.
 • Gamma correction: This technique applies a non-linear transformation to adjust the luminance of
 the image tiles, correcting for exponential brightness variations (e.g., using gamma values between
 0.5 and 2.0). For our dataset, it compensates for inconsistent illumination due to uneven laser
 intensity, ensuring that damage features remain visible across varying exposure levels. An example
 of this correction is shown in Figure 4.
 • Horizontal feature suppression: This step attenuates prominent horizontal artifacts such as
 scratches and machining marks, potentially reducing false positives.

3.2.5 Pixel and Connectivity Thresholding
Two key hyperparameters in our model are the “pixel threshold” and the “connectivity threshold.” The
pixel threshold defines the cutoff value at the model’s output layer to distinguish crack pixels from
background pixels. The connectivity threshold specifies the minimum number of adjacent pixels classified
as crack pixels required to prevent the group from being filtered out as noise. Results show that pixel
threshold and connectivity threshold produce a trade-off between precision and recall. Table 2 shows that
increasing pixel threshold and connectivity threshold improves pixel-level precision at the cost of pixel-
level recall (i.e., the number of false positives decreases, but the number of false negatives increases).

The Alpha dataset posed challenges for our models due to distinct coloring patterns across its sections. To
address this, we created a new dataset, termed the "Beta" dataset, focusing on a single section, A1 Section

 Figure 6. “Beta” Dataset from FY16 Zone 3 Dataset

In FY25, we labeled a new dataset, named the “Gamma” dataset, which provides more comprehensive
labeling across the entire FY16 Zone 3 dataset. This dataset includes annotations for 84 cracks across 24 of
the 112 sections in FY16 Zone 3. Image sections that are tightly cropped around each crack are used to
form the dataset, eliminating a lot of the “background” area with no cracks and significantly reducing the
number of tiles generated without crack pixels for a more balanced dataset.

This dataset contained original annotations provided by subject matter experts several years ago. However,
it was explained that the labels were not all certain and were not necessarily complete (some cracks may
have been missed). Using the annotations as a guide, the Image Analysis team blindly labeled the data
comprehensively. Crops were taken of various regions in the dataset which may or may not contain
suspected cracks. These images were sent individually to two team members who annotated any cracks
they identified as significant enough for consideration, based on the prior annotations. Person A annotated
107 cracks in the data. Person B annotated 94. Of these cracks, 69 of the annotations occurred in both. The
Jaccard index for these two sets is 52.3%. These were then labeled as new cracks to form the Gamma
dataset.

Training using the Alpha and Beta datasets was performed using random tile-sampling with an enforced
minimum number of tiles containing crack pixels as a strategy to better balance the data set between crack
and non-crack tiles. By contrast, training using the Gamma dataset employs a raster-scanning approach,
taking advantage of the improved crack vs. non-crack balance due to cropping the images.

3.4 CFI Program
A new graphical tool was developed to apply and evaluate the results of our trained models. The tool's
interface is divided into two tabs. In the first tab (“Prediction”), users can load a trained model and an image
dataset and run the ML algorithm (“Run Prediction”) to screen the images. The tool displays progress
updates for the loading and stitching of the images, as well as the ML classification. Users can queue
multiple datasets for batch processing. This tab is depicted in Figure 7.

In the second tab (“Inspection”), users can examine the dataset and model output/predictions with
interactive visualization options. They can toggle a heatmap of predicted crack pixels and/or display
bounding boxes around the predicted features. Users can zoom in and pan around the image, switch between
intensity, height, and optical channels (depending on which channels are available for the image type),
adjust the pixel threshold and connectivity parameters, and apply statistical filtering based on crack size or
core. Navigation buttons enable users to cycle through cracks in order of size or score, focusing on each
one sequentially. This tab is shown in Figure 8 and Figure 9.

5.0 Summary
FY25 work focused on finalization of the machine learning architecture and algorithms for the analysis of
LCM images for screening of 3013 canisters and the preparation of the Crack Feature Identifier GUI. The
goal of this year was to complete a final deliverable app for the 3013 surveillance team to begin utilizing
for LCM scan data.

The ML algorithms have been modified to a high level of accuracy which now appears to be useful for
deployment as a screening application. The HNN was replaced with a similar U-Net algorithm after
comparison of their relative performance, and attention layers were added to the ML architecture, providing
additional improvement to the model Fβ metric, both pixel and feature based metrics. Bayesian optimization
techniques were implemented to select values for various model hyperparameters to optimize the model’s
performance. The model hyperparameters included in the optimization are input tile size, network depth,
number of filters, class weights, learning rate, and pixel threshold. Pixel threshold and connectivity
threshold were determined to be key values in defining crack features in the model’s output. These values
have a significant impact on the visual results of the model for the user, as well as on the Fβ metrics.

 14

New data preprocessing and augmentation techniques were tested and applied, including random flips,
contrast limited adaptive histogram equalization, gamma correction, and horizontal feature suppression.
These preprocessing techniques helped to address some issues and limitations of the data, such as the
differing background color and contrast, resulting in improved model performance in darker regions with
previously lower scores than lighter ones.

The data annotations were carefully evaluated for accuracy and completeness via a blind evaluation process
by the Image Analysis team members. This helped to address features that were believed to be missed in
the previously provided annotated data and provided additional crack features for training the model. A
data set of cropped cracks was created to focus the model on identifying the crack features and help combat
the issue of extreme imbalance in the ratio of crack pixels to non-crack pixels. This provided a significant
improvement to the model’s performance as measured by the Fβ metrics.

The user interface for implementing the model was a main focus for this year. The program was rebuilt to
best implement the developed model(s) and provide a convenient, streamlined program to automate the
screening of 3013 scan data using pre-trained models. Multiple versions of the program were demonstrated
to the program management and delivered for testing.
