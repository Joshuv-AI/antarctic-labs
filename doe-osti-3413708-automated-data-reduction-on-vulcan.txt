 ABSTRACT

The automated data reduction on VULCAN is overhauled by using multithreading-capable python codes.
Other than just creating reduced histogram data in GSAS format and meta data as the prior mantid based
routine, more automated services are included in the new reduction pipeline, including, generating GSAS-
II format data, neutron and sample environment data slicing/chopping, plotting chopped meta data,
matching calibration files based on sample environments or instrument configurations, reduction of VNb
files, invoking AutoSAC, sending notifications to Slack channel on completion of data reduction, being
accessible via Slack APP commands, marking on data readiness, notifying PI via email when mail-in
proposal is complete, and parsing user’s special request from run note. The whole program is coded
through vibe-coding fashion, where an AI agent is used with multiple rounds of prompt-and-testing.
Thanks to this, further improvements and modification can be done by employing an AI agent after it
digests the routines or the markdown files. The current version has been delivered to VULCAN beamline
for running/testing with a full cycle of experiments, where frequent demands in either large data size or
numerus runs are encountered, and strategic approaches were introduced for a more robust execution.
While not included, the workflow allows further automated data analysis given a complete data analysis
routines to be ready and tested in command line interface (CLI). Current version can also be invoked by
using a specially constructed web agent based on an open large language model (LLM), thanks to the CLI
design.

 1. Introduction

The VULCAN instrument [1] at the Spallation Neutron Source (SNS) is a versatile neutron diffractometer
for materials science and engineering applications. The instrument is equipped with 3He linear position
sensitive detectors covering large 2theta angle range from 60 to 155 degrees. The instrument has several
operation modes depending on the selection of chopper spinning speed and/or use of No. 8 and No. 9
guides. There are various selections of beam collimations in both incident and diffraction directions.
Various sample environments such as texture fixture, load frames, furnaces, cryogenic chambers, and user
devices are often used for supporting different experiments. Because of the versatilities above, data
reduction of VULCAN instrument could be a challenging and tedious task when considering both
instrument configurations, experiment types, data sizes and data quantities, etc.

The diffraction data are collected in time-event mode, and the meta data are registered with a comparable
time stamp resolution for post data synchronization when needed. The reduced individual bank data after
time-focusing correction are created and saved in various data formats by a reduction pipeline and
delivered to a shared folder under proposal specific folder for further data analysis. Sometimes, a single
long run is collected over a lengthy period and data slicing with a selected time interval is required for
time-resolved data analysis. The data size varies from a few hundred of Mb to a few hundred of Gb,
where larger files take much longer time for reduction. The number of runs per experiment varies from a
few to thousands depending on the nature of the experiment types.

An experiment requires the proper calibration files including standard Si and VNb measurements, which
are saved under an instrument folder. Multiple pairs of calibration files may be needed for different
experimental configurations in a proposal folder.

Before any data reduction is conducted, all the neutron data and meta data are saved in HDF5 NeXus
event files from the standard data translation service. Further data reduction is required to generate
standard data format for further data analysis by using VDRIVE(X) [2] or other software package.

 2

The basic need of automated data reduction is to be reliable, efficient, and configurable while being
executed automatically. Without an automated reduction routine, VULCAN users need to use
VDRIVE(X) to conduct manual reduction before analysis.

 2. Program Design

2.1 Programming tool and language of choice

The language of choice is python version 3.9 with its relevant libraries. AI coding agent is used in
generating the overall codes while supplying agent constrains/guidance in a mark down (MD) file. The
IDE is VSCode with a built-in GitHub CoPilot agent, and an extension of Codex from ChatGPT is also
used when CoPilot is not available. The vibe coding includes generating progressive prompts and
intensive testing of the codes, execution performance, and file outputs etc. It worth being noted here that,
a large portion of the fundamental functions are from VDRIVE(X) [2], and they are refactored by sending
prompts to the AI agent. This expedites the learning process of AI agent to develop reliable codes for the
automated reduction.

The runtime error is collected in an error output file per run. The monitor.sns.gov also provides system
level monitoring of the errors or exceptions of from execution of the code. If Slack APP is available, at
the end of each data reduction, a notification is sent to the instrument reduction channel to report timely
the status. Email notification is also available when its option is set on.

The vibe coding is a powerful approach and does not rely on single developer, and when needed,
debugging or further development can be requested through an AI agent by any authorized users. A copy
of the source codes is stored in ORNL GitLab repository (https://code.ornl.gov/k6e/vreduce).

2.2 Functions of Vulcan event data reduction

VULCAN neutron event data reduction is designed to mainly deliver workable reduced data in analysis
and visualization software; it is available via CLI which is intended for future AI integration. While the
main purpose is to generate GSAS format histogram data, there are many needy functionalities and the
main actions in the pipeline are highlighted below.
 • Conduct time focusing of event data per detector bank and output three-column ASCII GSAS
 data.
 • Chop/slice long run with specified chop time.
 • Generate texture data by sectioning bank 1 and 2 detectors.
 • Generate metadata record per run in AutoRecord.txt, AutoRecordData.txt, and
 AutoRecordAlign.txt files.
 • Generate time dependent metadata logs in an ASCII file.
 • Generate 2D plots for bank histogram data.
 • Generate 2D plots for chopped bank histogram data and chopped logs.
 • Identify VNb data collection and generate VNb gda calibration file.
 • Locate matching VNb file based on instrument configurations and automatically copy calibration
 pair files to IPTS instrument folder, and update data status in IPTS.
 • Generate copy of GSAS II data files with normalization to relevant VNb data when needed.
 • Invoke AutoSAC service for sample activation calculation.
 • Notify Slack channel if available when a measurement is successfully reduced.
 • Parse vbot commands through EPICS note field to conduct specified reduction or chopping.
 • Automatically turning on parallel process for large data reduction.

 3. Access and Execution

The access of the automated reduction can be done by two ways, manual command and automated
execution through the data reduction service of SNS. For automated option, most default settings are used
while the service just invokes the reduce_vulcan.py under /SNS/VULCAN/shared/autoreduce folder. An
identical copy of reduce_vulcan.py is created for the convenience of use, vreduce.py. For manual
execution, one can do so through a terminal or through a Slack channel to start vreduce.py.

Below are some bash examples when the reduction is executed manually.

To process single run:

python vreduce.py --ifile /SNS/VULCAN/IPTS-1234/nexus/VULCAN_2171.nxs.h5 --ofile
/SNS/VULCAN/IPTS-1234/shared/autoreduce

To conduct batch reduction (run range):

python vreduce.py --ipts 1234 --runs 2171 --rune 2180

To process with chopping:

python vreduce.py --ipts 1234 --runs 2171 --chop-time-bin-s 60 # 60-second bins

The command options included in current version are listed below.

Reduction Options

| Argument | Purpose | Default value|
| `--chop-time-bin-s` | Chop duration in seconds | None (no chopping) |
| `--dbin` | Enable d-binning (spatial) | False |
| `--create-gsa` | Generate GSAS II normalized files | False |
| `--notify-email` | Send email on completion | None |
| `--force-vbot` | Force /vbot commands on re-reduction | False |

Calibration Options

| Argument | Purpose | Default value |
| `--difc-file` | Custom DIFC calibration file | Built-in default |
| `--vanadium` | Force vanadium processing | Auto-detect |
| `--silicon` | Force silicon processing | Auto-detect |

Processing Options

| Argument | Purpose | Default value |
| `--num-threads` | Number of processing threads | Auto (CPU count) |
| `--memory-limit-mb` | Max memory per process | Auto |
| `--dryrun` | Preview only, no file output | False |
| `--verbose` | Detailed logging output | False |

 5

Reduction takes the notes from EPICS note field to conduct user customized data reduction through vbot
commands. In the EPICS note field, users can input a reduction option which the vbot parser will take.
This is done by specifying ‘/vbot’ in the note. The code will parse the string to conduct specific data
reduction. In addition, in a Slack channel users can send prompts by adding requests after ‘/vbot’, and
they will be parsed by the built-in parser or processed by LLM (for example gemma4a from Alphabet) to
conduct a data reduction through vreduce.py accordingly. Below is the summary of vbot commands
allowed in run notes, and the free form queries to LLM are allowed via Slack channel.

Embed VBot commands in the EPICS Notes field to trigger post-reduction actions:

| Command | Effect |
|---------|--------|
| `/vbot send record` | Upload AutoRecord.txt to Slack |
| `/vbot send log plot` | Upload sample environment PDF |
| `/vbot send plots` | Upload diffraction + chopped plots |
| `/vbot send photo` | Send live detector photos |
| `/vbot save photo` | Save detector photos to disk |
| `/vbot V data` | Force Vanadium processing |
| `/vbot Si data` | Force Silicon processing |
| `/vbot chop 60s` | Force chopping with 60-second bins |
| `/vbot no` | Suppress Slack notification |

For example, in EPICS note field:

/vbot send plots; send photo; chop 120s

The reduction will send reduce the data now with 120s data chop and send plots and camera photos to
Slack channel.

And on manual re-reduction, use `--force-vbot` to override the single-execution guard:

python vreduce.py --ipts 1234 --runs 2171 --force-vbot

At the end of the successful reduction, a notification is sent to Slack IPTS channel, including current
sample environment status if there is any. Below is an example of notification when a furnace is used.

[VReduce] 2026-06-21 09:55:10, run 270807 reduced successfully, Raw Data: 4.8GB, total time taken
127.2s.

 4. Failure or Degradation Paths

We summarize the high-level failure/degradation paths for the VULCAN reduction flow:

 6

The pipeline first validates inputs, paths, and required configuration. If core prerequisites are missing
(invalid event file, inaccessible output targets, invalid activation prerequisites when enabled), it stops
early with a clear setup error. In batch mode, invalid runs are skipped individually so the batch can
continue.

The system prepares metadata-driven outputs (records, logs, optional activation estimates) before core
reduction. If metadata is required and cannot be read, this is treated as a hard failure. And if outputs
already exist and forced refresh is not requested, it may skip regeneration to reduce work.

Secondary operations (calibration copy, vanadium/silicon tagging workflows, optional notifications,
uploads) are designed to degrade gracefully. Most issues in this stage produce warnings and continue
rather than failing the run. This protects delivery of primary reduced data even when ancillary services are
unavailable.

Actual chop/binchop processing errors can fail overall status when those stages are expected to run. Runs
with no usable counts can still complete in a degraded mode (logs/records may still be produced, but no
primary diffraction product).

When run files are large in a few hundred of Gbs, depending on the reducer server used, auto reduction
service may throw out memory deficiency error or exceeding maximum reduction time error/warning.

Overall run status is an aggregate of major stage outcomes.
