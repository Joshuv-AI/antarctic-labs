ABSTRACT
This manuscript describes the Waveform Simulation Framework (WSF), a Python-based framework
that provides a unified, programmable interface for generating synthetic seismograms for
applications such as seismic array design, method development, and special event analysis. WSF
standardizes how users define sources, receivers, and velocity models while abstracting simulator-
specific configuration details, enabling workflows that are largely independent of the underlying
numerical engine. The document provides installation guidance and tutorial-driven examples for
three WSF simulator wrappers—WSF PyFK, WSF SW4, and WSF SPECFEM2D—illustrating end-
to-end workflows from forward waveform simulation to common post-processing tasks (e.g.,
visualization and backprojection) using consistent data products (e.g., ObsPy Stream objects and
SAC files).

1. GENERAL OVERVIEW
The Waveform Simulation Framework (WSF) is a Python-based framework that provides a
unified interface for generating synthetic seismograms for a range of applications, including seismic
array design and special event analysis. A variety of established simulators (e.g., PyFK, SPECFEM,
and SW4) can produce these waveforms, but each package has its own input formats, configuration
conventions, and usage patterns, which can create a barrier for non-specialist users. WSF addresses
this challenge by offering an intuitive, programmable interface for defining sources, receivers, and
velocity models in a consistent way, enabling users to build simulation workflows that are
largely independent of the underlying simulation engine.
This user guide covers three WSF simulator wrappers:
 • WSF PyFK uses PyFK as the simulation engine to generate synthetic seismograms
 efficiently using frequency–wavenumber Green’s functions (typically with 1-D velocity
 models) and supports streamlined batch execution and post-processing.
 • WSF SW4 uses SW4 as the simulation engine to model full 3-D elastic wave propagation
 using high-order finite differences, with the wrapper handling input-deck generation, run
 execution (serial or MPI), and conversion of outputs into ObsPy-friendly formats.
 • WSF SPECFEM2D uses SPECFEM2D as the simulation engine to perform 2-D spectral-
 element simulations (e.g., P–SV or SH formulations), with the wrapper generating required
 SPECFEM2D input files and organizing outputs into ObsPy Stream objects for analysis
 consistent with other WSF workflows.

2. WSF PYFK
The WSF PyFK code implements the Python-based WSF built around the PyFK library, which is a
Python adaptation of the FK package available on GitHub: https://github.com/ziyixi/pyfk. This
code provides comprehensive end-to-end tools for defining earthquake sources and receiver
stations, constructing 1D seismic velocity models, computing frequency–wavenumber Green’s
functions, and synthesizing three-component seismograms by convolving these Green’s functions
with user-defined source-time functions (STFs).
All functionalities within WSF PyFK are encapsulated in reusable simulation objects
(PYFKSimulation and simulationCollection) that facilitate parallel execution. Additionally, the
framework includes an extensive suite of post-processing and analysis utilities, such as ray-based
2D/3D travel-time calculations, stack-based backprojection locators, and arrival-time picking using
TauP, among others.

2.2. Notebook Tutorial
The Jupyter notebooks were written to be largely self-explanatory, with in-notebook comments and
outputs guiding the user through the workflow. The cell-by-cell descriptions provided in this
document are intended to go a step further by detailing the specific functionality of each cell (e.g.,
key parameters, methods invoked, and how intermediate products feed subsequent steps), and to
help users interpret the results.

2.2.1. PyFK Workflow Example
The notebook PyFK_Simulation_Example_RVDC.ipynb uses PyFK as the simulator within the
Waveform Simulation Framework, demonstrating a comprehensive workflow where a synthetic
source is propagated through a velocity model to a set of synthetic stations. Subsequently, the
synthetic data recorded at the stations are backprojected to estimate the source location. The
discrepancy between the known synthetic source location and the backprojected location provides
useful insights into the accuracy and effectiveness of the velocity model and the station array
geometry.
Section 2.2.1.1 provides a brief workflow summary before diving into the details, with key inputs
summarized in Section 2.2.1.2. The detailed cell-by-cell walkthrough is provided in Section 2.2.1.3.

2.2.1.1. Quick Workflow Summary
This quick workflow summary outlines an end-to-end synthetic seismogram workflow using PyFK:
the notebook imports the required WSF/PyFK modules, defines one or more sources and a receiver
array, configures and executes a batch of PyFK simulations to generate Green’s functions, converts
those Green’s functions to displacement seismograms by convolving with a user-defined source time
function, performs basic QC plotting via gathers, and then demonstrates a travel-time
backprojection step to estimate the source location and quantify mislocation error. A detailed cell-
by-cell walkthrough is provided in Section 2.2.1.3.
 • Cell 1: Imports. Load WSF PyFK simulation classes, backprojection utilities, and standard
 NumPy/Matplotlib tools.
 • Cell 2: Sources. Define an event epicenter and create three Source objects with multiple
 depths in km plus notional mechanism/STF metadata.
 • Cell 3: Receivers. Define station Receiver objects (all in network SY) and assemble the
 receiver list used for simulations.
 • Cell 4: Job setup function. Define setup_job() to configure a PYFKSimulation (receiver,
 source, 1-D velocity model, and time sampling).
 • Cell 5: Simulation collection. Create one simulation per source–receiver pair and package
 them into a simulationCollection.
 • Cell 6: Run simulations. Execute the full set in parallel (nthreads=6), producing Green’s
 functions for each job.
 • Cell 7: Post-process waveforms. Build a Gaussian STF per simulation and
 call processData() to convolve Green’s functions into displacement seismograms.

 12

 • Cell 8: QC plotting. Build a receiver gather for one station and plot traces to verify
 synthetic waveforms look reasonable.
 • Cell 9: Source gather + UTM. Build a source gather for one selected source, plot a record
 section, and convert source coordinates to UTM (Universal Transverse
 Mercator) meters.
 • Cell 10: Search grid. Build a 3-D local grid around the source in meters, extract receiver
 coordinates from headers, reference geometry to the source, and plot grid/receivers.
 • Cell 11: Backprojection misfit. Extract arrival times (t1) from headers and compute a 3-D
 RMS travel-time misfit volume using an assumed P-velocity.
 • Cell 12: Flatten misfit. Reformat the 3-D misfit array into a 1-D vector aligned with
 flattened grid coordinates to enable easy minimization.
 • Cell 13: Result visualization. Plot a 2-D misfit slice with receivers, mark the minimum-
 misfit (estimated) location vs. true location, compute errors, and save the figure.

2.2.1.2.   Inputs
All user-defined input parameters are specified within the notebook itself. If a custom velocity
model is used, it is loaded from the data subdirectory. Key inputs to the WSF PyFK example
workflow, as demonstrated in PyFK_Simulation_Example_RVDC.ipynb, are summarized here:
 • Source definition
 o Source geographic location: longitude, latitude
 o Source depth (the example sweeps multiple depths)
 o Origin time (metadata)
 o Source mechanism parameters (e.g., strike/dip/rake) as applicable
 o STF definition (Gaussian in the example, with parameter alpha)
 • Receiver (station) set
 o Station coordinates: longitude, latitude, elevation
 o Station identifiers/metadata: station name, network, location code
 • Velocity model (1-D)
 o A 1-D seismic velocity model. In the WSF PyFK example workflow, the notebook
 uses a PyFK-provided built-in test model, ak135f_no_mud, for convenience and
 reproducibility.
 o However, the workflow also supports using a custom, user-defined velocity model;
 the WSF SW4 tutorial notebook described in Section 3.2.1 provides an example
 implementation of a custom model, which requires changing only one line of code.
 • Simulation controls
 o Time sampling: dt
 o Record length/duration (converted to npt)

 13

 o Output/simulation directory and run identifiers (e.g., simDir, simID)
 o Execution configuration (e.g., number of threads for parallel runs)
 • Backprojection/location-recovery inputs (post-processing)
 o Arrival-time picks (in the example, taken from synthetic header field t1)
 o Assumed propagation velocity for travel-time backprojection (Pvel)
 o 3-D search grid definition (extent and resolution in x, y, z)
 o Receiver positions in a consistent projected coordinate system (UTM in meters) for
 distance calculations

2.2.1.3. Detailed Cell-by-Cell Walkthrough
The following cell-by-cell walkthrough provides a detailed reference for the WSF PyFK tutorial
notebook, PyFK_Simulation_Example_RVDC.ipynb. It describes the purpose of each cell, the key
parameters defined, the primary methods invoked (simulation, Green’s-function processing, and
plotting), and the main outputs used in subsequent steps, with the goal of supporting step-by-step
execution and interpretation of results.
Cell 1: Import required libraries and WSF/PyFK classes
 • Purpose: Loads all Python packages and Waveform Simulation Framework (WSF) modules
 needed for the end-to-end workflow: defining sources/receivers, running PyFK simulations,
 and performing post-processing (backprojection and plotting).
 • Key imports:
 o WSF + PyFK simulation components
 ▪ Source, Receiver for defining event and station objects.
 ▪ PYFKSimulation, simulationCollection, PYFKModel to configure and run
 PyFK-based simulations and manage results.
 ▪ Config, SeisModel, SourceModel from pyfk.config for PyFK configuration
 and model definitions.
 ▪ Model1D for representing/loading a 1-D velocity model.
 ▪ gaussian (gaussSTF) and cast_to_trace utilities for
 constructing/formatting an STF.
 o Post-processing utilities
 ▪ wsf_pyfk.backprojection for source backprojection/location recovery.
 ▪ wsf_pyfk.snlbrand for Sandia-branded plotting/formatting helpers.
 o Standard scientific Python stack
 ▪ numpy for numerical operations.
 ▪ matplotlib.pyplot for plotting.
 • Output: Prints a confirmation message (“Library functions successfully imported.”)
 indicating the environment is ready.

 14

Cell 2: Define the synthetic source
 • Purpose: Defines the “ground truth” event (source) location and constructs a set
 of Source objects representing the same epicenter with different assumed depths. These
 multiple depths enable later comparison of how depth and modeling choices affect the
 recovered (backprojected) location.
 • Key parameters defined:
          o   Event location: evla = 36.7202306 degrees, evlo = -116.12241 degrees
 o Depth sweep: depths = [1, 2, 10] km (three candidate source depths)
 o Notional focal mechanism: strike = 246, dip = 46, rake = -3
 • Methods/actions:
 o Loops over depths to create a Source((evlo, evla, depth), name=...) object for
 each depth.
 o Adds a dislocation component via addDislocationComponent(strike, dip, rake).
 o Sets a Gaussian STF via setSourceTimeFunction(type='Gaussian', alpha=-40).
          o   Sets the origin time with setOriginTime("1993-05-31T03:15:29.97Z").
 o Appends each configured Source to the sources list for later simulation runs.
 • Notes/assumptions:
 o The comments clarify that PyFK generates Green’s functions, so detailed source
 representation (e.g., moment tensor and final STF) is primarily applied later during
 post-processing (e.g., processData), but these fields are retained for completeness
 and compatibility with other simulators (e.g., CUDA2D).
 • Output: Prints each source index and its corresponding Source object to confirm successful
 creation.
Cell 3: Define the receiver (station) geometry
 • Purpose: Defines the set of synthetic stations (“receivers”) that will record the simulated
 waveforms. These stations collectively form the array geometry used later for
 backprojection.
 • Key parameters defined:
 o Creates Receiver objects with explicit (longitude, latitude,
 elevation/depth) coordinates for each station.
 o Assigns station metadata for each receiver:
 ▪ stationName (e.g., OBHN, OBHS, IST1, etc.)
 ▪ network="SY"
                  ▪   location="00"
 • Methods/actions:
 o Instantiates each receiver using:
 Receiver(coords=(...), stationName=..., network=..., location=...).

 15

 o Builds a receivers list by appending selected stations to be used downstream.
 • Output: Prints the index and representation of each receiver in receivers to confirm
 successful creation and list membership.
Cell 4: Define a helper function to configure a PyFK simulation job
 • Purpose: Defines setup_job(...), a convenience function that creates and fully configures
 a PYFKSimulation object for a single source–receiver pair, including simulation ID, receiver,
 source handling, velocity model, and time-sampling parameters.
 • Key inputs/parameters:
 o info: list – container holding job-specific items (used by index):
 ▪ info[0]: simulationIndex used to generate a unique simulation ID (UID)
 ▪ info[1]: receiver object assigned via sim.setReceiver(...)
 ▪ info[3]: source specification (either a WSF Source or a PyFK SourceModel)
 ▪ info[4]: source location override used when info[3] is a SourceModel
 o simDir: str = "RVDC_Simulations" – output/working directory for simulation
 artifacts
 o dt: float = 0.025 – sampling interval in seconds
 o duration: float = 30.0 – total record length in seconds
 • Methods/actions:
 o Initializes a PYFKSimulation with simID derived from simulationIndex.
 o Assigns the receiver from info[1].
 o Assigns the source from info[3], with special handling if the source is provided as
 a pyfk.config.SourceModel:
 ▪ Converts the PyFK SourceModel into a WSF Source via
 from_PyFKSourceModel(...)
 ▪ Overrides sim.source.lat and sim.source.lon using info[4]
 o Builds a 1-D velocity model using the default model provided in the PyFK package:
 Model1D().PyFK_TaupGenTestModel("ak135f_no_mud").
 o Converts the Model1D representation into the simulator-specific format
 using PYFKModel.convert_Model1D(...), then attaches it via sim.setModel(...).
 o Computes number of samples npt = round(duration/dt) and sets simulation time
 sampling with sim.setSimulationParameters(npt=npt, dt=dt).
 • Output: Prints "Simulation generation function ready." indicating the job-
 construction function is defined and ready for use.
Cell 5: Build the simulation ensemble (all source–receiver combinations)
 • Purpose: Constructs a set of PyFK simulation jobs spanning every combination of defined
 sources (depth cases) and receivers (stations), then bundles them into
 a simulationCollection for convenient batch execution.

 16

 • Methods/actions:
 o Initializes a simulation counter isim = 0 and an empty list simCol.
 o Nested loops over:
 ▪ receivers (index irec, receiver rec)
 ▪ sources (index isrc, source src)
 o For each source–receiver pair, packs job configuration into an info list:
 ▪ [isim, rec, 'dummy', src, [evla, evlo]]
 ▪ ('dummy' serves as a placeholder entry; setup_job uses indices 0, 1, 3, and 4.)
 o Calls setup_job(info) to create a configured PYFKSimulation object and appends it
 to simCol.
 o Increments isim for unique simulation IDs.
 o Converts the Python list into a simulationCollection(simCol) object.
 • Output: Prints a summary count of the number of sources, receivers, and total simulations
 created (i.e., #sims = #sources × #receivers).
Cell 6: Execute simulations in parallel
 • Purpose: Runs the full simulation ensemble generated in the previous cell, using
 multiprocessing to accelerate computation across the source–receiver combinations.
 • Methods/actions:
 o Calls simCol.execute_mp(nthreads=6) to execute all PYFKSimulation objects in

 • Output: Prints "Completed" after the batch run finishes.
Cell 7: Convolve Green’s functions with a source-time function and generate displacement
seismograms
 • Purpose: Converts the PyFK-generated Green’s functions into synthetic displacement
 waveforms by defining an STF and applying it to each completed simulation
 via processData(...).
 • Key parameters defined:
 o alpha = 1 – Gaussian pulse-width factor for the STF (larger values produce broader
 pulses).
 o Uses each simulation’s sampling interval dt = sim.parameters[0].dt to ensure the
 STF is sampled consistently with the simulation output.
 • Methods / actions:
 o For each simulation in simCol:
 ▪ Generates a Gaussian STF using gaussSTF(dt, alpha).

 17

 ▪ Converts the STF from an ndarray to an ObsPy Trace object using
 cast_to_trace(dt, stf[1]), because the internal
 synchronization/convolution routines in processData expect a Trace.
 ▪ Stores the per-simulation STF in source_time_functions.
 o Iterates over simulations again and, for each completed run (sim.Completed):
 ▪ Calls sim.processData(stf=source_time_functions[idx]) to apply the
 STF and compute displacement seismograms from the 9-component Green’s
 function tensor.
 ▪ processData also uses the source–receiver geometry to compute azimuth for
 the radiation pattern.
 • Output: Prints "Source time function convolved into Green's Functions." after
 processing; prints an error message for any simulation that did not complete.

 ▪ rgz (vertical), rgr (radial), rgt (transverse), and an additional returned object

 o Iterates through the transverse gather rgt and calls tr.plot() for each trace to

 • Output/figures: Produces one (or multiple) waveform plots, i.e., one per trace in rgt,

 • Key parameters defined:

 • Methods/actions:

 o Calls simCol.create_source_gather(source) to collect waveforms across receivers

 ▪ source_gather_z, source_gather_r, source_gather_t (component

 • Purpose: Builds a 3-D spatial search grid (in meters) for backprojection, extracts receiver

3. WSF SW4
The WSF SW4 toolkit consists of a Python backend module (SW4Simulator.py) and supporting
classes (SW4Model, Source, Receiver) that allow users to run the native SW4 application directly
from a Jupyter notebook using a workflow that is similar in style to the WSF PyFK examples.
SW4 is a highly scalable seismic-wave simulator that solves the 3-D elastic wave equations (in
displacement form) using a fourth-order summation-by-parts finite-difference scheme,
supporting large-scale runs in parallel using Message Passing Interface (MPI). MPI is a standard
programming model and set of libraries used to run a single application across multiple processes,
typically distributed over multiple CPU cores and/or multiple compute nodes, by passing messages
between those processes.

3.1. Installation and Setup
The tutorials and wrapper codes were developed and tested using Python 3.9, which is the
recommended version for running the notebooks to ensure package compatibility and reproducible
results. Running SW4 through the Waveform Simulation Framework requires two components: the
native SW4 application and the WSF SW4 wrapper. SW4 performs the underlying 3-D wave-
propagation calculations, while WSF SW4 manages model/source/receiver setup, writes the SW4
input deck, and formats simulation outputs for analysis within a workflow similar to that used with
other WSF simulators.
As explained in Section 3.2.1, the WSF SW4 notebook tutorial also requires WSF PyFK to be
installed because it imports modules directly from the WSF PyFK code library. See Section 2.1 on
installation instructions for WSF PyFK.

instructions and user documentation at the following site:

3.2. Notebook Tutorial

3.2.1. SW4 Workflow Example
The notebook SW4_Simulation_Example_RVDC.ipynb uses the SW4Simulator.py module – the WSF
SW4 backend – as a thin Python wrapper around SW4. SW4Simulator.py provides the interface
between WSF-style objects (1-D velocity models, sources, and receivers) and the native SW4
executable by generating the required SW4 input files (e.g., the material model and ASCII input
deck), launching SW4 (serial or MPI), and organizing outputs for post-processing. The notebook
interface and cell structure follow the PyFK example as closely as possible to support direct

 26

comparison and reproducibility, and it is designed to integrate cleanly with the same object schema
used in the PyFK workflow.
A typical WSF SW4 workflow starts by selecting a 1-D velocity model (Model1D) and converting it
into an SW4-ready model file (SW4Model, written as material.in). The user then defines one or
more Source objects (events) and Receiver objects (stations). Next, the wrapper’s
internal _assemble_deck() routine automatically builds the SW4 run configuration: it chooses a
simulation box large enough to include all sources and receivers, adds a boundary “buffer”
(supergrid) to reduce edge reflections, sets up the computational grid, writes the SW4 text input
deck, and launches SW4 either in parallel (MPI) or in serial using subprocess. After the run
finishes, processData() reads the SAC output files into ObsPy Stream objects, assigns consistent
UTC start times, and returns three-component waveforms for plotting and downstream analysis.
The primary output of this notebook is a set of SAC waveform files for the specified receiver list.
These SAC files can be read into ObsPy Stream objects for downstream processing and analysis.
ObsPy is an open-source Python library widely used in seismology for reading and writing
waveform formats (including SAC), managing time metadata, and performing common processing
tasks such as filtering, plotting, and phase picking; its wiki page is found here:
https://github.com/obspy/obspy/wiki/

4. WSF SPECFEM2D
The WSF SPECFEM2D codes are a Python-based wrapper for running the SPECFEM2D
waveform simulation package, which is implemented primarily in C and Fortran and uses
the spectral finite-element method to model 2-D seismic wave propagation in acoustic, elastic,
viscoelastic, and poroelastic media.
The wrapper leverages Waveform Simulation Framework (WSF) objects to define a 1-D or 2-D
simulation project, including a user-defined source, receiver set, source time function, and 1-D or
2-D velocity model. These inputs are passed to the SPECFEM2DSimulation object, which generates
the required SPECFEM2D input files in the correct formats. The wrapper also provides functions
that give users full access to modify parameters contained in the native SPECFEM2D input files,
enabling more flexible and advanced use of the underlying simulation codes.
After a SPECFEM2D run completes, the wrapper reformats the simulation outputs into three-
component, ObsPy-based Stream objects, which can then be used in downstream post-processing
workflows (including analysis approaches consistent with those used in the WSF PyFK examples).
In addition, the WSF SPECFEM2D distribution includes scripts to assist with initial SPECFEM2D
installation and directory organization, streamlining setup for rapid use with the wrapper.

4.1. Installation and Setup

the recommended version for running the notebooks to ensure package compatibility and
reproducible results. To use the framework with the SPECFEM2D simulator, users must install

wrapper. In this configuration, SPECFEM2D performs the numerical wave-propagation
simulations, while WSF SPECFEM2D provides the framework-facing interface that generates
correctly formatted SPECFEM2D inputs and organizes outputs for downstream analysis within the
same workflow used by other WSF simulators.
