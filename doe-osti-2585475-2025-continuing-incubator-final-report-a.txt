ABSTRACT
This project advanced the development of an active hybrid mooring system integrating experimen-
tal testing with numerical simulation to capture complex mooring dynamics not feasible in existing
wave basins, including deep-water and shared mooring interactions. The goals of this phase of
the project were to conduct nonlinear wave verification testing, enable shared mooring capabilities,
and enhance the realism of previously developed actuator models. The enhanced capabilities were
realized by developing a modified version of OpenFAST capable of accepting mooring loads as
external inputs from the existing numerical model running a modified version of standalone Moor-
Dyn. Time benchmarking demonstrated that the complete coupled model executed fast enough to
operate at 1:60 Froude scaling, even with conservative assumptions with the test hardware. Actua-
tor model validation showed negligible error relative to the expected force decomposition derived
from a Simulink Multibody model. Verification testing of the complete hybrid system yielded
good agreement in mooring tension and platform translation responses, though discrepancies in
platform pitch response indicate that further refinement of the modified OpenFAST implementation
is required for robust performance. The necessary improvements to the OpenFAST model have
been identified, and their resolution has been documented for prioritization in future research.

1. METHOD

1.1. Background

Active hybrid mooring (AHM) is a real-time hardware-in-the-loop system where a scaled tower,
blades, drivetrain, and platform are built in a wave basin, while some or all of the mooring system is
modeled numerically using a connected computer running a mooring model. The physical model
and the computer model interface through a series of sensors and actuators in the wave basin. The
computer model uses real-time motion inputs from the physical model to model the mooring system
load response. The mooring line loads are then sent to the actuators in the wave basin, providing
the proper mooring system response on the physical model with the desired parameters from the
computer model. Due to this partitioning strategy, the computer model can theoretically simulate
mooring system loads for any set of parameters, including a drastically increased water depth or
loads from shared mooring. One possible configuration of an active hybrid mooring system in a
wave basin is presented in Figure 1-1.

 Figure 1-1. Representation of a possible active hybrid mooring system
 setup.

Existing literature on AHM systems [1, 2] show the idea to be feasible when actuating horizontally
without wave loading. However, to fully account for realistic dynamics likely to be encountered
in deployed systems, six degree of freedom (6DOF) actuation in wave loading scenarios must be
explored. Since adding more degrees of freedom and wave excitation frequencies present stricter
time requirements into a real-time hybrid system, it remains an open question whether an AHM
system with wave loads can operate in real time in 6DOF. Thus, the goal of this Incubator project is

 11

to define, create, and verify a computer-simulated AHM model in Simulink, exploring the general
feasibility of a 6DOF AHM system in terms of speed and accuracy.

In the first year of this Incubator project, we:

 • Scoped and design a test setup of a 1,000-meter mooring system for the 15 MW VoltunUS-S
 floating wind turbine

 • Developed and tested initial models of a chained hydraulic actuator system in Simulink
 Simscape

 • Built the numerical model for the hybrid system based on a modified version of MoorDyn
 [3]

 • Conducted time benchmarking and accuracy verification studies for the system

Further details about the methodology and results from the first phase of the project can be found in
[4]. The testing in the first year of the project showed promising results and warranted expanding
capabilities based on feedback from WETO and ideas developed during the first year of the project.
Goals for this phase of the project were:

 • Fixing minor issues with the model unresolved after the first phase of the project

 • Testing the model against a more complex, nonlinear wave case to ensure the model maintains
 speed and accuracy under more complex loading conditions

 • Further improve and validate the actuator models, including realistic force decomposition
 and reference frame handling

 • Expanding the capabilities of the numerical model to be able to simulate the effects of shared
 mooring from other floating devices

This continued project work aims to further de-risk the AHM technology by making it capable
of handling realistic conditions that may be of interest to those conducting wave basin tests for
floating offshore wind turbines. Ultimately, the results of this work could provide the framework
to construct a physical AHM system when funding becomes available to do so.

This section will discuss new capabilities added to the AHM system during this phase of the project,

1.2.1. Experiment Representation

One of the major additions to the AHM system in this phase of the project was replacing the
surrogate model as the representation of the wave basin with a more robust representation. The
surrogate model proved to be very limited in its stable range of wave conditions, was limited to
first-order linear waves, and proved much less computationally efficient than desired, meriting its
replacement to fulfill the goals of this phase of the project. We decided on creating a modified
version of OpenFAST v2.3.0 [5]that would allow for coupling to the numerical model by transferring
the scaled force inputs to the OpenFAST MoorDyn module1 , which integrates into the overall
OpenFAST simulation framework capable of simulation the full floating wind turbine dynamics.

The primary modifications done to OpenFAST v2.3.0 involved adjusting the MoorDyn module
input file coupling between the MoorDyn mooring dynamics model and the OpenFAST simulation
framework to enable scaled force inputs to be applied directly at designated anchor points. This
required restructuring the workflow so that external input forces, passed from the AHM MoorDyn
S-Function, could be mapped into the OpenFAST external inputs and then transferred to specific
points with the MoorDyn module, which would be included in the integrated force equation.
We implemented an indexing scheme in the MoorDyn module input file corresponding to the
connections to the forces provided in Simulink from the AHM MoorDyn S-Function, allowing
OpenFAST to distinguish between externally driven points and those left to the internal force
calculations in the MoorDyn module. We restricted this to 3 indexed points per mooring line for
purposes of the initial implementation, which could be generalized in future revisions of the model.
We also adjusted the OpenFAST S-Function interface to accommodate the expanded number of
inputs required for the external point force application.

A key design consideration was how to treat the points in the MoorDyn module to ensure the
coupled behavior was physically realistic and stable in the OpenFAST simulation. We ultimately
defined the anchor points were redefined as Coupled nodes, allowing them to respond to external
forces provided by AHM MoorDyn while resolving with the other forces present in the rest of the
mooring system in the MoorDyn module. The original mooring system used in the first phase of
the project was also slightly re-tuned at this point to cooperate more realistically with the platform,
as we found the platform to slightly sink due to excessive pretension in the cables caused by a taut
mooring system operating on a semisubmersible platform.

Once a stable configuration was achieved, the modified OpenFAST S-Function was recompiled and
integrated into the larger AHM model. Initial free decay tests confirmed that the coupled anchor
points exhibited realistic motion, and relevant motion data could be extracted from OpenFAST
using MATLAB functions embedded in the Simulink loop. This enabled tracking of any standard
OpenFAST model output, which was used for the verification tests in Section 2.

With the modified version of OpenFAST successfully integrated into the AHM model to receive
force inputs at the partition/actuator location, the AHM model became capable of modeling complex

1.2.2. Numerical Model

As the implementation of the new modified OpenFAST S-Function into the AHM model enables the
bulk of the new capabilities sought in the project goals for this phase of the Incubator, adjustments
to the AHM MoorDyn numerical model were fairly minor. The main addition to the numerical
model was the capability to couple the numerical model at either end of the numerical mooring
line instead of only at the partition point. This added capability enables simultaneously coupling
to multiple external motion sources, which is crucial for the shared mooring capabilities. For
example, to model the experimental turbine with one mooring line shared with another floating
wind turbine, the numerical model must receive coupled motions from the experimental turbine at
one end of that line and a concurrent simulation of the modified OpenFAST program on the other
end.
Implementing this capability was straightforward, and merely required making the numerical model
S-Function more agnostic to where the inputs are coming from and the format they are received,
along with minor modifications to the default AHM MoorDyn input file. More discussion of the
definition and testing of the shared mooring setup is provided in the following section.

1.2.3. Shared Mooring Testing Methodology

The AHM configuration to test shared mooring capabilities, where the dynamics of multiple floating
wind turbines can be considered in a wave basin test while only physically testing one wind turbine,
is illustrated in Figure 1-2. In this setup, the numerical model running AHM MoorDyn and the
wave basin experiment (or, in the case of this project, a computer representation of the experiment)
are connected to each other in the same manner as in previous iterations of the AHM model. Other
wind turbines connected to the wave basin experiment via shared mooring are each simulated using
their own iteration of the modified OpenFAST model, which is also connected to the numerical
model via a coupled point at the other end of each mooring line. The wave basin experiment and
the OpenFAST-simulated wind turbines transmit motion data at the partitioning point between the
programs (ideally some midpoint on the mooring line beneath 40 meters in unscaled water depth,
where the effects of wave kinematics are typically considered negligible) to the numerical model,
which then calculates and returns the corresponding loads of the simulated mooring lines at the
same point, closing the loop.
Though not explicitly tested in this project, researchers will likely achieve best results with this
shared mooring testing method if the simulated wave environments in the HydroDyn input files in
the modified OpenFAST simulations matches the wave basin experiments as closely as possible.
This will allow the closest approximation to the shared mooring response of multiple turbines in
the wave basin at once.

1.2.4. Actuation System Definition

The proposed actuation system configuration for AHM can be seen in Figure 1-3. The stationary
coordinate frame provided in the figure is the body frame of the actuation system. The system is
initially configured with the linear actuator (3) in the 𝑥𝑧 plane pointing in the direction of +𝑥 and
+𝑧; coplanar to the taut mooring line. Rotary actuator (2) is initially rotating about the body −𝑦
axis, and rotary actuator (1) is always rotating about the body 𝑧 axis.

Assume there are two short rigid linkages connecting the three actuators: one linkage connecting
actuators (1) and (2), and the other linkage connecting actuators (2) and (3). Let Joint 1 be the
revolute joint on actuator (1), Joint 2 be the revolute joint on actuator (2), and Joint 3 be the prismatic
joint on actuator (3). The linkages are assumed to be small, and the displacement between Joint 1
and Joint 2 is assumed to be negligible.

1.2.5. Derivation of Actuator Torque/Force Equations

In order to actuate a global force using the proposed chained actuation system, the individual
actuator torques/forces must be computed based on the current pose of the actuation system and
the desired force for the end effector to produce. A common approach to solving this problem is
to use the following geometric Jacobian based equation which relates the end-effector forces to the
actuator forces and torques [6]:

                                              𝝉 = 𝑱𝑇 (𝒒) 𝒇𝑒𝑒                                         (1.1)

allow the system to be considered instantaneously static and allow inverse statics to be used. In
the actuation system described in Figure 1-3, there are three joints, therefore 𝝉 is the 3x1 vector
[𝜏1 , 𝜏2 , 𝑓3 ] 𝑇 , where 𝜏1 is the torque at actuator (1), 𝜏2 is the torque at actuator (2), and 𝑓3 is the

1.2.9. Middleware

OpenFresco (Open Framework for Experimental Setup and Control) is an open-source middleware
software developed to facilitate RTHS by integrating physical and computational components into a
unified testing environment [9]. It provides a flexible interface that links dynamic analysis programs
with experimental testing equipment, allowing for the execution of hybrid models where part of the
structure is simulated numerically and part is physically tested in real time. OpenFresco handles
the coordination and data exchange between the numerical model and the physical test specimen,
managing signal generation, data acquisition, and actuator control with strict timing constraints to
ensure accuracy and stability.

 26

 Figure 1-13. Results from actuator (2)

 Figure 1-14. Results from actuator (3)

In our AHM system, OpenFresco connects the two parts of the rehearsal simulation by combining
the modified MoorDyn numerical model with the simulated physical test specimen performed by
the actuator models and modified OpenFAST model within Simulink on an independent kernel
operating as an independent system. The OpenFresco submodel in Simulink contains a predictor-
corrector and delay compensator block, taking in inputs from the modified MoorDyn numerical
model (the “client") and allowing for continued real-time operation if the numerical model does
not supply inputs sufficiently quickly to operate in real time. The connections within OpenFresco
to the experimental setup components instead send outputs to the modified OpenFAST S-Function
connected via TCP/IP socket to a local port on the same machine. After the prediction/correction

2. KEY FINDINGS

2.1. Nonlinear Waves Testing

The assembled AHM model discussed in the previous sections was compiled and simulated to
verify the stability and accuracy of the coupled modeling approach. The verification testing used
load case 3.4 from the OC5 Phase II test campaign [10], with a JONSWAP wave spectrum defined
by 10.5 meter significant wave height, 14.3 second peak period, and 𝛾 of 3. The modified version
of OpenFAST discussed in Section 1.2.1 was used as the computational stand-in for the wave basin
experiment. We selected the fairlead tensions, anchor tensions, and dominant platform motions
(surge, heave, and pitch) as the variables of interest for the verification, as these would be indicative
of the overall performance of the coupled system. These variables were recorded in the output file
of the modified OpenFAST program, which was processed and analyzed after the test completed.
10 minutes of results were recorded after an initial minute of simulation to remove any transient
effects from the results. These results were compared to a standalone version of OpenFAST v2.3.0
with identical input conditions.
The verification results of the nonlinear wave test are shown in Figure 2-1. The AHM model
shows good matching in all the variables with the exception of platform pitch. There is a slight
overprediction of tension at both the fairlead and anchor points, with corresponding slight under-
prediction of platform surge and heave. This is likely due to a small discrepancy in the dynamic
relaxation routines between the AHM MoorDyn and OpenFAST MoorDyn module instances, re-
sulting in hydrostatic equilibrium positions between the mooring lines disagreeing slightly. The
pitch discrepancy is significant, with the AHM model displaying both substantially reduced pitch
motion and an equilibrium point centered on zero instead of slightly opposing the incoming waves.
We suspect this discrepancy is caused by the internal force discrepancies between the AHM Mo-
orDyn model and the MoorDyn module within the modified version of OpenFAST. Specifically,
the internal forces of the mooring lines captured in the modified version of OpenFAST are not
propagated as internal forces in the OpenFAST MoorDyn module. In other words, the stuctural
and hydrodynamic modules in the OpenFAST simulation are only capturing internal forces for the
depth of the partitioned mooring system, not the complete depth of the mooring system we wish
to simulate. Since the platform motions are calculated in the structural module of OpenFAST, and
pitch is particularly sensitive to internal mooring line forces, this error manifests most obviously
with these differences in the platform pitch.
Since this error in the experimental representation is specific to the modified OpenFAST model,
this result does not invalid the previous results found in the initial phase of this project, which used
a surrogate model with linear waves instead of the modified OpenFAST model. Additionally, since
this error is unrelated to the AHM numerical model itself, an AHM setup using a real experimental
setup not using shared mooring is expected to perform well, since no OpenFAST model would

in the modified version of OpenFAST is fixable, though we were unable to address it in this phase
of the project. The expected resolution for this issue is discussed in more detail in Section 4.

2.2. Shared Mooring Testing

The planned testing procedure for the shared mooring verification was similar to the test used for the
nonlinear wave verification test explained in Section 2.1, except with one mooring line shared with
an identical 15 MW turbine positioned 1,600 meters away in the direction of the shared mooring
line. To simulate this, two instances of the modified OpenFAST S-Function were used: one

 30

representing the experimental wind turbine operating in the wave basin (with a truncated mooring
system), and another representing the purely computational wind turbine (with a complete mooring
system sans the lower portion of the shared mooring line). The results were to be compared against
a parallel simulation of the system performed in an unmodified version of FAST.Farm with identical
input conditions.
Unfortunately, the AHM system would consistently go unstable and fail after about 1.2 seconds of
simulation time, preventing us from gathering any useful verification data. Considering the initial
time steps of these simulations indicate the platform pitch rapidly increasing to the point where the
small angle assumption used in the HydroDyn module is violated, we suspect that the error in the
modified OpenFAST program resulting in a significant pitch discrepancy discussed in Section 2.1
is the reason for the instability. This cause seems intuitive, given the close coupling between the
modified OpenFAST version and the numerical model for the shared mooring line, which could
cause drastically different tensions compared to the mooring lines that are not connected to the
OpenFAST simulation, potentially causing drastic platform rotations.
As discussed in Section 2.1, we believe the OpenFAST error causing these instabilities is fixable,
though we were unable to address it in this phase of the project. A discussion on the resolution of
this error can be found in Section 4. Unfortunately, as the shared mooring method used in the AHM
system requires at least one concurrent simulation of the modified OpenFAST program, realistic
shared mooring capabilities will not be feasible with the AHM model until this error is resolved.

2.3. Time Benchmarking

Despite the shortcomings of the verification tests due to the error with the modified OpenFAST
software, we were able to perform representative time benchmarking of the AHM system for the
shared mooring test by including all the relevant Simulink blocks (two modified OpenFAST S-
Functions, one AHM MoorDyn numerical model, and the OpenFresco subsystem) but leaving
the shared mooring inputs disconnected, instead being fed inputs from an unmodified OpenFAST
model. This allows all the blocks to execute as they normally would to capture the expected time it
would take for a shared mooring AHM simulation to run, with any differences resulting from the
disconnected inputs likely being minor due to the relative insignificance of the Simulink connections
within the model compared to the execution time of the OpenFAST and AHM MoorDyn programs.
Benchmarking simulations were run for 60 seconds for a variety of MoorDyn integration steps and
OpenFAST time steps. For simplicity, the MoorDyn integration steps were matched between the
OpenFAST MoorDyn module and the AHM MoorDyn numerical model.
Results of the time benchmarking are shown in Table 2-1. The results show greater computational
expense with the shared mooring AHM model compared to the time benchmarking from the

while maintaining internal stability. The greater computational expense is expected, considering
the fidelity of OpenFAST is much greater than the AHM MoorDyn model tested in previous

2.4. Actuator Model Validation

A model of the actuation system was developed in Mathworks Simulink Simscape to compare the
accuracy of the derived equations to a model made with a well established software package.

This subsection will give a brief overview of how the model functions. As can be seen in Figure 2-2,
the model is made up of blocks defining the geometry of the rigid bodies composing the actuation
system. There are also blocks that define the type of joint connecting each rigid body. Inside each
actuator subsystem are Rigid Transform blocks that define the position and orientation of each
rigid body and joint. The end effector in this model is a rigid cube that is connected to the end
of the linear actuator piston via a spherical joint such that it can move in all modeled degrees of
freedom.

 Figure 2-2. Simulink block based model of actuation system

Joint 1, Joint 2, and Joint 3 receive user defined 𝜃 1 , 𝜃 2 , and 𝑑3 as inputs, which define the pose
of the system. The user also defines an external force in Body frame coordinates to be applied to
the end effector. The joint blocks will then compute and output the necessary torques and forces
to provide to the actuators for the system to remain in static equilibrium (i.e. 𝜃 1 , 𝜃 2 , and 𝑑3 will

4. CHALLENGES ENCOUNTERED & LESSONS LEARNED

As discussed in Section 2, a major challenge preventing the goals of this phase of the project from
being realized was the discovery of an error in the modified version of OpenFAST we developed,
which resulted in significant platform pitch discrepancies in the nonlinear wave verification testing
and fatal errors rendering the shared mooring capabilities incomplete until resolved. We identified
the likely resolution for this error, but did not have sufficient time to implement the resolution before
the conclusion of the project. As resolving this error is paramount to allow the full capabilities
of the AHM system, future work expanding on this project should prioritize fixing this error by
following the procedure:
 1. Modify the AHM MoorDyn source code to allow for transfer of the internal mooring forces
 as an output independent of the primary mooring load outputs
 2. Modify the modified OpenFAST MoorDyn module source code to receive these internal
 mooring forces at the coupled points specified in the input file
 3. Ensure these forces are propagated to the ED_HD_InputOutputSolve subroutine, which
 handles the loose coupling between the hydrodynamics, mooring dynamics, and structural
 dynamics in OpenFAST
 4. Add checks to ensure the received internal forces are not double-counted by the modified
 OpenFAST MoorDyn module (optional, but recommended practice)
Additionally, while the results of the rehearsal simulation developed and tested in this project could
provide great value to future researchers interested in implementing a hybrid mooring system, this
work should be augmented by further scoping and model validation of other wave basin components
that were impractical to capture in the scope of this project, particularly the motion capture system
and specific actuator orientation in the wave basin. This setup could vary significantly between
test facilities based on the wave basin dimensions, the equipment available, and the accessibility of
the bottom of the wave basin to install the actuators and connect the mooring lines. Future work
may consider investigating these details for a specific wave basin of interest and integrated with
the AHM system developed in this project to further de-risk the hybrid mooring system before
launching a formal experimental campaign.
