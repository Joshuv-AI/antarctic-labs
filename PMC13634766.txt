A multilingual annotated dataset for metadata extraction from Persian, Arabic and English scientific articles: header and reference section annotations
Authors: Arash Yousefi Jordehi, Reza Fallah, Ebrahim Nikmard, Mahsa Hosseini Khasheh Heyran, Seyed Abolghasem Mirroshandel
Published: 2026

ABSTRACT
This data article describes a multilingual annotated dataset for training and evaluating metadata extraction systems for scientific articles written in Persian, Arabic and English. The dataset consists of 635 JSON files, one per scientific article, holding the annotations of the article header and of the reference section. The article-level language distribution is 352 Persian (55.4 %), 142 English (22.4 %) and 141 Arabic (22.2 %). Of the 635 articles, 621 contain annotated reference sections; the remaining 14 contain header annotations only. In total, 17,832 individual reference strings are annotated, comprising 8476 Persian (47.5 %), 5741 Arabic (32.2 %) and 3615 English (20.3 %) strings. Header annotations cover seven metadata fields: title, authors, affiliations, abstract, keywords, venue information and DOI. Reference annotations cover twelve metadata fields: title, authors, journal or conference name, volume, issue number, page range, year, DOI, publisher, book identifier, organisation and reference type, alongside the raw reference string. The source articles were retrieved from open-access repositories covering >580 conferences and journals. Annotation was carried out over a period of more than twelve months by a team of ten annotators using a purpose-built Java labelling tool with color-coded tagging, and every annotated file was checked against its source PDF in a dedicated review phase. Each file is self-contained: it stores the annotated text spans verbatim together with their labels, so the original PDF is not required in order to use the data. The format can be consumed directly by sequence labelling methods such as conditional random fields, recurrent neural networks, transformer-based token classifiers and large language models. The data can be reused to develop and benchmark metadata extraction and citation parsing systems and to support indexing in digital libraries and scholarly search services covering Persian and Arabic literature.

Openly annotated resources for these two languages are scarce, and the tools most widely used in this area, namely GROBID [2], ParsCit [3] and CERMINE [4], were developed and evaluated on English material. Groups working on non-English scholarly document processing can therefore train and evaluate models without first having to build an annotated corpus of their own.•Header and reference annotations are provided for the same set of articles, which allows a complete extraction pipeline, from the identification of bibliographic fields on the first page through to the parsing of individual reference strings, to be trained and evaluated on a single resource. Background

The growth in the volume of scientific publications has increased the demand for automated metadata extraction, which underpins digital libraries, citation indexes and scholarly search services. For English-language articles a number of mature systems are available, among them GROBID [2], ParsCit [3] and CERMINE [4]. Reference string parsing in particular has been approached with hidden Markov models [[5], [6], [7]], conditional random fields [8,9], structural support vector machines [10], sequence alignment [11] and hierarchical knowledge representation [12], and has been studied for PDF as well as HTML sources [13,14]. Surveys and comparative evaluations of the resulting tools are reported in [[15], [16], [17]]. These efforts have concentrated on English and, to a lesser extent, on other Latin-script languages. We are not aware of a publicly available annotated corpus for header or reference metadata extraction from Persian or Arabic scientific articles, which limits the extent to which scholarly output in these languages can be indexed by the same infrastructure that serves English-language literature. Right-to-left script, mixed-script reference strings, the use of the Solar Hijri calendar in Persian publication years and venue-specific formatting conventions all mean that models trained on English material cannot simply be transferred.

The present dataset was assembled to provide the annotated material required for that work. This data article describes the annotated data, its structure, its annotation schema and the procedure by which it was produced, so that the data can be reused and extended by other groups.

Record format

Each record is a single JSON object. The header fields are stored at the top level and the annotated reference strings are stored in the references array. Persian and Arabic text is stored as UTF-8 in logical order, without additional bidirectional control characters. Fields that do not occur in the source article are stored as null. Note on the original source documents

The annotations were produced from open-access PDF articles. The PDF files themselves are not redistributed in the repository, because their copyright is held by the respective publishers. The dataset is nevertheless self-contained: every annotated text span is stored verbatim inside the JSON files, so no part of the data requires access to the original PDFs in order to be used.

Experimental Design, Materials and Methods

The dataset was produced through the four-phase procedure shown in Fig. 3.Fig. 3The four-phase procedure by which the dataset was produced. Files rejected in the review phase were returned for re-annotation.Fig 3 dummy alt text

The four-phase procedure by which the dataset was produced. Files rejected in the review phase were returned for re-annotation.

Phase 1: collection of scientific articles

Open-access scientific articles in Persian, Arabic and English were collected from public online repositories and conference proceedings. Source selection prioritized breadth: one of the repositories used contains articles from >580 registered conferences alone. Collecting from many venues rather than a few ensures that the resulting data cover a wide variety of page layouts, formatting styles, fonts, citation formats and publisher conventions, and that they span several scientific disciplines.

Phase 2: classification and validation

Every collected file was inspected to confirm that it is a scientific article rather than, for example, a table of contents, a proceedings front matter or a poster abstract. Files that passed this check were classified by source venue, by language (Persian, Arabic or English) and by document structure. Language was assigned with Apache Tika [18] and confirmed manually. This phase acted as a quality filter and produced a validated corpus ready for annotation.

Phase 3: annotation

Annotation was carried out by a team of ten trained annotators over a period of more than twelve months. A Java labelling tool was developed specifically for this task; PDF text and layout were obtained with Apache PDFBox [19]. The tool provides:•Rendering of the PDF article with its full text;•A color-coded tagging interface in which the annotator selects a text span and assigns a metadata label, each label having its own color;•Support for right-to-left (Persian and Arabic) and left-to-right (English) text, including mixed-script reference strings;•Handling of multi-line metadata fields, footnotes and mixed-language content;•Export of the completed annotation to a structured JSON file.

Each article was annotated for both header metadata and reference metadata. Annotators worked from a written set of guidelines that fixes the label inventory, the span boundaries to be used for each label and the rules to apply to ambiguous cases, such as reference strings that carry both a journal name and a publisher, or affiliations that run across several lines. Annotation was carried out under supervision, and questions arising during annotation were resolved by the supervisor and, where they affected the conventions themselves, recorded in the guidelines.

The exported JSON file for each article is self-contained: it stores the annotated text itself rather than character offsets into the PDF, so neither the PDF nor the labelling tool is needed in order to use the data for training or evaluation.

Phase 4: review and quality control

Every JSON file produced in Phase 3 was reviewed systematically. Each file was compared field by field against the original PDF in order to verify that the annotated spans are correct and complete. Where discrepancies were found, the article was returned to Phase 3 for re-annotation and re-entered the review queue. Only files that passed review were included in the released dataset. Quality assurance

To provide an empirical measure of annotation reliability, an inter-annotator agreement study was conducted on a random sample of 127 articles, corresponding to approximately 20 % of the corpus. The results are summarized in Table 8. Agreement is consistently high for the core bibliographic fields: article title (99.2 % exact match), abstract (99.2 %), keywords (96.6 %), author names (F1 = 0.967), reference title (94.3 %), publication year (96.7 %) and reference type (97.6 %, Cohen's Kappa = 0.954, indicating almost perfect agreement on the scale of Landis and Koch [20]). The reference matching rate between the two annotators was 99.2 %, with 2881 of 2904 reference strings matched.

The high agreement on the high-volume fields confirms that the first-pass annotations were of high quality and that the review procedure functioned as a targeted correction mechanism rather than as a wholesale re-annotation.

Lower agreement is observed on fields whose boundaries are inherently ambiguous or whose occurrence is sparse. The venue_information field (16.7 % exact match) combines journal name, volume, issue and year into a single free-text string, and the two annotators differed in how they segmented these components. Affiliations (F1 = 0.527) are multi-line and heterogeneous in structure, which makes exact set comparison sensitive to minor formatting differences. DOI appears in only 11 of the 127 sampled articles, so the 54.5 % figure is based on a very small count. Among reference fields, book identifiers (18.5 %) and DOIs (41.3 %) are similarly sparse, and the reference-authors field (F1 = 0.726) reflects variation in how multi-author strings are split into individual names. These patterns are consistent with findings in the metadata extraction literature, where structural fields such as title and year are easier to delineate than composite or optional fields [16].

Limitations

The dataset covers born-digital PDF articles only; scanned and image-based documents are not represented, and the annotations therefore cannot be used to evaluate extraction from OCR output. The original PDF files are not redistributed because of publisher copyright, so only the structured JSON annotations are provided.

Several fields are sparsely populated and should not be used on their own to train a field-specific model. DOI occurs in 15.4 % of header annotations and in 12.1 % of reference strings, reflecting how infrequently DOIs appear in the source articles, particularly in Persian and Arabic publications. Book identifiers occur in 2.3 % of reference strings, and organisation in 12.5 %. Sixty-five reference strings (0.4 %) carry an unknown reference type, and 14 articles (2.2 %) have no reference annotations. The language distribution is unbalanced by design at the article level, with Persian articles making up 55.4 % of the corpus, and the distribution of reference strings differs again from the distribution of articles. The inter-annotator agreement study (Table 8) confirms that agreement is lower on composite fields such as venue_information and on sparse fields such as DOI and book identifiers; users who require these fields should treat them with caution.

Only the header and the reference section are annotated. Body text, section structure, figures, tables, equations and captions are not annotated, so the data do not support full-text structure recognition. Annotation was performed on open-access articles only, so paywalled publications, and any formatting conventions specific to them, are not represented. Persian publication years are recorded in the calendar used by the source article and are not normalised.
