ABSTRACT
The AEDR Fielding Interface Tool is required to configure, control, and extract data from the
Anomalous Environment Data Recorder (AEDR). This electronic circuit, housed in a 3D-Printed
case, connects via USB cable to a laptop computer. A custom, 15-pin cable connects to the AEDR.
Two barrel-connectors supply battery and external power to the AEDR. Because the AEDR
records up to one Gigabyte memory during its 213-second maximum record time, the Fielding
Interface includes a high-speed serial interface to extract data at a faster rate than it was recorded.

The design of the AEDR Fielding Interface Tool is described including details of the circuit board,
and steps presented to initialize a newly-assembled unit. Because key components have been
discontinued since the Fielding Interface was designed in 2015, the report concludes with an
approach to update the design with currently-available components.

EXECUTIVE SUMMARY
Extracting data efficiently from a large-capacity memory demands a high-speed interface tool.
Because the Anomalous Environment Data Recorder (AEDR) can contain up to one Gigabyte of
data, the AEDR design includes a high-speed, 150Mbps serial link. This data extraction link is
supported by the 3A7003-001 AEDR Fielding Interface tool, which uses a single USB connection to
incorporate a command and configuration link, the high-speed serial link, plus an additional serial
connection that collects diagnostic voltage and current data. A 3D-printed box that is about 1-in x
3-in x 4-in contains the electronics, as shown in Figure 1 below.

This report details the design and highlights the changes needed to replace the now-unavailable
components for a future design version. Because key components are no longer manufactured, the
Fielding Interface must be completely redesigned using currently-available chips. Once the
remaining stock of AEDR Fielding Interface Tool components is exhausted, no additional units can
be built and field operations may be impacted.

1. INTRODUCTION
The Anomalous Environment Data Recorder (AEDR) developed in 2015 was a huge step in the
volume of penetrator-type data collected. The AEDR samples 12 analog and 8 discrete channels at
250k samples per second each, capturing 5M Bytes of data per second. Total record time is 213
seconds maximum plus 75 milliseconds of pre-trigger data, meaning up to a Gigabyte of recorded
data needs extracted post-test. To practically extract this volume of data demands a high-speed
interface, so the AEDR included a high-speed serial interface implemented using the SerDes
protocol.

Support equipment developed to match the high-speed serial interface on the AEDR must be
capable of rapidly transferring data to a personal computer, typically a laptop used for field work.
The 3A7003-001 Fielding Interface uses a single USB 2.0 connection to implement the needed
interfaces. A USB composite device peripheral controller is capable of managing multiple device
functions simultaneously through a single physical connection. For the AEDR Fielding Interface
Tool, the functions are a 115.2k Baud bi-directional UART for command and response which
appears as a Virtual COM port, a 150Mbps SerDes receiver for data extraction, and an I2C bridge
for diagnostic voltage and current monitoring. The USB 2.0 interface operates at the High-Speed
mode, 480Mbps. A composite device implementing multiple serial interfaces requires multiple
endpoints. The Fielding Interface used an Infineon (formerly Cypress) High-Speed USB Peripheral
Controller controlled with Bitwise Systems QuickUSB firmware.

Using the high-speed SerDes interface, data extraction speed is about twice the speed that the
AEDR recorded. The AEDR records at 250,000 samples per second with each sample occupying
20 Bytes to capture the analog and discrete measurements. Twelve sample records are combined
with Reed-Solomon error checking and correcting bytes to form a “Glob” comprising 246 bytes.
Therefore, the AEDR fills Flash or FRAM at the rate of 5.125 x 10 6 bytes / second. Extraction
occurs at 150Mbps. The Serializer algorithm using 8b/10b encoding generates a 10-bit symbol for
each byte. The Low-Voltage Differential Signaling (LVDS) transmission protocol adds a start bit
and stop bit to each symbol. This means each byte recorded in the AEDR occupies 12 bits on
transmission, and the 150Mbps rate results in a theoretical maximum transfer rate of 12.5 x 10 6 bytes
/ second. In reality, the rate becomes lower because commands using the 115.2k Baud control
interface occur after transfer of 1024 Pages, each containing 4182 bytes for Flash (4096 bytes for
FRAM). Data transfer time for 1024 Pages is 343 milliseconds, followed by command of 7 bytes
and response from the AEDR of 3 bytes, totaling 10 bytes that take 0.87 milliseconds using the
115.2k Baud interface. (The UART protocol adds a start and stop bit per byte.) The total exchange
of SerDes plus command then occupies 344 milliseconds to transfer 1024 Pages, but transfers 836
milliseconds of recorded data. This also does not include possible retransmission of the 1024 Pages
if an error was detected.

Although SerDes is about a thousand times faster than low-speed serial while data are being moved,
this does not consider overhead for the command exchange. The number of Pages requested for
each transfer may need adjusted depending on data drop-out and subsequent retransmission.
Overhead would increase if fewer Pages were requested, for example 256 or 512 instead of the
default 1024 Pages, but this must be balanced with the number of retransmissions encountered
because smaller transfer sizes may be more efficient when frequent drop-outs occur.

 9

Functionality is mainly divided between the QuickUSB circuits providing the USB peripheral
controller and an Altera Max 10 FPGA that translates the 10-bit deserializer symbols into data bytes.
The QuickUSB implements the UART control serial interface, the high-speed SerDes link, and
captures I2C data from analog-to-digital converters that measure Vbat, Vcap, and Vext.

3. SERIALIZER / DESERIALIZER -- SERDES
Transmitting high-speed serial data relies on a Low-Voltage Differential Signaling (LVDS) physical
interface and a special 8b/10b symbol encoding scheme that improves data integrity. SerDes is a
portmanteau of the words SERializer and DESerializer. A SerDes converts parallel data to serial for
transmission, and back to parallel at the destination. Because high pin-count connectors are
vulnerable on penetrator recorders, the reduced pin count was an important concern. Further, the

 11

high shock environment precludes crystal-type precision oscillators for the frequency reference
needed for some types of high-speed serial data communication. The SerDes protocol uses clock
and data recovery circuitry to extract a stable clock signal directly from the incoming high-speed data
stream. The volume of circuitry and component count must also be limited for high-shock
electronics to improve reliability.

3.1. Implementation of the SerDes Interface
The Texas Instruments SN65LV1224B [1] is a 10-bit deserializer normally paired with the
SN65LV1023A serializer to transmit data over differential backplanes or unshielded twisted pair at
clock speeds from 10 MHz to 66 MHz. The serializer role is implemented in the FPGA as part of
the AEDR Digital board, followed by a differential LVDS transmitter, the SN65LVDS1DBVR.
Impedance is matched for 100-Ohm, the normal impedance for a twisted pair.

A 12.5MHz reference clock applied to the SN65LV1224BDB deserializer supports a 150Mbps
transfer rate. Each 8-bit byte from the AEDR is translated into a 10-bit symbol. When transmitted
by the AEDR, the SerDes bit stream includes a stop and stop bit for each symbol, so that an 8-bit
byte requires 12 bit-periods to transmit the corresponding symbol. Thus, without considering
handshake delays, the maximum transfer rate is 150Mbps / 12 = 12.5M bytes/second. The AEDR
captures 250k samples/second, with each sample using 20 bytes of memory plus 6 bytes ECC for
every 12 records, representing a storage rate of 5.125M bytes/second. This means if a continuous
SerDes transfer were possible, data could be extracted at about twice the speed it was collected.

 Figure 3. SerDes Timing Diagram from Texas Instruments SN65LV1023A
The 8b/10b encoding scheme finds application in a wide variety of high-speed serial interfaces, in
particular cameras, Serial Advanced Technology Attachment (SATA) storage devices, and Gigabit
Ethernet. The 8b/10b SerDes encoding converts 8-bit data into 10-bit symbols that ensure bit
sequences with the same number of '0' and '1' on average, effectively a direct current (DC) balance,
and sufficient transitions for clock recovery. As shown in Figure 4 below, symbol encoding splits
the 8-bit input represented as “HGFEDCBA” into a 5-bit group “EDCBA” for the lower bits and a
3-bit group “HGF” for the most-significant bits. Then, the two smaller groups use the 5b/6b
encoding to produce symbol “abcdei” and 3b/4b encoding to produce “fghj”. These two schemes
combine in reverse bit order to create the final 10-bit symbol, “abcdeifghj”. In order to achieve the
DC balance, some 8-bit values encode into two possible symbols, with the selected symbol chosen

 12

based on the Running Disparity (RD) to maintain a DC balance. If the RD is negative, meaning too
few 1s, the encoder selects the symbol with more 1s to increase the RD. Of the 1024 possible
symbols represented by 10 bits, 512 correspond to 8-bit values, one symbol 0b0000011111 – five
zeros followed by five ones – corresponds to Sync, and the rest are illegal combinations useful for
detecting transmission errors and set the “Invalid” flag.

3.2. Algorithm for 8b/10b Encoding
8B/10B Encoding [2] is a method to replace 8-bit original input data with a 10-bit symbol. This
encoding is implemented by combining two simpler encoding methods, 3B/4B and 5B/6B, as
illustrated below in Figure 4, taken from Reference [2].

 Figure 4. Explanation of 8b/10b Encoding Algorithm
Describing this in written form, the encoding process goes as follows:
i) Take the input data byte with the eight bits labeled: HGFEDCBA
ii) Split the input data byte into two blocks: HGF - EDCBA
iii) Swap the position of the two blocks and reorder bits: abcdei – fghj.

Decoding reverses this process, taking a 10-bit symbol and generating an 8-bit byte. Decoding can
be accomplished with combinatorial logic as was done for the AEDR Fielding Interface Tool, or a
memory-based Look-Up Table (LUT) that uses the 10-bit symbol as an address of the
corresponding 8-bit byte. Because programmable logic devices with the requisite logic element
capacity are packaged in 144-pin devices, a memory-based LUT could be more compact with regard
to board area. An 8k x 8 parallel EEPROM packaged in a 32-pin PLCC would be 0.49-in x 0.55-in,
compared with the Altera Max 10 FPGA 144-pin EPLC occupying 0.87-in square. This is 0.27 vs
0.76 square inches respectively, or 36% of the board area using EEPROM-based Look-Up Table.

4. FPGA IMPLEMENTING SERDES SYMBOL CONVERSION
The AEDR transmits the least significant bit of the 10-bit symbol first. The deserializer captures the
serial stream and presents a 10-bit symbol to an Altera MAX 10 FPGA for conversion into an 8-bit
byte. Schematic for the FPGA is shown in Figure 5. The Texas Instruments SN65LV1224B
Deserializer assumes the least-significant bit is transmitted first, and presents this on pin Rout0.
This connects to Data0 on Pin 88 of the Altera FPGA. The Verilog algorithm implemented in the

 13

FPGA uses combinatorial logic to translate the 10-bit symbol into an 8-bit byte. Using the
alternative look-up table with a 10-bit symbol representing 1024 possible addresses results in 512
valid bytes. This is double the expected 256, 8-bit values because two symbols code for the same
byte. Of the remaining 512 symbols, one represents Sync and the rest are invalid combinations used
to detect transmission errors.

 Figure 5. Altera MAX 10 FPGA Schematic

The FPGA also implements some additional “glue-logic” functions. To capture the 10-bit Sync
symbol 0b0000011111, AND / OR logic on symbol input datain[0:9] is ORed with the nLock signal
to generate output nSLWR, which is then presented to QuickUSB input RDY1. Buffering on the
nLock signal from the deserializer chip is captured in bit 15 of the 16-bit value presented to the
QuickUSB General-Purpose Input/Output (GPIO). This active-low signal indicates the deserializer
is locked and data are valid. Additional buffering on the nLock signal produces output “led2” which
drives red LED D10. Buffering is also used on the RCLK output from the deserializer chip to
produce signal “led” on Pin 140 which drives red LED D9, and “IFCLK” on Pin 102. The
captured symbol should be transferred on the edge of IFCLK, with either rising or falling selected
by deserializer input RCLK_R/nF. High level indicates Rising edge and low indicates Falling edge.
VCAPTHRESHOLD is buffered to become signal “led4” to indicate Vcap is above a threshold, and
drives blue LED D2. This was important on the 3AMP Classic interface, which had reverse-power
issues caused by the serial interface. Finally, signal Arm Indicate “armindicate” is buffered to

 14

become “ARM_LED” to show the AEDR is in Arm mode, recording pre-trigger data and ready to
detect a trigger signal level. This drives red LED D1. The Arm Indicate signal is also directly
applied to the QuickUSB.

The decoder function used an open-source Verilog implementation by Chuck Benz. [3] The Verilog
code is contained in Appendix B. This converts the 10-bit symbol into an 8-bit byte using a more
efficient algorithm than a simple Look-Up Table. Others have noted that this implementation might
cause a few false errors because of the way output “code_err” is calculated. [4] A minimalist logic
approach was taken, essentially using the FPGA the same way as a memory-based Look-Up Table
without Running Disparity tracking to check for errors. During compile using Quartus Prime Ver.
24.1, warnings indicate several signals are generated whose output is unused. In particular, the
“code_err” and “disp_err” signals are unused.

The FPGA design includes a 27-bit counter block, “divide.v” which was included in the design to
improve data capturing performance, but was never fully implemented and is unused. This means
the 50MHz clock oscillator is unnecessary because the clock only connects to the divider function,
and the “decode” block is entirely combinatorial logic without flip-flops that would require clocks.
The 27-bit counter is also implemented in Verilog code, and produces a zero output when the count
is less than 33554432 (hex 0x200 0000) and a one output when above that value. The counter rolls
over to zero. With the 50MHz input clock, this creates a pulse with a 2.68 second period that is low
for 671ms and high for 2 seconds.

5. HIGH-SPEED USB PERIPHERAL CONTROLLER
The AE Field (3A7003-001) interface box uses a single USB 2.0 connection to a laptop that is then
converted to AEDR interfaces for the 115.2k Baud serial command interface and the 150Mbps
SerDes output for rapid data extraction. In addition to these two, the single USB link also captures
I2C device data to monitor voltages and currents supplied to the connected AEDR. Using multiple
endpoints in a USB device allows a single physical connection (one cable and USB port) to handle
multiple, distinct communication channels simultaneously. While every USB device must have a
default control endpoint (Endpoint 0) for configuration, complex devices define additional
endpoints to separate different types of data. A device using multiple endpoints is a "Composite
Device".

USB Endpoints are logical, buffered, and addressable data sources or destinations on a USB
peripheral, and can be considered separate communication pipes between the USB host computer
and the peripheral. The peripheral device in this case is the AEDR.
  Direction: Endpoints are designated as either IN (device to host) or OUT (host to device).
  Capacity: A single device can have up to 32 endpoints (16 In and 16 Out).
  Addressing: Each endpoint is identified by a number and a direction.

Endpoints are configured for specific transfer methods:
  Control: For setup commands (Endpoint 0).
  Interrupt: For small, low-latency data – the AEDR 115.2k Baud interface.
  Bulk: For large, error-checked data – the 150Mbps SerDes.
  Isochronous: For real-time, streaming data where timing is more important than missed
 data, for example audio or video. This is not appropriate for the SerDes link because all data
 must be captured.

 15

For the AEDR Fielding Interface Tool, the Interrupt endpoint type supports the 115.2k Baud
UART for AEDR commands, and the Bulk endpoint handles the high-speed SerDes for rapid data
extraction. The I2C link and discrete signal input and output also are implemented as an Interrupt
endpoint.

The USB 2.0 composite device was implemented with an Infineon (formerly Cypress)
CY7C68013A-128AXC High-Speed USB Peripheral Controller with Bitwise Systems QuickUSB
firmware in a 24LC128T EEPROM. The CY7C68013A USB controller is the FX2LP version and
has an 8051-microprocessor core. The CY7C68013A is obsolete as of 2025 and is discontinued by
the manufacturer, Infineon. The recommended replacement is the CYUSB2316-BF104AXI, which
was released in 2025. Changes in this FX2G3 version include a dual Arm Cortex core. Note that
using the replacement requires a complete redesign of the Fielding Interface because the
replacement part differs substantially.

A USB composite device peripheral controller operating at 480Mbps generally refers to USB 2.0
(Hi-Speed) technology, which supports this maximum data transfer rate. While 8b/10b encoding is
commonly used in higher-speed serial links like Fiber Channel, USB 2.0 uses NRZI encoding,
whereas USB 3.0 (which can be used for high-speed peripheral mapping) uses 8b/10b or 128b/132b
encoding.

The UART portion of the composite device appears as a virtual COM port. A 115.2k Baud serial
link allows configuring the AEDR and could permit slow extraction of data. When using the
SerDes high-speed data extraction link, the UART sends commands to the AEDR to initiate a
transfer, and then after transfer of each data block, sends commands to proceed or retransmit
depending whether an error was detected.

After the 150Mbps SerDes stream is deserialized from an 8b/10b transmission and the 10-bit
symbols converted to 8-bit bytes in the Altera FPGA, the data are presented to the QuickUSB on a
16-bit GPIO bus. The lower 8 bits contain the data byte, Bit 15 captures the nLock signal indicating
that the SerDes link is locked and data are valid, and Bits 9 through 14 are tied to zero in the FPGA.
Detection of Sync is on signal nSLWR from the FPGA, which connects to signal RDY1 on Pin 5 of
the QuickUSB. Signal RDY0 is tied to Vcc through a 4.99k resistor.

The AEDR Fielding Interface also acquires analog voltage and current measurements on the power
supplied to a connected AEDR. These are captured using DS2745 battery monitor chips over an
I2C interface connected to QuickUSB, which also generates control signals to power each of the
three DS2745 chips. The I2C interface reads voltages and currents for Vbat and Vext, and voltage-
only for Vcap. Acquiring data uses routines QuickUsbWriteI2C() and QuickUsbReadI2C().

During power-up initialization, addresses are configured in each DS2745 device from the default
address 0x48 as follows:
  0x4A – Vbat, powered via Port E bit PE0
  0x4B – Vext, powered via Port E bit PE1
  0x4C – Vcap, powered via Port E bit PE2

The QuickUSB generates the “Power_On” signal to command the AEDR to turn on power and
latch it on. This is in parallel with push-button SW4 which can be pressed manually for the same

 16

function. QuickUSB monitors discrete control signals generated by the AEDR, including
“XMIT_EN” intended to enable a TX multiplexer when multiple AEDR modules are in parallel,
Arm_Indicate asserted when the AEDR is armed, Latch_Pwr showing a Power_On signal was
captured, Heart_Beat which is a 1-Hz signal showing proof-of-life, and finally Trig/Fidu which is
asserted when an armed recorder detects a trigger condition.

6. CONFIGURING THE QUICKUSB PERIPHERAL CONTROLLER
The QuickUSB firmware is contained in U17, a Microchip 24LC128T-I/ST 16k-byte EEPROM that
comes pre-programmed from Bitwise Systems. However, additional configuration is needed for the
Fielding Interface. Customization of the QuickUSB defines how the GPIO busses will be used and
which serial interfaces are implemented. Figure 6 below shows the changes needed for the AEDR
Fielding Interface Tool. Definitions of the configuration bits are listed in the QuickUSB User
Guide, “QuickUSB Settings”.

Note: The Write Protect pull-up resistor R63 must be removed before the configuration
step. This enables changes to be permanently stored in the EEPROM.

6.1. Definition of Indicators and QuickUSB Ports
Three LED indicators connected to the QuickUSB show status during data transfers. Orange LED
D12 connects to Pin CTL0 and illuminates when the CMD_DATA line is high meaning a
Command Transfer. Red LED D13 on Pin CTL1 indicates REN is active, meaning a Read
Transfer. Finally, green LED D14 on Pin CTL2 indicates WEN is active and a Write Transfer is
occurring.

The QuickUSB is configurable to assign Ports A through E for specific functions. For the AEDR
Fielding Interface Tool, the functionality assigned to each port is as follows:
  PortA is unused with PA2,5=3.3V, PA4,7=Gnd, and PA0, 1, 3, 6 not connected.
  PortB has the lower byte of data bus FD[0:15], the data byte from SerDes
  PortC drives LEDs on PC[0:3]
  PortD has the upper byte of data bus FD[0:15], flag in FD15 if SerDes clock locked
  PortE, power for I2C monitor chips, PE[0:2] VbatI, VextI, VcapV. Other control discrete
 signals are on PE[3:7]

A few additional functionality assignments are as follows:
  Rx/Tx0 serves the Command/Response interface for AEDR control
  Rx/Tx1 Feature for 3AMP to address the battery control board
  I2C is used for the QuickUSB EEPROM and for the DS2745 monitor devices

8.1. Schematic Block POWER
Power for the Fielding Interface circuitry is derived from 5V USB power, which is signal VBUS_5V.
A switch-mode power converter module Enpirion EP5388QI [5] [6] steps the 5V down to 3.3V for
all the digital circuits as shown in Figure 9. The Enpirion EP5388QI has been discontinued by Intel
and is no longer available. The MCP130 Supervisory Circuit generates a 350ms Reset signal, active
low, signal “RESET”, which connects to QuickUSB Reset. The MIC2004 Power Distribution
Switch was intended to provide additional current limiting during the initial USB 2.0 connection.
USB devices must initially default to a low-power load below 100 mA, and then negotiate with the
host to draw up to the full 500mA. Since steady-state current draw from the 5V USB power for AE
Field is about 120mA, performance may be marginal without enabling the current limit function.

The QuickUSB uses the +3VD power, while everything else including the Altera FPGA is powered
from the current-limited +3.3V power. The “SW_EN” input signal on the MIC2004 is connected
to QuickUSB Pin 34, named “BKPT”. But the signal is tied to 3.3V through a 0-Ohm resistor so
effectively locks the MIC2004 enabled regardless. The QuickUSB datasheet states this output signal
is used as SW_EN on the QuickUSB module to control the onboard VBUS switch. SW_EN is high
when the QuickUSB Module has successfully enumerated and power can be drawn from VBUS.
The intent was to allow the USB interface to enumerate before powering the rest of the circuit
board, but with both R92 and R93 installed this cannot occur, and since pin BKPT is an output, the
connection may cause higher current draw. A revised AEDR Fielding Interface Tool design would

 21

replace the EP5388QI power converter, and enable the MIC2004 power distribution switch to
ensure less than 100mA load before USB enumeration.

8.2. Schematic Block USB
The USB block in Figure 10 contains U16, the QuickUSB implemented using the Infineon (formerly
Cypress) CY7C68013A-128AXC [7] High-Speed USB Peripheral Controller with the firmware
contained in serial EEPROM U17, a 24LC128T-I/ST. This EEPROM from Microchip is a 16k-
Byte device with I2C interface and assigned address 0. The circuit board includes 0-Ohm resistor
R63 that pulls the Write Protect line high, preventing inadvertent writes to the device. Note that
resistor R63 must be removed for initial interface configuration. A more effective design
choice would use a 5k pull-up resistor to 3.3V and a jumper to ground Write Protect when
configuring.

The QuickUSB primary purpose is the UART and SerDes interfaces, but also data monitor from
measured voltages and currents. Frequency reference is an ECS International ECS-3953M-240-BN-
TR crystal oscillator, which is 24.0MHz.

The QuickUSB power is +3VD, which is output from the EP5388QI buck converter. The output
voltage select lines VS0-VS2 are all pulled low, which produces 3.3V. This output then supplies a
Microchip MIC2004-0.8YM5-TR P-Channel Power Switch current-limiting switch with an 800mA
current limit. The current limit switch output is labeled +3.3V. SW_EN is driven by the QuickUSB
and could enable the MIC2004-0.8YM5 current-limiting switch, except the design shows 0-Ohm
resistors R92 and R93 in place shorting SW_EN to +3VD. If R92 was not installed, the QuickUSB
would enable application of 3.3V to the Altera Max10 FPGA following an active-low Reset period
created by the Microchip MCP130T-315I/TT Microcontroller Supervisory Circuit. This device
holds Reset low for 350ms typically after the power converter output voltage +3VD reaches 3.075V
nominally (ranges from 3.0V to 3.15V).

8.3. Schematic Block MAX10
The Altera Max10 FPGA primarily handles the 8b/10b decode function from 10-bit symbols to 8-
bit values. The only other use is minor glue logic to select between AEDR and 3AMP interface
modes, and to drive indicator LEDs for Arm_Indicate and capattery voltage above threshold. The
Altera Max10 programming interface is a 10-pin header with JTAG signals. Figure 11 shows the
FPGA and programming connector.

The Altera Max 10 design was based on a Max 10M08 FPGA Evaluation Kit [8], October 2014
version. The Max 10 10M08 used in the design has 8000 logic elements, but only 719 logic elements
were needed to implement the decode function and the glue logic. The 50MHz clock oscillator X1,
a CTS-Frequency Controls CB3LV-3C-50M crystal oscillator with HCMOS TTL output, is only
used by the 27-bit counter, and outputs from that counter are not used. Therefore, Oscillator X1 is
unnecessary.

The output from the Texas Instruments SerDes deserializer chip is Data[0:9] which is input to the
FPGA’s 8b/10b decoder. The Max10 produces outputs on data bus FD[0:15], which includes the
outputs from the 8b/10b decoder in the lower byte. FD15 is buffered in the FPGA to connect to
nLock. Other signals from the deserializer include Rclk, IFclk, nSLWR, nLock.

8.5. Diagnostic Signal Conditioning Schematic Block SIG_CONDITION
Diagnostic measurements of power supplied through the Fielding Interface and the AEDR’s
capattery voltage are accomplished in the SIG_CONDITION schematic block shown in Figure 13.
ADC devices DS2745 uMAX monitor current on the return side of Vbat and Vext, and the
associated voltages. The DS2745 was designed for inclusion in battery packs. With a 50m-Ohm
sense resistor, current sense range is +/- 11.3A. Through its two-wire I2C interface, the DS2745
allows a host system read/write access to the Status, Configuration, and Measurement registers.
Additionally, the I2C slave address can be changed from the default after power up, and must be for
the Fielding Interface design. The programmable output PIO on Pin 3 was not used.

Each DS2745 device is powered in succession from the QuickUSB PE[0:7] output pins: PE0 maps
to VbatI, PE1 to VextI, PE2 to VcapV. Power supply current for the DS2745 is less than 100uA,
and the ADC uses an internal reference voltage so is not ratiometric based on the supply voltage.
Each DS2745 device is powered and its slave address programed in sequence from the default
address 1001000b. The lower 3 bits can be modified using the I2C.

Note that the design should have reused the Vcap_Monitor signal generated for the threshold
measurement for the Vcap voltage measurement.

9. RECOMMENDED CHANGES FOR NEW DESIGN
Because the QuickUSB device is no longer available (obsolete as of 2025), the AEDR Fielding
Interface Tool must be completely redesigned using currently-available chips. Options for the High-
Speed USB 2.0 include the Infineon EZ-USB Series FX2G3 that was released January 2026. The
redesign could begin by using the FX2G3 Development Kit KIT_FX2G3_104LGA. The 8b/10b
decode function was formerly implemented using an FPGA from Altera (now Intel)
10M08SAE144C8GES, but this device is also obsolete and discontinued. A replacement could be
the Altera 5M1270ZT144C5N which is available in a 144-TQFP package and has 1270 logic
elements. The old design used fewer than 10% of the 10M08SAE144C8GES device capacity.

 28

Although only 29 input/output pins are needed to implement the 8b/10b decoder function, about
800 logic elements are required and devices with this logic capacity have higher number of pins. A
better alternative to 8b/10b symbol decoding may be using an EEPROM Look-Up Table with an 8k
x 8 parallel-address, like the Microchip AT28BV64B which is packaged in a 32-lead PLCC. If the
Look-Up Table approach were used, some limited glue logic would need still to be implemented in
discrete logic to detect the Sync word.

Monitoring certain currents and voltages provides state-of-health data for the AEDR. The original
Fielding Interface design included battery monitor ICs that measured both the supplied voltage and
current drawn on the Vbat and Vext supplies. One of the devices also monitored capattery voltage
Vcap, another critical state-of-health measurement. The device used, an Analog Devices DS2745U,
was discontinued November, 2013 and although it is still available in 2026 the manufacturer
recommends it is not used in new designs. The recommended replacement is the MAX17055 but
this device could not function with three devices on a single I2C bus like the DS2745U.
Replacement of the function will require a different approach with current and voltage measurement
digitization possibly carried out in separate devices.

Power conversion from the 5-V USB supply to the logic 3.3V is best accomplished with a switch-
mode power converter. The module used in AE Field, the Enpirion EP5388QI [6], is discontinued
but many similar modules are available. The AE Field power draw from the 5-V USB was about
120mA and should be similar for the updated design.

Note that when redesigning the AEDR Fielding Interface Tool, creating a version to replace the
Comms Box would have advantages. The J68671-002 Communication Box supplies power and
control signals for up to three AEDR units installed on a test article, and is flown with the recorders.
The redesigned AE Field would form the core of a new Comms Box.

10. CONCLUSIONS
Because the Anomalous Environment Data Recorder (AEDR) contained such a large amount of
memory, efficient data extraction required development of a new high-speed interface tool – the
3A7003-001 AEDR Fielding Interface Tool. The single USB connection incorporates 1) a
command and configuration link, 2) the high-speed 150Mbps serial link, plus 3) an additional serial
connection that collects diagnostic voltage and current data. The circuit board is contained in a 1-in
x 3-in x 4-in 3D-printed box.

The specialized USB peripheral controller, the QuickUSB, implements the UART control serial
interface, the high-speed SerDes link, and captures I2C data from analog-to-digital converters that
measure Vbat, Vcap, and Vext. The 150Mbps SerDes (Serializer / Deserializer) link sends data
using the 8b/10b protocol that can detect and correct some errors in the serialized data. When the
serial stream is received by the Texas Instruments SN65LV1224B Deserializer, the 10-bit symbol
must be interpreted to derive the 8-bit value represented. The design uses an Altera MAX 10 FPGA
to implement conversion logic and handle some additional glue-logic functions.

The QuickUSB controller is obsolete and no longer available, so building additional units of the
AEDR Fielding Interface Tool will require a redesign effort. The report details the design and
highlights the changes needed to replace the now-unavailable components for a future design
version.
