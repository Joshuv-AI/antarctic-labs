 RAG for FLAG: AI Assistance for a Physics Code
 Rayannon Velarde (NMSU)(XCP-8), Rosalyn Rael (XCP-8), Emily Casleton (CCS-6)

Abstract
Artificial intelligence (AI) has quickly become an important tool in scientific research, where
significant efforts are underway to develop tools that will expedite the research process. One
area of particular impact is scientific software, which can be particularly complex, and therefore
time consuming to learn and use effectively. AI assistants are increasingly helping to streamline
the process by performing tasks such as interactively answering user questions or suggesting
solutions. Los Alamos National Laboratory (LANL) develops several advanced scientific codes,
such as FLAG, which can be used to run multiphysics simulations. With this study, our goal was
to develop an AI assistant for FLAG that could help make the process of understanding the
software and running physics simulations more efficient.

To develop an AI assistant for FLAG, we used a method called retrieval-augmented generation
(RAG), which is a technique that uses information from relevant data sources to enhance the
accuracy of large language models (LLMs). We used the FLAG user manual and other FLAG
documentation as the knowledge base for the RAG system. When a user provides a query,
RAG retrieves relevant sections from the knowledge base in response, then uses those
excerpts to generate grounded and contextually rich answers. We found that our AI assistant
was able to provide context aware answers and source references to user queries. To evaluate
performance, we developed a set of 40 benchmark questions and compared the accuracy of the
responses to those of two standard LLMs without retrieval. Our AI assistant significantly
outperformed the standard LLMs at answering FLAG-related questions, with an 82.5% accuracy
rate, compared to 47.5% for both of the standard LLMs. This has the potential to make the
process of learning and using FLAG much easier, especially for new users. Ultimately, it
supports LANL’s broader mission by empowering scientists and engineers to focus more on
discovery and analysis rather than on navigating complex software systems.

Introduction
 Artificial intelligence (AI) is the ability for machines to imitate the way humans think and
perform tasks. AI is rapidly expanding into many areas of communication and scientific
research. It is important that we understand the risks of this powerful new tool, while also
leveraging it to expedite the process of scientific research. AI can lead to ethical issues, privacy
concerns, security risks, job displacement, and more. Recognizing and addressing these risks is
essential so that we can use AI to our benefit and stay ahead of any potential concerns.so that
we can use AI to our benefit and stay ahead of any potential concerns. The goal of my project is
to help with the testing and evaluation of large language models (LLMs) in order to investigate
the process of using them to make the use of Los Alamos National Laboratory (LANL) codes
more efficient and to identify any risks involved. This will ultimately help with the development of
AI capabilities, which will benefit missions of LANL.
 Large language models are models trained on large amounts of text data, enabling them
to generate human-like text, answer questions, and complete other language-related tasks with
high accuracy [1]. There has recently been a great deal of research going into developing large

language models and improving their efficacy and trustworthiness. Significant efforts have been
made to examine LLMs from various perspectives, including uses in medical and educational
applications and more [2][3][4]. Due to their unprecedented performance in various applications,
LLMs are gaining increasing popularity in academia and industry, and they play a vital role in
research and daily use [5]. Their ability to learn from extremely large datasets and their large
amounts of parameters allow LLMs to perform well in various tasks. Recently, there have been
remarkable capabilities of LLMs developed for code generation [6]. For example, LLMs are
being trained to generate code based on natural language descriptions, fill incomplete code
segments, and repair buggy code [7]. Several LLMs and the tools powered by them have
gained widespread use, such as Github Copilot for coding, and ChatGPT, and Google Gemini
for information retrieval, summarization, creative tasks, and more.
 Los Alamos National Laboratory has multi-physics codes used to study a variety of
complex physics problems. FLAG is one such LANL code that can be used to run multi-physics
simulations. Like with any big code, it takes time to come up to speed and understand all the
aspects, such as the syntax, structure, etc., of input decks. An input deck is a file that contains
the parameters required to run the simulations [8]. One type of experiment of interest that many
scientists have used to learn about how materials subjected to high strain rate environments
behave is the flyer plate experiment [9]. An input deck for a flyer plate experiment will contain
information about the physics models used for material properties such as strength. Building an
input deck for an experiment requires time and expertise, though there are some common
conventions. With this project, we are working toward building a tool that could greatly reduce
the time it takes to go from taking experimental data to simulating that experiment with a LANL
code.
 Working toward making this process more efficient, I helped develop an AI tool for
running FLAG. It is able to answer user questions and provide context-aware assistance. With
further development, it will also be able to provide code assistance and debugging support.
Initial testing showed that the assistant significantly outperformed standard LLMs on benchmark
tasks, demonstrating high accuracy and relevance in responses grounded in FLAG
documentation. These results highlight the tool’s potential to enhance scientific productivity and
streamline the use of LANL simulation codes.

Methods
 To develop an AI assistance tool for FLAG, we used a method called
retrieval-augmented generation (RAG). RAG is the process of optimizing the output of a large
language model, so it references an authoritative knowledge base outside of its training data
sources before generating a response [12].
 To set up the RAG process, we used the FLAG User’s Manual [13] and other similar
documentation as the external knowledge base. The other documents included an overview, a
quick-start guide, and an example experiment. After collecting these documents, we first
extracted the text from the PDF documents and cleaned the text. Next, we split the text into
smaller chunks. For the manual, text was first split into manual sections, and further by
characters. The other documents were also split by characters. Splitting was done using
RecursiveCharacterTextSplitter, a tool in the LangChain LLM development framework [14].

 After chunking the text, we embedded the chunks using the embedding
modelnomic-embed-text [15]. This converted the text into high-dimensional vectors suitable for
similarity search. We then indexed these embeddings to enable efficient retrieval, using the
vector database FAISS [16]. With the vector embeddings indexed in FAISS, we constructed a
retrieval pipeline that could identify the most relevant document chunks based on a user’s
query. When a user input is received, it is first embedded using the same nomic-embed-text
embedding model to produce a query vector. This vector is then used to perform a similarity
search against the FAISS index, returning the top k most relevant chunks. These chunks serve
as contextual information for the language model.
 After retrieval, the selected document chunks are passed along with the user query to
the large language model, Meta Llama 3 8B [17]. This model is responsible for generating the
final response. The inclusion of retrieved, authoritative content ensures the response is
grounded in the FLAG documentation, improving both relevance and accuracy.

Results
​ After the RAG pipeline was constructed, we created a simple user interface for testing
and demonstration (Figure 1). Our AI assistant was able to successfully retrieve relevant content
from the knowledge base and generate context-aware and accurate responses to user queries.
It was also able to provide source references for each of the chunks it retrieved as context.

Figure 2. User interface for our RAG+Llama model with an example query and response.

 We evaluated the assistant by comparing its answers against those of standard LLMs
without retrieval, including Meta Llama 3 8B and Mistral 7B. We came up with a set of 40
benchmark questions with which to test the RAG pipeline and the LLMs . These questions
required different levels of reasoning, summarization, and fact retrieval. They included 20
true/false, 10 multiple choice, and 10 short answer questions.
 We found that the RAG-based assistant demonstrated 82.5% accuracy across these
benchmark questions. This was significantly better than the performance of the standard LLMs,
which both demonstrated 47.5% accuracy (Figure 2). Specifically, the RAG assistant correctly
answered 80% of the true/false questions, 100% of the multiple choice questions, and 70% of
the short answer questions. In contrast, the baseline models showed strong reliance on
guessable formats. Mistral 7B correctly answered 70% of the true/false questions and 40% of
the multiple choice questions, while Llama 3 correctly answered 65% of the true/false questions
and 50% of the multiple choice questions. Both baseline models only answered 10% of the
short answer questions correctly, demonstrating limited capability in generating detailed,
grounded explanations.

Discussion
​ The results of this project demonstrate that retrieval-augmented generation can
substantially enhance the performance of large language models in domain-specific
applications, such as aiding with FLAG at LANL by answering user questions. While
general-purpose LLMs struggled with precision and domain alignment, the RAG-enhanced tool
provided reliable, explainable outputs grounded in verified documentation. This approach has
several advantages, such as improved accuracy and greater efficiency. A tool such as this one
has the potential to make the process of learning FLAG much easier, enhancing productivity
and reducing onboarding time. This ultimately supports LANL’s broader missions by

empowering scientists and engineers to spend more time on discovery and analysis and
reducing the complexity of navigating software systems.
 It is important to acknowledge that FLAG already has extensive online documentation,
as well as numerous examples and tutorials available to users. These resources serve as
valuable references for new and experienced users alike. However, due to the breadth and
technical depth of the content, navigating this material can still be time-consuming and
challenging. The AI assistant complements these resources by making it easier to access and
understand relevant information through natural language queries, acting as a dynamic interface
to an otherwise static body of knowledge.
​ The success of the assistant and LLMs were evaluated based on benchmark questions.
The benchmark questions offered different insights into the tool’s performance. The questions
primarily tested the assistant’s ability to accurately retrieve and interpret factual information from
the FLAG documentation. However, it is important to note that the accuracy of the results for
these questions may not fully reflect the understanding of each model. True/false questions
inherently carry a 50% chance of correctly guessing, meaning that a correct answer could be
produced even if the model’s reasoning is flawed or entirely absent. In several cases, the
models selected the correct answer but gave an incorrect or irrelevant explanation, which would
be misleading in real-world use. This is also true for multiple choice questions, though the
likelihood of guessing the correct answer is lower than true/false questions. In contrast,
short-answer questions offered a clearer window into the assistant’s true capabilities, as they
required coherent synthesis and grounded explanations. While the benchmark scores provide a
useful performance metric, they should be interpreted with an understanding of the limitations of
these question types in assessing true comprehension and reliability.
​ While progress was made toward the goal of building an AI assistant for FLAG, there is
still much that can be done to enhance its capabilities. With continued development of this tool,
we could expand its knowledge base, improve its handling of complex or ambiguous queries,
and add more features. With further work, our focus would be on enabling the tool to assist with
building full simulation input decks. We would also enhance the assistant to provide code
suggestions and debugging support. Eventually, we would develop a more user-friendly
interface to improve accessibility. Ultimately, the goal would be to deploy the assistant to real
FLAG users, so it can support complex simulation workflows and reduce onboarding time. To
maximize its impact across the lab, we would ideally generalize the framework to support other
LANL simulation tools.
