1. INTRODUCTION
In this addendum report we take the lessons learned from our initial generic object pose estimation
research described in (Smartt, et al., 2025)1 and apply it to metal cup seals, which are attached to
items after an international nuclear safeguards inspection (i.e., metal cup seals may be attached to
containers of spent nuclear fuel after an inspector has measured and verified the material). We have
also refined our software pipeline and training techniques since the final Inspecta report and will
describe that process here. The objective of this task is to allow a robot to acquire images of the
engraved seal characters to confirm that the correct seal is attached to the correct container.
However, the seal may be attached in any orientation and therefore the robot manipulator arm with
a camera needs to align with the normal face of the seal.

4. RUN MULTI-VIEW STEREO AND PLACE AXES

4.1. CAD Generation
Given the images and their position and orientation of capture, a crude CAD file can be generated
using multi-view stereo (MVS)4. We use the COLMAP GUI or the following commands:
 1. Undistort images
 colmap image_undistorter \
 --image_path images \
 --input_path colmap/sparse/0 \
 --output_path dense \
 --output_type COLMAP

 2. Multi-view stereo (PatchMatchStereo)
 colmap patch_match_stereo \
 --workspace_path dense \
 --workspace_format COLMAP \
 --PatchMatchStereo.geom_consistency true

 3. Fuse depth maps into dense point cloud
 colmap stereo_fusion \
 --workspace_path dense \
 --workspace_format COLMAP \
 --input_type geometric \
 --output_path dense/fused.ply

 4. Poisson meshing
 colmap poisson_mesher \
 --input_ path dense/fused.ply \
 --output_path dense/mesh.ply

The CAD file is shown in Figure 3. The image on the left shows the raw CAD file generated by the
MVS process. The image on the right shows a trimmed version, performed in MeshLab5. Notice the
overall structure is sound but the visual quality of the CAD file is too low to be directly used for
pose estimation.

5. SAM2 SEGMENTATION
In this section we use the foundational Segment Anything Model 2 (SAM2)6 from Meta to segment
out the object from its background. SAM2 typically requires a mouse click from the user to identify
the object of interest. We use the object center identified in the previous step to automate this
process. We need some background texture for the downstream steps in the pipeline, so we don’t do
a pure background elimination. Rather, we set the red channel of the background to one-fourth its
original value, while maxing out the green and blue channels. The results are shown in Figure 6 for
select images.

 Figure 6: Labeled and segmented photos captured by camera and processed with SAM2.

After SAM2, we also use a basic OpenCV style segmentation to further clean up any small
segmentation artifacts. This is accomplished with the cv2.floodFill function seeded with the center
pixel of the object.

6. NERF TRAINING AND DATASET INTERPOLATION

6.1. Neural Radiance Fields
We now have a dataset of 308 segmented photos, which are labeled with their position and
orientation relative to the metal cup seal. However, this is far too few images to train a deep
learning-based pose regressor, so we need a way to densely interpolate this dataset. We achieve this
through Neural Radiance Fields (NERFs). NERFs are a recent innovation that store the ability to
render novel views of a scene in the weights of a neural network. They are trained using a labeled set
of photos such as ours. Once trained they can be queried from any position and orientation within
the scene (assuming it is well captured by the inputs), and a novel view of the scene will be rendered
from that perspective.
Figure 7 shows two views rendered from the NERF. The image on the left shows a perspective
from outside the volume of the dataset, with visual artifacts in the background. The image on the
right shows a perspective better supported by the dataset, which therefore has fewer undesirable
artifacts. Both images show camera frames that were used to train the NERF, though these will not
be a part of NERF renderings used downstream. Both images are included to make it clear that
these are synthetic images, not images captured with a physical camera. The visual quality of NERF
renderings can make it hard to tell the difference.

 Figure 7: Two synthetic NERF rendered views of the metal cup seal.

6.2. Dataset Generation
Using the NERF, we systematically render views where the position and orientation of the seal are
randomized within the frame. We isolate the background by grabbing pixels with a green value
above 128, a blue value above 128, and a red value below 128, on a pixel scale from 0 to 255. This
corresponds to the masking protocol on our NERF input dataset with a significant margin applied.
We repeat our origin seeded OpenCV – cv2.floodFill command to clean up rendering artifacts. We
also dilate the background by one pixel to trim cyan colored border artifacts. Lastly, we replace the
background with random images from the well-known COCO7 dataset. The first sixteen samples

7. POSE ESTIMATOR TRAINING

7.1. Pose Representation
Based on previous experiments, we’ve discovered that YOLO8 based bounding box methods tend
to train faster and with better validation set generalization compared to center xyz prediction. Based
on that observation we train bounding boxes rather than xyz, and sacrifice depth at this stage.
Additionally, our object is symmetric about the z axis, so we take a point at the origin and a point a
few centimeters down the z axis and make the vector between them our attitude representation. We
convert this to pixel space and plot it in the middle of the bounding box. This representation
sacrifices the absolute attitude of the object but retains the relative direction and magnitude of the
attitude of the metal cup seal. This is a perfectly suitable position-attitude representation for a
downstream PID controller9 used in the robotic arm.

7.2. Network Architecture
Our network first uses a pre-trained ConvNeXt10 model to extract features from the image at four
different levels, then resize them so they all line up and stacks them together into one big feature
map. This Feature Pyramid Network is inspired by YOLO. Late-stage features provide semantic
information while early-stage features provide precise geometric information. We also concatenate a
simple xy coordinate grid to retain a sense of position in the model. Our YOLO head passes a 3-
layer 1D convolutional block over this multi scale feature map, with each location making a
prediction of the bounding boxes size and location. We then take the average. A second attitude
head zooms in on just that predicted region to estimate the object’s attitude vector in pixel space.
This is called Region of Interest (ROI) Pooling, and it improved validation set generalization in our
experiments. We do global average pooling within the region of interest, meaning we take the spatial
average of final stage features to produce a single feature vector describing the semantics inside the
bounding box. Then we pass that to a simple three-layer linear network which outputs the attitude
vector. In short, it’s a two-stage system: finding the bounding box, then using features inside that
box to compute orientation.

8. CONCLUSIONS
We leverage COLMAP, NERFs, and modern neural network training techniques to create a pipeline
that can quickly train a pose estimator for novel objects – metal cup seals in this case. The objects
don’t need a CAD file, large features, or interesting geometry. Our method works with RGB data
alone, does not require depth, and does not require an Internet connection. While somewhat
complex to train, all but one step of our method can be automated, and the result is a very short
Python file and set of network weights, which is remarkably easy to deploy across platforms,
especially compared to competitor algorithms. The next step for this project would be integration on
a robot for use in physical manipulation of the metal cup seal.
