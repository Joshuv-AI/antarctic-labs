 A Simulator for Neyer Tests of Explosives
 David H. Collins, Michael S. Hamada
 Statistical Sciences Group, Los Alamos National Laboratory

Abstract Explosives and explosive devices such as detonators are typically tested
by applying a range of stimuli such as voltage or mechanical shock, and recording
binary “detonated/did not detonate” responses. These are analyzed using max-
imum likelihood or generalized linear models to provide estimates of quantities
such as the all-fire and no-fire points. Given that the true threshold for detonation
is unknown a priori, sequential design methods are typically used to optimize the
set of test points. One popular method, implemented in commercial software, is
Neyer’s algorithm. To support simulation and experimental design, we have de-
veloped code in the R programming language [8] to duplicate the functions of the
Neyer software. We provide code for the simulator along with a description and
examples of usage.

1 Explosives sensitivity testing
Sensitivity testing data for explosives consists of paired stimulus values xi (e.g.,
voltage or mechanical shock) and binary responses yi ∈ {0, 1} (did not or did
detonate, respectively). Interest lies in parameters of the distribution of response
thresholds in the subject population, such as location and scale parameters, and
quantiles of the distribution. The testing can be directed towards evaluation of
safety (is the threshold high enough to provide a margin over likely accidental
stimuli?) or reliability (does the threshold provide margin over a specified mini-
mum, and can it be estimated with precision?).
 Since the true threshold for detonation is unknown a priori, and tests are often
quite expensive, it is desirable to achieve good statistical properties (e.g., minimum
variance) with a small number of tests. Choosing the design points (stimulus levels)
for an experiment is commonly done using one of several sequential methods such
as the Bruceton or “up and down” method [3] or Langlie’s method [5]. Sequential
methods are feasible when the response to a stimulus is immediate, as in explosives
testing; in other sensitivity applications, such as toxicology, the complete design
may need to be defined prior to testing.

 1

 The general idea in all sequential methods is to use an initial stimulus level,
usually a guessed mean; in the case of a positive (“detonated”) response, test next at
a reduced level, otherwise at an increased level. Changes in level are usually based
on a guessed standard deviation. This tends to concentrate test levels near the mean;
efficiency of the method depends on how the new test levels are chosen. Both the
Bruceton and Langlie methods are designed to allow simple manual calculation of
new test levels.
 A more efficient algorithm developed by Neyer [6] generates an approximately
D-optimal design, which aims to minimize the variance of parameter estimates.
Neyer markets a proprietary software package, SentestTM [7], to select test levels
(it would not be possible to calculate them manually), and analyze the data using
maximum likelihood when testing is complete. For a general review and compari-
son of this and alternatives, see [4]. Sentest is widely used by the U.S. Department
of Defense and Department of Energy.

2 The Neyer algorithm
D-optimal designs maximize the determinant of the Fisher information matrix for
a specified model. This minimizes the volume of the confidence ellipsoid for the
model parameters, giving a good compromise in precision among the parameter
estimates (mean and standard deviation, taking a Gaussian threshold distribution
as an example).
 The Neyer D-optimal algorithm has three parts. Starting with initial guesses
supplied by the user of the mean µ and standard deviation σ, the first part uses a
modified binary search to bring test points into the region of interest (to within a
few standard deviations of the mean) as quickly as possible. The second part of the
test is designed to determine unique maximum likelihood estimates (MLEs) of the
parameters efficiently. This requires overlap of “detonated” and “did not detonate”
responses—where the lowest test level causing detonation is lower than the highest
level with non-detonation [9]. Following this, the third part of the test continuously
refines the estimates by choosing each test point to maximize the determinant of
the Fisher information matrix.
 As implemented in Sentest, after each new point is calculated, a unit is tested at
that level and the result is entered by the user. This process continues indefinitely
until stopped by the user. Typical test runs use 20-30 units. See [6] for a detailed
description of the sequential algorithm and statistical inference methods.

3 The Neyer simulator
Figure 1 shows the general flow of the simulator. The user supplies an initFunction
that returns MuMin and MuMax, estimates for the range of µ, and SigmaGuess,
an estimate of σ. Note that the code as written assumes a Gaussian threshold dis-
tribution. For a logistic distribution, change the call to glm in the updateMLE
function, and modify the computeInfo function appropriately.
 The user-supplied detonator model is coded as the responseFunction
passed to runNeyer. In the example shown in Section 4.1 this simply returns
a binomial value based on the “true” threshold distribution. In general, for an ex-
periment designed to evaluate the effect of covariates, this function might include
a predictive model for performance based on prior knowledge. For an example of
this type, see Section 4.1 in [2].

4 Appendix: Neyer simulation code
This is the code for the simulator of Neyer Sentest, as described above. It is loaded
as Neyer-auto.R in the example listed in Section 4.1 below.

# Neyer test implemented based on Neyer (1994),
# "A D-optimality-based sensitivity test,"
# Technometrics 36(1), 61-70.
# Input and output are done via program interface.

# Return TRUE if the largest stimulus with no response
# is larger than the smallest stimulus with response.
isOverlap <- function(x, y) min(x[y==1]) < max(x[y==0])

 3

# Update the current MLE for mu and sigma; use a guess if the MLE
# does not exist. The MLE exists if the smallest stimulus causing
# a response is less than the largest stimulus causing no response.
# See M. J. Silvapulle (1981), "On the existence of maximum
# likelihood estimators for the binomial response models,"
# Journal of the Royal Statistical Society B, 43(3):310{313, 1981.
updateMLE <- function(x, y, sigma) {
  x.temp <- x[1:length(y)]
  if(isOverlap(x.temp ,y)) {
 fit <- glm(y ˜ x.temp, family=binomial(link=probit))
 beta.hat <- fit$coef
   mu.hat <- -beta.hat[1]/beta.hat[2]
 sigma.hat <- 1/beta.hat[2]
  } else {
   mu.hat <- (min(x.temp[y==1]) + max(x.temp[y==0]))/2
 sigma.hat <- sigma
  }
  c(mu.hat, sigma.hat)
}

# Compute the Fisher information using x, mu and sigma.
computeInfo <- function(x, mu, sigma) {
  z <- (x - mu)/sigma
  P <- pnorm(z)
  Pprime <- dnorm(z)
  Q <- pnorm(-z)
  I00 <- sum(Pprimeˆ2/(P*Q*sigmaˆ2))
  I01 <- sum(Pprimeˆ2*z/(P*Q*sigmaˆ2))
  I11 <- sum(Pprimeˆ2*zˆ2/(P*Q*sigmaˆ2))
  I <- matrix(c(I00,I01,I01,I11), ncol=2, byrow=TRUE)
  I
}

# Compute the information with one added stimulus level.
# this is used for optimizing over x.new to maximize the
# information.
computeNewInfo <- function(x.new, x, mu, sigma) {
 x.add <- c(x, x.new)
 -det(computeInfo(x.add, mu, sigma))

 4

}
# Return the x.new that maximizes the Fisher information
maximizeInfo <- function(x, mu, sigma) {
  interval <- c(max(0, mu - 8*sigma), mu + 8*sigma)
  opt <- optimize(computeNewInfo, x, mu, sigma,
 interval=interval, tol = 0.001)
  round(opt$minimum, 2)
}

# Run a Neyer test with n points;
# initFunction returns a vector of mu.min, mu.max, sigma.guess;
# responseFunction returns 0 or 1 as the response to a stimulus;
# ... are additional parameters to be passed to the response
# function;
# if fileName is not NULL, output will be written to a .csv file;
# Typically, to emulate real Neyer tests, set round=TRUE, since
# test levels are almost always rounded to integer values;
# set trace = TRUE to write test details to the console.
# The function returns a list:
# x and y are the stimulus and response values;
# mu and sigma are the mean and standard deviation of the threshold
# distribution, estimated using glm (equivalent to the meaximum
# likelihood estimate from Neyer Sentest;
# infoMatrix is the Fisher information;
# mleAttained is TRUE if the MLE is valid (overlap occurred).
#
runNeyer <- function(n, initFunction, responseFunction,
 fileName=NULL, round=TRUE, trace=FALSE, ...) {
  inits <- initFunction()
  mu.min <- inits[1]; mu.max <- inits[2]; sigma.guess <- inits[3]
  x <- NULL # Successive stimulus values
  y <- NULL # Successive response values
  mu.hat <- NULL
  sigma.hat <- NULL
  x[1] <- (mu.min + mu.max)/2 # Initialize first-time value
  for(i in 1:n) {
 if(trace) {print(x); print(y)}
 # Get response from last stimulus
 if (round) x[i] <- round(x[i])
 y[i] <- responseFunction(x[i], ...)

 5

 if(i==n) break # All tests have been run, return final estimate
 # Set next stimulus level
 maxS <- max(x); minS <- min(x)
 if(sum(y) == 0) { # All failures so far
   x[i+1] <- max((mu.max + maxS)/2, maxS +
 2*sigma.guess, 2*maxS - minS)
 next
 }
 if(sum(y) == length(y)) { # All successes so far
   x[i+1] <- min((mu.max + minS)/2, minS -
 2*sigma.guess, 2*minS - maxS)
 next
 }
 minX <- min(x[y==1]) # Smallest stimulus giving success
 max0 <- max(x[y==0]) # Largest stimulus giving failure
 if(minX - max0 > sigma.guess) {
   x[i+1] <- (max0 + minX)/2
 } else {
 mle <- updateMLE(x, y, sigma.guess)
   mu.hat <- mle[1]; sigma.hat <- mle[2]
 if(isOverlap(x, y)) { # If MLE exists
 mu.hat <- max(minS, min(mu.hat, maxS))
 sigma.hat <- min(sigma.hat, maxS - minS)
 } else {
    mu.hat <- (minX + max0)/2
 sigma.hat <- sigma.guess
 sigma.guess <- sigma.hat*0.8
 }
 x[i+1] <- maximizeInfo(x, mu.hat, sigma.hat)
 }
 if(trace && !is.null(mu.hat)) {
 print(paste("mu.hat = ", round(mu.hat, 2), ", sigma.guess = ",
 round(sigma.guess, 2), ", sigma.hat = ",
 round(sigma.hat, 2), sep=""), quote=FALSE)
 }
}
mleAttained <- min(x[y==1]) < max(x[y==0])
if(mleAttained && trace) print("MLE attained", quote=FALSE)
if(!is.null(fileName)) write.csv(data.frame(x=x, y=y),
 toString(fileName))

 6

 list(data=data.frame(x=x, y=y), mu=mu.hat, sigma=sigma.hat,
 infoMatrix=computeInfo(x, mu.hat, sigma.hat), mle=mleAttained)
}

4.1 Usage example
The following code fragment runs a simulated test and prints the result on the con-
sole. Setting trace=TRUE causes the internal progress of the test to be printed as
well. The warning message
glm.fit: fitted probabilities numerically 0 or 1 occurred
may be printed; this can be ignored—it just indicates that one or more responses
(0 or 1, respectively) occurred at stimulus levels where the probability had already
been estimated as 0 or 1.
 The response function simply compares the stimulus to a random value drawn
from the “true” threshold distribution, and returns 0 or 1 depending on whether the
threshold value drawn is above or below the stimulus value.

source("Neyer-auto.R")
initGuesses <- function() {
  c(200, 500, 50)    # mu.min, mu.max, sigma.guess
}
response <- function(x) {
  muTrue <- 380; sigmaTrue <- 15
  p <- pnorm(x, muTrue, sigmaTrue)
  rbinom(1, 1, p)
}

runNeyer(20, initGuesses, response, trace=TRUE)
