 ABSTRACT
 SE2-ANL is a modified version of SUPERENERGY-2 which interfaces the power distribution
in the ANL maintained physics codes for the user. SE2RCT is a special version of SE2-ANL
developed for specific use on models of the Experimental Breeder Reactor-II (EBR-II). SE2RCT
fulfills a specific role in the calculated results as part of the Fuels Irradiation and Physics Database
(FIPD) and is built to connect with the Physics and Analysis DataBase (PADB) for metallic fuel
research and development in advanced sodium-cooled fast reactors (SFRs) created for EBR-II.
SE2RCT is primarily a thermal analysis code that interfaces with the RCT based pin power details
instead of the built-in pin power dehomogenization strategy in SE2-ANL. Beyond the thermal
hydraulic calculation, the SE2RCT code provides detailed axial distributions of the RCT calculated
results. SE2RCT also calculates the the axial distribution of pin wise DPA for the cladding materials
which is part of the FIPD calculated results. This report serves as the user manual for SE2RCT and
thus eliminates the QA gap of missing documentation on the SE2RCT software. All of the features
and limitations of SE2RCT are documented in this report. The input and output specifications of
SE2RCT are discussed in detail, and some unique features of SE2RCT, e.g. accurate pin power and
temperature results for problems with non-uniform composition within an assembly, are also
demonstrated and tested.

1. Introduction
 SE2RCT, historically referred to as SE2P [1], was developed to perform thermal analysis of
sodium cooled fast spectrum reactors with SUPERENERGY-2 [2-4] with the pin depletion and
power results from RCT [5,6]. SUPERENERGY-2 was developed in the late 1970s as a multi-
assembly, steady-state thermal analysis capability for Liquid Metal Reactor (LMR). It was heavily
updated at ANL to create SE2-ANL [4] such that it includes a pin power calculation, oriface search,
and hot channel factor temperature calculation capabilities. For more details on SE2-ANL, readers
are encouraged to consult reference [4]. SE2RCT is based upon an early version of SE2-ANL and
was modified to replace the pin power reconstruction based upon DIF3D-FD with the pin power
details from RCT. RCT is a post processing capability for REBUS [7,8] to do pin depletion and
reconstruct the pin power at the beginning and end of each REBUS time point. RCT was originally
built around the DIF3D-Nodal [9] capability of DIF3D, which itself is a part of REBUS. RCT was
recently extended to use the DIF3D-VARIANT [10] capability of DIF3D also implemented in
REBUS. For more details on how RCT functions, readers are encouraged to read references [5,6].
SE2RCT is a fundamental component of the EBR-II [11] analysis capability at ANL which is used
as calculated data in FIPD [13].
 The original SUPERENERGY-2 code was built to handle a user specified reactor size and
provide the steady-state temperature solution. SUPERENERGY-2 is based upon the subchannel
methodology and uses several correlations to avoid solving the momentum equation and allow it to
calculate the temperature distribution throughout the domain. The primary purpose for its creation
was to properly model interassembly heat transfer, and, for a given power and flow distribution,
calculate the detailed core-wide coolant temperature profile [2]. The SUPERENERGY-2 code
requires the user to provide a radial pin power profile and an axial power profile for each assembly.
The SE2-ANL version of SUPERENERGY-2 obtains those power profiles directly from the DIF3D
solution and users are referred to reference [4] for more details. SE2-ANL basically constructs an
input for SUPERENERGY-2 and then calls SUPERENERGY-2 as a subroutine instead of an
external code. After SUPERENERGY-2 is complete, SE2-ANL does non-trivial post processing
of the SUPERENERGY-2 results.
 Many modifications to the SUPERENERGY-2 input processing were made when building SE2-
ANL and some of those features are used in SE2RCT as the source coding of SE2-ANL. Unlike
SE2-ANL, which interfaces with the DIF3D-FD flux solution, SE2RCT interfaces with the
reconstructed pin power and flux results from RCT. RCT generates different power profiles for
each axial mesh of each assembly, however, it only tracks the axial meshes in the active core region.
The SUPERENERGY-2 coding only allows a single radial power profile and axial power profile
for each assembly. That aspect of SUPERENERGY-2 in SE2RCT was retained. In that regard, the
radial and axial profile the user provides in input is simply overwritten with one generated based
upon the RCT interpolated result. This same power profile is used in the fuel pin temperature
calculation although the pin temperature routine was modified from what SE2-ANL did. As RCT
tracks the pin nuclide densities, it can properly treat assemblies with non-uniform pin compositions.

The SE2RCT code produces detailed axial distributions of the pin-by-pin burnup, fast fluence, total
fluence, group fluxes, and atom densities generated from RCT. SE2RCT also calculates the axial
distribution of pin DPA (for cladding material).
  While SE2-ANL was a capability applicable to different reactor sizes, SE2RCT is not as general
and is effectively hardwired to be part of the EBR-II [11] analysis process. Most of the EBR-II
analysis work associated with SE2RCT started in the late 1980s and early 1990s as part of the
construction of the Physics Analysis DataBase (PADB) [13]. That work continued and today is
known as the Fuels Irradiation and Physics Database (FIPD) [12]. The various axial profile details
generated by SE2RCT feed into FIPD as the calculated data for specific measured assemblies. The
REBUS/RCT/SE2RCT calculation procedure was constructed in the early 1990s and has been
routinely tested since then. The updates made to RCT to utilize the DIF3D-VARIANT flux solution
were tested as part of this manscript creation and not found to cause any observable issues for
SE2RCT.
 Although SE2RCT has the ability to use the detailed radial and axial power profiles from RCT,
it has some serious limitations with regard to general purpose usage. As part of its creation,
SE2RCT was restricted to only allow a 7-assembly problem (2 rings) and allows a maximum of 91
pins per assembly (the fuel assembly size limits of EBR-II). The user must supply the power profile
via the standard SUPERENERGY-2 input (separate radial and axial profile) for all seven
assemblies (this is not consistent with SE2-ANL), and the RCT power profile only replaces that of
the central assembly power profile. The various axial output profiles are also only generated for the
central assembly.
 In addition to these restrictions, the neutron damage cross sections (DPA) are hardwired into
SE2RCT for the three structural materials included in SUPERENERGY-2. They have a nine energy
group structure consistent with the analysis work being done in the 1980s and thus the REBUS and
RCT calculations must use the same nine energy group structure. The RCT related part of SE2RCT
is hardwired to only allow three axial zones in the fuel region which is the only part of the power
profile that is replaced by RCT. The three axial zones was chosen because that was the extent of
the models built for PADB analysis in the 1980s. Today, the standard number of axial burnup zones
is five or more. For EBR-II, the fuel pins are effectively directly adjacent to the axial reflector and
this causes a significant power peaking detail that is hard to capture with the three burnup zone
methodology. The preceding highlights the primary limitations whereas SE2RCT has even more
which will be discussed later.
 The SE2RCT code was developed in early 1990s and very little documentation on it exists today.
This manuscript resolves the lack of documentation on SE2RCT and serves as the user manual. As
inferred from the preceding details, much work is done to explicitly detail the SE2RCT input and
its restrictions in addition to doing some cursory verification of the existing capabilities.

2. Major Features of SE2RCT
 As detailed earlier, SE2RCT combines the features of SUPERENERGY-2 (SE2) and RCTP
code. SE2RCT is limited to a seven assembly problem and adiabatic boundary conditions are
applied to all outward facing surfaces of the six assemblies in the second ring. The methodology in
SUPERENERGY-2 is only applicable to forced-convection problems consisting of bundles with
standard pin geometries and further details can be found in references [2,4]. The RCT program [5,
6] is tasked with carrying out pin depletion and stores the power, flux, and pin atom densities in
binary interface files for the beginning and end of a time step in a REBUS calculation [7,8]. The
RCTP [6] (the RCTP manual is embeded in the RCT manual) program was written as a post
processing capability for the RCT files to generate various pin power, flux, and atom density
profiles. The purpose of merging RCTP into SE2RCT was to enable SUPERENERGY-2 to access
the pin power profiles of RCT and have a single program produce all of the quantities of interest
with regard to measured fuel pin depletion data.
 In RCT, polynomial expansions of the nuclide density, flux, and power are defined for each
mesh that is tracked. For individual pins, the RCT methodology yields a simple 2 nd order
polynomial while the overall power distribution in each mesh is 2 nd order axially and ~4th order in
the radial plane. The RCT capability only works for user identified active core regions (depletion
regions) and the number of meshes within each region is fixed for any given REBUS depletion
model. However, with EBR-II models, the movement of control rods can cause the number of
meshes used in the active core region to change from one cycle to the next. Because RCT only
retains the details of the active core geometry, the SE2RCT code can only define the power
distribution in the identified active core region. Only three axial (depletion) regions were used in
the REBUS models of EBR-II and thus SE2RCT is hardwired to only consider three axial regions
in the REBUS models.
 The RCT axial mesh boundaries do not necessarily line up with the SUPERENERGY-2 mesh
boundaries and the SUPERENERGY-2 methodology requires an interpolatable power distribution
consistent with its solver mesh. While it might seem obvious to just use the RCT interpolation
scheme, this required too many changes and the existing scheme in SE2RCT is to backfit the RCT
calculated power distribution to be consistent with the SUPERENERGY-2 scheme. That scheme
uses a single radial profile (pin power) combined with a single axial profile for the entire assembly.
For the pin temperature calculation, the RCT based pin power specification is used. This means the
coolant temperature distribution is inherently inconsistent with the pin temperature calculation
although this might be a very minor issue.
 One important change from SE2-ANL to SE2RCT is the fuel and cladding temperature
calculation, both of which use a steady state one-dimensional conduction model. In SE2-ANL the
one-dimensional model is used assuming each interior subchannel connects to a unique pin which
is of course not consistent with the actual geometry where approximately six coolant sub-channels
connect to each pin. The approach taken in SE2-ANL effectively disregards the edge and corner

                                                    7                               ANL/NSE-25/68

coolant temperatures in the pin temperature calculation. In SE2RCT, the one-dimensional pin
temperature routine is solved by using the average temperature of the surrounding coolant
subchannels and the power density for each fuel pin coming from RCT. Because this only has to
be done for the central assembly in SE2RCT, the indexing of coolant sub-channels with the pin
lattice is rather easy to program. This is consistent with DASSH-F which computes the average
coolant temperature around each pin and uses that in the one-dimensional pin temperature routine.

2.1 Input files and built-in data
 The SE2RCT codes requires two input files: 1) A.SE2 and 2) A.SE2P. Besides these two input
files, SE2RCT also needs four RCT binary output files: RCTFLX1, RCTFLX2, RCTDEN1 and
RCTPWD1. The RCTFLX1 and RCTFLX2 files store the reconstructed group-wise neutron flux
corresponding to BOC and EOC respectively, and these two files are needed to calculate the neutron
damage of the structure material. The RCTDEN1 file stores the reconstructed pin nuclide density
at EOC, and it is only used for output editing. The RCTPWD1 file stores the reconstructed pin
power density, (either the BOC or EOC power details from RCT can be used in SE2RCT), and this
file provides the power profile for the temperature calculations. It should be noted that the names
of these four binary files are different from those from RCT, and need to be renamed as shown in
Table 2.1.

 The A.SE2 input file is the full input for a SUPERENERGY-2 calculation. This approach is
different from SE2-ANL which only required the user to provide a truncated input in A.SE2ANL
[10]. The geometry model in SE2RCT must contain just seven assemblies, as shown in
 Figure 2.1, and only the central assembly has any connection to the RCT calculated results.
Therefore, the A.SE2 file must specify the full SUPERENERGY-2 input for the seven assembly
problem including the assembly-averaged linear power and the radial and axial power profiles. The
values given for the central assembly will be overwritten with the refitted RCT result.
 The A.SE2P input file specifies information on the central assembly, e.g. duct geometry, fuel
pin cladding material, the fuel pin constitutents and porosity (correlations used for heat

conductivity), and the number of axial meshes for interpolation. Given the A.SE2P input file,
SE2RCT extracts the targeted assembly data from the RCT binary output files and interpolates it
with the RCTP program included in SE2RCT as a subroutine. Because RCTP was originally a
separate program, SE2RCT generates a RCTP BCD input file A.RCTP based upon the information
in the pin nuclide density RCTDEN1 which is then read by the RCTP program. As part of the input,
the user needs to define the number of axial interpolation zones. The power densities from
RCTPWD1 are interpolated to get the axial and radial shape factors, and the total assembly power.
These replace any values given in A.SE2 for the central assembly noting as stated earlier that the
original SUPERENERGY-2 power scheme is used for the coolant temperature calculation and the
RCT scheme is used for the pin temperature routine.

 Reading the A.SE2 and A.SE2P inputs, as well as the binary RCT output files, SE2RCT
performs the temperature calculations for the seven assembly model. As was done in SE2-ANL,
the pin temperatures are calculated at each axial mesh of the coolant temperature solver noting that
this is restricted to only consider the central assembly in SE2RCT where SE2-ANL did it for all
driver assemblies. With the RCT information on fuel pin composition available, SE2RCT improves
upon the SE2-ANL fuel temperature calculation because it can assign different cladding material
to each pin and handle the variable fuel composition and porosity.
 The SE2RCT provides tables of output for burnup, fast and total fluence, and nuclide densities

2.2 Limitation of SE2RCT
  The SE2RCT code was developed for use in the EBR-II follow-on analysis and no further
maintenance or development has been carried out on it since. Because of the DASSH development
work, non-trivial bugs were identified in the SUPERENERGY-2 code and thus bugs were figured
out in SE2RCT. SE2RCT was never intended for general use and it has many severe limitations:
 1. The geometry model of SE2RCT is limited to seven assemblies as shown in Figure 2.1. Only
 the central assembly is of interest and the RCT results are only applied to it. The central
 assembly only allows a maximum number of pin rings of 5 and thus can only model
 assemblies with at most 91 pins. This limitation is not applied to the 6 surrounding assemblies.
 This limitation arises because the maximum number of fuel pins for the metallic fuel
 assemblies used in EBR-II is 91.
 2. The axial coolant temperature calculation in SE2RCT only considers the active core region
 of the domain which must be consistent with the geometric specification in RCT. This ignores
 the impact of any power deposited below the active core on the coolant temperature
 distribution. Similarly, no concern is given for the coolant temperature details above the active
 core.
 3. The user must provide power profiles for all seven assemblies and only the central one is
 modified by SE2RCT using the information from RCT. The coolant temperature calculation
 uses the SUPERENERGY-2 methodology which approximates the detailed RCT power
 distribution. The fuel temperature calculation uses the RCT power distribution for the central
 assembly.
 4. The fuel pin temperature and DPA calculations are only performed for the central assembly.
 The interpolation of the accumulated burnup, fast and total fluence, and nuclide densities are
 only performed for the central assembly.
 5. SE2RCT was developed in the 1990s for the existing EBR-II analysis. At that time the number
 of axial depletion regions in the REBUS models of EBR-II was set to 3. Correspondingly, the
 axial interpolation scheme in SE2RCT only allows three axial burnup zones. It is very
 common today to use at least five axial depletion regions in a REBUS model of a reactor.
 6. The energy group structure in SE2RCT is restricted to only allowing 9 groups as it will die
 with a segfault if any number beside 9 is used. This forces the RCT and REBUS calculations
 preceding it to use the same 9 group structure.

4. Output Specification of SE2RCT
 The SE2RCT code is setup to obey the standard Unix redirect of input and output. In this
scheme, the default input, A.SE2, is imported into the Fortran program using unit 5 and the output
is sent to unit 6. SE2RCT does not push all of the output to unit 6 and in fact creates many files,
only a few of which are used by FIPD (main output is not used). Similarly, SE2RCT does not
import all input through unit 5 as the A.SE2P input is imported as a separate read. To execute
SE2RCT, the command should have the form: “se2rct.x < myinput > screenoutput.” The A.SE2P
file is assumed to exist in the current working directory.
 Table 4.1 lists all of the output files SE2RCT produces and their purpose. It should be noted
that the number of axial meshes for the RCTP interpolation, defined in A.SE2P, can be different
from the number of meshes defined in A.SE2 that is used for the coolant temperature solve in
SUPERENERGY-2 (SUPERENERGY-2 typically needs a finer axial mesh). From the description
column of Table 4.1, one should find that the files ATDEN, BUPWF, and fort.163 are generated
by RCTP and have the RCTP axial mesh. The files TCSU, TCMW, TCIN, TFSU, and TFCE are
generated as part of the added fuel pin calculation in SUPERENERGY-2 (i.e. part of SE2-ANL)
and the outputs have the SUPERENERGY-2 axial meshing scheme. The LINPW file provides the
pin-wise linear power used in the SUPERENERGY-2 fuel pin calculation and the TFLW file
provides the pin-wise coolant temperature which are calculated by averaging the temperatures of
the surrounding coolant subchannels in the SUPERENERGY-2 calculation. Both of these files have
the SUPERENERGY-2 axial meshing. The remaining binary and developer debug output files can
be ignored.

5. Test and Verification of SE2RCT
 SE2RCT can produce accurate pin power and temperature results for the central assembly of
interest although there are the stated limitations covered in the preceding sections. One advantage
of SE2RCT over SE2-ANL and DASSH-F [14] is that it can deal with non-uniform compositions
within an assembly. In this section, the focus will be placed on assessing the SE2RCT calculated
temperature results. Because SE2RCT must be interfaced with REBUS/RCT, some examples of
REBUS/RCT modeling are provided in this section.

5.1 SE2RCT and DASSH-F Comparison
 As explained earlier, SE2RCT can only calculate a seven-assembly model and the pin power
reconstruction from RCT only applies to the central assembly. For the six surrounding assemblies,
less accurate power profiles have to be used. For this reason the coolant temperature profiles for
the six surrounding assemblies might not be accurate, and the impact on the central assembly results
should be evaluated.
 Because expanding the RCT power profile results to all seven assemblies is not feasible without
major source code changes, the results from DASSH-F are used as a comparison point for SE2RCT.
DASSH-F uses a nearly identical methodology to SUPERENERGY-2 for the coolant and fuel pin
temperature calculation. DASSH-F is interfaced with DIF3D-VARIANT and can work directly
with files produced by REBUS to define the pin power distribution. Unlike SE2RCT, DASSH-F
solves the entire domain (like SE2-ANL does). DASSH-F does not rely upon RCT to reconstruct
the neutron flux and pin power within each assembly and instead uses VARPOW [15] and a power
reconstruction scheme consistent with DIF3D-VARIANT. As a consequence, the pin power
distribution in DASSH-F can be different from RCT.
 To directly compare the SE2RCT and DASSH-F results, a REBUS model was built. The core
layout of fuel assemblies, as well as relative assembly power at BOC, is shown in Figure 5.1. As
stated, the BOC power profile from REBUS can be used for both SE2RCT and DASSH-F. Only
the two hottest assemblies, identified in Figure 5.1, are deemed of interest in this analysis. To get
results, two separate SE2RCT calculations are required while DASSH-F obtains the results with a
single calculation. SE2RCT inherently assumes that assemblies beyond its seven-assembly have no
major impact on the calculated temperature results on the central assembly.

5.3 Non-uniform compositions
 One important feature of RCT/SE2RCT is that it can reconstruct the pin power for an assembly
with non-uniform pin compositions and obtain a corresponding temperature solution. This feature
is tested and the results detailed using the following two example cases:
 1) Increase the Pu239 atom enrichment from 66% to 90% for the central pin while the
 remaining 90 pins have a 66% enrichment. The modified RCT input is shown in Appendix
 A3 and the A.SE2P input is unchanged from Appendix B2.
 2) The number of pins is reduced from 91 to 89 by removing the first and 91 st pin from the
 assembly. Both the RCT and A.SE2P inputs are modified and shown Appendix A4 and
 Appendix B3, respectively.
 These two cases are only for demonstration purposes and the REBUS model was not modified
to account for the differences in composition. For the first case, the power of the central pin
increases because of the increase in Pu enrichment and the power delivered to the rest of the pins
should slightly decreased to preserve the total assembly power. For case 2, the power at the two
empty pin locations is effectively zero and the power of the remaining 89 pins should increase
slightly to preserve the total assembly power. As will be shown, the RCT methodology does not
preserve the total assembly power calculated in REBUS. Because the power in the central assembly
in A.SE2 is overwritten by RCT, the central assembly (unused) power profile in the A.SE2 was not
updated consistent with the composition changes.
 As there is no comparable capability in DASSH-F at this time, the change in the results will be
simply compared against the uniform composition results from SE2RCT. For case 1, the coolant
outlet temperature distribution is compared in Figure 5.9 while the peak pin temperature (AVPK
output) is compared in Figure 5.10. Starting with Figure 5.9, one can easily see that the coolant
temperature around the central pin is higher when the Pu enrichment is increased while the
remaining temperatures in the assembly are barely impacted. Looking at Figure 5.10, the power
for the central pin is notably impacted (grid location 46) while the power for all remaining pins
appear unchanged. The actual power change amounts to a ~12% increase in the central pin while
no power change for the rest 90 pins, and thus the assembly total power is not preserved. Note that
the burnup reported for the central pin is incorrect because the REBUS/RCT model was not updated
consistently.
 For case 2, Figure 5.11 shows the difference in the coolant outlet temperature while the difference
in the peak pin temperatures (AVPK output) is shown in Figure 5.12. From Figure 5.11, one can
see that the two corners marked with red circles (where there are two pins with ~zero power), the
coolant temperature is clearly substantially reduced. The temperature around the remaining pins is
again unchanged. The assembly total power is still not preserved, with the total power decreased
by ~2% . As the comparison shows, the pins assigned zero power (grid 1 and 91 positions) disappear
from the AVPK output but none of the other pin powers change. Because of the drop in the adjacent
coolant temperatures, the peak pin temperatures adjacent to the removed pins (such as grid 2 and

                                                    38                              ANL/NSE-25/68

90) are found to decrease in temperature as one would expect given the lack of a increase in power
to preserve the total.
  Overall, the capability appears to be working, but there are clearly some aspects that need to be
investigated with regard to it being correctly implemented. As this software lacks detailed
verification documentation and that work is scheduled to be part of the current project, this and all
other preceding concerns are deferred until after that work is completed.

6. Summary and Conclusions
 SE2RCT was developed to calculate coolant and fuel temperature conditions in the
Experimental Breeder Reactor-II (EBR-II) along with DPA on the cladding. It is primarily used as
part of the Physics and Analysis DataBase (PADB) for metallic fuel research and is part of
advanced sodium-cooled fast reactors (SFRs). The results from SE2RCT are included in the Fuels
Irradiation and Physics Data (FIPD) and this manual serves to describe the capability as required
by the SQA program it is covered by. Up to now, there was virtually no documentation on SE2RCT
and, similarly, little on SE2-ANL. To create this manual, much of the source code had to be
reviewed to understand what SE2RCT was actually doing and in many cases it is contrasted against
the approach taken in SE2-ANL.
 Not surprising, the SE2RCT is very much hardwired to work on EBR-II models and is not as
general use as SE2-ANL was intended. As an example, the number of pins per assembly is limited
to 91 and it only considers a seven assembly model producing output only for the central assembly.
It also has hard wired 9 group DPA cross sections and thus restricts the entire
REBUS/RCT/SE2RCT calculation scheme to using 9 groups. In this manual, the features and
limitations of this code were documented. As detailed, the central assembly takes the power profile
for the fuel temperature calculation from previously completed RCT calculations. For the coolant
temperature calculation, the RCT power distribution is coarsened to be consistent with the
SUPERENERGY-2 methodology. For the adjacent six assemblies to the central one, the user must
manually create the power profiles in the SUPERENERGY-2 input format.
 The SE2RCT input consists of two text based inputs:
 1) A.SE2 which is the full domain (seven assembly) input for SUPERENERGY-2
 2) A.SE2P which provides the central assembly information
  The input formats of these two files were detailed in this manual with examples. Because the
A.SE2 file is covered in the SUPERENERGY-2 manual, it is not covered in detail here. The
A.SE2P input file was detailed noting the major limitation that it must use the EBR-II pin
numbering and the preceding RCT calculations must define the fuel pins as special pins also
following the EBR-II pin numbering scheme.
 SE2RCT produces multiple output files as part of its regular execution. All of the output files it
produces were listed and the user relevant ones were documented in this manual with a specific
focus on those that feed into FIPD. As covered, much of the output is strictly focused on the results
calculated for the cental assembly.
 Using a manufactured REBUS core model, the temperature results of SE2RCT were compared
against those generated by DASSH-F which treats the entire domain rather than just a seven
assembly selection. The coolant temperature results were very similar with minor differences
observable in the fuel temperature results. Because neither code has any verification
documentation, no additional work was done to sort out the reasons for the differences at this time.

                                                    41                             ANL/NSE-25/68

The isolation boundary condition of SE2RCT and its ability to model non-uniform fuel pin
compositions was also tested generating the expected results. One aspect of concern is that the total
assembly power was not preserved when applying the non-uniform fuel pin compositions and this
will have to be investigated as part of the software verification work.
